## 一、项目概览

`go-op` 是 Bilibili 运维平台后端，基于 Bilibili 内部框架 `go-common`（Kratos v1 衍生版本）构建的 Go 微服务项目，约 46,000+ 行 Go 代码。

| 服务 | 协议 | 职责 |
|------|------|------|
| `manba-bi` | HTTP | 运维数据 BI 分析（MCDN 踢点/下线事件处理） |
| `manba-computer` | HTTP + gRPC | 计算服务（使用 Wire 依赖注入，DAO 为接口模式） |
| `manba-dispatcher` | HTTP | 调度分发（接收告警 webhook） |
| `portal` | HTTP | 运维门户核心（最大、最复杂，约 35+ HTTP handler，含前端资产） |

**统一分层架构**（各服务一致）：`cmd/main.go` → `internal/{dao, model, server/{http, grpc}, service}` → `configs/`

### 核心依赖

| 依赖 | 用途 |
|------|------|
| `go-common` v1.51.18 | 内部框架（paladin 配置、blademaster HTTP、ORM、Redis、Databus、log） |
| `gorm` + MySQL driver | MySQL ORM |
| `clickhouse-go` | ClickHouse 数据仓库 |
| `google/wire` | 依赖注入（仅 manba-computer） |
| `prometheus/client_golang` | 指标监控 |
| 内部中间件 | discovery（服务发现）、trace-sdk-go（链路追踪）、logging-sdk-go（日志采集） |

## 四、MCDN 节点上下线（踢点）体系

### 整体架构

```
moni/Prometheus（节点指标采集）
  → 告警平台（规则判定）
  → webhook → manba-dispatcher
  → databus（Mcdn-dispatcher-01-T）
  → manba-bi（消费，执行下线）
  → portal（PUT /pcdn，is_disabled=true）
```

### 关键常量

| 常量 | 值 | 含义 |
|------|-----|------|
| `BusinessTypePortal` | `"北斗"` | 运维门户 |
| `BusinessTypeBvc` | `"视频云"` | BVC 点播 |
| `BusinessTypeMob` | `"移动端"` | MOB 移动端 |
| `BusinessTypeBstar` | `"星辰"` | Bstar |
| `BvcMAX` | 50 | BVC 当日熔断阈值 |
| `MobMAX` | 100 | MOB 当日熔断阈值 |

### 自动恢复策略

定时任务（每 360 秒）扫描当日下线节点：

| 机型 | 触发原因 | 策略 |
|------|----------|------|
| `-v-`（视频云） | 丢包率 | 统一 30 分钟 |
| 其他（`-mp2sp-` 等） | 任意 | 1次 30 分 / 2次 2 小时 / ≥3 次人工 |

- 核心实现：`app/manba-bi/internal/service/autoonline.go`（`shouldOnline()` + `autoAction()`）
- 测试：`TestShouldOnline` 19 个用例（`autoonline_test.go`）
- 观测 SQL：`autoonline_observe.sql`

### 下线事件 action_id

| 值 | 含义 |
|----|------|
| 100 | 直接下线 |
| 200 | 预测下线（已停用） |
| 300 | 告警通知 |
| 400 | 自动上线 |

查询 API：`GET /api/v1/portal/bi/msgdata`（`msg_data_all` 表）、`GET /api/v1/portal/bi/tip/:key`、`GET /api/v1/portal/bi/msgdata/:id`

### 节点可见性

- `is_disabled=false` 且 `dial_ips!=''` 且 `updated_at` 3 分钟内 → 在服务列表
- 超过 3 分钟未上报心跳 → 移出，恢复后 portal 每 30 秒缓存刷新自动恢复
- 线路可用率（validRatio）< 80% 时不踢点

### 已废弃/停用

- BVC 割接下线（`ChangeBvc`/`ChangeBvckey` 已注释）
- 预测下线（action_id=200，基于 BVC 卡顿率 BufferRate）
- manba-bi 于 2023/11 弃用 databus/redis/clickhouse，当前仅依赖 MySQL + go-cache

## 五、MCDN 线路可用率监控

脚本 `.claude/scripts/line_availability.py` 从 `mcdn-data.biliapi.net/api/v1/portal/mcdn/resource` 拉取在线节点数据，输出 Prometheus 指标：

| 指标 | 用途 |
|------|------|
| `mcdn_diskinfo` | 节点资源（CPU/内存/硬盘/线路），`node_name` 标识 |
| `mcdn_lines_info`（`isp_lines`） | 线路可用率，`mcdn_identity` 标识 |
| `mcdn_lines_info`（`ip_repeat`） | IP 冲突检测 |

线路可用率 = `len(ips) ÷ (total_bandwidth / line_bandwidth) × 100`。告警：MOB 线路可用率 < 50% 自动下线（仅 `-mp2sp-` 节点）。

## 六、MCDN 丢包率监控

节点部署 `packet_loss.sh`（`.claude/scripts/packet_loss.sh`），ping 百度+淘宝（国内）/ Google+B站（Bstar），输出 `mcdn_network_quality` 指标到 Prometheus。

五条告警规则：

| 告警 | 节点类型 | 阈值 |
|------|---------|------|
| BVC-丢包率 > 20% | v / live / bvcmix | > 20% |
| MOB-丢包率 > 15% | v / live / bvcmix | > 15% |
| MOB-丢包率 > 15% | mp2sp | > 15% |
| MOB-重传率 > 15% | mp2sp | > 15% |
| BVC-重传率 > 20% | v / live / bvcmix | > 20% |

重传率 = `irate(Tcp_RetransSegs[4m]) / irate(Tcp_OutSegs[4m])`。历史上曾因重传率+丢包率导致大规模下线（2026/6/30，658 台/2 小时）。

## 九、常用命令速查

```bash
# 本地运行 manba-bi
LOG_NO_AGENT=true DEPLOY_ENV=uat go run ./app/manba-bi/cmd/main.go -conf=./app/manba-bi/configs

# 构建
go build ./app/manba-bi/cmd/...

# 单包单测
go test -v -short ./app/manba-bi/internal/server/http/...

# 集成测试（需先启动 Docker 数据库）
cd app/manba-bi/test && docker compose up -d
go test -v -run TestMsgDataHandler ./app/manba-bi/internal/server/http/...

# 全部单测
go test ./app/... 2>&1 | grep -E "^(ok|FAIL|---|\?)"

# 格式化
gofmt -w <file>

# Wire（仅 manba-computer）
cd app/manba-computer/internal/di && wire
```
