## 三、核心发现

### 1. bvc-iobone-bin 是 CPU 暴冲的最终根因

六台机器的共同特征：**bvc-iobone-bin 的 CPU 会大幅波动（2.7x~4.8x）**，在业务高峰期把 CPU 吃满。

| 机器 | 历史平均 | 7/7 实时 | 增幅 |
| ---- |:----:|:----:|:----:|
| v-1169 | 599%（6核） | 1679%（16.8核） | **2.8x** |
| v-344 | 108%（1核） | 522%（5.2核） | **4.8x** |
| v-1109 | 149%（1.5核） | 411%（4.1核） | **2.7x** |
| v-1125 | 133%（1.3核） | 355%（3.6核） | **2.7x** |
| v-337 | 201%（2核） | 216%（2.2核） | 1.1x |
| v-308 | 262%（2.6核） | 178%（1.8核） | 0.7x |

**bvc-iobone-bin 是业务进程（bvc-io），不是 bug。** 它的 CPU 波动直接反映业务流量——机器承载的流量越大，CPU 越高。

### 2. si（网卡软中断）是第二元凶

| 机器 | si | 说明 |
| ---- |:----:|------|
| v-1169 | 💀 **53.8%** | ksoftirqd 6 线程满载，网卡中断吃了一半 CPU |
| v-1109 | 💀 **38.3%** | 网卡收发包接近极限 |
| v-344 | 💀 **35.1%** | |
| v-1125 | 💀 **32.6%** | |
| v-337 | 🔴 25.5% | |
| v-308 | ⚠️ 11.7% | 正常偏高 |
| **v-357（正常）** | ⚠️ 17.8% | 对照基准 |

si 是网卡收发流量直接驱动的——流量越大，软中断越高。异常机器的 si 是正常的 1.5~3 倍，说明它们承载的**网络流量也远高于正常机器**。

### 4. mcdn_cpu_moni 不能反映瞬时 CPU

v-308 和 v-337 的分析中，ps 进程 CPU 总和与节点实际 CPU 严重不符——`mcdn_cpu_moni` 是平滑/累计值。这意味着：

- **不能用于 checkStatus 的 CPU 检查**——需要换用节点级原生指标
- **不能用于精确追溯暴冲元凶**——需要在告警触发时刻用 top/relay 直接采集

### 5. 回源带宽 vs CPU — 10 台机器实时数据验证 ✅✅

以下为 10 台机器同时刻的 MCDN 资源 API 快照，**回源带宽(incoming)和 CPU 完全正相关**：

| 机器 | 一周下线 | CPU | 回源带宽 | 状态 |
| ---- | ---- | ---- | ---- | ---- |
| v-337 | 2 | **94.02%** | **6.611 Gb/s** | 🚨 即将下线 |
| v-360 | 2 | **97.07%** | **5.873 Gb/s** | 🚨 即将下线 |
| v-308 | 2 | 60.60% | 1.785 Gb/s | 🟠 中间态 |
| v-340 | 2 | 30.52% | 1.070 Gb/s | 🟢 |
| v-344 | 5 | 29.51% | 0.430 Gb/s | 🟢 |
| v-348 | 2 | 25.22% | 0.418 Gb/s | 🟢 |
| v-1125 | 6 | 23.80% | 0.243 Gb/s | 🟢 已下线后 |
| v-1109 | 6 | 13.36% | 0.198 Gb/s | 🟢 上午下线后 |
| v-1169 | 6 | 2.18% | 0.044 Gb/s | 🟢 上午下线后 |

**阈值对应关系**：

| 回源带宽 | CPU 区间 | 判定 |
| ---- | ---- | ---- |
| > 5 Gb/s | > 90% | 🚨 触发下线 |
| 1~2 Gb/s | 30~60% | 🟠 中间态 |
| < 1 Gb/s | < 30% | 🟢 安全 |
| < 0.3 Gb/s | < 15% | ✅ 已下线，无流量 |

**v-1125 单个机器的时序验证**（7/7 上午 10:48 下线，触发值 88.12%）：

回源带宽从 10:00 的 313 Mb/s 暴冲到 10:48 的 **1.27 Gb/s（3.4x）**：

```text
回源带宽暴冲 (1.27 Gb/s)
  → 网卡收发包数暴增
  → si（软中断）飙升到 32.6%
  → bvc-iobone-bin 处理翻倍的业务数据（355%，历史 133% 的 2.7x）
  → busy = us + sy + si > 80%
  → 触发下线
```

**完整因果链已闭环：回源带宽↑ → si↑ + bvc↑ → CPU busy > 80% → 下线。**

> 正常机器 v-357 的 bvc 仅 161%、si 仅 17.8%——其回源带宽大概率也远低于 1 Gb/s。
