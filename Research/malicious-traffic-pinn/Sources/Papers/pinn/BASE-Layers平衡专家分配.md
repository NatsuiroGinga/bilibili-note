# BASE Layers 平衡专家分配

> Mike Lewis 等，2021，ICML · PDF 10 页

## 一句话

BASE 能保证训练批次计算负载相等，却不能保证物理状态比例合理或训练与推理路由一致，因此不适合直接照搬到自然长尾的物理状态专家。

## 背景

学习型专家路由常依赖辅助均衡损失、容量因子和丢词元策略。BASE 把每批词元分配给专家视为带等容量约束的线性指派，消除额外均衡权重。

## 方法核心

训练时最大化词元与专家的总亲和度，同时约束每个专家接收相同数量词元。每个词元只激活一个专家，专家输出经门控残差混入主干。

测试时无法使用需要完整批次全局信息的平衡指派，论文改用逐词元贪心分配。这造成训练路由与测试路由并不完全一致。

## 实验结果

- 论文训练最高 43B 参数模型，并比较语言模型困惑度和吞吐量。
- 128 块 GPU 上，数据并行、稀疏门控 MoE、Switch、BASE 的训练吞吐量分别约为 600k、292k、469k、545k 词元每秒。
- 43B BASE 模型训练速度可达到 1.5B 数据并行基线的约 90%。
- 专家分析显示路由常由局部词法或句法表面信号决定，如数字、专名或词类，而非高层可解释能力。

## 我的理解

这篇论文给物理专家路线提供两个反证。第一，强制等负载会改变真实物理状态比例；容量饱和可能本来就是稀有状态。第二，路由专家可能按表面格式分工，所以必须做数据来源、提示模板和标签泄漏检查。

当前单私有适配器不存在批次指派，不应引入 BASE。若未来启用三专家，应优先报告自然占比、最小专家利用率和物理状态条件分布，而不是强制三等分。

## 局限与不可外推结论

- 训练依赖全批次线性指派，在线单序列推理不能复现相同约束。
- 专家专门化分析揭示表面信号，不能支持预设物理语义。
- 大规模语言模型吞吐量不能外推到 LoRA 微调和单卡推理。
