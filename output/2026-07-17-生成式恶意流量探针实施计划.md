# 生成式恶意流量探针实施计划

> **执行方式**：在当前会话中按任务顺序实施，每个任务遵循“先写失败测试、确认失败、最小实现、确认通过”的测试驱动流程。

**目标**：建立可在本地验证、可同步到单张 RTX 5090 复现的 Qwen3-1.7B 生成式恶意流量二分类探针。

**架构**：实验包与旧 macOS/MPS 工程隔离。数据适配器把 GeNIS、HIKARI 和 CICIoT 的原始流记录转换为统一 `FlowSample`，再经分组划分、固定序列化、监督微调和严格输出解析产生效果与效率指标。

**技术栈**：Python 3.10 至 3.12、`uv`、PyTorch、Transformers、PEFT、TRL、bitsandbytes、pandas、scikit-learn、pytest、Ruff、Black、SwanLab 在线跟踪。

## 执行错误

- 首次运行 `uv` 因沙箱 DNS 限制无法访问依赖源；获得联网授权后恢复。
- Hatchling 首次无法从项目名推断 `src/flow_probe`；补充显式包路径后，测试进入预期失败状态。
- 首轮 Ruff 检查报告导入位置和一处简化规则；安全自动修复并手工处理剩余项后通过。
- 本机沙箱禁止写入用户级 `uv` 缓存；验证命令改用 `UV_CACHE_DIR=/tmp/uv-cache` 后通过，不改变锁文件。
- 服务端非登录 shell 找不到 `uv`；后续固定使用 `/root/.local/bin/uv`。
- macOS 通过 rsync 同步时产生 AppleDouble `._*` 文件并导致服务端测试失败；同步脚本已设置 `COPYFILE_DISABLE=1` 并排除该类文件。
- GeNIS 首次场景分组按软组数配额分配，验证集和测试集只含良性样本；测试驱动修复为“类别覆盖优先于软组数配额”，且禁止回退到逐行随机切分。
- SwanLab 指标查询必须使用 `swanlab api run summary 工作区/项目/运行编号`，不能省略 `api` 或完整三段路径。
- `ci-prd-pinn` 的 `Default` 仪表盘固定保留旧 PINN 指标面板，不能用其空白面板判断 `llm_probe` 指标未上传；生成式恶意流量实验统一写入 `mortiswang/malicious-traffic-llm`。
- 远程命令输出不完整时必须先检查输出目录、`artifact_manifest.json` 和云端运行列表，再决定是否重试；不得复用已有制品清单的输出目录。

## 全局约束

- 工程目录固定为 `thesis/experiments/llm_probe/`，不修改旧实验的 `pyproject.toml` 和 `uv.lock`。
- 首轮基座固定为 `Qwen/Qwen3-1.7B`，关闭思考模式，最多生成 16 个新令牌。
- 首轮只做良性/恶意二分类；攻击家族只保留为元数据。
- 跨数据集主实验只使用 `canonical_core_v1`，数据集特有字段只作域内诊断。
- 输入文本不得包含数据集名、源文件、样本标识和标签。
- 未知标签、必需列缺失、样本标识重复或分组交叉必须立即失败。
- 严格 JSON 解析不修复代码围栏、解释文本、额外键或未知标签；非法输出按错误预测处理。
- 本地单元测试不得下载模型或要求 GPU。
- 原始数据、模型权重、缓存和大体积运行产物不进入版本管理。
- SSH 命令、密码和令牌不得写入代码、配置、日志或文档。
- 所有非隐藏实验配置必须声明 `tracking.mode: online`，测试发现离线配置时立即失败。
- 所有 `llm_probe` 配置和运行时参数必须使用 `tracking.workspace: mortiswang` 与 `tracking.project: malicious-traffic-llm`。
- 每次实验必须保存 SwanLab 原始日志、控制台日志、配置、数据清单、环境、指标摘要和预测文件，并在运行卡中标注服务端与本地路径。
- 每次训练或评估必须生成 `console.log`、阶段专属 `swanlog/`、`swanlab_metrics.json`、结果文件和 `artifact_manifest.json`；已有制品清单的目录不得再次启动运行。
- 在线运行结束后必须同时验证云端指标接口和网页图表可见性；仅有上传完成提示或汇总值不算跟踪验收通过。
- 不执行 Git 提交，除非用户明确要求。
