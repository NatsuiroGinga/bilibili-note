# MalMoE：图漂移下的专家混合加密恶意流量检测

> Tan 等，2026，IEEE INFOCOM 2026 · arXiv 2602.10157v1 · 10 页 · SHA-256 `01c932b849269518843873cd84992c1bb180f59c86ff49e116ed8673f677df00`

## 证据等级

**E3 全文级**。原件已下载（`https://arxiv.org/pdf/2602.10157`，HTTP 200，579,631 字节），10 页正文与参考文献逐节读完。可支撑机制来源论断，不可直接支撑本课题实验结论。

## 一句话

MalMoE 的核心主张是：**抗漂移性不应来自重训，而应来自节点特征聚合算子本身的数学性质**；由于任一单一聚合算子只对一类漂移稳健，需要用专家混合把互补的聚合算子组合起来，并由门控在推理时按当前漂移类型硬选择一个专家。

## 背景：问题的演进

第 I 节与第 II-A 节给出问题链。加密普及使深度包检测失效（引用 Zscaler 报告称 `87.2%` 恶意流量已加密），单流统计法对隐蔽 C2 行为失效，于是图方法兴起（节点=IP，边=流，节点特征=IP 网络上下文，边特征=流统计量）。但图方法遇到新问题：**时序图漂移**。

第 II-A 节的实测（图 1）来自某骨干网运营商 `2025-04-23 00:00` 至 `2025-04-30 20:00` 的真实 NetStream：以 30 秒瞬时窗口统计流数量（代表图规模）与每包字节数（代表流统计量），两者都呈昼夜周期，`05:00` 最低、`15:00` 最高，**流数量最大最小比达 `400%`，每包字节数达 `300%`**。论文据此定义两类漂移：

- **Drift 1 流统计漂移**（flow statistic drift）：拥塞导致的字节数、包数、时长变化。
- **Drift 2 图规模漂移**（graph scale drift）：连接数变化导致的图大小变化。

第 II-A 节同时给出现有路线的失效理由：无监督异常检测（HyperVision、NetVigil）在良性流量本身漂移时误报升高；周期重训（CD-Net 等）依赖昂贵的安全专家标注；数据增强（Rosetta 等）强迫单模型记住所有分布，受限于单模型表达力。

## 方法核心

### 关键洞察：聚合算子决定抗漂移方向（第 II-C 节）

对节点 `u`，设入邻居集 `N_u^in`、出邻居集 `N_u^out`，边特征 `f_(i,u)`，论文式 (1)(2)：

```
h_{u,avg} = ( Σ_{i∈N_u^in} f_(i,u) + Σ_{j∈N_u^out} f_(u,j) ) / ( |N_u^in| + |N_u^out| )
h_{u,deg} = |N_u^in| + |N_u^out|
```

即 `h_avg` 是**边特征的均值池化**，`h_deg` 是**邻接边计数**。论文的机制论证：均值池化对分母（连接数）归一化，因而抗图规模漂移；计数不读取任何流统计量，因而抗流统计漂移。二者各自在对方的漂移下失效。

图 3 用同一 GNN 分别喂 AVG、DEG、AVG-DEG 拼接与 oracle（永远选逐样本交叉熵更低的那个模型）四种特征，在 `no Drift / Drift 1 / Drift 2 / Drift 1,2` 四种测试图上比较 Accuracy 与 F1，oracle 显著超过其余三者——这构成使用 MoE 的动机。

**拼接为什么不行**（第 II-C 节与第 IV-C 节）：其一，会偏向数值范围更大的特征（图 3 中 AVG-DEG 表现接近 DEG）；其二，任一漂移发生时被拼接向量中总有一部分在漂移，反而拖累模型。

### 专家模型（第 III-B2 节）

沿用 NetVigil 的论证（路由器多数情况下只能看到攻击者到被保护目标的直连流量），**1-hop 就够**。专家不做消息传递，直接把节点特征当作 1-hop 信息：

```
e_(u,v),* = h_{u,*} || h_{v,*} || f_(u,v),*          （* ∈ {avg, deg}）
p^cls_(u,v),* = MLP(e_(u,v),*; θ^cls_*)              式 (3)
L^cls_(u,v),* = CE(p^cls_(u,v),*, y_(u,v))           式 (4)
L_cls = (1/|E|) Σ_(u,v)∈E ( L^cls_(u,v),avg + L^cls_(u,v),deg )   式 (5)
```

第 IV-D1 节的消融（图 8）实测：在 Avg-Expert 前加 2/3/4 跳 GCN 层后，无漂移时都正常，但**图规模漂移下鲁棒性严重受损**，且多跳把显存推到原来的 `137%`。理由是多跳聚合了过多不相关邻居。

### 门控的两处改造（第 III-C 节）

**输入侧加图级表示**。传统 MoE 只用样本级特征路由，但样本级信息无法判断样本是否漂移（near-OOD）。举例：白天高流量上训练的 Deg-Expert 会漏掉凌晨低流量攻击，因为凌晨恶意节点的度落进了白天良性度的取值区间。解法是加入图级 readout：

```
g_* = Readout({e_(u,v),*}) = Mean({e_(u,v),*})       式 (6)
p^gate_(u,v) = MLP(g_avg || g_deg; θ_gate)           式 (7)
```

即使单样本的度看起来正常，凌晨的整张图显著更小，门可据此避开 Deg-Expert。

**输出侧改硬选择**。传统「加权求和」有两个问题：需额外训练分类头，提高对泛化能力的要求（而流量标签稀缺、训练集小）；不同专家的隐向量处在不同尺度的隐空间，权重失去物理意义（Deg-Expert 隐向量明显更大，门总给它极小权重）。改为硬选择：

```
y^gate_(u,v) = argmin( L^cls_(u,v),avg , L^cls_(u,v),deg )        式 (8)
mask_(u,v)  = 1( ŷ_(u,v),cls ≠ ŷ_(u,v),avg )                      式 (9)
L_gate = (1/||mask||_1) Σ CE(p^gate_(u,v), y^gate_(u,v)) · mask_(u,v)   式 (10)
```

掩码排除两个专家预测一致（都对或都错）的样本，此时门选谁都无差别。

### 训练（第 III-D 节）

漂移导向的数据增强，与两类漂移一一对应：

```
流统计扰动：F' = F + ε + b,  ε ~ N(0, σ),  b ~ U(-α, α),  σ ~ U(0, β)   式 (11)(12)
随机丢边：  E' = {(u,v) ∈ E | m_(u,v) ≤ a},  m ~ U(0,1),  a ~ U(γ, 1)     式 (13)(14)
```

`b` 刻意取有偏分布以放大漂移程度。两阶段训练：阶段一只用 `L_cls` 训专家（超参 `α1,β1,γ1`），阶段二只用 `L_gate` 训门（超参 `α2,β2,γ2`，且要求 `α2≥α1, β2≥β1, γ2≥γ1`）。第二阶段必须用更强增强，否则两个专家在阶段一都表现优异时门无从学习。实现取 `(α1,β1,γ1)=(0.2,0.5,0.5)`、`(α2,β2,γ2)=(0.0,1.0,1.0)`（第 IV-A3 节）。

论文明确澄清（第 III-D2 节末）：**专家的鲁棒性本质来自节点特征而非数据增强**，第 IV-C 节的消融支持这一点。

## 数据集与实验设置（第 IV-A 节）

- **公开数据集**：NF-CSE-CIC-IDS2018-v3（恶意占 `12.93%`）、NF-ToN-IoT-v3（`38.98%`）、NF-UNSW-NB15-v3（`5.4%`）、NF-BoT-IoT（`99.7%`），来自 Luay 等的时序分析版本。按流到达时间切训练/测试，并对测试图人工施加图漂移以模拟更大漂移幅度。
- **合成数据集**：取 NF-CSE-CIC-IDS2018-v1 的 Infiltration 攻击（单流特征本身不具判别性），恶意占 `50%`；训练图与测试图用**不同的增强参数组**预增强以造出分布差异。
- **真实轨迹**：某骨干网运营商 NetStream，用 IXP Scrubber 打标，恶意约占 `1%`。
- **效率**：MAWI 数据集，共 `6,268,116` 条流。
- **硬件**：单张 RTX 3090（24 GiB）＋ 32 核 AMD Ryzen 9 5950X。实现约 900 行 Python（Pandas / PyTorch / DGL）。
- **基线阈值口径**：HyperVision 与 NetVigil 需阈值，论文取**在测试集上最大化 TPR−FPR 的阈值**，明确承认这偏向基线，用意是给出这两者的理论上界。

## 与本课题的关系

### ① 它的漂移应对机制放在哪一层？

**主要在表示层，辅以决策层；显式回避训练流程层。** 三条依据：

1. 抗漂移的根源是节点特征的聚合算子（式 (1)(2)）——表示层；论文第 III-D2 节明确说「专家的鲁棒性本质来自节点特征而非数据增强」。
2. 门控在推理时按当前图状态硬选择专家（式 (7)(8)）——决策层；且门的输入包含图级 readout 统计量，属于「用聚合统计量做在线决策」。
3. 设计目标第一条就是 **Retraining-free**（第 II-B 节），即刻意不走训练流程层的重训路线；两阶段训练与数据增强只是把上述两层训出来的手段，不是部署后的适应机制。

### ② 对「实体级聚合在训练层＋因果前缀统计量在决策层」是支持、矛盾还是无关？

**支持，且是四篇中唯一在同域（加密恶意流量）同问题（跨时间漂移）上给出可迁移机制证据的一篇。** 但支持中带一条硬约束。

**支持的部分**：

- MalMoE 的 `h_{u,avg}` 就是**实体（IP）级的均值聚合**，`h_{u,deg}` 是实体级计数聚合，二者在监督训练中被固化进专家参数——这与本课题「实体级聚合放训练层」在数学形式与部署形式上同构。MalMoE 用真实骨干网与四个公开数据集证明：**把聚合算子当作抗漂移机制、免重训、且能实时运行，是可行路线**。这为本课题 X4（全容量 MLP O11，完整实体幂平均，LSPR24 实体 AP `0.58548960`）提供了机制来源级的文献支撑，而不只是 MIL 领域的类比。
- 门控输入图级 readout（式 (6)）证明：**在决策层引入聚合统计量来判断当前是否处于漂移态**是有效的（去掉后 ACC_gate 从 `0.8419` 降到 `0.8170`）。本课题在决策层用因果前缀统计量属于同一思路的因果化版本。MalMoE 的 readout 取当前 30 秒窗口全量均值，**不是因果前缀**，因此不与本课题矛盾，只是未占用该空间。
- 全文未出现「训练期前缀时序特征」或任何因果前缀机制，也未在相关工作（第 V 节，覆盖 E-GraphSAGE、DLGNN、Whisper、CD-Net、Rosetta、HyperVision、NetVigil、SNAKE、Hierarchical MoE、GraphMETRO）中提及。**这直接支撑 notes.md 第三节「未见以训练期前缀时序特征作为抗漂移机制的工作」这一缺口论断，并把它从题录级推到全文级。**

**硬约束（必须写进本课题设计，不能忽略）**：

表 II 实测证明**单一聚合算子只对一类漂移稳健**。本课题目前用「完整实体幂平均」这一族算子，其抗漂移覆盖面尚未按漂移类型分解验证。MalMoE 的证据要求本课题至少回答：本课题跨年（LSPR23→LSPR24）的漂移属于哪一类（流统计侧、实体规模侧、还是二者共存）？幂平均随幂次 `p` 变化时，是否也呈现「抗一类、垮另一类」的互补结构？若是，则本课题也应考虑多算子互补而非单算子；若否，则须给出为何幂平均族能同时覆盖的机制解释。**这是可直接落成消融的问题，不是文字担忧。**

**边界**：MalMoE 是流级二分类（边分类），本课题是实体级评价（实体 AP）；MalMoE 的漂移是同一网络内的昼夜周期漂移（小时到天），本课题是跨年攻防演习漂移（年）；MalMoE 的实体聚合服务于流级预测，本课题的实体聚合本身就是预测目标。三处口径差异使 MalMoE 的绝对数字不可直接对比，只有机制可迁移。

## 疑问 / 待验证

- 硬选择门在**两个专家都错**时被掩码排除（式 (9)），训练中不受监督。真实部署中若两个专家同时失效（Drift 1,2 共存），门的行为无定义；表 II 中 `MalMoE (w/o AUG)` 在 `Drift 1,2` 下 ACC 跌到 `0.7188` 正是这一情形，靠增强专家才补回 `0.9194`。本课题若借鉴该门控结构须处理同一缺口。
- 基线阈值取自测试集（TPR−FPR 最大化），论文自称是给 HyperVision / NetVigil 理论上界。这意味着表 I 中 MalMoE 相对这两者的优势是**在对方享有 oracle 阈值的条件下取得的**，比较对 MalMoE 更严苛，可以放心引用；但也意味着 HyperVision / NetVigil 的绝对数字不能当作真实部署性能。
- 论文未报告多种子重复与置信区间，表 I / 表 II 均为单次结果。
