# 问题空间对抗攻击的形式化

> 页码锚点：本地 PDF 共 36 页（正文 27 页 + 附录）。特征空间 vs 问题空间见 §2.1–§2.2（**p.3–11**）；四类约束与副效应特征见 §2.2（**p.5–11**，定义 6–14）；跨域参数表见 §2.3（p.11）；Android 案例的威胁模型与变换见 §3.1–§3.2（**p.12–14**）；保持语义、预处理鲁棒性、合理性见 §3.3–§3.5（**p.14–15**）；搜索策略见 §3.6（**p.15**）；实验见 §4（p.16–20）；**模型硬化见 §5（p.20–22）**；结论见 §9（p.27）。符号表在附录 A（p.32）。

## 一句话

它把"问题空间对抗攻击"从零散经验提升为**可比较的形式化**——四类约束 + 副效应特征——并给出两个对本课题直接有用的判断：**特征空间攻击投影到问题空间后置信度只会下降**，以及**用问题空间样本做对抗训练显著优于用特征空间样本**。

**判定依据**：攻击是**确定性贪心搜索**（§3.6，p.15），没有从检测器反馈中学习的攻击策略；防御侧是**一次性对抗训练/重训**（§5.1，p.20），检测器不与攻击器交替更新。因此属第 1 层，与 CharBot/MaskDGA/Drichel 同层。

**它在台账中的证据角色不是"近邻先例"，而是"约束词汇表的权威出处"**：report (8) 把它列为 semantics / artifact / plausibility 约束的形式化来源。本课题若在正文使用"有效性约束""保持语义""合理性"等概念，应引本文而非自创术语。

## 机制：形式化（§2.2，p.5–11）

**逆特征映射问题**（p.5）：梯度驱动的特征空间攻击难以直接落到问题空间，因为特征映射 $\varphi$ 在软件域**通常既不可逆也不可微**（"feature-problem space dilemma"）。因此问题空间的搜索**不能是纯梯度的**，只能"近似跟随负梯度方向"。

**定义 6（问题空间变换）**（p.6）：$T:\mathcal{Z}\to\mathcal{Z}$，$T(z)=z'$。变换只有三种：**增加、删除、修改**（修改即增删组合；程序混淆是修改的特例）。

**定义 7（变换序列）**（p.6）：$\mathbf{T}=T_n\circ\cdots\circ T_1$。

**四类问题空间约束（定义 8–12，p.7–8）** —— 本文最重要的贡献，作者明确指出这四类此前"被零散提及但从未被作为一组共同识别"：

| 约束 | 符号 | 定义 | 定义号/页 |
| --- | --- | --- | --- |
| **可用变换** | $\mathcal{T}$ | 攻击者能做哪些改动（如图像像素须在 0–255；程序中只能加合法的 no-op API 调用） | 定义 8，p.7 |
| **保持语义** | $\Upsilon$ | 一组自动测试 $\tau$，要求 $\llbracket z\rrbracket^\tau=\llbracket z'\rrbracket^\tau$。语义等价一般不可判定，故**用测试来形式化** | 定义 9，式(4)，p.7 |
| **合理性（不显眼）** | $\Pi$ | 人工审查下须像数据分布的真实成员；**通常难以自动验证**，常靠专家用户研究或"按构造保证" | 定义 10，p.8 |
| **预处理鲁棒性** | $\Lambda$ | 对非 ML 预处理算子 $\mathbf{A}$ 保持不变：$\mathbf{A}(\mathbf{T}(z))=\mathbf{T}(z)$（如图像压缩、程序死代码消除） | 定义 11，p.8 |

**定义 12（问题空间约束集合）**（p.8）：$\Gamma=\{\mathcal{T},\Upsilon,\Pi,\Lambda\}$；$\mathbf{T}(z)\models\Gamma$ 称"有效变换序列"。关键关系：**$\Gamma$ 决定特征空间约束 $\Omega$，记 $\Gamma\vdash\Omega$**，且因部分约束只在问题空间可表达（如"程序大小与良性应用相近"），可视作 $\Omega\subseteq\Gamma$。

**定义 13（副效应特征向量 $\eta$）**（p.8–9）：为满足 $\Gamma$ 而**附带**产生的特征改动。例：想加一个 API 调用以改动某特征，还必须补上合法参数、导入依赖——这些**不是**原意图的特征。作者的观察是：**$\eta$ 不沿任何特定梯度方向，因此对分类分数可能正也可能负**（p.9）。

**投影类比（图 1，p.9）**：把特征空间攻击解 $x+\delta^*$ 投影回 $\Gamma$ 的可行域，会产生 $x+\delta^*+\eta$，即**副效应特征就是投影的产物**。

**攻击置信度的单调性结论**（p.9，可直接引用）：若攻击者在 $\Omega$ 下做**最大置信度攻击**，则投影到问题空间后的攻击置信度**必然不高于**特征空间攻击。

**定义 14（问题空间攻击）**（p.10，式(5)–(6)）：$\arg\min_{\mathbf{T}\in\mathcal{T}} f_t(\varphi(\mathbf{T}(z)))=f_t(x+\delta^*+\eta)$，约束为语义保持。

**跨域参数表**（§2.3，表 1，p.11）：把四类约束在图像、音频、PDF、程序等域的取值并列——用于说明"同一形式化可覆盖不同问题空间"。

## Android 案例：四类约束如何落地（§3，p.12–15）

| 约束 | 具体做法 | 页码 |
| --- | --- | --- |
| 可用变换 | 用**自动软件移植**把良性应用的完整字节码切片注入恶意宿主 | §3.2，p.13 |
| 保持语义 | 把新注入的执行路径**包在恒为 False 的条件语句**里，保证运行期永不执行；并**排除 intent-filter** 作为移植候选（否则会影响应用可见行为） | §3.3，p.14 |
| 预处理鲁棒性 | 用**不透明谓词**（opaque predicates）构造"设计时恒 False、静态分析难以判定"的条件，以对抗死代码消除 | §3.4，p.14 |
| 合理性 | **按构造保证**：注入的是真实良性应用的**完整字节码切片**，而非孤立 API 调用/URL；只在守卫入口处注入少量人工代码；另在 Android 模拟器上安装运行做冒烟测试 | §3.5，p.15 |

**搜索策略**（§3.6，p.15）：贪心两阶段——**初始化（ice-box 构建）**：取分类器 **top $n_f=500$ 个良性特征**，每个取 $n_d=5$ 个候选 gadget，注入最小应用以**预先估计副效应特征**；**攻击阶段**：按"对宿主特征的净负贡献"排序候选，用 `check_feasibility` 过滤（经验规则：最多新增 1 个权限、不新增危险权限），最后一次性移植并复核约束。

## 模型硬化结果（§5，p.20–22）——本课题的直接对照

**两种防御的定义**（§5.1，p.20）：

- **对抗训练（adversarial training）**：在训练过程中**持续生成**对抗样本并混入，式(13) 为标准的 min-max 形式。
- **对抗重训（adversarial retraining）**：**用攻击 A 一次性生成对抗集 $D_a$**，与原始训练集合并得 $D^*=D\cup D_a$ 后重训。作者明确指出这与经典对抗训练不同（后者持续生成）。

**结果**（§5.2–§5.3，p.21–22）：

- **对抗重训一致失效**：对采用该策略的模型，攻击者始终能生成高置信度对抗样本，**ASR 恒 >95%**；作者称这一结果在不同实验设置与模型上"高度一致"（p.21）。
- **对抗训练有效**，尤其在 **LinearSVM** 上：能显著降低高置信度攻击的 ASR；对低置信度攻击仍有 >20% 的 ASR（p.21）。
- **问题空间样本 ≫ 特征空间样本**：只用特征空间变换硬化的模型，即便在 High-High 配置下也达不到合理鲁棒性；用问题空间变换硬化的可以（p.21）。鲁棒性提升 **10%–60%**，规避所需预算增加 **3%–15%**（p.22）。
- 约可从良性软件中采集 **≈800 个可用 gadget**（p.21）。
- **对 Sec-SVM 的意外发现**（§5.3，p.22）：SVM 比 Sec-SVM 在问题空间对抗训练下改善更大。作者解释：SVM 倾向于集中在一小组关键特征，而 Sec-SVM 的权重钳制把重要性摊平到更宽的特征谱上，**这种"分散"反过来给对抗训练的正向收益设了上限**。

## 可迁移机制

1. **四类约束是"离散空间对抗样本"的通用检查表**（定义 8–12，p.7–8）：可用变换、保持语义、合理性、预处理鲁棒性。**对域名空间可直接对位**：可做哪些字符串改动（可用变换）／域名仍能解析且仍是可注册的合法域名（保持语义）／看起来像真实域名而非随机串（合理性）／对 IDN 归一化、大小写折叠等预处理保持（预处理鲁棒性）。**用这一套词汇而不是自造术语**。
2. **副效应特征 $\eta$ 必须显式承认**（定义 13，p.8–9）：为满足约束而被迫引入的特征改动**不沿梯度方向**，可能反噬。**在离散扰动里，这对应"为了让域名合法/可注册而附带的改动"**——它们可能把攻击推回可检测区。
3. **投影只会降低攻击置信度**（p.9）：这是"特征空间最优 ≠ 问题空间最优"的形式化保证，**可作为"必须直接在问题空间搜索/验证"的论证依据**，而不是仅在特征空间优化后取近似。
4. **对抗重训 ≠ 对抗训练，且前者可被一致击穿**（§5.1–§5.3，p.20–22）：一次性生成对抗集再合并重训的做法，在本文设定下 ASR 恒 >95%。**这条直接支持"一次性静态增广不足"的判断**（与 CharBot §VI-C、MaskDGA §6 的观察同向）。
5. **训练样本的"真实性"比数量更重要**（§5.3，p.22）：作者观察到 ASR 无均匀规律，归因于每批变换点是随机选的，据此提出**"代表性样本的选择比样本数量更关键"**——即用真实问题空间变换生成的对抗样本，其价值高于特征空间上等量的样本。
6. **按构造保证合理性优于事后修补**（§3.5，p.15）：注入真实良性应用的完整切片，使合理性"免费"获得；对比之下注入孤立 API 调用会被识别为无支撑的孤儿代码。

## 不能直接声称内容

- **不能说本文做了双侧共演化**：攻击是贪心搜索、防御是一次性硬化，属四级表第 1 层。
- **不能把其 Android 数字外推到域名空间**：问题是 Android 应用的字节码移植，特征空间是 DREBIN（SVM），与域名分类器的特征、约束、可用变换都不同。
- **不能把"对抗重训失效"当成普遍定律**：这是**在本文的 Android + DREBIN + 无约束攻击者设定下**的实测（§5.2，p.21）；换问题空间需重新验证。
- **不能把"10–60% 鲁棒性提升"当作本课题的预期量级**：其对照、指标（ASR）与预算定义都与本课题不同。
- **本地 PDF 是 arXiv 扩展版（36 页）**，与 IEEE S&P 2020 正式版可能存在篇幅差异；引用正式版须回核。
- **合理性（plausibility）在本文是"按构造保证 + 冒烟测试"**，作者本人指出该约束"通常难以自动验证"（定义 10，p.8）——**不能声称本文给出了合理性的自动判据**。
