# INVARLLM: LLM-assisted Physical Invariant Extraction for CPS Anomaly Detection

> Abshari 等 · UNC Charlotte · arXiv:2411.10918 · 2024-11（v2 2025-06）· 16 页

## 一句话

**"物理"= 物理不变量（守恒律）**——不是微分方程残差。LLM 从系统文档里挖出"哪些变量该满足什么守恒关系"，再用数据验证这些关系，攻击一旦打破守恒关系就触发告警。

## 核心洞察（直接回答"物理是什么"）

这是三篇关键论文里**对开题方向最有指导意义**的一篇。它对"物理信息"的定义：

> Physical invariants = 数学表达式形式的基本物理定律，捕捉过程变量间的本质关系——**质量守恒、能量平衡、热力学原理**——无论运行条件如何都必须成立。

关键点：
1. **"物理"= 守恒律/不变量**，而非 PDE 残差。质量守恒（流入=流出）、能量平衡这类关系，比 TCP 流体 ODE 更有资格叫 physics-informed，答辩质疑最弱。
2. **不变量不必人工写死**：LLM 从部署文档（P&ID 管道仪表图、传感器语义说明，如 "FIT201 = 2 号工艺加药站化学流量"）里提取假设性不变量，再用因果检验过滤 LLM 幻觉。这解决了"物理模型需要大量人工工程"的痛点。
3. **检测信号= 不变量回归残差**：滑窗内攻击前后变量相关模式突变 → 回归误差显著上升 → 告警。这和 PINN"物理残差异常"思路同构，但用的是不变量不是 ODE。

## 方法三阶段

1. **Hypo-Invariants 提取**：定制文档解析器 + CoT prompt，让 LLM 输出"模糊函数形式"的不变量假设（指明变量间可能的关系，不写死系数）。
2. **因果验证**：PCMCI+ 启发的 K-means 方法，用历史训练数据检验假设不变量是否真的成立，剔除不附和数据的幻觉/伪不变量。
3. **滑窗回归检测器**：良性+攻击数据同窗时，相关模式前后差异使回归误差跳变，触发告警；并用机制应对概念漂移。

在 SWaT、WADI 两个真实 CPS 数据集上 100% 精度、零误报，超越所有不变量法和数据驱动法。

## 我的理解（对开题方案 B 的意义）

这篇**直接支撑方案 B（流守恒/不变量）优于方案 A（TCP 流体）**：

- "物理"用**守恒律不变量**比用 TCP ODE 更名正言顺，且检测信号（回归残差）天然落在攻击上。
- LLM 在这里的角色是**提取物理约束**，不是端到端判检测——这给开题"大模型"一个清晰的、与 PINN 协同的定位：大模型负责从领域知识/日志语义里提炼不变量，PINN/回归器负责算残差。
- **但有一个根本性 gap 必须正视**：INVARLLM 是 **CPS（水处理/水务）**，那里有真实的物理过程（水流质量守恒、液位平衡）。通用网络流量检测（IDS2018）里，"质量守恒"的对应物是什么？端点采集的流级数据是否可观测"节点流守恒"？**这正是本研究真正的创新空间**——把 CPS 不变量检测范式迁移到通用网络流量，定义网络流量的"守恒不变量"。

## 疑问 / 待验证

- IDS2018 是端点侧 CICFlowMeter 流特征，非拓扑采集，"节点流入=流出"能否定义？还是要换成更弱的不变量（如端口行为一致性、会话对称性、流量熵界）？
- LLM 提取网络不变量时，"文档"对应物是什么？协议规范 RFC？攻击特征知识库？需重新设计输入。
- 与 [[数字孪生约束LLM-CPS异常检测]] 的两阶段架构（启发式初筛→LLM 精判）能否合并为开题的两级流水线？
