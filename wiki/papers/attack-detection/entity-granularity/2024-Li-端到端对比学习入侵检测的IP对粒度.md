# IP 对（主机对）作为检测对象：流内特征正常、流间特征异常

> Li, Lu, Yang, Yan, 2024, *Sensors* 24(7):2122 · MDPI 开放获取

## 一句话

同一段扫描流量，按流看每条都像正常 TCP 握手，按 IP 对看则是短时间内的大量连续 SYN；
判定单元决定了同一份原始数据里哪些特征可被观测到。

## 论文原结论（全文核验，§3.2.1 Capture Packets）

1. **粒度谱系的出处**：论文引 Dainotti 等人（IEEE Network 2012）总结的五种常见流粒度——
   TCP 连接、流、双向流、服务、主机。流由五元组定义；双向流即会话，是最常见的分析粒度。
2. **对「主机」粒度的细化**：Dainotti 把主机粒度定义为「一台主机产生的主导流量，
   前提是能观测到该主机的双向流量」。本文把它细化为**通信双方的 IP 地址对**（源目的可互换），
   原文给出的理由是这样「比用单台主机的 IP 作为检测对象更相关」。
3. **IP 对粒度的关键优势**（原文）：「IP 对粒度包含多个会话，因而能反映**流间特征**。
   尤其对 PortScan 与 DoS 攻击，它们的**流内特征更接近正常流量，而流间特征呈现明显异常**。」
4. **图 2 给出的具体机制**：PortScan 的每条流都以一个 TCP SYN 开始、随后收到 ACK 或 RST，
   这在良性流中同样会出现；但在 IP 对粒度上，短时间内出现大量连续 SYN，异常一目了然。
5. **论文自己的边界表述**：IP 对粒度被定位为「**流粒度与会话粒度的补充**」，
   在具有明显流间特征的攻击上有优势——不是全面替代。

## 本课题可迁移的机制

- 这是「为什么单条流的信息不足以判定」的**可直接引用的机制性证据**，且给出了具体协议行为例证。
- 「IP 对比单主机 IP 更相关」这一句可用于解释本课题为何在主机与主机对之间做粒度选择。

## 不可直接声称的内容

- 论文**没有做逐流 vs IP 对的告警量或误报量对照实验**，也没有报告运维处置成本。
  不得用它支撑「实体级把告警压缩了多少倍」。
- 论文自述 IP 对粒度是补充而非替代；引用时不得写成「文献主张应放弃逐流判定」。
- 评估数据集为 CIC-IDS2017 与 CSE-CIC-IDS2018，两者的已知标注与设计缺陷
  （见本库 Arp 2022、Flood 2024 笔记）会影响其绝对数字，不宜引用其 99.9% 准确率。

## 仍需实验验证的假设

- 在加密流量与 LSPR 系列上，IP 对粒度相对单主机粒度是否同样更优，本文未涉及，属待验证。
