# WEB-IDS23：网络入侵检测数据集生成技术报告

> Eric Lanfer、Dominik Brockmann、Nils Aschenbruck，2025，arXiv:2502.03909v1，4 页。

## 一句话

WEB-IDS23 的独特价值是同时发布六组 HTTP/HTTPS 成对攻击与同服务良性流量，可以测试加密是否改变攻击可检测性；它不提供队列物理真值，也没有足以安全分割多流攻击的运行标识。

## 生成环境

论文在 OpenStack 中搭建两个虚拟网络，通过运行 Zeek 的路由器监测流量（PDF 第 2 至 3 页）：

| 区域       | 节点                            | 用途                         |
| ---------- | ------------------------------- | ---------------------------- |
| 外部区     | 5 个客户端                      | 在不同迭代执行良性与攻击动作 |
| 内部区     | Web、SMTP、SSH、DNS、FTP 服务器 | 提供被访问或被攻击服务       |
| 外部互联网 | 两网区均可访问                  | 引入普通 Web 背景流量        |

生成器对请求间隔、文件名、文件尺寸、权限、邮件内容、SSH 命令、扫描目标和攻击参数做随机化。每个客户端在多个迭代中都可执行良性和攻击模式，设计目标是降低单纯记住客户端的风险。论文不说明具体采集日期、迭代数、单次运行边界或随机种子。

## 攻击与加密范围

生成器实现 13 种基础攻击活动（PDF 第 2 页表 I）：

| 服务   | 攻击                                                                   |
| ------ | ---------------------------------------------------------------------- |
| FTP    | 版本指纹、登录暴力破解                                                 |
| HTTP/S | 跨站脚本、SQL 注入、拒绝服务、登录暴力破解、服务端请求伪造、反向 Shell |
| SMTP   | 版本指纹、用户枚举                                                     |
| SSH    | 登录暴力破解，包含成功登录变体                                         |
| 其他   | 端口扫描、两种主机发现扫描                                             |

六种 Web 攻击各有 HTTP 与 HTTPS 文件，可做协议配对诊断。HTTPS 六类共 1,021,519 条，SSH 两类共 68,525 条。数据不含 QUIC、HTTP/3 或 VPN。FTP 与 SMTP 是否使用 TLS 未在论文或 README 中声明，不应将其计入加密子集。

## 文件、字段和标签

Dataverse 1.0 发布 24 个文件：22 个按类拆分的 CSV、`README.md` 和 `README.pdf`，总计 3,285,730,370 字节，约 3.06 GiB。不包原始 PCAP。

每条 CSV 记录是一条 Zeek FlowMeter 流。论文声称有 80 个 FlowMeter 数值特征，加上 `service` 和 `traffic_direction` 为 82 个流量特征。官方 README 还列出：

- `uid`、`ts`、`id.orig_h`、`id.resp_h` 用于流、时间和端点标识；
- 双向包数、包速率、载荷、头部尺寸、TCP 标志、到达间隔、活动/空闲和窗口统计；
- `attack` 二元标签和 `attack_type` 细粒度标签。

`uid`、时间、IP、文件名和两个标签字段只能用于分组与审计，不得进入模型提示。

## 类别分布与数据契约矛盾

论文表 II 的 22 个文件标签合计 12,059,749 条流：

- `portscan` 5,046,406 条，占 41.85%；
- `hostsweep_Pn` 3,492,290 条，占 28.96%；
- 前两类合计占 70.80%；
- `benign` 825,187 条，占 6.84%；
- `smtp_enum` 仅 7 条。

论文和 README 均声称“21 个类标签，20 种攻击”，但论文表 II、README 标签表和 Dataverse 实际文件均为**21 个攻击文件标签加 1 个良性标签**。这是原始发布的计数矛盾，不应在适配时静默修正。

## 论文原结论

1. 模块化流量生成器可以在同一服务上混合良性与攻击动作，并通过随机化增加变化。
2. 细粒度攻击标签有助于暴露二元或宽泛家族标签遮蔽的过拟合问题。
3. 数据为全合成、协议范围受限，不能代表生产网络。
4. 反向 Shell 和服务端请求伪造需要结合结果流，但本数据没有记录触发流与结果流的因果关系（PDF 第 3 页）。

## 本课题推论

以下不是作者原话，而是基于文件和方法契约的实验判断：

1. 文件名直接编码类别，不能将 `source_file` 或文件顺序进入模型。
2. 论文未发布攻击迭代或运行 ID。对行做随机划分可能使同一攻击运行的相关流进入两侧。
3. 某些攻击在单流上理论不可辨，若单流模型得到极高分数，应先审计端点、服务、时间和生成器捷径。
4. 只适合在冻结 GeNIS 模型和阈值后执行二元域外测试。SQL 注入、XSS、SSRF、反向 Shell、扫描和枚举超出当前家族标签空间。

## 与现有 Qwen + PINN 的关系

WEB-IDS23 与 HIKARI 使用同一 Zeek FlowMeter 字段族，可派生当前 `canonical_core_v1` 的 8 个字段：包数、字节、包长均值/最小/最大值、平均到达间隔、包速率和字节速率。各数据集的字节层和聚合单元仍需显式记录，不能只因为字段同名就宣称物理语义一致。

数据没有队列长度、链路容量、入队量、出队量和丢弃量真值。它只能提供公开观测和检测标签，不能监督当前五锚点状态头或有限队列守恒残差。

## 可迁移机制

- HTTP/HTTPS 同攻击配对可用来检查模型是否依赖明文协议细节。
- 同服务良性与攻击混合可用于服务匹配误报评估。
- 论文对多流攻击不可辨性的警告可转化为强制的单流/会话级对照。

## 不可直接声称

- 不能声称 WEB-IDS23 是真实企业攻击流量。
- 不能把 12,059,749 条流解释为 12,059,749 次独立攻击或会话。
- 不能把 HTTPS 与 SSH 之外的全部文件称为加密流量。
- 不能把流统计中的丢包或重传类特征当成 ns-3 队列丢弃真值。

## 待验证

1. 实际 CSV 全部表头、时间单位、字节口径和缺失率。
2. `ts` 的时间间隔能否稳定恢复攻击运行边界。
3. IP/服务/时间是否与 `attack_type` 存在近确定性关联。
4. 良性文件内 HTTP、HTTPS 和 SSH 的可用数量，以及能否构造服务匹配对照。

## 原始摘要要点

作者针对现有入侵检测数据标签过粗、小类样本过少和攻击过时的问题，开发可随机化的模块化流量生成器，并发布超过 1,200 万条流、82 个流级特征与细粒度攻击标签。该段为 PDF 第 1 页摘要的中文转述。
