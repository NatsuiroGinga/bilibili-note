# QUIC 流量入侵检测：一种机器学习方法

> Al-Bakhat & Almuhammadi，2022，IEEE CDMA · 会议论文 6 页（p.194–199），沙特法赫德国王石油矿业大学

## 一句话

这是目前与本课题最接近的"QUIC 上的 C2 检测"工作，但它的高准确率建立在一个存在明确划分前重采样泄漏的协议上：SMOTE 与归一化先于 70/30 随机划分执行，恶意类由 940 条真实流被合成到 2820 条，测试集恶意侧的多数样本并非真实流量；再加上单一 C2 服务器、无捕获会话或主机分组、人工 1:1 平衡且不报每类召回与误报率，其数字只能作为"该任务可分"的存在性证据，不能作为性能参照。

## 背景与任务定义

- QUIC 默认加密且跑在 UDP 上，主流开源 IDS/IPS 无法检查用于判定恶意行为的报文细节（引 SANS 的 Decker 2020，p.194 引言）。作者由此提出基于统计指纹的网络侧检测。
- 两个任务：
  1. **C2 vs 正常浏览**（二分类，§VI.A，p.198）。
  2. **C2 内部命令类型识别**：执行 shell 命令（cmd）、从被控端下载文件（download）、向被控端上传文件（upload），三类（§VI.B，p.198）。
- 定位：网络侧、逐流、监督分类。不涉及主机侧、实体级聚合或告警预算。

## 数据集：自建，不公开

测试床为四台虚拟机（Figure 2，p.196）：

| 角色 | 配置 | 流量生成方式 |
| --- | --- | --- |
| VM1、VM2 | Ubuntu 20.04.1 | Selenium WebDriver + subprocess 自动访问支持 QUIC 的站点（Google、Cloudflare、YouTube），并模拟搜索后观看首个视频 20 秒；Chrome 与 Firefox 手动开启 QUIC（p.196） |
| VM3 | 被控主机 | 运行 Merlin C2 agent |
| VM4 | Kali Linux | Merlin C2 server v6.0，443 端口，参数指定 QUIC；由 pexpect 脚本自动执行下载/命令/上传（p.196） |

抓包用 Wireshark 保存 pcap，再转 CSV 提取指纹。

**规模（§V.A，p.197）**：

- 原始数据集"共 6980 条实例，其中 5968 条良性、940 条恶意，约 14% 为恶意"。
- **数字不自洽**：5968 + 940 = 6908，与文中写的 6980 差 72。按 940/6908 = 13.6% 与"约 14%"更吻合，推测 6980 为 6908 的笔误，但论文未给出可核对的分项，无法确认。
- 平衡后：SMOTE 过采样恶意类 + 随机欠采样良性类，得到每类 2820 条、合计 5640 条。
- 数据集与代码均未提供任何下载链接、仓库或许可证；全文无数据可用性声明。

## 指纹特征

表 I（p.196）给出 12 个流级特征，流由五元组 (ip_src, ip_dst, port_src, port_dst, protocol) 定义、双向：

- 方向包数：`Pkt_k^AB`、`Pkt_k^BA`，总包数 `n_k = Pkt_k^AB + Pkt_k^BA`
- 包长：最小 `∧L_k`、最大 `∨L_k`、均值 `L̄_k`
- 到达间隔：最小 `δ_k`、最大 `Δ_k`、标准差 `σ_k`
- UDP 段长：最小 `∧U_k`、最大 `∨U_k`、均值 `Ū_k`

缩减后的 7 特征集为 `{Pkt_k^AB, Pkt_k^BA, L̄_k, Δ_k, δ_k, σ_k, Ū_k}`（§V.A，p.197）。剔除理由：`n_k` 可由前两项直接导出；其余为零方差常数列。

**流时长未纳入指纹**，作者在 §VII（p.198–199）自陈这是缺陷。

**表 IV 内部矛盾（审计发现，非论文自陈）**：表 IV 的"C2 Commands / 缩减"行与"C2 vs Normal / 缩减"行逐位完全相同，且与表 III 的 Precision 行（98.90 / 98.78 / 99.56 / 85.06 / 80.51 / 85.06）不一致。§VII 正文（p.199）称命令分类下"AdaBoost 与 MLP 的精确率分别下降约 4% 和 8.5%"；用表 III 的 AdaBoost 80.51、MLP 85.06 与表 IV 完整列的 84.88、76.54 相减，得 −4.37 与 +8.52，量级与正文吻合（AdaBoost 实为上升而非下降）。据此推断表 IV 的"C2 Commands / 缩减"整行是复制粘贴错误，其真值应为表 III 的 Precision 行。论文中该表未经修正。

### 超参数与训练细节（§V.B，p.197）

- 70% 训练 / 30% 测试，无随机种子、无分层说明、无交叉验证、无重复次数、无置信区间。
- KNN 扫描 k = 1…10，最优 k = 1（k=1 的最近邻在含 SMOTE 合成样本的数据上极易记忆插值点）。
- AdaBoost 默认基学习器（深度 1 决策树）效果不佳，改用 SVC 后"准确率提高约 36%"。
- MLP 网格搜索最优：三隐层 (10, 30, 10)、100 轮、ReLU、Adam、alpha = 0.05。
- 论文把 MLP 描述为"a class of unsupervised, feed-forward neural networks"（p.197），属技术表述错误。

## 协议缺陷核验（本课题审计，非论文自陈）

按任务要求逐条核验，以下四点是必须明确指出的：

1. **划分前重采样导致的泄漏（最严重）**。§V.A 的预处理阶段包含 cleaning → labeling → balancing（SMOTE + 欠采样）→ 特征约减 → normalization；§V.B 随后写"we used 70% of the dataset obtained from the pre-processing phase for training"（p.197）。即 SMOTE 在划分**之前**执行。后果：恶意类由 940 条真实流被扩到 2820 条，合成样本按最近邻插值生成，母本与合成体会被随机分到训练与测试两侧；测试集恶意样本中约 (2820−940)/2820 ≈ 67% 并非真实抓包流量。表 II/III 的恶意侧指标主要在合成点上测得，KNN(k=1) 达到 99.67% 与这一泄漏路径高度一致。
2. **归一化在全量数据上拟合**。Min-max 缩放到 [0,1] 同样列在预处理阶段（p.197），先于划分，缩放统计量包含测试集信息。相比第 1 点属次要泄漏。
3. **逐流随机划分，无捕获会话/主机/时间分组**。一次 Selenium 自动化会话或一次 pexpect C2 会话产生的多条流会同时落入训练与测试。论文未报告流数与会话数的对应关系，无法排除会话指纹被记忆。
4. **生成环境捷径**。良性流全部来自 VM1/VM2 的两款浏览器访问 Google/Cloudflare/YouTube，恶意流全部来自 VM3↔VM4 的 Merlin 443 端口。§VI.A（p.198）自述 Merlin 包长被切成 52–1280 字节、平均 UDP 段长 400–500 字节，而正常浏览可达 1378 字节、平均约 1400 字节——分类器很可能只学到了"Merlin 默认 MTU 配置 vs 浏览器/CDN 配置"这一条捷径，而非 C2 语义。作者自己也承认这些值"不是常数，可从 Merlin 配置修改"。

**准确率是在什么类别平衡下报的**：人工 1:1（2820 : 2820）。原始比例为 13.6%（940/6908），真实网络中 QUIC C2 占比远低于此。论文**未报告任何误报率、每类召回、混淆矩阵或告警预算**；表 II/III 中 Accuracy 与 Recall 数值完全相同，是加权平均（weighted average）的典型特征，说明报的是加权指标而非恶意类单类指标。因此这些数字不能外推到任何现实先验下的部署性能。

## 作者自陈局限（§VII 讨论、§VIII 结论，p.198–199，原样记录）

- 分类只在**一个** C2 服务器上完成；要验证指纹的泛化性，需要在更多配置不同的 QUIC C2 服务器上测试。
- 指纹重度依赖统计分析；若 C2 流被修改为模仿常规客户端-服务端通信行为，就可能混入正常流量并逃避检测。
- 构成指纹的特征是**可变的（mutable）**，因此更有用的做法是把统计指纹与其他检测方法结合，例如调查持久连接——持久连接指示潜在 C2。
- 时间是识别 C2 流量的重要因素，但本方法的指纹**未考虑流时长**；加入时长与每流累计时间有助于识别持久 C2 连接。
- 未来工作：在更多 C2 服务器的 QUIC 流量上验证指纹；扩展到更复杂攻击如远程访问木马（RAT）。

## 与相关工作的关系

- 统计指纹谱系：Crotti 2007（包长/间隔/到达顺序三特征，仅 HTTP/SMTP/POP3）→ Dusi 2009 Tunnel Hunter（隧道检测约 90%）→ Boero 2017 SF-IDS（14 特征）→ Ahmed 2019（DPMM 聚类，DDoS 峰值 97%）。本文把这条线搬到 QUIC/UDP 上，特征集与 Crotti/Boero 同源。
- 与 [[H23Q-HTTP3与QUIC攻击数据集]] 的差别：H23Q 是公开的 HTTP/3 与 QUIC 攻击 PCAP 数据集（10 类攻击 × 6 服务端），本文数据不公开且只有一种 C2 框架。
- 与 [[VisQUIC加密QUIC流量数据集]]、[[QUIC隐蔽信道流量数据集]] 同属 QUIC 侧信道/统计特征方向，但本文是唯一直接做 QUIC **C2** 检测的。

## 与本课题的关系

本课题当前正从四个被否决的自研 P0 转向"基于他人已有工作提出改进"，本文与三个候选方向的关系如下：

- **方向 1（LSPR 跨年度、实体级 + 固定告警预算）——关系最强，是可直接引用的负面先例**。本文与 Känzig 2019、Gehri 2023 一样是 QUIC/C2 场景，但停留在逐流评价，且在此之上叠加了划分前 SMOTE。它恰好提供了"逐流 + 人工平衡 + 无误报预算"这一评价范式的失效样本：在只有一个 C2 服务器、一次生成流程的条件下，逐流准确率可以做到 99.67%，却对"能不能在真实告警预算下发现这台 C2 服务器"完全无信息。可用于论证实体级 + 固定预算评价的必要性——注意这是与 Känzig（30 分钟窗口内 12 台 C&C 命中 10 台，Discussion 节附加实验）互补的**反面**证据，不是同类正面先例。
- **方向 2（GeNIS 场景组隔离，量化随机行级划分的假饱和）——关系强，机制同构**。本文是"随机行级划分 + 划分前重采样 → 接近饱和的分数"的又一实例，且比 GeNIS 更极端（重采样泄漏叠加在随机划分之上）。可作为"假饱和"论证的第二个案例，说明该问题不限于某一个数据集。
- **方向 3（TQH-C2 的 interval × jitter 受控网格与跨传输协议迁移）——关系中等，提供缺口而非方法**。本文明确指出流时长与时间特征未纳入指纹、Merlin 包长可从配置修改、单一 C2 框架无法验证泛化，这三点正是 TQH-C2 受控网格要填的空：TQH-C2 用 48 格 interval × jitter 系统扫描本文只用单一默认配置覆盖的参数空间，B/D 受控对则回答本文完全没碰的跨传输协议问题（本文只有 QUIC，无 HTTP/2-over-TLS 对照）。

## 可迁移的机制

1. **7 维缩减指纹**（双向包数、平均包长、最大/最小到达间隔、间隔标准差、平均 UDP 段长）是极轻量的 QUIC 流表示，可作为本课题实体级实验中"最弱可用流特征"的对照基线——但必须在正确划分下重测，本文报的数字不可复用。
2. **"持久连接是 C2 指示"这一作者建议**（§VII）与本课题的实体级聚合方向一致：本文因为丢掉时长而无法利用，本课题若在实体级引入连接持续性与周期性，正好补上该缺口。
3. **可变特征的对抗边界**：作者承认包长与 UDP 段长可由 Merlin 配置改变。这支持本课题把"配置扰动下的鲁棒性曲线"（方向 3 的 interval × jitter 网格）设为评价维度，而不是只报单点分数。

## 不可直接声称

- 不得引用"98% 平均准确率"作为 QUIC C2 检测的可达性能参照或对比基线。该数字来自划分前 SMOTE、人工 1:1 平衡、单一 C2 框架、无误报率报告的协议。
- 不得称本文验证了指纹的泛化性——作者自己明确否认（只测了一个 C2 服务器）。
- 不得称本文提供了可复现资源：数据、代码、划分种子均未公开。
