## 一句话

作者把「浏览器开不开 QUIC」当作唯一变量做了 1023 对配对实验，发现长期聚合指标看不出差别、但逐会话看有近八成显著不同且方向对半开；他们没有停在相关性上，而是用 Granger 因果检验把矛头指向 QUIC 在低带宽下频繁回退 TCP 这一机制。

## 研究问题（印刷 p.3）

作者列出四问：
1. QUIC 支持的浏览器上回退发生得多频繁？是否只在中间盒封 UDP 时发生，还是网络条件差时也会发生？
2. 在重尾网络上，QUIC 相比 TCP 的长期性能如何？
3. 短期或瞬时性能是否受影响？
4. QUIC 为适应中间盒而设计的回退行为，对视频 QoE 的损害有多严重？

背景机制（印刷 p.2、p.5–6）：Chrome 会同时赛跑一条 TCP 连接与一条 QUIC 连接，但把 TCP 那条延后 300 ms；谁先建成用谁。QUIC 握手失败（被封或握手包超过 MTU）时，QUIC 被标记为 broken 一段时间（指数退避），期间请求全走 TCP。作者的核心观察是：**回退机制并不检查失败是不是中间盒造成的**，所以在丢包重尾的网络上，UDP 承载的握手包失败而 TCP 握手成功，也会触发回退。

## 实验设计

- 视频：46 个，时长 2400–6000 秒（40 分钟至 1 小时 40 分），涵盖新闻、娱乐、教育、脱口秀、喜剧、Stanford 公开课、英剧（印刷 p.9 表 2）。最低画质 144p，最高 720p。
- 带宽整形：Mahimahi `mm-link`，5 种模式（印刷 p.11 表 3）：Incr（128→2048 Kbps，每 60 s +64）、Decr（2048→128 Kbps，每 60 s −64）、Dynamic High（1152→896 Kbps，每 240 s −256）、Dynamic Low（640→128 Kbps，每 240 s −256）、Dynamic Very Low（64→256 Kbps，每 60 s +64）。静态标定结果：< 128 Kbps 全程 144p，> 1500 Kbps 全程 720p（印刷 p.11）。
- 地点：德里、班加罗尔、纽约、德国、新加坡；一个测试床在校园内，其余在 Digital Ocean（x86_64，2494.136 MHz，4 GB RAM，Ubuntu 18.04）（印刷 p.9–10）。
- 一个诚实的排障记录（印刷 p.10）：一开始所在机构防火墙封掉全部 QUIC 流量，导致即使指定 QUIC 也全走 TCP；作者加了防火墙例外，并核对 QUIC 包小于路径 MTU，才开始正式采集。
- 日志：自写 Chrome 扩展记录四个事件（BEFORE_REQUEST / SEND_HEADERS / RESPONSE_STARTED / COMPLETE），从 `videoplayback` 请求取 itag、rbuf、clen、dur、下载速度与实际使用协议，从 `qoe` POST 请求取播放统计（印刷 p.12）。
- QoE 定义（印刷 p.14）：`QoE = 平均码率 − 平均码率变化 − 4.3 × 平均卡顿`，沿用 Pensieve。**作者明确拒绝对整段会话取单一均值**，理由是均值无法捕捉瞬时变化，因此每个会话产生多个时刻 QoE 值（印刷 p.14–15）。

## 关键数字

### 一、回退有多普遍（印刷 p.15–16）

- 每个 QUIC-enabled 会话的**最初若干秒完全走 TCP**，QUIC 甚至不尝试建连：高带宽约 1 秒，低带宽约 10–12 秒（印刷 p.15）。
- 握手重试次数随带宽下降而上升：DH 重复 1–2 次、DL 2–3 次、DVL 3–4 次才建连成功（印刷 p.15）。
- 极端情况下客户端 3–4 次重试后仍失败，IP 层发 ICMP 错误后转 TCP SYN；此时 QUIC 被标记为 broken，**约 600–1000 秒内不再有 QUIC 包**，这段时间全部数据走 TCP（印刷 p.15）。
- 各带宽模式下 TCP 字节占比（图 5(b) 的 CCDF，印刷 p.16）：Incr 模式下 50% 的时间有 ≥2% 字节走 TCP；Decr 与 DH 分别有 78%、60% 的时间几乎没有 TCP 流量；**DL 与 DVL 分别有 50% 和 67% 的时间有 ≥40% 的字节走 TCP**。

### 二、聚合 vs 个体（本笔记要借的核心现象）

- 全部 1023 对会话的归一化 QoE 分布对比：**差别很小**（印刷 p.16 §4.2，图 6(a)）。
- 逐会话假设检验（双尾检验，零假设为两者统计相同，印刷 p.17 §4.3）：
  - 20.5% 的会话对两者表现相似；
  - 79.5% 显著不同；
  - 其中 **41% 是纯 TCP 更好**，**38.5% 是 QUIC-enabled 更好**。
- 分指标（印刷 p.18 图 8(b)）：平均播放码率与码率变化上 TCP 在 41% 的情形更好；**卡顿上 QUIC-enabled 在 51% 的情形更差**，作者点名这与既有报告「QUIC 卡顿减少 9%」相反（印刷 p.18）。
- 分带宽（印刷 p.19–20 图 10(a)）：DL 与 DVL 下 TCP 在超过 40% 的会话对上更好。
- 分地点（印刷 p.20 图 10(b)）：五个地区全都有超过 30% 的场景是 TCP 更好；德里与纽约的 QUIC-enabled 流中 TCP 流量比例更高，对应地这两地 TCP 更占优。
- 分月份（印刷 p.21 图 11）：40% 的时间，TCP 字节占比超过 9%（10 月）、24%（1 月）、51%（9 月）、59%（11 月）、61%（12 月）。作者据此称观察跨时间一致。
- 单视频重复 32 次（同一娱乐类视频、DVL、不同日期与时段，印刷 p.20–21）：仍出现 S1 场景 TCP 更好（p<0.05）、S3 场景 QUIC 更好（p<0.05）的分裂，且 S1 的 TCP 字节占比明显更高（50% 的时间 ≥10%，S3 只有约 1%）。**同一视频、同一整形、只差日期，结论就翻转。**

### 三、相关与因果（印刷 p.4、p.22–23）

- 建模（印刷 p.22）：把回退定义为时间序列 `F_v(t) = T(t) / (T(t) + Q(t))`（截至 t 时刻 TCP 字节占总字节的比例）；画质下降 `B_v(t)` 用质量等级映射（144p→1 … 720p→5）乘以该等级持续时长构造；卡顿 `S_v(t) = t − π(f_t)`。
- 作者显式讨论了**三条时间轴**（真实时钟、播放时间、下载时间）以及由此产生的滞后：回退的影响可能在回退发生后很久才显现，所以必须做带滞后的互相关（印刷 p.22）。
- 互相关结果（印刷 p.23）：约 50% 的视频相关系数 ≥ 0.55；滞后值分布在 250 秒以内。
- Granger 因果结果（**只在印刷 p.4 的贡献列表中给出，正文对应部分在还原范围之外**）：回退在近 20% 的会话上 Granger 引起画质下降、近 60% 的会话上引起卡顿，合计 70% 的会话上引起二者之一。
- 作者的方法论纪律值得抄：只在「纯 TCP 明显更好」的那批会话上做因果分析（印刷 p.4、p.21），而不是在全体上做——**先用假设检验切出失败子集，再在子集里找机制**。

## 与本课题的关系

以下第 1 点是引用边界，第 2–5 点为本课题推论，均未在本课题数据上验证。

1. **可引用边界**：本文与恶意流量检测无关，不能用于任何检测性能论断。且由于原件残损、题名与出处未核，**当前状态下不得进入论文参考文献**。它只能作为内部方法论材料与「协议标签污染」的提示。

2. **证据类型 (b)（分布漂移下的受控测量）——形式相关但对象不同**：本文测的是同一时段内两种协议配置的差异，不是跨时间漂移。它对本课题的真正提示是**聚合指标的欺骗性**：1023 对会话的总体分布几乎重合，逐对检验却有 79.5% 显著不同、且方向对半分。本课题当前的实体级 AP 0.5233–0.5475 是同一类聚合数字。**待验证假设**：若把实体级结果按实体做配对比较（同一实体在两种方法下的得分），是否也会出现「总体持平、个体分裂」？最小验证实验：逐实体计算两种方法的排名差，画分布而不是只报 AP。

3. **可迁移机制：标签与观测的口径污染**。本文最尖锐的一处是对既有工作的批评（印刷 p.8–9）：Seufert 等人采集了 900 个视频最终只用 500 个，声称已检查这些流「要么走 TCP 要么走 QUIC」；本文作者认为其中一部分 QUIC 流正是因为回退而含有大量 TCP 包才被丢弃。**即「按配置打标签」与「按实际承载协议打标签」不是一回事，而中间的差值恰好与网络条件相关，因此丢弃它们会引入选择偏差。** 本课题的对应风险：LSPR 数据里若按主机角色、端口或采集配置打标签，而实际行为与标签在困难样本上系统性不一致，被丢弃或被误标的正是最有信息量的那批。这一点值得在数据合同里显式检查。

4. **可迁移机制：两步走的归因流程**。先做逐单元假设检验切出失败子集 → 在子集内建时间序列 → 先互相关（含滞后搜索）→ 再 Granger 因果。本课题若要论证「实体级聚合为什么有效」，同样应当先切出「逐流失败但实体级成功」的子集，再在子集里找共同结构，而不是在全体上做相关分析。

5. **可迁移机制：显式承认三条时间轴与滞后**。本文因为播放时间 ≠ 下载时间 ≠ 真实时间而专门处理滞后。本课题的跨年度设置里同样存在多条时间轴（流开始时间、标签生效时间、实体首次出现时间），当前的因果前缀均值 `ctx=cumsum(h)/cumsum(mask)` 隐含假设它们对齐。这个假设是否成立、是否有滞后，属于**待验证假设**。
