# QUIC 时代的入侵检测机器学习适配

> Kadi、Khoukhi、Viinikka、Fabre，IEEE TNSM 22(2):1929–1944，2025 年 4 月。ENSICAEN / UNICAEN / CNRS / GREYC（Normandie Université）与法国 DDoS 防护厂商 6cure 的 CIFRE 产学合作（p.1929 脚注与作者简介）。
> 投稿 2024-03-26，修回 2024-08-29，录用 2025-02-04，在线 2025-02-21（p.1929）。
> 本文是作者 GIIS 2024 会议论文 [4]（"Machine learning for QUIC traffic flood detection"，DOI 10.1109/GIIS59465.2024.10449925）的期刊扩展版（p.1930）。

## 一句话

这是 QUIC 侧目前最新的期刊级 IDS 工作，它最有价值的部分不是那组接近满分的指标，而是它把「TLS 时代不可见、QUIC 时代可见」的观测量（长包头 QUIC 包类型、spin bit、UDP 数据报层方向与节律）系统地工程化成了一套流级特征；而它的评价协议是典型的单环境仿真 + 随机划分，八个模型 AUC 全部为 1.00，作者自己在正文中两次要求谨慎解读。

## 任务定义

- 任务不是漂移适应、不是跨年度迁移、也不是 C2 检测，而是**同一次受控仿真内的逐流监督分类**：判断与 HTTP/3 Web 服务器交互的每条双向 QUIC 流是 bot 攻击流还是正常流（p.1929 摘要、p.1935 §IV-C）。
- 落点是过滤规则：作者在 §IV-C 明确写道，对监控流量中检测到的每条流预测其恶意/良性，"以便基于 IP 地址和端口实施过滤规则"（p.1935）。
- 两种标签粒度（p.1936 §V-A）：
  - Dataset 1（二分类）：正常流 vs 攻击流（GET Flood、QUIC 连接尝试、Scan 合并成一个标签）。
  - Dataset 2（四分类）：Normal / Scan / GET Flood / QUIC Connect。
- 标签由 IP 地址直接给出：作者控制仿真环境中每台虚拟机的 IP，bot VM 与正常用户 VM 的地址已知（p.1934 §III-B）。

三类攻击（p.1934 §III-C-2）：

- **HTTP GET Flood**：单条 QUIC 连接上持续发送高速率 HTTP/3 GET，形成一条强双向流。
- **QUIC Connection Flood**：反复从不同源端口打开大量 QUIC 连接但不发后续数据，饱和服务器连接处理能力，形成多条并发双向流。
- **HTTP Scan**：每条连接发一个 GET 后立即新建连接，形成多条短双向流。

## 与 TLS 时代的差异处理（本文最可复用的部分）

作者在引言中先把问题定位为可见性丧失：Wireshark、Suricata、Snort 等传统 IDS/IPS 因 QUIC 的 TLS 1.3 内建加密与 UDP 承载而缺乏必要可见性；文中列举了三条既有路径——Zeek 自定义脚本（可识别 Merlin 等 C2 框架的 QUIC 流量）、ipoque DPI 的 Encrypted Traffic Intelligence、以及传统工具的直接困难（p.1930）。

其应对方式是把观测下沉到 UDP 数据报层，只保留在加密后仍然可见的字段（p.1934 §IV-A、图 2）：

1. **QUIC 包类型**：Initial / Handshake / 0-RTT / 1-RTT / Retry / Version Negotiation，六维 one-hot（表 II，p.1935）。这依赖长包头未加密部分，是 TLS-over-TCP 侧不存在的观测量。
2. **包方向**：进/出服务器。
3. **数据报大小**（字节）。
4. **时间戳**。
5. **Spin bit 值**——QUIC 显式暴露的延迟测量位，TLS 时代无对应物。

流的定义也随协议改变（p.1935 §IV-B）：由于 QUIC 跑在 UDP 上没有连接状态可跟踪，作者以「与虚拟机 443 端口通信的报文的源 IP + 源端口」为键聚合双向流，进包取源 IP/源端口、出包取目的 IP/目的端口更新代理列表。

作者用整整一页（图 3，p.1936）讨论 NAT 造成的实体归属歧义：NAT 网关后多个代理的流会表现为同一公网 IP，无法判断两条流来自两个代理还是同一代理的两条流。其处理方式仅是"用 IPv6 地址识别一台设备、用 IPv4 地址加源端口识别另一台"（p.1935），并未给出通用的实体聚合方案。

解析实现为 Rust + `pcap-file` + `etherparse`，建模为 Python + scikit-learn（p.1934 §III-B、p.1941 §VI-C）。

## 作者自陈局限（原样记录）

1. 关于 AUC 全为 1（p.1940 §VI-A 末）：作者写道，这一结果说明数据集高度可分、类别界限清晰；虽然从模型性能角度看是理想的，但必须考虑过拟合的可能性，尤其是在模型于训练所用的同一批数据上被评估时。
2. 关于仿真数据的外部效度（p.1940 §VI-B）：作者写道，本分析所用数据来自受控仿真，用于模拟与 HTTP/3 Web 服务器之间的各类双向流；仿真产生了多种场景来表示不同行为，但这些仿真数据可能与真实条件不同。因此，虽然过拟合与泛化的评估在该仿真语境下是有效的，结果仍应谨慎解读；它们给出的是该特定配置下的模型表现指示，并不必然保证在真实条件下取得等同结果。完整验证需要在真实环境中进一步测试。
3. 关于真实环境的额外挑战（p.1941）：作者写道，真实世界环境可能带来额外挑战——真实数据可能噪声更大、类别界限更不清晰、攻击模式比仿真中更加多样；因此尽管结果令人鼓舞，仍需在真实环境中进一步测试，以确保模型在更多样、更不可预测的条件下维持性能。
4. 结论节（p.1943）只声称"某些机器学习方法在识别攻击的双向流上是有效的"，并强调随着协议与攻击方法演化，检测策略必须持续调整，需要进一步研究。

## 与本课题的关系

以下第 1 点为论文原结论的引用范围界定，第 2–4 点为本课题推论。

1. **可直接引用的**：QUIC/HTTP/3 环境下传统 IDS 因 TLS 1.3 + UDP 缺乏可见性（p.1930）；现有 DDoS 数据集普遍不含 QUIC 流量与 QUIC 特有攻击，因为它们多创建于 QUIC 出现之前或之后不久（p.1931 §II）；spin bit 派生特征在 RF/GBM 中具备可观测的判别贡献（表 V，p.1939）。**不可引用为**"QUIC 恶意流量检测已解决"或把 0.999 级指标当作性能参照。

2. **对方向 3（TQH-C2 的 B/D 跨传输协议迁移）——方法来源，非性能参照**：
   - 正向价值：本文给出了一套完整的、只依赖 QUIC 长包头与 UDP 层可见信息的特征工程方案（包类型 one-hot、spin bit 比例、方向熵、IAT 统计、显著时间间隙计数）。这套特征恰好在 HTTP/3-over-QUIC 侧可算而在 HTTP/2-over-TLS 侧无对应物，因此它可以作为"B/D 受控对的跨传输协议迁移不是平凡问题"的文献依据：两侧的可观测量并不同构，共享特征空间必须显式设计，而不是假定同一组流统计量在两个协议上等价。
   - 明确边界：本文的攻击是 GET Flood / Connection Flood / Scan，全部是高速率行为；TQH-C2 的 B/D 是隐蔽 C2 信标。任务性质不同，本文的指标与结论不能用来预测 C2 跨协议迁移的难度或上限。
   - 可借用的具体机制：24 维"显著时间间隙计数"（不同阈值下的包间间隙统计）在信标类周期性行为上有直接适配价值，值得在 TQH-C2 的 interval×jitter 网格上做一次消融。

3. **对方向 1（LSPR 实体级 + 固定告警预算）——第三个"实体级评价缺位"证据点**：
   - 本文在动机层完全承认实体：处置落点是"基于 IP 地址和端口的过滤规则"（p.1935），并用整幅图 3 讨论 NAT 后实体归属歧义（p.1936）。
   - 但评价层完全停留在逐流：表 VI 只报逐流 P/R/F1，图 8 只报逐流误报率，全文没有任何实体级检出率、实体级误报或固定告警预算下的指标。
   - 这与既核验的 Känzig 2019 §5.A（30 分钟窗口内识别 12 台 C&C 中的 10 台，但只出现在 Discussion 的附加实验、未形式化为评价协议、未报实体级误报）与 Gehri 2023（逐流 F1 0.185 对主机级 33/39）构成同一模式：**动机承认实体、评价停在流**。三点合起来可以支撑"实体级评价协议缺位是该领域的系统性空白，而非个别论文的疏漏"这一论断。
   - 注意区分：本文没有出现"逐流差、实体好"的性能落差现象（它逐流就已经饱和），因此它是**缺位证据**而非**落差证据**，引用时不应与 Känzig/Gehri 混为一谈。

4. **对方向 2（GeNIS 组隔离）——旁证而非主证**：本文与 GeNIS 主题无关，但其评价形态是同一类问题的又一实例：标签由 IP 直接给出、划分粒度为流、未做实体或捕获会话分组、八个模型 AUC 全部为 1.00 且作者自认可能过拟合。可作为"随机行级/流级划分导致同域假饱和"的补充例证，与 [[GeNIS-跨网络迁移评估]] 中"同域近 100%、跨网络仅 67.05%"的对照结论方向一致。

## 可迁移的机制

1. **两段式流水线**：Rust 侧只做解析与最小编码（保留包类型 / 方向 / 大小 / 时间戳 / spin bit 五项），Python 侧做特征计算与建模。这种"编码后落盘、建模端与解析端解耦"的结构可直接对应本课题的统一物化器 + 统一加载器合同。
2. **QUIC 特有可观测量的显式提取**：长包头包类型 one-hot（6 维）与 spin bit 比例 / 无 spin bit 比例。前者只在 Initial/Handshake/Retry/Version Negotiation 阶段可见，后者在整条连接可见。
3. **多阈值时间间隙计数**（24 维）作为行为节律表征。
4. **特征重要性三方法交叉核对并公开报告不一致**（Lasso vs RF vs GBM，表 V），是可复用的诚实做法：单一重要性方法的排序不足以支撑特征取舍结论。
5. **训练与预测时延分列、按样本量给三档**（表 VII / VIII），是效率评价的可复用报告格式。
6. **反面教训**：标签来自可控 IP、划分不分组、单一环境、AUC 全 1 —— 这套组合在本课题中必须显式规避，并在自评时作为"是否又造出一个假饱和基准"的检查清单。
