# SAM Decoding：基于后缀自动机的推测解码

## 一句话

该论文把后缀自动机正式用于神经序列系统中的在线精确重复匹配：静态语料自动机与动态当前序列自动机共同提供最长后缀、匹配位置和匹配长度，再用验证通过的符号增量更新。因此候选 D 的后缀记忆与按匹配长度决策不能写成原创模块。

## 方法与页级证据

- PDF 第 1—2 页把目标限定为无损大语言模型推测解码，并声称每个生成步的自动机更新和最长后缀检索具有均摊 `O(1)` 时间。
- 第 2 页介绍标准后缀自动机：构建为 `O(L)`，可增量扩展；状态、扩展边与后缀链接支持最长后缀匹配。
- 第 3 页图 3 与第 3.1 节同时构建离线静态语料自动机和随已生成文本增长的动态自动机；两者分别承担外部语料复用和当前上下文复用。
- 第 4 页算法 1 保存最长匹配状态与长度，并以 `min_endpos` 定位后续候选；静态自动机还离线保存频率和 Top-k 后继。论文用均摊分析给出平均 `O(1)`、单步最坏 `O(L)`，附录第 11—12 页给出势能证明。
- 第 4—5 页以静态、动态自动机的匹配长度和固定偏置选择候选；验证后，静态自动机只转移状态，动态自动机先转移再扩展。候选 D 若用匹配长度门控或只写入可信符号，应承认这是相邻先例。
- 第 7—8 页分别检查匹配偏置、候选长度，并移除静态或动态自动机。表 2 中两类自动机都有贡献，动态自动机的影响更大；这只支持解码吞吐，不支持检测收益。
- 第 9 页限制指出性能依赖任务和检索语料质量，静态语料不够多样；基于匹配长度的方法选择仍是启发式，现有数据也不能充分代表真实使用情景。

## 与候选 D 的重叠矩阵

| 候选 D 构件 | SAM Decoding 是否覆盖 | 判断 |
|---|---|---|
| 后缀自动机精确重复匹配 | 是 | **强重叠**；最长后缀、位置、长度和增量状态均公开 |
| 静态历史＋在线动态记忆 | 是 | **强重叠**；论文明确维护两种自动机 |
| 按匹配长度选择证据／支路 | 是 | **强重叠**；论文用匹配长度和偏置切换候选来源与辅助方法 |
| 固定容量 ROSA 状态核 | 否 | 标准后缀自动机状态随参考序列增长；论文没有证明其等价于 RWKV-8 ROSA |
| 去身份网络行为码 | 否 | 输入是语言模型词元，没有身份泄漏审计或跨年度冻结码本 |
| 异常检测监督头 | 否 | 目标是无损加速，候选由目标大模型验证，不输出异常概率 |
| 正常预测残差 | 否 | 没有只在正常历史训练的预测器，也没有非重复异常支路 |

## 证据支持的构思四栏

| 可借鉴的机制／公式 | 不能再声称为本课题原创的部分 | 结合 LSPR 跨年度任务与 RWKV 后可形成的实质改造 | 最小可证伪消融与匹配强基线 |
|---|---|---|---|
| 静态／动态后缀自动机、最长后缀状态与匹配长度、验证后增量更新、均摊更新复杂度 | 用后缀自动机做精确重复序列检索、同时维护静态与动态记忆、按匹配长度切换神经与检索支路 | 将去身份流量行为码送入固定容量、带过期规则的因果后缀记忆；后缀命中不直接替代 RWKV 输出，而是估计“已知正常重复度”，只门控 RWKV 下一码异常残差与静态正常原型距离之间的冲突。这样研究对象从加速解码变为冻结正常性核查 | 同一行为码与内存预算下比较 RWKV 下一码分数、固定阶 `n` 元语法／哈希表、标准静态 SAM、静态＋动态 SAM、固定容量 ROSA 与完整冲突门；强基线至少含 SAM Decoding 数据结构移植版、CBSeq、PLM-NIDS、COMET。若 ROSA 不优于固定阶记忆或门控无独立收益即否决 |

## 允许主张

- 候选 D 可把后缀自动机视为既有序列检索构件，研究贡献限定为将去身份行为码、固定容量 ROSA 证据和正常预测残差用于冻结跨年度网络检测的组合。
- SAM Decoding 的静态／动态分支和匹配长度消融可作为候选 D 必须包含对应对照的依据。

## 禁止主张

- 不得宣称首次把后缀自动机用于神经序列系统、在线重复匹配或按匹配长度选择支路。
- 不得把 SAM Decoding 的均摊 `O(1)` 时间直接移植给 ROSA；两者的状态定义、容量和更新规则必须分别核验。
- 不得从语言模型推测解码吞吐实验推断候选 D 的入侵检测收益。

## 论文结论、项目推论与待验证项

- **论文结论**：静态和动态后缀自动机均被实现和消融，目标是提高推测解码吞吐且保持目标模型输出不变。
- **项目推论**：候选 D 的后缀记忆本身原创风险高；完整组合是否与既有异常检测同构，仍需结合行为序列、离散代码本和正常预测文献判断。
- **待验证**：LSPR 行为码是否形成足够重复的稳定后缀，以及 ROSA 是否在固定容量下保持所需匹配性质，只能由源码复现和真实数据消融裁决。
