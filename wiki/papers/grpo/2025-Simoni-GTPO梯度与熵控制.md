# GTPO（Simoni 等）：梯度冲突修正与熵控制

> Marco Simoni 等（Sapienza / 圣安娜高等研究学院 / CNR-IIT），2025，arXiv:2508.03772v5 · 20 页 · 原件 `raw/papers/grpo/2025-Simoni-GTPO-Gradient-and-Entropy-Control.pdf`

## 证据等级

**E3 全文级**。原件已下载（arXiv 2508.03772v5，2.4 MB，20 页），正文与消融逐节读完；公式经 MinerU `extract` 模式转 LaTeX 后回原文页核对，页码锚点用逐页文本索引确认（`pypdf` 只读检索，2026-09-10）。

**同名冲突警示（必须记录）**：本篇的 GTPO 全称是 **Group-relative Trajectory-based Policy Optimization**（摘要），与 [[2025-Tan-GTPO与GRPO-S熵加权]] 的 **Group Token Policy Optimization**（arXiv:2508.04349）是**两篇完全不同的论文**，同在 2025 年 8 月、同为 GRPO 修正、共用缩写。引用"GTPO"必须带编号。

## 一句话

GRPO 里同一段格式文本在不同回答中会同时收到"该多写"和"该少写"的指令；GTPO 直接把这类位置上的负向梯度跳过、正向加倍，并用熵门槛拦住注定坍塌的完成项。

## 机制（§4–§5，p.2–6）

### 两个病灶（§4，p.2–3）

| 病灶 | 机制 | 位置 |
|---|---|---|
| **Token 级惩罚**（§4.1） | 冲突 token 定义：正向对齐——同一 token 在位置 p 上同时出现在正优势完成与负优势完成中；反向对齐——距结尾 r 的位置上同理。冲突 token 收到方向相反的梯度 | p.2 |
| **策略坍塌**（§4.2） | 负奖励完成会惩罚高置信 token，把模型决策推向低概率 token；标准 KL 项反应太慢，拦不住 | p.3 |

作者指出冲突的实际来源是**首尾的格式标签**（如 `<reasoning>`、`</answer>`）（p.4）。

### 对策一：冲突掩码梯度修正（§5.1，式(8)(9)，p.4）

掩码只覆盖**首个连续冲突跨度**（前向扫描 `M^fw`）与**末个连续跨度**（后向扫描 `M^bw`），`M_i = M^fw ∨ M^bw`——刻意不碰序列中段，因为中段 token 的含义依赖上下文、改动梯度反而有害（p.4）。

`J* = E[ (1/G) Σ_i (A_i/|o_i|) Σ_t r_{i,t} λ_{i,t} ]` …(8)

`λ_{i,t} = 1`（非冲突）；`0`（冲突且 `A_i<0`）；`2`（冲突且 `A_i>0`） …(9)

**总信号守恒**（p.4）：因 `Σ_{i∈G⁺}|A_i| = Σ_{i∈G⁻}|A_i|`，把正完成为 2 倍正好补偿被移除的负更新。

### 对策二：熵控制（§5.2，式(10)(11)，p.5）

- **完成项过滤**（式(10)，p.5）：先测模型训练前在训练集上的平均熵 `<H>_ini`。若 `<H>_ini > ln2`（高熵模型）则不过滤；若 `<H>_ini < ln2`（低熵、易坍塌模型）则**丢弃平均熵超过 ln2 的完成项**的优势信号 `δ_i=0`。
- **熵正则**（式(11)，p.5）：`J_GTPO = E[ (1/G) Σ_i δ_i·(A_i − γ·<H>_i)/|o_i| Σ_t r_{i,t} λ_{i,t} ]`。注意方向：**最小化**该熵项（因为 GRPO 内在有让熵随时间上升的倾向），γ 取 0.1（p.6）。
- **去掉 KL**：GTPO 不用 KL 散度，因此**训练时不需要参考模型**，更轻更快（摘要、p.5）。

## 实验结果（§6，p.6）

| 项 | 内容 | 位置 |
|---|---|---|
| 模型 | LLaMA 8B、Qwen2.5 3B | §6，p.6 |
| 训练数据 | GSM8K、MATH 训练集 | §6，p.6 |
| 分布内评测 | 对应测试集（pass@k、maj@k） | §6，p.6 |
| 分布外评测 | AIME 2024、AIME 2025、AMC 2023 | §6，p.6 |
| 训练资源 | 2×NVIDIA A100；学习率 1e-6；temperature 1.0；G ∈ {8, 12} | §6，p.6 |
| 设置 | 单次迭代（`π_θ = π_θold`），因此裁剪不生效（论文自述） | §6，p.6 |

**必须随结论一起转述的作者限定**：**实验只做了单次迭代（one iteration）**，此时 `π_θ = π_θold`、裁剪失效、GRPO 目标退化为式(14)（p.6）。这意味着本文实验**没有检验多轮 off-policy 场景**，而冲突掩码的动机（正负优势出现在同一批次）在单次迭代设定下是否仍成立需注意。作者同时承认"有些人尝试从 GRPO 中移除 KL 项，但我们的实验显示它有时对更可靠的稳定训练是必要的"（p.5）。

## 可迁移机制

1. **冲突 token 的检测与处理是一个通用设计模式**（§5.1，p.4）：当同一个中间产物在不同样本中拿到相反方向的监督信号时，直接按位置对齐就能识别出来。**本课题可直接复用该判据**——若同一字段/同一动作在不同样本的奖励符号相反，应优先怀疑位置对齐的共享结构（格式标记、模板词）。
2. **"总信号守恒"作为掩码设计纪律**（p.4）：跳过负更新必须补偿正更新，否则优化目标被静默改变。这与 [[2025-Tan-GTPO与GRPO-S熵加权]] 命题 2.2 的守恒性是同一条纪律的两次出现，**可作为奖励/梯度重塑机制的通用自检**。
3. **掩码范围要保守**（p.4）：只改首尾连续跨度、不动中段——**对不确定的干预，最小化作用面**。这条经验对任何"按位置屏蔽梯度"的设计都适用。
4. **熵门槛的正确用法**（式(10)，p.5）：作者的过滤是**条件性**的——先测初始熵，只在低熵（易坍塌）模型上启用。这是"技巧不是普适的、要先诊断再启用"的一个具体范例，与 [[2025-Liu-LitePPO极简组合]] 的方法论一致。
5. **去 KL 的权衡**（p.5）：去掉 KL 可以省掉参考模型，但作者自己的实验表明 KL 有时对稳定性必要——**去 KL 不是免费的**。

## 不能直接声称内容

- **不能把本篇与 Tan 等的 GTPO 混为一谈**：见上文同名冲突警示。
- **不能把"不需要参考模型"写成纯收益**：作者自己指出 KL 项有时对稳定训练必要（p.5），GTPO 是选择去掉它并靠熵控制补偿。
- **不能声称 GTPO 在长 CoT 上有效**：实验是 GSM8K／MATH（短中长度推理），模型规模 3B／8B；**没有任何长 CoT 或大模型证据**。
- **不能把单次迭代的结论外推到多轮 off-policy**：见上文限定；冲突掩码的收益在真正 off-policy 的多轮更新下是否保持，论文未测。
- **不能引用本文未给出的最终数值**：AIME/AMC 等分布外结果以图呈现（图 2），正文没有给出完整的数值表；本笔记不提供、也不得补造分数。
- **不能把"跳过负更新"当成普遍更好的做法**：该设计明确以"负更新会抬高大量无关 token 概率"为前提（§4.1），在动作空间小、正负样本均衡的任务上该前提可能不成立。

## 与课题的关系

- **对 DRIFT 第三章的负面样本处理有直接参考**：本课题的"灰区样本"与负样本占多数，GTPO 的"负更新会破坏高置信结构"与"总信号守恒式补偿"两个论证都可用作设计依据；但**是否启用必须由本课题实验裁决**，本笔记不构成启用依据。
- 与 [[2025-Gao-SAPO软自适应门控]] 的关系：SAPO 从**裁剪算子**角度缓解负向梯度的破坏性（提高负优势温度），GTPO 从**掩码＋补偿**角度处理。两者针对同一病灶（负向更新在高维输出空间中的副作用），是**互斥的候选方案**，不宜叠加。

## 疑问 / 待验证

- 论文未报告：种子数、方差、训练步数／墙钟、`γ` 的搜索范围。
- 单次迭代设定下 `λ=2` 的补偿是否真的"总信号守恒"：式(9) 的加倍只在正完成为上执行，而掩码位置的正负完成数量未必相等，作者用 `Σ|A_i|` 相等论证，但该恒等式对**掩码内**的位置是否成立未给证明。
- `<H>_ini` 的门槛 `ln2` 是否有理论依据，论文只给出经验取值（p.5）。
