# GTPO / GRPO-S：用熵做细粒度信用分配

> Hongze Tan 等，2025，arXiv:2508.04349v6 · 22 页 · 原件 `raw/papers/grpo/2025-Tan-GTPO-and-GRPO-S-Token-Sequence-Entropy.pdf`

## 证据等级

**E3 全文级**。原件已下载（arXiv 2508.04349v6，2.2 MB，22 页），正文与定理逐节读完；公式经 MinerU `extract` 模式转 LaTeX 后回原文页核对，页码锚点用逐页文本索引确认（`pypdf` 只读检索，2026-09-10）。

**同名冲突警示（必须记录）**：arXiv 上存在**两篇不同的 GTPO**：
- **本文（Tan 等，2508.04349）**：Group **Token** Policy Optimization，熵加权奖励重塑；缩写常写作 GTPO，序列级变体为 GRPO-S。ChatGPT 交接中的"GTPO / GRPO-S — 动态熵权重细粒度对齐"指的是**这一篇**。
- **另一篇（Simoni 等，2508.03772）**：GTPO = Group-relative **Trajectory**-based Policy Optimization，冲突感知梯度修正＋熵控制。见 [[2025-Simoni-GTPO梯度与熵控制]]。

两者机制、作者、基线完全不同。**引用"GTPO"必须带编号**，否则无法区分。

## 一句话

同一序列里所有 token 共享一个奖励是浪费信息；用每个 token 自身的熵（不确定性）重新分配奖励质量，就能把梯度聚焦到真正的决策分叉点上。

## 机制（§2，p.1–5）

### 动机：变分归约论证（§2.1，p.1–2）

作者指出序列级基线与 token 级基线的差异：序列级均值 `R̂_1 = (1/G)Σr_i`；token 级均值 `R̂_2 = (Σ|o_i|r_i)/(Σ|o_i|)`。附录给出 `Var(R̂_2) ≤ Var(R̂_1)`，即 token 级基线方差更小。作者据此论证 GRPO 用的是 `R̂_1`，隐含"正确回答越长越好"的错误激励（p.2）。

### Dynamic Entropy Weighting（§2.1，p.2）

把序列按终止奖励分为成功集 `O⁺` 与失败集 `O⁻`，双策略分配：
- 成功序列中的**高熵** token → 奖励加成（强化有价值的探索）；
- 失败序列中的**低熵** token → 相对更大的惩罚（抑制自信但错误的推理）。

### 两个目标

- **GTPO**（token 级，式(7)，p.4）：分母为批次内 token 总数 `1/Σ_k |o_k|`，把塑形后的 token 奖励 `r̃_{i,t}⁺`、`r̃_{j,t}⁻` 代入 PPO 风格裁剪目标。
- **GRPO-S**（序列级，式(10)，p.4）：用序列平均熵 `Ĥ_i` 调整个序列的奖励，结构同 GRPO。

### 理论结果（§2.4，p.5）

| 命题／定理 | 内容 | 位置 |
|---|---|---|
| 命题 2.2 | 当 `α_1+α_2=1` 时，每个时间步上**塑形正奖励之和 = 原始二值奖励之和**（正奖励质量守恒） | p.5 |
| 命题 2.3 | 在"熵巩固条件"（成功序列间 token 熵差异随训练趋于 1）下，GTPO 相对 GRPO 的梯度偏置渐近消失 | p.5 |
| 定理 2.4 | GTPO 与 DAPO 共享同一全局最优 | p.5 |
| 式(14) | 正奖励分量梯度可分解为 `E[∇J_GRPO] + E[Cov(Δ_entropy, ∇logπ_θ)]`，第二项标为"探索项" | p.5 |

作者强调：由于总正奖励仍绑定真值 `r_i`，模型**不能只靠操纵熵来最大化目标**，必须最终提高正确答案的似然（p.5）。

## 实验结果（§3，p.6）

Qwen2.5-7B（表 1，p.6）：

| 方法 | AIME24 Mean@32 | AIME24 Pass@32 | AIME25 Mean@32 | MATH500 Mean@32 |
|---|---|---|---|---|
| GRPO | 28.36 | 46.01 | 15.00 | 78.62 |
| DAPO | 21.2 | 35.51 | 13.33 | 78.85 |
| DAPO w/ Forking Tokens | 30.77 | 54.16 | 15.21 | 79.25 |
| **GTPO** | **34.23** | **64.89** | **16.67** | 80.16 |
| **GRPO-S** | 34.67 | 64.76 | 18.33 | 80.07 |

Qwen2.5-32B：GTPO AIME24 Mean@32 35.21、GRPO-S 35.52，对比 GRPO 29.17、DAPO 34.06（表 1，p.6）。

作者自述的规模效应：AIME24 Pass@32 上 GTPO 在 7B 上绝对增益 `+29.4`，在 32B 上仅 `+9.9`，据此称熵加权对较小模型更关键（p.6）。

**必须随结论一起转述的作者限定**：全部实验只用 Qwen2.5 两个规模、三个数学基准；`α_1+α_2=1` 是理论命题的前提条件，**论文实验中的 α 取值需在附录核对**（本轮未逐项摘录）。DAPO 一栏在 7B 上低于 GRPO（21.2 vs 28.36）属异常，作者未解释。

## 可迁移机制

1. **熵作为"决策分歧度"的代理**（§2.1，p.2）：token 熵高 ⟺ 该步存在多个合意候选。用熵分配信用，等价于把学习信号集中在**真正的分叉点**上。这一思想不依赖语言模型：任何有"逐步决策 + 终局奖励"结构的任务都可考虑。
2. **守恒性约束（命题 2.2，p.5）是一条设计纪律**：奖励重塑不应改变总奖励质量，否则优化目标被静默替换。**任何奖励塑形机制都可用"重塑前后总质量是否守恒"做前置校验**——这是一个廉价且强力的自检。
3. **渐近无偏的条件写清楚**（命题 2.3，p.5）：偏置消失依赖"熵巩固条件"，即在训练后期成功路径间的熵差异趋于消失。**该条件不成立时（如任务天然多峰）偏置持续存在**——引用"无偏"时必须带这个条件。
4. **同一框架的两种粒度**（GTPO vs GRPO-S）：token 级更细但计算熵与奖励的开销更大；序列级更省但丢失位置信息。作者明确指出任务导向时序列级足够（p.4）。这是一个**成本／粒度取舍的模板**。

## 不能直接声称内容

- **不能把 GTPO 写成"用熵做正则"**：作者明确把自己与"仅把熵当正则项"的方法区分开（摘要），本文用熵**重塑奖励**。
- **不能不加编号地引用"GTPO"**：见上文同名冲突警示。
- **不能引用"无偏"而不带前提**：命题 2.3 的渐近无偏依赖熵巩固条件与 `α_1+α_2=1`。
- **不能把 7B 上的 `+29.4` 当作通用增益**：作者自己的数据表明 32B 上仅 `+9.9`，增益随规模递减。
- **不能把 DAPO w/ Forking Tokens 的对比当作 DAPO 的代表性能**：那是作者复现的变体，且 7B 上原生 DAPO 只有 21.2，与其它文献报告的 DAPO 表现差距较大，复现质量未经第三方核验。
- **不能把结论外推到非可验证奖励**：全部任务是数学推理，奖励是二值可验证信号；熵加权本身不要求可验证奖励，但论文无相关实验。

## 与课题的关系

- 与本课题"多目标奖励"设计的接口：熵加权提供了**不引入额外奖励权重**的信用分配方案——不必为"过程质量"另设一项奖励，而是用策略自身的不确定性重新分配已有奖励质量。这与 [[2025-Shrivastava-GFPO组过滤策略优化]] 的过滤思路是同一问题的两种解法。
- 命题 2.2 的**质量守恒校验**可直接作为本课题奖励设计的自检门：任何"物理残差奖励"的引入都应先证明它不改变原奖励的总质量分布。

## 疑问 / 待验证

- 论文未报告：α 的具体取值与搜索范围、训练算力、种子与方差。
- 熵的计算口径（用 `π_θold` 还是 `π_θ`）在算法 1 中记为 `π_θold`（p.5），但正文式(3)(5) 未明确区分；复现时需回原文核对。
- 定理 2.4"与 DAPO 共享全局最优"的证明依赖作者对 DAPO 的等价改写（把错误答案奖励记 −1），该改写与 DAPO 官方实现是否一致未核。
