# GSPO：序列级重要性比率与序列级裁剪

> Chujie Zheng 等（Qwen Team, Alibaba Inc.），2025，arXiv:2507.18071v2 · 7 页（正文 §1–§6，参考文献另计）· 原件 `raw/papers/grpo/2025-Zheng-GSPO-Group-Sequence-Policy-Optimization.pdf`

## 证据等级

**E3 全文级**。原件已下载（arXiv 2507.18071v2，458,773 字节，7 页），正文逐节读完；公式经 MinerU `extract` 模式转 LaTeX 后回原文页核对，页码锚点用逐页文本索引确认。

**实验规模提示**：全部实验是作者自有的大模型 RL 训练（Qwen3-30B-A3B-Base 冷启动 + MoE 架构），**没有公开的训练脚本、超参表或可复现的随机种子**；结果以训练曲线（图 1–图 3）呈现，**论文正文没有给出任何最终基准数值**（AIME/LiveCodeBench/CodeForces 的具体分数只在图内）。因此本笔记只能精确引用正文写出的数字（裁剪区间、专家激活变化比例等），引其效果时不得编造分数。

## 一句话

GRPO 的 token 级重要性权重在一个只有单个样本的下一 token 分布上做校正，这在统计上不成立；GSPO 改为在整条响应上定义重要性比率并整条裁剪，把优化单元与奖励单元（序列）对齐。

## 背景：问题的演进（§1–§2，p.1–2）

- **PPO**（式(1)，p.2）：token 级重要性比率 `w_t(θ)=π_θ(y_t|x,y_<t)/π_θold(y_t|x,y_<t)`，裁剪区间 `ε`，优势由另一个价值模型估计。
- **GRPO**（式(2)(3)，p.2）：去掉价值模型，用同一 query 下 G 条响应的组内归一化奖励作优势：
  `Â_{i,t} = Â_i = (r(x,y_i) − mean({r(x,y_i)}_{i=1..G})) / std({r(x,y_i)}_{i=1..G})`，响应内所有 token 共享同一优势。
- **动机（本文的核心诊断，§3，p.2–3）**：
  1. 重要性采样的成立条件是对行为分布取 **N≫1 个样本**平均（式(4)，p.2）。GRPO 在**每个 token 位置**用它，而该位置只有**一个**样本 `y_{i,t}`，因此不是分布校正，只是**高方差噪声**。
  2. 该噪声**随响应长度累积**，并被裁剪机制进一步放大。
  3. 后果：**模型坍塌，且常常不可逆**——作者称即使回退到早期检查点、重新调裁剪区间、延长生成长度或换 query 集也无济于事（p.3）。
  4. 由此提出原则：**优化目标的单元应与奖励的单元一致**；奖励给整条序列，因此在 token 级做 off-policy 校正是错位的（p.3）。

## 方法核心（§4，p.3–4）

### GSPO 目标（式(5)–(7)，p.3）

`J_GSPO(θ) = E_{x∼D, {y_i}∼π_θold}[ (1/G) Σ_i min( s_i(θ)·Â_i , clip(s_i(θ), 1−ε, 1+ε)·Â_i ) ]` …(5)

其中组相对优势与 GRPO 相同（式(6)），**序列级重要性比率**为

`s_i(θ) = ( π_θ(y_i|x) / π_θold(y_i|x) )^{1/|y_i|} = exp( (1/|y_i|) Σ_t log[ π_θ(y_{i,t}|x,y_{i,<t}) / π_θold(y_{i,t}|x,y_{i,<t}) ] )` …(7)

- **长度归一化是刻意的**（p.3）：不这么做，少数几个 token 的似然变化就会让序列级比率剧烈波动，而且不同长度响应需要不同的裁剪区间。
- **裁剪区间量级与 GRPO 不同**：作者明确提醒两者的重要性比率定义不同，裁剪区间通常**差若干数量级**（p.3）。

### 梯度分析（§4.2，式(8)–(12)，p.3–4）

- GSPO 梯度（式(10)，p.3）：`∇J_GSPO = E[ (1/G) Σ_i (π_θ(y_i|x)/π_θold(y_i|x))^{1/|y_i|} · Â_i · (1/|y_i|) Σ_t ∇log π_θ(y_{i,t}|x,y_{i,<t}) ]`——**响应内所有 token 权重相同**。
- GRPO 梯度（式(12)，p.4）：每个 token 被自己的 `w_{i,t}(θ)` 加权；当 `Â_i>0` 时该权重落在 `(0, 1+ε]`，`Â_i<0` 时落在 `[1−ε, +∞)`，**不等权且不可忽略**，随训练累积产生不可预测后果（p.4）。
- 结论句（p.4）：GSPO 与 GRPO 的**根本区别在于如何给各 token 的对数似然梯度加权**；GSPO 消除这一不稳定因素。

### GSPO-token 变体（§4.3，式(13)–(17)，p.4）

给多轮 RL 等需要逐 token 定制优势的场景提供：`s_{i,t}(θ) = sg[s_i(θ)] · π_θ(y_{i,t}|·)/sg[π_θ(y_{i,t}|·)]`，`sg[·]` 表示只取值不回传梯度（PyTorch 的 `detach`）。当响应内所有 token 优势相同（`Â_{i,t}=Â_i`）时，**GSPO-token 与 GSPO 在目标、裁剪条件与理论梯度上数值等价**（p.4）。

## 可迁移机制

1. **优化单元 = 奖励单元**（p.3）：奖励落在哪个粒度，off-policy 校正就应落在哪个粒度。这是一个不依赖具体模型的**结构性判据**，可用来审查任何「奖励给整体、梯度按部件加权」的设计。
2. **诊断法：检查重要性权重是否真有多个样本**（p.2）：若某个层级的重要性比率在统计上只有 N=1 个样本支撑，它就不是分布校正而是噪声注入。
3. **反直觉检验**：裁剪比例大幅上升却效率不降反升，说明原方案的梯度估计本身无效（p.5）。这一「裁剪比例—效率」对照可作为识别梯度估计噪声的实验设计范式。
4. **对不连续结构的鲁棒性**（§5.3，p.6）：当被优化的网络存在不连续/硬路由（MoE 专家、量化、硬门控）时，依赖**逐部件似然**的比率会因部件切换而剧烈波动，而依赖**聚合似然**的比率则不敏感。

## 不能直接声称内容

- **不能写成「序列级比率在小模型/表格数据/二分类上更优」**：本文全部证据来自 30B 级 MoE 语言模型的数学与代码 RL，**没有任何非 LLM 或小模型实验**。跨模型规模的泛化不在其证据范围内。
- **不能引用具体基准分数**：AIME'24／LiveCodeBench／CodeForces 的数值只在图 1 内，正文未给出；本笔记不提供、也不得补造这些数字。
- **不能把「GSPO 更好」当作独立复现结论**：对照组（GRPO）的超参由作者选择，且 GRPO 侧额外依赖 Routing Replay；两者裁剪区间量级本就不同（p.3），比较的公平性未经第三方验证。
- **不能把 GSPO 的 MoE 结论搬到无路由结构的模型**：§5.3 的机制解释严格依赖 MoE 的专家激活波动（10% 变化这一数字是 48 层 Qwen3-30B-A3B-Base 的实测，不适用于其它模型）。
- **不能声称「序列级目标一定消除熵坍塌」**：本文处理的是**训练稳定性/坍塌**，不是熵最大化或探索问题；GRPO 侧的探索问题由 DAPO 等另一条线处理。
