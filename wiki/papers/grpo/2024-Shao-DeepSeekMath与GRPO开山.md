# DeepSeekMath：GRPO 的首次提出

> Zhihong Shao 等 11 人（DeepSeek-AI、清华大学、北京大学），2024，arXiv:2402.03300v3 · 30 页 · 原件 `raw/papers/grpo/2402.03300.pdf`

## 证据等级

**E3 全文级**。原件已下载（arXiv 2402.03300v3，1,844,642 字节，30 页），GRPO 相关全部章节（§4.1–§4.2、§5.2、附录 A.1.6）逐节读完；公式经 MinerU `extract` 模式转 LaTeX 后回原文页核对。

**范围提示**：本文是「模型＋数据＋算法」的整篇报告（120B math token 继续预训练 + 数据选择流水线 + GRPO），**GRPO 是其中一节**。本笔记只覆盖 GRPO 与统一范式，不展开数据流水线与预训练细节。

## 一句话

GRPO 用「同一问题下多条输出的组内奖励统计量」替代 PPO 的价值函数：既省掉与策略等规模的价值模型，又天然对齐奖励模型「比较同一问题下多个回答」的训练形态。

## 背景：问题的演进（§4.1.1，p.11–13）

- **PPO**（式(1)，p.11）：actor-critic；优势 `A_t` 由 GAE 基于奖励序列与学习到的价值函数 `V_ψ` 计算。
- **PPO 的两个负担**（p.13）：
  1. 价值函数通常与策略模型规模相当，显存与算力开销大；
  2. 价值函数用作方差缩减的基线，但 LLM 场景**通常只有最后一个 token 被奖励模型打分**，这使得「每个 token 都准确的价值函数」很难训练。
- **KL 惩罚的位置**（式(2)，p.13）：标准做法是把每 token 的 KL 惩罚**加进奖励** `r_t = r_φ(q,o_≤t) − β log(π_θ/π_ref)`，这会让优势 `Â_{i,t}` 的计算更复杂。
- **本文的替代**（图 4，p.13）：用「同一问题下多个采样输出的平均奖励」作基线，**去掉价值模型**；并把 KL 直接作为损失项而非奖励整形（p.13）。

## 方法核心（§4.1，p.13–15）

### GRPO 目标（式(3)，p.13）

`J_GRPO(θ) = E_{q∼P(Q), {o_i}∼π_θold(O|q)} [ (1/G) Σ_{i=1}^{G} (1/|o_i|) Σ_{t=1}^{|o_i|} { min( [π_θ(o_{i,t}|q,o_{i,<t})/π_θold(o_{i,t}|q,o_{i,<t})]·Â_{i,t}, clip(·, 1−ε, 1+ε)·Â_{i,t} ) − β·D_KL[π_θ‖π_ref] } ]` …(3)

三处与 PPO 的形式差异：
1. **无价值网络**，优势只由组内相对奖励决定；
2. **KL 项在损失内**（`−βD_KL`），不是在奖励内——作者明确这是为避免复杂化 `Â_{i,t}` 的计算（p.13）；
3. KL 用**无偏估计器**（Schulman, 2020）估计（p.14）。

作者给出的合理性论证（p.13）：奖励模型通常在「同一问题的多个回答之间的比较」数据上训练，因此**组相对的优势计算方式与奖励模型本身的比较性质对齐**。

### 优势的两种实例化

- **结果监督（Outcome Supervision，§4.1.2，p.14）**：奖励模型只给整条输出一个分数，组内标准化
  `Â_{i,t} = r̃_i = (r_i − mean(r)) / std(r)`，**输出内所有 token 共享同一优势**。
- **过程监督（Process Supervision，§4.1.3，p.14）**：过程奖励模型给每一步（step）末尾打分，得到 `R = {{r_i^{index(1)}, …, r_i^{index(K_i)}}}…`，同样用组内均值/标准差标准化；**每个 token 的优势 = 其后续所有步骤标准化奖励之和**：
  `Â_{i,t} = Σ_{index(j) ≥ t} r̃_i^{index(j)}`。

### 迭代 RL（§4.1.4、算法 1，p.14–15）

- 每轮迭代把**参考模型设为当前策略**；
- 用策略采样结果生成奖励模型的新训练集，并以**含 10% 历史数据的回放机制**持续训练奖励模型；
- 每轮内对每个问题采 G 条输出，计算组相对优势后做 μ 次策略更新。

### 训练配置（§4.2，p.15）

基座 DeepSeekMath-Instruct 7B；RL 数据为 GSM8K 与 MATH 的 CoT 格式 SFT 问题（约 **144K** 条，刻意排除其它 SFT 问题以观察对无数据基准的影响）；奖励模型从 DeepSeekMath-Base 7B 起步、学习率 **2e-5**；**策略学习率 1e-6**；**KL 系数 0.04**；每问采 **64** 条输出；最大长度 **1024**；训练批大小 **1024**；**每次探索阶段只做一次策略更新**（μ=1）。

**RL 如何起作用（§5.2.2，图 7，p.21）——本文最可迁移的实证结论**：RL 提升 **Maj@K** 但**不提升 Pass@K**，作者据此判断 RL 的增益来自「让输出分布更稳健、把 TopK 中的正确答案推上来」，而非基础能力增强。

**统一范式（§5.2.1，式(5)、表 10，p.18–19）**：把任意训练方法的梯度写成
`∇_θ J_A(θ) = E_{(q,o)∼D}[ (1/|o|) Σ_t GC_A(q,o,t,π_rf) · ∇_θ log π_θ(o_t|q,o_<t) ]`，
三个构件为**数据来源 D**、**奖励函数 π_rf**、**算法 A 决定的梯度系数 GC**。SFT／RFT／DPO／在线 RFT／PPO／GRPO 只是这三者的不同组合（表 10，p.19；详细推导在附录 A.1）。在 DeepSeekMath-Instruct 1.3B 上的对照（图 5，p.19）显示 GRPO+PS（过程监督）优于 GRPO+OS。

## 可迁移机制

1. **用组统计量替代价值网络**（p.13）：当奖励天然是「同一输入下多个输出的比较」时，组内均值/标准差就是免费且对齐的基线。这是对「需要学习一个基线估计器」路线的替代方案，**代价是每条样本要采一组输出**。
2. **KL 约束放在损失内而非奖励内**（p.13）：把约束与优势计算解耦，优势仍是纯任务信号。这是一条实现层面的可迁移选择。
3. **奖励粒度决定优势分配粒度**（§4.1.2 vs §4.1.3，p.14）：结果监督=整条共享一个优势，过程监督=按后续步求和分配；两者共用同一目标式(3)。**「信用分配粒度」是可独立于优化器选择的设计维度**。
4. **迭代式参考模型更新 + 奖励模型回放**（§4.1.4，p.14–15）：固定参考模型会与当前策略渐行渐远；把参考模型换成当前策略并用历史数据回放防止奖励模型漂移，是可迁移的稳定化组合。
5. **Maj@K／Pass@K 分解**（图 7，p.21）：用两个指标区分「排序能力提升」与「能力提升」。**这是判定「适应/微调是否真的提升基础能力」的通用诊断对**，可直接借用到本课题的适应类实验上。
6. **统一范式（数据来源×奖励函数×梯度系数）**（式(5)、表 10，p.18–19）：把不同方法放进同一梯度分解里比较，是写方法综述与做机制对位的通用框。

## 不能直接声称内容

- **不能把 GRPO 的效果与本课题的判定任务等同**：全部实验是数学推理，奖励是**答案正确性**（可验证、二值），优势的组内标准化依赖「同一问题可采多条输出」这一前提。
- **不能把 GRPO 说成「无 KL」**：式(3) 明确保留了 `−βD_KL` 项；后来 DAPO 才在长 CoT 场景下删掉 KL（§2.3，DAPO p.3），两者不可混淆。
- **不能把「组内标准化优势」当作 GRPO 的独有创新**：论文自述其对齐的是奖励模型的比较性质（p.13）；归因时须限定为「在 PPO 框架内去掉价值模型的实现」。
- **不能引用 144K／64 条输出／1e-6 等超参作为通用推荐值**：它们绑定 DeepSeekMath-Instruct 7B 与 GSM8K+MATH 数据，论文未给敏感性分析。
- **不能把「RL 提升 Maj@K 不提升 Pass@K」外推到所有任务**：该结论是本文在 GSM8K/MATH 上、温度 0.7 的实测（图 7），作者自己也只把它与 SFT 对齐问题联系起来讨论。
- **过程监督优于结果监督（图 5，p.19）只在 1.3B 模型上报告**，不得写成 7B 或通用结论。
