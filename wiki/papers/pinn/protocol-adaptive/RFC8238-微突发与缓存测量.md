# RFC 8238：数据中心微突发与缓存测量术语

## 一句话

只报告“队列峰值”不足以复现实验；必须同时固定分组大小、分组间隔、业务类别、缓存单位和丢包统计，而规范不提供统一的理想缓存容量。

## 规范原结论

- 第 3.2 节把缓存大小列为需要明确的设备属性，要求说明测量和报告单位。
- 第 6.1.1 节讨论微突发测试，要求控制分组最大传输单元、业务类别或差分服务码点，以及分组发送间隔等参数。
- 规范明确说明这些术语不规定理想缓存大小；更大的缓存不必然更好，过大缓存还可能增加排队时延。

## 对 R2 的直接约束

- v4 收据应记录每个数据报的字节数、到达时刻、服务开始、服务完成、传播释放、方向、实现和丢包原因。
- 三次门禁必须固定最大数据报、链路速率、传播时延、抖动、业务大小和执行顺序。
- 峰值占用应同时以字节、容量比例和服务时间等价量报告，不能只给一个百分比。

## 本课题推论

逐事件收据和离线重放是把微突发现象从日志描述变成可核验制品的必要工程措施；这是可复现性推论，不是 RFC 强制要求的具体文件格式。

## 不能推出

- RFC 8238 不支持 `2 MiB` 或 `80%` 门禁。
- 数据中心交换机测试术语不能直接证明 QUIC 用户态代理模型等价于真实瓶颈队列。

## 待实验验证

- 同一冻结配置的三次运行能否用收据重放得到完全一致的计数与峰值。
- quiche 与 aioquic 的到达间隔分布差异是否可由端点节奏实现解释。
