## 北斗恢复节点流程：

## 1，自动恢复

## (1) 适用场景

manba-bi服务启动定时任务，每360s扫描所有的下线节点，根据该节点当天被下线的次数决定恢复节点时间：

<table><tr><td>今日下线次数</td><td>自动恢复条件</td></tr><tr><td>1次</td><td>距最后一次下线≥30分钟且健康检查通过</td></tr><tr><td>2次</td><td>距最后一次下线≥2小时且健康检查通过</td></tr><tr><td>≥3次</td><td>不自动恢复,需人工上线</td></tr></table>

\*当前健康检查为空实现，调用 moni.GetInstance 后直接返回 true，不做任何实质性健康检查

## (2) 恢复流程

（a）满足恢复条件以后，同步调用portal.ChangeServerStatus(name, false)，发起http请求：PUT /api/v1/portal/pcdn?name=<hostname>，将节点的is\_disabled字段设置为false，将dial\_ips清空，不修改其他字段；执行SQL：

```txt
1 UPDATE p_instances SET is_disabled=0, dial_ips=", updated_at=NOW() WHERE name=?
```

（b）异步向 msg\_data\_all 表插入一条 action\_id=400 的记录，标记本次自动上线事件。

(c) 异步发送企业微信通知和blink通知

(d) portal 的缓存刷新 ticker (ticker.go:19) 每 30 秒执行一次 refreshMCDN 等函数，从 dao.GetLiveMCDNs 重新查库：

```sql
-- dao/mcdn.go:11
updated_at > NOW() - INTERVAL 3 MINUTE
AND is_deleted = 0
AND dial_ips != "
AND type = 'v'
```

此时 is\_disabled 刚被置为 false，但 dial\_ips 也同时被清空了，节点不会立即出现在服务列表，需要等 MCDN agent 重新上报心跳、填充 dial\_ips 并更新 updated\_at 后，才会在下一个 30 秒窗口内重新出现。

## 2，人工手动上线

人工发起HTTP请求，基本可以认同为第一种方式，目前基本不使用

```txt
1 PUT /api/v1/portal/pcdn?name=<hostname>
2 Body: {"is_disabled": false}
```

## 3，北斗节点心跳恢复

（1）适用场景：北斗节点超过3分钟未上报心跳包，后续心跳恢复，重新上报心跳。这种情况会通过portal原地进行恢复。

## (2) 恢复流程：

portal本身会有定时任务，30s执行一次。刷新mcdn节点服务列表，每次都会从数据库中加载最近3分钟内有更新的节点。

```txt
// dao/mcdn.go:11
sql := `updated_at > ? and is_deleted = ? and dial_ips != ? and type = 'v'
m, _ := time.ParseDuration('-3m')
d.db.Where(sql, time.Now().Add(m), 0, "").Find(&instances.PInstances)
```

MCDN agent 恢复运行 →重新上报拨测结果 →portal 更新 p\_instances.updated\_at 和 dial\_ips →下一个 30 秒缓存刷新周期内节点自动重新出现，全程无任何 API 调用或状态变更。

## 两个维度的叠加关系：

<table><tr><td>is_disabled</td><td>updated_at / dial_ips</td><td>节点是否在服务列表(前端页面展示)</td></tr><tr><td>false</td><td>3 分钟内有更新 且 dial_ips 非空</td><td>在</td></tr><tr><td>false</td><td>超时 或 dial_ips 为空</td><td>不在(心跳失效)</td></tr><tr><td>true</td><td>任意</td><td>不在(is_disabled 过滤发生在 getMCDNs 业务层)</td></tr></table>

## 4，blink调用北斗接口进行恢复

（1）适用场景：北斗节点超过3分钟未上报心跳包且未自动恢复、北斗节点一天内被踢点下线超过3次，需要blink调用portal接口选择原地恢复节点或者重新交付节点

## (2) 恢复流程：

重新交付：会把该节点作为全新机器进行交付，走portal POST /pcdns/create接口

原地恢复：blink原地恢复会通过执行脚本，然后等待mcdn恢复心跳。脚本命令是：

```shell
1 supervisorctl restart portal_pin && python /data/cdn_tools/mcdn_init.py
```

该命令其实是重启portal服务，然后运行mcdn\_init脚本，对portal服务进行检查，输出各项状态监控指标（服务类型、hostname、厂商、sid、dns、内核版本、系统语言、时区、v/live类型检查磁盘挂载+BvcApp容器是否运行；mp2sp/mnet类型检查cyberpunk容器是否运行）
