# bili-tellurium 项目架构与核心知识

## 一、项目概览

bili-tellurium（网络遥测）是 Bilibili CDN 基础设施的网络遥测服务，从 Prometheus 采集指标，经数据/变更立方处理，运行意图模型做自动化决策（节点下架、路径下架、水位线告警），结果写入 ClickHouse/MySQL。

- 模块名：`bili-tellurium`
- Go 版本：1.24
- 私有依赖需设 `GOPRIVATE=buf.bilibili.co,git.bilibili.co`
- `go.mod` 通过 `replace` 映射内部依赖：`bili-carbon`、`bvccdn-bban2api`、`go-common`

## 二、架构（流水线模式）

```
Collection（采集） → Data Cube（数据立方） → Intent/App Model（意图模型） → Action（执行）
```

| 目录 | 职责 |
|------|------|
| `init/` | 启动引导：加载配置、初始化 DB 连接、日志、协程池 |
| `timer/` | Cron 调度入口，通过 `beego/task` + 内部 `framework/model` 注册定时任务 |
| `collection/` | 从 Prometheus 等数据源采集数据，每个采集器实现 `Model` 接口并自注册 |
| `framework/` | 核心抽象：`Model` 接口、`Cube` 接口、`ChangeCube`、查询引擎、协程池（ants） |
| `cube/data_cube/` | 具体数据立方定义（主机带宽、节点信息、探测信息等） |
| `model/intent_model/` | 决策模型：节点下架、主机下架、水位线、路径下架、探测分位数 |
| `model/app_model/` | 应用层模型，作用于意图模型输出 |
| `model/data_model/` | 数据聚合模型 |
| `database/` | DAO 层：ClickHouse（主要分析存储）、MySQL、Redis、Databus |
| `server/` | HTTP 服务（blademaster），pprof 注册在 HTTP 端口 |
| `conf/` | TOML 配置文件（`conf.toml`、`http.toml`、`db.toml`） |

**关键模式**：模型通过 `init()` + `framework/model.RegisterModel()` 自注册，由 cron 表达式调度执行。ClickHouse 是时序立方数据的主要存储。

## 五、常见开发任务

### 新增模型

1. 在 `model/` 子目录创建文件
2. 实现 `Model` 接口：`Name()`、`Frequency()`（cron 表达式）、`Handle(ctx context.Context)`
3. `init()` 中调用 `framework/model.RegisterModel(myModel)`
4. 添加单测

### 新增数据采集器

1. 在 `collection/` 创建文件，实现 `Model` 接口 + `RegisterModel()`
2. 通过 `database/` 函数查询 Prometheus/ClickHouse
3. 通过 DAO 方法写入对应立方或表

### 查询数据立方

使用 `framework/engine`：`GetCube(name, time)` 取时间点立方、`TraceDown(cube)` 遍历依赖。
