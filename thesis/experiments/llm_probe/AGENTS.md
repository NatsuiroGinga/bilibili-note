## 按需合同入口

- 修改、同步或运行 `scripts/` 前读取 `scripts/AGENTS.md` 和 `.Codex/docs/agents-split/remote-script-execution-contract.md`。远程操作可按任务选择直接 SSH、持久化脚本或启动器，以能最快安全执行并保留退出码与日志为准，不强制使用统一包装器。
- 服务器切换、硬件降级、下载、镜像、资源监测、Rust 物化、生成评测和检查工具读取 `.Codex/docs/agents-split/llm-probe-operational-contract.md` 的匹配章节。
- 外部制品、远程载荷、任务冲突、SwanLab 故障、制品枚举、恢复门禁、包哈希、冻结合同、模型视图、PINN 指标、TCP 配对或 ns-3 故障读取 `.Codex/docs/agents-split/llm-probe-failure-prevention-handbook.md` 的匹配章节。
- 编写或修改任何包装器的制品枚举、输入哈希与后置验收前，先读该手册的「制品枚举与忽略规则」；新增恢复或跳过门禁前，先读「历史启动器证据的 schema 漂移」。
- 新增需注册的机器学习组件才使用 `architecture-design`；版本控制任务才使用 Git 技能。
- 同一缺陷、协议合同或外部依赖连续两次修复无可验证进展时，停止同类补丁并核验版本匹配的官方规范、文档、源码和问题记录；第三次修复必须基于新证据形成单一可证伪假设，且不阻塞无关实验。

## 服务器、GPU 与凭据（强制）

- 当前服务器和凭据键只从所属路线总控读取；密码、令牌、连接地址及解析值不得打印、回显或写入配置、日志、URL、清单、文档和汇报。
- 服务器离线、切换或回收后停止自动重试且不计为科学失败；新环境先只读核验身份、根目录、磁盘、依赖、源码锁、数据和制品，不沿用旧进程假设。
- GPU 训练、推理、生成评测、显存兼容或加速测试前，告知用户任务、预计时长、显卡与卡数、显存、开机和费用需求，确认可用后才执行。
- 默认本机执行短小的 CPU 开发、复审、哈希、统计和报告；服务器执行 GPU 工作、大规模物化与大规模 CPU 实验。
- **规模阈值（强制）**：单次任务预计满足下列任一条即属大规模实验，必须移到服务器执行，不得在本机启动：预计墙钟超过 30 分钟；预计常驻内存超过 8 GiB；需要扫描超过 500 万行或超过 1 GiB 的输入；训练样本矩阵超过 100 万行乘 100 列。启动前必须先估算并把估算值告知用户。
- **百万级物化状态上界门禁（强制）**：处理预计达到 100 万条记录、会话或行的数据物化前，必须在配置、实施计划或运行记录中证明每类中间状态的固定上界，并列出键基数、每键最大历史长度、批大小、单条状态字节数、峰值内存、临时文件大小与总 I/O 的计算口径；未证明上界不得启动。仅把输入分批读取不构成有界内存证明：若跨批的 `HashMap`、排序缓存、去重集合、聚合器、待写缓冲或历史窗口会随累计输入或唯一键数增长，必须先增加驱逐/分区/磁盘溢写策略和明确容量阈值，再进行物化。
- 移到服务器前先核验：凭据变量已就位、目标机器身份与项目根、磁盘与内存余量、依赖与数据是否已在服务器。**数据不在服务器时先比较传输代价与计算代价**，传输耗时接近或超过计算耗时的任务不搬。凭据变量缺失时如实报告并停止，不得猜测连接方式。
- 本机只保留探索性小样本、冻结夹具测试、只读审计和秒级到分钟级的诊断脚本；本机任务超出上述阈值时立即停止并改投服务器，不得靠"再等等"硬扛。
- **实现效率先于换机器**：任务变慢时先判断是算法还是硬件问题。逐行 Python 循环、重复的全量扫描、未缓存的中间制品属于实现缺陷，必须先向量化并把中间结果落盘缓存，再决定是否需要服务器。
- **大样本阈值选择禁止二次复杂度**：在验证集上从逐样本概率候选中选择阈值时，禁止对每个候选重复扫描全部标签或反复调用完整指标函数。必须采用一次稳定排序后按同分数组累计混淆计数的精确扫描，或证明具有等价语义且复杂度不高于 `O(n log n)` 的实现；启动真实运行前先按验证行数估算候选数与总操作量。
- 冻结合同要求双池等量批次时，每轮收据必须记录两个池的规模及各自抽取量。
- 低精度概率阈值必须按实际可观测的并列概率组整体选择，并在源验证重新计数假阳性；超过上限即失败停止。
- 所有用于阈值冻结的源验证逐样本概率、样本键、序列位置和哈希必须持久化。
- 多轮迭代的实验必须把昂贵中间制品（扫描结果、聚合视图、样本矩阵）落盘缓存并记录输入哈希，后续消融直接复用；禁止每次调参都重跑全量扫描。
- Arrow 固定长度列表按扫描批次转为 NumPy 时，必须同时校验 `list_size` 并按父数组 `offset × list_size` 切取当前批次的子值缓冲区；禁止直接把 `array.values` 全缓冲区当作当前批次，否则第二批以后会产生长度漂移。
- 使用暂存目录原子发布缓存或数据产品时，持久化清单必须写发布后最终绝对路径，不能记录 `.partial` 暂存路径；发布后立即逐项核验清单路径存在、位于发布根内且哈希一致，再允许训练消费者读取。
- 磁盘达到 80% 或可用不足 10 GiB 时通知用户；达到 90% 或不足 5 GiB 时停止新增大型文件和下载。

## 数据与最终测试隔离（强制）

- 冻结划分按样本、会话、时间或场景验证互斥，标签只取自冻结字段；提示、特征、路径、元数据和后处理不得泄露标签、攻击名或划分身份。
- 最终测试在方案、字段、提示、解析器、阈值、批大小、停止条件和超参数冻结前完全不可见，不得用于选择或修复方案。
- 数据路径、样本数、模型和物化语义以当前路线总控、冻结合同、配置与制品收据为准，不复制到长期规则。

## PyTorch 训练、精度与显存合同（强制）

- 新增或修改 PyTorch 模型、训练循环、混合精度、显存优化、`DataLoader` 或检查点入口前，实施前必须显式调用并读取 `$pytorch-patterns`；在实施计划或报告记录采用的技能条目。首次使用或对接口、参数、属性不确定时，先确认目标服务器实际安装版本，再按 Context7 或该版本官方文档核验；在实施记录写明库名、版本、查询来源和已核验签名。技能与目标版本官方接口或仓库规则冲突时，以官方版本文档和仓库规则为准，并披露冲突点与采纳理由。不得凭记忆把语法或导入通过当作接口存在。
- 资源估算必须以真实展开张量的上界为口径，至少写明序列批量、长度以及树、头、叶、层或等价并行维度的乘积、类型字节数和反向传播保留量；不得只按参数量估算显存。最坏候选的第一次真实 `optimizer.step()` 必须记录 `allocated`、`reserved`、`max_allocated`、`max_reserved`，并同时记录外部 `nvidia-smi` 进程显存；无 CUDA 时明确记录适用设备与可取得的等价资源读数。
- 每个训练合同在启动前预注册 `FP32`、`BF16` 或 `FP16` 及启用条件；不得把纯 `FP32` 作为无依据默认。设备支持且数值稳定时可选低精度：`BF16` 通常不配 `GradScaler`，`FP16` 必须使用已核验的 `GradScaler` 路径；敏感的 softmax、对数、归一化、损失和数值诊断可以保留 `FP32`。规则不强制所有模型使用 AMP；确有数值不稳定证据的模型可使用 `FP32`，但必须记录证据与合同理由。
- 不同结构用于科学选优、比较或消融时，精度合同必须一致。精度不同的比较只可标为工程资格或资源观察；若要作科学比较，必须补充同精度对照。精度与微批量只能按预注册合同和资源收据选择，不得依据 AP 或其他目标指标调节。
- OOM 的首选修复是数学等效的微批量与梯度累积：每有效批以微批损失 `sum` 累加、除以该有效批全部有效样本数；在有效批起点只执行一次 `zero_grad(set_to_none=True)`，结束时只执行一次梯度裁剪和 `optimizer.step()`；尾批按真实样本数归一化，禁止填充或丢弃。仅在此后仍不安全时才考虑 activation checkpointing，并记录重算范围与计算代价；禁止缩小冻结模型、树数、头数、序列、有效批量、训练步数或评价来伪装修复。
- 检查点只能写在完整 `optimizer.step()` 边界，至少保存模型、优化器、`scaler`（如有）、随机数状态、采样器状态、精度合同、微批量和累积步数；半步中断必须从该有效批的 `step` 起点重放，禁止保存或恢复部分累计梯度后跳过样本。
- 训练、验证和推理必须明确 `model.train()`、`model.eval()` 与梯度模式；模型及输入采用设备无关放置，并明确 CUDA、MPS、CPU 回退及其能力限制。推理只能在已核验接口下使用 `torch.no_grad()` 或 `torch.inference_mode()`，不得把训练路径误置为无梯度模式。
- 每个运行的资源收据和日志至少包含：设备与精度合同、有效批量、微批量、累积步数、张量上界口径、首次最坏步的内外部显存、峰值显存、峰值主存、磁盘余量、检查点边界、恢复次数和 OOM/数值异常原因。不得设置人为墙钟或 GPU 小时上限；保留显存、主存和磁盘安全门，资源不安全时停止并保留收据。

## 正式运行、同步与复审

- 精确目标测试通过后，不以无关完整测试、重复检查、格式化或非阻断复审延迟正式实验；审查并行并标记 `review_pending`，发现影响有效性的严重或重要问题时立即停止并作废结果。
- 两个及以上相互独立的训练或评估变体，在数据只读、输出目录与 SwanLab 身份独立且按保守峰值计算后显存和内存仍有安全余量时，默认并行启动；启动器必须提供可配置最大并发数、独立状态锁和已完成幂等跳过。仅共享可变制品、资源不足、I/O 瓶颈或需隔离测量单进程效率时可串行，并在状态收据记录精确原因；非阻断审查或归档不得作为串行理由。
- 正式包装器必须对代码、数据、配置、哈希、设备、SwanLab、标签和运行目录执行运行时断言；失败即保留日志并结束。
- 远程同步可直接使用 `rsync`、`scp` 或等价工具，不要求预建白名单；必须明确源与目标，禁止 `rsync --delete`，重要代码、配置和数据同步后核对存在性或摘要，服务器不得保存唯一代码、数据合同或结果副本。
- 禁止把远程执行辅助脚本、同步清单、配置、日志、状态文件或实验中间制品写入 `/tmp`；这些文件必须按用途保存在本项目的 `tools/`、`configs/`、`runs/` 或 `.Codex/docs/` 下。
- 本机和服务器运行实验前统一加载 `tools/env/activate.sh`；该入口负责把项目虚拟环境、`uv` 所在目录、项目工具目录和项目内 Rust 工具链加入 `PATH`，禁止再次仅凭初始 `PATH` 判断依赖不存在。
- 在 `llm_probe` 项目内执行 Python、模块入口、配置解析、导入检查或一次性诊断时，统一使用 `uv run --no-sync python`；禁止裸用 `python`、`python3` 或系统解释器。远端启动器与主进程临时门禁必须复用这一入口，不得因系统解释器缺失误判项目依赖不可用。2026-08-12 曾因启动前门禁误用裸 `python -m json.tool` 导致三项实验在启动前停止；改用项目 `uv` 入口后配置、依赖和模块门禁全部通过，详见 `.Codex/docs/RWKV/2026-08-12-C56远程门禁误用系统Python记录.md`。
- **禁止独立冒烟实验（强制）**：不得创建或运行任何独立冒烟**实验**，包括人工夹具、合成数据和真实数据最小子集。
- **允许合成数据的实现验证（2026-08-13 精确化）**：上一条禁止的是「用合成数据或最小子集得出科学结论」，
  不禁止「用合成数据验证公式实现与指标性质是否正确」。二者按下表区分，允许项须满足全部四条约束。

  | | 禁止：冒烟实验 | 允许：实现验证 |
  | --- | --- | --- |
  | 目的 | 判断方法有没有效 | 判断代码算的是不是公式说的那个量 |
  | 真值 | 未知，靠结果推断 | **已知**，由构造给定或有解析解 |
  | 产出 | 指标、排序、结论 | 通过/不通过，及偏差量 |
  | 能否进论文 | 不能，且不得冒充 | 不能，只作实现正确性附录 |

  四条约束：一，必须有**构造给定的真值**或解析对照，不得用真实数据子集充当；
  二，**不得创建运行身份**（不注册 SwanLab run、不占用运行目录编号），产物落 `tools/` 或临时目录并随任务清理；
  三，**结果只能表述为「实现正确/不正确」**，禁止表述为方法性能、禁止进入任何结果表；
  四，**必须写明验证了哪条公式或哪个性质**，以及判据。

  **依据（2026-08-13 实测）**：当日三次实现验证各抓到一个会污染论文的错误——
  其一，为「攻击类别分面不可比」设计的 `lift = AP/基率` 修法，在难度相同、仅改正例数的构造上
  实测 AP 变 8 倍而 lift 变 506 倍，该修法被当场证伪，改用 ROC-AUC 与 `Rec@4%FPR`（实测基率不变）；
  其二，Saerens EM 先验估计要求输入为源先验下的校准后验，而本课题模型经 `pos_weight` 训练后输出非校准后验，
  直接喂入会收敛到 1.0，据此在实现中前置保序回归校准；
  其三，检查点调度由「末 5 个 epoch」被无意改成「全程 5 等分」，靠位置枚举发现，
  否则 `L=128` 的集成会混入只训到 20% 的模型、与冻结的 C11 无法对表。
  三者均无法由编译、导入或 CLI 入口检查发现，也无法在真实实验跑完后区分于机制效应。生产代码仅可执行格式化、编译、导入或 CLI 入口检查，随后直接运行冻结开发区的真实快速实验。设备、依赖和数据合同门禁必须作为正式运行的前置阶段或同一单入口内的机械检查，不得单独拟合或预测、另建运行身份或重复消耗数据；正式运行前失败必须保留收据，但不得称为科学结果。
- 长任务使用唯一运行身份、持久状态、检查点和原始日志恢复；阶段门禁完成后及时回收源码、配置、清单、日志、检查点和结果。
- 删除前列出精确路径并确认已有本机、可重下或私有备份；原始或冻结数据、检查点和日志必须另获用户明确授权，禁止通配符、上级递归和删除唯一证据。

## SwanLab、日志与结果写回（强制）

- 正式 GPU 实验使用 SwanLab 在线模式，项目与运行身份从当前路线总控或冻结配置读取；唯一运行目录保存配置、环境、数据摘要、控制台与 SwanLab 日志、逐步指标、结果、预测和制品清单，失败也保留状态与原因。
- 任何会向 SwanLab 上报的入口必须在创建运行、启动 `screen` 或读取数据前，机械断言工作区和项目名与用户本轮明确授权完全一致；不得只检查登录状态或在运行后从日志发现目的地错误。目的地不一致时退出且不上传，修正后使用新的运行身份，禁止把旧项目记录冒充授权项目记录。
- 使用 PyTorch 新增张量接口前必须以正式服务器已安装版本为准；首次或不确定的第三方接口必须先调用 **`find-docs` 技能**（`daily-coding` 已规定的文档查询入口；Context7 为其后端之一），或在其不可用时核验该版本官方文档/本机源码，并在实施报告记录版本、来源和接口。仅有 `py_compile` 不足以证明运行时属性存在。2026-08-11 的 R1 M1 因实现代理未执行该既有门禁、误用不存在的 `torch.flatnonzero` 而失败；等价索引统一使用 `torch.nonzero(condition, as_tuple=True)[0]` 或已核验接口。 2026-08-13 同型事故复发：SwanLab 埋点凭记忆写成 `run.public.cloud.project_name`，实测 0.9.0 的 `Run` 公开属性仅 `id/name/path/url/dir/config/log*`，无 `public`；代码未经审查即推送，首个 run 崩溃。**同一事故中主代理还断言 `experiment_name=` 无效，实测该参数经向后兼容映射有效**——凭记忆断言接口「不存在」与断言其「存在」同样不可靠。两起事故的共同点是「语法检查通过」被误当作「接口存在」。混合精度分支的聚合缓冲区必须从实际生产张量继承设备与类型，禁止依据未经过同一算子的输入张量推断类型，否则 `index_copy`、拼接或散射会在真实运行中出现类型不一致。
