# llm_probe 实验工程规则

<!-- 规则加载哨兵：NOTE_LLM_PROBE_20260724 -->

本文件只规定 `thesis/experiments/llm_probe/` 的实验工程增量。当前数据、候选、服务器、运行身份和数值合同从路线总控、章节恢复卡、冻结配置与制品读取，不复制进长期规则。

## 按需合同

- 修改、同步或运行 `scripts/` 前读取其 `AGENTS.md`。
- GPU、服务器、任务放置、容量估算、有界状态、数据热路径、资源监测、下载、镜像、物化和检查工具读取 `.Codex/docs/agents-split/llm-probe-operational-contract.md` 的匹配章节。
- 新增或修改神经模型、训练循环、精度、显存、`DataLoader`、推理模式或检查点时，先读取 `$pytorch-patterns`，核验目标环境版本与接口，再读取 `.Codex/docs/agents-split/llm-probe-neural-training-contract.md`；同族科学比较必须使用同一冻结 profile。
- 外部制品、任务冲突、SwanLab、制品枚举、恢复、包哈希、冻结合同、模型视图和历史故障读取 `.Codex/docs/agents-split/llm-probe-failure-prevention-handbook.md` 的匹配章节；重复门具体反例和其他事故详情不得重新复制到本文件。
- 新增需注册的机器学习组件才用 `architecture-design`。同一问题连续两次无进展即停止同类补丁，改核验目标版本官方文档、源码和问题记录。

## 数据合同与最终测试隔离

- 划分须按冻结的样本、会话、时间或场景互斥；标签只取冻结字段，特征、路径、提示、元数据和后处理不得泄露标签、攻击名或切分身份。
- 最终测试在方案、字段、解析器、阈值、批量、停止条件和超参数冻结前不可见，不得用于选择、诊断或修复。阈值须按可观测的并列概率组整体选择，并在源验证重新计数假阳性。
- 新增或修改数据视图、物化器、加载器或模型适配器前，冻结生产端与全部消费者共享的模式版本、主键、切分、标签连接、字段、历史表示、制品清单和兼容策略；统一清单与加载器服务传统模型、神经基线和候选，禁止模型专用重复物化。
- 所有用于阈值冻结的源验证逐样本概率、样本键、序列位置和哈希须持久化；双池或配对合同记录各池规模和每轮抽取量。
- 正式比较、候选与消融须遵守共同预算、字段权限、精度和评价合同。`engineering_only` 与 `screening_only` 运行只用于实现调试、速度诊断或信号筛选，可自选微批量、精度、容量、训练与评估预算和资源，但仍须遵守数据与标签合法性、年度隔离、结果真实性、唯一运行身份和原子断点恢复；其结果不得进入论文正式结果、表格、帕累托比较或模型与机制优劣主张，拟晋级正文的结论须以独立正式运行身份按冻结公平合同重跑，不得据此削弱正式基线。

## 数据集－模型适配硬门

- 任何新骨干、新机制或模型适配器在编写代码前须提交并冻结“数据集－模型适配表”；表未完成不得实现、同步、启动或创建正式运行身份。
- 适配表逐项登记：字段名称、类型和索引；连续、计数、端口、协议和二元粗拓扑字段的处理；训练区拟合的变换、词表、缺失补零和回退；原始 IP 的仅分组用途；实体时间顺序、`I/M` 切片和历史表示；因果边界；标签与损失权重；模型输入、输出、状态和梯度接口；参数量公式；数据、切分、字段清单、拟合状态和变换哈希。
- 所有适配、拟合、候选选择和封印只可使用 LSPR23 的训练区及其冻结开发划分；LSPR24 对适配、字段、变换、词表、容量、优化器、检查点和阈值零参与。统一 83 字段只约束信息预算，不要求各模型用相同张量布局、归一化或表示。
- 适配表须明确模型所需输入与当前数据视图的缺口及满足缺口的全文或官方依据；无法冻结字段处理、时间因果或接口合同则停在适配阶段，不得用默认扁平输入绕过。

## 实现验证与真实运行

- 实验工程不创建或运行人工夹具、单元测试、集成测试或独立冒烟实验，不用合成数据或真实最小子集判断方法性能。生产代码执行与任务直接相关的语法、导入、静态或 CLI 检查后尽快进入冻结开发区真实实验；禁止运行 `black` 和其他未经用户当轮授权的自动格式化器。
- 允许用有构造真值或解析解的合成输入验证公式实现与指标性质，但不得创建 SwanLab 身份或正式运行编号；只输出“实现正确/不正确”和偏差量并注明判据，产物放临时目录并清理，禁止进入论文结果。
- 本机 Python 的语法、导入、配置与诊断检查先 `source tools/env/activate.sh`，再用 `uv run --no-sync python`；服务器同样遵守该入口。禁止裸用系统 `python` 或 `python3`，也不得手工设置缓存变量绕过激活脚本；该脚本统一设置 `PYTHONPYCACHEPREFIX`，使字节码缓存离开工作树。
- **本机真实数值与 MPS 实验环境**：截至 2026-08-28，项目 `.venv` 未安装 NumPy 与 PyTorch，不得用它启动数据扫描、训练或评价；已验证入口固定为 `/opt/miniconda3/envs/rwkv/bin/python`，其中 PyTorch `2.12.0`、scikit-learn `1.9.0`、SciPy `1.18.1`，沙箱外 `torch.backends.mps.is_available()` 为真。运行前先用该解释器一次性核验版本与 MPS；失败则报告环境漂移，不得回退到裸 `python3`、不得再向项目 `.venv` 临时补包。该环境只服务本机 `screening_only`/工程校准；服务器仍用项目 `uv run --no-sync` 和冻结 CUDA 精度配置。两端必须执行同一 Python 工具、模型公式、数据接口、指标和检查点模式，只允许运行配置、设备精度、批量、计算预算、资源收据与运行身份不同；MPS 权重不得续训或冒充正式 CUDA 权重。
- 正式入口对代码、数据、配置、哈希、设备、跟踪平台、标签和运行目录作运行时断言；失败保留脱敏日志和原退出码。相互独立变体在只读数据、独立输出与跟踪身份、资源安全时默认并行；共享可变制品、资源或 I/O 不足时才串行并记录原因。
- 并发条件下的性能与工程指标可进入正式实验表，但收据须记录并发对象、时间窗口、`resource_contention=true` 与采样来源，时间、吞吐和峰值资源标为“并发条件实测”，不得冒充独占效率或用于严格效率支配；确认无数值漂移者可作正式值，资源公平比较须在正文加脚注说明并发条件或补做独占复测。本规则不削弱数据隔离、结果真实性、唯一运行身份和原子断点恢复。
- 长任务使用唯一运行身份、持久状态、检查点、原始日志和幂等完成判断；删除运行制品按根规则列出精确路径、确认可恢复并取得用户明确授权，禁止通配符递归删除和删除唯一证据。

## 门禁密度与恢复

- 只有数据或标签合法性（含泄漏、年度隔离与最终测试隔离）、代码与配置身份、硬资源安全，或原子断点恢复不能成立时，门禁才可阻断实验。不得以本节任何条款削弱这些硬门。
- **默认不新增阻断门。** 新增任何 `raise` 或非零 `exit` 前，先证明它防止的是会使结果无效的真实失败，并在实施计划或故障手册写明该失败、权威输入（冻结配置、身份清单、资源实测或已发布断点）、正式入口的验收位置和失败后的保留恢复行为。证明不成立即改为披露；独立静态门、历史数值一致性和未验证推测不得充当阻断依据。
- **同一门连续两次拦下本可正常进行的实验，即判为冗余，立即废弃或降级为披露，不必复审。**
- **禁止用多个门检查同一件事。** 新增前核对既有门是否已覆盖，重复的一律不加；具体事故与处置只读故障手册。
- **披露优先于阻断。** 并发、资源争用、非独占、重复静态检查、格式检查、非关键诊断、归档和非阻断复审只写收据并打印，不阻塞已通过硬门的实验。并发或资源门须按实际子进程、进程组或运行身份排除自身启动器与监控进程，不依赖 `ALLOW_CONCURRENT` 放行。
- **三类不可废弃，因为它们是事实记录而非门禁**：年度隔离与最终测试隔离、`training-identities.json` 的训练身份漂移检查、`code_sha256` 等代码身份冻结。删除它们不会让实验更顺，只会让结果无法解释。
- 优先执行能证伪假设的最小真实实验并以最小实现推进，不为未证实的收益预建体系；新增抽象、配置或制品须说明相对复杂度的具体收益与权威依据。
- 同一门在同一动作中最多执行一次；中断后由同身份原子断点恢复，不重跑已完成阶段来重复门禁。已封印清单登记的用途令牌由正式入口注入，禁止要求操作者重复配置或回显令牌。
