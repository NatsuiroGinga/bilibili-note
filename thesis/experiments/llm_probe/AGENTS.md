## 强制路由

- 修改、同步或运行 `scripts/` 前，完整读取 `scripts/AGENTS.md` 及其远程执行合同；正式远程操作只用统一启动器。
- 涉及外部制品、非 ASCII 远程载荷、任务边界冲突、TQH-C2、SwanLab、包时间与哈希、冻结合同、模型视图、生成式评测、Rust 工具或 ns-3 同步时，分析或编辑前完整读取 `.Codex/docs/agents-split/llm-probe-failure-prevention-handbook.md` 的匹配章节。
- 新增需注册的机器学习组件才用 `architecture-design`；版本控制任务才用 Git 技能。缺陷按根规则调试。生产代码或实验协议实质修改经最小行为验证后由新代理独立审查；已过正式门禁时审查不得延迟启动，但运行标记 `review_pending`。审查发现影响有效性的严重或重要问题时立即停止并作废结果。

## 服务器、硬件与凭据

- 本地根为 `/Users/bilibili/personal/note/thesis/experiments/llm_probe`，服务端根为 `/root/autodl-tmp/thesis/experiments/llm_probe`。生成式基座固定为 Qwen3-1.7B；RTX 5090 32GB 只是当前环境，不得成为正确性条件。
- 当前活动服务器只从 `GPU_SSH_378`、`GPU_PWD_378` 或其既有登录状态取得，缺失时先 `source ~/.zshrc`；旧的 `GPU_SSH`、`GPU_PWD` 仅在用户明确指定旧服务器仍可用时使用。密码、地址解析结果和令牌不得进入输出、配置、日志、URL、清单或文档。
- 服务器不得假定在线或长期保留。GPU 训练、生成式评估、显存兼容或加速测试前，告知用户任务、预计时长、显存、开机需求和费用性质，确认可用后才执行；纯 CPU 实现、审计和确定性物化无需等待。遇到预期关机、服务器回收或地址切换时，立即停止自动重试，不计作科学失败；新服务器先只读核验身份、项目根、磁盘、依赖、源码锁、数据和运行制品，再决定白名单同步或恢复动作，禁止凭旧状态直接续跑。
- 默认计算分工为“本机 CPU、服务器 GPU”。代码开发、复审、数据物化、哈希、统计、报告、传统基线和其他纯 CPU 工作全部在本机执行；Linux 专属但不需要 GPU 的任务优先使用本机容器或虚拟机。GPU 服务器只运行 GPU 训练、GPU 推理、生成式评估及这些运行不可避免的数据加载和日志进程。除用户再次明确授权外，不得在 GPU 服务器执行独立 CPU 编译、ns-3 仿真、QUIC 采集、数据处理、物化、统计或审查。
- 新旧服务器之间仅允许只读盘点、白名单 `rsync` 中转以及 GPU 正式运行所需的最小启动操作。CPU 任务缺少远端原始制品时，优先把必要输入回收本机后处理；不得因为本机较慢或工具缺失自动退回服务器计算。Linux 环境不具备且本机容器或虚拟机无法满足时，明确报告阻塞并等待用户裁决。
- 外部源码、Linux 工具链、依赖包、模型和可中转数据默认在本机下载；本机记录来源 URL、固定版本、文件大小和内容哈希后，通过白名单 `rsync` 同步服务器。服务器默认只执行 GPU 正式运行所需的解压、隔离安装、启动与结果回收，不直接访问 GitHub、Rust 官方源、镜像站、包仓库或数据下载站，也不承担独立 CPU 编译或数据生成。因服务器专属签名地址、授权状态或本机及其容器确实无法取得而必须例外时，先记录具体原因、目标路径和可恢复策略，再取得用户明确许可；不得为方便或速度自行退回服务器下载或计算。
- 本机下载必须在启动前执行镜像优先选择：Rustup 与 crates.io 优先使用清华大学开源软件镜像站，Hugging Face 优先使用既定镜像或 ModelScope，其他来源优先使用已核验的国内学术镜像。仅当镜像缺少固定版本、返回不可用状态、内容哈希不符、授权无法转移或镜像实测持续失败时，才能回退官方源；“官方源可以连接”不构成回退理由。每次回退必须在下载日志或来源清单记录镜像地址、失败证据、官方地址和制品哈希。已经开始且切换注册表会导致已完成内容全部重下时，可以在记录一次性例外后完成当前制品，但后续重试和新下载必须使用镜像。
- 数据处理、协议审计、HGB、XGBoost 和通用评价支持纯 CPU；神经入口默认 `device=auto`、`precision=auto`。无 CUDA 时至少能加载与评价，不适合正式训练则结构化拒绝。硬件降级不得改变有效批量、样本、种子、步数、评价清单和科学超参数；记录实际硬件与适配项，只在同档硬件比较成本和性能。
- 预计超过 5 分钟的编译、数据生成、物化或独立实验，在启动后 2 分钟内必须采样 CPU、GPU、内存、磁盘写入、负载、活动子进程数和实际吞吐；禁止假定 Cargo、CMake、Python 执行器或第三方工具会自动并行。任务彼此独立且资源明显空闲时，立即采用受控并行、分片或作业数参数，并保留成功制品后只续跑缺失项；先以保守并发度运行 3 分钟，再依据吞吐和资源压力上调或下调。并发变化只允许改变执行调度，不得改变数据、种子、步数、配置或科学参数，且必须写入资源与吞吐收据。
- 磁盘使用率达到 `80%` 或可用不足 `10 GiB` 时通知用户；达到 `90%` 或不足 `5 GiB` 时停止新增大型文件和下载。

## 数据工程与防泄漏

- 新建的性能敏感数据热路径默认用 Rust；读取 `rust-skills`，采用流式、有界内存和确定性并行。训练、推理、SwanLab、配置保留 Python，ns-3 保留 C++。Rust 与冻结参照比较模式、行数、类型、缺失、`sample_id`、顺序和语义哈希；不得静默回退 Python，也不运行 `cargo fmt`。
- GeNIS 种子 42 数据为 `runs/data-bundled/genis-hierarchical-v2-multitask-seed42`，训练 `15000` 条、验证 `2700` 条。训练、校准、提示和超参数选择不得含未知攻击子类或使用最终测试集。
- 冻结划分按 `sample_id`、会话、时间或场景验证互斥；标签只来自冻结字段。提示、特征、路径、元数据和后处理不得泄露标签、攻击名或划分身份。最终测试只用于方案冻结后的最终评价，不得选择阈值、批大小、解析器、提示、停止条件或修复方案。
- 最终冻结或字段、单位、划分、排序、解析语义改变时才双物化；探索与先导一次并记录输入和代码摘要、模式、行数、顺序、缺失和语义哈希。训练与推理不为逐字节一致重复运行。
- 超过 `1000` 条的生成式评测先在非最终测试样本核对批量与单条贪心输出、吞吐、显存、增量落盘和断点续评；不得改变冻结顺序、标签合同、最大生成长度或指标，受约束候选评分不能替代自由生成有效率。

## SwanLab、验证与写回

- 正式 GPU 实验使用 SwanLab 在线模式，项目固定为 `mortiswang/malicious-traffic-llm`，禁止旧项目。唯一目录保存配置、环境、数据、控制台与 SwanLab 日志、逐步指标、结果、预测和制品清单；失败也保留状态与原因。云端核对运行、指标点和图表，并记录服务端、本地与运行地址。
- 未获用户重新授权，正式运行前不得新增或重跑独立 `pytest` 目标测试。禁止 `ast.parse`、抽象语法树断言和独立真实导入预检；每项任务至多一次精确范围 Pyright，已有零问题不得重复。Black、Ruff 只在交付、审查或提交前集中一次；禁止直接或经任何包装器调用 Prettier，Markdown、YAML、JSON 不自动格式化。Shell 门禁见 `scripts/AGENTS.md`。
- Git 状态和差异不得作为实验启动门禁，仅用于提交、冲突或疑似误覆盖。验证失败先最小修复，禁止回滚无关改动。
- 新实验决策、确定结果、路径和错误先写详细记录，再更新 `output/第一创新点实验总控.md`；章节关系或长期边界变化还要更新 `output/开题改进交接文档.md`。长日志和逐轮审查只放 `.Codex/docs/`。
- 故障完成根因定位和最小验证后，把可复用触发条件、根因、检查与验证写入故障手册；未写回不得标记调试完成，但不得阻塞已通过门禁的实验。
