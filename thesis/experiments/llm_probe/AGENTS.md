# llm_probe 实验工程规则

<!-- 规则加载哨兵：NOTE_LLM_PROBE_20260724 -->

本文件只规定 `thesis/experiments/llm_probe/` 的实验工程增量。当前数据、候选、服务器、运行身份和数值合同从所属路线总控、章节恢复卡、冻结配置与制品读取，不复制进长期规则。

## 按需合同

- 修改、同步或运行 `scripts/` 前读取其 `AGENTS.md` 与 `.Codex/docs/agents-split/remote-script-execution-contract.md`。
- 服务器切换、资源监测、下载、镜像、物化和检查工具读取 `.Codex/docs/agents-split/llm-probe-operational-contract.md` 的匹配章节。
- 外部制品、任务冲突、SwanLab、制品枚举、恢复、包哈希、冻结合同、模型视图和历史故障读取 `.Codex/docs/agents-split/llm-probe-failure-prevention-handbook.md` 的匹配章节；事故详情不得重新复制到本文件。
- 新增需注册的机器学习组件才使用 `architecture-design`。同一问题连续两次无可验证进展时停止同类补丁，核验目标版本官方文档、源码和问题记录；第三次必须基于新证据提出单一可证伪假设。

## 资源与远程执行

- GPU 训练、推理、生成评测、显存或加速测试前，向用户说明任务、预计时长、显卡与卡数、显存、开机和费用需求，确认资源可用后执行。本机只做短小 CPU 开发、哈希、统计和报告；服务器承担 GPU、大规模物化和大规模 CPU 工作。
- 预计墙钟超过 30 分钟、常驻内存超过 8 GiB、扫描超过 500 万行或 1 GiB、训练矩阵超过 100 万行乘 100 列，任一满足即为大规模任务，不得在本机启动。先估算并报告；若传输代价接近或超过计算代价，先修正放置方案。
- 预计处理 100 万条以上记录、会话或行时，启动前证明每类中间状态的固定上界，登记键基数、每键历史、批大小、单状态字节、峰值内存、临时文件和总 I/O。跨批集合、聚合器、排序或缓存随输入增长时，先增加驱逐、分区或磁盘溢写。
- 性能异常先区分算法与硬件。逐行 Python、重复全量扫描和未缓存中间制品先修复、向量化或落盘复用，再决定换机器；验证集阈值选择不得对每个候选全量重扫，采用一次稳定排序与同分组累计，或证明复杂度不高于 `O(n log n)`。
- Arrow 固定长度列表按批次转 NumPy 时，同时校验 `list_size` 并按父数组 `offset × list_size` 切当前值缓冲区；原子发布数据产品时，清单写发布后的最终路径，发布后核验路径位于根内、存在且哈希一致。
- 磁盘占用达到 80% 或可用不足 10 GiB 时通知用户；达到 90% 或不足 5 GiB 时停止新增大型文件和下载。资源不足、服务器离线或回收不计科学失败，保留状态收据。

## 数据合同与最终测试隔离

- 划分须按冻结的样本、会话、时间或场景互斥；标签只取冻结字段，特征、路径、提示、元数据和后处理不得泄露标签、攻击名或切分身份。
- 最终测试在方案、字段、解析器、阈值、批量、停止条件和超参数冻结前完全不可见，不得用于选择、诊断或修复。阈值须按实际可观测的并列概率组整体选择，并在源验证重新计数假阳性。
- 新增或修改数据视图、物化器、加载器或模型适配器前，冻结生产端与全部消费者共享的模式版本、主键、切分、标签连接、字段、历史表示、制品清单和兼容策略；统一清单与加载器服务传统模型、神经基线和候选，禁止模型专用重复物化。
- 所有用于阈值冻结的源验证逐样本概率、样本键、序列位置和哈希须持久化；双池或配对合同记录各池规模和每轮抽取量。
- 正式比较、候选与消融须遵守共同预算、字段权限、精度和评价合同。筛选运行只支持候选裁决，不能进入论文正式结果或对外效果主张。

## 数据集－模型适配硬门

- 任何新骨干、新机制或模型适配器在编写代码前，必须先提交并冻结“数据集－模型适配表”；表未完成时不得实现、同步、启动或为其创建正式运行身份。
- 适配表逐项登记：字段名称、类型和索引；连续、计数、端口、协议和二元粗拓扑字段的处理；训练区拟合的变换、词表、缺失补零和回退；原始 IP 的仅分组用途；实体时间顺序、`I/M` 切片和历史表示；因果边界；标签与损失权重；模型输入、输出、状态和梯度接口；参数量公式；数据、切分、字段清单、拟合状态和变换哈希。
- 所有适配、拟合、候选选择和封印只可使用 LSPR23 的训练区及其冻结开发划分；LSPR24 对适配、字段、变换、词表、容量、优化器、检查点和阈值零参与。统一 83 字段只约束信息预算，不要求不同模型使用相同张量布局、归一化或表示。
- 适配表必须明确模型所需输入与当前数据视图之间的缺口，以及满足缺口的全文或官方依据；无法冻结字段处理、时间因果或接口合同则停止在适配阶段，不得用默认扁平输入绕过门禁。

## PyTorch 训练与显存

- 新增或修改 PyTorch 模型、训练循环、混合精度、显存优化、`DataLoader` 或检查点前，必须调用并读取 `$pytorch-patterns`，核验目标服务器实际安装版本及所用接口，在计划或报告记录技能条目、版本、官方来源和签名。
- B76 RTX 5090 的新神经训练默认使用 `configs/neural-precision-profiles-v1.json` 中的 `cuda-bf16-amp-fp32-sensitive-v1`，并通过 `tools/neural_precision_runtime.py` 接入：BF16 autocast，参数、优化器状态和敏感计算保持 FP32，BF16 不使用 `GradScaler`，有效批固定且只按资源选择数学等效微批与累积。FP32、FP16 和 activation checkpointing 只能作为有收据的显式例外；同族结构、机制和选型的科学比较必须使用同一 profile，跨 profile 只作完整系统或工程 Pareto，活动旧运行不得中途切换精度。完整合同见 [RTX 5090 神经训练默认精度模式实施报告](../../../.Codex/docs/RWKV/2026-08-21-RTX5090神经训练默认精度模式/实施报告.md)。
- 资源估算按真实展开张量上界，写明批量、长度以及树、头、叶、层等并行维度乘积、类型字节与反向保留量；不得只按参数量。最坏候选第一次真实 `optimizer.step()` 记录 `allocated`、`reserved`、`max_allocated`、`max_reserved` 和外部进程显存。
- 每个合同预注册 `FP32`、`BF16` 或 `FP16` 与启用条件。`BF16` 通常不用 `GradScaler`，`FP16` 使用已核验缩放路径；敏感 softmax、对数、归一化和损失可保留 `FP32`。结构比较必须同精度；异精度只作工程资格观察，除非补同精度对照。
- OOM 首选数学等效微批量和梯度累积：有效批起点一次 `zero_grad(set_to_none=True)`，微批损失按 `sum` 累加后除以全部有效样本数，有效批结束一次裁剪和 `optimizer.step()`，尾批按真实样本归一。此后才考虑 activation checkpointing；禁止缩小冻结模型、序列、有效批量、训练步数或评价伪装修复。
- 检查点只写在完整 `optimizer.step()` 边界，保存模型、优化器、缩放器（如有）、随机状态、采样器、精度、微批量和累积步数；半步中断从有效批起点重放，不恢复部分累计梯度后跳过样本。
- 训练、验证和推理明确 `model.train()`、`model.eval()` 与梯度模式，设备无关放置并记录 CUDA、MPS、CPU 回退限制。推理只在已核验接口下使用 `torch.no_grad()` 或 `torch.inference_mode()`。
- 每次运行收据至少包含设备、精度、有效批量、微批量、累积步数、张量上界、首次最坏步内外显存、峰值主存、磁盘、检查点边界、恢复次数和 OOM 或数值异常。不得设置人为墙钟或 GPU 小时上限；资源不安全时停止并保留收据。

## 实现验证与真实运行

- 实验工程不创建或运行人工夹具、单元测试、集成测试或独立冒烟实验，不用合成数据或真实最小子集判断方法性能。生产代码执行与任务直接相关的语法、导入、静态或 CLI 检查后，尽快进入冻结开发区真实实验。
- 允许用有构造真值或解析解的合成输入验证公式实现与指标性质，但不得创建 SwanLab 身份或正式运行编号；只输出“实现正确/不正确”和偏差量，注明公式与判据，产物放任务临时目录并清理，禁止进入论文结果。
- 本项目禁止运行 `black` 和其他未经用户当轮授权的自动格式化器。格式、重复检查、归档和非阻断复审不得延迟已满足数据与运行门禁的实验。
- 本机和服务器运行前加载 `tools/env/activate.sh`；项目内 Python、模块、配置、导入和诊断统一使用 `uv run --no-sync python`，禁止裸用系统 `python` 或 `python3`。
- 正式入口对代码、数据、配置、哈希、设备、跟踪平台、标签和运行目录作运行时断言；失败保留脱敏日志和原退出码。相互独立变体在只读数据、独立输出与跟踪身份、资源安全时默认并行；共享可变制品、资源或 I/O 不足时才串行并记录原因。
- 长任务使用唯一运行身份、持久状态、检查点、原始日志和幂等完成判断。删除前列出精确路径并确认可恢复；原始或冻结数据、检查点和日志须用户明确授权，禁止通配符递归删除和删除唯一证据。

## SwanLab、日志与写回

- 正式 GPU 实验使用 SwanLab 在线模式；项目和运行身份来自总控或冻结配置。任何上报入口在创建运行、启动持久会话或读数据前，机械断言工作区与项目名等于用户本轮授权；不一致即停止并使用新身份修正。
- 唯一运行目录保存配置、环境、数据摘要、控制台与 SwanLab 日志、逐步指标、结果、预测和制品清单；失败也保留状态和原因。云端日志不能替代本地原始日志。
- 预计超过 1 分钟的构建、物化、训练、评估、下载和启动器记录各阶段开始、结束、跳过与状态转换；限频心跳包含已处理量、总量、吞吐、耗时和可计算的剩余时间。超周期无进度时记录阻塞阶段、等待和恢复动作，不逐样本刷屏，不记录凭据或敏感载荷。
- 交付前用真实运行或最小命令入口确认关键阶段日志、心跳或快速完成记录、持久化路径和失败保留行为。每次运行核对云端指标与图表，记录服务端路径、本地回收路径和运行地址。
- 新裁决、确定结果、路径和错误先写 `.Codex/docs/` 详细记录，再按当前路线规则更新总控或章节恢复卡；可复用故障模式写入既有故障手册，不扩写本文件。
