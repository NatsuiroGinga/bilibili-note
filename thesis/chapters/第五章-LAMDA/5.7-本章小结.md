## 5.7 本章小结

本章把第三章的数据预算分配与第四章的成员化训练组装为一个训练系统，用统一入口重跑全部配置格，以系统级测试回答组装有效性与组装代价两个问题。

系统在整体上分为服务与计算两侧。服务侧以 Go 实现，承担任务生命周期、接口服务与结果读取；计算侧以 Python 的统一训练入口承担，按配置层、数据预算层、成员化引擎层与评测层四层组织，两章机制以直接导入的方式进入数据预算层与成员化引擎层，统一入口自身不含新算法。任务按单一工作协程串行消费，同刻最多一个训练子进程，每格收据在独占条件下取得。数据库以容器方式部署，凭据只经环境变量注入；训练内核运行于宿主机，原因是本机容器环境无法访问 Metal 加速框架。

系统级消融给出三项读数。两项开关单独启用均为正增益，数据预算开关 9.26 个百分点、成员引擎开关 3.32 个百分点；两项同时启用取得 10.79 个百分点，完整格达到 83.23%；成员引擎在数据预算之上的增量为 1.54 个百分点，其置信区间 [1.22, 1.87] 排除零。预算格的重跑读数与第三章正式制品逐位一致，组装不改变任一章机制的读数。年度分面给出两项开关的作用面分工：数据预算开关的增益集中在富余年度，把 2017 与 2018 两个年度的回看 F1 从 47.17% 与 47.90% 带回 90.61% 与 88.85%；成员引擎的增量偏稀缺年度，在 2023 与 2024 两个年度分别取得 4.38 与 2.82 个百分点。两项开关的作用面在年度轴上互补，完整系统的增益由这一互补构成。

组装代价集中在成员引擎的墙钟上。集成形态的墙钟为朴素形态的 5.1 倍，与四倍浮点运算量的下限相合，超出部分落在算子调度与启动开销，该差距的收窄幅度在迁移到 CUDA 设备后以编译优化对照实测；参数开销为 1.34%，驱动层峰值显存由加速器上下文主导，三项代价都不构成运行约束。full 格与评测服务对照实验的读数在各自实验完成后回填，本机 MPS 序列的制品保持冻结，迁移后的正式读数在 CUDA 序列下整体重跑取得。
