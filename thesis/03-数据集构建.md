## 3.1 引言

守恒不变量是 CI-PRD 与 PIC-GRPO 的物理前提——只有先在数据上把不变量定义清楚、验证其可计算性，两个创新点才有物理依据（见 [[04-CI-PRD-创新点1]] §4.3）。然而，现有公开入侵检测数据集（如 CSE-CIC-IDS2018 [cite:CIC-IDS2018]）均为端点侧单点采集的流级聚合特征，不提供拓扑多节点视图与路由器内部状态。IDS2018 字段普查（见 [[IDS2018字段普查报告]]）实证表明：节点流量守恒（I1）所需的多端口字节计数不可观测，TCP 流体方程残差（I5）所需的队列 $q(t)$、丢包概率 $p(t)$ 亦为路由器内部状态——即便使用原始 PCAP 包级数据，仍无法计算。

因此，本章采用**公开数据集 + 自构造测试床**的组合策略：公开数据集提供流级守恒不变量（I2/I3/I4）的可计算性与有标签的定量评测基准，自构造测试床补足节点级守恒（I1）所需的多节点拓扑视图。本章依次介绍公开数据集选型（§3.2）、自构造测试床设计（§3.3）、守恒不变量的定义与可计算性验证（§3.4）、课程难度标注方案（§3.5）、数据集统计与划分（§3.6）。

## 3.2 公开数据集

本节介绍已核实（curl 官方页面确认格式与可获取性，见 [[数据集选型核实报告]]）的公开数据集短名单，按角色分为主数据集、跨集泛化基准与专项验证集。

### 3.2.1 CSE-CIC-IDS2018（主数据集）

CSE-CIC-IDS2018 [cite:CIC-IDS2018] 由加拿大网络安全研究所发布，是本课题的主实验数据集，包含 Brute Force、Heartbleed、Botnet、DoS、DDoS、Web Attack、Infiltration、PortScan 等多类攻击标注。

**流级 CSV（CICFlowMeter）**：80 个流级双向特征（协议、端口、时间戳、前/后向字节与包计数、TCP 标志计数、IAT 统计、子流指标、活跃/空闲时间等），经普查确认字段完整（见 [[IDS2018字段普查报告]]）。协议分布混合（如 Friday-02-03 日 TCP 79%、UDP 19%），覆盖 TCP 与非 TCP 流量。标签分布以 Benign 为主（72-99%），攻击样本稀疏，符合真实场景的长尾特性。

**原始 PCAP**：IDS2018 配套完整原始包捕获文件（每日 pcap.zip，约 35-55 GB），可提取 TCP 窗口、RTT、报文间隔等包级时序特征，用于严格 I3（逐包未答 SYN）与部分 I5（TCP 窗口/RTT 重建）。本课题从截断下载中用 `zip -FF` 修复恢复了多个完整的 per-host pcap（30-70 MB，Thursday-15-02 DoS 日），并在其上验证了严格 I3 的可计算性（见 [[experiments/README|实验 v4]]：未答 SYN 均值 26-37%，多窗口 100%）。

**实验验证**：在 IDS2018 流级 CSV 上，I2（流双向守恒）对单向 DDoS 洪泛（HOIC/LOIC-UDP）召回 76-100%、误报 0.6%（见 [[experiments/README|实验 v3]]），验证了守恒不变量在公开数据上的有效性。

**局限**：IDS2018 为端点侧单点采集，无拓扑多节点视图 → I1 不可算；无路由器队列/丢包 → I5 不可算。这些局限由 §3.3 自构造测试床补足。

### 3.2.2 跨集泛化基准

为验证模型的分布外（OOD）泛化能力，选用两个与 IDS2018 特征体系不同但学术认可度高的公开基准：

- **CIC-IDS2017** [cite:CIC-IDS2017]：与 IDS2018 同属 CICFlowMeter 系列，特征定义与标注规范完全兼容，适合同架构跨数据集对比验证。已核实公开下载（License）。
- **UNSW-NB15** [cite:UNSW-NB15]：业界公认的泛化性测试基准，样本分布更均衡。特征 schema 与 CICFlowMeter 不同（49 特征），需适配层，但其不同分布特性可检验模型对特征空间偏移的鲁棒性。已核实公开下载（PCAP + CSV）。

### 3.2.3 专项验证集

针对特定实验需求，补充以下已核实公开数据集：

- **CIC-DDoS2019** [cite:CIC-DDoS2019]：DDoS 专项数据集，含 12 类攻击变种且样本充足，配套 PCAP。适合单独验证 CI-PRD 物理残差对高流量 DDoS 攻击的检测效果，并测试变种鲁棒性。
- **CTU-13** [cite:CTU-13]：同时提供 PCAP + NetFlow + 攻击行为日志的三模态数据，已核实公开（stratosphereips.org）。完美匹配两级检测架构的多模态输入需求——PCAP 喂 CI-PRD 物理初筛，日志喂 PIC-GRPO 语义精判。
- **BoT-IoT** [cite:BoT-IoT]：UNSW 2018 发布，含完整 PCAP + 精细标注，覆盖 DDoS/DoS/侦察/数据窃取。公开直下，适合作为 PINN 物理检测的异源补充验证集。

### 3.2.4 公开数据集局限与自构造必要性

综上，公开数据集覆盖了流级（I2/I3-弱/I4）与部分包级（I3 严格）守恒不变量的计算需求，并提供了有标签的定量评测基准。但其根本局限在于：均为端点侧单点采集，**无拓扑多节点视图**，节点流量守恒（I1）的连续性方程残差无法计算。此外，路由器内部状态（队列 $q(t)$、丢包概率 $p(t)$）在端点 PCAP 中不可观测，TCP 流体方程残差（I5）亦无法算全。

为补足 I1 所需的多节点拓扑视图，使 CI-PRD PINN 的连续性方程约束在真实拓扑上可计算，需自构造一个可控的测试床环境。详见 §3.3。

## 3.3 自构造数据集与可控测试床

### 3.3.1 可行性复核结论

自构造数据集**可行且应保留**，但其角色必须从“主检测数据集”调整为“物理机制真值集与可控反例集”。公开数据集负责主要性能、未见攻击和跨数据集泛化；自构造数据负责提供公开 PCAP 缺失的拓扑、队列、丢包和协议状态真值。

原方案把攻击描述为“打破节点流量守恒”，这一表述不成立。只要到达、离开、丢弃、缓存变化和端系统吸收等源汇项测量完整，守恒关系在正常和攻击状态下都应成立。攻击造成的是到达率超过服务能力、队列积压、丢包增加或协议状态异常，而不是物理守恒定律失效。

已有 ns-3 实验中的

\[
\left|B^{in}-B^{out}\right|
\]

在受害节点随 DDoS 上升，只能说明该统计量遗漏了应用层吸收和队列变化，不能称为守恒残差。将星形离散拓扑映射到一维坐标后使用

\[
\partial_t\rho+u\partial_x\rho=0
\]

也已经实验失败，因此不再把一维连续场 PINN 作为测试床主线。

### 3.3.2 自构造数据的研究角色

自构造数据集只承担以下三个任务：

1. **约束正确性验证**：检查离散队列平衡、TCP 状态一致性等约束能否由真实采集变量计算。
2. **受控因果对照**：在相同拓扑、背景流和随机种子下，只改变攻击注入，构造配对正常与攻击序列。
3. **困难负例构造**：加入正常闪拥、备份流量和突发访问，检验模型是否把高流量错误地等同于攻击。

自构造数据不能单独证明方法对真实网络有效，也不能替代 GeNIS、CICIoT2023 和 HIKARI 等公开数据集。

### 3.3.3 修订后的技术选型

| 维度 | ns-3 | Mininet |
| --- | --- | --- |
| 队列、丢包和拥塞状态真值 | 可直接记录 | 需从 Linux 流量控制和交换机计数器近似 |
| 协议与攻击工具真实性 | 仿真实现 | 使用真实内核协议栈和安全工具 |
| 参数扫描与重复实验 | 易于固定随机种子并批量运行 | 环境噪声更大，重复成本更高 |
| 当前角色 | 第一阶段机制真值集 | 第二阶段真实协议栈验证集 |

首轮以 **ns-3 为主**，因为第一创新点首先需要可复现的约束真值。只有候选约束在 ns-3 与公开数据的小样本实验中有效，才增加 Mininet 验证，避免同时维护两套测试床。

### 3.3.4 修订后的场景设计

不能只使用一个固定星形拓扑，否则模型可能记住拓扑和固定速率。首轮至少包含：

- 星形、树形和单瓶颈三种拓扑；
- 三档链路带宽、时延与队列容量；
- 正常稳态、正常突发、备份或闪拥、SYN 洪泛、UDP 洪泛和端口扫描；
- 训练未见的攻击速率、持续时间和拓扑组合；
- 每个组合至少三个随机种子。

应用层 Slowloris、HTTP 洪泛和真实工具流量留到 Mininet 阶段。不得使用只有攻击、没有正常高负载对照的场景。

### 3.3.5 可观测约束

对链路或队列 \(e\) 在时间窗 \([t,t+\Delta]\) 内记录到达量 \(A_e(t)\)、成功离开量 \(D_e(t)\)、丢弃量 \(L_e(t)\) 和队列长度 \(Q_e(t)\)。离散队列平衡为：

\[
Q_e(t+\Delta)-Q_e(t)
=A_e(t)-D_e(t)-L_e(t).
\]

对应一致性残差为：

\[
r_e^{queue}(t)
=Q_e(t+\Delta)-Q_e(t)-A_e(t)+D_e(t)+L_e(t).
\]

该残差应在正常和攻击下都接近零，主要用于约束模型的状态估计并检查数据完整性，**不能直接作为攻击标签**。与攻击更直接相关的是可解释的过载裕度：

\[
m_e(t)=A_e(t)-C_e(t),
\]

其中 \(C_e(t)\) 为窗口内可服务能力。还应记录队列占用率、丢包率、SYN 未完成比例、请求响应不平衡和目的地址熵。

只有在部署输入中可获得的变量才能成为推理期约束。队列等测试床特权变量可以作为训练期辅助监督，但必须另做“不使用特权变量推理”的实验。

### 3.3.6 与公开数据和生成式模型的统一

公开数据与自构造数据统一转换为前 \(K\) 个报文或固定时间窗的元数据序列，至少包含方向、长度、到达间隔、协议、TCP 标志和端口类别。模型统一生成恶意性、攻击大类、置信度和可观测证据。

自构造数据额外保存拓扑、队列和丢包真值，用于训练期辅助约束和机制分析；这些字段不直接拼入公开数据的主输入。自构造数据训练的仍是与公开数据相同的生成式检测模型，不恢复独立物理初筛器或两级检测架构。

### 3.3.7 最小试验与保留门槛

首轮只生成约 1 万至 3 万个平衡窗口，用于比较普通 QLoRA、固定权重物理辅助损失、原始—对偶物理约束、原始—对偶约束加可靠性门控。

自构造路线只有同时满足以下条件才进入第一创新点：

- 完整方法在至少两种拓扑和三个随机种子上优于普通 QLoRA；
- 对正常闪拥的误报率不高于普通 QLoRA；
- 去掉任一机制后性能或约束满足率显著下降；
- 在至少两个公开数据集上仍有稳定增益。

### 3.3.8 历史方案原文（不得直接用于论文）

以下设计保留用于追溯，但其“一维连续性 PINN”和“攻击打破守恒”解释已被上述复核否决。

#### 历史技术选型：ns-3 与 Mininet 对比

| 维度               | ns-3（离散事件仿真）            | Mininet（容器仿真）                |
| ------------------ | ------------------------------- | ---------------------------------- |
| 物理控制           | 精确（可设 TCP 状态/队列/丢包） | 依赖内核协议栈，较真实但控制弱     |
| 队列 $q(t)$ 可观测 | ✅ 仿真内部直接读               | △ 需 tc/SDN 计数器近似             |
| 拓扑/节点字节计数  | ✅ Trace 回调逐包               | ✅ Open vSwitch per-port 计数      |
| 真实流量逼真度     | △ 仿真                          | ✅ 真实协议栈/工具（Scapy/hping3） |
| 部署成本           | 中（C++/Python 绑定）           | 低（容器即起）                     |

**选型建议**：以 **Mininet** 为主（真实流量 + per-port 计数给 I1，工程轻），**ns-3** 作补充（需精确控制 $q(t)$ 做 I5 消融时用）。两者均经 [[数据集选型核实报告]] 确认公开可获取。

#### 历史拓扑设计

3-5 节点 SDN 小拓扑，够定义节点守恒即可，不追求大规模：

```
 客户端区          核心交换机 S1          服务端区
 C1 ─┐          ┌──────────┐          ┌─ SV1 (Web)
 C2 ─┼──(链路)──│  S1 (核心) │──(链路)──┼─ SV2 (DB)
 C3 ─┘          └────┬─────┘          └─ SV3 (DNS)
                     │(镜像/采集点 T1)
                  控制器 + 采集
```

- **核心交换机 S1** 是 I1 守恒的计算节点：其所有端口 per-port 字节计数可读，$\sum B^{in} - \sum B^{out} - B^{drop} - \Delta q$（式 4.2）可算。
- **采集点 T1** 做镜像抓包，供包级 I3（严格未答 SYN）与 I5（TCP 窗口/RTT）。

#### 历史流量生成与攻击注入

- **正常流量**：D-ITG / iperf3 / 真实 PCAP 回放，产生混合 TCP/UDP 背景流，满足连续性方程（$s\approx 0$）。
- **攻击注入**（与 §3.4 不变量映射对应）：
  - DDoS 洪泛（hping3/Scapy SYN flood、UDP flood）→ 打破 I1（受害节点流入≫流出）+ I2（单向）+ I3（未答 SYN）。
  - 端口扫描（nmap）→ 打破 I2 + I4（目的熵升）。
  - 漏洞利用模拟（Scapy 载荷）→ 打破 I2（请求/响应比）。
  - OOD 变种（协议混淆/速率调制）→ 测泛化。
- 每场景含正常对照窗口，确保"正常成立、攻击打破"可对照。

#### 历史多节点采集：产出 $\rho(v,t)$ 与通量 $J$

按时间窗 $\Delta$（如 1s）采集：

- **per-port 字节计数** $B_i^{in/out}(v,\Delta)$（Open vSwitch sFlow/计数器）→ 节点守恒残差 $\mathcal{R}_{I1}$（式 4.2）。
- **链路流量密度** $\rho_e(t)=B_e(\Delta)/(\Delta\cdot u_e)$、通量 $J_e=\rho_e u_e$ → 连续性方程残差（式 4.1，供 CI-PRD PINN autodiff）。
- **包级**（镜像抓包 tcpdump）：TCP 标志、窗口、RTT → I3 严格、I5。

采集字段与 IDS2018 对齐（流级双向字节、SYN 计数等），保证 I2/I3-弱/I4 在测试床与公开数据上可比（I2 作桥接不变量）。

#### 历史 CI-PRD PINN 衔接

测试床产出的 $\rho(v,t)$ 即 v7 autodiff PINN（[[experiments/README|实验 v7]]）所需的真实时空流量场——把 v7 的合成 $\rho$ 替换为测试床实测 $\rho$，连续性方程残差（torch.autograd）在真实拓扑上计算，残差幅值作 I1 异常得分。这闭合了"合成证机制 → 测试床证真实"的链路。
