## 一、结论先行

**写 `w_e = 1.0` 并非等权，实体项被额外除了一次「有效流数」。**

要使两项处于同一尺度（均为「每单位平均损失」），`w_e` 应抵消这次多余的除法：

```
w_e ≈ total_valid_units（本步有效流数）
```

量级为 `10³`–`10⁴`，**不是 `1.0` 附近**。

**这不是调参，是修正一次口径错位**，故可按根 `AGENTS.md` 魔法数字门禁登记为
**数学推导**，而非「任务化设定」。

## 二、代码链路（逐行核实，非推测）

### 2.1 实体级损失返回的是**均值**

`tools/ch3_ft_entity_bce.py:141`：

```python
loss = per_entity_bce[scored_mask].mean()
```

返回一个标量，已对「批内被打分的实体」取平均。

### 2.2 并入总损失时只是加权相加

`tools/ch3_ft_c00_dual_selection.py:1566`：

```python
loss_sum = loss_sum + entity_bce_weight * entity_bce_value
```

**注意 `loss_sum` 此前装的是逐流 BCE 的「求和」**（`:1536`
`(loss_fn(...) * mask32).sum()`），两者归约口径已不同：一个是和，一个是均值。

### 2.3 累加器统一除以有效流数

`tools/neural_precision_runtime.py`（`backward` 方法）：

```python
normalized_loss = loss_sum / self.total_valid_units
normalized_loss.backward()
```

`total_valid_units` 即本步有效流数（配置 `training.normalization_unit = "valid_flow"`）。

### 2.4 两项的实际尺度

| 项 | 进入累加器前 | 除以流数后 | 语义 |
| --- | --- | --- | --- |
| 逐流 BCE | `Σ 每流损失` | `Σ / N_flow` | **每流平均**，尺度正常 |
| 实体级 BCE | `w_e · mean(每实体损失)` | `w_e · mean / N_flow` | **均值又被除一次** |

**故 `w_e = 1.0` 时实体项的有效权重是 `1 / N_flow`。**

## 三、更正一处此前的记载

恢复卡 L4 条与三目标梯度合成设计曾记「`w_e = 1.0` 实际被压到约 `1/128`」，
依据是「实体数 `64` ÷ 流数 `8192`」。

**该数不准确**：代码中实体项**没有乘以实体数**（`:141` 是纯 `.mean()`，不是 `.sum()`），
故压缩倍数是 `1 / N_flow` 本身，**量级 `1/8192` 到 `1/几百`**（随本步真实有效流数变动），
而非固定的 `1/128`。

`1/128` 的算法隐含假设「实体项传入的是逐实体损失之和」，与实现不符。

## 四、待实测的部分（须在服务器执行）

上述推导只解决**归一化尺度**。两项梯度的**方向与量级**在同尺度下是否仍匹配，需实测：

**判据（冻结于测量之前）**：以 `w_e = N_flow` 归一后，
若 `‖∇_θ L_flow‖ / ‖∇_θ L_entity‖` 的**中位数**落在 `[0.5, 2]`，判为「同量级，推导值可直接采用」；
