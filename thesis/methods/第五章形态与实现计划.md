## 八、算子层分析：不自写 Rust 算子，用 torch.compile（2026-10-22）

DeepSeek 式自定义算子的三个前提（新算子/前沿规模/CUDA 生态）本课题均不占：成员化训练的全部算子是标准件（GEMM＋逐元素），数学下限 4× FLOPs、实测 5× 墙钟，可榨空间约 20–25%（调度与 launch 开销）。该空间的目标实现是 **torch.compile**（Inductor 自动融合核）——NVIDIA 迁移后以 compile on/off 实测收窄幅度，作为第五章工程分析的可测项；Rust 不用于训练算子（Metal 需经 wgpu 不成熟、CUDA 算子语言是 C++/Triton），Rust 的位置在第五章评测服务层（对比实验在跑）。

### 8.1 DeepSeek mHC 论文的算子方法学对照（本地全文 2512.24880v2 §3.2/§4.3）

mHC 的底层优化序列恰是本课题应遵循的方法学模板，逐条对照：
1. **先有新机制并量化其瓶颈**：mHC 的 n 流残差使每 token 内存访问约 n 倍（§3.2 表 2 的 I/O 账）——对照本课题：成员化结构无新算子、无 I/O 瓶颈（每 token 访问与 base 同量级），5×/4× 的墙钟差已有时间账定位；
2. **数学等价重排先于写核**：mHC 把除范数移到矩阵乘之后（"maintains mathematical equivalence while improving efficiency"）——对照本课题：r⊙x→matmul 公式本身已是等价高效形式，等价重排空间为零；
3. **写核语言是 TileLang 不是 Rust**：三个专用 mHC 核＋反向合并＋小系数机会主义融合，全部为压制新机制的边际开销至 6.7%；
4. 结论不变且更精确：DeepSeek 写核是为了让**新机制的边际开销可负担**；本课题机制二的失败与开销无关（判据问题），机制一的 20–25% 调度开销等待 torch.compile（＝自动化的核融合＋数学等价重排，与 DeepSeek 手工序列同构）——NVIDIA 迁移后实测。
