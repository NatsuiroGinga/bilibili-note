### 文档与代码的一处措辞差异（如实记录，非机制冲突）

四份配置的 `training.normalization_unit` 字段值均为字符串 `"valid_flow"`
（例：`ch3-ft-c11-entitybce-halfwidth-screening-v1.json:108`），这是 `validate_config`
校验的**配置级标签**（`ch3_ft_c00_dual_selection.py:571`）。但归一化除法实际调用时传入的
`normalization_unit` 参数值是 `base.NORMALIZATION_UNIT`，其定义为字符串常量 `"flow"`
（`ch3_ft_transformer_field_token_protocol_a.py:308`），经 `training_step`/`_flow_phase_bare`
在构造累积器时传入（`ch3_ft_c00_dual_selection.py:1750`、`2390`）。两个字符串**只是同一概念的
两套命名**（配置层「valid_flow」vs 代码常量「flow」），归一化的分母在两处语义完全一致——都是
`total_valid_units`（本步有效流总数），运算本身见 `neural_precision_runtime.py:461`：
`normalized_loss = loss_sum / self.total_valid_units`。不是数值口径分歧，只是两层命名不统一，
本文档统一按代码实际参与运算的取值 `"flow"` 登记。

## 二、算法伪代码

```text
算法 3-X ETA-BER 联合训练步（一次优化迭代）

输入:
  当前共享参数 θ
  机制开关 z1' ∈ {0,1}（ETA）、z2 ∈ {0,1}（BER）
  冻结超参数：尾部水平 α=0.5；共同底座权重 w_e=1303；
             六档预算 K=(121,606,1213,2426,4853,9706)；
             排序批构成 n_pos=2、n_neg=64；源年负实体池 N⁻=121336；
             阈值学习率 η_ξ=1e-4；截断长度 L=8192；
             有效批 64 序列、微批 64 序列（当前冻结配置下累积步数=1）
  持久状态：CVaR 阈值表 ξ_state（仅 z2=1 使用，跨优化步维护）

输出:
  更新后的共享参数 θ
  （若 z2=1）更新后的 ξ_state

1.  阶段一：逐流批与共同底座（实体级 BCE）——对应 C00/C10 的 training_step
    与 C01/C11 的 _flow_phase_bare，二者共用同一份底座实现
2.  从训练角色片段中不放回抽取 64 个互异序列，记为逐流批 B
3.  optimizer.zero_grad()
4.  total_valid ← B 中的有效流总数
5.  loss_sum ← 0
6.  For 每个微批 b（划分 B，当前冻结配置下只有 1 个微批）do:
7.      logits ← f_θ(b)                                  # 逐流 logit，FP32 敏感区内计算
8.      loss_sum ← loss_sum + Σ_{(e,t)∈b, 有效} BCEWithLogits(logits_{e,t}, y_{e,t})
9.      agg ← "tail_mean" 若 z1'=1，否则 "maximum"        # 共同底座对四格恒启用
10.     S_e^{(bce)} ← tail_aggregate(logits, valid, entity_of_row, α_agg)
                                                            # α_agg = α 若 agg="tail_mean"，否则 None（退化为 max）
11.     y_e^{(bce)} ← max_{t∈b, 该实体有效} y_{e,t}         # 批内该实体有效流标签的最大值
12.     L_ent ← mean_{e: m_e>0} BCEWithLogits(S_e^{(bce)}, y_e^{(bce)})
13.     loss_sum ← loss_sum + w_e · L_ent
14.     (loss_sum / total_valid).backward()                # 归一化并反传，跨微批梯度累加进 θ.grad
15. End For
16. If z2 = 0 then:
17.     校验 θ.grad 全部有限；optimizer.step()（不裁剪梯度，官方 FT-Transformer 配方无 clip）
18.     Return θ                                            # C00／C10 到此结束，无阶段二、三
19. Else（z2 = 1）：
20.     g_flow ← flatten(θ.grad)                            # 阶段一梯度快照，供阶段三使用

21. 阶段二（仅 z2=1）：独立实体排序批——对应 C01／C11 的 _ranking_phase
22. optimizer.zero_grad()                                   # 清空阶段一累积的 .grad；g_flow 已单独快照，不受影响
23. (P, N, 该批片段) ← Sampler.sample()                     # |P|=n_pos=2，|N|=n_neg=64，从 N⁻ 池均匀抽取负实体
24. 对 P∪N 中每个实体，按因果序只保留前 L=8192 条有效流（因果前缀截断）
25. entity_logits ← f_θ(截断后的片段)                        # 与阶段一同一组 θ，独立一次前向
26. α_agg ← α 若 z1'=1，否则 None
27. S_e^{(rank)} ← tail_aggregate(entity_logits, valid, entity_of_row, α_agg)
                                                            # α_agg=None 时即 prefix_scores 的 max，同一份算术退化
28. S_p ← S_e^{(rank)}[P]；S_n ← S_e^{(rank)}[N]
29. ξ_{p,K} ← ξ_state.get(P)                                # 叶张量，取自更早步 commit() 写入的值，本步样本不参与
30. For K ∈ (121,606,1213,2426,4853,9706) do:
31.     K_eff ← K · n_neg / N⁻
32.     L_pn ← softplus(S_n − S_p)                          # (|P|×|N|) 成对损失矩阵
33.     R_K ← mean_p[ ξ_{p,K} + (1/K_eff) · Σ_n [L_pn − ξ_{p,K}]_+ ]
34. End For
35. L_rank ← mean_K R_K
36. If z1' = 1 then:
37.     g_S ← ∂L_rank/∂S_e^{(rank)}（先于下一行的 backward 取，保留计算图；仅诊断用）
38.     记录 nonargmax_grad_share(g_S, k_e)                  # 可证伪观测量，见 ETA 方案第七节，不改变梯度本身
39. L_rank.backward()                                        # 累积进 θ.grad 与 ξ.grad（同一次反传）
40. ξ_updated ← ξ_{p,K}.detach() − η_ξ · ξ_{p,K}.grad
41. ξ_state.commit(P, ξ_updated)                             # 子梯度 SGD 写回持久表，供未来步使用
42. g_rank ← flatten(θ.grad)

43. 阶段三（仅 z2=1）：单向 PCGrad 投影 + 范数上限——对应 _combine_and_step
44. If ‖g_flow‖ = 0 then: g_rank^+ ← 0
45. Else If ⟨g_flow, g_rank⟩ < 0 then:
46.     g_rank^+ ← g_rank − (⟨g_flow,g_rank⟩ / ‖g_flow‖²) · g_flow   # 单向投影，只保护主任务方向
47. Else: g_rank^+ ← g_rank                                  # 方向不冲突，不投影
48. If ‖g_rank^+‖ > 0 then: c ← min(1, ‖g_flow‖ / ‖g_rank^+‖)
49. Else: c ← 0
                                                            # ⚠️ c 是上限截断（clamp），不是把 g_rank^+ 归一化到单位范数
50. g ← g_flow + c · g_rank^+
51. 校验一阶不变量：⟨g,g_flow⟩ ≥ ‖g_flow‖² 且 ‖c·g_rank^+‖ ≤ ‖g_flow‖   # 任一不成立即停止，不静默继续
52. 按参数形状把 g 写回各参数的 .grad；optimizer.step()（不裁剪梯度）

53. 返回结果:
54. Return θ（若 z2=1，另返回更新后的 ξ_state）
```

## 三、逐行说明

**第 1–20 行（阶段一，共同底座）**

- 第 6–15 行是 C00（`z1'=0,z2=0`）与 C10（`z1'=1,z2=0`）的**完整训练步**——四格的共同底座
  `entity_bce` 对全部四格恒启用（第 9 行的 `agg` 分支只改聚合口径，不改是否启用），这正是
  「新四格」相对「旧四格」的核心改动：旧四格里 ETA 只有开了 BER 才有训练期梯度通道，
  新四格给 C10 补上了经 `L_ent` 的独立训练通道（第三章定案 §二之二「训练通道（新四格）」列）。
- 第 10 行的 `tail_aggregate` 是 ETA 唯一的算术实现，`agg="maximum"` 时传 `α_agg=None`，
  函数内部取 `k≡1`，与 `prefix_scores` 的 max 逐位相等（自检 `assert_tail_aggregation_degenerates_to_max`，
  `ch3_ft_entity_ranking_loss.py:408-449`）——这保证「关闭 ETA 即回到现状」在共同底座这一层同样成立。
- 第 14 行的归一化除以 `total_valid`（本步有效流数），**不是**除以实体数或微批数；
  `w_e=1303` 正是为抵消这次「实体项被多除一次流数」而标定的（§一符号表 `w_e` 行的引用文档）。
- 第 16–18 行：`z2=0` 时函数在此返回，不构造排序批、不导入 `ch3_ft_entity_ranking_loss`——
  这是 `entity_ranking_enabled_from_config` 统一读取入口的直接后果（`ch3_ft_c00_dual_selection.py:2292-2295`），
  C00／C10 因此不承担任何 BER 相关的计算或显存代价。
- 第 20 行的 `g_flow` 是**快照**（`.clone()` 语义，见 `_flat_grad_from_params`），
  第 22 行的 `zero_grad()` 清空的是 `.grad` 属性本身，两者互不影响——这是阶段一、二
  必须分两次独立反传而非合并成一次 `backward()` 的直接原因：控制器需要**分别**拿到
  `g_flow` 与 `g_rank`，标准自动微分只能给出合并梯度。

**第 21–42 行（阶段二，BER 排序批）**

- 第 23 行的采样与阶段一第 2 行的采样**完全独立**——`Sampler` 按正/负实体分层抽样
  （`n_pos=2`、`n_neg=64`，来自源年训练角色负实体池 `N⁻=121336`），阶段一的 64 个逐流
  样本则是不放回均匀抽取的序列，二者的实体覆盖面通常不重合。**这一点在第四节
  「ETA 与 BER 的作用点关系」中有直接后果，务必对照阅读。**
- 第 24 行的因果前缀截断把每实体的有效流上限压到 `L=8192`，是工程必需
  （最大袋达 `2,475,228` 条流，单步预算差 302 倍，见 BER 方案第三节 3.2），
  不改变 CVaR-pAUC 目标本身的定义。
- 第 26–27 行是 ETA 在 BER 侧的挂载点：`α_agg=α` 时 `S_e^{(rank)}` 由 `tail_aggregate`
  给出（即 ETA 生效），`α_agg=None` 时退化为 `prefix_scores` 的 max（即 ETA 关闭）——
  与第 9–10 行使用**同一份** `tail_aggregate` 实现，但输入的批（第 23 行）与阶段一
  第 2 行的批不同，故 `S_e^{(rank)}` 与 `S_e^{(bce)}` 是**两个独立计算的张量**（细节见第四节）。
- 第 29、41 行体现 `ξ` 的**严格过去性**：本步使用的 `ξ_{p,K}` 恒等于更早步骤 `commit()`
  写入的值，本步的 `(p,n)` 样本只经第 39–41 行的反传更新 `ξ`，供**未来**步骤使用，
  不参与本步阈值本身（BER 方案第二节，已由本机合成脚本逐步核验 `torch.equal` 全部通过）。
- 第 37–38 行的 `nonargmax_grad_share` 只在 `z1'=1` 时计算（`z1'=0` 时 `k_e≡1`，该量恒为
  数学上的 `0`，无需计算即知结果），且必须**先于**第 39 行的 `backward()` 取——`backward()`
  会释放计算图，之后再对 `S_e^{(rank)}` 求梯度会报错（`ch3_ft_c00_dual_selection.py:2806-2809` 注释原文）。
  该量只写入诊断收据，不改变梯度或损失本身。

**第 43–52 行（阶段三，梯度控制器）**

- 第 44–47 行是**单向** PCGrad 投影：只在两梯度方向冲突（`⟨g_flow,g_rank⟩<0`）时才投影，
  且只保护 `g_flow` 的方向不被排序梯度侵蚀，不对称地处理两个损失——这与标准 PCGrad
  （双向互相投影）不同，是本课题按「逐流为主、排序为辅」的设计意图收窄后的版本
  （BER 方案 3.6 节，文献定位见该节「控制器的文献定位」）。
- 第 48–49 行的 `c`**是这份联合算法里最容易被误读的一步**：`c = min(1, ‖g_flow‖/‖g_rank^+‖)`
  是一个**上限截断（clamp）**——它只在 `‖g_rank^+‖ > ‖g_flow‖` 时把 `c` 压到小于 `1`，
  使 `‖c·g_rank^+‖` 不超过 `‖g_flow‖`；当 `‖g_rank^+‖ ≤ ‖g_flow‖` 时 `c=1`，`g_rank^+` **原样**
  加入合成梯度，不做任何缩放。**这不是把 `g_rank^+` 归一化到单位范数、也不是归一化到
  `‖g_flow‖`**——归一化会在 `‖g_rank^+‖` 偏小时把它**放大**，而这里的公式在该情形下
  取 `c=1` 保持原样，只在偏大时才压缩。把它读成「归一化」会导致伪代码在
  `‖g_rank^+‖ < ‖g_flow‖` 的分支上写反符号，这是一个已被本课题实测记录过的误读
  （BER 方案 3.6.1 节「已被推翻的原假设」一段：`c_scaling` 数值很小时曾被误读为
  「梯度被压没了」，实际是分母 `‖g_rank^+‖` 本身很大，除下来的结果仍等于 `‖g_flow‖`）。
- 第 51 行的两条不变量（`⟨g,g_flow⟩≥‖g_flow‖²` 与 `‖c·g_rank^+‖≤‖g_flow‖`）由 `c` 的构造
  与投影的非负内积性质**直接保证**（`ch3_ft_gradient_controller.py:95-137` 的推导注释），
  代码仍在每一步机械核验一次（`require(invariants["both_hold"], ...)`），
  不成立即抛异常终止，不静默继续。
- 第 52 行**不裁剪梯度**——无论 `z2=0`（第 17 行）还是 `z2=1`（本行），最终写回的梯度都不经
  `clip_grad_norm_`：`no_clip_accumulator_class` 明确按官方 FT-Transformer 配方取消裁剪
  （`ch3_ft_transformer_field_token_protocol_a.py:3218-3277`），只用 `get_total_norm` 做诊断记录，
  非有限梯度直接失败（`error_if_nonfinite=True`）。这是本联合算法与许多常见训练循环的一处
  显式差异，正文若讨论稳定性须注明。

## 四、ETA 与 BER 的作用点关系

**框架性表述**（"ETA 改变实体分数怎么由片段分数聚合而来、BER 改变实体分数之间怎么比较"）
在**排序阶段内部**逐字成立：第 26–27 行的 `S_e^{(rank)}` 由 ETA 的聚合算子产生，
第 30–35 行的 `L_rank` 直接消费这同一个 `S_e^{(rank)}`（`S_p`、`S_n` 都取自它），
`ch3_ft_c00_dual_selection.py:2787-2789` 的注释原文正是「训练侧挂载点：`α` 非 `None` 时
`S_e` 改由 `tail_scores` 给出」——即 BER 的输入张量确实就是 ETA 聚合的输出，二者在
排序阶段是同一条数据流上的相邻两步，这一点已核实与代码一致。

**但把这句话推广到"整个训练步"是不准确的，需要一处更正**：

共同底座（第 9–13 行）里还有**另一个独立的 `S_e^{(bce)}`**。它同样由 ETA 的聚合算子
（`tail_aggregate`，与 `S_e^{(rank)}` 是**同一个函数、同一个冻结 `α=0.5`**）产出，
但消费它的不是 BER 的排序比较，而是一个**普通的实体级二分类交叉熵**
（`entity_bce_loss`，`ch3_ft_entity_bce.py:60-155`）——这里没有"实体分数之间怎么比较"
这一步，`S_e^{(bce)}` 只是单独对一个标量标签做 BCE，语义上更接近"ETA 单独使用"而非
"ETA 作为 BER 的前置步骤"。

更重要的是一个**已核实的实现事实**：`S_e^{(bce)}` 与 `S_e^{(rank)}` 不是同一个张量，
甚至不是同一批数据算出来的——

- `S_e^{(bce)}` 的输入批是阶段一第 2 行**不放回均匀抽取的 64 个序列**
  （`sample_distinct_positions`，`ch3_ft_c00_dual_selection.py:2384`），实体覆盖面是
  抽样的偶然结果，不受控；
- `S_e^{(rank)}` 的输入批是阶段二第 23 行 `Sampler.sample()` **按角色分层抽样**的
  `2` 个正实体与 `64` 个负实体（外加因果前缀截断到 `8192` 条流），是刻意构造的批。

即使在 `z1'=1,z2=1`（C11）这一格、ETA 的两条通路都打开的情况下，训练一步之内实际执行
的是**两次独立的聚合计算**，分别作用在两个不同来源的批上，只是共享同一份聚合函数与
同一个冻结 `α`。**"ETA 与 BER 作用在同一个 `S_e` 的两侧"这一表述，严格意义上只在
"排序阶段内部"成立；把它读成"全局只有一个 `S_e`，ETA 与 BER 分别改写它的产生方式与
比较方式"是不准确的，本文档在此更正为"两个独立实例，共享同一聚合算子"。**

**关于"ETA 是否在两处都生效"的直接结论**：本次代码核对（2026-09-04）确认，
在当前工作树中 ETA 的两条通路（共同底座聚合、排序阶段聚合）**都已接线生效**——
四份配置的 `mechanism.entity_bce.aggregation` 与评价侧 `evaluation.entity_aggregation`
在 `z1'=1` 的两格（C10、C11）均正确切到 `tail_mean`（§一"魔法数字与四格配置对照"表）,
`_flow_phase_bare`（`ch3_ft_c00_dual_selection.py:2361-2417`）确实调用了
`_entity_bce_mechanism_config`／`_add_entity_bce_microbatch_loss`。
这与「第三章定案」§四之二列出的历史阻断项——「实体级 BCE 未接入 `z2=1` 路径……
`_flow_phase_bare`……全文件 1756 行之后零出现……**修复中**」——描述的状态**不一致**：
