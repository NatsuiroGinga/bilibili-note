## 一、使用规则

### 1.1 候选编号与四格编号分离

- 数据集用 `Dxx`，基础模型用 `Bxx`，RWKV/RWKV-8 机制用 `Rxx`，非 RWKV 机制用 `Nxx`，联合配对用 `Jxx`，历史否决实现用 `Xxx`。
- `C00/C10/C01/C11` 只表示某个已冻结联合配对的四个实验单元，不作为候选编号。
- 同一候选只保留一个编号；更名、替代实现或新证据追加到原行，不复制新行。

### 1.2 状态机

状态只评价“当前门级”，不得跨级解释。

| 状态 | 机械含义 | 允许动作 |
| --- | --- | --- |
| `已否决` | 当前候选或绑定实现触发了已冻结失败条件，或资格硬门失败 | 保存反例；只有出现新数据、接口、全文或实验合同时才可重新登记，不得原样追调 |
| `待证` | 已登记但尚未进入当前门，或当前门的前置证据不完整 | 等待队列；不得写为有效、优选或已支持 |
| `进行中` | 当前唯一队首任务正在补齐该门的合同或证据 | 只执行该项；不得并行启动同级其他候选 |
| `通过` | 当前门的全部预注册条件由可回指制品满足 | 只获得进入下一门的资格，不等于论文有效 |

状态更新必须同时写明：门级、日期、配置或数据版本、原始制品、检查命令与下一项动作。没有制品不得从 `待证/进行中` 升为 `通过`。

### 1.3 证据等级

| 等级 | 含义 |
| --- | --- |
| `E0` | 只有名称、概念或待核题录 |
| `E1` | 官方元数据、许可、版本、数据小样或接口已核 |
| `E2` | 本地全文或固定官方源码已核，可证明机制来源与可试性 |
| `E3` | 本课题同数据合同的零训练数据/病灶制品已核 |
| `E4` | 本课题同数据合同的缩容短训或固定开发池实验已核 |
| `E5` | 本课题冻结正式单种子四格、强基线、统计和资源制品均已核 |

`E1/E2` 不能证明本课题有效；`E3/E4` 只支持对应筛选门；只有 `E5` 才能进入第三章正式结果候选。

### 1.4 四格硬约束

1. 每个联合候选只含两个独立开关 `M1/M2`：`C00=00`、`C10=10`、`C01=01`、`C11=11`。
2. C00 必须含公平共同底座；关闭开关不能故意清零原生 RWKV 状态、删除强字段、减少预算或弱化基线。
3. M1 在 M2 关闭时仍须独立改变共享预测路径；M2 在 M1 关闭时亦然。任一机制只在另一机制开启后才有作用即为惰性四格。
4. C11 使用与 C10、C01 相同的两个机制公式、系数、数据、预算与选择规则；**禁止 C11 独有第三模块、动态控制器、课程、门控器或额外调参机会**。
5. DeepEmbedAttention 的官方 `rwkv7b` 实现已经包含 DeepEmbed。因此 `R02 DeepEmbed` 与 `R03 DeepEmbedAttention` 是同一家族的替代分支，**不得同时充当两个独立机制开关**。
6. 所有训练只用一个冻结种子。四格在同一初始化规则下成对；实体、域名、执行实例或自然主体的配对重采样只量化固定预测集的评价不确定性，**不覆盖也不冒充训练随机性**。
7. `R07 Engram` 与 `R02 DeepEmbed` 同属条件记忆/嵌入扩容家族。二者只能作为同一个机制轴的替代实现，不能拆成两个机制；DRIFT 原方法已有字符/子词双分支、池化融合、MTP/TPP/TOV 和带标签持续学习，这些也不能改名后成为新轴。
