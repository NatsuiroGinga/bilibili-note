### 1.2 检查点把显存换成了两倍前向

`_entity_ranking_bare_forward`（`:2180-2247`）与 `_entity_ranking_memory_forward`
（`:2262-2360`）对**每一个**微批的纯计算段调用
`torch.utils.checkpoint.checkpoint(..., use_reentrant=False)`（`:2238`、`:2341`）。

以「一条序列的一次前向」为 `1` 单位、反向约 `2` 单位记，排序阶段的模型计算量是

```
现状 = 前向 M + 反向期重算 M + 反向 2M = 4M          （M = 微批数）
无检查点 = 前向 M + 反向 2M = 3M                      （已实测 OOM，不可行）
```

即检查点的代价是 `4M/3M = 1.33` 倍计算量，换来激活显存从 `O(M)` 降到 `O(1)`。
实测步速比 `6.9/2.6 = 2.65` 倍**大于** `1.33`，差额须由独立测量解释，
本文件不臆测（列为待测项 T4）。

### 1.3 CVaR 的梯度只落在活动集上（源码可证）

`cvar_pauc_loss`（`ch3_ft_entity_ranking_loss.py:432-504`）的字面实现是

```
loss = (1/6) · Σ_k (1/N_p) · Σ_p [ ξ_{p,k} + (1/K_k) · Σ_n relu(L_pn − ξ_{p,k}) ]
```

（`:485-487` 的 `hinge = relu(pairwise − ξ_k)`、`r_k = ξ_k + hinge.sum(dim=1)/k`、
`:492` 的 `loss = stack(budget_terms).mean()`）。对配对损失求导：

```
∂loss/∂L_pn = (1/(6·N_p)) · Σ_k (1/K_k) · 1[L_pn > ξ_{p,k}]
```

`relu` 在零点的子梯度取零（`:485` 注释明写）。定义**活动集**

```
A = { n ∈ 负实体 : ∃(p,k), L_pn > ξ_{p,k} }
```

则对任意 `n ∉ A`，`∂loss/∂S_n ≡ 0`（**精确为零，不是数值上的小量**）。
`S_p` 恒有梯度（`∂L_pn/∂S_p = −σ(S_n−S_p) < 0`，`softplus` 严格增）。

**ξ 的更新不需要 θ 的梯度路径**：`∂loss/∂ξ_{p,k} = (1/(6N_p))(1 − m_{p,k}/K_k)`，
其中 `m_{p,k} = #{n : L_pn > ξ_{p,k}}` **只需前向值**。宿主的实现（`:2423-2424` 取
`xi` 叶张量并 `retain_grad()`，`:2451` 反传，`:2454-2455` 更新并 `commit`）
把 ξ 的子梯度挂在同一次 `backward()` 上，但这只是实现上的顺手，不是数学必需：
把损失建在 **detach 后的实体分数**上同样能得到逐位相同的 `xi.grad`。

**主代理简报中的提示由此得到源码确认**：计数 `m_{p,K}` 确实只需前向值，
不构成稀疏建图的障碍。

### 1.4 聚合算子把梯度进一步压到「每实体 k_e 条流」

这一层稀疏性简报未提及，是本文件的独立发现。

`prefix_scores`（`:67-121`）的梯度路径：

- `:96-97` 先对每个片段行取 `argmax` 再 `gather` → 每行只有**一列**有梯度；
- `:104-112` 用 `scatter_reduce` 的 `amax`/`amin` **只做定位**（`:105` 显式
  `segment_scores.detach()`），不反传；
- `:115` `entity_scores = segment_scores.gather(0, first_pos)` → 每个实体只有**一行**有梯度。

**结论**：`z1'=0`（max 聚合，即 C01）时，`∂loss/∂logits` 的非零元恰好是
**每实体一个 `(行, 列)`**，全批至多 `E = 66` 个，而 `logits` 有
`B×T ≤ 4224×128 = 540,672` 个元素。**非零率上界 `66/540672 ≈ 1.22e-4`。**

`tail_aggregate`（`:149-243`）的梯度路径：`:230-233` 的
`take = (rank_in_group < k_e) & valid`、`contribution = where(take, sorted_scores, 0)`
使梯度落在每实体**得分最高的 `k_e` 条流**上，`k_e = max(1, ⌈α·m_e⌉)`（`:225`）。
`z1'=1`（ETA，`α=0.5`）时 `k_e ≈ m_e/2`，**流级稀疏度只有 `2` 倍，不是 `m_e` 倍**。

这一非对称是候选二的适用边界，也是它与四格的天然交互项（见候选二卡）。

### 1.5 三种袋处置全部带图计算，其中两种只用于记数

`bag_policy_diagnostics`（`:866-969`）对同一批**并行计算三种袋处置**：
`full`（`:937`）、`causal_prefix_truncation`（`:942`）、`stratified_weighting`（`:950`）。
只有 `config.active_policy` 那一支进入 `backward()`（宿主 `:2439`、`:2451`），
另两支的返回值只被写进诊断字典（`:938`、`:947`、`:955` 的 `loss_value`）。

但三支都在 `torch.no_grad()` **之外**执行，即两支纯记录分支同样建立并持有 autograd 图，
直到 Python 引用消失才释放。

### 候选一 · 活动集稀疏反传（ASB, Active-Set Sparse Backward）

```md
## Research Question Card

Question:
  CVaR-pAUC 对非活动负实体的梯度恒为零，能否只对活动集构建反向图，
  在不改变损失值、ξ 更新与 θ 梯度的前提下降低排序阶段的计算与显存？

Type: applied

Hypothesis:
  设 A 为活动负实体集、P 为正实体集、G = P ∪ A。
  只对 G 所属片段构建反向图，得到的 θ 梯度与现状在精确算术下相同；
  排序阶段模型计算量从 4M 降到 M + 3m（m 为需建图的微批数）。

Why it matters:
  排序阶段是 C01 相对 C00 慢 3.4 倍的唯一来源（1.1 节）。
  该候选不触碰损失定义、采样口径与超参数，因此第三章四格结果不需重跑。
```

**形式化**

两遍算法。记微批划分 `{B_1,…,B_M}`（按现状 `indices[start:stop]` 切分，
`ch3_ft_c00_dual_selection.py:2220`），`rows(e)` 为实体 `e` 的片段行集合。

```
Pass 1（torch.no_grad）：
    对 j = 1..M：  logits_j ← f_θ(B_j)                     # 不建图
    S ← aggregate(logits, valid, owner)                    # 全体实体分数（detached）
    L_pn ← softplus(S_n − S_p)
    A ← { n : ∃(p,k), L_pn > ξ_{p,k} }
    m_{p,k} ← #{ n : L_pn > ξ_{p,k} }

Pass 2（建图）：
    G ← P ∪ A
    J ← { j : B_j ∩ (∪_{e∈G} rows(e)) ≠ ∅ }                # 需建图的微批
    对 j ∈ J：  logits_j' ← f_θ(B_j)                        # 建图
    对 j ∉ J：  logits_j' ← logits_j.detach()               # 复用 Pass 1 结果
    S' ← aggregate(logits', …)
    loss ← cvar_pauc_loss(S'_P, S'_N, K_eff, ξ)
    loss.backward()
```

`ξ` 的更新与现状逐字相同（`:2453-2455`），因为 `∂loss/∂ξ` 只依赖前向值。

**省的是什么**

| 量 | 现状 | ASB | 依据 |
| --- | --- | --- | --- |
| 模型计算 | `4M` | `M + 3m`（不套检查点）或 `M + 4m`（仍套） | 1.2 节的单位记法 |
| 加速比 | — | `4M/(M+3m) = 4/(1+3·m/M)` | 同上 |
| 激活显存 | `O(1)` 微批（检查点已压） | `O(1)` 微批，且 `m` 小时可整批弃用检查点 | `:2238` |

`m/M = 0.3` → `1.05` 倍…等等，`4/(1+0.9) = 2.11` 倍；`m/M = 0.5` → `1.60` 倍；
`m/M = 1.0` → `1.00` 倍（无收益）。**收益完全由 `m/M` 决定。**

**数值语义是否改变**

- **损失值**：Pass 1 在 `no_grad` 下运行同一组核，值与现状逐位相同 → `loss` 逐位相同。
- **`ξ` 更新**：只依赖前向值 → 逐位相同。
- **`θ` 梯度**：`n ∉ A` 的贡献精确为零（1.3 节），故数学上相同。
  **逐位相等的充要条件是 Pass 2 保持微批形状不变**——本候选按微批粒度跳过，
  不重打包，因此保形；被保留微批的前向与 Pass 1 走同一形状同一核，逐位相同。
- **判定方式**：同种子同批数据下，开关前后 `loss`、`xi.grad`、`g_rank` 三者
  `torch.equal` 全为真。**这是可机械判定的断言。**

**开关设计**

```json
"mechanism": { "entity_ranking": {
    "active_set_backward": false        // 默认 false = 现状
} }
```

- 关闭时**逐位退化**：`active_set_backward=false` 时函数体走原封不动的现有代码路径
  （与 `BagPolicyConfig.alpha is None` 走原 `prefix_scores` 同一手法，
  见 `ch3_ft_entity_ranking_loss.py:132-137` 的口径说明），
  「逐位相同」由「同一段代码」保证，强于任何数值断言。
- 断言函数：`assert_active_set_backward_preserves_gradient`，
  对照 `assert_tail_aggregation_degenerates_to_max`（`:383-424`）的写法，
  在 CPU 上比较开关两侧的 `loss`/`xi.grad`/`g_rank`。
- 消融维度：**独立第三维 `z3`**，与四格 `z1'×z2` 正交。
  `z2=0` 时排序损失不进训练图，`z3` 无定义（收据须显式记 `z3=n/a`）。
  故消融格点是 `{C01, C11} × {z3=0,1}` 共四格，**指标是速度与显存，不是 AP**；
  AP 必须逐位不变，任何 AP 差异都判为实现错误而非机制效果。

**可证伪的验证方案（判据在此冻结）**

| 项 | 内容 |
| --- | --- |
| 观测量 | `m/M`（需建图微批数占比，聚合标量）、`|A|/N_n`（活动负实体占比，聚合标量）、排序阶段墙钟耗时、峰值显存 |
| 最小实验 | 合成数据上构造 `E=66`、`M∈{6,20,100}` 的排序批，跑开关两侧，比较三项 `torch.equal` 与耗时 |
| **支持判据** | 三项 `torch.equal` 全真 **且** `m/M ≤ 0.6`（对应 ≥ `1.43` 倍加速） |
| **证伪判据** | `m/M > 0.8`（加速 < `1.18` 倍，不值得引入一维消融）**或** 任一 `torch.equal` 为假 |
| 落盘 | 只落聚合标量：`m_over_M`、`active_negative_frac`、`ranking_phase_seconds`、`peak_mib`。**禁止落逐实体成员表** |

**杀死它的那条理由**

**微批级聚类失效。** 微批按行序切分（`:2220`），行按 `(entity, T23)` 分组有序，
所以一个 `64` 序列的微批覆盖若干**相邻**实体。袋小的实体（源年验证集袋大小中位数 `2`）
密集堆在少数微批里；只要其中一个实体活动，整个微批就得保留。
若活动负实体在实体序上均匀散布，则 `m/M → 1`，**收益归零**。

**如何证伪这条杀手理由**：测 `m/M` 的真实分布（待测项 T1）。
若 `m/M ≤ 0.6` 则杀手不成立；若 `> 0.8` 则候选一按上面的证伪判据出局，
但**候选二仍可能存活**——后者不依赖实体在微批中的聚类。

### 候选二 · 聚合稀疏梯度重打包（ASR, Aggregation-Sparse Repacking）

```md
## Research Question Card

Question:
  max 聚合使 ∂loss/∂logits 每实体只有一个非零元（1.4 节）。
  能否只把这些携带梯度的流重新打包成一个极小的批做反向，
  把排序阶段的建图规模从「全批片段」降到「每实体 k_e 条流」？

Type: applied

Hypothesis:
  FT-Transformer 在本实现中是**逐流独立**的（注意力在字段维、不在流维，
  见 1.2 节引用的 `flat_num = numeric_t.reshape(batch*length, F)`）。
  因此把任意流子集重打包成新批，其逐流输出在数学上不变。
  以 Pass 1 的 detached 分数算损失得到 ∂loss/∂S_e，再对重打包批
  用 `backward(S', grad_tensors=g)` 播种，可得与现状数学相同的 θ 梯度，
  而建图规模从 O(B·T) 降到 O(Σ_e k_e)。

Why it matters:
  z1'=0 时 Σ_e k_e = E ≤ 66，相对 B·T ≤ 540,672 是 8000 倍压缩。
  这是本文件中唯一可能达到参照论文第四章量级（4.6 倍）的候选。
```

**形式化**

借 GradCache（对比学习中的分块梯度缓存）的两遍结构，但稀疏性来源不同——
GradCache 靠的是「表示向量是瓶颈」，本候选靠的是「聚合算子把梯度压到 `k_e` 条流」。

```
Pass 1（torch.no_grad）：同候选一，得全体 S（detached）与 valid、owner
选择集：  Sel ← ∪_{e∈G} argtop_{k_e}(该实体的有效流)        # 由 Pass 1 确定并冻结
损失与播种：
    Ŝ ← S.clone().requires_grad_(True)                      # E 个标量的叶张量
    loss ← cvar_pauc_loss(Ŝ_P, Ŝ_N, K_eff, ξ)
    loss.backward()                                          # 只反传 E+|ξ| 个标量
    g ← Ŝ.grad                                               # ∂loss/∂S_e，E 维
Pass 2（建图，重打包）：
    把 Sel 中的流按任意确定序打包成 ⌈|Sel|/(micro·T)⌉ 个新批
    logits_sel ← f_θ(打包批)                                 # 建图
    S' ← aggregate_from_selected(logits_sel, Sel, k)          # 只用选中流重建 S_e
    torch.autograd.backward(S', grad_tensors=g)               # 播种反传
```

`aggregate_from_selected` 在 `z1'=0` 时是恒等映射（每实体一条流），
在 `z1'=1` 时是 `mean` over `k_e`（权重 `1/k_e`，与 `tail_aggregate:239` 一致）。

**省的是什么**

| 量 | 现状 | ASR（`z1'=0`） | ASR（`z1'=1`, α=0.5） |
| --- | --- | --- | --- |
| 建图流数 | `B·T` | `E ≤ 66` | `Σ_e ⌈m_e/2⌉ ≈ (B·T)/2` |
| 模型计算 | `4M` | `M + 3·⌈66/8192⌉ ≈ M + 3` | `M + 3·(M/2) = 2.5M` |
| 理论加速 | — | `≈ 4M/(M+3)`，`M=100` 时 `3.88` 倍 | `1.6` 倍 |
| 激活显存 | `O(1)` 微批 | `O(1)` 微批且可弃检查点 | 同左 |

**`z1'` 决定收益量级，这是候选二与第三章四格的真实交互，不是设计缺陷。**

**数值语义是否改变**

分两个子变体，**必须分开裁决**：

| 子变体 | θ 梯度 | 判定 |
| --- | --- | --- |
| **ASR-保形**：只跳过完全不含选中流的整微批，不重打包 | **逐位相等** | `torch.equal` 可断言 |
| **ASR-重打包**：把选中流压成新批 | **数学相等，逐位不等** | 差异只来自 GEMM 分块的浮点重结合律 |

- `loss` 值与 `ξ` 更新在两个子变体下**都逐位相等**（都由 Pass 1 的 detached 分数算得，
  而 Pass 1 与现状同形同核）。
- ASR-重打包的误差上界**不能靠推演给出**，必须实测：在合成数据上比较
  `‖g_repacked − g_current‖_∞ / ‖g_current‖_∞`，登记该比值。**这是待测项 T5。**
- **若该比值不能稳定低于 BF16 的机器精度量级，ASR-重打包必须标注
  「改变数值语义、需重跑第三章」**，代价是四格全部重跑（`4 × 20 × 1000` 步）。

**开关设计**

```json
"mechanism": { "entity_ranking": {
    "sparse_backward_mode": "off"      // "off" | "shape_preserving" | "repack"
} }
```

- `"off"` 走原封不动的现有代码路径 → 逐位退化由同一段代码保证。
- `"shape_preserving"` 的断言：`loss`/`xi.grad`/`g_rank` 三者 `torch.equal` 全真。
- `"repack"` 的断言：`loss`、`xi.grad` `torch.equal` 为真；`g_rank` 只断言相对误差
  上界（阈值由 T5 实测确定后冻结，**不得在看到 AP 结果后调整**）。
- 消融：与候选一同属 `z3` 维，取值 `{off, ASB, ASR-保形, ASR-重打包}` 为四水平因子。
  **主指标是速度与显存**；`off`/`ASB`/`ASR-保形` 三档的 AP 必须逐位相同，
  只有 `ASR-重打包` 允许 AP 有浮点级差异，且该差异须单独报告。

**可证伪的验证方案（判据在此冻结）**

| 项 | 内容 |
| --- | --- |
| 观测量 | `选中流数/总有效流数`（聚合标量）、`‖Δg‖_∞/‖g‖_∞`、排序阶段耗时、峰值显存 |
| 最小实验 | CPU 合成数据：`E=66`、每实体袋大小取 `{1,2,64}` 三档混合、`B·T` 约 `5e5`；跑三档开关 |
| **支持判据** | `z1'=0` 下 ASR-保形的 `torch.equal` 三项全真 **且** 端到端排序阶段耗时降低 ≥ `40%` |
| **证伪判据** | ASR-保形耗时降低 < `15%`（说明模型前向不是瓶颈，主机同步或损失侧才是），**或** `loss`/`xi.grad` 任一 `torch.equal` 为假（说明两遍结构本身破坏了语义） |
| 落盘 | `selected_flow_frac`、`grad_rel_err_inf`、`ranking_phase_seconds`、`peak_mib`，全为标量 |

**杀死它的那条理由**

**Pass 1 的无梯度前向本身就是下界。** ASR 无论多稀疏，都必须完整跑一遍全批前向
才能知道谁是 argmax、谁在活动集里。该前向占现状 `4M` 中的 `1M`，
即 **ASR 的加速上限是 `4` 倍，且逼近该上限时 Pass 1 独占全部时间**。
若排序阶段的真实耗时中**模型前向只占一小部分**（另一大部分是 1.6 节的主机同步、
1.5 节的三支袋处置、以及 `view.features()` 的 numpy 取数与 H2D 搬运），
则 ASR 削掉的那部分本来就不大，`40%` 判据不可能达成。

**如何证伪这条杀手理由**：先做待测项 T3（排序阶段的耗时分解）。
**T3 必须先于 T5 执行**——若模型计算不占主导，候选二整体降级、候选三升为首选。

**第二条杀手（对 C11 专属）**：`_entity_ranking_memory_forward`（`:2262-2360`）中
片段状态由 `_segment_summary_from_injected` 从检查点内的 `injected` 导出后
`scratch_memory_state.write`（`:2346-2349`），**状态本身携带梯度并跨片段串联**。
重打包会切断这条链。故候选二在 `z1'=1`（C11、启用实体记忆）下**可能整体不成立**，
须单独核验状态是否真的进入反传图。列为待测项 T6。

### 候选三 · 热路径主机同步消除（HSE, Host-Sync Elimination）

```md
## Research Question Card

Question:
  排序阶段每步在 GPU 热路径上执行 O(片段数) 次主机同步（1.6 节）
  与两支只用于记数的带图袋处置（1.5 节）。消除它们能省多少？

Type: applied

Hypothesis:
  因果前缀截断（`_causal_truncate_valid`, :839-863）的逐行 Python 循环
  可改写为按实体分组的累积和 + 阈值比较，语义**逐位相同**（布尔掩码，无浮点）；
  两支非生效袋处置移入 `torch.no_grad()` 后，生效支的值与梯度**不受任何影响**。

Why it matters:
  这是本文件中唯一**不需要任何数值容忍**的候选：
  掩码是布尔量，可以断言逐位相等；非生效分支根本不参与反传。
  若它的收益量级可观，它应当先做——风险最低。
```

**形式化**

因果前缀截断的等价向量化定义。设实体 `e` 的片段按 `(片段序, 列序)` 展平后，
第 `i` 条流的有效指示为 `v_i ∈ {0,1}`，则原实现保留的集合是

```
keep_i = v_i ∧ ( Σ_{j ≤ i, j ∈ e} v_j ≤ L )
```

即「按因果序的有效流累积计数不超过 `L`」。向量化实现：对 `valid` 展平后
按实体分组做 `cumsum`，再与 `L` 比较。全程无 `.item()`、无 `nonzero`、无 Python 循环，
主机同步次数从 `O(片段数)` 降到 `0`。

诊断分支：`bag_policy_diagnostics` 的 `full` 与 `stratified_weighting` 两支
（`:937`、`:950`）包进 `torch.no_grad()`；`entity_score_source_row` 的
`.tolist()`（`:925`）改为只在生效支执行，或降级为聚合标量。

**省的是什么**

| 量 | 现状 | HSE |
| --- | --- | --- |
| 主机同步次数/步 | `≥ 2 ×` 片段数（`:853`、`:857`）+ `2`（`:832-833`）+ `3 ×` 实体数（`:925`） | `O(1)` |
| 损失侧建图分支 | `3` 支 | `1` 支 |
| 模型计算 | 不变 | 不变 |

**收益量级完全未知，且不可由推演给出**——单次 `cudaStreamSynchronize` 的代价
在不同驱动、不同队列深度下差两个数量级。**必须实测（待测项 T3）。**

**数值语义是否改变**

- 截断掩码：布尔量，判定方式是 `torch.equal(old_mask, new_mask)` 在真实批上为真。
  **无浮点参与，逐位相等是可达成的强断言。**
- 非生效袋处置移入 `no_grad`：生效支的前向值与反向图完全不被触及，
  数值语义不变是**结构性的**，不需要实验证明（但仍应断言三支的 `loss_value` 不变）。

**开关设计**

```json
"mechanism": { "entity_ranking": {
    "vectorized_causal_truncation": false,
    "diagnostic_policies_no_grad": false
} }
```

两个**独立**开关（它们解决的是两件不同的事，不应捆绑）。
关闭时走原代码路径。断言函数
`assert_vectorized_truncation_matches_loop`：在真实形状的随机 `valid` 上
比较两种实现的掩码 `torch.equal`。

消融：属工程维，**不进四格**。收据记录开关状态与耗时即可。

**可证伪的验证方案（判据在此冻结）**

| 项 | 内容 |
| --- | --- |
| 观测量 | `_causal_truncate_valid` 的墙钟耗时占排序阶段比例；掩码 `torch.equal` |
| 最小实验 | CPU 上按真实形状（`B=4224`, `T=128`, `E=66`, `L=8192`）跑两种实现，计时并比较掩码 |
| **支持判据** | 掩码 `torch.equal` 为真 **且** 循环版在 CPU 上的耗时 ≥ `50 ms`/次（对应 GPU 上因同步而放大的量级值得处理） |
| **证伪判据** | 循环版 CPU 耗时 < `10 ms`/次 **且** 同步次数在 GPU 上无法被证明放大 → 判为噪声级，出局 |
| 落盘 | `truncation_seconds`、`mask_bitwise_equal` |

**杀死它的那条理由**

**它可能根本不在关键路径上。** 若排序阶段的耗时被模型前向/反向完全支配
（`4M` 单位对应数百毫秒），那么哪怕主机同步有 `4224 × 2` 次、每次 `20 μs`，
也不过 `0.17` 秒——量级相当，但若实测同步只有 `2 μs`，就只有 `17 ms`，可以忽略。
**这条只能用 T3 裁决，推演给不出答案。**

**第二条杀手**：`_causal_truncate_valid` 的循环里 `remaining` 一旦耗尽就走
`truncated[row] = False` 的快路径（`:849-851`），**不再触发 `.item()`**（`:853` 在
`continue` 之后）。所以真实同步次数是「每实体前若干行」而非全部行，
可能远小于片段数。**这条使收益上界大幅下降，必须在 T3 中按真实袋分布计数。**

### 候选四 · 选择性激活重计算（SAC, Selective Activation Checkpointing）

```md
## Research Question Card

Question:
  现状对 100% 的微批套梯度检查点，代价是 1.33 倍计算量（1.2 节）。
  在给定显存预算下只对必要的微批重算，能省多少？

Type: applied

Hypothesis:
  设单微批保留激活需 a MiB、可用余量 R MiB，则可保留 k = ⌊R/a⌋ 个微批不重算，
  计算量从 4M 降到 4M − k。该候选与候选一、二**乘性叠加**：
  后者把需建图的微批数从 M 降到 m，若 m·a ≤ R 则检查点可整体弃用，
  计算量降到 M + 3m（候选一卡中「不套检查点」那一行的前提由此成立）。

Why it matters:
  单独看它的上限只有 4M/3M = 1.33 倍。
  它的真正价值是**让候选一、二的收益兑现**——否则那两者仍要付 4m 而不是 3m。
```

**形式化**

```
k ← ⌊ (显存预算 − 基线占用) / 单微批激活量 a ⌋
对 j = 1..M：
    若 j ≤ k：  logits_j ← f_θ(B_j)                    # 直接建图，保留激活
    否则：      logits_j ← checkpoint(f_θ, B_j)        # 重算
```

`a` 与基线占用**必须实测**，不得按参数量估算（待测项 T7，须在 GPU 上做，
本轮不做，只登记为待测）。

**省的是什么**

计算量 `4M → 4M − k`，加速 `4M/(4M−k)`。`k = M`（全不重算）时 `1.33` 倍，
是**硬上限**。显存则从 `O(1)` 微批升到 `O(k)` 微批——**这是与候选一、二相反方向的权衡**。

**数值语义是否改变**

- 不改变。检查点的重算若与首次前向逐位相同，则「不重算、直接用保存的激活」
  给出的梯度与之逐位相同。
- **但这个前提必须核验**：若前向段含 dropout 或其他 RNG，
  `use_reentrant=False` 的检查点会保存并恢复 RNG 状态，
  而不重算路径根本不重跑 RNG——两者仍相同。若含非确定性 kernel，则两者可能不同。
  **现状实现已经依赖「重算与首次前向一致」这一假设**（否则当前梯度就是错的），
  所以本候选不引入**新的**数值假设。这一点须在 T8 中用现有代码验证一次。

**开关设计**

```json
"mechanism": { "entity_ranking": {
    "checkpoint_microbatch_budget": -1   // -1 = 全部重算（现状）；k ≥ 0 = 前 k 个不重算
} }
```

`-1` 时走原代码路径。断言：`checkpoint_microbatch_budget = -1` 与现状
`torch.equal` 三项全真（这是**恒等**，因为是同一段代码）。

消融：工程维，随候选一、二一起报告；单独一档 `k` 扫描没有科学意义，
**只报「弃用检查点是否可行」这一二值结论**。

**可证伪的验证方案（判据在此冻结）**

| 项 | 内容 |
| --- | --- |
| 观测量 | 单微批激活量 `a`（MiB）、可用余量 `R`、`k`、排序阶段耗时 |
| 最小实验 | 需 GPU，**本轮不做**。~~本轮只从现有收据反解 `a`（`(30970−15175)/M`）~~ —— **该反解不成立，已划掉，理由见下** |
| **支持判据** | 候选一或二把 `m` 降到 `m·a ≤ R` 的水平，使检查点可整体弃用 |
| **证伪判据** | 即使 `m/M ≤ 0.3`，`m·a` 仍 > `R` → 检查点不可弃用，本候选退化为纯 `1.33` 倍上限，**不足以单独成为第四章机制** |
| 落盘 | `microbatch_activation_mib`、`checkpoint_dropped`（布尔）、`peak_mib` |

**反解 `a` 为何不成立（本文件自查发现的一处错误，保留以志其误）**

原打算用 `a = (30970 − 15175)/M` 反解单微批激活量。该式有两个未验证前提：
两个显存峰值来自**同一批**，且该批的 `M = 100`。二者都无制品支撑——
`15,175 MiB` 是修复后的运行峰值，其批构成未记录，而 5.1 节已证典型批的 `M` 只有 `2~4`。

**算术自检直接推翻它**：若 `M = 100`，得 `a = 158 MiB`；而单个微批
（`64 × 128 = 8192` 条流、`84` token、`d = 192`、BF16）**仅存一份中间张量**就需
`8192 × 84 × 192 × 2 B = 264 MiB` > `158 MiB`。**反解值低于物理下界，故该式错误。**

`a` 只能由 GPU 实测给出（T7）。此处不给数值。

**杀死它的那条理由**

**上限只有 `1.33` 倍，而参照论文第四章的量级是 `4.6` 倍。**
单独拿它做第四章的机制，工作量与效果量级都不够。
它只能作为候选一或二的**配套项**出现，不能独立立章。
**这一条不需要实验即可成立**——`4M/3M` 是算术上界，除非「反向 = 2 × 前向」
这个记法本身错了（可由 T4 校准）。

## 三、候选间关系与执行顺序

```
候选三（HSE）    ── 风险最低、语义最强、与其余三者正交
   │

   │  ⊂

   │
候选四（SAC）    ── 使一、二的收益从 M+4m 降到 M+3m；不独立立章
```

**候选一是候选二的特例吗？** 不是。候选一按**实体**跳过整袋，候选二按**流**只保留

可以叠加：叠加后建图流数为 `Σ_{e∈G} k_e`。

**执行顺序由 T3 决定，不由推演决定**：
若模型计算占排序阶段 `< 50%`，先做候选三；否则先做候选二的保形子变体。

### 5.4 T3 的算术定界：模型计算解释不了 BER 的全部开销（推论）

**这是一条推论，不是实测**，前提逐条列出，任一不成立则结论作废。

前提：
1. 逐流批 `64` 序列 × `128` = `8192` 槽；排序批均值 `91.35` 片段 × `128` = `11,693` 槽（5.1 节）。
2. 反向 ≈ `2 ×` 前向；检查点使排序阶段为 `4 ×` 前向（1.2 节记法）。
3. C00 单轮模型计算 `148` 秒、`1000` 步（主代理简报，属 0.1 已看过数据）。
4. 模型逐流独立（5.5 节已核验），故计算量与槽位数成正比。

推导：一次 `8192` 槽前向记为 `u`。C00 每步 `3u`，`1000` 步 `= 148` 秒 → `u = 49.3` 毫秒。
排序阶段每步 `= 4 × (11693/8192) × u = 5.71u = 281` 毫秒 → `281` 秒/轮。
则 C01 单轮预测 `= 462 + 281 = 743` 秒 `= 12.4` 分钟，**实测 `26` 分钟 `= 1560` 秒**。

**残差 `≈ 817` 秒/轮 `= 0.82` 秒/步，无法由模型计算解释。**

敏感性：若 `capped_segment_count` 的真实均值被 `20` 个末步快照低估，取 `150` 片段
（远高于观测最大值 `196` 的一半）重算，排序模型计算升到 `462` 秒/轮，残差仍有
`≈ 636` 秒/轮。**在片段均值 `91` 到 `150` 的整个区间内，残差都超过模型计算本身。**

**候选二、五的收益上限由此被限死**：它们只能削减那 `281`–`462` 秒中的一部分，
即使把排序阶段的模型计算削到零，C01 单轮也只从 `26` 分钟降到约 `21` 分钟（`1.24` 倍）。

**要达到参照论文第四章的量级（`4.6` 倍），必须先查明那 `0.82` 秒/步是什么。**
这使 **T3（排序阶段耗时分解）从「验证项」升为「本课题第四章能否成立的前置问题」**。
T3 需要 GPU 计时，本轮不做，登记为最高优先级待测项。

**候选二的「杀死它的那条理由」（第一遍前向是下界、模型前向可能不占主导）
由本节推论直接命中。** 该候选在 T3 出结果前不得被当作第四章主机制。

### 5.5 T6：模型逐流独立性（已核验，源码级）

`FTTransformerFieldToken`（`tools/ch3_ft_transformer_field_token_protocol_a.py:2301`）：

```
forward(x_num, x_cat) = predict(blocks(tokenizer(x_num, x_cat)))
```

`tokenizer` 把每一行的各字段变成 token，`blocks` 的自注意力作用在 **token 轴**
（字段轴），`prediction` 逐行输出。**批轴 `n` 上没有任何跨行算子**
（`LayerNorm` 逐 token、注意力逐样本）。故：

- **`z1'=0`（C01，`_entity_ranking_bare_forward`）：把任意流子集重打包成新批，
  逐流输出在数学上不变。** 候选二、五的重打包前提成立。
- **`z1'=1`（C11，`_entity_ranking_memory_forward`）：模型多接
  `broadcast_memory, broadcast_valid` 两个入参（`:2335-2337`），
  仍是「给定状态后逐流独立」，但状态由 `_segment_summary_from_injected`
  从检查点内的 `injected` 导出后 `scratch_memory_state.write`（`:2346-2349`），
  即状态携带梯度并跨片段串联。** 重打包必须同时携带每行对应的状态，
  且不能打乱片段深度层的执行序（`:2288-2298` 的 `depth_orders`）。
  **候选二、五在 C11 上的可行性未被本轮核验推翻，但复杂度显著高于 C01，
  须单独设计并单独验证。**

## 六、候选五 · 有效流稠密打包（VFP, Valid-Flow Packing）

**判据未预先冻结的声明**：本候选由 5.3 节的实测数据派生，
**不得用 5.3 节的同一批数据验证**。其判据在本节写定，验证须用独立的
合成等价实验（V1）与 GPU 计时（V2）。

```md
## Research Question Card

Question:
  排序批的张量形状是 (片段数, 128)，模型跑满全部槽位，
  而实测有效槽位中位仅 19.9%（5.3 节）。
  模型逐流独立（5.5 节）意味着可以把有效流压成稠密批。
  这样做能省多少，代价是什么？

Type: applied

Hypothesis:
  设批内有效流数 V、槽位数 S = 片段数 × 128。
  把有效流按确定序聚成 ⌈V/128⌉ 个稠密片段前向，再按原下标散回 (片段, 列) 位置，
  逐流输出在数学上不变，模型计算量降为原来的 V/S 倍（中位 1/5）。

Why it matters:
  这是四个候选中唯一不依赖活动集、不依赖聚合算子、不需要两遍结构的机制，
  实现最简单，且对 C01 与 C00 的逐流阶段同样适用。
```

**形式化**

设 `valid ∈ {0,1}^{B×T}`，有效位置集合 `V = {(b,t) : valid_{b,t} = 1}`，`|V| = V`。
取确定序 `π : {0..V−1} → V`（按 `(b, t)` 字典序，即现有的行主序）。

```
打包：  X_packed[i] = X_flat[π(i)]                       # (V, F)
前向：  y_packed = f_θ(X_packed)                          # (V,)
散回：  logits[b,t] = y_packed[π^{-1}(b,t)]  若 (b,t) ∈ V
        logits[b,t] = 任意常数（被 valid 掩码吞掉）        否则
```

散回后的 `logits` 直接喂现有的 `prefix_scores`／`tail_scores`，
下游一字不改（两者都先按 `valid` 做 `masked_fill`／`where`，
`ch3_ft_entity_ranking_loss.py:95`、`:197-199`）。

**省的是什么**

| 量 | 现状 | VFP | 依据 |
| --- | --- | --- | --- |
| 模型计算 | `∝ S` | `∝ V` | 逐流独立（5.5 节） |
| 中位倍数 | `1×` | **`5.03×`**（`1/0.199`） | 5.3 节 `17` 轮中位 |
| 最好情形 | `1×` | `17.6×`（第 1 轮 `5.7%`） | 同上 |
| 最坏情形 | `1×` | `2.19×`（第 7 轮 `45.7%`） | 同上 |
| 激活显存 | `∝ S` | `∝ V` | 同比例下降 |

**换算到端到端（沿用 5.4 节推论的前提）**：排序模型计算 `281 → 56` 秒/轮，
C01 单轮 `1560 → 1335` 秒，**`1.17` 倍**。**收益量级同样被 5.4 节的残差限死。**

**数值语义是否改变**

- **逐流输出**：数学恒等（5.5 节）。
- **逐位性**：`f_θ` 在 `(V, F)` 与 `(S, F)` 两种批形状下的 GEMM 分块不同，
  差异只来自浮点重结合律。**必须实测误差上界，不得推演**（验证项 V1）。
- **无效槽位的取值**：现状把 `view.features()` 对无效位置返回的值送进模型，
  其 `logits` 被 `masked_fill(~valid, -inf)`（`:95`）丢弃。VFP 下这些位置根本不算，
  下游行为完全一致。**需核验一件事：无效位置的 `logits` 是否在别处被使用**——
  已查 `prefix_scores:95`、`tail_aggregate:197-199` 均先掩码，
  `bag_policy_diagnostics` 不直接读 `logits`。**核验通过。**
- **C11 的状态路径**：`_segment_summary_from_injected(injected, micro_valid, ...)`
  按 `micro_valid` 汇总，同样只用有效位。但打包会改变「哪些行在同一个微批里」，
  进而改变 `scratch_memory_state` 的读写批次结构。**C11 下须单独设计，本卡不覆盖。**

**开关设计**

```json
"mechanism": { "entity_ranking": {
    "valid_flow_packing": false
} }
```

- 关闭时走原封不动的现有代码路径 → 逐位退化由同一段代码保证。
- 断言函数 `assert_valid_flow_packing_matches_dense`：在 CPU 上用同一权重、
  同一输入，比较打包与不打包的 `logits`（只在有效位比较），
  报告 `max |Δ|` 与相对误差；`float64` 下应为 `0`。
- 消融：与候选二、三同属工程维 `z3`，**主指标是速度与显存，不是 AP**。
  若 `float32`/`BF16` 下的 `Δ` 非零，须单独报告 AP 的浮点级差异，
  **不得把该差异解释为机制效果**。

**可证伪的验证方案（判据在此冻结）**

| 项 | 内容 |
| --- | --- |
| 观测量 | `valid_slot_frac = V/S`（聚合标量）、`max|Δlogits|`、排序阶段耗时、峰值显存 |
| V1（本轮，CPU） | 合成权重与输入，`float64` 下比较打包/不打包的 `logits` 是否 `torch.equal`；`float32` 下报告 `max|Δ|` |
| V2（需 GPU，登记） | 真实批上比较排序阶段墙钟耗时与峰值显存 |
| **支持判据** | `float64` 下 `torch.equal` 为真 **且** V2 中排序阶段模型段耗时降低 ≥ `2×` |
| **证伪判据** | `float64` 下 `torch.equal` 为假（说明打包本身破坏了逐流独立性，机制不成立）**或** V2 降幅 < `1.3×` |
| 落盘 | `valid_slot_frac`、`packing_max_abs_delta`、`ranking_model_seconds`、`peak_mib` |

**杀死它的那条理由**

**它省的是 5.4 节那 `281` 秒里的一部分，而不是那 `817` 秒的残差。**
若 T3 查明残差来自数据侧（`view.gather_sequences`、`view.features` 的 numpy 取数、
H2D 搬运）或 Python 侧（1.6 节的主机同步），VFP 只能拿到 `1.17` 倍，
**不足以单独构成第四章**。

**反过来**：VFP 同时压缩了 H2D 搬运量（`numeric_t`、`categorical_t` 只搬有效流），
若残差恰在数据搬运，VFP 的收益会**高于**上表的模型侧估算。
**这两种可能只能由 T3 分辨，本文件不预判。**

### 7.1 T5：两遍播种反传与单遍全图反传**逐位相等**（三种配置全通过）

| 配置 | `loss` 逐位 | `xi.grad` 逐位 | `logits.grad` 逐位 | `max|Δ|` |
| --- | :---: | :---: | :---: | ---: |
| max 聚合（`z1'=0`），`float64` | 真 | 真 | 真 | `0.0` |

### 7.3 T3 代理：因果前缀截断的 Python 循环开销远低于预设阈值

向量化实现（按实体分组累积和 + 阈值比较，无 `.item()`、无 `nonzero`）与
`_causal_truncate_valid` 的掩码**逐位相等**（两种批型均为真，保留流数分别
`1821 = 1821`、`41381 = 41381`）。耗时（`5` 次平均）：

| 批型 | 片段 | 循环版 | 向量版 | 倍数 |
| --- | ---: | ---: | ---: | ---: |
| 典型批（有效槽 `19%`） | `76` | `0.281` 毫秒 | `0.228` 毫秒 | `1.23` |
| 极端批（长袋触发截断） | `1021` | `2.982` 毫秒 | `1.800` 毫秒 | `1.66` |

**候选三的冻结支持判据是「循环版 CPU 耗时 ≥ `50` 毫秒/次」，实测 `0.281` 毫秒，
低 `178` 倍 —— 支持判据不成立。**

其冻结的证伪判据是「CPU 耗时 `< 10` 毫秒 **且** 同步次数在 GPU 上无法被证明放大」，
第一个合取项成立，第二个尚未测（需 GPU）。故**候选三处于「支持判据不成立、
证伪判据未完全满足」的状态**，按纪律记为**大幅降级但未正式出局**。

主机同步次数的源码计数（**推论，未在 GPU 上实测**）：
`_causal_truncate_valid` 的 `remaining` 耗尽后走 `:849-851` 的快路径且
`continue` 在 `:853` 之前，故只有「每实体前若干行」触发同步；典型批下
每实体 `1` 段 → 同步次数 ≈ 片段数 `76`，加 `_entity_groups` 的 `2` 次
（`:832-833`）与三支袋处置的 `entity_score_source_row.tolist()` 各 `1` 次（`:925`），
合计约 `81` 次/步。按单次 `10~50` 微秒计，为 `0.8~4` 毫秒/步、即 `0.8~4` 秒/轮，
**相对 5.4 节 `817` 秒/轮的残差可忽略**。

**这条杀死了候选三作为第四章主机制的可能**——它连残差的 `0.5%` 都解释不了。
它仍可作为随手的工程整改（向量化掩码逐位相等，零风险），但**不足以立章**。

### 7.4 V1：有效流稠密打包的误差是浮点级，但**不逐位相等**

用与 FT-Transformer 同构的逐行模型（字段 token 化 + token 轴注意力 + 逐行预测头，
`dropout=0`、`eval()`），比较「满槽前向后取有效位」与「只前向有效流」：

| 精度 | 槽位 | 有效流 | 逐位相等 | `max|Δ|` | 最大相对误差 |
| --- | ---: | ---: | :---: | ---: | ---: |
| `float64` | `9728` | `1821` | **假** | `2.22e-16` | `1.13e-15` |
| `float32` | `9728` | `1821` | **假** | `1.49e-07` | `9.56e-07` |

`float64` 的 `2.22e-16` 恰是 `float64` 的机器精度 `eps`，相对误差 `1.13e-15 ≈ 5 ulp`；
`float32` 的 `9.56e-07 ≈ 8 ulp`。**误差量级与「GEMM 分块顺序不同导致的浮点重结合」
完全一致，与「机制被破坏」不一致**（后者会给出 `O(1)` 量级的差异）。

**但候选五冻结的支持判据是「`float64` 下 `torch.equal` 为真」，实测为假；
其冻结的证伪判据「`float64` 下 `torch.equal` 为假」被触发。
按纪律，候选五按其自身判据被证伪，本文件不为救它而修改判据。**

**同时如实记录判据本身的规格缺陷**：该判据把「逐流独立性」（数学性质，
本轮实测**成立**——误差 `5 ulp`）与「不同批形状下的逐位可复现性」（核实现性质，
对任何批处理 GEMM 都**不成立**）混为一谈。用户在硬约束 4.1 中给的判定方式是
「逐位相等**或**差异仅来自浮点重结合律，须给出可验证的误差上界」——
按用户约束，候选五落在第二支，误差上界已实测给出。

**两个判据冲突，裁决权不在本文件。** 处置：把候选五标为
**「按本文件自身判据证伪、按用户硬约束第二支通过」**，交主代理与用户裁定。
同一冲突同样适用于候选二的 **ASR-重打包** 子变体。

## 九、由本轮证据新开的两个候选

### 候选六 · 空活动集短路（EAS, Empty-Active-Set Short-Circuit）

**数据来源声明**：本候选由 5.2 节的活动率数据派生。5.2 是**轮均值**与
**`20` 个末步快照**；本候选的判据落在**逐步的空活动集占比**上，
该统计量尚不存在于任何制品，**是独立数据**，不构成循环论证。

```md
## Research Question Card

Question:
  当某一步的六档活动集全空时，L_rank 关于 θ 退化为常数，g_rank 恒等于零向量。
  能否在第一遍无梯度前向后直接判空并跳过整个反向，而不做任何重打包？

Type: applied

Hypothesis:
  活动集全空 ⟺ 对所有 (p,n,k) 有 L_pn ≤ ξ_{p,k}
             ⟹ loss = mean_k mean_p ξ_{p,k}（对 θ 为常数）
             ⟹ ∂loss/∂θ ≡ 0（精确为零向量，不是近似）
  此时 Pass 2 可整体跳过，g_rank 直接置零。ξ 仍须更新，
  因为 ∂loss/∂ξ_{p,k} = (1/(6N_p))(1 − m/K_eff) = 1/(6N_p) ≠ 0，
  而它只需前向值。

Why it matters:
  这是本文件唯一一个「逐位精确、不需重打包、不改变任何形状」的稀疏化机制，
  数值风险为零，实现只有几行。
```

**形式化**

```
Pass 1（torch.no_grad）：得 S、L_pn、m_{p,k}
若 max_{p,n} L_pn ≤ min_{p,k} ξ_{p,k}：
    g_rank ← 0                                      # 精确，不是近似
    ξ_{p,k} ← ξ_{p,k} − η_ξ / (6 N_p)               # 只用前向值，逐位等价
    跳过 Pass 2
否则：
    走现状路径（或候选二的稀疏路径）
```

**逐位性**：`g_rank` 在两条路径下都是零向量，`torch.equal` 恒真；
`ξ` 的更新量在两条路径下都是 `η_ξ/(6N_p)`，逐位相同；
`loss` 的值 `= mean_k mean_p ξ_{p,k}` 由 Pass 1 的前向值算出，逐位相同。
**这是四类候选中唯一一个可以在任意精度下断言逐位相等的。**

**省的是什么**：空步的排序阶段计算从 `4u'` 降到 `1u'`（`u'` 是排序批一次前向），
即该步省 `75%` 的排序模型计算。全轮收益 `= 空步占比 × 75% × 排序模型计算`。

**开关设计**

```json
"mechanism": { "entity_ranking": { "empty_active_set_shortcut": false } }
```

关闭走原代码路径。断言 `assert_empty_active_shortcut_is_exact`：
构造全空活动集的合成批，比较开关两侧的 `g_rank`、`xi` 更新量、`loss`，
三者 `torch.equal` 须全真。

消融：工程维，主指标速度；**AP 必须逐位不变**，任何差异判为实现错误。

**可证伪的验证方案（判据在此冻结）**

| 项 | 内容 |
| --- | --- |
| 观测量 | `empty_active_step_frac`（轮内空活动集步数占比，聚合标量，**须新增收据字段**） |
| 最小实验 | 现有 C01 运行加一个只读计数器即可测，不改数值 |
| **支持判据** | `empty_active_step_frac ≥ 0.20`（对应至少省 `15%` 的排序模型计算） |
| **证伪判据** | `empty_active_step_frac < 0.05` |
| 落盘 | `empty_active_step_frac`、`ranking_shortcut_step_count` |

**实测佐证（判据冻结后读取的独立数据）**

`ch3-ft-c01-entity-ranking-cuda-formal-v1`（编译路径运行，早于当前即时执行复现合同）
的逐轮末步快照，把最高档活动率与该步的排序梯度范数对照：

| 轮 | 最高档活动率 | `grad_norm_rank` | `c_scaling` | `controlled_rank_step_norm` |
| ---: | ---: | ---: | ---: | ---: |
| 3 | `0.03125` | `38.1631` | `0.0762916` | `2.30002` |
| **7** | **`0.0`** | **`0`** | **`0`** | **`0`** |
| **8** | **`0.0`** | **`0`** | **`0`** | **`0`** |
| **9** | **`0.0`** | **`0`** | **`0`** | **`0`** |
| 12 | `0.0078125` | `1.48477e-4` | `1` | `1.47603e-4` |
| **18** | **`0.0`** | **`0`** | **`0`** | **`0`** |
| 20 | `0.0234375` | `9.20999e-4` | `1` | `9.20999e-4` |

**活动集全空的步里 `grad_norm_rank` 精确等于 `0`，控制器给出 `c_scaling = 0`，
合成梯度 `combined = g_flow + 0 × 0 = g_flow` 逐位等于纯逐流梯度。**
（`ch3_ft_gradient_controller.py:74-81`：`norm_r_plus = 0` 时走 `c = 0.0` 分支；
`ch3_ft_c00_dual_selection.py:2051-2057`：`.grad` 为 `None` 时补零，不会崩。）

**即：这些步里整个排序阶段的前向、重算与反向全部是纯浪费，
现有代码已经在合成时把结果丢掉，只是丢之前先算了一遍。**
`20` 个末步快照中有 `5` 个（`25%`）落在此情形——**但这是 `20/20000` 的采样，
不能当作逐步占比的估计**，故本候选的判据仍落在须新增的 `empty_active_step_frac` 上。

**口径限定**：v2 运行（`ch3-ft-c01-ranking-eager-formal-v2`）的**轮均**活动率最低为
`0.0068`（第 6 轮最低档），非零；v1 与 v2 的运行身份、执行路径与轮次范围都不同，
**两者的空步占比不可互相代用**。

**杀死它的那条理由**：**它省的是 `4u'` 里的 `3u'`，而 `u'` 只占 `706` 秒里的 `70` 毫秒/步。**
即使空步占比 `100%`，全轮也只省 `211` 秒（8.3 节 `91.35` 片段假设下），
端到端 `1181 → 970` 秒，`1.22` 倍。**它是必做的便宜项，不是第四章的主机制。**

### 候选七 · 排序步频下调与阈值补偿（RSC, Ranking-Step Cadence）——**改变数值语义**

**本候选明确标注：改变数值语义，需重跑第三章全部四格。** 代价见下。

```md
## Research Question Card

Question:
  排序阶段每个训练步都跑一次（1.1 节），占 C01 单轮 59.8%（8.2 节）。
  若每 R 步只跑一次排序阶段，端到端加速接近 R 的上限；
  代价是优化轨迹改变。这个代价有多大，值不值？

Type: confirmatory

Hypothesis:
  排序阶段的计算量与 R 成反比，端到端单轮耗时降为 475 + 706/R 秒。
  R=2 → 828 秒（1.43 倍）；R=4 → 652 秒（1.81 倍）；R=8 → 563 秒（2.10 倍）。
  与候选五叠加后，R=4 时可达约 2.2 倍——接近 8.4 节的硬上限 2.49 倍。

Why it matters:
  这是唯一能逼近 2.49 倍硬上限的单一机制。
  但它把「BER 每步参与」这一冻结行为改掉了，属实质改动。
```

**为什么它改变数值语义**

1. **优化轨迹**：`g_rank` 只在 `1/R` 的步上进入合成梯度，梯度控制器的
   `c_scaling` 与投影行为随之改变（`_combine_and_step`，`:2560-2580`）。
2. **`ξ` 的更新次数减少 `R` 倍**，而 `ξ` 的下行速度已有硬上界
   `η_ξ/(6N_p) = 8.333e-6`/次（BER 方案 3.4 节）。**更新次数除以 `R` 会使
   已知的「高档 `ξ` 系统性滞后 `3.4σ`」进一步恶化**，除非同步把 `η_ξ` 乘以 `R`——
   而那是又一个未登记的数值改动。
3. **正实体轮转采样的一轮长度变为 `R` 倍**，第 3.1 节无偏性成立的
   「一轮轮转平均」意义随之改变。

**代价**：第三章四格全部重跑（`4 × 20 × 1000` 步）。按 8.1 实测，
C00 `9505` 秒、C01 `23620` 秒、C10 零训练、C11 约 `24000` 秒，
**合计约 `16` 小时 GPU 独占**，且第三章已有的全部读数作废。

**开关设计**

```json
"mechanism": { "entity_ranking": {
    "ranking_step_interval": 1,          // 1 = 现状
    "xi_learning_rate_compensation": false
} }
```

`ranking_step_interval = 1` 时逐位退化为现状（同一段代码）。
`R > 1` 时**必须**在收据里显式记录 `ranking_step_interval` 与
`xi_effective_update_count`，正文任何比较都须注明该值。

消融：**这是科学维，不是工程维。** `R` 是一个新的科学超参数，
按仓库的魔法数字门禁，须登记用途、值、文献依据（预期为「无直接文献依据，任务化设定」）、
数学推导（`ξ` 更新次数与滞后的关系）、真实数据诊断、适用边界、是否接触最终目标标签。

**可证伪的验证方案（判据在此冻结）**

| 项 | 内容 |
| --- | --- |
| 观测量 | 源年验证实体 AP、六档活动率轮均值、`ξ` 滞后统计、单轮耗时 |
| 最小实验 | **单种子筛选臂**：`R ∈ {1, 4}` 两档，同预算同种子，比较源年实体 AP 与耗时 |
| **支持判据** | `R=4` 的源年实体 AP 相对 `R=1` 的下降 ≤ `0.01`（绝对值）**且** 单轮耗时降低 ≥ `1.6` 倍 |
| **证伪判据** | 源年实体 AP 下降 > `0.03`，**或** 六档活动率轮均对 `β_K` 的比值全部跌破 `0.5`（沿用水库修法裁决的既有下界） |
| 落盘 | `ranking_step_interval`、`validation_entity_ap`、`per_budget_active_rate`、`epoch_seconds` |

**杀死它的那条理由**：**BER 的作用本来就建立在「排序梯度与逐流梯度每步竞争」之上**
（BER 方案 3.6 节：控制器把排序梯度归一化到与逐流梯度同幅值，两者余弦在第 2 轮翻负）。
把排序梯度改成每 `R` 步来一次，等于把一个持续的方向约束改成脉冲式扰动，
**很可能直接把 C01 的正增益打没**。这条只能由上面的单种子筛选臂裁决。

## 十一、时间维（跨步复用）的可用性：按抽样算术关闭

[第四章效率机制文献调研](第四章效率机制文献调研.md) 5.2 节指出，参照论文第四章
把效率问题拆成**空间维（样本级筛选）× 时间维（跨轮次复用）**两个正交维度乘性叠加，
而本文件的七个候选**全部落在空间维**，时间维是空缺的设计维度。

本节用抽样算术直接评估该维度对 BER 是否可用。**不需要实验。**

**负实体侧（占批内实体的 `97%`）**：负实体池 `N⁻ = 121,336`，每步抽 `n_neg = 64`，
每轮 `1000` 步 → 每轮共 `64,000` 次抽取。

```
每个负实体的每轮期望被抽次数 = 64000 / 121336 = 0.527
每轮期望不同负实体数 = 121336 × (1 − e^(−0.527)) = 49,700
每轮可命中「轮内缓存」的抽取数 = 64,000 − 49,700 = 14,300 → 22.3%
```

即**轮内最多 `22.3%` 的负实体抽取有机会命中缓存**，且命中时缓存的分数已陈旧
**最多 `1000` 个优化步**。折算收益：命中部分只省 Pass 1 的前向，
`22.3% × 70` 毫秒/步 `≈ 15` 毫秒/步 `= 15` 秒/轮，
**相对 `706` 秒/轮的 BER 开销为 `2.1%`**。

**正实体侧**：`165` 个正实体，每步 `n_pos = 2`，每轮 `2000` 次抽取 →
每个正实体每轮被抽 `12.1` 次，复用率高。**但正实体只占批内实体的 `2/66 = 3%`，
且它们是恒有梯度的那一批（1.3 节：`∂L_pn/∂S_p < 0` 恒成立）**，
缓存它们既低收益又直接破坏梯度。

**裁定：时间维对 BER 结构性不可用。** 根因是负实体池比批规模大三个数量级
（`121,336 / 64 = 1896` 倍），跨步之间根本没有重复对象可复用。
这与参照论文的情形相反——**其被缓存量是每个样本自己的慢变量，样本在轮次间必然重现；
本课题的负实体在一轮内有 `77.7%` 的概率只出现一次。**

**这一条同时说明**：本文件七个候选全部落在空间维不是设计疏漏，
而是抽样结构决定的。**该结论应写入正文作为方法边界的中性陈述**，
按参照论文体例写成作用条件，不写成「局限」。

**尚未评估的第三类对象**：`ξ` 本身已经是跨步持久状态（`CvarThresholdState`，
`ch3_ft_entity_ranking_loss.py:526-716`），即时间维在 BER 中**已经被 `ξ` 占用**，
只是它服务的是正确性而不是效率。是否存在第二个可缓存的慢变量（如活动集成员、
argmax 位置），本文件未评估，标为**待验证假设**。
