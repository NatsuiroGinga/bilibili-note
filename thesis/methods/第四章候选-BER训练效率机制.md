### 1.2 检查点把显存换成了两倍前向

`_entity_ranking_bare_forward`（`:2180-2247`）与 `_entity_ranking_memory_forward`
（`:2262-2360`）对**每一个**微批的纯计算段调用
`torch.utils.checkpoint.checkpoint(..., use_reentrant=False)`（`:2238`、`:2341`）。

以「一条序列的一次前向」为 `1` 单位、反向约 `2` 单位记，排序阶段的模型计算量是

```
现状 = 前向 M + 反向期重算 M + 反向 2M = 4M          （M = 微批数）
无检查点 = 前向 M + 反向 2M = 3M                      （已实测 OOM，不可行）
```

即检查点的代价是 `4M/3M = 1.33` 倍计算量，换来激活显存从 `O(M)` 降到 `O(1)`。
实测步速比 `6.9/2.6 = 2.65` 倍**大于** `1.33`，差额须由独立测量解释，
本文件不臆测（列为待测项 T4）。

### 1.3 CVaR 的梯度只落在活动集上（源码可证）

`cvar_pauc_loss`（`ch3_ft_entity_ranking_loss.py:432-504`）的字面实现是

```
loss = (1/6) · Σ_k (1/N_p) · Σ_p [ ξ_{p,k} + (1/K_k) · Σ_n relu(L_pn − ξ_{p,k}) ]
```

（`:485-487` 的 `hinge = relu(pairwise − ξ_k)`、`r_k = ξ_k + hinge.sum(dim=1)/k`、
`:492` 的 `loss = stack(budget_terms).mean()`）。对配对损失求导：

```
∂loss/∂L_pn = (1/(6·N_p)) · Σ_k (1/K_k) · 1[L_pn > ξ_{p,k}]
```

`relu` 在零点的子梯度取零（`:485` 注释明写）。定义**活动集**

```
A = { n ∈ 负实体 : ∃(p,k), L_pn > ξ_{p,k} }
```

则对任意 `n ∉ A`，`∂loss/∂S_n ≡ 0`（**精确为零，不是数值上的小量**）。
`S_p` 恒有梯度（`∂L_pn/∂S_p = −σ(S_n−S_p) < 0`，`softplus` 严格增）。

**ξ 的更新不需要 θ 的梯度路径**：`∂loss/∂ξ_{p,k} = (1/(6N_p))(1 − m_{p,k}/K_k)`，
其中 `m_{p,k} = #{n : L_pn > ξ_{p,k}}` **只需前向值**。宿主的实现（`:2423-2424` 取
`xi` 叶张量并 `retain_grad()`，`:2451` 反传，`:2454-2455` 更新并 `commit`）
把 ξ 的子梯度挂在同一次 `backward()` 上，但这只是实现上的顺手，不是数学必需：
把损失建在 **detach 后的实体分数**上同样能得到逐位相同的 `xi.grad`。

**主代理简报中的提示由此得到源码确认**：计数 `m_{p,K}` 确实只需前向值，
不构成稀疏建图的障碍。

### 1.4 聚合算子把梯度进一步压到「每实体 k_e 条流」

这一层稀疏性简报未提及，是本文件的独立发现。

`prefix_scores`（`:67-121`）的梯度路径：

- `:96-97` 先对每个片段行取 `argmax` 再 `gather` → 每行只有**一列**有梯度；
- `:104-112` 用 `scatter_reduce` 的 `amax`/`amin` **只做定位**（`:105` 显式
  `segment_scores.detach()`），不反传；
- `:115` `entity_scores = segment_scores.gather(0, first_pos)` → 每个实体只有**一行**有梯度。

**结论**：`z1'=0`（max 聚合，即 C01）时，`∂loss/∂logits` 的非零元恰好是
**每实体一个 `(行, 列)`**，全批至多 `E = 66` 个，而 `logits` 有
`B×T ≤ 4224×128 = 540,672` 个元素。**非零率上界 `66/540672 ≈ 1.22e-4`。**

`tail_aggregate`（`:149-243`）的梯度路径：`:230-233` 的
`take = (rank_in_group < k_e) & valid`、`contribution = where(take, sorted_scores, 0)`
使梯度落在每实体**得分最高的 `k_e` 条流**上，`k_e = max(1, ⌈α·m_e⌉)`（`:225`）。
`z1'=1`（ETA，`α=0.5`）时 `k_e ≈ m_e/2`，**流级稀疏度只有 `2` 倍，不是 `m_e` 倍**。

这一非对称是候选二的适用边界，也是它与四格的天然交互项（见候选二卡）。

### 1.5 三种袋处置全部带图计算，其中两种只用于记数

`bag_policy_diagnostics`（`:866-969`）对同一批**并行计算三种袋处置**：
`full`（`:937`）、`causal_prefix_truncation`（`:942`）、`stratified_weighting`（`:950`）。
只有 `config.active_policy` 那一支进入 `backward()`（宿主 `:2439`、`:2451`），
另两支的返回值只被写进诊断字典（`:938`、`:947`、`:955` 的 `loss_value`）。

但三支都在 `torch.no_grad()` **之外**执行，即两支纯记录分支同样建立并持有 autograd 图，
直到 Python 引用消失才释放。

### 1.6 因果前缀截断是逐行 Python 循环，每行两次主机同步

```python
count = int(row_valid.sum().item())          # :853  主机同步
```

### 候选一 · 活动集稀疏反传（ASB, Active-Set Sparse Backward）

```md
## Research Question Card

Question:
  CVaR-pAUC 对非活动负实体的梯度恒为零，能否只对活动集构建反向图，
  在不改变损失值、ξ 更新与 θ 梯度的前提下降低排序阶段的计算与显存？

Type: applied

Hypothesis:
  设 A 为活动负实体集、P 为正实体集、G = P ∪ A。
  只对 G 所属片段构建反向图，得到的 θ 梯度与现状在精确算术下相同；
  排序阶段模型计算量从 4M 降到 M + 3m（m 为需建图的微批数）。

Why it matters:
  排序阶段是 C01 相对 C00 慢 3.4 倍的唯一来源（1.1 节）。
  该候选不触碰损失定义、采样口径与超参数，因此第三章四格结果不需重跑。
```

**形式化**

两遍算法。记微批划分 `{B_1,…,B_M}`（按现状 `indices[start:stop]` 切分，
`ch3_ft_c00_dual_selection.py:2220`），`rows(e)` 为实体 `e` 的片段行集合。

```
Pass 1（torch.no_grad）：
    对 j = 1..M：  logits_j ← f_θ(B_j)                     # 不建图
    S ← aggregate(logits, valid, owner)                    # 全体实体分数（detached）
    L_pn ← softplus(S_n − S_p)
    A ← { n : ∃(p,k), L_pn > ξ_{p,k} }
    m_{p,k} ← #{ n : L_pn > ξ_{p,k} }

Pass 2（建图）：
    G ← P ∪ A
    J ← { j : B_j ∩ (∪_{e∈G} rows(e)) ≠ ∅ }                # 需建图的微批
    对 j ∈ J：  logits_j' ← f_θ(B_j)                        # 建图
    对 j ∉ J：  logits_j' ← logits_j.detach()               # 复用 Pass 1 结果
    S' ← aggregate(logits', …)
    loss ← cvar_pauc_loss(S'_P, S'_N, K_eff, ξ)
    loss.backward()
```

`ξ` 的更新与现状逐字相同（`:2453-2455`），因为 `∂loss/∂ξ` 只依赖前向值。

**省的是什么**

| 量 | 现状 | ASB | 依据 |
| --- | --- | --- | --- |
| 模型计算 | `4M` | `M + 3m`（不套检查点）或 `M + 4m`（仍套） | 1.2 节的单位记法 |
| 加速比 | — | `4M/(M+3m) = 4/(1+3·m/M)` | 同上 |
| 激活显存 | `O(1)` 微批（检查点已压） | `O(1)` 微批，且 `m` 小时可整批弃用检查点 | `:2238` |

`m/M = 0.3` → `1.05` 倍…等等，`4/(1+0.9) = 2.11` 倍；`m/M = 0.5` → `1.60` 倍；
`m/M = 1.0` → `1.00` 倍（无收益）。**收益完全由 `m/M` 决定。**

**数值语义是否改变**

- **损失值**：Pass 1 在 `no_grad` 下运行同一组核，值与现状逐位相同 → `loss` 逐位相同。
- **`ξ` 更新**：只依赖前向值 → 逐位相同。
- **`θ` 梯度**：`n ∉ A` 的贡献精确为零（1.3 节），故数学上相同。
  **逐位相等的充要条件是 Pass 2 保持微批形状不变**——本候选按微批粒度跳过，
  不重打包，因此保形；被保留微批的前向与 Pass 1 走同一形状同一核，逐位相同。
- **判定方式**：同种子同批数据下，开关前后 `loss`、`xi.grad`、`g_rank` 三者
  `torch.equal` 全为真。**这是可机械判定的断言。**

**开关设计**

```json
"mechanism": { "entity_ranking": {
    "active_set_backward": false        // 默认 false = 现状
} }
```

- 关闭时**逐位退化**：`active_set_backward=false` 时函数体走原封不动的现有代码路径
  （与 `BagPolicyConfig.alpha is None` 走原 `prefix_scores` 同一手法，
  见 `ch3_ft_entity_ranking_loss.py:132-137` 的口径说明），
  「逐位相同」由「同一段代码」保证，强于任何数值断言。
- 断言函数：`assert_active_set_backward_preserves_gradient`，
  对照 `assert_tail_aggregation_degenerates_to_max`（`:383-424`）的写法，
  在 CPU 上比较开关两侧的 `loss`/`xi.grad`/`g_rank`。
- 消融维度：**独立第三维 `z3`**，与四格 `z1'×z2` 正交。
  `z2=0` 时排序损失不进训练图，`z3` 无定义（收据须显式记 `z3=n/a`）。
  故消融格点是 `{C01, C11} × {z3=0,1}` 共四格，**指标是速度与显存，不是 AP**；
  AP 必须逐位不变，任何 AP 差异都判为实现错误而非机制效果。

**可证伪的验证方案（判据在此冻结）**

| 项 | 内容 |
| --- | --- |
| 观测量 | `m/M`（需建图微批数占比，聚合标量）、`|A|/N_n`（活动负实体占比，聚合标量）、排序阶段墙钟耗时、峰值显存 |
| 最小实验 | 合成数据上构造 `E=66`、`M∈{6,20,100}` 的排序批，跑开关两侧，比较三项 `torch.equal` 与耗时 |
| **支持判据** | 三项 `torch.equal` 全真 **且** `m/M ≤ 0.6`（对应 ≥ `1.43` 倍加速） |
| **证伪判据** | `m/M > 0.8`（加速 < `1.18` 倍，不值得引入一维消融）**或** 任一 `torch.equal` 为假 |
| 落盘 | 只落聚合标量：`m_over_M`、`active_negative_frac`、`ranking_phase_seconds`、`peak_mib`。**禁止落逐实体成员表** |

**杀死它的那条理由**

**微批级聚类失效。** 微批按行序切分（`:2220`），行按 `(entity, T23)` 分组有序，
所以一个 `64` 序列的微批覆盖若干**相邻**实体。袋小的实体（源年验证集袋大小中位数 `2`）
密集堆在少数微批里；只要其中一个实体活动，整个微批就得保留。
若活动负实体在实体序上均匀散布，则 `m/M → 1`，**收益归零**。

**如何证伪这条杀手理由**：测 `m/M` 的真实分布（待测项 T1）。
若 `m/M ≤ 0.6` 则杀手不成立；若 `> 0.8` 则候选一按上面的证伪判据出局，
但**候选二仍可能存活**——后者不依赖实体在微批中的聚类。

### 候选二 · 聚合稀疏梯度重打包（ASR, Aggregation-Sparse Repacking）

```md
## Research Question Card

Question:
  max 聚合使 ∂loss/∂logits 每实体只有一个非零元（1.4 节）。
  能否只把这些携带梯度的流重新打包成一个极小的批做反向，
  把排序阶段的建图规模从「全批片段」降到「每实体 k_e 条流」？

Type: applied

Hypothesis:
  FT-Transformer 在本实现中是**逐流独立**的（注意力在字段维、不在流维，
  见 1.2 节引用的 `flat_num = numeric_t.reshape(batch*length, F)`）。
  因此把任意流子集重打包成新批，其逐流输出在数学上不变。
  以 Pass 1 的 detached 分数算损失得到 ∂loss/∂S_e，再对重打包批
  用 `backward(S', grad_tensors=g)` 播种，可得与现状数学相同的 θ 梯度，
  而建图规模从 O(B·T) 降到 O(Σ_e k_e)。

Why it matters:
  z1'=0 时 Σ_e k_e = E ≤ 66，相对 B·T ≤ 540,672 是 8000 倍压缩。
  这是本文件中唯一可能达到参照论文第四章量级（4.6 倍）的候选。
```

**形式化**

借 GradCache（对比学习中的分块梯度缓存）的两遍结构，但稀疏性来源不同——
GradCache 靠的是「表示向量是瓶颈」，本候选靠的是「聚合算子把梯度压到 `k_e` 条流」。

```
Pass 1（torch.no_grad）：同候选一，得全体 S（detached）与 valid、owner
选择集：  Sel ← ∪_{e∈G} argtop_{k_e}(该实体的有效流)        # 由 Pass 1 确定并冻结
损失与播种：
    Ŝ ← S.clone().requires_grad_(True)                      # E 个标量的叶张量
    loss ← cvar_pauc_loss(Ŝ_P, Ŝ_N, K_eff, ξ)
    loss.backward()                                          # 只反传 E+|ξ| 个标量
    g ← Ŝ.grad                                               # ∂loss/∂S_e，E 维
Pass 2（建图，重打包）：
    把 Sel 中的流按任意确定序打包成 ⌈|Sel|/(micro·T)⌉ 个新批
    logits_sel ← f_θ(打包批)                                 # 建图
    S' ← aggregate_from_selected(logits_sel, Sel, k)          # 只用选中流重建 S_e
    torch.autograd.backward(S', grad_tensors=g)               # 播种反传
```

`aggregate_from_selected` 在 `z1'=0` 时是恒等映射（每实体一条流），
在 `z1'=1` 时是 `mean` over `k_e`（权重 `1/k_e`，与 `tail_aggregate:239` 一致）。

**省的是什么**

| 量 | 现状 | ASR（`z1'=0`） | ASR（`z1'=1`, α=0.5） |
| --- | --- | --- | --- |
| 建图流数 | `B·T` | `E ≤ 66` | `Σ_e ⌈m_e/2⌉ ≈ (B·T)/2` |
| 模型计算 | `4M` | `M + 3·⌈66/8192⌉ ≈ M + 3` | `M + 3·(M/2) = 2.5M` |
| 理论加速 | — | `≈ 4M/(M+3)`，`M=100` 时 `3.88` 倍 | `1.6` 倍 |
| 激活显存 | `O(1)` 微批 | `O(1)` 微批且可弃检查点 | 同左 |

**`z1'` 决定收益量级，这是候选二与第三章四格的真实交互，不是设计缺陷。**

**数值语义是否改变**

分两个子变体，**必须分开裁决**：

| 子变体 | θ 梯度 | 判定 |
| --- | --- | --- |
| **ASR-保形**：只跳过完全不含选中流的整微批，不重打包 | **逐位相等** | `torch.equal` 可断言 |
| **ASR-重打包**：把选中流压成新批 | **数学相等，逐位不等** | 差异只来自 GEMM 分块的浮点重结合律 |

- `loss` 值与 `ξ` 更新在两个子变体下**都逐位相等**（都由 Pass 1 的 detached 分数算得，
  而 Pass 1 与现状同形同核）。
- ASR-重打包的误差上界**不能靠推演给出**，必须实测：在合成数据上比较
  `‖g_repacked − g_current‖_∞ / ‖g_current‖_∞`，登记该比值。**这是待测项 T5。**
- **若该比值不能稳定低于 BF16 的机器精度量级，ASR-重打包必须标注
  「改变数值语义、需重跑第三章」**，代价是四格全部重跑（`4 × 20 × 1000` 步）。

**开关设计**

```json
"mechanism": { "entity_ranking": {
    "sparse_backward_mode": "off"      // "off" | "shape_preserving" | "repack"
} }
```

- `"off"` 走原封不动的现有代码路径 → 逐位退化由同一段代码保证。
- `"shape_preserving"` 的断言：`loss`/`xi.grad`/`g_rank` 三者 `torch.equal` 全真。
- `"repack"` 的断言：`loss`、`xi.grad` `torch.equal` 为真；`g_rank` 只断言相对误差
  上界（阈值由 T5 实测确定后冻结，**不得在看到 AP 结果后调整**）。
- 消融：与候选一同属 `z3` 维，取值 `{off, ASB, ASR-保形, ASR-重打包}` 为四水平因子。
  **主指标是速度与显存**；`off`/`ASB`/`ASR-保形` 三档的 AP 必须逐位相同，
  只有 `ASR-重打包` 允许 AP 有浮点级差异，且该差异须单独报告。

**可证伪的验证方案（判据在此冻结）**

| 项 | 内容 |
| --- | --- |
| 观测量 | `选中流数/总有效流数`（聚合标量）、`‖Δg‖_∞/‖g‖_∞`、排序阶段耗时、峰值显存 |
| 最小实验 | CPU 合成数据：`E=66`、每实体袋大小取 `{1,2,64}` 三档混合、`B·T` 约 `5e5`；跑三档开关 |
| **支持判据** | `z1'=0` 下 ASR-保形的 `torch.equal` 三项全真 **且** 端到端排序阶段耗时降低 ≥ `40%` |
| **证伪判据** | ASR-保形耗时降低 < `15%`（说明模型前向不是瓶颈，主机同步或损失侧才是），**或** `loss`/`xi.grad` 任一 `torch.equal` 为假（说明两遍结构本身破坏了语义） |
| 落盘 | `selected_flow_frac`、`grad_rel_err_inf`、`ranking_phase_seconds`、`peak_mib`，全为标量 |

**杀死它的那条理由**

**Pass 1 的无梯度前向本身就是下界。** ASR 无论多稀疏，都必须完整跑一遍全批前向
才能知道谁是 argmax、谁在活动集里。该前向占现状 `4M` 中的 `1M`，
即 **ASR 的加速上限是 `4` 倍，且逼近该上限时 Pass 1 独占全部时间**。
若排序阶段的真实耗时中**模型前向只占一小部分**（另一大部分是 1.6 节的主机同步、
1.5 节的三支袋处置、以及 `view.features()` 的 numpy 取数与 H2D 搬运），
则 ASR 削掉的那部分本来就不大，`40%` 判据不可能达成。

**如何证伪这条杀手理由**：先做待测项 T3（排序阶段的耗时分解）。
**T3 必须先于 T5 执行**——若模型计算不占主导，候选二整体降级、候选三升为首选。

**第二条杀手（对 C11 专属）**：`_entity_ranking_memory_forward`（`:2262-2360`）中
片段状态由 `_segment_summary_from_injected` 从检查点内的 `injected` 导出后
`scratch_memory_state.write`（`:2346-2349`），**状态本身携带梯度并跨片段串联**。
重打包会切断这条链。故候选二在 `z1'=1`（C11、启用实体记忆）下**可能整体不成立**，
须单独核验状态是否真的进入反传图。列为待测项 T6。

### 候选三 · 热路径主机同步消除（HSE, Host-Sync Elimination）

```md
## Research Question Card

Question:
  排序阶段每步在 GPU 热路径上执行 O(片段数) 次主机同步（1.6 节）
  与两支只用于记数的带图袋处置（1.5 节）。消除它们能省多少？

Type: applied

Hypothesis:
  因果前缀截断（`_causal_truncate_valid`, :839-863）的逐行 Python 循环
  可改写为按实体分组的累积和 + 阈值比较，语义**逐位相同**（布尔掩码，无浮点）；
  两支非生效袋处置移入 `torch.no_grad()` 后，生效支的值与梯度**不受任何影响**。

Why it matters:
  这是本文件中唯一**不需要任何数值容忍**的候选：
  掩码是布尔量，可以断言逐位相等；非生效分支根本不参与反传。
  若它的收益量级可观，它应当先做——风险最低。
```

**形式化**

因果前缀截断的等价向量化定义。设实体 `e` 的片段按 `(片段序, 列序)` 展平后，
第 `i` 条流的有效指示为 `v_i ∈ {0,1}`，则原实现保留的集合是

```
keep_i = v_i ∧ ( Σ_{j ≤ i, j ∈ e} v_j ≤ L )
```

即「按因果序的有效流累积计数不超过 `L`」。向量化实现：对 `valid` 展平后
按实体分组做 `cumsum`，再与 `L` 比较。全程无 `.item()`、无 `nonzero`、无 Python 循环，
主机同步次数从 `O(片段数)` 降到 `0`。

诊断分支：`bag_policy_diagnostics` 的 `full` 与 `stratified_weighting` 两支
（`:937`、`:950`）包进 `torch.no_grad()`；`entity_score_source_row` 的
`.tolist()`（`:925`）改为只在生效支执行，或降级为聚合标量。

**省的是什么**

| 量 | 现状 | HSE |
| --- | --- | --- |
| 主机同步次数/步 | `≥ 2 ×` 片段数（`:853`、`:857`）+ `2`（`:832-833`）+ `3 ×` 实体数（`:925`） | `O(1)` |
| 损失侧建图分支 | `3` 支 | `1` 支 |
| 模型计算 | 不变 | 不变 |

**收益量级完全未知，且不可由推演给出**——单次 `cudaStreamSynchronize` 的代价
在不同驱动、不同队列深度下差两个数量级。**必须实测（待测项 T3）。**

**数值语义是否改变**

- 截断掩码：布尔量，判定方式是 `torch.equal(old_mask, new_mask)` 在真实批上为真。
  **无浮点参与，逐位相等是可达成的强断言。**
- 非生效袋处置移入 `no_grad`：生效支的前向值与反向图完全不被触及，
  数值语义不变是**结构性的**，不需要实验证明（但仍应断言三支的 `loss_value` 不变）。

**开关设计**

```json
"mechanism": { "entity_ranking": {
    "vectorized_causal_truncation": false,
    "diagnostic_policies_no_grad": false
} }
```

两个**独立**开关（它们解决的是两件不同的事，不应捆绑）。
关闭时走原代码路径。断言函数
`assert_vectorized_truncation_matches_loop`：在真实形状的随机 `valid` 上
比较两种实现的掩码 `torch.equal`。

消融：属工程维，**不进四格**。收据记录开关状态与耗时即可。

**可证伪的验证方案（判据在此冻结）**

| 项 | 内容 |
| --- | --- |
| 观测量 | `_causal_truncate_valid` 的墙钟耗时占排序阶段比例；掩码 `torch.equal` |
| 最小实验 | CPU 上按真实形状（`B=4224`, `T=128`, `E=66`, `L=8192`）跑两种实现，计时并比较掩码 |
| **支持判据** | 掩码 `torch.equal` 为真 **且** 循环版在 CPU 上的耗时 ≥ `50 ms`/次（对应 GPU 上因同步而放大的量级值得处理） |
| **证伪判据** | 循环版 CPU 耗时 < `10 ms`/次 **且** 同步次数在 GPU 上无法被证明放大 → 判为噪声级，出局 |
| 落盘 | `truncation_seconds`、`mask_bitwise_equal` |

**杀死它的那条理由**

**它可能根本不在关键路径上。** 若排序阶段的耗时被模型前向/反向完全支配
（`4M` 单位对应数百毫秒），那么哪怕主机同步有 `4224 × 2` 次、每次 `20 μs`，
也不过 `0.17` 秒——量级相当，但若实测同步只有 `2 μs`，就只有 `17 ms`，可以忽略。
**这条只能用 T3 裁决，推演给不出答案。**

**第二条杀手**：`_causal_truncate_valid` 的循环里 `remaining` 一旦耗尽就走
`truncated[row] = False` 的快路径（`:849-851`），**不再触发 `.item()`**（`:853` 在
`continue` 之后）。所以真实同步次数是「每实体前若干行」而非全部行，
可能远小于片段数。**这条使收益上界大幅下降，必须在 T3 中按真实袋分布计数。**

### 候选四 · 选择性激活重计算（SAC, Selective Activation Checkpointing）

```md
## Research Question Card

Question:
  现状对 100% 的微批套梯度检查点，代价是 1.33 倍计算量（1.2 节）。
  在给定显存预算下只对必要的微批重算，能省多少？

Type: applied

Hypothesis:
  设单微批保留激活需 a MiB、可用余量 R MiB，则可保留 k = ⌊R/a⌋ 个微批不重算，
  计算量从 4M 降到 4M − k。该候选与候选一、二**乘性叠加**：
  后者把需建图的微批数从 M 降到 m，若 m·a ≤ R 则检查点可整体弃用，
  计算量降到 M + 3m（候选一卡中「不套检查点」那一行的前提由此成立）。

Why it matters:
  单独看它的上限只有 4M/3M = 1.33 倍。
  它的真正价值是**让候选一、二的收益兑现**——否则那两者仍要付 4m 而不是 3m。
```

**形式化**

```
k ← ⌊ (显存预算 − 基线占用) / 单微批激活量 a ⌋
对 j = 1..M：
    若 j ≤ k：  logits_j ← f_θ(B_j)                    # 直接建图，保留激活
    否则：      logits_j ← checkpoint(f_θ, B_j)        # 重算
```

`a` 与基线占用**必须实测**，不得按参数量估算（待测项 T7，须在 GPU 上做，
本轮不做，只登记为待测）。

**省的是什么**

计算量 `4M → 4M − k`，加速 `4M/(4M−k)`。`k = M`（全不重算）时 `1.33` 倍，
是**硬上限**。显存则从 `O(1)` 微批升到 `O(k)` 微批——**这是与候选一、二相反方向的权衡**。

**数值语义是否改变**

- 不改变。检查点的重算若与首次前向逐位相同，则「不重算、直接用保存的激活」
  给出的梯度与之逐位相同。
- **但这个前提必须核验**：若前向段含 dropout 或其他 RNG，
  `use_reentrant=False` 的检查点会保存并恢复 RNG 状态，
  而不重算路径根本不重跑 RNG——两者仍相同。若含非确定性 kernel，则两者可能不同。
  **现状实现已经依赖「重算与首次前向一致」这一假设**（否则当前梯度就是错的），
  所以本候选不引入**新的**数值假设。这一点须在 T8 中用现有代码验证一次。

**开关设计**

```json
"mechanism": { "entity_ranking": {
    "checkpoint_microbatch_budget": -1   // -1 = 全部重算（现状）；k ≥ 0 = 前 k 个不重算
} }
```

`-1` 时走原代码路径。断言：`checkpoint_microbatch_budget = -1` 与现状
`torch.equal` 三项全真（这是**恒等**，因为是同一段代码）。

消融：工程维，随候选一、二一起报告；单独一档 `k` 扫描没有科学意义，
**只报「弃用检查点是否可行」这一二值结论**。

**可证伪的验证方案（判据在此冻结）**

| 项 | 内容 |
| --- | --- |
| 观测量 | 单微批激活量 `a`（MiB）、可用余量 `R`、`k`、排序阶段耗时 |
| 最小实验 | 需 GPU，**本轮不做**；本轮只从现有收据反解 `a`（`(30970−15175)/M`） |
| **支持判据** | 候选一或二把 `m` 降到 `m·a ≤ R` 的水平，使检查点可整体弃用 |
| **证伪判据** | 即使 `m/M ≤ 0.3`，`m·a` 仍 > `R` → 检查点不可弃用，本候选退化为纯 `1.33` 倍上限，**不足以单独成为第四章机制** |
| 落盘 | `microbatch_activation_mib`、`checkpoint_dropped`（布尔）、`peak_mib` |

**杀死它的那条理由**

**上限只有 `1.33` 倍，而参照论文第四章的量级是 `4.6` 倍。**
单独拿它做第四章的机制，工作量与效果量级都不够。
它只能作为候选一或二的**配套项**出现，不能独立立章。
**这一条不需要实验即可成立**——`4M/3M` 是算术上界，除非「反向 = 2 × 前向」
这个记法本身错了（可由 T4 校准）。

## 三、候选间关系与执行顺序

```
候选三（HSE）    ── 风险最低、语义最强、与其余三者正交
   │
候选一（ASB）    ── 实体级稀疏；C01、C11 均适用
   │  ⊂
候选二（ASR）    ── 流级稀疏；C01 收益大，C11 可能不成立（T6）
   │
候选四（SAC）    ── 使一、二的收益从 M+4m 降到 M+3m；不独立立章
```

**候选一是候选二的特例吗？** 不是。候选一按**实体**跳过整袋，候选二按**流**只保留
`k_e` 条。两者稀疏性来源不同（前者来自 CVaR 的 hinge，后者来自聚合算子），
可以叠加：叠加后建图流数为 `Σ_{e∈G} k_e`。

**执行顺序由 T3 决定，不由推演决定**：
若模型计算占排序阶段 `< 50%`，先做候选三；否则先做候选二的保形子变体。
