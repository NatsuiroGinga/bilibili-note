# 补丁格式详解

写补丁前必须先 `get-lossless-markdown.mjs` 拿到当前最新内容作基准，补丁里的每一行都要与它逐字一致。

## 格式（OpenAI apply_patch 风格）

```
*** Begin Patch
@@
 <上下文行：前缀 1 个空格，不变，用于定位>
-<删除行：前缀 -，后面紧跟要删的整行原文>
+<新增行：前缀 +，后面紧跟新的整行>
*** End Patch
```

**两个标记必须各自独占一行、顶格写**（行首不留空格，行尾不接别的内容）——服务端按整行识别补丁边界。所以正文里出现 `*** End Patch` 字样不会截断补丁（它带着 `+` 或 ` ` 前缀，不是边界行）；反过来，把标记缩进、或和别的内容写在同一行，会直接报「补丁格式非法」。

## 操作符（最容易错的地方）

每行第一个字符是操作符：

- ` `（空格）= 上下文行，内容不变，仅用于定位。**解析时会吃掉这 1 个前导空格**，所以锚一行原文有 4 空格缩进时，要写 5 个空格（1 操作符 + 4 原文）。
- `-` = 删除这一行。要删的**每一行都要单独加 `-`**，不能只给第一行加。
- `+` = 新增这一行。
- 操作符后**紧跟内容，不额外加空格**。若行内容本身以 `-` 开头（如列表项 `- 文字`），删除它要写成 `-- 文字`（第一个 `-` 是操作符、第二个是列表标记）。

## 定位：上下文锚要唯一

hunk 的「上下文行 + 删除行」在文档里必须**只匹配一处**：

- 匹配 0 处（锚点原文对不上）→ 报「未在文档中找到匹配」。核对原文、注意缩进和空格。报错会精确指出是 hunk 的第几行、第几个字符对不上，并把你的补丁行与文档实际行围绕差异并排列出（`⇥`=Tab、`␣`=行尾空格、`^` 指差异位置）——照着它指的那行、那一列改。
- 匹配多处（内容重复，如表格里多个空单元格 `<td><p></p></td>` 长得一样）→ 报「匹配到 N 处，不唯一」。**多加几行上下文**（如上一行、上方唯一的行）把位置锁死。
- 报错时按提示调整，**不要**改用 `update-document` 整篇覆盖来绕过。

**建议默认带上下文行定位**：即使要改的行看起来唯一，也默认在 `-`/`+` 前面带 1 行前置上下文（该行的上一行原文，前缀 1 个空格），一次成功率更高。若报「匹配到多处」，再把上下文加到 2–3 行。注意上下文行同样必须逐字一致——带错了反而让整个 hunk 失败，所以别过量（1–2 行通常够）。

## 常见操作示例

**改一行文字 / 表格单元格**（删旧行、加新行，用上一行做锚保证唯一）：

```
*** Begin Patch
@@
  </tr>
  <tr>
-    <td colwidth="255"><p>排名</p></td>
+    <td colwidth="255"><p>名次</p></td>
*** End Patch
```

**插入内容**（只锚定「插入点上面那一行」，在它后面全用 `+`，不要把下面的行也拉进来）：

```
*** Begin Patch
@@
 ## 二级标题
+
+这是新插入的一段文字
*** End Patch
```

> 插入段落 / 标题时，`+` 行之间要按 markdown 规则留**空行**（上例第一个 `+` 是空行），否则新内容会和上一段粘连。

**删除一行**（只有 `-`，无 `+`）：

```
*** Begin Patch
@@
-- 要删除的这个列表项
*** End Patch
```

**一次改多处**：一个补丁里放多个 `@@` hunk，每个 hunk 各自定位、各自 `-`/`+`。

## 表格编辑

无损 markdown 里表格是**多行结构**（每个 `<tr>`、每个 `<td>`/`<th>` 独占一行、带缩进），别自己拼 `| a | b |` 这种 GFM 竖线表格：

```
<table>
<colgroup>
  <col style="width: 255px;" />
  <col />
</colgroup>
<tbody>
  <tr>
    <td colwidth="255"><p>内容</p></td>
    <td><p>其它</p></td>
  </tr>
</tbody>
</table>
```

- **改单元格文字**：定位到那一行 `<td>...</td>`，删旧行加新行。若同样内容的单元格重复出现，用上方的 `<tr>` / 唯一表头单元格做上下文锚。
- **加一行**：锚定上一行 `</tr>`，`+` 一整组 `<tr>...</tr>`（缩进照现有行对齐）。
- **保留单元格原有属性**（`colwidth`、`data-attrs`、`<span style>` 颜色、`<mention>`/`<comment>` 标签等）——照抄原行、只改要改的文字部分，别删属性。

## 长文档：按章节取基准

`get-lossless-markdown.mjs` 的返回分两种模式，**看返回的模式**决定下一步：

- **返回全文**（直接打印无损 markdown）：文档不长（正文约 5 万字符以内），直接改。
- **返回目录**（打印「标题目录 + 总长度 + 提示」，即 `mode=outline`）：文档较长，服务端只给了目录以免撑爆上下文。按目录取要改的章节：

```bash
node {baseDir}/scripts/get-lossless-markdown.mjs doc_xxx --section "1.1 大盘数据"
node {baseDir}/scripts/get-lossless-markdown.mjs doc_xxx --full   # 跨多章节改动、或需通读全文
```

- `--section` 填**目录里那一项显示的标题文字**（已是纯文本，不带 `<strong>` 等标签）。照抄目录里的 text 即可，不要自己去全文找带标签的原始标题。
- **目录里出现重名标题**（「概述 / 背景 / 总结」这类）时，那几条会额外带一个 `path` 字段（形如 `一、背景 > 概述`）——**对重名标题请把 `path` 原样传给 `--section`**。直接传重名的 text 会报错并列出全部候选路径，照着其中一条重发即可，不要随便挑一个（会改错位置）。
- 标题文字里可能含 `&`、`@` 等字符——用脚本的 `--section` 参数即可（脚本会自动转义），不要手拼 URL。
- **补丁提交永远不需要章节号 / 页号 / 长度信息**——补丁靠文本锚点定位，`--section` 只是「读」时的过滤器。

## 报错处置

- **「未找到匹配」/「匹配到多处」**：定位问题，不是服务端故障。按上面「定位」一节调整锚点重试。
- **「文档在本次编辑期间被其他协作者改动」**：有真人正在同一篇文档上编辑，且改到了你补丁的锚点行上。服务端已中止本次编辑（文档未被修改），**不要原样重试**（重试用的还是同一份过期基准），应重新 `get-lossless-markdown` 拿最新内容、基于它重写补丁。注意：协作者只改了别处时，服务端会自动把补丁 rebase 到最新内容上并正常写入，你不会看到这个错误。
- **「文档中包含暂不支持的自定义元素」**：文档里有服务端 schema 未注册的自定义节点，与你改哪里无关。此时补丁编辑无法使用，请反馈给平台维护方补节点支持，不要反复重试不同锚点。任务列表 taskList/taskItem、@提及 mention、附件/视频/嵌入块、划词评论等**已支持且无损保真**，不属于此类。
