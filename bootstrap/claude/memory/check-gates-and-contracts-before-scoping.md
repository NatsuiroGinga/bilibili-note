用户 2026-08-07 要求复盘"为什么把问题想复杂"。四条可复用规则：

1. **先查上游门禁，再查资源。** 判断任务能否并行，科学依赖优先于 GPU/CPU/磁盘。上游门禁失败时下游不是"可以并行"，是"应当停止"。当时 E2-P 刚判失败，我却去规划 18 GiB 的 QUIC 采集。
2. **冻结合同优先于代码能力。** 回答"能不能这么做"要先查合同再查实现。当时我用"采集器支持续采"回答了"能不能往冻结的 v5 里追加"，而合同明令禁止。
3. **断言某能力"缺失"前，先读最贴近它的函数。** 我读了入口 `main()` 就断言"不支持续采"，实际逻辑在 `collect_connection()` 前五行。"没找到"不等于"不存在"。
4. **结论表每行必须标注证据等级。** 已核验 / 未核验 / 推测不能混排。我把自己标了"未核验"的项仍列进"阻塞缺陷"表，详尽的形式给了错误内容可信度。
5. **技能流程不得覆盖仓库规则。** 技能文本刚加载、指令性强，`AGENTS.md` 可能是上百轮前读的，容易按新近性误用技能。`subagent-driven-development` 把复核设成任务间阻塞门，而 `AGENTS.md` 要求"审查并行并标记 review_pending，非阻断审查不得延迟已满足运行条件的实验"——我按技能串行跑了三个任务才被用户点破。

6. **抄进步骤的命令必须能独立正确执行。** 我把「隔离 CMake 在 `.tools/ns3-cmake-3.25.2/`」正确抄进了计划的 Global Constraints，却在两百行外的可执行步骤里只写了 `env USER=ns3builder ./ns3 build`，漏掉 CMake 路径，然后照那步跑，编译因系统 cmake 3.22.1 < 3.25 失败。**执行任何步骤前，回头对一遍 Global Constraints**——技能文本自己就写着每个任务的要求隐含包含该节。

**Why:** 六条都不是知识不足，是**手里有管辖文本却没去应用**——同一根因在一次会话里出现四次（上游门禁、冻结合同、复核并行、约束抄漏）。

**How to apply:** 接到任务先问三句：上游门禁过了吗？合同怎么规定？决定性代码在哪个函数？三问答完再定范围。**调用任何技能前，先检查它的流程有没有和 `AGENTS.md` 冲突的地方，冲突处以仓库规则为准并明说改了哪里。** 相关：[[record-fixed-bugs-into-rules]]
