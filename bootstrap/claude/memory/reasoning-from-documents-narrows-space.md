## 两个共同点

**① 理由的来源决定了判断的可靠性。** 站得住的全来自实测或带控件的诊断；翻车全来自推演。这正是仓库「**实验先于推演**」条款的镜像——**我一直用它约束实验，却没用它约束判断**。于是实验是实测的、判断是推演的。

**② 我的判断几乎总是收窄空间。** 占用→砍方向；协议锁死→砍方向；外部性→砍方向。每条"严谨"的理由都在**提前关门**。而结果是：被占用砍掉的双预算方向，最后是被**实验**否决的（结论碰巧对，理由错）；被"协议锁死"砍掉的 RL 方向**根本不该砍**。

## 机制性修正（不靠记性）

1. 家族／候选比较表**禁设"是否被占"列**；占用信息只进引用与划界清单（见 [[occupancy-is-not-a-disqualifier]]）。
2. 任何「做不到／没有自由度／不可能」的断言，**必须先写明**：这是协议、数据、资源的要求，还是**我们当前的选择**？属后者的一律附「改它的代价」。
3. **排序前先查障碍**：每条候选先写"已知障碍"再排序，不得排完再查。
4. 引用「本课题已否决」时必须标明是**同一形式**还是**同族不同形**（仓库早有「被否决实现的读数隔离」条款，但那条只管读数、不管存废）。

## 补充形态（2026-10-15，同日第三、四次）：**用摘要表代替读原文**

用户问「GroupDRO 有没有最新的文献可以拿来参考」，我自查发现：

- **库里早就有 2023／2024／2026 的 DRO 新形态**（`2023-Aigner-Data-Driven-DRO-over-Time`、`2024-Lin-TDRO`、`2026-Asness-Exponential-Smoothing-CVaR`），**全是本地全文，我一篇都没打开**，却在家族比较里写「锚点是老的 2019–2020」。
- **更严重**：我提议的第四章方向（按年度分组的不变/最坏组训练用于 Android 恶意软件漂移）**最近的先行工作 `2025-Zheng-TIF` 就在库里、有逐页核验的全文笔记**（IEEE TSE，arXiv 2502.05098，AndroZoo + Drebin 特征，按观测日期切时间环境 + IRMv1）。**我用 `families.md` 摘要里的「TIF 2026 占大半」一句话，把它当作家族排序的理由——没有打开那篇论文。**

6. 家族排序前，先 `fd` 扫一遍 `raw/papers` 与 `wiki/papers` 的**实际年份分布**，用实测分布说话，不用摘要里的措辞。
