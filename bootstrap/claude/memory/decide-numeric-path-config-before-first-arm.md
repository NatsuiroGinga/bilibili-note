启动一组要互相比较的实验臂（消融四格、基线对照、多候选）之前，**先把所有会改变数值路径的运行配置一次性定死**：`torch.compile`、TF32、混合精度 profile、算子实现（SDPA vs 手写注意力）、随机性设置。这些不是"以后有空再调的优化"，它们和数据、超参一样属于比较集的公共合同。

**Why:** 2026-08-28 第三章四格实验。C00 启动前我提到过 `torch.compile`，但判断为"要改代码、风险大于收益，先不做"，打算事后再评估。C00 跑完（81 分钟）后实测：`torch.compile` 训练步提速 **1.316×**，但与 eager **非逐位等价**（最大绝对差 `8.94e-07`）。于是陷入两难——给后续臂启用会让编译臂与 C00 的训练轨迹自第一步分叉，单种子下无法区分机制效应与轨迹噪声；不启用则每臂多花约 20 分钟。**若一开始就在 C00 上启用，四格全用同一路径，四臂共省约 80 分钟。** 事后追加的唯一合法路径是重跑全部已完成臂，成本恒大于收益。

**How to apply:** 派发第一个臂之前列一张「数值路径配置清单」并冻结进配置文件与实施计划，清单至少含：编译开关与模式、TF32、精度 profile、注意力实现、确定性设置。每项标注"已定/不用"及理由，不留"待评估"。**微批大小与梯度累积不在此列**（它们只改运行开销，数学等价，可随时调整）——区分标准是「会不会改变浮点运算的顺序或精度」。评估某项优化时先问"它改不改数值"，改则必须在第一个臂前决定；顺带一提，验证是否逐位等价用 `torch.equal` 而非 `allclose`。相关：[[falsify-directions-with-experiments-not-speculation]]、[[check-gates-and-contracts-before-scoping]]
