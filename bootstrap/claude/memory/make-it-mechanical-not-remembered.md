在这个项目里，凡是靠"我记得做"的事情，最终都会漏掉。发现自己在说"等 X 完成我再做 Y"
或"记得回传/记得更新/记得标注"的时候，立刻停下来，把 Y 变成程序动作。

**Why:** 2026-08-29 一天内漏了四件事，全是同一个结构。C00 训完只把「最佳轮 = 第 17 轮」
抄进文档、漏了实体 AP 数值本身，服务器关机后取不回来。C10 被记成「第 3/20 轮」，
实际关机前已跑到第 15 轮——记的是我最后一次看日志的瞬间，不是运行收据。
四格制品在服务器上躺了两天没有本机副本，而全量只有 130 MiB，规则本就写明
「服务器不得保存唯一结果副本」。派子代理忘了标模型档位，尽管记忆里有这条。
用户的评价是准确的：「你是不是没有遵守规则」「记忆写了你一点不看」。

**How to apply:** 三种可用的机械化手段，按场景选：
关键读数 → 写脚本从运行收据自动提取并落盘到固定路径，接进启动器的每个阶段边界
（本项目是 `ch3_ft_emit_four_cell_summary.py` 接进四格守护脚本）。
周期性动作 → 后台守护进程，别用 cron（会往会话里塞 prompt 打断用户），
用 `nohup bash ... &` 加轮次上界和完成即退出（本项目是 `watch_and_pull_ch3_ft.sh`）。
跨会话的待办 → `spawn_task` 开成 chip，用户一键可起，不占当前上下文。
判断标准很简单：如果这件事漏了会损失证据或要重跑，它就不该由记性负责。
与 [[syntax-check-is-not-execution]] 配套——机械化的脚本本身也必须真跑过才算数。
