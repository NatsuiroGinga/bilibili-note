用户 2026-09-03：「几件压着的决定，能不能通过文献和实验方式来确定，**实在不行才通过我来决定**。」

**Why**：把能自己查、自己测的问题攒成「待用户裁决」清单，等于把工作推回给用户。
当天实测：三件「待裁决」里两件本就有答案——多指标选轮的文献已查完（11 篇中 0 篇支持
「三口径三模型」），埋点方案的设计文档自己就写着「成本须用一步 probe_runtime 实测后再确认，
**不凭本文估计**」。只有「旧四格在论文里怎么保留」这类写作判断才真正需要用户。

**How to apply**：
- 列出任何「待裁决」之前先自问三步：**能不能测？能不能查文献？设计文档里是不是已经写了怎么定？**
  三个都否，才上呈。
- 上呈时说明**为什么不能自己解决**，而不是只列问题。
- 实测型裁决必须**先冻结判据再测**，看到数字后不得改判据。
- 归类：可实验的（量级比、开销、偏差）→ 派实测；可查证的（惯例、先例、原文设定）→ 派文献；
  纯取舍的（正文怎么写、旧结果怎么标注、要不要入库某篇）→ 才交用户。

同源教训 [[falsify-directions-with-experiments-not-speculation]]（用实验反驳方向）与
[[consult-sources-before-asserting]]（不确定先查原件）——那两条管「别空想」，
这条管「别把能自己办的事推给用户」。
