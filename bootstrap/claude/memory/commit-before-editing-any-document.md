**修改任何文档之前先提交，让 `HEAD` 成为可回退的改前快照。** 用户 2026-08-19 明确重申。

**Why:** 仓库 `AGENTS.md` 已有这条强制规则，但它只写了「目标文档有未提交变更就先提交这些目标文档」。实际会话里真正咬人的是**没被点名的那部分**：

**会话开始前就存在的未提交改动。** 2026-08-19 会话里，工作树一直带着 **20 个已跟踪文件**的改动，全部来自本会话之前——图件重绘（`Heiti SC → SimHei`）、绘图脚本重写 2,309 行、恢复卡 117 行、`wiki/` 索引、以及 Hook 自动维护的 `output/` 时间戳。这些文件里有几个正好是后续要动的（恢复卡、绘图脚本）。**只要动其中任何一个又不先提交，就会把别人的、或更早会话的未提交工作夹带进自己的提交**，事后无法分辨谁改的，也无法只回退自己那部分。

**How to apply:**

1. 动手前跑 `git status --short --untracked-files=no`，看的是**整棵树的已跟踪改动**，不只是目标文件。
2. 树干净 → `HEAD` 已是快照，**不要建空提交**。
3. 树不干净 → **按目录或主题分批提交**（正文一批、图件一批、过程文档一批），每批提交前先看 `git diff --stat` 确认改动认得出来，不盲提。
4. **未跟踪文件不同批处理**：并行代理产出、下载的原件、实验制品常有上百个，逐批审过再收，不能 `git add -A`。
5. 有后台代理在跑时，「干净」是会变的。Hook 维护的文件（如 `output/` 的触发时间戳）也会自己变。检查与编辑要挨着做，不要中间隔很多轮工具调用。

提交信息按约定式提交，描述用英文动词开头小写不加句号，正文用中文说清背景；**末尾不加任何 `Co-Authored-By`**。相关：[[keep-handoff-doc-in-sync]]、[[annotate-model-effort-on-every-dispatch]]。
