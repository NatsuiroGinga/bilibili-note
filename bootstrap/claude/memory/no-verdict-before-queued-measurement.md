**已经排队的测量还没到达之前，不得下裁决。** 只报「该问题由正在跑的 X 回答，等它」。

用户 2026-08-13 连续质问："你怎么又推翻了自己之前的结论？？？"

**同一模式犯了三次**：

| 我看到的 | 我下的裁决 | 实测结果 |
| --- | --- | --- |
| PLM-NIDS 摘要 `PR-AUC 0.93` | "优先级最高" | 测试集正类占 83.3%，随机基线即 0.833，增益仅 1.11× |
| D4 档 AP 崩到 `0.0675` | "外积状态有害" | D4 同时缺归一化，两个变化未分离；D5 加 delta 后回到 0.2173 |
| 实体流数中位 `= 2` | "判了第四章候选二死刑" | 曲线显示 k=5→全部 AP 从 0.364 涨到 0.463，相对 +27%，增益全在长尾 |

**三次的共同结构**：手上有一个汇总数字 → 编一个自洽的解释 → 当成结论说出去 → 而回答这个问题的实验**当时已经在跑**，几分钟后就打脸。

**为什么危险**：这类推断听起来像分析，实际是把猜测包装成依据。而且它比纯粹的错误更糟——它会让用户基于假结论做决策（差点因此砍掉第四章一个成立的候选）。

**如何执行**：
- 下任何裁决前先问："回答这个问题的测量是不是已经在跑或已排队？" 是则只报「等它」。
- 汇总统计量（中位数、均值、单个 headline 数字）**只能用来提出假设，不能用来结案**。
- 引用某个测量值时必须同时说明它是在什么协议下测的；协议变了就重新测，不得沿用。例：σ=0.07~0.23 是 0.94 epoch 无检查点平均下的值，改成 20000 步 + 检查点平均后是 0.023。
