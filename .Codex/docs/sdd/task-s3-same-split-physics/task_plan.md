# S3 同分区物理评估计划

## 目标

加载已冻结的 S3 检测适配器与状态头，在 E1/E2 使用的同一 seed44 测试集上完成只读物理评估，并据此重算 S3 与 E2 种子 42、43、44 的物理比较。

## 阶段

- [x] 阶段一：确认跨分区比较根因与现有同分区制品边界。
- [x] 阶段二：审计现有模型加载、状态掩码与物理评估接口。
- [x] 阶段三：实现 S3 固定测试评估入口并同步服务器。
- [ ] 阶段四：在 RTX 5090 上运行 S3 三种状态掩码的 807 条测试评估。
- [ ] 阶段五：重算 S3 与 E2 三随机种子比较并核验输入哈希。
- [ ] 阶段六：回收制品，更新两份恢复文档与最终报告。

## 固定协议

- S3 训练目录：`runs/physics-sparse/qwen3-1.7b-seed42-s3-anchor0-plus-one-fullphys202-v1/`。
- 测试数据：`runs/ns3-data/ns3-queue-sequences-h4-seed-split-20260721-v2/test.jsonl`。
- 测试数据必须为 807 条，`split_seed=44`，SHA-256 必须为 `6e64d2ab290813a246ed8efcefd1bb19f1026c2de7b7904d111af67b4465ef94`。
- 状态监督模式固定为 `anchor0_plus_one`，分别使用状态掩码种子 42、43、44。
- 批量大小固定为 8，不训练、不校准、不调参、不修改模型权重。
- E2 已有检测预测和配对自助统计保持不变，只替换跨分区物理参照。

## 关键问题

1. S3 状态头能否在同一测试集、同一状态掩码下被现有评估函数直接加载？
2. 三个 E2 种子的物理比较是否均满足原预注册改善门槛？
3. 同分区结果是否足以恢复或否决此前暂缓的 S3→E2 物理结论？

## 已确认根因

- 既有 S3 比较读取训练目录 `training_summary.json` 中的 validation 指标。
- E2 比较读取 `physics_test_summary.json` 中的 seed44 test 指标。
- 两者数据分区不同，因此原 S3→E2 物理改善百分比不可采用。
- E1→E2 已是同分区比较，结果不受本次修正影响。

## 实现决策

- 复用 `bounded_physics_evaluation._load_frozen_evaluation_model` 加载冻结的 4 位 Qwen、S3 LoRA 与 S3 状态头。
- 复用 `representation_train._evaluate_physics` 执行只读状态与队列残差计算，避免复制物理公式。
- 单次加载模型后依次评估掩码种子 42、43、44；每个掩码独立保存摘要、逐样本预测和分析兼容视图。
- 使用既有 `s3_s4_detection_analysis` 重算比较，只替换 S3 物理参照，不改变已冻结检测预测。

- 首次创建计划时父目录不存在；创建目录后重新写入，未影响实验代码或数据。
