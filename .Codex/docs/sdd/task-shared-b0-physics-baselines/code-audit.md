# shared B0 物理基线代码审计

## 1. 审计结论

- 审计对象：`state-supervision-only Qwen` 与 `standard PINN Qwen` 两条 shared B0 基线。
- 当前状态：`ready_for_planning=true`，`ready_for_training=false`。
- 两条基线可以共用普通 shared B0 Qwen 的分类训练清单、训练顺序和公开检测评估集。
- 当前发布的 `physics/ns3_candidate.jsonl` 不能直接驱动物理训练。它缺少分组、逐窗容量、共享归一化尺度等训练必需字段，需要新增不可变物理旁路清单。
- 历史 `physics_train.py` 可提供状态头、掩码、残差公式和梯度接口，但不能直接作为正式训练器。它的提示词字段、有效批量、优化器、调度器、采样、检查点和恢复语义均不符合 shared B0 公平性要求。
- 两条基线必须固定相同的有效生成批量 `4`、相同的 200 个优化步、相同的 LoRA、优化器、调度器、生成样本顺序、物理样本顺序和状态头初始化。`standard PINN Qwen` 唯一允许增加的训练项是固定权重的物理残差损失。
- 2421 条 ns-3 shared B0 候选样本已经全部进入统一训练清单，不能再将旧的 `807/807/807` 划分描述为未见测试集。当前只能报告训练拟合物理诊断；最终物理泛化结论需要新生成、与训练配置不相交的外部场景。

## 3. shared B0 数据与训练清单

### 3.1 统一分类视图

`configs/shared_b0_view_v1.yaml` 固定了 8 个共同观测字段：

1. `duration_s`
2. `total_packets`
3. `total_bytes`
4. `mean_packet_size`
5. `packet_rate`
6. `byte_rate`
7. `src_port`
8. `dst_port`

候选训练清单总计 10,000 条：

- GeNIS：3973 条。
- TQH：3606 条。
- ns-3：2421 条。

正式发布目录为 `runs/data-frozen/dataset-v1-shared-b0/`。Qwen 分类训练入口为 `candidate/qwen_train.jsonl`。这 10,000 条记录构成两条物理基线与普通 Qwen B0 的共同分类预算，不允许为物理基线额外复制或过采样 ns-3 记录。

### 3.2 Qwen B0 训练协议

`configs/shared_b0_qwen_seed42_200.yaml` 固定了以下关键超参数：

- 基座：`Qwen3-1.7B`。
- `seed=42`。
- `max_input_length=512`。
- `max_new_tokens=16`。
- LoRA：`r=16`、`alpha=32`、`dropout=0.05`。
- 学习率：`0.0002`。
- 每设备训练批量：`2`。
- 梯度累积：`2`。
- 科学有效生成批量：`4`。
- `max_steps=200`。
- `save_steps=20`。
- 恢复策略：`auto`。

由此可得：

- 每条基线固定 200 个优化步。
- 每条基线固定 400 个微步。
- 每条基线消费 800 个生成训练样本位置。
- 若显存要求改变，只允许将硬件形状从 `2 x 2` 改为 `1 x 4`；科学有效批量仍必须为 `4`，并且两条基线必须相同。

### 3.3 当前物理发布视图不足

`src/flow_probe/shared_b0_view.py` 当前物理记录只保留：

- `sample_id`
- `stable_order`
- 单一聚合后的 `model_input`
- `target`
- `state_supervision`
- 原始五锚点
- `normalized_physics`

当前发布物理记录缺少：

- `group_id`
- 原始审计划分
- 每个锚点的容量序列
- 每个锚点的接收字节和接收包数
- 出队、丢包等残差所需流量项
- 共享归一化尺度
- 面向训练的明确用途标记

此外，发布器只生成一个 `physics/ns3_candidate.jsonl`，没有符合当前任务语义的训练旁路清单，也没有可用于外部物理泛化的未见场景清单。

结论：同一 `candidate/qwen_train.jsonl` 可以继续作为分类训练清单；物理监督必须通过 `sample_id` 连接到独立、不可变、可审计的旁路清单，不能把额外物理字段重新写入 Qwen 提示词。

## 4. 可复用实现

### 4.1 `src/flow_probe/physics_train.py`

可复用的纯计算组件：

- `ContinuousQueueStateHead`：从 Qwen 最后有效令牌隐藏状态预测连续队列状态。
- `build_state_supervision_masks`：构建锚点监督掩码。
- 掩码状态均方误差的实现思路。
- `queue_balance_residual`：计算可微队列平衡残差。
- M1 状态监督与 M2 状态加物理损失的变体分支结构。
- Qwen 与状态头的联合反向传播路径。

不得直接复用的训练协议：

- 旧 `MODEL_INPUT_FIELDS` 将容量、接收流量等物理字段放入模型提示词，违反当前共同观测协议。
- `prepare_state_record` 依赖旧的复数 `model_inputs` 与 `group_id`，无法读取当前发布物理记录。
- 旧训练器强制有效生成批量 `16`，与普通 shared B0 Qwen 的有效批量 `4` 不一致。
- 旧训练器使用自定义循环和 `torch.optim.AdamW`，没有复用普通 Qwen 的 `SFTTrainer`、`paged_adamw_8bit` 和学习率调度语义。
- 旧训练器没有每 20 步检查点、自动恢复、训练绑定和完整运行状态。
- 旧训练器只保存最终适配器与状态头，不满足正式运行的中断恢复和审计要求。

### 4.2 `src/flow_probe/qwen_physics_gradient.py`

## 5. 两条基线的严格差异

### 5.1 共同部分

两条基线必须完全相同：

- Qwen 基座、量化、LoRA 和随机种子。
- 8 字段 shared B0 提示词。
- 10,000 条分类训练清单及其哈希。
- 200 个优化步、400 个微步和有效生成批量 `4`。
- 优化器、学习率、调度器、梯度裁剪和保存频率。
- 生成训练样本顺序及其持久化哈希。
- 2421 条物理样本的顺序、批次边界和持久化哈希。
- `ContinuousQueueStateHead` 结构与初始化。
- 状态监督掩码：`anchor0_plus_one`。
- `lambda_state=1.0`。
- 公开检测评估配置和批量推理协议。

### 5.2 `state-supervision-only Qwen`

总损失：

```text
L = L_generation + 1.0 * L_state
```

强制限制：

- 不计算物理残差。
- 不读取容量、出队、丢包或其他残差专属字段。
- 运行绑定必须记录 `lambda_physics=0` 和禁用残差分支。

### 5.3 `standard PINN Qwen`

总损失：

```text
L = L_generation + 1.0 * L_state + 0.01 * L_physics
```

强制限制：

- `lambda_physics=0.01` 固定，不做权重扫描。
- 物理残差使用状态头预测的五锚点队列状态计算，保持到 LoRA 和状态头的梯度路径。
- 容量、出队、丢包等系数只进入损失侧，不能进入 Qwen 提示词。
- 除物理残差项外，不允许改变任何训练预算或超参数。

## 6. 物理样本调度与损失归约

2421 条物理样本需要在 400 个微步内各消费一次。建议冻结以下确定性调度：

- 21 个微步各取 7 条。
- 379 个微步各取 6 条。
- 总数：`21 * 7 + 379 * 6 = 2421`。
- 顺序由固定种子和稳定标识生成，并将完整顺序、批次边界和哈希写入运行目录。
- 两条基线必须使用完全相同的调度文件。

由于物理批量为 6 或 7，若直接对每个微步的批均值等权，单样本权重会略有差异。实现必须固定一种逐样本等权归约，例如将微步批均值乘以：

```text
actual_physics_batch_size / (2421 / 400)
```

对应测试必须证明：

- 所有 2421 条样本恰好出现一次。
- 没有重复、遗漏或跨基线顺序差异。
- 批次大小变化不会引入隐式样本权重差异。

## 7. 泄漏与公平性风险

### P0：提示词泄漏

旧物理训练器会把容量和接收流量等字段序列化进提示词。若继续使用，物理基线将比普通 Qwen 获得额外输入，公开检测对比失效。

控制措施：Qwen 前向只能读取 `candidate/qwen_train.jsonl` 中已经发布的 shared B0 提示词；物理旁路清单只能在损失侧按 `sample_id` 连接。

### P0：有效批量不一致

旧物理训练器有效批量为 `16`，普通 Qwen 为 `4`。这会改变优化噪声、调度和样本消费预算。

控制措施：两条物理基线强制有效生成批量 `4`，默认 `2 x 2`，显存不足时仅允许 `1 x 4`。

### P0：ns-3 测试集误称

2421 条 ns-3 候选样本已全部进入分类训练清单。旧 `807/807/807` 或历史校准、未见配置、越界集合均不能自动成为本次未见物理测试证据。

控制措施：当前物理输出标记为 `train_fit_diagnostic`；最终物理测试需另行生成并冻结不相交的配置、哑铃拓扑或停车场场景。

### P1：分类与物理顺序未绑定

若状态分支重新构造提示词或按行号连接，会出现截断差异、排序漂移和错配。

控制措施：保留 `sample_id`，按键连接，预检集合相等性和唯一性，并持久化两种顺序哈希。

### P1：训练器协议漂移

直接沿用旧自定义循环会改变优化器、调度器、检查点和恢复语义。

控制措施：从 `train_sft.py` 提取公共构建路径，并以普通 Qwen 回归测试作为合入门禁。

### P1：断点恢复不确定

若只恢复 Qwen 检查点而不恢复状态头、物理调度游标和随机数状态，恢复运行不再等价于连续运行。

控制措施：检查点必须原子保存适配器、状态头、优化器、调度器、生成游标、物理游标、随机数状态、配置哈希和数据哈希。

## 8. 历史物理数据的用途边界

历史目录 `runs/ns3-data/ns3-observability-sequences-h4-20260722-v1/` 共 24,570 条，包含：

- `train`：14,040 条。
- `calibration`：3510 条。
- `unseen_configuration`：3510 条。
- `out_of_range`：3510 条。

这些集合可以为数据结构、残差实现和开发期诊断提供参考，但存在两个限制：

- 它们已经用于历史任务，不能无条件声明为全局未见测试集。
- 它们没有与当前 shared B0 分类清单建立冻结绑定。

因此，本任务不得默认把它们纳入正式结论。若后续使用，必须由独立协议说明其历史暴露情况和仅限开发诊断的用途。

## 9. 同一 shared B0 清单是否阻塞

### 不阻塞的部分

- 两条基线可以使用同一个 `candidate/qwen_train.jsonl`。
- 两条基线可以使用同一 GeNIS 验证集。
- 两条基线可以使用同一 GeNIS 与 TQH-C2 公开检测评估集。
- 两条基线可以复用普通 Qwen 的 200 步分类预算和评估口径。

### 当前阻塞的部分

- 缺少可审计的 shared B0 物理旁路清单。
- 缺少普通 Qwen 与物理基线共用训练器路径的行为等价证明。
- 缺少有效批量 `4`、共同生成顺序和共同物理调度的强制门禁。
- 缺少状态头、优化器、调度器和双游标的完整检查点恢复。
- 缺少训练拟合诊断与外部物理测试的用途隔离。

结论：分类清单本身不阻塞；直接启动训练被工程门禁阻塞。外部未见物理数据缺失不必阻止完成训练和公开检测评估，但会阻止任何物理泛化结论。
