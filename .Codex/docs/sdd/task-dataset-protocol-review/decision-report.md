# GeNIS、TQH-C2 与 ns-3 统一数据和基线协议决策报告

## 决策状态

**文献层协议冻结为 `data-protocol-v1.0-rc1`。** 文献裁决已经完成；在生成首个训练样本前，还必须通过本报告末尾的 P0 物化验收。P0 只核验身份、字段、标签和边界，不运行模型，也不得依据最终测试表现修改协议。全部门禁通过并记录制品哈希后，才升格为正式 `data-protocol-v1.0`。

本协议只使用三类来源：GeNIS 2025、TQH-C2 2026 与 ns-3。**不增加第四个数据集。**

## 一、三类数据的固定角色

| 来源        | 主角色                                           | 可提供                                              | 不得宣称                                               |
| ----------- | ------------------------------------------------ | --------------------------------------------------- | ------------------------------------------------------ |
| GeNIS 2025  | 公开恶意流量的家族、子类型、时间前向和开放集评价 | 原始 PCAPNG、攻击步骤、场景、时间、分层标签         | 官方随机留出等于跨会话或跨运行泛化；流统计等于队列真值 |
| TQH-C2 2026 | 加密 C2、留一加密配置、间隔/抖动敏感性评价       | 36 个独立 cell、PCAP、Zeek `uid`、标签、UTC 清单    | 不同 cell 的行可随机混合；`unknown` 等于未知攻击       |
| ns-3        | 队列状态、物理系数、残差和跨拓扑机制评价         | 完整仿真状态、场景配置、随机种子、拓扑与包/队列轨迹 | 仿真物理指标等于真实 PCAP 检测外部效度                 |

## 二、先建主清单，再建模型视图

### 2.1 主记录层级

固定四层实体：

1. `source_artifact`：具有内容哈希的原始 PCAP、标签归档或 ns-3 运行制品。
2. `allocation_group`：训练、验证、测试不可拆分的最外层实体。
3. `parent_session`：双向流、连接或仿真运行内的序列父实体。
4. `sample`：由父实体确定性派生的完整流或包序列窗口。

窗口、突发、截断、填充、增强和模型序列化都只能发生在 `allocation_group` 已冻结之后。任何派生样本必须继承父组 `split_id`。

### 2.2 `sample_id` 契约

使用规范 JSON 的 SHA-256：

```text
sample_id = sha256(canonical_json({
  "dataset_id": dataset_id,
  "dataset_version": dataset_version,
  "source_capture_sha256": source_capture_sha256,
  "extractor_contract_sha256": extractor_contract_sha256,
  "parent_session_id": parent_session_id,
  "window_start_ns": window_start_ns,
  "window_end_ns": window_end_ns,
  "window_ordinal": window_ordinal
}))
```

规范 JSON 必须使用 UTF-8、键名升序、整数纳秒、无多余空白。`sample_id` **不包含**标签、`split_id`、模型名或训练种子，因此标签修订和模型视图不会改变样本身份。另生成包含标签和分区的 `record_sha256`，用于检测清单被修改。

### 2.3 主清单必填字段

| 类别 | 字段                                                                                                                      |
| ---- | ------------------------------------------------------------------------------------------------------------------------- |
| 身份 | `sample_id`、`dataset_id`、`dataset_version`、`source_artifact_id`、`source_capture_sha256`、`extractor_contract_sha256`  |
| 层级 | `allocation_group_id`、`parent_session_id`、`capture_group_id`、`time_block_id`、`scenario_group_id`、`topology_group_id` |
| 范围 | `sample_unit`、`window_start_ns`、`window_end_ns`、`window_ordinal`、`packet_count_raw`、`packet_count_kept`              |
| 标签 | `native_label`、`binary_label`、`family_label`、`subtype_label`、`label_status`、`unknown_role`、`label_schema_version`   |
| 边界 | `split_id`、`suite_id`、`fold_id`、`domain_role`、`split_protocol_version`                                                |
| 审计 | `exclusion_reason`、`join_status`、`field_mask`、`record_sha256`                                                          |

## 三、不可拆分分组键

### 3.1 GeNIS

分组优先级从强到弱为：

1. 原始 PCAPNG 内容哈希与独立捕获/攻击运行；
2. 场景编号与攻击步骤；
3. 规范主机对；
4. 双向五元组流谱系与重叠时间范围。

正式家族、时间前向与开放集套件的 `allocation_group_id` 至少包含“原始捕获 × 攻击步骤”。同一 PCAP 派生的 5、10、30、60 秒版本必须映射到同一父组；**首轮正式协议只选择一个流时间间隔或从 PCAP 统一重提取，禁止把四种版本当作四份独立数据。**

GeNIS 每个子类型的独立攻击运行可能不足。由此作出两个明确限定：

- 家族级、时间前向与子类型开放集可以作为主要泛化结果。
- 若同一已知子类型只有一个独立运行，则该子类型的 8:1:1 会话级闭集结果只能标为“同捕获内部诊断”，不得表述为跨运行泛化。

### 3.2 TQH-C2

`allocation_group_id = dataset_version | profile | interval | jitter | capture_sha256`。整个 cell/capture 不可拆分。Zeek `uid` 是标签连接与父会话键，不是模型输入。

QUIC 配置会把多个信标复用在长寿命 UDP 流中。若对长流生成多个窗口，所有窗口必须同时继承相同 `uid` 和 cell 边界。不得用逐信标或逐包随机划分放大独立样本数。

### 3.3 ns-3

`allocation_group_id = scenario_contract_sha256 | topology_id | seed | run | source_destination_set`。同一次运行的所有窗口、流和队列轨迹不可跨边界。域随机化参数属于该运行的上下文，不得按窗口重新抽样后跨边界。

星型、哑铃与停车场拓扑分别形成 `topology_group_id`；外部拓扑在模型选择阶段完全不可见。

## 四、PCAP 到流、突发和包序列的确定性处理

### 4.1 处理顺序

1. 核验数据版本、归档哈希、PCAP 哈希与标签文件哈希。
2. 将时间统一为 UTC 纳秒；保留原始时间字段供审计。
3. 先建立捕获/cell/运行父组，再连接标签。
4. 以端点规范排序构造双向会话，保留每包有符号方向。
5. TQH-C2 使用官方 `uid` 连接标签；GeNIS 使用真值、FlowID 和时间范围复核；无法唯一连接的样本隔离，不猜标签。
6. 切分 `allocation_group`，冻结 `split_id`。
7. 仅在各边界内部生成完整流、突发、包序列窗口和统计视图。
8. 只用训练清单确定截断长度、缩放器、缺失值规则、类别权重和词表/模板参数。
9. 验证和测试只应用已冻结转换；最终测试不删类、不均衡、不重新采样。

### 4.2 共同检测观测

所有检测模型只能从以下原始语义派生输入：

| 字段                   | 规范                                                  |
| ---------------------- | ----------------------------------------------------- |
| `direction`            | 按规范端点顺序记为 `-1/+1`，首包方向不重新编码身份    |
| `network_length_bytes` | IP 网络层报文长度；不含以太网头，三源统一单位为字节   |
| `payload_length_bytes` | 可从公开头部确定时记录，否则置缺失并带掩码            |
| `delta_time_us`        | 相对前一保留报文的非负微秒间隔；首包为 0 并带首包掩码 |
| `transport_family`     | 有限枚举 `TCP/UDP/ICMP/OTHER`；所有模型相同           |
| `tcp_flags`            | 仅 TCP 可见标准标志，多热编码并带协议掩码             |
| `burst_id`             | 同一方向连续包的确定性分段编号                        |
| `observation_mask`     | 缺失、填充、截断与协议不适用掩码                      |

允许由这些字段确定性派生包数、双向字节、包长分位数、相对时间分位数、突发包数/字节/持续时间、活动/空闲比和序列位置。派生统计不引入新原始信息。

### 4.3 禁止进入共同检测输入的字段

- 源/目的 IP、MAC、绝对端口、文件路径、捕获名、cell 名、数据集名和拓扑名；
- 绝对时间、采集日期、攻击脚本阶段、标签与标签连接键；
- TCP 初始序列号、确认号、绝对 TCP 时间戳等隐式流身份；
- 原始载荷字节、加密内容和数据集私有指纹；
- ns-3 队列占用、容量、到达率真值、残差、攻击强度配置等物理监督列。

保留 `transport_family` 是有意裁决，因为它是部署时可观察语义；另做一个所有模型共享的“去协议枚举”消融，用于判断 TQH-C2 跨配置结果是否只依赖 TCP/UDP 区别。

### 4.4 过滤与长序列

- 只保留能统一解释的 IP 层 TCP、UDP、ICMP；ARP、链路层广播和损坏包记录排除原因及数量。
- 不因包长、流长或类别样本少而从最终测试删除样本。
- 长父流按固定最大包数生成窗口；最大包数与步长只根据训练分布和预注册算力上限确定一次，随后对所有模型和全部边界冻结。
- 重叠窗口允许存在，但必须共享父组，且跨边界近重复检查必须为零。

## 五、标签与未知类契约

### 5.1 统一层级

每条记录保留 `native_label`，再映射为：

```text
binary_label  -> benign / malicious
family_label  -> 数据源内可验证攻击家族
subtype_label -> 数据源内原生细粒度类型
label_status  -> mapped / auxiliary / unresolved / excluded
unknown_role  -> known / u_val / u_test / not_applicable
```

任何无法证明等价的标签都不得靠名称相似强行映射。

### 5.2 数据源映射

| 来源   | 主任务映射                                                                                                                                                                                                             |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GeNIS  | `BinaryLabel`、`CategoryLabel`、`SubCategoryLabel` 原样保留并做别名规范；三层均可评价。                                                                                                                                |
| TQH-C2 | `malicious_c2` 为主任务正类；`benign` 与 `benign_external` 为负类；`malicious_lateral`、`malicious_recon` 标为 `auxiliary`，单独报告或排除主任务；源数据 `unknown` 标为 `unresolved`，不作为良性，也不冒充开放集攻击。 |
| ns-3   | 检测标签只来自预注册场景语义；队列状态和物理系数属于监督目标，不属于 family/subtype。                                                                                                                                  |

标签连接率、各状态数量和排除比例必须在任何训练前公布。TQH-C2 README 顶部为 1.0.1，而引用块仍写 1.0.0；实验必须记录实际归档版本 1.0.1、归档哈希和修订说明。

### 5.3 开放集

GeNIS 开放集采用两套互斥未知集合：

- `U_val`：只用于在验证阶段选择未知阈值、温度或拒识规则。
- `U_test`：最终未知子类型，从训练和验证完全删除，且与 `U_val` 不相交。

`K_train`、`U_val`、`U_test` 必须按**原生子类型和父捕获组**冻结，而不是按表格行抽样。具体子类型名单只能从训练前标签/独立组数量审计生成，选择规则为“满足最低独立组数后按稳定标签名哈希”，不得依据任何模型表现选择。若没有足够独立组，则缩小开放集层级，不拆分同一攻击运行伪造未知。

## 六、训练、验证、测试与域外套件

### 6.1 通用 8:1:1 规则

8:1:1 是**样本数量目标，不是拆组命令**。分配算法以完整 `allocation_group` 为单位，目标函数最小化样本量与 80%/10%/10% 的偏差，并受以下硬约束：

1. 同一父捕获、cell、运行和重叠谱系只出现一次；
2. 先冻结最终测试，再从其余训练域产生验证；
3. 不为类别比例拆组；
4. 相同比例目标的并列方案用 `sha256(protocol_version | allocation_group_id)` 决定；
5. 输出实际组数、样本数、类别分布和比例偏差。

训练种子固定为 42、43、44，但种子只影响模型训练，不改变已冻结清单。

### 6.2 GeNIS 套件

| 套件                            | 边界                                                                             | 用途                                 |
| ------------------------------- | -------------------------------------------------------------------------------- | ------------------------------------ |
| `genis_family_time_forward`     | 父捕获/攻击步骤按最早 UTC 排序，最后约 10% 组为测试、此前约 10% 为验证、其余训练 | 家族级时间前向主结果                 |
| `genis_subtype_open_set`        | 在时间边界外再应用 `K/U_val/U_test` 原生子类型隔离                               | 未知子类型拒识主结果                 |
| `genis_same_capture_diagnostic` | 仅在无法跨独立运行覆盖的已知子类型内按会话谱系分组                               | 闭集可学习性诊断，明确标注弱外部效度 |

时间顺序相同的并列组按稳定哈希排序。测试组一旦冻结，任何标签别名、阈值或字段修订必须重新提升协议版本，而不能原地修改。

### 6.3 TQH-C2 套件

| 套件                                | 边界                                                                                                                          | 用途                    |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- | ----------------------- |
| `tqhc2_cell_indomain`               | 36 个完整 cell 目标分为 28/4/4；验证和测试各覆盖三种 profile、四种 interval，并尽量覆盖三种 jitter；并列方案按稳定哈希        | 同域 cell 级基线        |
| `tqhc2_leave_one_profile_out_A/B/C` | 每折测试为被留出的完整 12 个 profile cell；其余 24 个 cell 中 4 个作验证、20 个训练，验证覆盖两种训练 profile 和四种 interval | 加密/传输条件域外主结果 |

留一 profile 测试不受 8:1:1 约束，因为 12 个测试 cell 是完整域。验证 cell 只能来自两个训练 profile。interval/jitter 结果按 cell 分层报告，不把同一 cell 的流重新分区。

### 6.4 ns-3 套件

| 套件                       | 边界                                     | 用途                         |
| -------------------------- | ---------------------------------------- | ---------------------------- |
| `ns3_star_indomain`        | 星型拓扑完整运行按场景分层、组级约 8:1:1 | 物理状态、残差和检测同域结果 |
| `ns3_dumbbell_external`    | 全部哑铃拓扑运行只作最终外部测试         | 跨拓扑泛化                   |
| `ns3_parking_lot_external` | 全部停车场拓扑运行只作最终外部测试       | 多瓶颈跨拓扑泛化             |

外部拓扑不参与特征范围、损失权重、早停、阈值或模型选择。

### 6.5 GeNIS↔TQH-C2 跨源压力测试

只使用共同观测和 `binary_label` 交集，分别做 GeNIS→TQH-C2 与 TQH-C2→GeNIS。TQH-C2 的辅助/未解析标签排除并报告覆盖率。由于两源攻击类型并不相同，该套件同时包含数据域和攻击语义偏移，只能称为**跨源压力测试**，不能解释为纯采集域迁移。

## 七、四类模型视图与公平信息预算

### 7.1 视图定义

| 模型       | 派生视图                                                                                             | 可见信息                                            |
| ---------- | ---------------------------------------------------------------------------------------------------- | --------------------------------------------------- |
| 树模型     | `tree_flat_view`：固定包序列展平、掩码及由共同观测确定性计算的训练内统计                             | 共同检测观测，不见身份与物理真值                    |
| DistilBERT | `distilbert_sequence_view`：固定字段顺序的数值/枚举词元序列，统一截断父样本                          | 与树模型同一语义观测                                |
| Qwen       | `qwen_sequence_view`：与 DistilBERT 同字段、同包顺序、同样本截断的确定性文本序列；只增加输出格式指令 | 与 DistilBERT同一语义观测，不添加背景描述或数据集名 |
| 标准 PINN  | `pinn_observation_view`：共同检测观测；仅在 ns-3 训练损失侧另接状态目标、物理系数、残差点和边界条件  | 推理输入不见真值；真实 PCAP 没有补造物理列          |

文本模板、数值精度、单位、字段顺序、缺失标记与截断规则必须版本化并哈希。Qwen 的自然语言提示不得透露数据集、攻击名称、profile 或标签先验。

### 7.2 公平门槛

- 四类模型读取完全相同的 `sample_id`、`split_id` 和共同语义字段。
- 所有缩放、分位点、统计聚合边界、类权重和截断参数只由训练样本确定。
- 每个模型最多使用一个公开默认配置加 10 次验证集调参；早停只看验证集。
- 所有模型运行种子 42、43、44；最终报告均值、标准差和按父组自助法置信区间。
- 类别不平衡优先使用训练内类权重；若重采样，记录父 `sample_id`，验证/测试不重采样。
- 不强求相同参数量或词元数，但必须报告可训练参数、总参数、训练时长、加速器、峰值显存、吞吐和单样本延迟。
- 标准 PINN 必须有相同状态监督、相同网络容量但去掉物理残差的对照；否则不能把提升归因于物理约束。

## 八、指标与报告方式

### 8.1 检测主指标

- 二元、家族和子类型：宏平均 F1、每类召回、良性误报率、平衡准确率；准确率只作补充。
- 开放集：未知召回、未知精确率、已知宏平均 F1、已知误拒率、未知/已知 AUROC 与开放集分类率曲线。
- 校准：期望校准误差、Brier 分数及固定阈值来源。
- 跨域：域内指标、域外指标和泛化落差分开报告；不得把多个域按样本量微平均成一个总分。

Qwen 的结构化输出有效率单列；树模型、DistilBERT 和 PINN 对此记为“不适用”，不是零分。

### 8.2 物理指标

仅在 ns-3 报告队列/状态的 MAE、归一化 RMSE、物理残差分布、边界违约率及分场景误差。物理指标与检测指标放在不同表中，不形成加权总分。

### 8.3 统计单位

置信区间按 `allocation_group` 自助抽样，不按窗口或表格行独立抽样。TQH-C2 以 cell 为统计单位；ns-3 以完整运行为单位；GeNIS 以独立捕获/攻击步骤为优先单位，并明确独立组数量不足的类别。

```text
    ├── field-budget.json
    └── artifact-sha256.txt
```

每个清单记录协议版本和父制品哈希。模型运行目录只能引用清单哈希，不得复制后私自删样本。

## 十、P0 物化验收门禁

以下检查全部通过后，协议才从“候选”转为“冻结”：

1. **身份**：三类来源的版本、原件哈希和提取器契约均非空，TQH-C2 明确为实际 1.0.1 归档。
2. **唯一性**：`sample_id` 全局唯一；相同输入重跑得到完全相同的清单哈希。
3. **组互斥**：任一 `allocation_group_id`、父会话、重叠窗口谱系只属于一个 `split_id`。
4. **近重复**：规范包长/方向/时间序列的精确哈希和近重复签名跨边界交叉为零，或逐项给出可解释例外。
5. **标签连接**：TQH-C2 `uid`、GeNIS 真值与 ns-3 场景连接率和隔离数量已报告；未连接记录不进入监督训练。
6. **开放集**：`U_test` 原生子类型在训练和验证计数为零；`U_val ∩ U_test = ∅`。
7. **时间**：GeNIS 训练最晚时间不晚于验证，验证不晚于测试；所有时间为 UTC。
8. **跨域**：留一 profile 和外部拓扑在训练、验证、缩放和调参输入中的记录数均为零。
9. **训练内拟合**：缩放器、截断长度、类权重和词表/模板统计的来源清单哈希只指向训练集。
10. **字段预算**：逐模型可见字段与 `field-roles.yaml` 完全相符；地址、端口、绝对时间、源标识、标签和 ns-3 真值不可见。
11. **比例**：输出实际组数与样本比例；任何偏离 8:1:1 都由完整组约束解释，不自动重分。
12. **可复现性**：另一进程从同一原件和协议生成相同 `sample_id`、`split_id` 与制品哈希。

## 十一、当前风险与最小下一步

### 已知风险

- GeNIS 的子类型独立攻击运行少，限制已知子类型的强闭集泛化结论。
- TQH-C2 三种 profile 同时改变加密层和 TCP/UDP/HTTP 传输，留一 profile 结果不能归因于单一因素。
- GeNIS↔TQH-C2 的攻击语义不同，跨源结果混合攻击与采集域偏移。
- 标准 PINN 无法在缺少物理真值的真实 PCAP 上按同一方式训练；它只能在 ns-3 机制套件中公平归因。

### 最小下一步

1. 只下载并核验 TQH-C2 标签/清单小归档，不下载超过 200 MB 的 PCAP；先完成 36 个 cell 的版本、标签和组清单审计。
2. 盘点 GeNIS 每个家族/子类型的独立捕获、攻击步骤和时间范围，确认 `U_val/U_test` 是否可行。
3. 用不含模型训练的清单构建器物化 `groups.parquet`、`samples.parquet` 和三类 split manifest。
4. 运行上述 12 项 P0 检查，通过后记录最终哈希并冻结 `data-protocol-v1.0`。

**在 P0 通过前不得启动正式训练；在最终测试解封前不得依据测试结果修订字段、标签、阈值或分区。**
