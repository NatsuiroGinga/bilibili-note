# R2 任务 02S：GeNIS `Dur` 表示精度与流身份语义复审

日期：2026-08-03

## 1. 终态裁决

**R2 继续保持 `NO-GO`。** 本轮证据足以否决“把固定容差从 500 纳秒直接放宽到 1,000 纳秒后继续运行”，但还不足以放行 GeNIS 强物理监督。

本轮得到三个明确结论：

1. GeNIS CSV 中的 `Dur` 不是纳秒精确点。它经过 Argus 微秒端点差、单精度浮点转换、默认 6 位小数格式化，以及 HERA/Pandas 再读取和重写。相对于原始 PCAPNG 纳秒时间戳，它应被视为**有明确生成机制的区间删失观测**，而不是简单的“六位小数实数”。
2. 3,973 条冻结候选中，现有候选专属分包规则只能让 3,823 条表面满足总包数和双向包数；其余 150 条身份失败。在 3,823 条中，3,746 条严格符合上述表示链，77 条不符合。
3. 77 条时长异常全部来自重复 `FlowID`，且全部是 TCP、`Cause=Status`；150 条身份失败中有 137 条来自重复 `FlowID`。因此当前首要缺口是长连接多记录情况下的流记录身份与包序列分配，而不是一个可由全局固定时间容差解决的数值误差。

**唯一推荐方案：强制解耦“流身份唯一性”和“`Dur` 验收”。** 先在完全不使用 `Dur` 的条件下，对同一成员内的全部相关流记录做唯一、全局一致的包序列分配；只有身份唯一后，才按样本自身的 Argus/HERA 表示链逆像区间验收 `Dur`。在新的独立实现完成并全量通过前，不得启动 R2 最终物化或训练。

## 4. `Dur` 的实际表示链

### 4.1 不是“CSV 有几位小数就有几位精度”

HERA 调用 Argus 客户端时没有传 `-p`，所以客户端采用默认 6 位小数。随后 HERA 用 Pandas 读取中间 CSV，数值推断会把 `Dur` 变为浮点列，再写出带标签 CSV。这会去掉尾零，也可能把很小的值改写成科学计数法。

3,973 条冻结候选的原始字符串分布为：

| 表示属性 | 数量 |
| --- | ---: |
| 固定小数 | 3,972 |
| 科学计数法 | 1 |
| 可见 1 位小数 | 445 |
| 可见 3 位小数 | 2 |
| 可见 4 位小数 | 31 |
| 可见 5 位小数 | 317 |
| 可见 6 位小数 | 3,178 |

因此 `0.0`、`6e-06` 或尾零被去掉的值仍来自同一个 6 位输出通道。**可见小数位数不能用来逐行推断源精度。**

### 4.2 可证伪的表示模型

对原始首包和末包纳秒时间 `t_first`、`t_last`，当前一手实现支持以下生成模型：

```text
u_first = floor(t_first / 1000)
u_last  = floor(t_last  / 1000)
d_us    = u_last - u_first
y_argus = format_6_decimals(float32(d_us / 1_000_000))
y_csv   = pandas_reserialize(parse_number(y_argus))
```

其中 `y_csv` 是发布 CSV 中可见的 `Dur`。在身份已独立锁定后，不能再把 `y_csv` 乘以十亿当作唯一纳秒点，而应先求：

```text
C(y) = {d_us | parse_number(format_6_decimals(float32(d_us / 1_000_000))) = y}
I(y) = union over d_us in C(y) of [max(0, 1000*d_us - 999), 1000*d_us + 999] ns
```

`I(y)` 同时包含两个端点各自丢失的亚微秒余数和单精度浮点/六位小数输出的逆像。只有实际包首末跨度属于 `I(y)` 时，`Dur` 才能通过。这个规则是**样本级表示区间**，不是从观测误差最大值事后拟合出的全局容差。

## 6. 对三次失败的重新解释

### 6.1 整数 `Start/Last`

HERA 在标注阶段明确执行 `round().astype(int)`。因此整数 `Start/Last` 是粗定位中心，不是精确包边界。首个失败版本将其当作精确秒边界，应继续判定为错误实现。

### 6.2 科学计数法

唯一的 `6e-06` 来自 Pandas 再序列化，数值上与 6 位 Argus 输出兼容。解析器必须接受精确十进制科学计数法，但不能据此推断该行精度不同。

### 6.3 单个 670 纳秒样本

样本 `genis:05769bc97f41c70f01b0d0da45be3443c97f8dfab712eb39f9885a9558cab819` 的实际跨度为 `3,987,493,670` 纳秒，发布 `Dur` 为 `3.987493` 秒，差 `+670` 纳秒。该样本仍与微秒端点截断模型一致，但它只能证明 500 纳秒阈值可能误拒，不能证明全量候选可以采用固定 1,000 纳秒容差。

全量结果显示，3,746 条表示链内记录支持区间模型，而另外还有 77 条无法由同一模型解释。因此后续合同不得以 670 纳秒这一条观测设阈值。

## 7. 可证伪方案裁决

### 方案 A：继续保留固定 500 纳秒

**否决。** 它会拒绝 872 条能够由一手实现链和原始包端点共同解释的记录。

### 方案 B：把全局固定容差改为严格小于 1,000 纳秒

**否决。** 该规则能覆盖 3,746 条表示链内记录，却不能解释 77 条时长异常和 150 条身份失败。它还把“由生成机制推导的区间”错误简化成一个不区分样本表示逆像的经验阈值。

### 方案 C：保留候选专属分包，只把 `Dur` 改为区间验收

**否决。** 当前工具只加载候选行。相同连接键下未入选候选的相邻状态记录不会参与全局分包约束，其包可能进入候选的半秒粗窗口。包数恰好相等也不能证明所选包序列唯一；77 条异常全部来自重复 `FlowID` 正是这一风险的集中信号。

### 方案 D：先做全记录唯一身份分配，再做样本级表示区间验收

**唯一推荐。** 该方案可以被全量数据直接证伪，并且不使用标签、测试结果或 `Dur` 本身选择包序列。

### 方案 E：停用发布 CSV 的 `Dur` 强监督，或用固定版本导出器重新生成流

**失败后的唯一后备方案。** 若方案 D 仍有任意候选无法唯一分配或无法通过表示链，不得继续放宽条件。应把发布 `Dur` 降级为不可用于强监督，或者从官方 PCAPNG 使用锁定版本与配置重新生成网络层字段和持续时间。

## 8. 下一独立实现边界

下一任务必须由新的独立实现代理执行，并建立新计划、新代码锁和新正式输出。允许的最小范围如下：

1. 修改 `thesis/experiments/llm_probe/tools/r2_genis_totbytes_verifier/src/flow.rs` 及为承载明确证据字段所必需的同工具内部模型/输出文件；不得修改官方归档、冻结候选、标签或候选选择逻辑。
2. 每个流成员先读取**全部** 10 秒流记录；按规范化五元组、记录顺序、粗时间窗、`TotPkts/SrcPkts/DstPkts` 对同一连接的包做全局一致分段。`Dur`、`TotBytes`、类别标签和最终测试结果不得参与身份选择。
3. 只有当每条候选对应恰好一个可行包子序列，且同一包不能被多个流记录消费时，身份门禁才通过。零解或多解均直接失败。
4. 身份锁定后，根据发布 `Dur` 求 `C(y)` 与 `I(y)`，记录逆像候选数、实际跨度、合法区间和验收结果。不得用本轮观测到的最大误差生成阈值。
5. 继续逐条核对总包数、双向包数、五元组、二层字节和网络层字节。身份失败与时长失败必须分开计数和输出。
6. 对全部 3,973 条候选从头运行。任意身份多义、身份缺失、表示逆像为空或跨度不在区间内，都保持 `NO-GO`，不得启动 R2 训练。

建议正式摘要至少新增：

```text
all_rows_loaded
candidate_identity_unique
candidate_identity_missing
candidate_identity_ambiguous
dur_inverse_empty
dur_interval_match
dur_interval_mismatch
repeated_flow_id_candidate_count
```

只有 `candidate_identity_unique == 3973`、其余身份失败项为 0，且 `dur_interval_match == 3973` 时，才允许继续裁决 `TotBytes`。这仍不自动代表 R2 数据集总门禁通过。
