### 3.1 ACK 与丢包关系语义门禁已经闭合

- `src/main.rs:109-111` 按本端发送、对端发送和包号空间分别维护包历史。
- `src/main.rs:168-201` 对 ACK 闭区间和单个丢包包号同时验证事件序号严格早于关系事件、包时间不晚于关系事件。
- `src/main.rs:308-323` 在流式读取当前包时按发送或接收方向写入相互隔离的历史；ACK 承载于本端发送包时只查询对端历史，承载于本端接收包时只查询本端历史。因此当前承载包不会被当成自己确认的包。
- `src/main.rs:329-400` 从 ACK 承载包继承包号空间，要求整个 ACK 闭区间都存在于同一空间的对向先前包集合；范围非法或无法关联时登记异常和无法关联计数。
- `src/main.rs:435-472` 只允许 `packet_lost` 关联本端同空间先前发送包，无法关联时登记异常和分空间计数。
- `src/main.rs:501-530` 要求应用数据空间至少一条有效 ACK、至少一条有效丢包，并拒绝任何无法关联 ACK 或丢包。

在线流式历史只包含已经读取的事件；再叠加严格事件序号、时间比较和全轨迹时间单调门禁，未来包不能进入有效关系。发送与接收历史相互隔离，同端包号碰撞也不能通过对向关系检查。

### 3.2 核心异常硬门禁与制品证据已经闭合

- `src/main.rs:223-300` 将事件时间、时间回退、未知事件、包号空间、包号和包长异常写入 `TraceAudit.issues`。
- `src/main.rs:329-472` 将 ACK 范围、ACK 关系、恢复指标单位、在途字节、拥塞窗口和丢包关系异常写入同一异常集合。
- `src/main.rs:475-546` 对非空 `issues` 添加 `hard_semantic_issues_present` 及逐项失败原因，候选无法绕过异常门禁。
- `src/main.rs:847-907` 在候选、排除和先导结构中显式保存分空间关系、允许缺失掩码、允许缺失计数和核心异常计数；候选与排除制品还保存核心异常清单。
- `src/main.rs:1051-1072` 对被排除 qlog 同时输出硬失败原因与原始异常；`src/main.rs:1119-1168` 对候选输出零异常证据；`field-coverage.json` 汇总候选异常及关系计数。

ACK 延迟缺失和源数据没有显式 PTO 被作为允许缺失显式保留，不进入部署输入，也没有被零填充或推测；其余字段、单位、观察点、时序和关系异常全部作为硬失败处理。
