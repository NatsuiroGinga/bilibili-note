# 任务 06Q：QUIC qlog 物理辅助池审计与候选冻结计划

> **执行代理要求：** 使用 `subagent-driven-development` 执行本计划；读取 `rust-skills` 后实现流式审计。本任务不使用测试驱动开发，不运行格式化、Pyright、pytest、Prettier、冒烟或无关 Git 检查。

**目标：** 从固定提交的 QUIC-MedNetCom 原始仓库中确定性识别字段完整 qlog，冻结 QUIC 动力学字段、单位、方向、缺失掩码和训练期特权真值，形成 R2 QUIC 物理辅助池候选。

**架构：** 独立 Rust 审计工具以只读方式流式解析旧 qlog，统一事件名和时间/字节单位，分别输出部署可观测字段与训练期特权状态。候选构建执行两次并逐文件比较，只有字节级一致且全部硬门禁通过才发布候选审计结果。

**技术栈：** Rust 发布构建、JSON/qlog 流式解析、SHA-256、确定性 JSONL。

## 字段合同

### 部署可观测输入

- 相对到达时间、包间隔、方向、包长、窗口包数/字节数和速率
- 可由被动链路观测稳定取得的传输族适用性
- 不包含 TLS 密钥、端点 qlog、攻击标签、服务器名称或采集场景编号

### 训练期特权真值

- QUIC 包号空间与包号
- ACK 范围或首次确认关系
- 最新、最小和平滑 RTT 及 ACK 延迟语义
- 端点判定的丢包与 PTO 事件
- 在途字节和拥塞窗口

### 标准单位

- 时间统一为整数纳秒，保留原始单位和转换证据
- 字节量统一为非负整数，禁止由总流量反推拥塞窗口或在途字节
- 方向统一为相对 qlog 观察端点的发送/接收，并保存观察点类型
- 缺失值使用显式掩码，不做插值、零填充或后验猜测

1. 仓库提交、200 文件大小与 SHA-256 清单必须匹配；任一变化立即失败。
2. 8 个零字节 qlog 必须登记为上游占位并排除，不能当作下载损坏或补造内容。
3. 每条候选必须同时具有可映射的发送包、ACK、RTT、端点丢包、在途字节和拥塞窗口证据；字段存在但单位、观察点或时序不可解释也要排除。
4. `.json` 与 `.qlog` 内容重复必须按内容摘要去重，不能把同一轨迹重复计权。
5. qlog 只进入物理辅助池，不添加或推测恶意/良性标签。
6. 包号、ACK、RTT、丢包、PTO、在途字节和拥塞窗口仅为训练期特权真值，不能进入部署输入视图。
