## 验收命令

- 原始包：`stat`、`md5`、`shasum -a 256`、`unzip -t`
- PCAP：`capinfos` 或等价解析器逐文件读取，零损坏文件，包数和时间范围可追溯
- 派生数据：读取全部 Parquet，核对行数、主键唯一性、缺失掩码、标签连接覆盖率和协议适用掩码
- 泄漏：模型输入字段中不得出现标签、文件名、路径、地址、采集配置或采集单元编号
- 格式与静态检查：针对修改文件运行 Black、Ruff、`bash -n`、Prettier，并运行 `git diff --check`
- 上传：`rsync` 返回码为 0，目标存在，源端与目标端 SHA-256 一致

## 决策

- 先完成 C 的端到端验证，再允许 A 和 B 进入下载队列，避免把错误处理逻辑扩散到约 51 GiB 原始数据。
- 初始方案为 A 完成后再启动 B；2026-07-24 用户明确改为 A/B 并行下载。现保持每个类别只有一个活动下载器、独立会话、独立目标和独立日志。
- 所有解压使用独立目录并保留压缩包，不覆盖原始文件。
- 官方 1.0.1 修订计数与随包标签脚本在 9 个 C cell 上存在差异；标签真值按逐流 `labeled.jsonl` 重新计数，脚本摘要只作审计对照。
- Zenodo 记录页端点单连接范围测速快于 API 单连接，但仍慢于现有 8 连接总速率；A 保持原会话续传，不切换端点。
- C-only 候选固定为 `data-protocol-v1.0-rc1` / `theory_selection` / `review_pending`；它只用于理论筛选，A/B 与完整三源 `dataset-v1` 完成后必须重新执行 `final_tuning`。
- 2026-07-28 用户决定保留 B，并批准仅适用于 TQH-C2 B v1.0.1 的受限门禁例外。失败集合只能来自 H1/H3/H7；H4/H5/H6、UID、五元组、元数据、标签合法性、不变量和修订计数必须全部通过，输出必须保留源 `FAIL` 与例外依据。
- A/B/C 统一候选不覆盖 C-only 历史产物，使用全局唯一 `samples.parquet` 与四套独立清单：36 cell 的 28/4/4 域内套件，以及三个 20/4/12 留一 profile 套件。
