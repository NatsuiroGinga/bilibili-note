# PINN 与 PCAP 加密恶意流量检测文献综述

## 摘要

本综述核验了 17 篇全文，其中 12 篇作为核心证据，覆盖物理信息神经网络、有限控制体守恒、TCP/AQM 流体动力学、网络演算、队列可辨识性、分组到达点过程和加密流量表征。结论是：**PCAP 不是物理真值，但它能通过方向、包长、到达间隔、突发和可见协议状态改善潜在物理状态的可辨识性。**在现有数据条件下，最可执行的主线仍是多尺度控制体守恒，而不是把点过程似然、流量统计或网络演算输入特征重新命名为 PINN。TCP 流体动力学与网络演算可作为两个条件备选，但分别受协议可观测性和服务曲线缺失限制。

## 一、阶段一：范围定义

### 研究问题

PCAP 的包级、流级、双向时序和协议观测，能否支持可验证的网络动力学状态预测，并通过可微物理残差和显式前向接口改善 Qwen3-1.7B 的加密恶意流量检测？

### 纳入标准

1. 提供网络动力学方程、可辨识性边界、PCAP 观测机制或加密流量序列表征中的至少一项直接证据。
2. 核心公式论断必须有可读全文、页码和章节位置。
3. 优先 2019 至 2026 年研究；奠基理论可早于 2019 年。
4. 明确区分预测状态的可微物理残差与普通统计正则。

### 排除标准

1. 只有“物理启发”命名，没有状态方程、边界或可微残差。
2. 只由输入计算且对模型参数梯度为零的恒等式。
3. 把道路交通流公式直接当成互联网分组队列公式。
4. 把单点双向会话流量误作同一交换机队列的入队和离队。

详细假设、支持和否决标准见 `research-question-card.md`。

## 三、阶段三：筛选与分类

### 核心方法与理论

1. Raissi 等建立“预测状态－控制方程残差－自动微分”的 PINN 基本计算图。
2. Usama 等展示了稀疏状态、守恒方程和网络交汇边界共同闭合的应用范式，但研究对象是道路交通。
3. Misra、Vardoyan 和 Belamfedel Alaoui 等给出 TCP/AQM 流体动力学和时滞模型。
4. Helm 与 Zhang 等给出网络演算到达曲线、服务曲线和时延上界与神经网络的组合。

### 观测与可辨识性

1. QuASI 说明粗粒度计数对队列有约束，但包时序、顺序和路由缺失使唯一状态不可辨识。
2. Habib 与 Molle 说明输出链路轨迹可反演队列，但必须有正确观测点、服务事件、容量和工作守恒等前提。
3. De Vaere 等说明 QUIC 对确认和控制信息的加密破坏传统 TCP 被动往返时延观测，显式旋转信号只能恢复部分信息。

### 统计与表征

1. Paxson 与 Floyd 否决广域分组到达的通用泊松假设。
2. Hohn 等用聚类点过程解释流内包模式和多尺度突发。
3. ET-BERT、YaTC 和 NetMamba 证明包方向、突发、多层流结构和去偏预处理对加密流量分类有价值。

逐篇决策见 `screening-table.md`。

## 四、阶段四：核心全文分析

### 4.1 什么才是本课题中的 PINN

根据 Raissi 等的基本定义，候选残差 `R(z_hat, x, theta)` 至少需要满足：

1. `z_hat` 是模型预测的连续或离散物理状态，而不是固定输入统计量。
2. 残差来自可说明适用条件的守恒、动力学、边界或容量约束。
3. `R` 对状态预测器或相关可训练参数的梯度非零。
4. 状态与边界可在 ns-3、正确观测点或外部遥测中独立验证。
5. 低残差不能由常数解、复制输入或标签捷径平凡实现。

因此，下列项本身都不是 PINN：

- 粗窗口包数等于细窗口包数之和。
- 包到达点过程的负对数似然。
- 自相似或重尾分布匹配。
- 网络演算时延上界作为输入特征。
- ET-BERT 的掩码报文或同源突发预训练损失。

### 4.2 PCAP 提供了什么

PCAP 能可靠提供相对时间、包长、会话方向、突发结构以及部分可见传输首部。TLS 只加密应用载荷，TCP 的序列号、确认号和标志通常仍可见；QUIC 将更多传输控制信息加密，普通旁路观察者不能直接恢复确认关系和拥塞窗口。协议可观测性必须通过字段掩码显式表示。

ET-BERT 和 YaTC 证明，连续同方向包组成的突发、包序和多层流结构对加密流量分类有实际信息。它们适合作为 PCAP 编码器设计依据和同输入强基线，但不能支撑物理方程论断。

### 4.3 PCAP 不提供什么

PCAP 通常不直接提供：

1. 交换机内部队列占用。
2. 入队前与成功离队后的对应事件。
3. 缓冲区上限、链路有效容量与调度策略。
4. 设备内部丢弃原因。
5. QUIC 加密确认帧和端点拥塞窗口。

Habib 与 Molle 的反演只在输出链路和已知服务条件下成立。QuASI 更进一步说明，即使有每端口输入、输出和丢弃计数，仍需在许多相容包轨迹上回答“可能性”查询，而非直接恢复唯一队列轨迹。因此，公开 PCAP 只能增强观测；ns-3 或额外遥测仍是物理真值来源。

### 4.4 六类技术路线比较

| 路线                | 物理对象                           | PCAP 作用                   | 真实可微残差可行性                 | 当前裁决         |
| ------------------- | ---------------------------------- | --------------------------- | ---------------------------------- | ---------------- |
| 有限控制体/队列守恒 | 占用、到达、服务、丢弃、容量       | 补充有方向时序和突发观测    | 高；ns-3 可闭合状态与边界          | 首选             |
| 宏观流体动力学      | 平均速率、窗口、队列、损失         | 估计发送速率和反馈时序      | 中；依赖协议和观测点               | 并入 TCP 备选    |
| 网络演算/容量边界   | 到达包络、服务曲线、积压和时延上界 | 构造累计到达与突发量        | 中；服务曲线需 ns-3/测试床         | 备选二           |
| TCP/QUIC 协议动力学 | 拥塞窗口、往返时延、丢包反馈       | TCP 可见较多，QUIC 可见较少 | TCP 中等；统一 QUIC 很低           | 备选一，限定 TCP |
| 时间点过程          | 到达强度、聚类和长程相关           | 直接提供时间戳              | 低；似然通常是统计约束             | 只作编码/基线    |
| 多尺度控制体        | 不同窗口的占用和流量守恒           | 提供嵌套时间尺度观测        | 高；必须约束预测状态而非输入恒等式 | 并入首选         |

### 4.5 为什么首选仍是控制体守恒

首选不是因为已有实验只做过队列，而是因为它同时满足现有资源下的五项条件：

1. 状态和边界能由 ns-3 直接记录。
2. PCAP 的包时序可以与 ns-3 生成的同构观测对齐。
3. 方程不依赖特定 TCP/QUIC 实现。
4. 可构造同字段、同状态头、去掉残差的严格对照。
5. 计算量适合 1.7B QLoRA 和单张 RTX 5090。

其主要风险仍是仿真到真实数据的状态迁移，以及物理梯度与生成梯度冲突。PCAP 只能改善可辨识性，不能自动解决目标冲突。

## 五、综合与研究空白

### 5.1 已有研究的断裂处

1. **网络动力学文献与加密流量分类文献相互分离。**前者有方程但依赖内部状态，后者有 PCAP 表征但通常没有动力学残差。
2. **网络演算与神经网络的组合多停留在输入特征。**现有工作证明形式化上界有预测价值，却没有证明把可微边界施加到生成式检测模型能产生独立收益。
3. **公开 PCAP 缺乏内部状态真值。**队列和传输状态论文常依赖正确端口、端点或仿真，而恶意流量数据只提供会话和标签。
4. **协议异质性没有统一闭合。**TCP 可见确认与序列关系，QUIC 则主动隐藏多数控制信息；统一协议状态往往需要伪造缺失量。
5. **物理改善与检测改善缺少严格隔离。**若没有“同 PCAP 字段 + 同状态监督 + 无物理残差”对照，无法判断收益来自物理约束还是更多输入。

### 5.2 可形成的自主创新点

可辩护的创新不是“首次把 PINN 用于恶意流量”，而是以下组合：

1. 建立 PCAP 观测、潜在网络状态和生成检测表示之间的显式可微计算图。
2. 以协议可见掩码和多尺度控制体残差避免 TCP/QUIC 状态混用。
3. 用 ns-3 状态真值、TQH-C2 加密条件留出和 GeNIS 检测主证据组成分工明确的验证协议。
4. 通过同字段无残差、时序打乱和状态前向移除消融，识别物理约束的独立贡献。

这些仍是待验证主张，不能在阶段 A 可辨识性探针前写成已证实结论。

### 5.3 最小研究缺口

最关键的未决问题只有一个：**PCAP 新增观测是否能把物理状态辨识从现有约 3% 改善提升到三种子均超过 10%。**若不能，继续修改 Qwen 条件接口不会解决输入不可辨识问题，PINN 支柱应收窄为 ns-3 机制约束，而不是无限试验更多公式。

## 最终判断

PCAP 值得加入 PINN 技术路线，但其角色必须限定为**观测增强和协议可见性载体**。首个实验不应直接训练大模型，而应先证明 PCAP 能稳定改善目标物理状态的可辨识性。通过后再比较“特征、状态监督、物理残差、生成前向”四个因素；失败则转向带已知服务曲线的网络演算边界，不再无限扩展 PINN 公式。

实验论证不能只复现 PINN 文献的“残差下降”叙事。第三章 `3.6` 必须以未触碰数据、同输入强基线、四臂因果消融、独立状态真值、边界闭合、分级噪声与分布外留出、同硬件效率和明确失败规则组成完整证据链。
