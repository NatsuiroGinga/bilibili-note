# PINN 与 PCAP 技术路线决策报告

## 结论

**首选路线是“PCAP 增强的多尺度控制体状态 PINN”**。PCAP 不作为物理真值，而是补充有方向包长、到达间隔、突发结构和可见协议状态，以提高潜在到达、服务、丢弃与占用状态的可辨识性；ns-3 提供容量、入队、成功离队、丢弃与队列占用真值；预测状态再通过有界条件接口进入 Qwen3-1.7B 的生成检测前向。

这不是对现有有限队列公式改名。路线变化在于：

1. 从五个窗口聚合量扩展为包级观测到多尺度控制体状态的显式映射。
2. 把“物理状态是否可由观测辨识”设为进入大模型训练前的硬门槛。
3. 以“同字段状态监督但无方程残差”为关键对照，排除单纯增加 PCAP 特征带来的收益。
4. 对 TCP、QUIC 和字段缺失设置协议与观测掩码，不把不可见状态伪装成共同物理量。

该结论只冻结**下一次最小验证合同**，不冻结第三章第二结构支柱、算法名称或正式章名。

## 一、首选路线：PCAP 增强的多尺度控制体状态 PINN

### 1. PCAP 是否必要

**对本路线的可辨识性验证是必要的，对物理真值仍不充分。**

- 必要性：现有五字段四窗口相对常数状态基线只改善约 3%，缺少包内时序、方向、突发和协议反馈信息。
- 不充分性：单点 PCAP 通常没有交换机内部入队、离队、丢弃、容量和队列占用真值，也不能把双向流两个方向当成同一队列的入队与离队。
- 正确分工：PCAP 提供观测，ns-3 提供动力学状态与边界；公开加密数据提供检测与跨协议证据。

### 2. 最小字段

#### 所有协议共同字段

1. 相对时间戳与到达间隔。
2. 有符号包长，符号仅表示会话方向。
3. 每个嵌套窗口的包数、字节数、平均与分位包长、到达间隔分位数。
4. 连续同方向包形成的突发长度、字节、持续时间与空闲间隔。
5. 累计包数和累计字节曲线。
6. 协议族、字段可见掩码和缺失掩码。

#### TCP 可选字段

- SYN、ACK、FIN、RST 标志。
- 可见序列号与确认号差分。
- 重传、乱序与可被动估计的往返时延。

#### QUIC 可选字段

- 长短首部、版本、连接标识长度、可见旋转位及其有效性。
- 不解析加密确认帧，不伪造拥塞窗口或确认关系。

#### 必须去偏的字段

- 地址、绝对端口、场景名、文件路径、采集单元编号和标签不进入模型。
- 端口只保留粗粒度服务类别时，也必须增加端口置零消融。

### 3. 状态与自有残差

在窗口 `k` 上预测状态

\[
\hat{z}_k=(\hat{q}_k,\hat{a}_k,\hat{s}_k,\hat{\ell}_k,\hat{c}_k),
\]

分别表示控制体占用、到达量、成功服务量、丢弃量和有效服务能力。ns-3 中这些量有真值；公开 PCAP 中仅部分到达观测可得，其他量均保持为潜状态。

候选守恒残差采用本课题自有的平滑有界形式：

\[
r_k^{\mathrm{bal}}=
\hat{q}_{k+1}-
\operatorname{softclip}_{[0,B_k]}
\left(\hat{q}_k+\hat{a}_k-\hat{s}_k-\hat{\ell}_k\right),
\]

并增加能力与非负边界：

\[
r_k^{\mathrm{cap}}=\operatorname{ReLU}(\hat{s}_k-\hat{c}_k\Delta t_k),
\qquad
r_k^{\mathrm{pos}}=\sum_{u\in\{q,a,s,\ell,c\}}\operatorname{ReLU}(-\hat{u}_k).
\]

多尺度残差不使用“粗窗口等于细窗口求和”这一输入恒等式，而要求**预测状态**在相邻尺度上满足控制体守恒：

\[
r_{k,m}^{\mathrm{ms}}=
\hat{q}_{k+m}-\operatorname{softclip}_{[0,B]}
\left(\hat{q}_{k}+\sum_{i=k}^{k+m-1}
(\hat{a}_i-\hat{s}_i-\hat{\ell}_i)\right).
\]

上述公式是对控制体守恒、有限容量和多尺度观测条件的重新组合，不照抄任一论文。正式使用前必须验证残差对状态预测器参数的梯度非零，并排除常数解、复制输入和协议标签捷径。

### 4. 接入 Qwen3-1.7B 的前向

1. 包序列编码器把共同字段与协议可见掩码编码为 `E_pcap`。
2. 物理状态头从 `E_pcap` 预测 `z_hat`，在 ns-3 样本上接受稀疏状态和物理残差监督。
3. 状态词元 `E_z(z_hat)` 通过零初始化、有界门控交叉注意力写入 Qwen 中间层：

\[
h_l'=h_l+\tanh(g_l)\,\operatorname{CrossAttn}
(h_l,E_z(\hat{z})).
\]

4. 协议与缺失掩码同时进入状态编码器，避免 QUIC 不可见字段被零值误解释为真实状态。
5. 完整模型与“同一 PCAP 编码器 + 同一状态头 + 去掉物理残差”共享参数预算，才能识别 PINN 的独立贡献。

该前向只规定 PINN 支柱如何进入生成模型，不解决当前已知的生成梯度与物理梯度冲突；第二结构支柱仍需另行冻结。

### 5. 三类数据的分工

| 数据        | 作用                                           | 可用信息                                              | 禁止主张                                   |
| ----------- | ---------------------------------------------- | ----------------------------------------------------- | ------------------------------------------ |
| ns-3        | 物理状态训练、残差核验、跨拓扑外测             | PCAP、容量、入队、成功离队、丢弃、占用和边界真值      | 不能代替真实恶意流量检测结果。             |
| TQH-C2 2026 | TLS、QUIC/HTTP3、HTTP+AES 检测与跨加密条件留出 | PCAP 可生成统一包时序；标签日志提供连接与场景信息     | 不能把场景编号或日志标签作为物理状态输入。 |
| GeNIS 2025  | 主检测与未知攻击证据                           | 现有流级字段；若无 PCAP，则使用共同聚合字段和缺失掩码 | 不能声称其流表提供内部队列真值。           |

TQH-C2 当前 52 GiB PCAP 尚未下载，服务器仅余约 22 GiB。正式全量提取前必须扩容；最小探针可按完整采集单元选择少量 TLS、QUIC 和 HTTP+AES 单元，不按行随机抽样。

### 6. 最小实验

#### 阶段 A：离线可辨识性探针，不训练 Qwen

在相同 ns-3 分组划分上比较：

1. 常数与简单统计状态基线。
2. 现有五字段四窗口状态预测器。
3. 新增 PCAP 包时序和突发字段的同容量预测器。
4. 第 3 项打乱包序和方向后的负对照。

**进入阶段 B 的硬门槛**：三个种子中，PCAP 版本相对第 2 项的未观测状态误差均改善至少 10%，且打乱时序后改善显著收缩；每个关键状态均不能退化超过 5%。

#### 阶段 B：四臂 50 步诊断

1. 普通监督 Qwen，同一 PCAP 字段。
2. Qwen + 状态监督，无物理残差。
3. Qwen + 物理残差，但状态不进入生成前向。
4. 完整模型：状态监督 + 物理残差 + 有界条件前向。

目的不是发表 50 步结果，而是确认：残差可反向传播、状态确实进入生成表示、完整模型没有立即出现检测和校准崩溃。

#### 阶段 C：通过后才运行三种子正式实验

- 同一训练清单、输入、参数预算和评测清单。
- ns-3 报告状态误差、守恒残差和跨拓扑稳定性。
- TQH-C2 报告跨 TLS、QUIC 和 HTTP+AES 条件留出。
- GeNIS 报告家族/子类宏平均 F1、未知攻击召回、良性误报、拒识和校准。

### 7. 接受与否决门槛

#### 接受

1. 阶段 A 三个种子未观测状态误差均改善至少 10%。
2. 完整 PINN 相对“状态监督但无残差”在三个种子上同时改善状态误差与守恒残差至少 10%。
3. 检测、开放集和校准复用实验总控中已预注册的非劣门槛，不另行降低。
4. TQH-C2 至少一个跨加密协议或高抖动条件的置信区间支持完整模型优于同输入无物理基线。
5. 时序打乱、残差移除或状态前向移除后，增益按因果预期消失。

#### 否决

1. PCAP 字段不能越过阶段 A 的 10% 可辨识性门槛。
2. 完整 PINN 的增益可被“同字段无残差”全部解释。
3. 低残差伴随更高状态误差，或常数/复制输入即可最小化残差。
4. 三个种子中任两个违反检测非劣、校准或开放集门槛。
5. 依赖标签、场景、地址或采集单元泄漏。

### 8. 成本

- **存储**：TQH-C2 PCAP 约 52 GiB，当前服务器空间不足；提取后只保留无敏感载荷的序列特征可显著减小训练盘占用。
- **预处理**：主要是 CPU 和顺序读盘成本，可在 GPU 训练前离线完成。
- **显存**：短包序列编码器、状态头和低秩条件接口可控制在 Qwen3-1.7B QLoRA 预算内；最小实验应先限制每流包数和状态词元数。
- **训练**：阶段 A 不占 GPU 或只占很小 GPU；阶段 B 允许 RTX 5090 并行两个 50 步进程；正式三种子只能在阶段 A/B 通过后启动。

## 二、备选路线一：协议感知 TCP 流体 PINN

### 适用条件

- 仅用于 TCP 承载的 TLS 和 HTTP+AES 子集，或 ns-3 中明确采用 Reno/CUBIC 的受控流。
- PCAP 必须保留方向、时间戳、包长、标志、序列/确认差分、重传和可测往返时延。
- QUIC 若没有旋转位、端点日志或密钥，不进入同一动力学残差。

### 状态与方程

- 状态：拥塞窗口、距最近丢包时间、往返时延、丢包概率、发送速率和瓶颈队列。
- 方程：基于 Reno/CUBIC 增长－回退与时滞反馈建立**重新离散化**残差，不复制 Misra 或 Vardoyan 原式。
- Qwen 接口：协议专家输出少量状态词元，通过与首选路线相同的有界条件接口进入生成前向。

### 数据分工

- ns-3：提供拥塞窗口、队列和丢包真值。
- TQH-C2：只在 TCP 单元做真实加密检测与状态迁移。
- GeNIS：仅使用可确认的 TCP 子集，不为缺失协议状态补假值。

### 最小实验与门槛

- 先在 ns-3 Reno/CUBIC 跨往返时延和丢包条件做状态辨识。
- 再在 TQH-C2 TLS 与 HTTP+AES 单元比较同字段无流体残差基线。
- 只有三种子状态与残差均改善 10%，且 TCP 子集检测非劣时保留。
- 若跨拥塞控制算法或采集点后状态误差恶化，或 QUIC 需要另造不可观测状态，则否决其章级统一地位。

### 成本与风险

- 状态更丰富、时滞序列更长，训练和调试成本高于首选路线。
- 依赖协议实现和观测点，覆盖面不足，最多作为物理专家而非第三章统一支柱。

## 三、备选路线二：网络演算边界 PINN

### 适用条件

- PCAP 提供累计到达曲线、长期速率和突发量。
- ns-3 或测试床明确提供每跳容量、固定时延、路径和调度策略，以建立服务曲线。
- 公开 PCAP 不具备服务曲线时只做外部验证，不强加残差。

### 状态与自有约束

- 预测状态：积压、排队时延、有效服务率和累计离开量。
- 到达包络与服务曲线先从可核验参数构造。
- 可微项约束**预测状态**不违反积压、容量和时延上界，而不是把确定性上界本身作为损失。

### 最小实验与门槛

- 在 ns-3 星型、哑铃和停车场拓扑上比较普通状态回归、网络演算特征基线和边界 PINN。
- 跨突发量、容量和路径长度留出；三个种子状态误差与边界违反率均改善至少 10%。
- 若只加入上界特征就获得相同收益，或真实状态长期贴不到过松的最坏上界，则否决 PINN 主张，降级为理论特征或安全约束。

### 成本与风险

- 计算成本低于 TCP 时滞模型。
- 最大风险是最坏情况边界过松，以及公开数据缺少服务曲线和拓扑，可能只能支撑 ns-3 机制实验。

## 四、明确不选为 PINN 主路线的方向

| 方向                         | 决定                   | 原因                                                         |
| ---------------------------- | ---------------------- | ------------------------------------------------------------ |
| 时间点过程/自激过程          | 只作观测编码或统计基线 | 负对数似然刻画到达分布，不等于网络守恒或协议动力学残差。     |
| 自相似、重尾与多尺度突发正则 | 只作分布诊断           | 数据集统计规律不是逐样本控制方程，且跨场景参数不稳定。       |
| ET-BERT、YaTC、NetMamba 表征 | 作为同输入强基线       | 能证明 PCAP 序列有信息，但不能证明 PINN 有效。               |
| 输入窗口求和一致性           | 禁止称作物理残差       | 它是输入恒等式，对模型参数梯度为零，或可被复制输入平凡满足。 |
| 把会话双向包当入队与离队     | 禁止                   | 两个方向通常经过不同队列和路径，违反控制体定义。             |

## 五、立即执行顺序

1. 先冻结 PCAP 字段、去偏规则、协议缺失掩码和 ns-3 同构提取格式。
2. 扩容前从 TQH-C2 按完整采集单元取得最小 TLS、QUIC、HTTP+AES PCAP 样本，完成字段可得性审计。
3. 只运行首选路线阶段 A 可辨识性探针。
4. 阶段 A 通过后，才实施四臂 50 步诊断；失败则转向网络演算边界备选，不无限扫描公式。
5. 文献综述不改变当前总控裁决：PINN 保留，第二结构支柱仍未冻结，正式基线优先级不变。
