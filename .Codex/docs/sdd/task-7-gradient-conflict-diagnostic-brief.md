# 任务七：真实批次梯度冲突诊断

## 目标

三档物理权重 `0.001`、`0.01`、`0.03` 均未同时改善生成验证损失、状态均方误差和物理残差均方误差。本任务不继续扫权重，也不引入 M3，而是在真实 GeNIS 与 ns-3 批次上直接测量生成、状态和物理目标对共享 LoRA 参数的梯度关系，为下一机制选择提供证据。

## 固定条件

- 基座：`/root/autodl-tmp/thesis/models/Qwen3-1.7B`。
- 随机种子：42。
- GeNIS 与 ns-3 输入、序列化、批量大小和采样顺序沿用 M0/M1/M2 首轮实验。
- 使用未经本任务更新的初始 LoRA 与状态头，不执行优化器更新。
- 只使用模型可观测字段构造提示；训练期通量真值只进入状态或物理损失，不进入提示。
- 保存的真值残差不得进入任何损失或梯度计算。
- 正式物理残差严格除以正容量积分，不增加 `epsilon`。

## 诊断指标

对 20 个配对批次分别计算共享 LoRA 参数上的：

1. 生成梯度、状态梯度、物理梯度的有限性和范数。
2. `cos(g_gen, g_state)`、`cos(g_gen, g_physics)`、`cos(g_state, g_physics)`。
3. 三组夹角为负的批次数和比例。
4. 在 `lambda_physics={0.001,0.01,0.03,0.1}` 下，加权物理梯度相对生成梯度和状态梯度的范数比。
5. 每步损失、样本顺序哈希、运行时间和峰值显存。

梯度点积和范数按参数张量逐项累计，禁止把全部 17M LoRA 梯度拼接成单个大向量。任一目标在共享 LoRA 上无梯度、非有限或严格为零时立即失败。

## 输出与跟踪

- 新模块、测试和命令入口放在 `thesis/experiments/llm_probe/`，不得改动既有正式运行制品。
- 输出目录：`runs/physics-gradient-conflict/qwen3-1.7b-seed42-init-real20-v1/`。
- SwanLab 在线项目：`mortiswang/malicious-traffic-llm`，逐步记录损失、三个梯度范数、三个余弦值、负夹角标记、运行时间和显存。
- 保存配置、环境、输入哈希、样本顺序、逐步指标、汇总、控制台、SwanLab 原始日志和制品清单。

## 验证与执行

- 本任务不再次启用测试驱动开发技能；先写最小覆盖测试，再实现。
- Python 测试只在服务器执行：目标测试后运行受影响测试，不重复扫描无关未完成任务。
- 同步仅使用 `rsync`，禁止 `scp`、`--delete` 和裸 `uv sync`。
- 测试通过后立即在 `screen` 中运行 20 批次正式诊断，不等待格式化或文档更新。

## 裁决

- 若生成与物理梯度持续负相关，下一候选只允许研究梯度协调或冲突投影，并必须与相同权重 M2 对照。
- 若梯度方向不冲突但物理梯度尺度明显失衡，下一候选只允许研究尺度归一或动态权重。
- 若方向和尺度均无明显异常，则优先检查物理样本覆盖、分场景分布和训练/验证种子迁移，不得直接增加复杂模块。
