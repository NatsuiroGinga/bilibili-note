# 物理状态路由适配专家方向探针证据笔记

## 已恢复事实

- 任务十七四窗口状态估计相对常数下界只改善 `3.017%`，范围外不确定性曲线下面积为 `0.08111`。因此不能把公共字段历史估计写成已恢复真实队列状态，也不能恢复原物理软令牌或不确定性门控。
- D0 的家族路径因硬隔离保持不变，未观测状态误差和物理残差显著下降，但子类宏平均 F1 下降 `0.088946`，未知攻击召回下降 `0.374444`。
- D1 证明加法式私有 LoRA 本身并非必然破坏检测；D2 与 D3 指向物理梯度造成开放集误报、未知召回和校准取舍。
- E2 种子 42 已通过九项门槛，其有界条件注意力是当前主线；本任务只验证一个备选方向，不改变 E2 的冻结前复现状态。

## 本任务相对既有失败路线的实质差异

- D0-D3 使用一个始终激活的加法式私有 LoRA；本任务使用由模型预测物理状态决定的序列级条件参数路径。
- 路由只接受五锚点预测状态和四个预测增量，既不接受原始攻击文本表示，也不接受真值状态、场景号或标签。
- 大类任务仍固定关闭物理路径；子类路径只激活与预测动力学状态对应的专家。
- 专家是否成立必须由使用分布、路由熵、状态条件混淆、专家移除和同预算对照共同证明。

## 文献边界

- 混合专家与 LoRA 专家文献只能支持条件计算的工程先例，不能支持本任务的物理语义或检测增益。
- APINN 与物理硬约束混合专家支持按物理区域分解，但研究对象为偏微分方程，不能直接外推到恶意流量。
- 任务十七负结果要求把所有公开域物理状态称为“模型预测潜在物理状态”，不能称为真实队列恢复。

## 待核验

- 服务端当前无训练 GPU 进程、无 `screen` 会话；数据盘使用 `77%`，剩余 `12 GiB`。
- 既有私有 LoRA 每层秩为 `16`，全线性层可训练参数为 `17,432,576`；本探针采用四个目标层的共享秩 16 基底，只在内部同预算单适配器与路由候选之间作方向比较，不把参数量与 D0 直接等同。
- 当前 S3 状态头输出五个非负状态锚点。设计采用冻结副本负责路由、可训练副本负责最终状态与物理损失，避免阈值漂移并保留物理梯度到专家的路径。
- 主代理已经确认共享基底正交通道码方案，并要求准确命名为“共享低秩基底的物理状态编码专家”。
- 用户随后调整实验优先级：必须先完成正式基线，再探索相对基线提升的方法。本任务当前只完成实现与静态复审，不同步服务器、不运行服务器测试、冒烟或 50 步训练。
