# 任务十七数据与服务器只读审计

- **审计日期**：2026-07-22
- **审计范围**：GeNIS 2025、HIKARI-2021、ns-3 正式队列真值与四窗口制品
- **执行边界**：只读检查；未修改实验源码、数据或既有制品；未启动训练或仿真
- **核心裁决**：**必须先完成一次 ns-3 域随机化扩展和公共观测接口重建，不能直接启动任务十八。**

## 1. 结论

1. **GeNIS 可以形成真实的同一流四段历史，但只在子集上成立，且类别分布严重偏斜。**原始表包含 `FlowID`、`StartTime` 和 `LastTime`。采用“同一 `FlowID`、四条相邻记录、起始间隔 9 至 11 秒、相邻记录不重叠”的保守判据，共找到 132,870 个合格会话和 412,375 条四段候选；其中 130,992 个会话、392,976 条候选来自域外留出的 `dos-pushack` 与 `dos-udp`。现有域内训练、验证、测试分别只剩 1,064、54、293 个合格会话。
2. **HIKARI 当前汇总 CSV 不能形成有时间语义的四窗口历史。**555,278 行中 `uid` 全部唯一，表内没有绝对时间戳；端点对只是代理分组，未命名索引既不唯一也不单调，不能当作时间。
3. **当前模型可直接读取的严格字段交集为空。**ns-3 的五个输入字段与公开数据的八个规范字段没有同名字段；按物理量映射时，只有包数具有相同量纲，但 ns-3 是瓶颈队列 0.1 秒聚合，公开数据是双向流记录，统计对象仍不一致。字节量还存在 L3 字节、总字节和负载字节口径差异，不能直接合并。
4. **当前 ns-3 不足以辨识环境或校准不确定性。**它只有一个拓扑、一个 FIFO 队列策略、一个 50 包队列上限、固定时延、固定 UDP 与固定包长；容量只有 5 与 2.5 Mbit/s，链路损失只有 0 与 1%。21 个运行实际只覆盖 7 个场景配置。
5. **现有状态头尚未优于常数均值。**按训练集五个锚点均值构造的最优全局常数，在验证集上的状态均方误差为 `0.369276`；B0 为 `0.397640`，B1 为 `0.375989`，分别比常数基线差 `7.68%` 和 `1.82%`。因此任务十七不是可选补充，而是进入物理软令牌前的阻塞门禁。

### 3.1 原始字段与现有制品

- 原始目录：`/root/autodl-tmp/thesis/datasets/GeNIS-2025/extracted/2-flows/flows-10-sec/`
- 原始表共有 11 个场景 CSV、1,472,133 行。
- 时间与分组字段：`FlowID`、`StartTime`、`LastTime`。
- 既有会话审计：`runs/data-audit/genis-10s-20260718/audit.json`。
- 既有前向划分：`runs/data-splits/genis-hybrid-forward-v1-20260719-v2/`。
- 既有物化数据：`runs/data-prepared/genis-hybrid-forward-v1-20260719-v4/`。
- 当前物化 JSONL 只保留 `group_id` 和八个规范流特征，**没有保留 `StartTime`、`LastTime` 或窗口序号**，不能直接组成历史。

### 3.2 保守四段判据

本次只读聚合采用以下条件：

1. 四条记录来自同一源场景文件和同一 `FlowID`。
2. 按 `StartTime` 排序后取相邻四条记录。
3. 三个相邻起始间隔均位于 9 至 11 秒。
4. 后一条的 `StartTime` 不早于前一条的 `LastTime`。

该判据只能证明“同一流的连续四段统计”，**不能证明四段来自同一瓶颈队列，也不能把它称为真实队列状态历史**。

## 5. 与 ns-3 的严格公共观测交集

当前公开数据规范字段定义在 `src/flow_probe/schemas.py`，ns-3 输入定义在 `src/flow_probe/ns3_field_roles.py` 与 `src/flow_probe/physics_train.py`。

| 物理量        | GeNIS / HIKARI                          | 当前 ns-3                                          | 严格裁决                                       |
| ------------- | --------------------------------------- | -------------------------------------------------- | ---------------------------------------------- |
| 容量          | 无                                      | `capacity_start_bps`、`capacity_end_bps`、容量积分 | 排除；公开推理不可得                           |
| 包数          | `total_packets`                         | `qdisc_received_packets`                           | 同量纲，但流级与瓶颈窗口级统计对象不同         |
| 字节数        | GeNIS `TotBytes`；HIKARI 负载字节       | `qdisc_received_l3_bytes`                          | 排除；协议层与聚合口径不同                     |
| 包速率        | `packet_rate`                           | 可由包数除以 0.1 秒得到                            | 只能在统一窗口聚合后使用                       |
| 字节速率      | `byte_rate`                             | 可由 L3 字节除以 0.1 秒得到                        | 排除；字节层口径未统一                         |
| 平均包长      | 两个公开数据均有                        | 可由 L3 字节除以包数得到                           | 排除；字节层不同，且 ns-3 固定为 1,052 L3 字节 |
| 最小/最大包长 | 有                                      | 无                                                 | 排除                                           |
| 平均到达间隔  | 有                                      | 无                                                 | 排除                                           |
| 时间          | GeNIS 有绝对起止；HIKARI 只有流持续时间 | ns-3 有固定窗口边界                                | HIKARI 无法构成绝对时间历史                    |

因此有两层结论：

1. **当前序列化字段名的精确交集为 `∅`。**不能把 ns-3 的五字段提示直接应用于 GeNIS 或 HIKARI。
2. **可进一步统一的最小物理原语只有包数与持续时间。**在 GeNIS 重新按公共时间窗聚合后，可派生包速率；字节相关量必须先证明协议层口径一致。HIKARI 当前无法执行这种时间聚合。

任务十七的公共输入至少应删除三项容量字段，禁止把公开推理时不存在的容量继续当作已知输入。容量、时延、丢包率和队列策略只能作为 ns-3 监督的环境目标或潜变量。

## 6. 当前 ns-3 域随机化覆盖

### 6.1 固定项与变化项

| 因素         | 当前覆盖                                                          |
| ------------ | ----------------------------------------------------------------- |
| 拓扑         | 仅 `star-bottleneck-v1`                                           |
| 队列策略     | 仅 `fifo-queue-disc`                                              |
| 队列上限     | 固定 50 包                                                        |
| 瓶颈容量     | 5 Mbit/s；容量变化场景在第 6 秒固定降至 2.5 Mbit/s                |
| 接入链路     | 固定 100 Mbit/s、1 ms                                             |
| 瓶颈时延     | 固定 5 ms                                                         |
| 传输协议     | 仅 UDP                                                            |
| 发送端       | 固定 4 个                                                         |
| 负载         | 每发送端良性 0.25、0.75 或 0.90 Mbit/s；攻击发送端 8 或 15 Mbit/s |
| 包长         | 应用负载固定 1,024 字节；进入队列后所有非零包均为 1,052 L3 字节   |
| 到达过程     | 恒定开启；仅开始时刻在 0 至 40 ms 内均匀抖动                      |
| 下游随机丢包 | 0 或 1%；1% 只与 `benign-random-loss` 场景绑定                    |
| 测量噪声     | 无                                                                |
| 窗口与时长   | 固定 0.1 秒、12 秒                                                |
| 随机性       | 种子 42、43、44；每个种子仅 `run=1`                               |

正式矩阵为 7 个场景乘 3 个种子，共 21 个完整运行、2,520 个窗口、2,421 条高度重叠的四窗口序列。训练、验证、测试虽然 `group_id` 不交叉，但三个分区都包含相同七种场景配置，**不是未见环境参数留出**。

### 6.2 分布退化

- 队列起始状态为 0 的窗口占 `68.29%`。
- 队列起始状态达到 50 包上限的窗口占 `25.71%`。
- 队列起始包数只有 12 个不同取值。
- 每窗接收包数和字节数分别只有 30 个不同取值。
- `benign-high` 三个种子在 `84.17%` 的同位置窗口上完全相同；其三种子合计只有 5 种完整窗口向量。
- 其余场景的同位置三种子完全相同比例为 `11.67%` 至 `53.33%`。

当前数据主要区分“空队列”和“满队列”，不能支持连续环境后验、不确定性校准或仿真覆盖外检测。

## 7. 常数下界

### 7.1 必须报告的下界

设训练集归一化队列锚点为 `q_ij`，五维训练均值为：

```text
μ = [0.378272, 0.380316, 0.382130, 0.383590, 0.384758]
```

均方误差下的最优全局常数为：

```text
q_hat_ij = μ_j
```

当前制品上的结果为：

| 切分 | 常数均值均方误差 | 全零均方误差 |
| ---- | ---------------: | -----------: |
| 训练 |         0.368834 |     0.514621 |
| 验证 |         0.369276 |     0.515152 |
| 测试 |         0.369706 |     0.515687 |

验证集逐锚点常数均方误差为：

```text
[0.366037, 0.367857, 0.369686, 0.371076, 0.371726]
```

全零基线用于检查模型是否只利用大量空队列样本；均值基线是主常数下界。环境连续量使用训练均值基线，环境类别使用训练多数类基线。禁止使用场景标签构造条件均值，因为场景标签不属于部署输入。

### 7.2 通过条件

扩展后的正式诊断应预注册以下门槛：

1. 四窗口模型在未见配置测试集上的全状态均方误差，相对训练均值常数至少降低 `10%`。
2. 四窗口模型必须优于同容量的单窗口模型；差值按完整 `group_id` 做配对区组自助法，95% 置信区间上界必须小于 0。
3. 五个锚点分别报告误差，不能只用总体平均掩盖后部锚点失败。
4. 不确定性只在独立校准集上定标，公开数据不得参与阈值选择。
5. 报告全零、均值、单窗口、四窗口四组结果；缺一组不能裁决可辨识性。

当前 B0 与 B1 的全状态均方误差均未优于验证集常数均值，不能作为“已辨识队列状态”的证据。

## 8. 样本规模与切分契约

### 8.1 当前有效样本量

2,421 条四窗口序列来自 21 个完整运行，每个运行内相邻样本共享三个窗口。统计单位应是完整运行或独立环境配置，而不是每条滑窗。当前每个分区只有 7 个运行配置，无法可靠估计置信区间或校准不确定性。

### 8.2 一次性扩展的最低建议

采用分层随机或拉丁超立方采样覆盖容量、时延、队列策略与上限、丢包、测量噪声、流量混合和包长。最低独立运行规模为：

| 分区             | 独立完整运行 | 用途                       |
| ---------------- | -----------: | -------------------------- |
| 训练             |          120 | 学习状态与环境映射         |
| 域内校准         |           30 | 早停、超参数与不确定性校准 |
| 未见配置域内测试 |           30 | 可辨识性主裁决             |
| 参数范围外测试   |           30 | 覆盖外不确定性裁决         |
| **合计**         |      **210** | 不含公开数据               |

按每运行约 117 条四窗口序列估算，约得到 14,040 条训练序列和三个各约 3,510 条的独立评估序列。该规模是工程诊断下限，不替代后续多随机种子正式统计。

切分必须满足：

1. 环境参数元组在四个分区间不重复；换随机种子不等于新配置。
2. 同一完整运行的所有窗口只属于一个分区。
3. 参数范围外测试至少留出一个容量区间、一个时延区间和一种训练未见队列策略。
4. 误差与置信区间按 `group_id` 聚合或区组自助，不能把重叠滑窗当作独立样本。
5. GeNIS 历史沿用现有会话级前向划分，只在各分区内部构造；按场景限额或加权，避免 `dos-udp` 与 `dos-pushack` 淹没其余场景。
6. HIKARI 只进入单窗口覆盖外诊断，不进入四窗口性能表。

## 9. 是否必须扩展 ns-3

**必须扩展，且应在状态估计器训练之前完成。**阻塞理由不是样本行数不足，而是以下结构性缺口：

1. 容量当前直接作为模型输入，无法检验“从公开观测辨识环境”。
2. 时延、队列策略、队列上限和测量噪声没有变化，相关环境量不可辨识。
3. 丢包率与单一场景绑定，模型可以学习场景捷径。
4. UDP、包长、发送端数和到达过程固定，ns-3 与公开流量容易被固定 1,052 字节包长直接区分。
5. 三随机种子仍复用同七种配置，不能作为仿真覆盖证据。
6. 当前状态头未超过训练均值常数下界。

一次性扩展应至少改变：容量及变化时刻、接入和瓶颈时延、队列策略及上限、独立链路丢包、观测噪声、UDP/TCP 与良恶性混合、包长、发送端数量和突发到达过程。扩展后还必须输出与公开数据同口径的包数与时间原语；字节量在协议层口径核验前不进入严格交集。

**禁止事项**：不因本次裁决修改 Qwen 主干，不恢复博弈或 Stiefel 扫描，不直接启动 C1/C2，不用 HIKARI 行号伪造时间，不把 GeNIS 流历史表述为真实队列历史。
