> **执行工作流**：先用 `writing-plans` 完成实施计划，再用 `subagent-driven-development` 分派实现与独立审查；实现代理可按局部规则使用一次测试驱动开发。

## 目标

在不读取 `eval300` 或最终测试结果调参、不修改 TQH-C2 已发布协议目录的前提下，审计服务器既有 GeNIS 派生输入，冻结 `genis_family_development`、子类与开放集候选清单、稳定 `sample_id`、字段角色及泄漏审计，并在相同训练/验证清单上运行 HGB 与 XGBoost 的种子 42、43、44 验证基线。

## 不可变边界

- 输入优先使用服务器 `runs/data-prepared/genis-hybrid-forward-v1-20260719-v3/`；旧输入证据不足时停止并报告缺口，不补造分组或时间元数据。
- `eval300` 与任何拟作为最终测试的数据只允许确认隔离，不允许读取标签分布、指标或样本内容来选择清单、字段、阈值或超参数。
- 所有模型共享同一训练/验证 `sample_id` 清单、样本顺序、标签与字段来源；树模型只使用 `model_input` 字段。
- 地址、原始端口、文件名、路径、采集单元编号、场景名、标签派生描述和划分元数据不得进入推理输入。
- 候选制品只写独立临时目录；不修改 `runs/data-frozen/dataset-candidate-c-v0/` 或任何已发布 TQH-C2 协议目录。
- 不切换当前共享分支、不提交、不暂存、不回滚其他任务改动。
- Python 测试只在服务器项目 `uv` 环境运行；正式基线启用 SwanLab 在线模式，项目固定为 `mortiswang/malicious-traffic-llm`。

- 首次服务器只读核对受沙箱网络限制失败；经批准使用既有只读 SSH 包装器后成功。
