# 基线实验并行补齐计划

> **执行方式**：使用子代理驱动开发逐任务实施；项目明确禁止测试驱动开发，因此每项先实现，再运行最小定向验证。

## 目标

在 TQH-C2 下载和 `dataset-v1` 物化期间，补齐不依赖最终样本内容的基线代码、配置、权重与服务器环境，使数据通过 12 项 P0 门禁后可以立即启动首批基线。

## 全局边界

- 不生成伪造的 `dataset-v1`，不触碰最终测试标签，不依据测试结果修改字段或划分。
- 基线内部使用稳定语义键：`hgb`、`xgboost`、`distilbert`、`qwen_sft`、`state_supervision`、`standard_pinn`、`published_flow`、`final_method`；M0 至 M7 编号待两份合同统一后映射。
- 所有方法只读取最终协议生成的同一 `sample_id`、`split_id`、字段角色和模型视图。
- Python 测试只在服务器 `uv` 环境运行；本机不运行 `pytest`。
- 不使用测试驱动开发，不提交、不推送；生产代码完成最小验证后必须独立审查。
- 所有新入口采用 `device=auto` 和能力探测，不假定 NVIDIA GPU、RTX 5090、固定 CUDA 或固定显存；CPU 路径至少覆盖数据、树模型、评价和神经模型功能冒烟。
- CPU、通用 CUDA GPU 与 RTX 5090 的成本结果分栏，硬件降级不得改变有效批量、样本、步数、种子或评价清单。

## 分级判定

- **可以启动首批基线**：`dataset-v1` 通过 P0，HGB、XGBoost、DistilBERT 和 Qwen 入口至少各有一个服务器冒烟通过，且全部引用同一清单哈希。
- **完整基线矩阵已就绪**：状态监督、标准 PINN 和已发表流量方法也完成同协议冒烟，三随机种子配置、评价和成本记录均可用。
- **当前禁止正式启动**：`dataset-v1` 尚未生成，任何旧 GeNIS 开发集结果只能作为代码回归证据。

2. 现有 HGB 与 Qwen 入口读取旧 JSONL，不读取冻结协议。
3. 项目尚无 XGBoost 依赖与运行实现。
4. 项目尚无 DistilBERT 分类实现和配置。
5. 已发表同输入流量方法尚未选型。
6. 统一实验合同与外部对比计划的 M 编号不一致，代码不得依赖编号。
