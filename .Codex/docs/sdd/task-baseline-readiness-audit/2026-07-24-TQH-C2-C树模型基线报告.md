## 1. 结论

HGB 与 XGBoost 的六个运行均已完成，服务器、本地归档和 SwanLab 云端三侧制品可对应。两个模型在固定 TQH-C2 C 验证集上得到完全相同的硬分类结果：宏平均 F1 为 `0.9310799563`，平衡准确率为 `0.9788940481`，准确率为 `0.9636231357`，良性误报率为 `0`。三个种子内这些检测指标和两项校准指标的样本方差均为 `0`。

这组结果只能建立 C/HTTP+AES 二分类开发门槛，不能作为最终测试结论。验证集没有未知真值样本，无法评价未知攻击召回；当前协议仍为 `review_pending`，且必须补做去除 53 个跨开发划分同观测极短流哈希、共 260 条样本后的敏感性分析。

XGBoost 的平均拟合时间比 HGB 少 `36.30%`，平均推理时间少 `72.73%`，平均吞吐量为 HGB 的 `3.72` 倍，但平均进程常驻内存高 `14.45%`。XGBoost 的已知类对数损失低 `0.00004240`，期望校准误差却高 `0.00664782`，因此当前不能宣称任一模型在校准上全面占优。

## 6. 结果解释与边界

1. **检测门槛成立**：两个树模型都在 C-only 固定验证集上达到宏平均 F1 `0.9311`、平衡准确率 `0.9789` 和良性误报率 `0`。
2. **没有检测赢家**：两个模型的硬分类指标和混淆矩阵完全相同，不能依据这批结果选择检测性能赢家。
3. **成本倾向 XGBoost**：在当前 CPU 单线程、并发运行条件下，XGBoost 更快但占用更多常驻内存。该结论是工程测量，不是算法复杂度证明。
4. **校准存在取舍**：XGBoost 的对数损失略低，但期望校准误差更高；差异只在一个验证划分上观察到。
5. **不含开放集证据**：`unseen_truth_sample_count=0`，未知召回率为空；不得把 C-only 二分类结果外推为未知攻击能力。
6. **不含最终测试证据**：本批次没有评价测试清单，也没有进行验证集调参；全部结果仅用于 `theory_selection`。
7. **重复观测敏感性待补**：53 个跨开发划分同观测极短流哈希涉及 260 条样本。当前标签无冲突且来自不同源捕获，但在剔除敏感性分析完成前，结果保持 `review_pending`。
