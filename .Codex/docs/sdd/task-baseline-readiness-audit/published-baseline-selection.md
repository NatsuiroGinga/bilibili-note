## 一、结论

唯一首选是 Finamore 等人在 IMC 2023 公开的 TCBench 监督式 `mini-FlowPic + LeNet5`，采用无增强、从头训练版本。唯一备选是同一论文和 MIT 制品中的 `SimCLR mini-FlowPic`，采用 `Change RTT + Time Shift`、30 维投影、关闭 dropout 和从头训练版本。

两者均可从冻结主记录中的 `network_length_bytes` 与 `delta_time_us` 确定性生成，不需要载荷字节、地址、端口、绝对时间或数据源身份。首选的适配范围仅限字段映射、任务分类头和当前 PyTorch 环境移植，仍能保持论文方法的核心语义。

这不等于首批训练现在可以启动。`data-protocol-v1.0-rc1` 的 P0 物化门禁、`dataset-v1` 清单与包序列视图、薄适配层、许可证清单和三档设备烟测尚未全部完成。在这些门禁通过前，本报告只冻结选择和复现合同。

RTX 5090 不是方法前提。适配层必须支持 `device=auto`：PyTorch CUDA 可用时使用 CUDA，否则回退 CPU；`nvidia-smi` 只可作为可选遥测，命令缺失或不可调用不得导致训练、评价或审计失败。

## 四、统一输入合同

### 4.1 样本单位

一个模型样本严格对应主清单中的一个 `sample_id`，单位为协议已冻结的完整流或包序列窗口。FlowPic 是该样本的派生视图，不创建新样本身份。

不得执行以下操作：

- 把同一 `sample_id` 再切成多个训练样本；
- 合并多个 `sample_id` 形成一张图；
- 在 FlowPic 适配器内重新分配训练、验证或测试；
- 对验证或测试做重采样、增强或基于标签的过滤；
- 把增强视图写成独立样本并纳入父组置信区间。

### 4.2 允许字段

| 用途       | 主记录字段                        | 转换                                           |
| ---------- | --------------------------------- | ---------------------------------------------- |
| 包长坐标   | `network_length_bytes`            | 转为非负字节值并按官方逻辑截断到 1500          |
| 时间坐标   | `delta_time_us`                   | 对有效包累加，得到相对首包秒数 `timetofirst_s` |
| 有效行过滤 | `observation_mask`                | 排除填充、缺失和协议不适用的行                 |
| 连接与评价 | `sample_id`、`split_id`、任务标签 | 只用于索引、训练目标和结果连接，不进入像素     |

`direction`、`payload_length_bytes`、`transport_family`、`tcp_flags` 与 `burst_id` 在共同主记录中保留，但首选和备选均不读取。论文明确不在 FlowPic 中使用方向，因此这属于方法自身的信息子集，不是适配器遗漏。

### 4.3 禁止字段

地址、端口、MAC、绝对时间、文件名、cell、数据集身份、拓扑身份、原始载荷、标签文本、攻击配置、队列占用、容量、到达率真值、残差和其他物理监督列不得进入表征或模型输入。

### 4.4 确定性 FlowPic

对每个 `sample_id` 按以下固定顺序生成视图：

1. 只保留 `observation_mask` 标记为有效的包，并保持主记录顺序。
2. 令首个有效包时间为 0，累加 `delta_time_us / 1_000_000` 得到 `timetofirst_s`。
3. 只保留 `timetofirst_s < 15` 的包。
4. 将 `network_length_bytes` 截断到闭区间 `[0, 1500]`。
5. 时间与包长分别线性映射到 32 个区间，使用二维计数直方图生成 32×32 单通道矩阵。
6. 每个单元计数截断到 `[0, 255]` 并存为 `uint8`。
7. 记录视图合同哈希、输入清单哈希、包长截断率、15 秒后丢弃率和空图比例。

短于 15 秒的样本不复制或循环填充，未覆盖区域保持零。长于 15 秒的样本只使用前 15 秒。该裁决忠实于官方实现，但必须在结果中报告不同来源的有效观察覆盖率。

## 七、设备解析与不可比边界

### 7.1 `device=auto` 合同

适配层必须接受 `--device auto|cpu|cuda[:index]`，默认 `auto`。解析顺序如下：

1. 显式 `cpu` 始终使用 CPU，不探测 `nvidia-smi`。
2. 显式 `cuda[:index]` 只依据 PyTorch CUDA 可用性和设备索引校验；不可用时给出清晰错误，不静默换设备。
3. `auto` 在 `torch.cuda.is_available()` 为真且最小张量设备测试通过时解析为 CUDA，否则解析为 CPU。
4. `nvidia-smi` 只尝试补充驱动、显存和 GPU 名称；命令缺失、权限不足或返回非零时写入 `telemetry_status=unavailable`，继续运行。
5. 运行清单必须记录 `device_requested`、`device_resolved`、CPU 型号与线程数、GPU 型号与索引、PyTorch 版本、CUDA 运行时、精度、批大小和硬件指纹。

自动回退只保证功能可用，不保证效率结果可比较。运行开始后不得因暂时 OOM 在 CPU 与 GPU 间来回切换；应停止并重新以明确设备启动。

### 7.2 正式比较边界

- 正式检测性能和效率比较应在同一硬件档位、同一软件环境、同一精度与同一设备指纹内完成。
- CPU 与 GPU 的训练时间、吞吐、延迟和能耗不得出现在同一排名列，也不得计算混合均值。
- 不同 GPU 型号的效率指标只可并列陈述，不直接形成快慢结论；RTX 5090 结果不能代表所有 CUDA GPU。
- 如果某模型只能在 CPU 完成而其他模型在 GPU 完成，检测指标可作为额外诊断单列，但该组不构成正式同硬件矩阵。
- 三档都使用同一清单、超参数和输出模式；不得为了 CPU 降级减少最终测试样本或改变类别。
- `nvidia-smi` 遥测缺失的 GPU 运行仍可用于检测评价；若无法从 PyTorch 获得设备身份，则效率比较降级为不可比。

## 十、公平性与报告协议

### 10.1 必须相同

- 所有方法读取完全相同的 `sample_id`、`split_id`、任务标签和最终测试清单。
- FlowPic 不得从原 PCAP 绕过 `dataset-v1` 自行重提取字段。
- 每个任务最多使用协议允许的验证调参次数，最终测试只评价一次。
- 训练种子固定为 `42`、`43`、`44`。
- 分类指标使用共同评价器；按 `allocation_group` 自助抽样置信区间。
- 参数量、训练时长、峰值显存、推理吞吐和单样本延迟按同一测量脚本记录。
- 正式比较必须固定硬件指纹；CPU 与 GPU 时间、不同 GPU 型号的效率结果不得混排。

### 10.2 必须单列

- 结构化输出有效率只适用于生成式模型，FlowPic 记为“不适用”，不得记零。
- ns-3 的状态误差、物理残差和边界违约率对 FlowPic 为“不适用”，不得记零。
- FlowPic 的开放集结果是共同外部校准器作用于 logits 的结果，不得表述为论文原生开放集方法。
- GeNIS、TQH-C2 和 ns-3 的标签与域不同，分别报告，不形成微平均总分。
- 论文数值只用于说明原方法设置与风险，不作为目标值、先验或验收阈值。

### 10.3 特有风险

1. **任务迁移**：原论文做应用分类，本项目做恶意检测，只有方法可迁移，分数不可迁移。
2. **层级口径**：原制品的 `pkts_size` 来自各数据集预处理，本项目固定 IP 网络层长度；需标记为字段受限复现。
3. **观察时长**：15 秒固定窗口可能比其他模型的训练内截断更长或更短；必须证明所有模型仍基于同一原始样本，而不是同一张量形状。
4. **信息子集**：FlowPic 忽略方向与协议，使用的信息少于共同预算；不得额外补入端口或字节弥补。
5. **空图与截断**：短流、长度截断和单元计数饱和可能因数据源而异；三项覆盖率必须按来源和类别报告。
6. **偏移与泄漏**：论文已揭示人工与自动采集偏移以及原作者实现的切分风险；本项目禁止适配器自建随机行级划分。
7. **旧依赖**：直接安装官方包可能污染公共环境；移植必须通过固定夹具而非依赖版本降级。
8. **增强身份**：备选的两个视图共享父 `sample_id`，统计时不能当成独立样本。

## 十一、选择与停止门禁

### 11.1 首选进入首批基线的全部条件

- [ ] `data-protocol-v1.0` 已由 P0 物化验收升格，清单和视图散列非空。
- [ ] 三源包序列视图都能提供有序的 `network_length_bytes`、`delta_time_us` 与 `observation_mask`。
- [ ] `sample_id` 一对一、组互斥、近重复跨边界和禁止字段审计全部通过。
- [ ] 官方固定夹具与移植实现生成的 FlowPic 逐元素一致。
- [ ] 移植 LeNet5 的层结构、参数量和初始化语义与固定发布版一致。
- [ ] 代码中保留 MIT 许可与来源版本，权重清单明确为从头训练。
- [ ] CPU 路径的无训练视图审计和 64/32 样本烟测通过，且缺少 `nvidia-smi` 不会失败。
- [ ] 当前可用 CUDA 路径的同等烟测通过；若服务器为 RTX 5090，另记录其硬件指纹而不增加专属前提。
- [ ] 预测输出可由共同评价器按 `sample_id` 无歧义连接。
- [ ] 峰值显存、时间和磁盘未超过本合同上限。

全部通过后，`published_flow` 可进入首批基线。缺少任一项时状态仍是“选型完成但不可启动”。

### 11.2 立即停止条件

- 最终数据只能提供流级聚合而不能恢复同一 `sample_id` 内的有序包长和相对时间；
- 需要读取原始载荷、地址、端口或数据源私有字段才能运行；
- 适配器必须重新切分、重新采样测试集或改变 `sample_id`；
- 官方夹具与移植实现无法逐元素一致且差异没有被定位；
- 必须降级公共 PyTorch/CUDA 环境或覆盖现有锁文件才能运行，且 CPU 回退也不可用；
- 任何测试标签被用于包长范围、观察时长、增强选择、早停或阈值；
- 资源超过上限后仍需扩大训练轮数或缩减最终测试样本；
- 许可证文件或来源版本无法随移植代码一并保留。

触发停止条件时不切换到 ET-BERT、YaTC 或 NetMamba。应先报告 `published_flow` 因共同协议不可实现；不能用违反字段预算的方法填空。

### 11.3 备选启停

- 只有第六节预注册触发条件满足、首选适配器已经通过、增强仅发生在训练分区且资源预算获批时才启动。
- 若只需一个已发表基线、无标签效率问题或成本超过首选两倍，停止备选。
- 不得在查看 `U_test`、最终时间前向测试、跨源测试或跨拓扑测试后决定启用备选。
