# DRIFT T17 伪未见 family 辅助任务梯度诊断实现报告

## 结论

**阶段 0 否决当前最小实现。** 已完成 P0 没有保存 MTP、TPP、TOV 三个辅助头的训练后权重，故不能计算“原辅助任务梯度”。以相同结构新建头会随机初始化并改变梯度方向，违反本任务的硬约束；因此未创建生产脚本、JSON 配置或远程启动器，未读取 T18--T25，未运行真实实验。

## 核验证据

审计对象为唯一完成的 P0：

- 运行身份：`ch3-drift-n10-conservative-fusion-pilot-batch1024-v2-p0_c00-c00`。
- 数据 revision：`3b31077020cd1c013d0a75cad51042a2327c4521`；有效配置的 fit 与 validation 年份均为 `T17`。
- 最终检查点：[checkpoint.pt](../../../thesis/experiments/llm_probe/runs/diagnostics/ch3-drift-n10-conservative-fusion-pilot-batch1024-v2/p0_c00/checkpoint.pt)，SHA-256 为 `45abd75581a711c1907855bf9a3311ed4bfef459d2c690675574b750b576d86d`。
- 字符骨干：[char-backbone.pt](../../../thesis/experiments/llm_probe/runs/diagnostics/ch3-drift-n10-conservative-fusion-pilot-batch1024-v2/p0_c00/char-backbone.pt)，SHA-256 为 `fe33df4b907d3a342e157c4e0dc68566715a25145c389eb18e8eab0a9ec38041`。
- 子词骨干：[token-backbone.pt](../../../thesis/experiments/llm_probe/runs/diagnostics/ch3-drift-n10-conservative-fusion-pilot-batch1024-v2/p0_c00/token-backbone.pt)，SHA-256 为 `1190c1bd0a3d0c65762d4deb94f443eeae3ad938b46b447ef16394f5e9befc5e`。

只读载入显示：

1. `checkpoint.pt` 的顶层键为 `completed_batch`、`config_hash`、`examples_seen`、`optimizer`、`phase`、`rng_state`、`script_hash`、`static_model`、`tokenizer_sha256`；其 `phase` 是 `static`。
2. `static_model` 共 152 个状态键，只含 `token`、`char`、`classifier` 三类前缀；搜索 `mtp_head`、`tpp_head`、`tov_head` 的结果为空。
3. 两个独立骨干文件均只保存 `EncoderBranch(static.<branch>).state_dict()`。每份各有 74 个状态键，仅为 `embedding`、`position` 与六层 `encoder`；同样没有三个辅助头。
4. 训练代码确实在 `PretrainedBranch` 定义了 `mtp_head`、`tpp_head`、`tov_head`，但保存独立骨干前显式包裹为 `EncoderBranch`，随后把两个分支转换为 `EncoderBranch` 再训练静态监督模型。因此最终 P0 的持久制品无法恢复辅助头参数。
5. 另一份 `pilot-v1/p0_c00/checkpoint.pt` 仍处于 `tokenizer` 阶段，没有 `static_model` 或分支参数，不能作为替代；SHA-256 为 `cb482f97876e18061f9c72407e3b2bc7d38b1e59a4daf460268ad752bf4f58b6`。

直接代码证据在 [P0 训练器](../../../thesis/experiments/llm_probe/tools/ch3_drift_n10_conservative_fusion_pilot.py)：`PretrainedBranch` 定义辅助头，保存阶段使用 `EncoderBranch(static.char)` 与 `EncoderBranch(static.token)`，最终加载路径也把分支转换为 `EncoderBranch`。

## 最小替代方案

不重训、不新建辅助头、不接触未来年份。仅当能找到**同一已完成 T17 P0 身份**在转换为 `EncoderBranch` 之前持久化的检查点，且该检查点同时满足下列条件，才可重新开启本诊断：

1. `char` 和 `token` 全部分支状态都带有训练后的 `mtp_head`、`tpp_head`、`tov_head` 参数。
2. 检查点的配置、代码、分词器、数据 revision 与 T17 训练输入哈希可核验，并与该 P0 身份一致。
3. T17 raw family 映射仍能按既有首标签键连接官方 eSLD，所有多 family 歧义键隔离。
4. family 分组、抽样量、一步线性化步长和长度分层的数值均已有冻结依据。

若不存在这样的历史制品，当前“原 MTP/TPP/TOV 梯度”命题不可检验；后续只能经新的科学合同把问题改写为不同的、明确不声称原辅助梯度的诊断，不能把编码器梯度或随机头梯度改名替代。
