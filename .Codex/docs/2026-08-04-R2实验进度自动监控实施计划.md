# R2 实验进度自动监控实施计划

## 目标

建立低开销、可恢复的统一实验状态快照，自动检测 TCP/UDP、QUIC、数据门禁、模型门禁和后续 GPU 正式运行的完成、失败、停滞与资源告警，避免依赖人工逐个询问子代理。

## 边界

- 不改变实验配置、数据、种子、并发度或科学参数。
- 不轮询最终测试内容，不读取凭据，不记录密码或令牌。
- 不依赖 `screen` 套接字判断任务是否完成，以运行目录的结构化状态和制品为准。
- 当前 Codex 会话不能在没有用户输入时主动发送聊天消息；自动化负责持续检测、持久化快照和状态变化告警，并在下一次用户输入时自动提供最新摘要。

## 实施步骤

- [ ] 盘点现有 Hook、正式启动器状态文件和运行目录合同。
- [ ] 实现服务器只读状态汇总器，输出原子更新的统一 JSON 快照和状态变化记录。
- [ ] 实现本机轻量读取器，只在快照变化、失败、停滞、完成、需要 GPU 或磁盘越界时输出摘要。
- [ ] 将读取器接入项目现有 `UserPromptSubmit` 或等价当前可用入口；Hook 必须在无网络、服务器关机和状态缺失时退出 0。
- [ ] 对当前 TCP、QUIC 和门禁任务做一次真实状态验收，确认不会重复启动、修改或终止实验。
- [ ] 写实施报告和恢复说明，注明当前会话需重启后 Hook 才能加载。

## 验收标准

1. 一个统一快照能显示任务标识、状态、完成/失败/总数、最后更新时间、停滞时长、首错、资源告警和是否需要 GPU。
2. 汇总器只读实验制品，写入自身监控目录时使用临时文件加原子替换。
3. 相同状态不重复输出；关键状态变化必须保留历史记录。
4. 服务器关机、SSH 不可用、部分状态文件损坏时不阻塞用户输入，并明确标记数据陈旧。
5. 不包含凭据、最终测试内容或敏感路径载荷。
