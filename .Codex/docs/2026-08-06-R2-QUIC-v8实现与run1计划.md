# R2 QUIC v8 实现与 run1 计划

## 目标

在不改变已冻结网络参数、工具树、端点和随机种子的前提下，将确定性的有限队列容量丢包纳入 QUIC 物理真值合同，使新版物理旁路实验具备可审计的 QUIC 专家输入。核心门禁通过后立即启动唯一的 v8 run1；run1 失败时停止，不启动 run2 或 run3。

## 修改边界

- 新增 `configs/r2_quic_controlled_deterministic_queue_drop_v8.json`。
- 修改 `scripts/r2_quic_udp_proxy.py`，显式绑定 v8 队列丢包接受合同。
- 修改 `scripts/r2_quic_controlled_collect.py`，仅对 v8 接受可回放、容量因果的队列丢包。
- 修改 `scripts/audit_r2_quic_determinism_gate.py`，增加 v8 事件生命周期、严格空值、完整 qlog、完整 pcap 和抓包计数审计。
- 新增 `scripts/audit_r2_quic_v8_gate.py`，提供唯一单轮门禁和三轮门禁入口。
- 新增 `tests/test_r2_quic_v8_contract.py`，覆盖上述合同的最小目标行为。
- 不修改 TCP 文件，不改变 v4-v7 的零队列丢包语义。

## 唯一测试驱动周期

1. 先新增 v8 目标测试并同步旧服务器，运行一次观察预期红灯。
2. 实施最小生产改动，在本机仅做写入 `/tmp` 的语法检查。
3. 同步生产文件并在旧服务器运行同一目标测试一次，取得绿灯。
4. 核对本地与服务器同步哈希。

## 正式运行

- 仅启动 `r2-quic-deterministic-queue-drop-v8-run1-aioquic`。
- 输出根：`runs/data-raw/r2-quic-deterministic-queue-drop-v8-run1-aioquic`。
- 记录启动进程号、首个代理统计、事件数和首个错误。
- 独立复审与运行并行，不得阻塞 run1。
- run1 未通过时不重试，不启动 run2/run3；先形成失败裁决。

## 验收条件

- 配置规范化投影与 v7 完全相同，哈希为 `933d82e530200a7bd0dabd12d25a809aec4a14a9888e62a3b210b6c0295c44ef`。
- 目标测试在旧服务器由红转绿。
- run1 的服务端到客户端方向至少出现一次容量因果队列丢包，且事件账本可完整回放。
- 随机丢包、发送错误、合同错误、停机积压、抓包内核丢包均为零。
- QUIC 专家仅在正式样本规模和绑定完成后标记就绪；run1 仅证明真值合同可运行。
