# 第三章单数据集转向与候选路线验证计划

## 1. 文档状态

本文记录下一阶段的**待验证研究路线**。除已标明的历史结果外，主题、基座、模型结构、章节名和效果主张均未冻结。任何候选只有通过预先规定的开发实验后才能进入正式三种子矩阵和论文主张。

## 2. 转向原因

现有 GeNIS/TQH 混合候选同时改变数据来源、标签体系、样本单位和采集环境，不利于解释收益来自物理机制还是数据域差异。Qwen3-0.6B 与 DistilBERT 的先导实验都出现真实物理优于置换物理、但低于无物理基线的结果，说明物理信号并非完全随机，但旧的直接旁路结构不能作为第三章最终方法。

TQH-C2 v1.2.0 在同一发布中提供 A/B/C/D 四个测试床、间隔与抖动网格，以及 B/D 的受控协议栈配对。它有机会同时承担困难域、受控迁移和稳健性证据，从而把正式公开检测数据收缩为一个版本明确的数据集。

## 3. 候选研究主题

### 3.1 路线 A：受控协议栈迁移

研究同一 Merlin C2 框架从 HTTP/3/QUIC/UDP 切换到 HTTP/2/TLS/TCP 后，检测器能否保持性能。训练与测试围绕 B/D 双向迁移建立，优点是控制变量清晰；局限是 B、D 的尺寸与时序基线可能接近天花板，单独承担第三章难题的空间不足。

### 3.2 路线 B：间隔与抖动扰动稳健性

研究 C2 信标间隔和抖动变化造成的行为分布漂移。训练保留部分间隔与抖动组合，测试完整留出组合。优点是与动态行为和物理状态自然连接；局限是容易退化为普通数据增强或时间序列分类，需要物理机制和严格留组设计才能形成创新。

### 3.3 路线 C：困难域检测与受控协议栈迁移

以 C 测试床为主要困难域，在排除地址、端口、采集身份和连接状态捷径后验证检测性能；以 B/D 作为受控协议栈迁移面板，以间隔和抖动作为稳健性面板，以 A 作为简单域非退化检查。

**当前推荐路线 C。**它把困难检测、机制解释和部署变化分别交给不同面板，避免用一个混合总分掩盖问题。但该推荐仍须由实际 A/B/C/D 基线和完整文献报告确认。

## 4. 候选基座

### 4.1 路线 M1：Qwen 解码式生成主模型

Qwen3-0.6B 同时生成检测标签和结构化解释。优点是输出能力完整；缺点是数值流表二分类适配和训练成本不占优，现有物理旁路退化明显。它继续作为候选和跨基座验证，不因旧题目获得优先级。

### 4.2 路线 M2：流量编码器主模型

使用轻量 Transformer 编码器或流量专用预训练编码器承担检测与物理融合。DistilBERT 只代表结构化字段序列化的通用文本编码器；ET-BERT 使用 PCAP 会话的字节 BURST、专用词表和流量预训练，二者必须分开报告。优点是分类、物理状态接入和成本更匹配；缺点是不能直接承担自由文本解释。

### 4.3 路线 M3：编码检测与生成分析双阶段系统

编码器负责检测、置信度和物理状态，Qwen 只读取编码器的结构化输出并生成分析。该路线可能兼顾检测性能与解释能力，但必须明确两阶段职责、端到端成本和错误传播，不能把两个独立模型的结果拼成一个虚假单模型创新。

**当前文献中间证据倾向 M3，主检测器倾向 M2。**最终选择只依据冻结开发协议上的性能、校准、成本、物理接入和可复现性，不依据题目措辞。

## 5. 候选物理结构

1. 共享守恒通路负责协议无关的包量、字节量、速率和边界条件。
2. TCP 专家处理 A、C、D 的可观测历史与训练期特权真值。
3. QUIC 专家处理 B，并把 UDP 包量、字节量与速率守恒作为底层物理项，再叠加 QUIC 的长连接、确认、拥塞和复用状态。
4. 协议不确定或字段不足的样本进入共享回退，不用地址、端口、测试床身份或标签作路由捷径。
5. 独立普通 UDP 专家仅作为 ns-3 机制消融候选，不与 QUIC 专家竞争 B 样本。

该结构目前只是假设。正式冻结前必须比较“独立 UDP”与“UDP 内嵌 QUIC”，并验证真实物理优于置换和随机物理。

## 6. 单数据集实验面板

| 面板 | 目的 | 划分单位 | 主要报告 |
| --- | --- | --- | --- |
| C 困难域 | 验证去除快捷特征后的主要检测能力 | 完整采集单元或独立会话组 | 宏平均 F1、平衡准确率、良性误报率、校准误差 |
| B↔D 迁移 | 隔离 QUIC/UDP 与 HTTP/2/TLS/TCP 协议栈变化 | 完整测试床和采集单元 | 双向迁移宏平均 F1、性能下降和最差方向 |
| 间隔/抖动留组 | 验证行为扰动稳健性 | 完整间隔×抖动单元 | 平均和最差组合、置信区间 |
| A 简单域 | 检查方法不以牺牲简单条件换取困难域收益 | 完整采集单元 | 非退化差值和误报率 |
| 效率 | 判断论文方法是否具备部署可行性 | 同硬件、同批量、同输入预算 | 参数量、显存、训练时间、吞吐和延迟 |

最终测试在字段、划分、基座、阈值和方法冻结前不可见。TQH 的 `unknown` 标签不作为未知攻击真值。

## 7. 逐级验证顺序

### 阶段 E0：数据审计

核对 1.2.0 的文件哈希、实际测试床与单元数、标签、字段、缺失值和重复组；解决 README 的 36/48 单元、26/27 特征不一致。输出不可变来源清单和防快捷特征清单。

### 阶段 E1：传统与轻量基线

在只含开发训练、校准和开发验证的单数据集划分上运行 HGB、XGBoost 和轻量序列编码器。其作用是测量 C 困难域、B/D 迁移和间隔/抖动面板的真实难度，并建立训练时间与推理成本下界。

### 阶段 E2：基座筛选

使用相同结构化输入比较轻量编码器、DistilBERT 和 Qwen3-0.6B；ET-BERT 使用原生字节 BURST，作为独立原生输入强基线，不能伪装成共同字段比较。先只运行种子 42，在开发区按主要面板性能、最差面板、校准和成本选择进入物理机制筛选的基座。

### 阶段 E3：PINN 机制筛选

在胜出基座上比较无物理、仅状态监督、标准 PINN、层级物理专家、置换物理和随机物理。真实物理必须在主要困难面板上优于置换和随机对照，并相对无物理基线形成预注册的改善或非劣；状态误差与物理残差不能替代检测证据。

### 阶段 E4：一次有界重构

若层级物理专家仍低于无物理基线，只允许进行一次由诊断证据驱动的结构重构，例如零初始化门控、特权物理教师向可观测学生蒸馏或不确定性感知条件强度。不得修改最终测试、削弱基线或重复挑有利种子。

### 阶段 E5：正式矩阵

只有 E3 或 E4 通过后，才运行种子 42、43、44，并补齐强外部基线、关键消融、B/D 双向迁移、间隔/抖动留组、效率、跨基座和统计区间。若一次重构后仍失败，PINN 的主张必须收缩为实验实际支持的校准或稳定性作用，不能继续声称提高检测 F1。

## 8. 第三章工作量与效果参照

朱焱雷论文第三章约 26 页，含 33 个编号公式、1 个算法、2 个定理、1 个引理、11 幅图和 7 张表。本课题第三章计划为 28 至 35 页，并以相近或更高的论证完整度验收候选路线。数量用于检查理论、实现和实验是否足以构成一章，不允许拆公式、制造定理或重复图表凑数。

| 部分 | 计划篇幅 | 理论与算法责任 | 图表责任 |
| --- | ---: | --- | --- |
| 问题、威胁模型与数据协议 | 4–5 页 | 任务、组级划分、快捷特征边界和评价定义 | 数据结构图、协议栈图、数据统计表 |
| 共享守恒与 TCP/QUIC 物理状态 | 7–9 页 | 状态方程、残差、可观测性、量纲、边界条件和至少一个引理 | 状态演化图、残差分布图、变量表 |
| 层级物理专家与有界路由 | 6–8 页 | 专家映射、UDP 内嵌 QUIC、有界注入、梯度与稳定性分析和至少两个理论命题 | 总体结构图、路由图、复杂度表 |
| 训练与推理算法 | 3–4 页 | 完整目标、掩码、教师监督、算法流程与复杂度 | 算法 1、训练流程图 |
| 实验评估与分析 | 8–10 页 | 基线、消融、统计、失败边界和效率解释 | 至少 7 张核心表、11 幅具有独立证据责任的图作为规划参照 |

公式计划以约 30–36 个有独立推导责任的编号公式为目标，算法 1–2 个、理论命题约 2 个、引理约 1 个；最终数量服从真实机制。候选路线如果只能产生单一损失项、单一结果表或缺少独立消融，即使取得小幅提升也不能冻结为章级创新。

效果幅度以朱论文第三章原表的同类指标作为**量级参照**，不得预设或制造固定提升。正式比较必须先核对朱论文中的任务、基线和指标，再分别报告绝对百分点、相对增幅、多种子区间和实际成本。本课题不通过挑选种子、查看最终测试后改样本、削弱基线或隐藏失败条件来追求相似数值。

## 9. 第三、四章候选组织

第三章暂定为《基于物理条件专家与有界路由的加密 C2 检测方法》，组织为问题定义、物理状态与残差、层级专家、有界路由、训练与推理算法、实验评估。该标题尚未冻结。

第四章复用同一数据、划分、主基座和评价协议，候选研究间隔、抖动、困难域和长尾条件下的动态课程与约束强化训练。第三章未冻结前不提前确定强化算法。

## 11. 与历史结果的关系

旧 GeNIS/TQH 混合数据、旧 TQH 版本、DistilBERT 与 Qwen3-0.6B 的 `F-A/F-P/F-S`、QUIC 工具门禁和 ns-3 物理真值均保留。它们分别证明旧数据混合和旧物理注入的问题、提供工程复现资产，并约束下一版设计；它们不自动进入 TQH-C2 v1.2.0 单数据集的正式结果表。
