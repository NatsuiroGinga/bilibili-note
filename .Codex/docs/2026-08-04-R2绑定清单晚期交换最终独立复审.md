第五轮复审发现的“不可变绑定清单在发布后、返回前仍接受父目录交换”问题已经按原门槛完成最小修复。独立故障注入确认：发布后的首次目录 `fsync` 返回时交换最终父目录，以及临时名清理后的最终目录 `fsync` 返回时交换最终父目录，发布函数都会拒绝成功；替换目录中的注入内容保持不变，被移走的原目录不残留本轮最终清单或临时名，所有清理均使用已固定目录描述符和相对名称。

确认结果：

1. 新清单完成非覆盖硬链接发布，或既有同内容清单完成稳定读取后，固定最终父目录先执行 `fsync`，随后复核完整目录链。
2. 临时名只通过同一固定目录描述符删除；删除后再次刷新该目录并执行末次目录链复核。
3. `completed=True` 位于末次目录链复核之后。末次复核失败时仍进入异常清理分支。
4. 异常清理只以临时名、最终名和固定 `dir_fd` 调用 `unlink`；没有按词法完整路径重新打开或删除替换目录内容。
5. 异常清理完成后刷新同一固定目录并再次复核目录链，函数不会把目录链已变化的结果报告为成功。

```text
PUBLISH_AFTER_FIRST_FSYNC_REJECTED_FIXED_DIRFD True True True True True True
PUBLISH_AFTER_FINAL_FSYNC_REJECTED_FIXED_DIRFD True True True True True True
```
