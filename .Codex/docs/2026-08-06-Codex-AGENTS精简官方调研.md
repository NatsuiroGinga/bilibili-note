## 结论

本仓库有明确且应立即处理的精简空间。推荐采用“**最小常驻规则 + 局部规则 + 按需技能 + 机械门禁 + 状态文档**”的结构，而不是单纯提高 `project_doc_max_bytes`。

- 当前纳入本次审计的 10 份规则文件共 `48,254` 字节。它们不会在每次会话中全部自动加载，但进入 `llm_probe` 的常规发现链按官方专门指南的合并口径达到 `32,912` 字节，超过默认 `32 KiB`；进入 `scripts/` 时达到 `33,953` 字节。
- 建议目标总量约 `21,900` 字节，预计减少 `26,354` 字节，即约 `54.6%`。
- 最直接的收益来自全局规则和仓库根规则：两者当前合计 `22,582` 字节，每个从仓库根启动的会话都会承受这部分常驻上下文。
- `AGENTS.override.md` 和回退文件都不能把同一层规则拆成多个可累加文件。前者替换同层普通文件，后者只在前面的候选不存在时使用。
- 技能适合承载规划、调试、实验恢复、文献处理等重复工作流；钩子和 `.rules` 适合执行可判定的机械限制；`config.toml` 适合运行时设置。把同样的长说明搬到 `developer_instructions` 不会减少上下文。
- **精简本身不应阻塞实验**。但是当前仓库根规则指定旧服务器变量，`llm_probe` 局部规则仍指定 378 服务器变量；在唯一化当前服务器合同并完成恢复文档与服务器实况核验前，不建议直接启动远程实验。完成这项 `P0` 后，无需等待 `P1/P2` 精简即可开始已经冻结的实验。

## 官方事实

### 规则发现

OpenAI 的专门指南说明了以下顺序：

1. 全局层先检查 `$CODEX_HOME/AGENTS.override.md`，不存在时检查 `$CODEX_HOME/AGENTS.md`；只使用第一个非空文件。
2. 项目层从项目根走到当前工作目录；每一层依次检查 `AGENTS.override.md`、`AGENTS.md`、`project_doc_fallback_filenames`，每层最多使用一份文件。
3. 文件按根到当前目录顺序合并，越近的文件越晚出现，因此拥有更高优先级。
4. 发现链只在一次运行开始时建立；随后编辑或切换任务不会动态重新发现更深目录的规则。
5. 专门指南写明达到 `project_doc_max_bytes` 后停止继续加入规则，默认值为 `32 KiB`。

证据：[OpenAI：使用 `AGENTS.md` 的自定义指令](https://learn.chatgpt.com/docs/agent-configuration/agents-md)。

配置概要页把 `project_doc_max_bytes` 简写为“从每个 `AGENTS.md` 读取多少”，与专门指南的“合并大小”措辞不完全一致。由于专门指南是该功能的完整说明，本报告采用更保守的**整条发现链合并上限**核算。正式改造后还应通过新会话和日志验证实际客户端版本的加载结果。

证据：[OpenAI：项目指令发现配置](https://learn.chatgpt.com/docs/config-file/config-advanced#project-instructions-discovery)。

### 各载体职责

OpenAI 官方建议保持 `AGENTS.md` 小而必要：全局文件主要表达个人沟通偏好，仓库文件只保留每次都要遵守的构建、测试、审查和目录约定。可确定的要求应同时由提交前检查、静态检查器或类型检查器执行。

证据：[OpenAI：技能与渐进式披露](https://learn.chatgpt.com/docs/customization/overview#skills)。

钩子适合确定性生命周期动作。`PreToolUse` 可以拦截或改写本地命令和文件编辑；`Stop` 可以要求继续验证；`SessionStart`、`PreCompact` 可以注入或保存恢复信息。但官方明确说明工具钩子只是护栏，不是完整安全边界，部分专用工具可以绕过默认钩子路径；钩子输出也会占用上下文，因此必须保持简短。

证据：[OpenAI：Codex 钩子](https://learn.chatgpt.com/docs/hooks#tool-coverage)、[OpenAI：大型钩子输出](https://learn.chatgpt.com/docs/hooks#large-hook-output)。

`.rules` 可以针对命令参数前缀设置 `allow`、`prompt` 或 `forbidden`，适合“禁止直接 `grep`，改用 `rg`”这类简单机械约束。复杂的远程命令解析、路径判断和跨参数条件仍应使用经过测试的 `PreToolUse` 钩子。

证据：[OpenAI：命令规则字段](https://learn.chatgpt.com/docs/agent-configuration/rules#understand-rule-fields)。

## 主要问题

### 1. 全局层放入了大量项目和工作流规则

[全局规则](/Users/bilibili/.codex/AGENTS.md) 同时包含：

- `rg`、`fd`、`sd` 的长示例和命令规范
- 按语言强制格式化、静态检查及失败回滚
- `Codex Scholar` 身份、写作方法、交付模板
- 本论文实验复审边界
- 规划、技能路由与 Obsidian 写回工作流

其中只有简体中文、回答结构、破坏性操作确认等少量个人偏好真正适合全局常驻。论文实验规则应归入本仓库；重复工作流应归入技能；确定性命令禁令应归入规则或钩子。

### 2. 存在直接冲突

- 全局规则要求 TypeScript/JSON 使用 `prettier --write`，仓库级钩子却明确禁止任何 Prettier 调用。
- 全局规则要求检查失败时执行 `git checkout -- <file>`。这可能覆盖用户已有修改，不应作为通用恢复策略。
- [仓库根规则](../../AGENTS.md) 指定当前使用 `GPU_SSH`、`GPU_PWD`，只有用户重新启用 378 时才能使用带 `_378` 的变量；[实验局部规则](../../thesis/experiments/llm_probe/AGENTS.md) 却反向规定当前只使用 `_378` 变量。

这些冲突会让“更近规则覆盖上层规则”成为偶然裁决，而不是明确合同。服务器变量冲突是远程实验启动前必须消除的操作风险。

### 3. 机械门禁尚不能直接接管文字规则

- [全局钩子配置](/Users/bilibili/.codex/hooks.json) 中 `security-guard.js` 的路径通过 `path.join(home, '/Users/bilibili/...')` 生成。实际解析结果是 `/Users/bilibili/Users/bilibili/.codex/hooks/security-guard.js`，该路径不存在。
- [项目钩子配置](../../.codex/hooks.json) 当前只接入 Prettier 拒绝和压缩前快照，并明确写着“其他项目执行门禁继续暂停”。
- [project_policy_guard.py](../../.codex/hooks/project_policy_guard.py) 和 [server_launcher_guard.py](../../.codex/hooks/server_launcher_guard.py) 已存在测试，但尚未接入当前 `hooks.json`。
- [skill-forced-eval.js](/Users/bilibili/.codex/hooks/skill-forced-eval.js) 读取旧字段 `user_prompt`，而当前官方 `UserPromptSubmit` 输入字段是 `prompt`；同时它在每个用户提示后无条件注入技能路由说明，形成重复上下文开销。

因此正确顺序必须是：**先修复、测试、接入并信任机械门禁，再删除等价文字规则**。不能先删规则后假定钩子会接管。

### 4. 易变状态混入了持久规则

以下信息会随实验阶段变化，不应长期驻留在 `AGENTS.md`：

- 当前服务器选择和变量名
- 当前基座模型与规模提升候选
- 固定数据路径、样本数和种子
- 当前 SwanLab 项目和运行阶段
- RWKV 当前门禁状态和待办顺序

这些内容应以两份恢复文档、冻结合同、运行配置和制品清单为事实来源。`AGENTS.md` 只保留“启动前必须读取哪个事实源”和不可变安全边界。

## 推荐结构

| 内容类型 | 推荐载体 | 常驻方式 |
|---|---|---|
| 简体中文、简洁度、破坏性操作确认 | 用户级 `AGENTS.md` | 所有会话常驻，但控制在约 2.6 KiB |
| 仓库使命、证据边界、最小子域路由、凭据禁写 | 根 `AGENTS.md` | 本仓库常驻 |
| 目录独有且每次都必须遵守的规则 | 最近的局部 `AGENTS.md` | 仅对应工作目录自动加载；从根启动时由短路由按需读取 |
| 规划、调试、测试驱动开发、文献与 Obsidian 工作流 | 现有技能 | 仅元数据常驻，命中任务后读取正文 |
| 实验恢复、远程运行、数据防泄漏和结果写回 | 2 至 3 个仓库级技能 | 仅任务命中后加载，不拆成大量微技能 |
| `grep/find/sed` 禁令、危险同步和远程入口 | `.rules` 与经过测试的 `PreToolUse` 钩子 | 命令执行时判定 |
| 格式化、静态检查、测试命令 | 项目脚本、技能、持续集成或 `Stop` 钩子 | 修改相关语言后才运行 |
| 沙箱、审批、模型、并发、功能开关 | `config.toml` | 配置层，不写成提示词 |
| 当前服务器、运行状态、数据路径和实验裁决 | 恢复文档、冻结配置、运行目录 | 按需读取，禁止复制到多个规则文件 |

`AGENTS.override.md` 只建议用于临时替换某一层规则，例如短期迁移或事故处置。它不应成为永久拆分机制，因为同层 `AGENTS.md` 会被忽略。`project_doc_fallback_filenames` 只解决其他文件名兼容问题，也不应作为分片机制。

## 实施验收
