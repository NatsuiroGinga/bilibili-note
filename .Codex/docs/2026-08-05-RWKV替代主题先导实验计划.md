# RWKV 替代主题先导实验计划

## 目标

在不读取最终测试、不修改 R2 工程和不弱化基线的前提下，快速判断“面向长时加密流的 RWKV 状态检测与漂移校准”是否值得作为 PINN 失败后的替代毕业论文主题。

## 任务边界

- 先导只使用冻结的开发训练、校准与开发验证数据。
- 优先复用 GeNIS 与 TQH-C2 的合法时间、会话或独立组信息；若现有数据无法构造无泄漏长序列，必须直接给出 `DATA_NO_GO`，不得按标签或模型结果重新拼样本。
- 现有 `thesis/experiments/llm_probe/` 只读。新增代码与配置放在 `thesis/experiments/rwkv_probe/`，运行制品放在该工程的唯一 `runs/` 子目录。
- 第一阶段只筛查 RWKV 递归状态是否具有任务价值；漂移校准只在第一阶段通过后进入第二阶段，不一次堆叠两个机制。
- 当前 R2 `F-A` 优先使用服务器。RWKV GPU 运行必须等待主代理确认 GPU 空闲后再启动。

## 阶段与状态

### 阶段 1：数据适用性与来源门禁

- [ ] 核验 GeNIS、TQH-C2 的官方来源、许可证、本地制品摘要、组与时间字段、标签粒度及最终测试隔离。
- [ ] 只用开发区构造长度 `4/16/32` 的候选因果序列，统计独立序列数、类别、来源、时长、缺失和跨组重叠。
- [ ] 若无法形成至少两个长度档、每个主要类别具有足够独立组的无泄漏序列，输出 `DATA_NO_GO` 并停止模型实现。

### 阶段 2：冻结比较合同

- [ ] 冻结共同数值字段、归一化拟合范围、样本与组顺序、训练预算、随机种子和开发验证面板。
- [ ] 参数匹配模型至少包含 GRU、轻量 Transformer 和普通 RWKV；CPU HGB 仅作非序列下界，不参与参数匹配。
- [ ] 主指标为预注册困难开发面板宏平均 F1；同时报告简单域、最差域、校准误差、峰值显存、吞吐和延迟。
- [ ] 单种子只作淘汰：RWKV 若不能相对最佳参数匹配神经基线提高至少 `0.01` 宏平均 F1，且也不能在性能差不超过 `0.005` 时实现至少 `1.5` 倍吞吐或降低至少 `25%` 峰值显存，则第一阶段淘汰。阈值冻结后不得因结果修改。

### 阶段 3：最小实现与 CPU 基线

- [ ] 使用 `writing-plans -> subagent-driven-development`；每个实现或修复任务执行一次精确范围的测试驱动开发。
- [ ] 建立独立 `uv` 工程、确定性数据加载器、增量日志、断点状态和 SwanLab 在线记录。
- [ ] 先运行 CPU 数据门禁与 HGB 下界；禁止为等待代码复审阻塞已经通过运行时门禁的实验。

### 阶段 4：单卡 5090 筛错

- [ ] 参数匹配的 GRU、轻量 Transformer、普通 RWKV 采用相同数据、字段、序列长度、训练步数、优化器调参次数和种子 42。
- [ ] 模型从小规模开始，目标峰值显存低于 `8 GiB`，单模型预计不超过 30 分钟；运行前向用户报告显存、时长和服务器开机需求。
- [ ] 所有运行各用唯一进程、目录、配置、日志、指标和 SwanLab 标识；失败不得覆盖或自动补跑。

### 阶段 5：路线裁决

- [ ] 第一阶段通过后，才增加漂移校准机制并做普通 RWKV、仅校准、完整组合消融。
- [ ] 单种子通过只授权三种子小型确认，不能写成论文有效性结论。
- [ ] 三种子仍通过后，才提出替代论文主题冻结建议；否则保留当前 R2 或评估主题二。
