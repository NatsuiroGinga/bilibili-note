# Qwen3-0.6B R2 正式首批运行实施计划

> **执行技能：** 使用 `subagent-driven-development` 执行；涉及生产实现时仅完成一次 `test-driven-development` 最小红绿灯周期。

**目标：** 在不更换数据、划分、可见字段、训练预算、评价协议或削弱基线的前提下，为官方后训练版 `Qwen/Qwen3-0.6B` 建立独立 R2 生成式入口，并启动冻结 59,656 条正式协议上的种子 42 `F-A/F-P/F-S`。

**架构：** 复用现有 Qwen QLoRA 模型、分词器和聊天模板构建路径，复用 R2 冻结数据加载、物理检查点、协议路由、三组视图和 G3 评价路径。新增入口只把统一或协议物理序列通过等参数量的有界旁路注入同一个 Qwen 生成式模型；QUIC v8 未放行时权重固定为 0 并路由 `UNKNOWN`，结论限定 TCP/UDP。

**技术栈：** Python、PyTorch、Transformers、TRL、PEFT、bitsandbytes、uv、SwanLab、Qwen3-0.6B。

## 全局约束

- DistilBERT 已封存，不作为启动前置门禁，不运行种子 43、44。
- 新文件和新运行目录不得覆盖历史 Qwen3-1.7B、DistilBERT 或 QUIC v8 制品。
- 正式数据、字段、样本顺序、训练预算、评价脚本和调参次数在三组间完全一致。
- 最终测试只按冻结正式协议使用，不用于修改模型、阈值、样本、权重或配置。
- 正式运行使用旧 RTX 5090 服务器、`uv run --no-sync`、独立 Python 进程和在线 SwanLab。
- ModelScope 为模型下载第一来源；模型身份、修订、配置摘要和权重摘要进入运行绑定。
- 本机不运行 `pytest`；最小红绿灯只在服务器执行一次。
