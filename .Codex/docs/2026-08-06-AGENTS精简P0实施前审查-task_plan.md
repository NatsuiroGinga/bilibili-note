# AGENTS 精简 P0 实施前审查计划

## 目标

在不修改现有规则、钩子、配置或代码的前提下，完成一次且仅一次的独立实施前审查，并给出 `GO`、`GO_WITH_FIXES` 或 `NO_GO` 唯一结论。

## 边界

- 输入：官方调研、用户级规则、仓库根规则、`llm_probe` 局部规则、用户级与项目级钩子配置及其引用脚本。
- 输出：`.Codex/docs/2026-08-06-AGENTS精简P0实施前审查.md`。
- 允许写入：本计划、审查笔记和最终审查报告。
- 禁止写入：任何现有规则、钩子、配置、脚本或代码。

## 阶段

- [x] 阶段 1：检查当前工作树差异，确认用户改动边界。
- [x] 阶段 2：完成 RWKV 路线恢复并读取适用规则和技能。
- [x] 阶段 3：盘点 P0 项、钩子配置、引用脚本与等价承载关系。
- [x] 阶段 4：核验两个钩子缺陷的根因、最小修复和测试现状。
- [x] 阶段 5：计算当前发现链字节、P0 预计字节和 32 KiB 余量。
- [x] 阶段 6：按严重、重要、次要分级，限定允许实施范围并形成唯一结论。
- [x] 阶段 7：验证报告内容、路径和未触碰范围。

## 关键问题

1. 每项拟删除规则是否已有实际生效、可验证的等价承载？
2. 是否存在先删文字规则、后补或假定钩子有效的时序风险？
3. 简体中文、凭据与防泄漏、路线恢复、GPU 通知、SwanLab、用户改动保护是否完整保留？
4. 服务器变量如何消除冲突，同时不把易变服务器状态写死为长期规则？
5. `security-guard` 路径与 `skill-forced-eval` 字段缺陷的根因、最小修复和验收是什么？
6. 当前各发现链与精简后各发现链是否均低于 32,768 字节，并留出可解释余量？

## 验收

- 报告逐项回答七项核对要求。
- 报告引用当前磁盘路径、行号、字节数和可复现检查命令。
- 报告只给一个最终判断。
- `git diff --check` 对新增文档无格式错误。
- `git status --short` 证明未修改现有规则、钩子、配置或代码。

## 状态

**审查完成**：报告已写入目标路径，定向验证完成，未修改现有规则、钩子、配置或代码。
