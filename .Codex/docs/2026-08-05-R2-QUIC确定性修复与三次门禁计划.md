# R2 QUIC 确定性修复与三次门禁实施计划

> **执行要求：** 后续实现必须使用子代理开发流程；项目已禁止测试驱动开发，本计划不运行 `pytest`、格式化、Pyright 或 Git 差异检查。

**目标：** 对当前用户态 QUIC 采集器实施一次且仅一次的确定性修复，以完整固定双向 socket 四元组、隔离每轮进程与队列状态、按单调包序号生成冻结发送时刻，并用三个不可重试的新运行裁决门禁。

**架构：** aioquic 客户端、用户态 UDP 代理和 quiche 服务端使用固定本地端口形成两条完整 UDP 四元组。每个诊断轮由独立采集进程启动全新服务端与代理，运行前后都验证四个端口可独占绑定；代理的每个方向以首个已接受报文建立本轮私有调度纪元，之后只按方向包序号、累计字节串行化时间、冻结时延和冻结随机流计算单调发送时刻。三个新身份串行运行，每轮客户端基础设施上限 240 秒，全部终态计入且不重试，最后由机器审计器输出唯一门禁状态。

**技术栈：** Python 3.10 标准库、aioquic 1.3.0、quiche 0.24.5、tcpdump 4.99.1、现有项目隔离工具链。

## 全局约束

- 用户已明确授权本任务作为“本机 CPU、服务器 GPU”规则的任务级例外，在新服务器执行 QUIC 修复、编译、采集与三次门禁。远程凭据只允许来自 `GPU_SSH_378` 与 `GPU_PWD_378`，不得输出或持久化。
- 主代理只读审计已确认新服务器项目根、隔离 Rust/quiche 二进制与数据盘均存在；cgroup `memory.max` 约 90 GiB、当前约 0.4 GiB、无 OOM 事件。不得把旧服务器进程、状态目录或环境事实当作前提。
- 修复次数固定为一次；出现新的实现缺陷或三次门禁失败后停止，不进入第二轮补丁。
- 网络参数保持 `p03/seed43/bulk`：双向时延 50 ms、抖动 0 ms、丢包率 0%、速率 20 Mbit/s、队列上限 1,000 包、负载 67,108,864 字节。
- 方向种子保持客户端到服务端 `373387841787797959`、服务端到客户端 `7996260466250834367`。
- 固定客户端到代理四元组为 `127.0.0.1:21012 -> 127.0.0.1:20012`。
- 固定代理到服务端四元组为 `127.0.0.1:22012 -> 127.0.0.1:4433`。
- 每轮使用新输出根和新启动器身份，不复用失败、超时或成功目录。
- 三次结果全部计入，不重试、不挑选、不补第四次。
- 通过也只请求独立复审，不自动恢复原字段矩阵；失败则保持 QUIC `UNKNOWN` 回退并停止扩充。
- 不修改恶意标签、最终测试不可见性、qlog 特权监督边界或内核真值否定声明。
