# R2 QUIC v8 审计门禁实现报告

## 结论

R2 QUIC v8 单轮审计器与目标合同测试已实现，并在旧服务器通过唯一目标测试。最终结果为 `4 passed in 0.04s`，可据此启动唯一 v8 run1。

## 修改文件

- `thesis/experiments/llm_probe/scripts/audit_r2_quic_v8_gate.py`
- `thesis/experiments/llm_probe/tests/test_r2_quic_v8_contract.py`

未修改 v8 配置、采集器、UDP 代理或公共审计器；这些文件由并行实现任务负责。

## 实现范围

- 验证 v8 与 v7 仅存在冻结允许差异，并绑定规范化投影长度 `5398` 与 SHA-256 `933d82e530200a7bd0dabd12d25a809aec4a14a9888e62a3b210b6c0295c44ef`。
- 按方向重放准入决策、接收批次、容量丢弃因果、服务完成和最终转发生命周期。
- 严格要求 `proxy-stats.json` 显式包含 `contract_error` 且值为 JSON `null`。
- 枚举并完整解析全部 qlog，分别验证整体 JSON 和 JSON 文本序列的冻结模式、trace 与事件结构，拒绝坏行和尾随残片。
- 从 PCAP 全局头开始逐记录解析至文件结尾，拒绝截断、尾随字节、非法时间戳或长度。
- 解析捕获日志，并要求捕获包数、过滤器接收包数为正且内核丢包严格为零。
- 将单轮摘要绑定到冻结配置、运行身份、输出根、启动器状态和唯一摘要路径；已有摘要或临时摘要存在时拒绝覆盖。

## 测试驱动记录

服务器红灯命令：

```bash
UV_CACHE_DIR=/tmp/uv-cache uv run --no-sync python -m pytest tests/test_r2_quic_v8_contract.py -q
```

红灯结果为测试收集阶段 `ModuleNotFoundError: No module named 'audit_r2_quic_v8_gate'`，退出码 `2`。同步收据：

`thesis/experiments/llm_probe/runs/hook-receipts/r2-quic-v8-audit-test-red-20260806.json`

首次绿灯尝试为 `3 passed, 1 failed`。根因是 `str.splitlines()` 会把 JSON 文本序列记录分隔符 `0x1E` 当作行边界并移除。最小修复改为只按 `\n` 分割，保留每条记录首个 `0x1E`，并只允许唯一末尾空片段；测试合同未改。

最终使用同一命令得到：

```text
4 passed in 0.04s
```

最终远端审计器 SHA-256 为：

`a61a1f21b51cd2871917ef64273e5920a5366b16af170e53914beb4cddc94d17`

该哈希与本机文件一致。
