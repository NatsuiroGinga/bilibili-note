# 服务器启动器安全 Hook 说明

## 目的

服务器非交互启动器若先执行 `set -u` 或 `set -o nounset`，再加载 `~/.bashrc`，可能在 `.bashrc` 读取尚未定义的 `PS1` 时立即退出。项目级 PreToolUse Hook 会在工具执行前机械检查这一顺序，并拒绝已确认存在错误顺序的服务器启动命令。

正确顺序固定为：

```bash
source ~/.bashrc
set -u
```

## 登记位置

- Hook 配置：`.codex/hooks.json`
- 守卫程序：`.codex/hooks/server_launcher_guard.py`
- 单元测试：`.codex/hooks/tests/test_server_launcher_guard.py`

新增 PreToolUse Hook 的匹配器覆盖 `Bash`、`exec_command` 和 `functions.exec`。原有 PreCompact 快照 Hook 已保留，事件、匹配器、命令、超时和状态提示均未改变。

## 判定范围

守卫只处理能够确认属于服务器启动或远程执行的命令，包括：

- `ssh` 或 Expect 中的 `spawn ssh`；
- `GPU_SSH`、GPU 执行或同步包装器；
- `/root/autodl-tmp/` 下的服务器实验路径；
- 内联 `screen` 启动命令；
- 命令引用且可安全读取的本地 `.sh`、`.bash`、`.zsh` 和 `.exp` 脚本。

守卫能够从直接 Bash 输入、`exec_command` 的 `cmd` 字段以及 `functions.exec` 中嵌套的 `tools.exec_command({cmd: ...})` 提取命令。脚本文件只在项目目录、当前工作目录或系统临时目录内读取，文件上限为 1 MiB。

以下情况返回中性放行，不包含 `permissionDecision=allow`，因此不会额外授予工具权限：

- 命令与服务器启动无关；
- Hook 输入格式未知或没有可提取命令；
- 引用文件不存在、不可读、超出允许目录或不是受支持脚本；
- 动态拼接使实际命令无法确定。

中性放行不替代 Codex 沙箱、权限审核或人工确认。

## 显式预检

当前会话不会热加载新 Hook。重启 Codex 前，或者在运行临时启动器前，可以显式预检：

```bash
python3 .codex/hooks/server_launcher_guard.py --file /tmp/launch_experiment.exp
```

输出为单行 JSON：

- `status=deny`：发现错误顺序，进程退出码为 `2`；
- `status=pass`：确认相关服务器启动脚本没有错误顺序，退出码为 `0`；
- `status=neutral`：无法确认或与服务器启动无关，退出码为 `0`，不代表授权。

也可以模拟 PreToolUse 标准输入：

```bash
printf '%s' '{"hook_event_name":"PreToolUse","tool_name":"Bash","tool_input":{"command":"ssh host '\''source ~/.bashrc; set -u; true'\''"}}' | python3 .codex/hooks/server_launcher_guard.py
```

## 生效方式

Hook 配置在 Codex 会话启动时加载，当前会话内修改不会热更新。完成本次修改后必须退出并重启 Codex，新的 PreToolUse 守卫才会自动执行。重启后仍应使用一次显式 `--file` 预检验证临时服务器启动器。

## 能力边界

- 守卫不执行 Shell，也不访问服务器。
- 守卫不是完整 Bash、JavaScript 或 Expect 解释器，不展开环境变量、命令替换、编码载荷或运行时生成的脚本。
- 守卫只拒绝可确定的错误顺序。动态内容无法判断时保持中性，调用方仍需遵守实验目录的启动规则。
- 守卫不会修改命令，不会自动插入 `source ~/.bashrc`，也不会批准任何原本需要审核的操作。
