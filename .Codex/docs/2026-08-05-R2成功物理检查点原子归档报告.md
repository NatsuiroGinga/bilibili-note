## 实现要点

- 拒绝参数、活动物理拟合或旁路探针进程、缺失或空成功制品、已有归档目标、已有源内收据及跨文件系统归档。
- 校验五个非空成功制品：`checkpoint-latest.pt`、`checkpoint-binding-manifest.json`、`zero-collapse-receipt.json`、`result.json`、`metrics.jsonl`。
- 移动前计算五项 SHA-256，将收据写入源根；收据只记录旧制品摘要，不包含自身摘要。
- 以 `superseded-by-probe-fix-<UTC>-<PID>` 创建唯一归档目录，使用一次目录级 `mv`，再以 `rmdir` 验证新源根为空后重建。
- 标准输出包含归档根、源根、旧检查点摘要、旧清单摘要与 `status=finished`。

## 红绿证据

唯一测试节点：

```bash
uv run pytest tests/test_archive_r2_successful_physics_fit.py::test_archives_complete_source_atomically_and_rejects_missing_artifact
```

红灯结果：失败，原因是目标脚本不存在：

```text
FileNotFoundError: .../scripts/archive_r2_successful_physics_fit.sh
```

首次实现验证发现本机 Bash 3 不支持关联数组，已以五个显式摘要变量作最小兼容性修复；远端 Bash 合同与归档语义未改变。

最终绿灯结果：`1 passed in 0.23s`。同一节点覆盖成功目录移动、归档收据摘要、空源根重建，以及缺制品时拒绝且不创建第二个归档。

## 风险与边界

- 本机测试通过替换固定项目根在临时目录模拟同文件系统行为，不执行服务器命令，也不替代服务端进程检查与实际制品核验。
- 收据写入后、目录移动前若发生底层 I/O 失败，脚本仅清理由本次生成且未移动的收据；成功制品不会被删除或逐文件复制。
- 主代理须按远程脚本合同同步、核对 SHA-256，并在确认无活动拟合或探针进程后执行。
