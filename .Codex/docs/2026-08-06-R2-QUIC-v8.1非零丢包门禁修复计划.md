# R2 QUIC v8.1 非零丢包门禁修复计划

## 目标

修复分层先导中非零丢包档位被错误判定为字节守恒失败的问题，不改变代理丢包、队列或动力学实现。

## 根因证据

- 失败连接 `56eabe0fc9ab2df5abdfe98f` 完成 4 MiB 下载，客户端、代理和抓包退出码均为 0。
- 客户端到服务端满足 `57281 = 57235 + 46 + 0` 字节和 `1093 = 1092 + 1 + 0` 包。
- 代理关停时等待、服务、队列和传播在途字节均为 0，发送错误为 0。
- 采集器在守恒检查后仍无条件要求 `random_drop_packets == 0` 与 `random_drop_bytes == 0`，与 `loss_percent=0.5` 的正式配置冲突。

## 变更边界

- 生产文件：`thesis/experiments/llm_probe/scripts/r2_quic_controlled_collect.py`。
- 测试文件：仅新增或修改覆盖该门禁的最小目标测试。
- 零丢包档位继续强制随机丢弃为零；非零丢包档位允许随机丢弃，但包、字节守恒和干净关停门禁保持不变。
- 不修改代理算法、丢包随机数、队列容量、现有 10 条成功样本或失败制品。

## 验收

1. 最小目标测试先复现非零丢包统计被拒绝，再验证修复后通过。
2. 零丢包配置出现随机丢弃时仍被拒绝。
3. 非零丢包配置若包或字节不守恒仍被拒绝。
4. 同步服务器后使用新运行标识启动 120 条分层先导，不覆盖 `v3`。
