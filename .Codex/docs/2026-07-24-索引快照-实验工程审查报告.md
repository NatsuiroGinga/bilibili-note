## 发现

### 严重（提交前必须处理）

1. **ns-3 真值生产端、校验端和测试端处于互不兼容的契约版本，当前快照不能验证自身生成的 CSV。**

   - `ns3/queue_truth_scenario.cc:74` 写出旧表头，且 `:188` 固定写入 `flow_probe_ns3_queue_v3`；字段包括 `service_budget_bytes`、`queue_start_bytes`、`offered_bytes` 等。
   - `src/flow_probe/ns3_truth.py:15` 和 `:28` 则只接受 `flow_probe_ns3_queue_v4` 及 `configured_capacity_integral_link_bytes`、`queue_start_l3_bytes`、`qdisc_received_l3_bytes` 等新字段。因此，对当前 C++ 生成器的任何实际输出调用 `flow-probe-validate-ns3-truth` 都会在表头/模式版本校验阶段失败，无法形成第一创新点所需的 ns-3 真值链路。
   - 同一索引的 `tests/test_ns3_truth.py:187` 断言 `qdisc_drop_l3_bytes`、`downstream_error_loss_ppp_frame_bytes`、`nonzero_l3_residual_count` 和 `nonzero_packet_residual_count`；但校验器在 `ns3_truth.py:717` 返回的是 `queue_drop_bytes`、`downstream_error_loss_bytes` 与单个 `nonzero_residual_count`。即使使用测试构造的 v4 CSV，首个成功路径也会因缺失键而失败。
   - 建议：将 C++ 生成器、Python `CSV_FIELDS`、摘要接口和测试同步到同一已定版模式（建议 v4），并新增“构建 C++ → 生成一个场景 CSV → Python 校验 → 断言摘要”的服务器冒烟测试；不要通过只修改测试断言来掩盖生产端与校验端的字段不一致。

### 重要（应在提交前处理）

1. **训练入口默认模型路径违反固定服务器模型路径约束，直接执行默认命令会在错误目录查找模型。**

   - `scripts/run_genis_hierarchical_qwen.sh:6` 默认值为 `models/Qwen3-1.7B`，且 `:12` 会要求这个相对目录存在；服务器规则要求固定使用 `/root/autodl-tmp/thesis/models/Qwen3-1.7B`。
   - 同时，已暂存训练配置（例如 `configs/genis_hierarchical_v2_qwen3_1_7b_seed42_pilot.yaml:2`）是 `Qwen/Qwen3-1.7B`。绕过脚本直接调用 `flow-probe-train` 时会转为远程模型标识，不满足“服务端必须使用绝对本地模型路径”的可复现要求，并可能触发非预期下载。
   - 建议：把脚本默认值改为固定绝对路径；为 `--model-path`/`model_id` 加入同一条路径白名单或在命令入口统一覆盖，并测试“不传模型参数时实际传给训练器的路径”。

   - 建议：在服务器 CI/提交门禁中加入 ns-3.48 编译和单场景 CSV 的校验测试，并把 CSV 模式版本和字段数作为生成器、校验器共享的契约断言。
