# 任务十二：非 Qwen 基座兼容性探针报告

## 1. 结论

- 本轮跨基座兼容性探针选择 `HuggingFaceTB/SmolLM2-1.7B-Instruct`。
- 该模型是公开、非门控、Apache-2.0 许可的 1.7B 指令模型，采用标准 `LlamaForCausalLM` 解码器架构，带官方对话模板，不需要 `trust_remote_code`。
- 本轮只验证当前生成式训练管线能否在非 Qwen 解码器上加载、注入 `all-linear` LoRA、返回隐藏状态并执行最小前向传播。它不替换 Qwen3-1.7B 主基座，也不构成跨基座机制增益证据。
- `BERT-base` 与 `DistilBERT` 是双向编码器和掩码语言模型，只能进入传统判别式基线，不能作为本课题的生成式主基座。
- DeepSeek 的 1.5B 推理蒸馏模型以 `Qwen2.5-Math-1.5B` 为底层，不能作为非 Qwen 迁移证据。DeepSeek 自有通用对话模型最小为 7B，超出 1B～3B 范围。

**当前状态**：SmolLM2、MiniCPM5 与 Llama 3.2 1B Instruct 的固定版本下载、逐文件 SHA-256 和 GPU 最小加载冒烟均已完成；MiniCPM5 隔离环境已完成。未启动训练。

## 2. 研究边界

1. 本轮必须使用指令或对话版本，不使用 Base 版本。当前恶意流量任务依赖官方对话模板和指令式标签生成，使用 Base 会把指令对齐差异混入 PINN 对照。
2. 候选必须是 1B～3B、非 Qwen、因果生成解码器，且能由 `AutoModelForCausalLM` 加载。
3. 最小加载冒烟只检查分词器对话模板、四位 NF4 加载、`output_hidden_states=True` 和 PEFT `target_modules="all-linear"`。不启动正式训练。
4. 后续若运行 S1/S2，必须沿用同一 GeNIS/ns-3 数据、稀疏状态掩码、物理残差、样本顺序、LoRA 超参数和评价指标。
5. 不直接比较不同分词器下的绝对生成损失，只比较同一基座内 S2 相对 S1 的变化。

## 4. MiniCPM5 专项核验

- **发布时间**：OpenBMB 官方仓库记录为 2026-05-19。
- **参数与架构**：总参数 1,080,632,832，非嵌入参数 679,552,512；24 层，隐藏维度 1536，16 个查询头和 2 个键值头；`model_type=llama`，`architectures=["LlamaForCausalLM"]`。
- **生成属性**：官方模型卡明确标记为因果语言模型，带 `enable_thinking` 可切换的官方对话模板。
- **非 Qwen 性质**：配置为标准 Llama 架构，模型由 OpenBMB 发布，不是 Qwen 蒸馏权重。
- **许可与门控**：模型卡声明代码与权重均为 Apache-2.0；公开非门控。
- **Transformers**：无需 `trust_remote_code`，但配置声明 `transformers_version=5.6.2`，官方快速开始要求 `transformers>=5.6`。
- **PEFT**：官方仓库提供 TRL+PEFT、LLaMA-Factory、ms-swift、Unsloth 和 XTuner 微调路线。
- **四位量化**：官方明确提供 MLX 4 位和 GGUF 量化发布；在 NVIDIA 上使用 bitsandbytes NF4 属于基于标准 Llama 架构与 PEFT 文档的兼容性推断，当前环境未完成实际加载，因此不能提前标为通过。
- **取舍**：模型大小、许可和架构均满足要求，但为了使用它而升级 Transformers 会改变已经通过回归的训练环境。本轮优先选择无需升级的 SmolLM2，将 MiniCPM5 保留为环境升级后的候选，而不是当前探针。
