# R2 种子 42 物理指标只读诊断

## 结论

种子 42 当前不能按冻结 `G3` 合同解释为“F-P 获得物理收益”。唯一首要根因是：**发送者级 TCP 真值被一对多绑定到相同的网络级公共观测，模型没有任何发送者级可观测输入，却被要求恢复八套不同的发送者状态。** 该目标在当前输入合同下不可辨识。

`ssthresh` 的 `UINT32_MAX` 哨兵值未经语义转换直接进入状态监督，是第二个确定问题。F-A 的近零残差则主要说明预测落入固定方程的零空间，不能作为 F-P 必须击败的物理门槛。当前不应扩展到种子 43、44，也不应通过调权、延长训练或更换检查点修补结果。

本报告只做本地制品与源码的只读诊断，没有修改生产代码、配置或数据，没有启动任何实验，也没有读取最终测试。

## 当前结果

| 组别 | 开发验证宏平均 F1 | 总体状态 MSE | 总体残差 MSE |
| --- | ---: | ---: | ---: |
| F-A | 0.9245755 | 3.72274 | 4.6976e-6 |
| F-P | 0.9406325 | 6.13705 | 3.74138 |
| F-S | 0.9280703 | 6.98770 | 3.36009 |

补充结果：F-P 的 TCP 残差 MSE 为 `7.48274`，UDP 为 `1.469e-5`；F-A 的 TCP 残差 MSE 为 `6.46e-6`。

检测结果说明 F-P 在本种子上比 F-A 高约 `1.61` 个绝对百分点，比 F-S 高约 `1.26` 个绝对百分点。该结果与物理主张分开解释，不能用于挽救已经失效的物理比较。

## 根因排序

### P0：发送者级目标与网络级输入粒度不一致

物理加载器按 `(sequence_id, source_window_index)` 将一条 TCP 公共窗口一对多连接到发送者真值，再把 `sender_index` 加入序列身份。模型输入仍只有公共窗口的总包数、总字节数、包速率和字节速率，`sender_index` 和任何发送者级被动历史都不进入输入。

验证集包含 `3,840` 个公共 TCP 窗口、`30,720` 条发送者记录，即每个公共窗口固定对应 `8` 个发送者。相同输入下，八个发送者真值的组内分歧率如下：

| TCP 状态 | 有分歧的公共窗口比例 |
| --- | ---: |
| `cwnd_start` | 98.91% |
| `cwnd_end` | 99.74% |
| `ssthresh_start` | 61.64% |
| `ssthresh_end` | 62.16% |
| `bytes_in_flight_start` | 99.04% |
| `bytes_in_flight_end` | 99.87% |
| `acked_bytes` | 99.43% |
| `loss_event_count` | 51.09% |
| `timeout_event_count` | 1.35% |
| `rtt_mean` | 99.79% |

因此，同一确定性模型会对八条相同历史产生同一预测，却面对八套不同真值。该问题同时解释 TCP 状态误差和由预测状态计算的 TCP 残差异常。它不是增加轮数或调节损失权重可以解决的优化问题。

证据：

- `thesis/experiments/llm_probe/src/flow_probe/r2_final_physics_fit.py:897`：公共窗口与伴随真值只按 `sequence_id` 和 `source_window_index` 连接。
- `thesis/experiments/llm_probe/src/flow_probe/r2_final_physics_fit.py:941`：TCP 使用 `one_to_many` 连接。
- `thesis/experiments/llm_probe/src/flow_probe/r2_final_physics_fit.py:960`：`sender_index` 只追加到序列身份。
- `thesis/experiments/llm_probe/configs/r2_final_physics_fit_seed42.yaml:33`：模型输入只有四个公共聚合观测。
- `.Codex/docs/2026-08-05-R2最小旁路种子42启动报告.md:51`：已有运行记录明确记载一对多展开为发送者序列。

### P1：`ssthresh` 哨兵值未作语义化处理

验证 TCP 真值中，`ssthresh_start` 和 `ssthresh_end` 约 `39%` 为 `4294967295`。当前配置统一除以 `1e6`，哨兵仍变成 `4294.967295`，而常规中位值约为 `0.00268`。这不是普通连续状态，而是“未设置或无限阈值”的离散语义。

该问题与拟合日志完全一致：TCP 状态损失长期约为 `400`，共享与 UDP 状态损失则约为 `1e-3` 至 `1e-2`。训练区标准差约为 `2146.7`，后续标准化状态 MSE 会压缩这一异常，但不能修复训练目标语义。

证据：

- `thesis/experiments/llm_probe/configs/r2_final_physics_fit_seed42.yaml:60`：两个 `ssthresh` 字段进入连续状态向量。
- `thesis/experiments/llm_probe/configs/r2_final_physics_fit_seed42.yaml:79`：两个字段均按 `1e6` 缩放。
- `thesis/experiments/llm_probe/runs/r2-minimal-sidecar-physics-fit/tcp-udp-v2-seed-42/metrics.jsonl`：TCP 状态损失约 `400` 的逐步证据。

### P2：F-A 近零残差是方程零空间捷径，不是可信物理优势

F-A 和 F-P 的固定残差都由预测状态计算，算子本身不是常数零函数。但共享守恒、UDP 守恒和 TCP 分段关系都是低维约束作用于更高维状态，存在大量零空间。预测状态只要内部满足等式，即使不接近真值，也可得到近零残差。

物理拟合中，统一 TCP 支路和路由 TCP 支路的状态损失处于同一数量级，残差却相差约六个数量级。这证明残差近零没有同步证明发送者状态正确。现有“零坍缩收据”只证明人工非平凡状态能产生非零残差且梯度可回传，不能证明模型预测没有落入方程零空间。

F-A 统一支路也不具有硬编码零输出：它使用与 TCP、UDP 专家相同的状态头和固定方程。因此准确表述应是“结构允许并实际出现了物理一致性捷径”，而不是“代码直接返回零”。

另外，F-A 与 F-P 在评价时共用 validation 真值、真值掩码、训练区归一化和逐状态、逐方程、逐协议等权聚合；但二者的训练激活语义不同。F-A 的统一组件默认对全部样本激活，F-P 的协议专家只对对应协议激活。特别是统一 UDP 组件在 TCP 行也计算齐次守恒残差。故二者的物理指标分母相同，不代表训练约束机会完全相同。

证据：

- `thesis/experiments/llm_probe/src/flow_probe/r2_final_experts.py:257`：状态经 `softplus` 产生，不是硬编码零。
- `thesis/experiments/llm_probe/src/flow_probe/r2_final_experts.py:327`：共享守恒只约束一个平衡式。
- `thesis/experiments/llm_probe/src/flow_probe/r2_final_experts.py:427`：TCP 四段残差只使用部分预测状态。
- `thesis/experiments/llm_probe/src/flow_probe/r2_final_experts.py:523`：UDP 六个状态只受两个守恒式约束。
- `thesis/experiments/llm_probe/src/flow_probe/r2_final_experts.py:657`：F-A 统一 TCP、UDP 组件没有协议激活掩码。
- `thesis/experiments/llm_probe/src/flow_probe/r2_final_physics_fit.py:1386`：F-P 训练按协议路由建立激活掩码。
- `thesis/experiments/llm_probe/src/flow_probe/r2_final_distilbert_probe.py:1425`：三组重新加载同一物理划分。
- `thesis/experiments/llm_probe/src/flow_probe/r2_final_distilbert_probe.py:1428`：归一化只由 train-fit 真值计算。
- `thesis/experiments/llm_probe/src/flow_probe/r2_final_distilbert_probe.py:1484`：F-A 选择统一支路，F-P/F-S 选择路由系统。
- `thesis/experiments/llm_probe/src/flow_probe/r2_final_distilbert_probe.py:1629`：状态与残差均按分量等权。
- `thesis/experiments/llm_probe/src/flow_probe/r2_final_distilbert_probe.py:1843`：TCP 与 UDP 最终等权。

## 已排除项

1. **检查点未加载不是首因。** 三配置绑定同一检查点和同一不可变清单；入口在评价前核对文件摘要、内部绑定、容量收据和零坍缩收据，并以 `strict=True` 分别加载路由系统和统一支路。任何未加载或键不一致都会直接失败。物理拟合日志本身也已经出现路由 TCP 残差远大于统一 TCP 残差，异常早于分类探针。
2. **状态顺序错位不是首因。** TCP 专家逐字断言十个真值字段的冻结顺序；加载器按配置顺序构造状态矩阵。
3. **固定公式整体错误不是首因。** 将 validation 真值代入当前四段 TCP 公式，并应用相同观测阶段掩码，四个方程的等权总体残差约为 `3.25e-6`，与 F-P 的 `7.48274` 相差约六个数量级。公式能描述真值，问题在预测状态。
4. **路由错误不是首因。** 正式物理 validation 只接受 TCP、UDP，按冻结 `route_index` 选择专家；每个样本恰好激活一个协议支路。当前异常也只集中于 TCP，UDP 残差为 `1.469e-5`。

## F-P 相对 F-S 的有限结论

F-P 的总体状态 MSE 从 F-S 的 `6.98770` 降至 `6.13705`，相对降低 `12.17%`。该差异在冻结聚合口径下是真实的，因为 F-P 与 F-S 使用同一系统、检查点、真值、掩码、归一化和聚合，F-S 只在同协议内置换观测供体。

但该结果只能说明“正确的网络级聚合历史比协议内置换历史包含更多状态相关信号”，不能证明发送者级 TCP 状态已经被恢复。F-P 的残差 MSE 反而比 F-S 高 `11.35%`，进一步说明当前状态误差与残差误差没有形成一致的物理证据链。

在逐协议、逐状态制品回收前，也不能声称 `12.17%` 改善同时覆盖 TCP 和 UDP。

## 下一最小 CPU 实验

在修改模型或重新使用 GPU 前，只执行一个不训练的 CPU 诊断包：

1. 从现有三组 `physical-validation-clusters.jsonl` 读取逐簇预测，不重跑模型。
2. 按 TCP 的十个状态、四个阶段方程和 UDP 的六个状态、两个方程重算 F-A/F-P/F-S 指标，并核对三组真值、掩码、归一化和簇顺序摘要逐项相同。
3. 对每个相同公共历史的八个 TCP 发送者计算组内方差和“使用组均值预测”的不可辨识下界；当前仅依据真值计算得到 TCP 十状态等权下界约为 `0.36894`。
4. 增加三个只读参照：全零状态、同输入组均值状态、真值状态。分别计算状态 MSE 和固定残差，用于量化 F-A 与零空间捷径的接近程度。
5. 输出唯一裁决：若现有 F-P 预测显著高于同输入组均值下界，记录为训练失败；无论是否高于，该发送者级合同都因一对多不可辨识而不能进入正式物理主张。

完成该 CPU 诊断后，再决定新的数据合同。合法方向只有两类：一是构造部署时同样可得的发送者级被动历史，与发送者级真值一对一绑定；二是把 TCP 目标改成与网络级公共观测同粒度、且仍有严格动力学含义的状态。不得把 `sender_index`、仿真身份或连接标识直接加入推理输入，也不得把 `UINT32_MAX` 当作普通连续数继续训练。

## 制品一致性限制

本机物理拟合目录存在混合世代：当前 `checkpoint-latest.pt` 和 `checkpoint-binding-manifest.json` 的修改时间晚于 `result.json`、`run-binding.json` 和 `metrics.jsonl`，且摘要绑定内容不完全一致。三份探针配置绑定的是较新的检查点与清单，正式入口通过说明探针实际使用了该绑定；但本地旧结果和旧日志不能冒充新检查点的完整训练收据。

服务器在本次诊断期间连接被本机代理关闭，因此没有回收三组逐簇物理预测。本报告对三组总指标采用当前已核验汇总，对逐状态预测分布不作推测。上述下一最小 CPU 实验必须在逐簇制品回收后执行。
