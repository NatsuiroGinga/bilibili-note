### 4.4 对本课题的直接含义

1. **工作量上的缺口是「公式与定理数」，但这不是应当补的方向**：朱的 33 式与 3 个定理中，**可用于正文的可核结论远少于其数量**。本课题应把「理论深度」落在**能自证并被实验佐证的命题**上（例如 H.1.4 的留一基线无偏性——一条真正能被验证的代数恒等式，优于三条无证明的定理）。
2. **可复用的理论写作体例**：`陈述 → 展开 → 分阶段解释物理含义`（定理 1 的三阶段写法），**但不得复用其强度词**。
3. **必须避免的形态**：把「假设」写成「引理」（引理 1 的前提即假设）；把「论证散文」冠以「证明分析」（定理 2）。本课题若出现同类写法，属可被答辩直接击穿的缺陷。

### 4.5 本课题应做到的理论深度档位（主代理 2026-09-11 验收问答回填）

**建议档位：1–2 个自证命题 ＋ 完整初等证明（正文给陈述与编号前提，附录给 3–5 行证明）＋ 1 段可复现数值核验 ＋ 1 条适用边界声明。** 不追求朱式的 3 定理数量。

| 件 | 内容 |
| --- | --- |
| 命题 P1 | 留一基线下的组相对优势是 REINFORCE 梯度的**无偏**估计（前提两条：基线不含自身样本；`y_(1..k) ~i.i.d. π_θ(·\|x)`） |
| 命题 P2（可选） | 全组均值基线的期望为 `(1−1/k)` 倍 ⇒ 为「用留一而非全组均值」这一**设计选择**提供依据 |
| 证明 | 3–5 行，只用 `E_{y~π_θ}[∇_θ log π_θ(y\|x)] = 0`（对 `Σ_y π_θ = 1` 求导）；不引入未验证假设 |
| 数值核验 | 精确枚举（27 组 / 机器精度）作附录一小节，脚本落盘可复现 |
| 边界声明 | 命题只保证**期望无偏**；**不承诺方差缩减、不承诺收敛率** |

**三条档位理由**：

1. **「不低于参照」的实质标准是「每条理论主张可被独立核验」，不是条数**。朱的 3 条中 0 条给出编号假设、误差界或收敛率，1 条前提是被假定的、1 条「证明」是论证散文。1–2 条能被复算的命题，占据的是同一位置。
2. **「不过度声称」的手段是压条数**：每多一条命题就多一份被追问「前提成立吗」的风险。只保留能写清前提的那一条。
3. **方差缩减不得进命题**——`Var[(R−b)G] = E[R²G²] − 2E[b]·E[RG²] + E[b²]·E[G²]`，只有 `b` 与 `R` 相关性足够时方差才下降；组内留一基线的 `b` 是噪估计，**无一般性方差缩减保证**。方差主张若要有，只能由同预算实测承担，不由命题承担。

**同时明确放弃朱式强度词**：「全局更优均衡点」「严格约束 Hessian 的迹」「充要条件」「从根本上提升」一律不用（上游 §9.4 已判其无对应定理条件）。

### 6.1 主指标建议：`对抗检出缺口（FNR）+ 干净 FPR` 双主轴

**建议**：以 **maskdga 面板的 FNR（主面板）** 与 **干净面板的 FPR** 构成**并列双主轴**，两条都必须单独报告且各自设门；k2／krand 作为次级面板分列。

**理由（三条，均可指向本课题实测）**：

1. **AP 在本任务无动态范围**——三面板 AP 在 A／B／C 三臂全部封顶于 `1.0`（排序未破），这是本课题已实测的判据指标教训（task_plan §5.6.2）。**主指标不能是 AP**。
2. **单轴检出会重演 B／C 的失败形态**——B／C／D 的对抗检出已近饱和（maskdga 缺口 `68.2%` → `1.8%` → `0.85%`），代价却是干净 FPR 单调恶化（`0.01453` → `0.01973` → `0.02707`）。若只报检出，B／C 会被误判为「持续改善」；**只有双轴才能把「真改善」与「用误报换检出」分开**（这正是 G2＋G3 两道的由来）。
3. **这是本课题相对朱的结构性增量，不是加码**——朱的主指标是**单侧**的 `RA@PGD-20`（「别被打垮」），代价项（干净准确率）不单列、无阈值门。本课题的任务是**检测器**，病灶天然双侧（漏检 vs 误报），因此**双主轴由任务结构决定**；把它降为单轴才是自我削弱。

**必须一起写的口径**：
- 阈值统一为 `0.5`（与七臂可复算口径一致）；同时报**源 1% FPR 工作点**作稳健性检查——G6 已要求两个操作点的 `ΔFPR` 符号一致。
- **同族／异族分组报告**（task_plan §5.2 强制）：训练扰动族与评价扰动族必须分开列；**泛化主张只能基于异族列**。
- 使用 T21–T25 时**必须标注「目标知情评价面板」**，不得称独立泛化确认、零回流或无偏最终估计。

**建议 1：把 C 臂改造为「Drichel 均匀混合臂」（恒定 1:1 配比）——建议采纳。**
- **对应朱的哪个做法**：对位 **FreeLB 所在的「同架构强基准」层**——即「任务相同、训练机制不同」的强基准。
- **本课题的差量在哪**：七臂读数显示，FPR 最高的两臂恰是**批内恶意占比失衡**的两臂（C 全入批时批内恶意:良性 ≈ `5:1`，FPR `0.02707`）。Drichel 2404.06236 **§4.4.2**（`PDF p.7`，Fig 1／Fig 2 批次构成条带）用的是**恒定 `256:256 = 1:1`** 配比（本地全文笔记 [`2024-Drichel-DGA检测鲁棒分类.md`](../../../wiki/papers/attack-detection/dga/2024-Drichel-DGA检测鲁棒分类.md) 第 79、94 行，2026-09-11 复核）。当前**没有任何一个臂在恒定 1:1 下报数**，因此「组相对过滤的增益」与「配比变化」**尚未分离开**。补上该臂后，才能把 F 的增益归因到机制而非配比——这同时是 **G4 近邻解释门**的要求（不能被「只是更多样扰动样本」解释）。

**建议 2：不把 CharBot 静态增广单列为独立臂——建议不采纳（若要，只作附录补充臂）。**
- **理由 (a) 算子泄漏**：CharBot 2 位替换正是评价面板 `k2` 的算子来源（task_plan §5.6.1 面板判读）。用同源算子做训练，会把 `k2` 面板从「未见扰动族」降为「同族」，**使该列的泛化主张失效**。
- **理由 (b) 与 B 非正交**：B 已是朴素增广；「离线一次性生成 vs 在线生成」改变的是**生成时机**，不是新因素。加进主表会把四臂结构扩成五臂，破坏 `2×2` 的归因结构（AGENTS：`2×2` 不得夹带第三模块）。
- **理由 (c) 结论已知**：CharBot 原文自报一次性静态增广在低 FPR 下失效（本方案 §4.3 已登记），单列该臂只会重复既有负结论。
- **对应朱的哪个做法**：朱的六个基线**没有一个是自家方法的变体**；为其加一条「生成时机」臂不符合该结构。

**建议 3：不照搬 CAT／Adv-LoRA／DiffPurify——建议不采纳。**
- **理由**：三者都作用于**连续特征空间**（对比学习对齐、低秩矩阵对抗微调、扩散净化），且需要 LoRA 微调或扩散模型等额外设定；本课题的对象是 `24.18M` 参数的**离散字符序列**检测器。强行实现属「为凑基线而凑」，且会引入与主线无关的实现风险。

### 7.3 ⚠️ 三处必须登记的原文／实现差异（引用前必读）

1. **残差块数：以「1 个」为准，图注「6 Residuals」是矛盾项。** 论文 §3.2 正文逐字：*"For binary classification, **we use a single residual block**."*（p.3）；官方代码同样**只实例化一个** `ResidualITsec`。但**图 1(a) 的文字层含「6 Residuals」标注**（p.3），与正文和代码**都矛盾**（M-ResNet 是 11 块，也对不上 6）。**裁决：以正文＋代码为准，B-ResNet = 1 个残差块。** 引用架构时**不得写 6 块**；若正文需要展示该图，须加注说明图注与正文不一致。
2. **输入长度：论文用 253（完整域名），官方代码默认 63（e2LD）。** 论文 §3.1（p.3）明确「**不删除 TLD**」，左零填充到 **253**；官方代码 `seq_len` 默认 **63** 且注明用于 **e2LD**（剥离 TLD 的有效二级域）。**两者不是同一个输入视图**，混用会同时改变「输入长度」与「TLD 是否存在」两个因素。
3. **2020 年论文本身未给出作者自有代码链接。** 该版 PDF 全文检索只找到参考文献中 Bader 的 DGA 实现（`github.com/baderj/domain_generation_algorithms`）。**本节所用官方实现出自 2024 年的 `robust-dga-detection` 库**（该库的模型定义回溯引用 2020 ARES 论文）。引用「官方实现」时须写明**是哪个仓库**。

### 7.5 训练协议对齐

- **可对齐项**：损失（BCE）、优化器（Adam）、batch size（128）——论文明确给出（p.3），与现有 p2p3 arm 循环的 batch 128 一致。
- **不可直接对齐项**：**权衰减、学习率与调度、训练轮数、阈值选择规则**——论文 §3.2 未给出，官方仓库又没有训练脚本，**本轮无法核验**。⇒ **必须作为「无直接文献依据的任务化设定」登记**（根 `AGENTS.md` 魔法数字门禁），不得冒充「官方微调协议」。
- **现有可分性**：我们侧 p2p3 的冻结规格是 `3 epochs`、Adam 分层 lr（骨干 `1e-6`／分类头 `1e-4`）、seed `42`、阈值 `0.5`。**B-ResNet 的层结构与 DRIFT 完全不同，「分层 lr」这一项无对应物**，需要重新定义（建议：单组 lr）。
- **一条强约束**：两骨干比较必须**共享同一冻结数据成员、切分、批大小、评价面板与阈值规则**（`thesis/AGENTS.md`），因此 B-ResNet 的轮数与 lr **不能按「跑出最好结果」调**，须在看结果前冻结。
