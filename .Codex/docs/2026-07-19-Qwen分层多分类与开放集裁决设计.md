# Qwen 分层多分类与开放集裁决设计

## 1. 目的

本设计只服务于第一创新点收敛路线的阶段 B：判断 `Qwen/Qwen3-1.7B` 作为生成式恶意流量检测基座是否具有继续引入 PINN 的研究价值。

本阶段不把多分类、未知拒识或 Qwen 本身写成第一创新点，也不提前命名最终方法。

## 2. 固定实验问题

在 GeNIS 2025 的同一防泄漏清单上回答四个问题：

1. 一个共享 QLoRA 适配器能否根据任务提示同时完成攻击家族分类和已见攻击子类分类。
2. 自由生成 JSON 的合法率、分类性能和推理成本是否达到可用水平。
3. 只使用域内验证集校准的生成概率能否拒识 `dos-icmp`、`dos-pushack` 和 `dos-udp`，并降低传统梯度提升树的良性误报代价。
4. 生成式输出相对同一 Qwen 基座的分类头是否提供了可验证价值，而不是只增加生成成本。

## 3. 数据契约

- 数据版本固定为 `flow_probe_hierarchical_sample_v2`。
- 随机种子固定为 `42`、`43`、`44`；先运行种子 42 探针，通过后再扩展其余种子。
- 家族标签为 `benign`、`bruteforce`、`dos`。
- 已见子类标签为 `benign`、`ftp`、`smb`、`ssh`、`hulk`、`slowloris`。
- 未知攻击统一记为 `unknown_attack`，但不进入监督训练。
- 每条提示词只包含八个统一数值字段和任务标签空间，不包含样本标识、来源、时间戳、地址、端口或原始攻击子类。
- 家族与子类训练样本合并为一个确定性打乱的多任务训练文件，共享一个 QLoRA 适配器。相同底层流量可因任务不同出现两次，但必须保留不同的 `task`。
- 未知攻击拒识阈值只能用域内子类验证集计算。三个域外测试标签不得参与温度、阈值、提示词或训练轮数选择。

## 4. 模型对照

### 4.1 M0-G：生成式多任务基线

- 基座：`Qwen/Qwen3-1.7B`。
- 训练：4 位 NF4、BF16、秩 16 QLoRA、关闭思考模式、仅对完成部分计算损失。
- 输出：严格单键 JSON，例如 `{"label":"hulk"}`。
- 适配器：家族任务和子类任务共享同一个适配器。

### 4.2 M0-C：同基座分类头对照

- 使用相同 Qwen 基座、相同八字段输入、相同训练/验证/测试清单和相同随机种子。
- 家族和子类分别使用分类头，避免把不同标签空间强行合并为一个固定头。
- 记录参数量、训练时间、显存、吞吐量和推理延迟。
- M0-C 在 M0-G 种子 42 探针有效后实施，单独形成后续实现计划。

### 4.3 传统对照

- 多数类、逻辑回归和直方图梯度提升树。
- v1 结果保留为错误发现前的历史制品；正式比较重跑 v2，确保清单哈希和运行卡一致。

## 5. 两条生成式评价路径

### 5.1 自由生成路径

模型按任务提示自由生成最多 16 个新令牌。解析器只接受单个 JSON 对象、单个 `label` 键及当前任务允许的标签。

非法 JSON 不静默修复，按错误预测计入，并单独报告：

- JSON 合法率；
- 非法输出数量；
- 宏平均 F1；
- 各类召回率；
- 良性误报率；
- 输入/生成令牌数、吞吐量和延迟分位数。

自由生成是否直接输出 `unknown_attack` 只作为附加诊断，不作为正式开放集裁决依据。

### 5.2 候选完成概率路径

对于提示词 \(x\) 和候选标签 \(y_j\)，构造固定完成串：

\[
c_j=\texttt{\{"label":"}y_j\texttt{"\}}.
\]

若候选完成包含 \(m_j\) 个令牌，其长度归一化条件对数似然定义为：

\[
s_j(x)=\frac{1}{m_j}\sum_{k=1}^{m_j}
\log p_\theta\!\left(c_{j,k}\mid x,c_{j,<k}\right).
\]

长度归一化用于降低 `ftp` 与 `slowloris` 等标签令牌长度不同造成的系统偏差。第一轮固定温度为 1，不利用域外标签调节温度：

\[
q_j(x)=\frac{\exp(s_j(x))}{\sum_{l=1}^{K}\exp(s_l(x))},
\qquad
\hat y(x)=\arg\max_j q_j(x).
\]

已见类置信度为：

\[
u(x)=\max_j q_j(x).
\]

只在域内子类验证集上，以最大已知类拒识预算 \(\rho=0.05\) 校准阈值：

\[
\tau=Q_{\rho}\!\left(\{u(x_i)\}_{x_i\in\mathcal D_{val}}\right).
\]

使用离散样本分位数的较低取值，并验证实际拒识率不超过 5%。测试阶段规则为：

\[
\tilde y(x)=
\begin{cases}
\texttt{unknown\_attack}, & u(x)<\tau,\\
\hat y(x), & u(x)\ge\tau.
\end{cases}
\]

## 6. 指标与裁决条件

### 6.1 域内指标

- 家族宏平均 F1、平衡准确率、各类召回率和良性误报率。
- 已见子类宏平均 F1、配置标签宏平均 F1、各类召回率和良性误报率。
- 子类测试集已知类拒识率。
- JSON 合法率和非法输出数量。

### 6.2 域外指标

- 每个未知场景的未知攻击召回率。
- 混合域外集合的良性误报率。
- 仅对实际出现类别计算的宏平均 F1。
- 对全部配置类别计算的宏平均 F1，避免遗漏类别被隐藏。
- 三个场景分别报告，禁止只给合并分数。

### 6.3 效率指标

- 训练总秒数、每步秒数、峰值显存和最终适配器大小。
- 自由生成与候选评分分别报告样本/秒、输入令牌、生成令牌、P50/P95 延迟。
- 与传统模型及 M0-C 的训练、推理成本分别比较。

### 6.4 阶段 B 通过条件

满足以下任一条件，才值得进入 PINN 数学有效性阶段：

1. M0-G 在困难子类或未知拒识的召回率—误报率权衡上稳定优于传统梯度提升树；
2. M0-G 与 M0-C 性能接近，但统一多任务生成、输出合法性或后续连续状态联合建模提供明确结构价值，且成本可接受；
3. 失败分析证明问题来自单流表示，并能通过时间序列输入形成可检验的新探针。

若 M0-G 在域内、域外和结构价值上均不成立，应先调整输入序列或基座，不得直接加入 PINN 包装。

## 7. SwanLab 记录规则

- 训练由 `SFTTrainer` 每个 `logging_steps=1` 步骤记录损失、学习率、梯度范数和训练进度。
- 评估每完成一个固定批次记录累计 JSON 合法率、宏平均 F1、样本数、吞吐量和显存，而不是只在全部结束后上传一个 `step=0` 数据点。
- 家族测试、子类测试及三个域外场景使用独立指标前缀。
- 每次运行保存 `console.log`、阶段专属 `swanlog/`、配置、环境、数据清单、结果、预测、关键云端指标查询和 `artifact_manifest.json`。
- 云端验收同时检查运行状态、指标历史数据点和实际图表页。

## 8. 实施顺序

1. 验证 v2 三种子清单并重跑传统基线。
2. 构造种子 42 的确定性多任务训练与验证文件。
3. 测试驱动实现严格多标签解析、候选完成评分、验证集阈值校准和开放集指标。
4. 运行种子 42 的 200 步探针，检查学习曲线、JSON 合法率、显存和推理成本。
5. 探针无工程错误后运行完整一轮训练。
6. 根据种子 42 结果决定是否扩展种子 43、44，并进入 M0-C 对照。

## 9. 失败边界

- 不把测试标签用于阈值选择。
- 不用正则表达式从非法自然语言中“抢救”标签。
- 不因网页图表缺失而否定已由云端指标接口确认的数据，也不因接口有数据而省略图表验收。
- 不把生成概率评分包装成 PINN 创新。
- 不在当前阶段加入 Stiefel-LoRA、mHC、GRPO 或物理残差，避免同时改变多个变量。
