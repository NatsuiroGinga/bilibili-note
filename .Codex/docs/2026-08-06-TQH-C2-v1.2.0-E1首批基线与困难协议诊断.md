# TQH-C2 v1.2.0 E1 首批基线与困难协议诊断

## 结论

E1 的数据与执行门禁可运行，但跨域有效性门禁不通过。

- 域内开发验证上，HGB 与 XGBoost 的宏 F1 均为 `0.999618`。
- 当训练数据不包含测试床 C 时，C 上宏 F1 降至 `0.128186～0.146574`，恶意召回降至 `0～0.003272`。
- 七个允许字段中，多个单字段已能取得很高的域内或 C 域内宏 F1；删除任一字段的最大绝对宏 F1 变化仅 `0.0002183`。
- 输入没有包含 IP、端口、`conn_state`、`capture_id`、`profile` 等禁止字段，因此没有发现直接字段泄漏。结果支持“存在强数据生成捷径”，不支持“已经获得真实跨域泛化”。
- 最终测试仍未分配、未读取；校准区和 8 个未分配 capture 组也未用于模型训练或诊断。

- 数据版本：TQH-C2 v1.2.0 官方小包，E0 已完成 ZIP 哈希、Parquet 行数和标签联结核验。
- 开发协议：`thesis/experiments/llm_probe/runs/data-prepared/tqh-c2-v120-e1-dev-seed42-v1-20260806T092613Z/protocol/`
- 协议样本哈希：`9ddcc80a30a374dbdf1339a161f02019c16536ffc1cc7f73dce2465ab0c3daac`
- 训练：24 个完整 capture 组，83,099 条。
- 校准：8 个完整 capture 组，26,216 条，本轮未加载。
- 验证：8 个完整 capture 组，19,212 条。
- 未分配：8 个完整 capture 组，只保留组身份摘要，不进入 `samples.parquet`。
- 分组验证：训练与验证的 `capture_id` 交集为 0，`timing_group_key` 交集为 0。
- 标签：`malicious_c2` 与 `non_c2`；官方小包实际 `unknown=0`，不得解释为未知攻击能力。
- 字段：`duration`、`orig_bytes`、`resp_bytes`、`orig_pkts`、`resp_pkts`、`orig_ip_bytes`、`resp_ip_bytes`。

## 共同预算

- 随机种子：`42`。
- HGB：学习率 `0.1`、100 轮、31 个叶节点、关闭提前停止。
- XGBoost：学习率 `0.1`、100 棵树、最大深度 6、`hist`、CPU 单线程。
- 两模型使用相同训练样本、样本顺序、平衡类别权重和验证视图。
- 调参试次为 0，配置来源为公开默认值。
- 本轮为本地传统 CPU 基线，没有使用在线 SwanLab；正式 GPU 实验的在线跟踪规则未被放宽。

| 训练到验证 | 模型 | 宏 F1 | 恶意召回 | 良性误报率 |

## 指标口径

公共评估器将良性标签硬编码为字面值 `benign`，而本协议负类名称为 `non_c2`，所以公共摘要中的 `benign_false_positive_rate` 为空。本文与困难诊断制品统一按混淆矩阵计算：

`良性误报率 = 真实 non_c2 被预测为 malicious_c2 的数量 / 真实 non_c2 数量`。

该兼容问题不改变预测、宏 F1、恶意召回或混淆矩阵。

## 运行问题

- 在线跟踪入口缺少 `swanlab`，HGB 与 XGBoost 首次尝试均在拟合前失败；失败目录未删除或复用。
- XGBoost 初次导入缺少动态链接的 `libomp`；复用本机已有动态库后成功，没有变更项目依赖。
- `joblib` 无法从系统接口识别物理核心数，自动回退到逻辑核心数；模型执行仍由参数和线程池限制为单线程。
- 诊断脚本在运行后执行 Black 和 Ruff 的纯格式化修正；结果目录没有绑定运行前脚本哈希，这是当前制品的可复现性局限。当前格式化脚本哈希为 `0e36f7b6283ad26ca3b5e985de66adc6cd4abca844de9f785b67924548f2bc00`。

## 验证

- 首批基线：状态为 `finished`，制品哈希全部复核通过，预测记录 115,272 条，没有 `final_test` 评估名。
- 困难诊断：状态为 `finished`，8 个制品哈希全部复核通过。
- 困难诊断表：72 条场景指标、28 条字段重要性记录。
- 协议隔离：训练和验证的 capture 组、timing 组交集均为 0。
- 诊断脚本：Black、Ruff、`py_compile` 均通过。
- 困难诊断摘要明确记录：`calibration_manifest_loaded=false`、`unassigned_groups_loaded=false`、`final_test_assigned=false`、`test_manifest_visible=false`。

## 裁决与下一步

1. 不开启最终测试，也不把域内 `0.999618` 用作论文泛化结论。
2. 后续方法的主门禁固定为 `A+B→C` 与 `A+B+D→C`，至少同时报告宏 F1、恶意召回和良性误报率。
3. 任何新机制必须先证明相对相同预算 HGB/XGBoost 改善 C，而不是继续提高已饱和的域内指标。
4. 字段消融应保留单字段与逐字段去除表，防止把数据生成模式误写为方法贡献。
