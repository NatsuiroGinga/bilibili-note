# GeNIS 跨场景泛化与固定告警预算 Q0 快速实验冻结合同

## 一、状态与唯一目的

- 合同版本：`genis-q0-track-a-60s-subcategory13-v1`。
- 证据标志固定为 `screening_only=true`、`formal_paper_evidence=false`、`final_accessed=false`。
- 唯一目的：用一次种子 `42` 的真实训练判断“类别支持权重 + 固定预算尾部难例权重”在强 XGBoost 上是否存在足以继续投入的信号。
- 本合同只冻结 Q0；不声称理论保证、方法有效、论文贡献或严格复现 Shukla 等的未公开实现。
- GeNIS 已获准进入独立真实实验；旧的论文子域限制不再构成训练阻塞。

## 四、去重与内部三分割

1. 以原始 CSV token（解析前）串联 84 个非标签字段，采用“字段名 + 字节长度 + 字节内容”的无歧义编码后计算 SHA-256，得到 `observation_hash`。
2. 相同 `observation_hash` 若出现不同三层标签，数据门禁失败；标签一致的重复行不删除，但必须整体进入同一分区。
3. 在十三类内按哈希组、种子 `42` 做确定性近似分层分割：`fit/calibration/q0_eval=60%/20%/20%`。按组内行数贪心逼近比例；每类三个分区均须非空，稀有 `recon-dns` 也不得丢类。
4. 三个分区的 `observation_hash` 两两交集必须为 0；分割完成后输出每类行数、哈希组数和比例偏差。
5. `q0_eval` 在基线参数、四格权重和阈值规则全部确定前不可读取标签或预测结果。任何根据 `q0_eval` 调参、换字段、换权重或改阈值的运行作废。
6. 官方测试成员在整个 Q0 中不得打开；若被读取，必须把 `final_accessed` 改成 `true`、停止本合同并报告污染，不能静默继续。

## 五、强 XGBoost 基线

共同固定项：

```text
objective=multi:softprob
num_class=13
tree_method=hist
n_estimators=100
learning_rate=0.2
gamma=0.01
subsample=1.0
min_child_weight=1
reg_lambda=1.0
eval_metric=mlogloss
random_state=42
```

只允许在 `fit` 拟合以下八格：`max_depth∈{4,8,12,16}` × `colsample_bytree∈{0.8,0.9}`。用 `calibration` 的十三类宏平均 F1 选择 B0 参数；并列依次选择较浅树、较小列采样。该组参数随后冻结给四格，候选不得另行调参。线程数与 CPU/GPU 设备只影响效率记录，不得改变算法参数。

该范围来自 Silva 等《Binary and Multiclass Cyberattack Classification on GeNIS Dataset》（DOI `10.1007/978-3-032-20018-1_18`）表 3、PDF 第 8 页：直方图法、100 棵树、学习率 0.2、最大深度 4–16、列采样 0.8–0.9、最小损失下降 0.01；本地原件为 `raw/papers/datasets/published-baseline/2511.08660v1-GeNIS-binary-multiclass-classification.pdf`。

## 六、唯一候选与四格消融

先用已选定的 B0 参数在 `fit` 内按 `observation_hash` 做三折分层交叉拟合，生成每行不由包含自身的模型产生的十三类概率。该概率只用于冻结权重，不进入输入。

令 `u_c` 为 `fit` 中类别 `c` 的唯一 `observation_hash` 数，`U=Σ_c u_c`，类别支持权重为：

```text
a_c = min(20, U / (13 * u_c))
```

再按 `fit` 全部行将 `a_c` 归一化到行均值 1。这里的哈希组只防完全重复，**不等于独立攻击运行或场景支持**；Q0 不据此声称簇级理论保证。

对交叉拟合概率定义恶意分数：

```text
s(x) = 1 - p(benign-admin) - p(benign-background) - p(benign-user)
```

固定告警预算 `alpha=0.005`，即每万条良性流最多 50 条经验误报。以 `fit` 良性行的交叉拟合分数第 `99.5%` 分位为 `q_fit`。将良性且 `s>=q_fit` 或恶意且 `s<=q_fit` 的行定义为预算尾部难例：

```text
t_i = 5  （预算尾部难例）
t_i = 1  （其余行）
```

四格只改变 XGBoost 的 `sample_weight`：

| 短键 | 展示名称 | 原始权重 | 作用 |
| --- | --- | --- | --- |
| B0 | 强 XGBoost 均匀权重基线 | `1` | 强基线 |
| S1 | 类别支持权重 XGBoost | `a_y` | 单机制一 |
| T1 | 固定预算尾部难例 XGBoost | `t_i` | 单机制二 |
| ST | 类别支持与预算尾部联合 XGBoost | `min(20,a_y*t_i)` | **唯一完整候选** |

每格权重在裁剪后再次归一化到行均值 1。四格使用同一数据、参数、种子和训练次数；禁止只给完整候选额外轮数或另选参数。类别支持加权和难例加权均为已有思想，Q0 只检验该冻结组合在 GeNIS 上是否值得继续，不主张原创。

## 七、阈值、指标与读取顺序

每格模型在 `calibration` 上独立产生恶意分数。设良性分数升序为 `b_(1)…b_(n0)`，`m=floor(0.005*n0)`，取 `threshold=b_(n0-m)`，并固定以 `s>threshold` 报警；并列时采用严格大于，确保校准集经验误报不超过 `m`。阈值冻结后才允许一次读取 `q0_eval`。

主指标按以下优先级报告，不得只报最好数字：

1. `recall_at_fpr_0.005`：固定校准阈值下的恶意召回，**唯一晋级主指标**。
2. `fpr_at_threshold` 与 `false_alerts_per_10000_benign`。
3. 十三类宏平均 F1、宏平均召回；逐类支持、精确率、召回率、F1 和混淆矩阵。
4. `min_supported_class_f1`：只在 `q0_eval` 支持不少于 20 的类别中取最小值；`recon-dns` 仍逐类报告，但不得用 3–4 个样本的偶然 F1 代表长尾稳定性。
5. 恶意 PR-AUC、十三类负对数似然、训练时间、每百万行推理时间、峰值内存。

所有四格同时输出绝对值和相对 B0 的差值；Q0 单种子不计算或暗示统计显著性。

## 八、机械失败与晋级门槛

### 8.1 数据或实现无效，立即停止

- 归档、成员 SHA、87 列表头、76 字段顺序或十三类顺序不符。
- 哈希标签冲突不为 0；三分区哈希交集不为 0；任一分区缺类。
- 任一概率非有限或行概率和偏离 1 超过 `1e-5`。
- 官方测试成员被读取，或用 `q0_eval` 选择参数、权重、字段或阈值。

### 8.2 强基线资格门

B0 在 `q0_eval` 的十三类宏平均 F1 必须不低于 `0.9700`。低于该值视为实现、字段或基线能力不足，**不得用弱 B0 判候选有效**；先停止并诊断。本门槛低于 Shukla 等正式论文所报四列 RF 宏 F1 最低值 `0.9713`，只用于识别明显失真的 Q0 基线，不是论文效果门槛。

### 8.3 完整候选 ST 的唯一晋级门

ST 必须同时满足：

1. `recall_at_fpr_0.005(ST) - recall_at_fpr_0.005(B0) >= 0.005`；
2. `macro_f1(ST) - macro_f1(B0) >= -0.001`；
3. `fpr_at_threshold(ST) <= 0.005`；
4. `recall_at_fpr_0.005(ST) - max(S1,T1) >= 0.002`。

任一项失败，结论固定为“Q0 未支持联合候选晋级”，停止增加公式、组件或参数。若 S1 或 T1 单格相对 B0 的主指标提升至少 `0.005` 且满足第 2–3 项，只能登记为“单机制有筛选信号”，允许另立更窄合同；不能把 ST 的失败改写成联合机制有效。若 B0 已有 `recall_at_fpr_0.005>=0.995` 且宏平均 F1 `>=0.990`，则本 Q0 协议记为近饱和并停止追逐微小增益。

无论通过或失败，结果仍保持 `screening_only=true`、`formal_paper_evidence=false`。
