# Qwen3-0.6B 正式数据视图物化计划

## 目标

从冻结 `dataset-v1` 主索引核验并物化 Qwen3-0.6B 正式实验预算，形成可复核的角色清单、样本数和哈希收据，同时保持最终测试不可见。

## 边界

- 只新增正式数据目录、角色清单、收据和 `.Codex/docs/` 报告。
- 不修改模型入口、QUIC v8 文件或历史数据。
- 公开检测监督目标为 57,235 条；ns-3 物理辅助目标为 2,421 条。
- ns-3 标签不得进入检测监督。
- 最终测试只允许在方案、字段、提示、解析器、阈值、批大小、停止条件和超参数全部冻结后由正式评测入口读取。
- 本机只执行 CPU 物化、哈希和静态核验；本机不运行 `pytest`。

## 关键问题

1. 现有清单是否已经足够直接物化 59,656 条正式预算？
2. 57,235 条公开检测监督如何分配到训练、校准、验证和最终测试角色？
3. 2,421 条 ns-3 物理辅助来自哪个冻结视图，如何证明未混入检测标签？
4. 最终测试制品能否仅绑定路径和哈希，而不在当前阶段读取内容？

## 验收证据

- 每个来源、角色的路径、行数、字节数和 SHA-256。
- 角色间主键互斥检查。
- 公开检测监督与 ns-3 物理辅助来源隔离检查。
- 最终测试读取时点和门禁的机器可读声明。
- 物化命令的退出状态与静态语法检查结果。

## 决策

- 优先复用现有物化入口；只有确认现有入口不能满足冻结合同时才考虑生产代码修改。
- 服务器 `dataset-v1` 已有原子发布的正式训练清单，不重跑统一预算构建器；精确回收冻结主索引和清单后，在本机只派生角色隔离视图。
- `train_unified_formal.jsonl` 只作 59,656 条顺序和集合审计；检测训练入口只能绑定公开检测视图，不能直接绑定该混合清单。
- 开放集评测清单只绑定冻结收据中的路径、计数和哈希；当前不回收、不打开、不解析其内容。
