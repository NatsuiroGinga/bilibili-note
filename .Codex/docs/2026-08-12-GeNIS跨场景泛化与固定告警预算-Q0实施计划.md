## 唯一目标

在 GeNIS v1.0.0 官方 60 秒训练成员的内部冻结开发划分上，使用 CUDA XGBoost 运行八格强基线选择以及 `B0/S1/T1/ST` 四格消融，判断“类别支持权重 + 固定预算尾部难例权重”是否满足预注册晋级门槛。官方 60 秒测试成员和其他时间粒度成员全程禁止打开。

## 统一入口与阶段

Python 模块提供四个子命令，启动器在同一正式运行身份内依次调用：

1. `prepare`
   - 只打开冻结归档中的 `4-preprocessed/genis-60-sec-train.csv`。
   - 校验归档 MD5、成员 SHA-256、87 列表头、76 字段顺序、十三类顺序和有限数值。
   - 按冻结观察哈希合同生成 `fit/calibration/q0_eval` 分组划分。
   - 写出 `fit` 与 `calibration` 的特征/标签，以及相互分离的 `q0_eval` 特征和标签侧车。
   - 写出 `data_manifest.json`、`feature_manifest.json`、`split_manifest.parquet`、`split_audit.json`。
   - 退出前释放全部原始标签与特征；状态升为 `DATA_GATE_PASSED`。
2. `select`
   - 只允许读取 `fit` 和 `calibration`；机械拒绝打开 Q0 标签侧车。
   - 在 CUDA 上运行八格 XGBoost 网格并按校准宏平均 F1 冻结参数。
   - 在 `fit` 内做三折观察哈希分组交叉拟合，冻结 `S1/T1/ST` 权重。
   - 用相同参数和预算拟合四格模型，在 `calibration` 上冻结各自阈值。
   - 保存四格模型、校准概率、`selected_xgb_params.json`、`oof_weight_audit.parquet`、`threshold_audit.json` 和 `evaluation_freeze.json`。
3. `evaluate`
   - 只有 `evaluation_freeze.json`、代码/config/input 哈希和四格模型全部一致时才读取一次 Q0 标签侧车。
   - 逐格输出十三类与恶意告警指标、逐类表、混淆矩阵、效率和峰值内存。
   - 机械复算强基线资格门、近饱和门、四道联合候选晋级门和单机制信号门。
   - 写出 `metrics.json`、`per_class_metrics.csv`、`confusion_matrices.json`、`runtime.json`、`status.json`。
4. `swanlab-publish`
   - 只读取聚合指标和协议元数据。
   - 禁止上传逐样本概率、标签、哈希、文件路径、凭据或模型。
   - 工作区和项目必须与用户本轮明确授权逐字一致，否则在读取数据前失败。

## 实现约束

- 项目 Python 命令统一使用 `uv run --no-sync python`，禁止系统解释器。
- XGBoost 固定 `tree_method=hist`、`device=cuda`；完整训练后从 Booster 配置断言实际设备为 CUDA，禁止静默回退 CPU。
- 预测统一使用显式 `xgboost.DMatrix` 与 `Booster.predict`，避免设备不匹配回退。
- 运行前调用 `tools/memory_admission_gate.sh 8 genis-support-tail-q0-seed42-v1`；拒绝与其他实验并发。
- 解析器采用有界批次或预分配数组；不得将整个 87 列 CSV 同时保留为 Python 字符串对象表和数值矩阵。
- 观察哈希以原始 CSV token 计算；哈希组是拆分原子，三个分区交集必须为零。
- 阈值选择采用一次稳定排序和同分组累计，复杂度不高于 `O(n log n)`；禁止逐候选重复全量扫描。
- 所有概率必须有限，行和与 1 的偏差不超过 `1e-5`。
- 长阶段每 60 秒或每个模型结束时记录进度、已完成模型数、累计耗时和预计剩余时间。
- 不创建或运行人工夹具、单元测试、集成测试或独立冒烟实验。

## 配置冻结内容

JSON 配置必须逐字包含科学合同中的：

- 数据版本、归档与成员哈希、禁止成员、76 字段和十三类顺序。
- 种子 42、内部 60/20/20 分组划分和三折交叉拟合。
- 八格 XGBoost 网格及所有固定参数。
- `alpha=0.005`、类别权重上限 20、尾部难例权重 5。
- 四格展示名与短键。
- 强基线资格门、近饱和门、完整候选四道门和单机制信号门。
- 运行根、证据标志、SwanLab 目标及允许上传字段白名单。

1. 实现模块、配置、启动器和运行报告骨架。
2. 集中执行一次 `black`、`ruff`、`py_compile`、JSON 解析、`bash -n` 和 CLI 帮助入口检查。
3. 不运行测试或独立冒烟；检查通过后回报三份生产文件 SHA-256 和 `READY_FOR_SYNC`。

5. 获得 GeNIS 代码/配置/启动器/数据同步以及 SwanLab 聚合上传的明确授权后，精确同步三份生产文件与冻结归档，逐项核对 SHA-256。
