# functions.exec 反引号防错报告

## 机制判定

- `functions.exec` 的 FREEFORM JavaScript 在工具调用与 Hook 之前必须先完成宿主语法解析；反引号模板字符串因文档反引号失配时，工具调用不存在，运行时 Hook 无从拦截。
- 当前仓库 Hook 只匹配 Bash、`apply_patch|Edit|Write`，用户级 Hook 同样未提供对未解析 FREEFORM 源码的解析前观察点。

## 实现

- 根 `AGENTS.md` 增加硬规则：`functions.exec` 和 `apply_patch` 禁止反引号模板字符串承载 shell、补丁或文档内容；改用双引号 JSON 兼容字符串、行数组 `.join("\n")`、参数对象或字符串拼接。
- 未修改 Hook 或新增 lint：对解析前失败的源码无法可靠触发，增加运行时拦截会制造覆盖错觉。

## 验证与边界

- 安全模式：双引号静态字符串、`["行一", "行二"].join("\n")`、参数对象和按路径读取文档均不含模板字符串。
- 故意模板字符串只能在已合法解析、已到达 Hook 的工具调用中成为补充检查对象；对本问题的编译前语法错不覆盖。
- 不限制 Markdown 文件中的反引号，也不扫描文档内容。
- JavaScript 安全双引号/行数组示例已通过 `Function` 解析；用字符码构造的未闭合模板字符串返回 `template-parse-error-before-runtime`。
- 现有仓库和用户级 Hook 的匹配项仅为 Bash、`apply_patch|Edit|Write`；无 `functions.exec` 解析前匹配项，故未增加虚假运行时 lint。
- 最长实验脚本链为 `28,487` 字节，距 `28,500` 目标余 `13` 字节；`git diff --check` 通过。
