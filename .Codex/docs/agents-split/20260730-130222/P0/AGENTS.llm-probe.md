## 固定路径、主机与凭据

- 本地项目根目录：`/Users/bilibili/personal/note/thesis/experiments/llm_probe`。
- 服务端项目根目录：`/root/autodl-tmp/thesis/experiments/llm_probe`。
- 当前已租服务器配有单块 RTX 5090 32GB，但它只是一种可用验证环境，不是代码或实验协议的固定前提。当前生成式基座固定为 Qwen3-1.7B；在该服务器上模型默认路径为 `/root/autodl-tmp/thesis/models/Qwen3-1.7B`，其他环境必须允许通过配置覆盖。扩大模型前先证明小模型上的机制增益。
- 本机连接只从 `GPU_SSH` 和 `GPU_PWD` 读取登录信息；缺失时先 `source ~/.zshrc`。登录后先 `source ~/.bashrc`，再调用 `uv`、`fd`、SwanLab 或实验命令。禁止在命令输出、文档、配置或制品清单中回显凭据。

## 按量计费与重启恢复（强制）

- GPU 服务器按量计费，默认可能在任意两个操作之间关机或重启。`screen` 只防 SSH 断线，不提供关机恢复；不得把进程仍在 `screen` 中视为进度已持久化。
- 服务端代码、派生数据、模型、环境、检查点、日志和运行元数据必须位于 `/root/autodl-tmp/thesis/`。`/tmp/`、未写盘进程内状态、临时 Shell 环境和 `/root/autodl-tmp` 之外的单份文件均不得成为唯一副本。
- 每次运行必须在唯一输出目录中先写配置快照、输入与代码 SHA-256、完整启动命令、随机种子、运行阶段和状态文件，再开始计算。状态至少区分 `prepared`、`running`、`interrupted`、`failed` 与 `finished`；写入采用临时文件后原子替换，禁止重启后覆盖原目录。
- 正式训练必须支持从最近一个完整检查点恢复，并把优化器、学习率调度器、随机数状态、当前步数和模型或适配器状态一并持久化。检查点间隔不得超过 20 个优化步或 10 分钟；不具备等价恢复能力的入口不得启动超过 20 分钟的正式任务。
- 数据下载与物化必须支持校验后续传或按确定性阶段重跑。未完成输出写入带 `.partial` 标记的独立目录；只有行数、哈希、清单和门禁全部通过后才原子发布正式目录。
- 每个独立阶段完成后立即用 `rsync` 回收配置、状态、日志、指标、清单、哈希和摘要到本机对应实验目录。大型数据与权重可以继续只保存在数据盘，但必须有可公开重下、Hugging Face 私有备份或本机备份中的至少一种恢复来源。
- 关机前先只读检查 GPU 进程、`screen`、运行状态文件与最新检查点。没有活动实验时可直接关机；存在活动实验时，只有确认最近检查点完整且恢复命令已落盘后才允许停止实例。
- 重启后必须重新执行硬件、磁盘、命令、`uv` 环境和输入哈希探测，再扫描未完成运行。只允许在配置、代码、数据清单、种子和硬件适配参数一致时续跑；否则保留旧目录并建立新运行，禁止伪装成连续实验。
- 详细操作清单见 `.Codex/docs/2026-07-28-按量GPU服务器重启恢复协议.md`。

## 本机与服务器同步（强制）

- 代码同步只使用 `rsync` 增量传输，不再逐文件使用 `scp`。从本地实验项目根执行，使用明确的文件或目录白名单及相对路径，保持两端结构一致。
- `rsync` 默认禁止 `--delete`，并排除 `.venv/`、`runs/`、模型权重、原始数据集、缓存、凭据和本地环境文件。同步数据集、模型或运行制品必须作为独立任务，先说明源、目标和空间影响。
- 同步后必须核对返回状态和目标文件存在性。正式入口、配置或数据清单变化时，再比较源端与目标端 SHA-256；同步失败或版本不一致时禁止启动实验。
- 实验代码不得只存在于服务器。结果回收后按实验记录中的本地路径归档，但不得用回收操作覆盖本地用户改动。

## `uv` 与服务端环境（强制）

- 训练依赖位于可选组 `gpu`。禁止执行裸 `uv sync` 或裸 `uv sync --locked`，否则训练包可能被当作多余依赖移除。
- 仅更新项目代码或控制台入口时，使用 `uv pip install --no-deps -e .`，不得同步整个环境。
- 确需重建环境时，先运行 `uv sync --locked --extra gpu --dry-run`。计划若移除 `torch`、`transformers`、`swanlab`、`accelerate`、`peft`、`trl` 或 CUDA 运行库，立即停止。
- 预演安全后才可执行 `uv sync --locked --extra gpu`。GPU 档位完成后验证上述包均可导入和加速器可用；CPU 档位不得把 `torch.cuda.is_available()` 为假当作环境失败。

## 硬件能力探测与降级（强制）

- 数据处理、协议审计、HGB、XGBoost 和通用评价必须支持纯 CPU，不得调用必需的 `nvidia-smi`、CUDA 或 bitsandbytes 路径。
- 神经模型入口默认采用 `device=auto`、`precision=auto` 和显式硬件能力探测。CUDA 可用时选择受支持精度与量化；CUDA 不可用时回退 CPU 安全路径，至少能够完成数据加载、前向冒烟、评价和小规模功能验证。正式大模型 CPU 训练若成本不可接受，应输出结构化的“不支持该正式档位”原因，不得以导入错误或硬编码设备崩溃。
- 降级只允许调整微批量、梯度累积、数据加载线程、精度和可选量化等硬件适配项；有效批量、训练样本、随机种子、训练步数、评价清单和科学超参数必须保持等价，任何会改变科学问题的调整都要作为新配置单独报告。
- 每次运行记录实际设备类型、CPU 型号、逻辑线程、内存、GPU 型号与显存（若存在）、精度、量化、微批量和梯度累积。`nvidia-smi` 缺失时记录为不可用，不得使运行失败。
- 性能与成本比较只能在同一硬件档位内进行。CPU、通用 CUDA GPU 和 RTX 5090 的训练时间、吞吐与延迟必须分栏，禁止混合排序或据此宣称算法效率优势。
- 运行脚本不得通过设备名称判断算法分支，也不得把 RTX 5090、固定 CUDA 版本或固定显存容量写入模型正确性条件。

- 服务器重启或更换实例后必须重新执行命令能力探测，不能沿用“已安装 `fd`”等历史事实；文件枚举优先使用 `fd`，若当前实例确实不可用则显式记录并回退到 `rg --files`，不得让监控命令失败掩盖实验状态。
- Shell 状态输出若内容可能以连字符开头，统一使用 `printf '%s\n' "$text"`，不得把 `---` 等内容直接作为格式串，以免被解释为选项并污染监控日志。
- 本机受限执行环境可能无法写入 `~/.cache/uv`。本机只做 Black、Ruff、编译等静态检查时显式设置 `UV_CACHE_DIR=/tmp/uv-cache`；出现 `Failed to initialize cache` 先核对缓存路径权限，不得误判为依赖或源码故障，也不得因此在本机运行 `pytest`。
- 本机受限执行环境会回收后台进程，`screen -dmS` 可能返回 `0` 却没有持久化套接字。需要在本机长期处理原始 PCAP 时使用获批的沙箱外执行，并在启动后同时核对 `screen -ls`、持久化 `run_state.json` 和 `.partial` 目录；只看到启动命令退出码不算启动成功。
- 通过 `expect /tmp/gpu-exec.exp '远端命令'` 直接执行远端 Shell 时，单引号已经阻止本地展开，状态变量应写为 `$?`、`$status` 和 `$((...))`，不得额外写成 `\$?` 或 `\$((...))`。只有变量位于再次嵌套的双引号命令字符串中时才按对应 Shell 层级转义；启动前先用最小状态命令验证引用层级。
- 测试 Shell 包装器时不得把现有虚拟环境的 Python 解释器符号链接到临时伪 `.venv/bin/python`。Python 会按新路径重新判定 `sys.prefix`，导致已安装依赖不可见；测试夹具应创建可执行转发脚本并以原解释器绝对路径 `exec ... "$@"`，然后用一个依赖导入冒烟确认解释器边界。
- 预计超过 10 分钟的服务器回归不得放在单个前台 SSH 命令中。应按互不共享写状态的测试节点分成少量 `screen` 会话，每个分片在持久化验证目录保存完整命令、独立日志和原子写入的退出状态；切换无卡/有卡档位或实例重启后，只重跑没有成功退出状态的分片，禁止因总日志缺少最终摘要而重复已明确通过的节点。
- 真实包表不得假设 `sample_id` 在单个 Parquet 行组内连续；合法输入可以交错，但每个样本按 `packet_index` 恢复后必须连续。包聚合测试夹具必须覆盖“`sample_id` 交错但 `packet_index` 连续”的输入；处理大量包记录时先冻结实际使用的 `sample_id` 再过滤聚合，除非合同明确要求全量处理。
- 合成分配夹具只能验证算法行为，不能替代版本库中真实固定清单的验收。凡运行依赖受版本控制的 JSON 或 YAML 数据合同，必须有最小测试直接加载真实配置，并验证合同要求的硬覆盖以及至少包含抽样算法、源样本总数的元数据；真实配置通过最小测试和独立复审前不得启动物化。
- 测试若故意改写同时受协议文件和外部固定配置双重哈希绑定的制品，必须先更新夹具中的全部预期哈希，才能断言更下游的泄漏、重复或划分门禁；漏更新任一独立绑定时，预期行为是先报哈希不一致，不得据此修改生产代码或放松哈希校验。
- 使用 `load_frozen_protocol` 审计 `data-protocol-v1.0-rc1/provisional/theory_selection` 候选制品时，必须显式传入候选版本、状态和阶段；其默认参数只接受 `data-protocol-v1.0/frozen/final_tuning`。遇到“协议版本不一致”先读取 `protocol.yaml` 并比较调用参数，不得直接改写已完成双物化的协议文件，也不得把候选状态伪装成最终冻结状态。
- 非交互启动器同时使用 `.bashrc` 与 `set -u` 时，必须先 `source ~/.bashrc`，再启用 `set -u`。服务器 `.bashrc` 会用 `$PS1` 判断是否为交互 Shell；若先启用未定义变量检查，启动器会在首个状态文件前退出，且重定向后可能表现为 `screen` 返回成功但空日志、无套接字。同步后先运行 `bash -n` 和 `bash -c 'source ~/.bashrc >/dev/null 2>&1; set -u; command -v uv >/dev/null'`，启动后同时核对 `screen -ls` 与首个种子状态文件。
- 新增确定性模型视图时，不能只在数据物化配置中声明新名称；训练前必须同时登记到 `ProbeConfig` 的字段视图白名单，并增加一个直接解析真实训练配置的最小测试。出现“未知字段视图”时先比较配置值与白名单，不得改回语义不一致的旧视图名称绕过门禁。
- 使用 `rsync` 精确同步单个文件或白名单文件前，必须先在远端创建并核对目标父目录；同步后再检查返回状态、目标文件存在性和必要的 SHA-256。不得把父目录不存在导致的传输失败误判为权限、网络或源文件故障。
- 服务器启动器不得假定 `/usr/bin/time` 存在。启动前先探测资源统计命令；不可用时采用进程组 `ps` 采样记录峰值常驻内存和墙钟耗时，或明确记录指标不可用，不能让缺失的统计工具阻止实验启动或丢失退出状态。
- `flow-probe-train` 的新运行目录在 `training_binding.json` 与 `run_state.json` 创建前必须保持为空；不得预先把命令、哈希、硬件摘要或 `launcher.log` 写入该目录，否则训练入口会以“输出目录非空且缺少恢复元数据”拒绝启动。启动证据先写入目标目录同级、同文件系统的唯一 staging，子进程启动后按条件等待 `run_state.json` 出现，再把证据和仍在写入的日志移动到正式目录；若子进程在状态文件出现前失败，则等待其退出后再归档全部证据并原子写入退出码。该过程只允许一次正式启动，禁止因包装器错误自动重试。
- 不得在 `screen ... bash -lc "..."` 的嵌套双引号命令中直接内嵌含 `$arg` 的 `jq` 过滤器；外层 Shell 会提前展开 `jq` 变量，可能生成零字节状态文件且不影响主进程继续运行。复杂状态更新应写入持久化包装脚本并先执行 `bash -n`，或使用不含跨层变量的固定 JSON 模板；启动后必须同时检查状态文件非空和 `jq -e` 解析通过，不能只检查 `screen` 与主进程。若主计算已正常运行，只修复状态制品并在结束后再次验收，禁止因此重启实验。
- 新模型视图进入生成式评测前，必须逐条预检 `prompt`、真实标签来源、`completion` 的单键 JSON 合同及输出解析器期望键，并在加载模型前失败。旧视图的 `label` 与共享视图的 `binary_label` 必须按各自记录合同严格解析，禁止为兼容而同时接受任意键；不得等全部 GPU 生成结束后才读取标签或发现字段缺失。
- 当一组实验代码、配置、测试和防复发规则已经完成最小验证，且改动范围足以形成一个职责单一、可复现的提交时，必须主动提醒用户“当前可以提交”，并简述建议提交范围与仍在运行的实验。未经用户明确授权不得自动提交，也不得为等待提交而阻塞实验运行。
- 任何超过 `1,000` 条样本的生成式评测在正式启动前，必须先在非最终测试样本上完成吞吐预检：比较单条与候选批大小的预测一致性，记录样本吞吐、GPU 利用率、峰值显存并估算全量耗时；同时确认预测按批增量落盘且可按 `sample_id` 断点续评。若实现仍逐条调用 `model.generate`、GPU 明显闲置或故障会丢失全部内存结果，则不得启动全量评测，除非用户在获知预计耗时和重算风险后明确要求保留串行基线。
- 生成式评测默认按以下顺序加速：先在非最终测试样本上探测批大小 `8/16/32/64`，再按输入长度分桶，并在输出时按冻结 `sample_id` 顺序还原；每批增量写入预测和完成清单，支持断点续评；随后优先测试 PyTorch 缩放点积注意力，只有兼容性和实测收益均通过时才启用 FlashAttention。批量版本必须与单条贪心生成进行逐样本一致性核对，并保留吞吐、显存和延迟证据。候选答案似然评分属于受约束分类协议，可以作为额外效率结果，但不能替代自由生成的结构化输出有效率；不得为了提速擅自改变标签合同、测试清单、最大生成长度或评价指标。
