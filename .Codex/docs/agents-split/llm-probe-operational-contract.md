# llm_probe 按需运行合同

本文件承接不适合常驻上下文、但仍具强制性的实验运行细节。任务触发对应主题时，只需完整读取匹配章节；远程 Shell、同步和恢复还须读取 `remote-script-execution-contract.md`，具体故障还须读取 `llm-probe-failure-prevention-handbook.md`。

## 任务放置、容量与数据热路径

- GPU 训练、推理、生成评测、显存或加速测试前，向用户说明任务、预计时长、显卡与卡数、显存、开机和费用需求并确认资源可用。本机只做短小 CPU 开发、哈希、统计和报告，服务器承担 GPU、大规模物化和大规模 CPU 工作。
- 预计墙钟超过 30 分钟、常驻内存超过 8 GiB、扫描超过 500 万行或 1 GiB、训练矩阵超过 100 万行乘 100 列，任一满足即为大规模任务，不得在本机启动；先估算并报告，若传输代价接近或超过计算代价则先修正放置方案。
- 预计处理 100 万条以上记录时，启动前证明每类中间状态的固定上界，登记键基数、每键历史、批大小、单状态字节、峰值内存、临时文件和总 I/O；跨批集合、聚合器、排序或缓存随输入增长时先加驱逐、分区或磁盘溢写。
- 性能异常先区分算法与硬件：逐行 Python、重复全量扫描和未缓存中间制品先修复、向量化或落盘复用再考虑换机器；验证集阈值选择不得对每个候选全量重扫，须用一次稳定排序与同分组累计，或证明复杂度不高于 `O(n log n)`。
- Arrow 固定长度列表按批次转 NumPy 时，同时校验 `list_size` 并按父数组 `offset × list_size` 切当前值缓冲区；原子发布数据产品时，清单写发布后的最终路径，发布后核验路径位于根内、存在且哈希一致。
- 资源不足和离线不计科学失败，保留状态收据；不得因此改变冻结数据、协议、评价或科学参数。

## 服务器切换、硬件与降级

- 本地根为 `/Users/bilibili/personal/note/thesis/experiments/llm_probe`，服务端根为 `/root/autodl-tmp/thesis/experiments/llm_probe`。生成式基座固定为 Qwen3-1.7B；RTX 5090 32GB 只是当前环境，不是正确性条件。
- 数据处理、协议审计、HGB、XGBoost 和通用评价支持纯 CPU；神经入口默认 `device=auto`、`precision=auto`。无 CUDA 时至少能加载与评价，不适合正式训练则结构化拒绝。
- 硬件降级不得改变有效批量、样本、种子、步数、评价清单和科学超参数；记录实际硬件与适配项，只在同档硬件比较成本和性能。
- 新旧服务器之间只做只读盘点、白名单 `rsync` 中转和 GPU 正式运行所需的最小启动。Linux 专属 CPU 任务优先使用本机容器或虚拟机；仍不能满足时报告阻塞，禁止为方便退回 GPU 服务器。

## 下载、依赖与镜像

- 外部源码、Linux 工具链、依赖、模型和可中转数据默认在本机下载，记录来源、固定版本、大小和哈希后白名单同步。服务器只做 GPU 正式运行所需的解压、隔离安装、启动和回收。
- 本机启动下载前先选镜像：Rustup 与 crates.io 优先清华镜像，Hugging Face 优先既定镜像或 ModelScope，其他来源优先已核验国内学术镜像。
- 仅当镜像缺版本、不可用、哈希不符、授权不可转移或持续失败时回退官方源，并记录镜像失败证据、官方地址和制品哈希。为避免已完成内容全部重下可记录一次性例外完成当前制品，后续重试仍须用镜像。
- 因服务器专属签名地址、授权状态或本机及容器确实无法取得而必须例外时，先记录原因、目标路径和恢复策略，再取得用户明确许可。

## 资源监测与受控并行

- 预计超过 5 分钟的编译、生成、物化或独立实验，启动后 2 分钟内采样 CPU、GPU、内存、磁盘写入、负载、活动子进程和吞吐，不得假定工具自动并行。
- 任务独立且资源空闲时，采用受控并行、分片或作业数参数；先保守运行 3 分钟再按吞吐与压力调整，只续跑缺失项。并发变化只影响调度，不得改变数据、种子、步数、配置或科学参数，须保存资源和吞吐收据。
- 磁盘达到 80% 或可用不足 10 GiB 时通知用户；达到 90% 或不足 5 GiB 时停止新增大型文件和下载。

## Rust 数据热路径与确定性

- 新建的性能敏感数据热路径默认用 Rust；读取 `rust-skills`，采用流式、有界内存和确定性并行。训练、推理、SwanLab 和配置保留 Python，ns-3 保留 C++。
- Rust 输出与冻结参照比较模式、行数、类型、缺失、`sample_id`、顺序和语义哈希；不得静默回退 Python，也不运行 `cargo fmt`。
- 最终冻结或字段、单位、划分、排序、解析语义变化时才双物化；探索和先导只运行一次，并记录输入与代码摘要、模式、行数、顺序、缺失和语义哈希。训练和推理不为逐字节一致重复运行。

## 生成式评测与加速

- 超过 1,000 条的评测先在非最终测试样本核对批量与单条贪心输出、吞吐、显存、增量落盘和断点续评；不得改变冻结顺序、标签合同、最大生成长度或指标，受约束候选评分不能代替自由生成有效率。
- 批量实现按输入长度分桶并按冻结 `sample_id` 还原；每批增量写预测与完成清单。正式全量前应消除逐条生成、GPU 明显闲置和故障丢失全部内存结果，除非用户明确接受串行成本与重算风险。
