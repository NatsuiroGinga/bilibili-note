# 远程脚本完整执行合同

本合同保存 P1 的完整可执行细则。`scripts/AGENTS.md` 要求在任何脚本修改、同步或运行前完整读取本文件；本合同同时继承仓库根、`thesis/AGENTS.md`、实验根和 `scripts/AGENTS.md`。

## 远程入口与引用

- 正式远程命令可使用直接 SSH、项目内持久化脚本或已有启动器，不强制统一包装器。按步骤最少、退出码可靠、日志可追溯和可恢复性选择执行方式；超过一条简单语句的操作优先写入持久化 `.sh`，但不要求预建同步白名单。禁止难以复现的嵌套 here-document、多层字符串拼接或把动态参数重新拼成 Shell。
- **B76 默认显式直连**：当使用 `GPU_SSH_B76` 时，先设置 `GPU_SSH_ACTIVE="ssh -o ProxyCommand=none -o ProxyJump=none ${GPU_SSH_B76#ssh }"`，再由正式 `tools/remote_exec/gpu_env_quiet.exp` 使用该入口。即使 `GPU_SSH_B76` 表面仅为 `ssh -p <端口> <目标>`，也不得假定现有 SSH 配置未隐式指向本地 `127.0.0.1:7890`。
- 不得探测或启动 Clash Party，不得将 `7890` 或任何代理视为 B76 的必需条件。显式直连失败时，保留并报告原始脱敏 SSH 错误；不得自动改走代理，只有用户明确授权后才可使用代理路径。凭据仅从既有环境变量读取，禁止打印、回显或写入文件。
- 传给 SSH 或 `expect /tmp/gpu-exec.exp` 的临时载荷只能是短单行。多行操作必须传脚本，禁止用 `JSON.stringify` 把真实换行变成字面量 `\n`；检查时必须区分真实换行与反斜杠加 `n` 两个字符。
- `expect ... '远端命令'` 的单引号已阻止本地展开，远端状态写 `$?`、`$status`、`$((...))`，不得多加反斜杠；再次嵌套双引号时按实际 Shell 层级转义，并先用最小状态命令验证。可能以连字符开头的状态文本统一用 `printf '%s\n' "$text"`。

## 环境与能力预检

- 非交互远程脚本先 `source ~/.bashrc`，再启用 `set -Eeuo pipefail`；不得在加载 `.bashrc` 前启用 `set -u`。同步后先运行 `bash -n` 和 `bash -c 'source ~/.bashrc >/dev/null 2>&1; set -u; command -v uv >/dev/null'`。
- 每次服务器重启或实例变化后重新探测硬件、磁盘、输入哈希及命令能力；先核对 `command -v fd`，未命中时再核对 `command -v fdfind`，将命中的绝对路径保存为统一的 `FD_CMD`，后续只通过 `"$FD_CMD"` 调用；另行核对 `command -v rg`、`command -v uv`、绝对路径和版本，并把结果写入持久化能力清单。不得沿用历史 PATH 或安装结论。
- 工具不在 PATH 时先补入已批准目录；`uv` 再检查 `/root/.local/bin/uv`。仅当 `fd` 与 `fdfind` 均不存在时，仅文件枚举可显式降级到 `rg --files`，其他遍历必须停止，禁止使用 `find`；`rg` 缺失必须停止，禁止传统搜索替代；`uv` 缺失必须明确安装或停止。`/root/.bashrc` 的 `uv` PATH 异常时比较 `.bashrc.pre-uv-path-20260720`，禁止重复追加 PATH。
- 训练依赖位于 `gpu` 可选组，禁止裸 `uv sync` 或裸 `uv sync --locked`。仅更新代码或入口时用 `uv pip install --no-deps -e .`；重建前先执行 `uv sync --locked --extra gpu --dry-run`，若拟移除 `torch`、`transformers`、`swanlab`、`accelerate`、`peft`、`trl` 或 CUDA 库立即停止，安全后才执行正式同步。GPU 档位验证依赖导入与加速器；CPU 档位不得把 CUDA 不可用判为环境失败。
- 启动器不得假定 `/usr/bin/time` 存在；缺失时用进程组 `ps` 采样峰值常驻内存和墙钟耗时，或明确记录不可用，不得丢失主进程退出状态。本机 Python 静态或语法检查从第一次执行起就同时设置 `UV_CACHE_DIR=/tmp/uv-cache` 与 `PYTHONPYCACHEPREFIX=/tmp/codex-pycache`，禁止先写 macOS 全局缓存再失败重试；缓存权限错误不得误判为代码或依赖故障，也不得改在本机运行 `pytest`。

## 同步与可恢复运行

- 代码与制品可直接使用 `rsync`、`scp` 或等价工具同步，不要求预建白名单或仅限相对路径；必须明确源和目标，默认禁止 `--delete`，排除凭据与无关缓存。数据、模型或大型制品同步前说明源、目标和空间影响。
- 精确同步前先创建并核对远端目标父目录；同步后检查状态和目标存在性，正式入口、配置或清单变化时再核对 SHA-256。核对脚本模式；仓库内 `0644` 包装器统一用 `bash scripts/<脚本>.sh`，不得因 `Permission denied` 重复启动。服务器代码不得成为唯一副本，回收不得覆盖本地改动。
- 长任务使用 `screen`，但不得把套接字当作关机恢复。代码、数据、环境、检查点、日志和状态必须落在 `/root/autodl-tmp/thesis/`；运行状态至少含 `prepared`、`running`、`interrupted`、`failed`、`finished`，用临时文件原子替换，禁止重启后覆盖旧目录。
- 正式训练应保存模型或适配器、优化器、调度器、随机状态和步数，检查点间隔不超过 20 个优化步或 10 分钟；否则不得启动超过 20 分钟的任务。下载与物化必须可续传或确定性重跑，未完成输出使用 `.partial`，通过行数、哈希、清单和门禁后才原子发布。
- 每个独立阶段完成后立即回收配置、状态、日志、指标、清单、哈希和摘要；仅留数据盘的大型数据或权重必须至少具备公开重下、Hugging Face 私有备份或本机备份之一。关机前核对 GPU、`screen`、状态和检查点；重启后重做能力、环境、哈希预检，只在配置、代码、数据、种子和硬件适配项一致时续跑，否则保留旧目录并新建运行。详细清单见 `.Codex/docs/2026-07-28-按量GPU服务器重启恢复协议.md`。
- 超过 10 分钟的服务器回归拆成不共享写状态的少量 `screen` 分片，各自保存命令、日志和原子退出状态，只重跑无成功状态的分片。本机沙箱可能回收后台进程；本机长期 PCAP 任务须获批在沙箱外启动，并同时核对 `screen -ls`、`run_state.json` 和 `.partial`。

## 启动与日志完整性

- 一般运行在计算前保存配置、输入与代码 SHA-256、命令、种子、阶段和状态。`flow-probe-train` 是例外：正式目录在 `training_binding.json` 与 `run_state.json` 出现前必须为空；证据写到同文件系统唯一 staging，状态出现后再移动，提前失败则退出后归档并原子写退出码。一次包装只允许一次正式启动，禁止自动重试。
- 训练前失败必须保留启动日志、崩溃状态和生成目录，移动到带日期的失败归档；不得删除证据或复用失败目录。嵌套 `screen ... bash -lc "..."` 禁止内嵌含 `$arg` 的 `jq`；复杂更新写入已通过 `bash -n` 的持久脚本。状态文件必须非空且通过 `jq -e`，主计算正常时只修状态制品，不得重启实验。
- 执行 `命令 | tee "$log_path"` 前先创建日志父目录并验证可写。默认依赖 `set -Eeuo pipefail`；若为汇总状态暂时关闭 `errexit`，管道后的第一条语句必须复制完整 `PIPESTATUS`，分别检查前序命令与 `tee`，再恢复 `set -e`，禁止只读 `$?`。
- 只有前序命令与 `tee` 都退出 0 且日志存在、非空，才能执行 `wc`、`jq` 或上传；失败时写独立状态并返回非零。最小冒烟覆盖父目录自动创建、目标不可写、管道两侧分别失败及双方成功五类情况。

## 脚本门禁

- 修改的 Shell 脚本在交付、独立审查或提交前集中运行一次 `bash -n`，不在每轮重复，也不阻塞已通过行为门禁的实验；验证失败立即修复，不得提交语法错误。测试包装器不得把现有解释器符号链接到伪 `.venv/bin/python`，应以转发脚本 `exec <原解释器绝对路径> "$@"`，并先做依赖导入冒烟。
