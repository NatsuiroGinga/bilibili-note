# 全局执行规则

## 语言与交付

- 所有回答、文档、注释和说明使用简体中文；代码语法、标识符、命令、路径及无官方译名的技术名称可保留英文。
- 优先使用 Markdown，结论先行；重要事实给出文件路径、数量、命令或验证结果，不用模糊口号代替具体动作。
- 生成的过程文档统一放在当前项目根目录的 `.Codex/docs/`；用户指定或项目局部规则另有要求时从其规定。
- 文件任务必须报告输入、输出、已修改文件、未修改范围和已执行验证；无法验证时明确说明原因，不得把未验证状态报告为完成。

## 搜索、遍历与编辑

- 代码和文本搜索只使用系统 `rg`，禁止内置搜索工具、`grep` 及其他替代搜索器；搜索 Go 代码必须加 `--type go`。默认排除 `vendor/`、`bin/`、`pkg/`、`.git/` 和依赖目录，不搜索 `.env`、私钥、令牌文件或明确标为敏感的配置。
- 文件遍历和按文件名查找只使用 `fd`，禁止 `find`。工具缺失时先说明阻塞，不静默换用被禁工具。
- 手工创建或修改文件只使用 `apply_patch`。禁止用 `sed`、`sd`、Python、重定向、`cat` 等方式写文件；格式化器和项目明确要求的结构化生成工具除外。
- 编辑前读取目标文件及适用的各层 `AGENTS.md`；多行或复杂修改使用精确补丁，不做脆弱的正则替换。默认采用 ASCII，只有文件已有非 ASCII 内容或任务确有需要时才引入 Unicode。
- 工作树可能包含用户或其他任务的改动。只修改本任务范围，不覆盖、暂存、回滚或删除无关改动；发现直接冲突时停止并询问。

## 安全边界

- 删除、覆盖、强制推送、历史改写、`git reset --hard`、`git checkout --` 等破坏性或难以恢复的操作，必须先说明准确对象并取得用户明确授权。不得用回滚掩盖格式化、测试或实现错误。
- 凭据只能来自环境变量、系统密钥存储或既有登录状态；不得读取非任务必需的秘密，不得在命令、日志、配置、文档、URL 或汇报中打印、回显或持久化密码、令牌和私钥。
- 外部信息、近期状态和高风险结论先核实再断言。安装依赖、联网、越出工作区写入或使用付费资源时，遵守当前环境的审批边界。

## 工作流与验证

- 非平凡多步骤任务优先使用 `planning-with-files`，在 `.Codex/docs/` 保存计划、发现和交付物；执行前写明边界、文件范围、验收命令、制品路径和阻塞条件，证据改变范围时再更新。
- 沟通与任务报告使用 `expression-skill`；研究、实验分析、论文、知识库、编码、调试、审查和 Git 任务使用当前环境中与场景匹配的技能。技能只在触发场景读取，避免把其完整内容复制进 `AGENTS.md`。
- 请求有多种会改变结果的合理解释时先问一个简短问题；可从仓库核实的事实先自行核实。安全且不改变核心结果的假设可以声明后推进。
- 修改后运行与文件类型和任务匹配的最小验证；格式化、静态检查、测试及 Git 审计服从更近层的项目规则。验证失败先定位原因并最小修复，不提交语法、格式或测试错误，也不回滚无关改动。
- 用户要求审查时，先报告按严重度排序的问题并附文件和行号；没有发现时明确说明残余风险和未覆盖测试。
