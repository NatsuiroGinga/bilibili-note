# R2 QUIC v8.1 正式物化器实施计划

## 目标

在 v5 分层先导采集完成后，将 120 条独立 QUIC 连接物化为可供 `r2_final_physics_fit.py` 消费的训练期特权物理制品。

## 边界

- 只新增 QUIC 物化脚本、配置和过程记录。
- 不修改采集器、`r2_final_experts.py`、`r2_final_physics_fit.py`、恢复文档或 v5 原始目录。
- 输入状态不是 `finished` 且完成数不是 `120` 时必须拒绝物化。
- 不生成最终测试集、恶意标签或伪造的缺失真值。

## 执行步骤

- [x] 核对 R2 路线规则、v8.1 实施计划、600 连接裁决协议和训练器数据合同。
- [x] 核对 TCP/UDP v2 物化器、QUIC 采集器及现有 qlog 真值结构。
- [x] 新增配置化的 QUIC 正式物化器，解析 PCAP、aioquic JSON 和 quiche JSON-SEQ qlog、代理事件与统计。
- [x] 新增 120 条连接级 80/20/20 分区配置，并输出制品合同、哈希和收据。
- [x] 对脚本和配置执行静态编译与合成 120 连接物化验证。
- [x] 写入实现报告，记录当前 v5 状态门禁和遗留风险。

## 决策

- 采用连续、非重叠的四个 100ms 窗口组成一个序列，序列不得跨 `connection_id`。
- 采用确定性哈希将连接划入 80 个 `train-fit`、20 个 `calibration`、20 个 `validation`，只在连接内生成序列。
- 公共观测只从部署 PCAP 聚合；qlog 和代理制品仅用于训练期真值，不写入公共观测列。
