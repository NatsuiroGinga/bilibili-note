# ns-3 真值到 PINN 首轮实验实施计划

> **执行要求：** 必须使用 `superpowers:subagent-driven-development` 逐任务执行；每个实现子代理必须使用 `superpowers:test-driven-development`，先保存红测证据，再写生产代码、执行绿测和独立评审。

**目标：** 完成可进入第一创新点 M0、M1、M2 的 ns-3 物理真值、字段防泄漏契约、SwanLab 正式运行和 Qwen3-1.7B 物理约束训练入口。

**总体结构：** `ns-3` 只提供单瓶颈队列的受控物理真值；生成式基座仍为 Qwen3-1.7B。M1 使用共享隐藏表示预测连续队列状态，M2 在同一状态头上增加由预测状态构造的可微队列守恒残差；保存的真值零残差只用于生成器审计，不进入训练损失。

**技术栈：** ns-3.48、C++17、Python 3.10、PyTorch、Transformers、PEFT、`uv`、pytest、SwanLab 0.9。

## 全局约束

- 所有回答、文档、代码注释和日志说明使用简体中文；技术标识符可保留英文。
- 本地代码位于 `thesis/experiments/llm_probe/`，服务端代码位于 `/root/autodl-tmp/thesis/experiments/llm_probe/`。
- 本地只运行 Black、Ruff、clang-format、Bash 语法、Prettier 与 `git diff --check`；pytest 只在服务器 `uv run --no-sync` 环境执行。
- 每项行为变更必须先写失败测试并在服务器观察预期失败，再写最小实现并观察通过。
- 正式实验固定使用 Qwen3-1.7B、RTX 5090、SwanLab 在线项目 `mortiswang/malicious-traffic-llm`。
- 数据切分以完整 `group_id` 为最小单位；场景、组号、种子、运行号、绝对时间、标签和真值残差禁止进入模型输入。
- 配置容量积分只作为外生控制量或残差归一化尺度，不得解释为同窗实际发送完成量。
- 队列规则 L3 字节、点到点 PPP 帧字节和应用负载字节禁止直接相减。
- `ns-3` 只承担物理机制和因果干预证据，不替代 GeNIS、DEDALE 的检测性能与跨域证据。

- [ ] **步骤 1：确认既有 v4 红测**

  运行 `uv run --no-sync pytest tests/test_ns3_truth.py::test_validate_ns3_truth_paths_accepts_minimal_complete_group`，必须因旧验证器只接受 v3/42 字段而失败；红测日志固定保存到 `runs/ns3-data/validator-tests-20260720/red-v4-contract.log`。

- [ ] **步骤 2：完成验证器最小实现**

  将字段统一为：

  ```text
  configured_capacity_integral_link_bytes
  queue_start_l3_bytes, queue_end_l3_bytes
  qdisc_received_l3_bytes, qdisc_enqueued_l3_bytes, qdisc_dequeued_l3_bytes
  qdisc_dropped_before_enqueue_l3_bytes, qdisc_dropped_after_dequeue_l3_bytes
  device_tx_drop_ppp_frame_bytes, downstream_error_loss_ppp_frame_bytes
  sink_received_app_payload_bytes
  queue_start_packets, queue_end_packets, qdisc_received_packets
  qdisc_enqueued_packets, qdisc_dequeued_packets
  qdisc_dropped_before_enqueue_packets, qdisc_dropped_after_dequeue_packets
  device_tx_drop_packets, downstream_error_loss_packets, sink_received_packets
  queue_balance_residual_l3_bytes, queue_balance_residual_packets
  ```

  字节残差和包残差都必须逐行复算为零；两个保存残差也必须为零。

- [ ] **步骤 3：完成生成器最小实现**

  `QueueWindowCollector` 同时维护当前队列字节数和包数；入队时同时增加，出队时同时减少，窗口结束写出起止状态、接收量及两种残差。流量持续到 12 秒测量结束，禁止再次产生提前停止的空闲攻击尾部。

- [ ] **步骤 4：加入运行时自证**

  每个 `TraceConnectWithoutContext` 返回值必须检查，失败时终止；回读并断言根队列规则类型为 `ns3::FifoQueueDisc`、上限为 `50p`、设备队列为 `1p`、初始链路速率为 5,000,000 bit/s。入队前丢弃原因必须是 FIFO 上限触发，否则终止。

- [ ] **步骤 5：补齐关键负向测试**

  至少覆盖：字段缺失、窗口少于 120、窗口索引乱序、时间不连续、队列字节与包状态不连续、错误拓扑、错误队列模型、错误 `group_id` 组成、组内固定值漂移、缺少必需丢弃、非随机场景出现误码、包级残差错误。

- [ ] **步骤 6：执行绿测和真实冒烟**

  服务器依次运行：

  ```bash
  uv run --no-sync pytest tests/test_ns3_truth.py
  uv run --no-sync pytest
  env USER=ns3builder ./ns3 build scratch/flow-probe-queue-truth
  ```

  再生成 `dos-udp-high` 与 `benign-random-loss` 各一组，验证 46 字段、120 窗口、双残差为零、攻击尾部有活动、跨层字段不混算。

- [ ] **步骤 7：格式化并记录**

  C++ 运行 clang-format；Python 运行 Black 与 Ruff；报告写明红测、绿测、服务端日志和未解决边界。
