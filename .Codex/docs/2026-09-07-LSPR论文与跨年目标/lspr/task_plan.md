## 任务目标

系统检索并全文核验直接使用 LSPR 数据集的论文，优先覆盖 LSPR23→LSPR24 跨年评价。逐篇提炼研究问题、训练/测试年份、指标、基线、跨年退化、目标年信息权限和实验编排，形成可供 Astra 独立复核的证据表。

最终证据只服务第四章“**两个机制＋一个联合算法/框架**”的章级结构，工作量、理论深度、任务化改造、`2×2` 消融须与参照论文第三章同层次。不得据此建议退化为单机制或只做基线比较；论文证据也不得替代本课题真实实验。

## 强制证据边界

- 检索顺序：本地混合索引 → Zotero 语义检索 → 在线学术检索 → 全文获取与逐项核验。
- 在线结果只作候选。只有本地全文或合法获取并实际阅读的在线全文可以支撑结论。
- 每条主张记录原始 PDF 页码、节、表或公式；转换文本仅作定位辅助。
- 题录以 DOI、arXiv、出版社页面、数据集官方页面或 Zotero 已核标识交叉核验。
- 严格区分目标年无标签特征、目标年标签、目标年验证集、目标年测试集、事后分析和部署期可用信息。
- 当前仓库已历史访问 LSPR24，后续项目评价须标 `target_informed=true`；本文献中原作者的权限不自动成为本课题的合法权限。

## 执行步骤

1. **P0 本地索引**：运行索引状态命令；在 `paper` 作用域、`hybrid` 模式查询 `LSPR`、`LSPR23 LSPR24`、`cross-year`、数据集作者与论文题名；记录索引状态和命中。
2. **P0 Zotero**：语义检索与题名/作者精确检索；读取已有条目的索引全文，记录 Zotero 键、附件和全文可用性，避免重复入库。
3. **P0 在线候选**：用 Google Scholar、学术 MCP 与官方页面补足直接使用 LSPR、官方数据论文和引用网络候选；只登记可核验题录。
4. **P0 全文核验**：对每篇直接相关论文读取原始 PDF；用 MinerU 转换辅助定位，不使用 `pdftotext`；逐篇即时写入 `notes.md`。
5. **P1 比较综合**：按研究问题、年份协议、指标、基线、跨年结果、目标年权限、实验编排和可迁移证据结构形成矩阵。
6. **P1 引用核验**：核对题名、作者、年份、出处、DOI/arXiv/稳定 URL 与主张页码，标出元数据冲突和全文缺口。
7. **P1 交付**：写入 `证据综述.md`，给出事实、研究空白、对两个机制和联合框架的约束，以及 Astra 应重点复核的问题。
