## 现有收据健康参照

当前 FT 基座计算随机实体与时间尾部切分，并断言角色行不交叠。历史 Raw83 加载器另有冻结制品和计数，但它是不同产品；不再将其计数报告为当前 FT 的收据。这些旧口径均不能证明新的严格时间前向合同。

旧切分公式为：

```text
train = 非验证实体 且 非时间尾部
validation = 验证实体 且 非时间尾部
```

因此验证集含有时间尾部之前的序列，训练集也含有时间尾部之前的序列；从设计上不能满足 `max(train_time) < min(validation_time)`。

## 本次未能实测的必要计数

以下项均须由同一次只读、单进程 mmap 源侧扫描给出；目前不能用 `T23` 或实体摘要替代：

1. 每个候选前向窗口训练和验证有效流的最小与最大逐流时间，以及 `max(train_time) < min(validation_time)` 的布尔结果。
2. 训练与验证实体集合、交集、首次出现时间，以及旧“按实体首次出现分组”中晚于训练截止的流计数。
3. 依真实采集日或自然相位边界产生的每个前向留出窗中，清除跨截止实体后的正、负实体数和有效流数。
4. 每个角色仅用该角色截止时间及以前流标签聚合后的正、负实体数；不得使用全期实体标签。
5. 是否存在至少一个训练严格早于验证、实体不泄漏、正负类非空的对照窗。

## 最小解锁接口

在已授权的服务器 CPU 环境，以当前 FT 配置的 Dijk 缓存为发现入口，读取下列**源侧** mmap 制品并输出聚合收据：`I23`、`M23`、`E23`、`y23`、逐流 `mTimestampStart` 与 `mTimestampLast`（或等价、经哈希绑定的两条旁车）。不得打开目标年数组、不得训练或使用 GPU。

诊断必须先以 `mTimestampLast` 定义特征形成/可见时间，再按真实自然采集日或相位边界迭代，而不是预设环境数量或伪造日期。每个窗口必须机械检查：

```text
max(train flow time) < min(validation flow time)
intersection(train entities, validation entities) = empty
labels(role) 仅由 flow_time <= role_cutoff 的流聚合
每个角色的正实体和负实体均非空
```

只有上述收据存在，才能报告实际的最低样本量、统计精度或可用环境数；本报告不对这些量作“足够”判断。

当前路线不得用旧 Protocol A 切分、Raw83 旁车或目标年结果替代当前 FT 缓存的数据门。待安全远端只读访问恢复后，先确认 `mTimestampLast` 是否以可哈希旁车保留；未保留则当前 FT 严格前向合同失败。若存在，再运行一次上述源侧扫描并保存聚合收据；若没有任何窗口同时满足时间严格性、实体隔离和类别非空，则应明确否决该源侧前向对照，而不是改变切分或借用目标年。
