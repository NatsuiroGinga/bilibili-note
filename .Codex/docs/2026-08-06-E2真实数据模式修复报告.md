# E2 真实数据模式修复报告

## 结论

已修复 E2 冻结开发视图无法读取真实 `samples.parquet` 的两项字段模式缺陷。真实 Parquet 使用 `development_split` 和字符串 `binary_label`，冻结 JSONL 清单继续使用 `split_id`；加载后仍统一写入整数 `E2Sample.label` 与 `E2Sample.split_id`，因此下游面板和基线接口不变。

## 根因

- 真实 `samples.parquet` 的开发划分字段为 `development_split`。
- 冻结清单的划分字段为 `split_id`。
- 原实现错误地要求 Parquet 提供 `split_id`。
- 原测试夹具也把 Parquet 写成 `split_id`，因此没有覆盖真实数据模式。
- 真实 `binary_label` 只有 `non_c2` 和 `malicious_c2`，原实现对其执行 `int()` 转换，导致所有基线在数据加载阶段共同失败。
- 原测试夹具使用整数标签，因此没有覆盖真实字符串标签模式。

## 修改文件

- `thesis/experiments/llm_probe/src/flow_probe/e2_hard_domain_data.py`
  - Parquet 投影列由 `split_id` 改为 `development_split`。
  - Parquet 与清单的一致性核验改读 `development_split`。
  - 清单读取和 `E2Sample.split_id` 保持不变。
  - 显式限定标签映射为 `non_c2 → 0`、`malicious_c2 → 1`，其他值一律拒绝。
  - `E2Sample.label` 继续向下游提供整数标签。
- `thesis/experiments/llm_probe/tests/test_e2_hard_domain_data.py`
  - 测试 Parquet 夹具改用真实字段 `development_split`。
  - 增加显式断言，要求 Parquet 包含 `development_split` 且不包含 `split_id`，防止模式回退。
  - 测试夹具改用真实字符串标签，并断言其内部整数映射。
  - 增加未知字符串标签拒绝测试，防止静默接受未登记类别。
