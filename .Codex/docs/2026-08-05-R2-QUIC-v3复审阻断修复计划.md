# R2 QUIC v3 复审阻断修复计划

## 目标

解除 v2 独立复审发现的三个重要问题，以全新 v3 合同和三次全新运行判断 QUIC 用户态采集链路是否可进入字段矩阵。旧 v2 三轮结果保持原裁决，不改写、不复用、不拼接。

## 修复范围

1. 服务端生命周期不再把原始 `-15` 无条件改写为成功。若参考服务端无法自然退出，则新合同显式允许控制器受控发送 `SIGTERM`，并同时记录发送主体、发送时刻、发送前存活状态和原始退出码；审计器逐项核验，不满足时失败。
2. quiche 客户端命令必须传入冻结的 `--source-port`，并由 v3 三次门禁至少覆盖一轮 quiche 固定四元组运行。
3. 旧 v1 配置缺少超时字段时继续使用 900 秒；只有 v2/v3 新配置显式声明 240 秒时才使用 240 秒。
4. 审计器核验启动器状态、开始结束时间不重叠、运行身份恰好三份，并逐项重算状态清单中的制品大小与 SHA-256；不得用常量声明代替机器证据。

## 执行合同

- 修改范围限定为 QUIC 采集器、包装器、审计器和全新 v3 配置；不修改 TCP/UDP 物理拟合代码和数据。
- 新配置保持 `p03/seed43/bulk` 科学参数、64 MiB 载荷、固定方向种子、固定四元组和 240 秒上限。
- 三次新运行使用全新 v3 身份，至少包含一轮 aioquic 和一轮 quiche；串行执行，不重试、不补第四次。
- 审计通过只进入独立复审，不自动恢复完整字段矩阵；失败继续保持 QUIC `UNKNOWN`。
- 按用户本轮明确要求，本任务例外启用一次测试驱动开发：先为四项复审阻断分别编写最小行为测试并观察预期失败，再实施最小修复并运行同一组目标测试至通过。只运行本任务目标测试，不运行完整测试集、格式化、Pyright 或 Git 差异检查；完成后另执行一次精确 Python 编译、Shell 语法和 JSON 合同检查，实际端到端语义仍由三次正式门禁验证。
- QUIC 修复与 TCP/UDP GPU 物理拟合并行，但不得改变后者的代码、配置、资源预算或运行目录。

## 验收

- 三个全新启动器目录、数据根和完整退出状态。
- 服务端原始退出码与受控信号来源证据均保留，审计器不得覆盖原值。
- quiche 实际观察源端口等于冻结源端口。
- v1 缺省超时仍为 900 秒，v3 显式超时为 240 秒。
- 三轮制品清单的路径、大小和 SHA-256 全部重算一致。
- 独立复审严重和重要问题均为 0 后，才允许进入新的字段矩阵。

**已获用户明确要求修复 QUIC，进入 v3 单轮最小实现。**
