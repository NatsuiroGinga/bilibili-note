# E2 v3 物化器摘要绑定修复报告

## 结论

已修复 v3 正式物理池缺少 `source-lock.json` 导致的启动阻断。v3 现在直接使用已由配置 SHA-256 固定的 `matrix-summary.json` 校验场景源码、TCP 真值合同和冻结 512 项清单身份，不生成占位来源锁，也不把摘要伪装成来源锁。

旧 v2 路径仍强制读取独立 `source-lock.json`。若 v2 把矩阵摘要作为来源锁，或 v3 重新声明 `ns3_source_lock`，物化器会立即拒绝。

## 修复内容

1. v3 模式固定为数据版本 `r2-final-tcp-udp-physics-v3` 和摘要模式 `flow_probe_r2_ns3_protocol_dynamics_v2_parallel_summary_v3`。
2. v3 摘要必须同时满足：`review_pending` 状态、四项运行计数、256 个有效配对、v3 窗口模式、方向语义与六个方向字段。
3. v3 摘要直接核对 `scenario_source_sha256`、`contract_sha256` 和 `manifest_sha256`，任一缺失或不一致均结构化拒绝。
4. v2 仍只接受独立来源锁；矩阵摘要路径或带矩阵状态、计数特征的对象不得冒充来源锁。
5. 未改变逐运行收据、CSV 哈希、512 项覆盖、方向字段、划分和最终测试隔离门禁。

## 最小回归覆盖

新增一个聚合回归测试，覆盖：合法 v3 摘要通过；三项来源字段缺失或错误拒绝；错误摘要模式拒绝；合法 v2 来源锁继续通过；矩阵摘要冒充 v2 来源锁拒绝。

## 验证边界

按任务边界只执行 Python 语法检查，不运行本机 `pytest`、格式化、SSH、同步或真实物化。真实 v3 物化仍须由主任务在服务器最小门禁后启动。
