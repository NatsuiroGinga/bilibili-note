# 本地文献混合检索修复实施计划

## 一、目标

依据 `本地文献混合检索优化审计` 和冻结效果评估，修复索引对象、论文身份、结构化元数据、增量向量复用、结果解释与在线降级合同；随后落地 `paper-note-search/v1` 模板、lint 和 `indexed-paper-reading` 薄编排技能。当前规模继续使用 SQLite 与 NumPy 精确点积，不引入向量数据库、近似最近邻或外部向量服务。

## 二、全局约束

1. 效果评估代理提交旧版本冻结基线前，实施代理不得修改 `scripts/literature_search/`、现有检索技能或索引配置。
2. 不修改 `raw/`、`wiki/` 现有论文笔记、Zotero、论文正文、RWKV 实验或服务器制品；模板和 lint 先兼容旧笔记，只报告缺失，不批量重写。
3. 依赖使用 `scripts/literature_search/pyproject.toml` 与 `uv.lock`；禁止系统 Python、全局安装、`/tmp`、`black` 和外部向量服务。
4. 保留临时数据库构建后原子替换；增量更新只复用文本哈希与嵌入合同哈希均一致的向量，不能只依赖路径、位置或修改时间。
5. 旧索引与新索引的对比只使用冻结查询集；不得根据测试查询结果追调融合参数。
6. OpenAlex、Semantic Scholar、Crossref 只返回在线候选，不能升级为本地全文证据。

## 三、实施任务

### 任务 1：P0 索引对象、身份与增量合同

修改范围：

- `scripts/literature_search/documents.py`
- `scripts/literature_search/types.py`
- `scripts/literature_search/storage.py`
- `scripts/literature_search/build.py`
- `scripts/literature_search/config.py`
- `scripts/literature_search/config.json`
- `scripts/literature_search/README.md`

要求：

1. 明确排除所有 `INDEX.md` 和非论文笔记；构建收据记录排除数量与原因。
2. 使用真正的 YAML 解析读取标量和列表；让 `title_zh/authors/year/aliases/tags/key_finding/tasks/datasets/methods/metrics/supports/cannot_support` 进入结构化列和可检索文本。
3. 当前论文 DOI/arXiv 只接受规范 YAML 字段；正文 DOI 只能作为 `cited_doi`，不得生成 `paper_id`。
4. 分开 `paper_id` 与 `note_id`，允许一篇论文多视图；默认按 `paper_id` 聚合，保留视图列表。
5. 以规范路径、标题路径、文本哈希和嵌入合同哈希构造稳定分块键；旧索引只读复用未变向量，变化块重嵌入。
6. `status/build` 输出 `added/changed/deleted/unchanged/reused/reembedded/excluded`、合同变化与陈旧原因。
7. 增量构建与干净全量构建在笔记、分块、FTS 文本、向量字节和冻结查询排序上必须一致。

### 任务 2：P0 结果解释、评估接口与在线合同

修改范围：

- `scripts/literature_search/ranking.py`
- `scripts/literature_search/search.py`
- `scripts/literature_search/cli.py`
- `scripts/literature_search/evaluate.py`
- `scripts/literature_search/online.py`
- `scripts/literature_search/README.md`
- `.agents/skills/literature-hybrid-search/SKILL.md`

要求：

1. 混合结果展示实际贡献于融合排名的最佳证据块，不得固定优先词法片段；输出词法块、向量块、最终证据块及各通道排名。
2. 评估支持多相关项、块级命中、Recall@5/10、MRR、nDCG、去重、延迟、页码/原件存在性、负例与通道独有贡献。
3. 负例只报告当前无可靠拒答门，不凭 16 条查询拍阈值；拒答阈值留待独立开发集。
4. OpenAlex 无密钥时直接 `skipped_missing_key`；删除无密钥普通搜索回退说明。
5. 在线来源并发时 Crossref 保持本进程单飞；记录认证、延迟、缓存、限流、去重和降级原因。本轮不强制实现持久缓存，若未实现须在报告中明确。

### 任务 3：P1 模板、lint 与薄编排技能

新增或修改范围：

- `scripts/literature_search/lint_notes.py`
- `scripts/literature_search/cli.py`
- `.agents/skills/indexed-paper-reading/SKILL.md`
- `.agents/skills/indexed-paper-reading/references/paper-note-search-v1.md`
- `.agents/skills/indexed-paper-reading/references/checklist.md`
- `scripts/literature_search/README.md`

要求：

1. 模板采用 `paper-note-search/v1`，明确题名、中文题名、作者、年份、身份、原件、别名、任务、数据集、方法、指标、支持点、不能支持点、公式页码和关系。
2. lint 检查 YAML 类型、当前论文身份、原件路径、全文状态、物理页锚点、支持/不能支持分区；旧模板默认给出报告而非自动改写。
3. 新技能只编排本仓库特有的 `raw -> wiki -> INDEX -> Zotero -> 索引更新 -> 检索自检`，复用现有 Zotero/Obsidian 技能，不复制通用 PDF 阅读能力。
4. 技能触发、输入输出、失败边界和引用资源必须真实存在；通过 frontmatter、引用路径与技能完整性检查。

## 四、验收

1. Python 编译、模块导入、CLI 帮助、配置解析和技能 frontmatter 各执行一次。
2. 在冻结语料快照上分别执行干净全量构建、无变化增量构建和单篇变化增量构建；记录复用率、重嵌入块数、耗时和索引哈希。
3. 用效果评估代理的冻结查询集运行 lexical/vector/hybrid；修复不得降低既有 Recall@5/10，MRR/nDCG 变化据实报告。
4. 对至少一篇 `paper-note-search/v1` 示例和一篇旧笔记运行 lint，验证严格模式与兼容报告模式。
5. 禁止修改或删除现有论文笔记来制造 lint 通过。
