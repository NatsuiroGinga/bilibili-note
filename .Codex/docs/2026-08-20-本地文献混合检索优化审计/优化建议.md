# 本地文献混合检索优化建议

## 结论

当前系统不需要向量数据库、近似最近邻服务或更大的嵌入模型。511 篇、6854 块的精确向量矩阵只有 10.5 MB，热状态精确点积中位数约 0.74 ms；真正应先修的是索引对象与论文身份、结构化字段可检索性、增量更新、结果证据解释和评估覆盖。

最多三项立即实施建议如下：

1. **P0：冻结论文索引合同并改为内容哈希增量更新。** 排除 `INDEX.md`，只索引合法论文笔记；规范 DOI/arXiv 身份，禁止从正文引用中猜当前论文 DOI；按笔记和分块哈希复用未变向量。
2. **P0：先补检索评估与证据可观测性，再改 BM25、RRF 或模型。** 扩充异质查询与多相关项标注，增加块级命中、Recall、nDCG、去重、延迟和通道贡献；修正混合结果片段与实际命中块不一致。
3. **P1：落地可检索全文笔记模板、lint 和仓库级薄编排技能。** 让 `authors/year/aliases/key_finding/method/tasks/datasets/metrics/supports/cannot_support` 真正进入索引，并机械执行 `raw -> wiki -> INDEX -> Zotero -> 索引更新 -> 检索自检`。

在上述三项有评估结果前，不实施生成式查询扩展、交叉编码器重排、BGE-M3、Faiss、HNSW、外部向量服务或 WAL 常驻写库。

## 主要发现

### P0：索引合同与知识库合同不一致

1. `wiki/papers/**/*.md` 同时收录了 14 个 `INDEX.md`。这些内容地图不是全文论文笔记，却参与 BM25、向量和 RRF。
2. 当前解析器只保留 YAML 中的 `title/source_pdf/doi`。`authors/year/aliases/tags/key_finding/method` 被剥离后不进入任何检索通道。
3. 现有 5 条评估用例的依据写有“别名、标签、`key_finding`”，但这些字段实际上没有进入索引，评价说明与实现不一致。
4. 无显式 DOI 时，解析器扫描正文前 4000 字符并取首个 DOI。这可能把被引用论文的 DOI 当成当前论文身份。现有 22 组重复 DOI 已出现明显错误归属。
5. 混合结果展示片段固定优先选择词法块。若笔记主要由向量通道命中，展示片段可能不能解释最终排序。

**影响：** 检索可能返回内容地图、错误去重、错误本地命中注释和无法解释的片段。此问题比召回模型选择更优先。

### P0：陈旧检测正确但维护粒度过粗

`status` 重新计算全库清单哈希，能发现任何新增、删除或修改；但只返回布尔值，不报告差异，`build` 总是新建临时库、重嵌入 6854 块后原子替换。两处源文件变化触发 348.798 秒全量构建，说明增量复用有直接收益。

建议保留“构建临时索引并原子替换”的读一致性，同时把旧索引作为只读复用源：

- 笔记键：规范相对路径；身份键另存规范 DOI、arXiv 和标题键，不混用。
- 笔记差异：新增、修改、删除、未变四类。
- 分块键：`note_path + section_breadcrumb + chunk_position + normalized_text_hash + embedding_contract_hash`。
- 嵌入合同哈希包含模型名、修订、前缀策略、分词与分块版本；合同变化时才全量失效。
- 未变块复制既有 `float32` 向量；变化块才调用 E5。
- 输出 `added/changed/deleted/reused/reembedded` 数量和耗时。

**预期收益：** 日常新增一篇论文时，把向量计算从全库降到新增或变化块，同时不牺牲原子替换的一致性。

**成本：** 中等，需要稳定分块键、模式迁移和复用验证。

**风险：** 分块顺序变化导致错误复用；必须以文本哈希和嵌入合同哈希共同校验，不能只靠位置。

**验证指标：** 增量索引与干净全量索引的笔记、块、FTS 命中、向量字节和固定查询排序完全一致；报告复用率、重嵌入块数、构建时长和原子替换失败恢复。

### P1：当前分块没有 E5 截断，但语义边界仍可改进

当前配置按 400 字符、80 字符重叠，以任意 Markdown 标题切节。实测 6854 块最大 303 token，没有超过 E5 的 512 token 上限，因此**没有立即缩块或换长文本模型的证据**。

仍有三个结构问题：

- 204 块短于 64 字符，过短块可能只含标题或一句目录说明。
- 所有层级标题都成为独立节，块只保留当前标题，不保留父级标题路径。
- 标题前缀过长时，最终字符数可超过配置的 400，因为预算只最多扣除 133 字符。

建议在 P1 中改为“标题路径 + 段落边界 + token 上限”的确定性分块，并把当前字符策略保留为基线。不要引入 LLM 语义分块。先比较块级 Recall/nDCG 与证据定位，再决定是否调整。

**预期收益：** 减少孤立短块，保留章节上下文，避免未来长公式或 URL 导致静默截断。

**成本：** 中等；会使分块哈希整体变化，需要一次全量迁移。

**风险：** 合并过多会降低证据定位精度，拆分过细会增加标题重复和向量噪声。

**验证指标：** 截断块数必须为 0；短块比例下降；块级 Recall@k、nDCG@k、命中页码率和平均片段可解释性不退化。

### P1：中文 trigram BM25 可保留，但查询构造需受评估约束

SQLite 官方说明 trigram 按连续三字符建立子串索引，适合不依赖空格分词的中文；短于三字符的全文查询无法命中，当前用 `instr` 线性回退，方向合理。

当前查询把所有查询 trigram 用 `OR` 连接，长查询只需命中任意三字符即可入选；再加上每块重复论文标题，可能放大常见片段。FTS5 BM25 固定 `k1=1.2`、`b=0.75`，不是可由当前配置调节的参数。

建议评估以下确定性变体，而不是直接换中文分词器：

- 原始完整 trigram 短语与分词段的 AND/OR 分组。
- `title/aliases/heading/body` 分列并设置列权重，避免标题在正文块中重复计算。
- 基于文档频率丢弃无区分度 trigram，但阈值必须由开发集冻结。
- 中文、英文、缩写、公式符号分别报告，不能只看平均命中率。

**预期收益：** 提高长查询精度和标题命中稳定性。

**成本：** 低到中。

**风险：** AND 过严会损失同义表达召回；必须保留当前 OR 版本作基线。

**验证指标：** Recall@5/10、nDCG@10、MRR、空结果率、短查询延迟与词法独有相关项数量。

### P1：E5 接口正确，需补合同断言和批量实测

固定模型卡要求查询和文档分别加 `query: `、`passage: `，最大 512 token。当前实现正确使用前缀并开启单位归一化；Sentence Transformers 官方说明归一化后可用更快点积，因此 `vectors @ query_vector` 是正确的精确余弦排序。

建议补充：

- 构建元数据记录模型修订、前缀、最大 token、实际 token 分布、截断数和向量范数误差。
- 查询时断言索引嵌入合同与运行时模型合同一致。
- 仅对待编码变化块，在当前机器上实测 CPU 批量大小；当前 `16` 没有记录的硬件依据。
- MPS 只在 `is_available()` 为真且真实批量基准优于 CPU 时启用。本机当前为假，不应围绕 MPS 做架构设计。

**验证指标：** 零截断、向量范数接近 1、重复构建向量差异处于浮点允许范围、每秒编码块数、峰值内存、设备回退原因。

### P1：RRF 继续作为基线，不应把 60 当本域最优

RRF 原论文的 `k=60` 是作者在其先导集上冻结的值。近期融合分析指出 RRF 可能对参数敏感，少量标注下归一化分数组合可更好。当前只有 5 条单相关项查询，不能支持调参或替换融合。

建议：

- 当前保留 `k=60`，明确它是外部默认基线，不是本库验证最优。
- 扩充开发查询后，只在开发集比较少量预先登记的 RRF 常数与归一化线性融合。
- 保留独立冻结测试集，禁止看测试结果再调融合。
- 报告词法独有、向量独有、双通道一致命中，而不只报告最终排名。

### P1：笔记级去重应区分身份、视图与展示

同一论文可能有多个研究路线笔记，这是合法“多视图”；但当前结果把每个 Markdown 文件都当独立论文，并用可能误提取的 DOI 注释本地命中。

建议数据模型：

- `paper_id`：优先规范 DOI，其次 arXiv，最后规范原始题名加年份。
- `note_id`：相对路径，允许一个 `paper_id` 对应多个 `note_id`。
- 默认检索按 `paper_id` 聚合，展示最佳笔记视图并列出其他视图。
- `--show-note-views` 才展开全部笔记。
- DOI 只接受 YAML 规范字段或 Zotero 已核元数据；正文中的 DOI 只能派生为 `cited_doi`，不得充当身份。

**验证指标：** 身份误并率、重复展示率、合法多视图保留率、DOI/标题/arXiv 三种匹配冲突数。

### P1：元数据过滤与引用链应基于已核字段，不应用向量猜

当前 SQLite 没有作者、年份、任务、数据集、方法、指标和引用关系列。应将这些字段作为确定性过滤和解释信息：

- 过滤：作者、年份范围、标签、任务、数据集、方法、指标、证据等级、全文核验状态。
- 引用链：作者显式写入的 `related`、正文双向链接和已核参考文献 DOI；索引器派生有向边和反向边。
- 先过滤后排名时必须记录过滤条件和候选数量；空结果允许降级为“取消某项过滤”的建议，不能静默放宽。
- 在线引用与被引关系只用于候选发现，未有本地全文前仍标“未核全文候选”。

### P2：查询扩展和交叉编码器都应等评估集就绪

第一阶段只做可审计的确定性扩展：规范缩写、YAML `aliases`、中英文题名、方法全称与缩写。每个扩展词必须回指笔记字段，原查询始终保留。

生成式 Query2doc/HyDE 和交叉编码器重排均有文献依据，但不立即采用：

- 生成式扩展可能包含虚构术语，增加联网、成本和非确定性。
- 交叉编码器适合重排小候选集，但引入第二模型和逐对推理；只有首阶段 Recall 足够、最终 nDCG 仍不足时才有意义。
- 若进入实验，先冻结候选数、模型修订、最大长度、超时和回退；评估增益、延迟和资源，不得只报最好查询。

### P2：当前不需要向量数据库或 ANN

当前矩阵只有 10.5 MB，热状态加载约 39 ms，精确点积约 0.74 ms。Faiss 官方指南也强调少量查询时直接计算更合适，Flat 才保证精确结果。

继续使用 SQLite BLOB + NumPy 精确点积。更值得做的是让查询进程复用一次加载的只读矩阵，避免每次从 SQLite 重建数组。

只有同时出现以下证据时再评估 ANN：

- 精确矩阵常驻内存超出目标环境预算；或
- 代表性并发下 P95/P99 延迟超过明确服务目标，且剖析确认向量扫描是主因；或
- 语料规模增长后，精确扫描占查询时长的主要部分。

届时以精确结果为金标准，报告 ANN Recall@k、延迟、内存、构建时间和增量更新成本。禁止仅凭“未来可能变大”引入服务。

### P2：WAL 不是当前必要条件

当前查询以 `mode=ro&immutable=1` 打开索引，构建临时数据库后 `os.replace`，读路径简单且一致。WAL 会增加检查点和伴随文件管理，只在改为长期开启的可写数据库且真实读写冲突出现时有价值。

推荐的增量方案仍在临时库中复用旧向量并原子替换，不需要 WAL。若未来做常驻服务，再依据 SQLite 官方约束单独设计同机 WAL、单写者、检查点和备份合同。

### P1：在线降级需更新当前合同

1. OpenAlex 官方变更日志说明 2026-02-13 起所有 API 调用要求密钥。无密钥时应直接标记 `skipped_missing_key`，不要再尝试普通搜索并称为“回退”。
2. 三个来源当前串行，最坏延迟可接近三个超时之和。可并发独立请求，但 Crossref 公共池并发限制为 1，只能保证本进程对 Crossref 单飞。
3. 缓存规范化查询与提供者响应，记录获取时间和过期策略；对 403/429 使用 `Retry-After` 或指数退避，不在一次交互内盲重试。
4. 以 DOI、arXiv、提供者 ID、规范题名加年份跨来源去重，保留 `providers` 列表，不把同一论文计为多条候选。
5. 记录每来源延迟、认证状态、降级原因、返回数、去重后新增数和缓存命中。
6. `scope=all` 继续把本地全文证据与在线候选分区，在线失败不得清空本地结果。

## 面向混合检索的论文全文笔记写作规范

### 规范版本与适用边界

- 模板版本：`paper-note-search/v1`
- 适用对象：已获得并核验全文、原件已落 `raw/papers/` 的论文。
- 不适用：仅摘要、搜索结果、网页占位、尚未获得全文的候选。此类内容只记入 `.Codex/docs/` 的待获取清单。
- 兼容说明：当前解析器尚不能索引本规范的大部分 YAML 字段；必须与“结构化字段进入索引”的 P0/P1 修改一同验收。

### 作者写入与索引器派生的边界

| 信息 | 作者必须写入 | 索引器应派生 | 禁止行为 |
|---|---|---|---|
| 题名 | 官方原文题名 `title`、准确中文题名 `title_zh`、已使用缩写与别名 `aliases` | 规范大小写、标点和标题键 | 自动翻译后冒充官方题名 |
| 作者与年份 | `authors` 列表、`year` 整数 | 规范作者检索键、`FirstAuthorYear` 别名 | 从正文引用猜作者或年份 |
| 身份 | 核验后的 `doi`、`arxiv_id`，未知写 `null` | 规范 DOI/arXiv、冲突检测、`paper_id` | 从正文首个 DOI 认定当前论文 |
| 原件 | `source_pdf` 双向链接、全文核验状态 | 路径存在性、文件哈希、PDF 元数据对照 | 把落地页或摘要当全文 |
| 研究语义 | `tasks/datasets/methods/metrics` 与正文对应章节 | 规范词表、过滤列、同义词倒排 | 仅写宽泛标签而无正文证据 |
| 论断 | “论文支持”“不能支持”“本课题假设”“负证据”分区 | 生成检索字段和证据等级，不改写语义 | 索引器推断因果或升级证据 |
| 公式与页码 | 公式、符号、印刷页、PDF 页、式号/表号 | 页码标准化、块级定位 | 只写“见论文”或只留脚本提取页 |
| 关系 | 显式双向链接并写关系类型 | 正反向图边、引用邻域 | 仅凭向量相似自动写知识关系 |
| 分块 | 自包含标题、单一论证段落 | 标题路径、token 数、重叠、块哈希 | 作者手工复制重叠文本 |

### YAML 字段

必填字段沿用 `SCHEMA.md` 与 `wiki/AGENTS.md`，并增加检索字段：

```yaml
---
schema: paper-note-search/v1
title: "官方原文题名"
title_zh: "准确中文题名"
authors:
  - "第一作者"
  - "第二作者"
year: 2025
date: 2026-08-20
journal: "会议、期刊或预印本"
doi: "10.xxxx/xxxxx" # 无 DOI 时写 null
arxiv_id: null # 有则写不带 URL 的规范标识
source_pdf: "[[raw/papers/领域/论文.pdf]]"
fulltext_verified: true
tags:
  - "主题/具体方向"
  - "类型/论文"
aliases:
  - "常用缩写"
  - "英文短题名"
  - "中文检索别名"
tasks:
  - "论文直接处理的任务"
datasets:
  - "论文实际使用的数据集"
methods:
  - "方法全称"
  - "方法缩写"
metrics:
  - "论文实际报告的指标"
key_finding: "带适用范围的一句话原结论，不写本课题尚未验证的推论。"
related:
  - "[[相关论文笔记]]"
zotero_key: null
---
```

字段规则：

- `title` 保留原文官方题名；中文翻译单列 `title_zh`，不覆盖原题名。
- `aliases` 只放真实使用或可核验的别名、缩写、连字符变体和中英表达，不堆关键词。
- `authors` 保持题录顺序；检索器负责大小写、姓名顺序和变音符规范化。
- `year` 采用规范出版年；预印本与正式出版年冲突时在正文“题录与版本”说明。
- `doi/arxiv_id` 只能写当前论文标识；引用文献标识写在正文引用关系，不进入当前身份。
- `tasks/datasets/methods/metrics` 只写论文实际使用或评估内容；本课题计划不得混入。
- `key_finding` 同时包含对象、条件、结果和边界，避免“效果很好”“提出新方法”等空话。

### 反例

```markdown
---
title: "一个中文简称"
doi: "正文里最先出现的 DOI"
tags: [深度学习, 安全]
---

## 方法

提出了一个先进方法，效果显著，可以用于本课题。

## 结果

准确率提升很多，详见论文。
```

问题：

- 中文简称覆盖官方题名，英文题名和别名不可检索。
- DOI 未说明是否属于当前论文，可能误取引用文献。
- 没有作者、年份、原件、全文状态、任务、数据、方法和指标。
- “先进”“显著”“可以用于”均无比较对象、数值、页码和适用边界。
- 标题过泛，脱离父章节后没有检索上下文。
- 没有负证据、不能支持点和本课题假设边界。

### 写作规范的检索验证

建立模板前后对照，但不能用最终测试查询调模板：

1. 在写笔记前冻结查询意图，不看检索结果。每篇核心论文至少覆盖题名、作者年份、缩写、中文/英文、方法加数据集、指标、公式页码、支持点、不能支持点、引用邻域等类型中的适用项。
2. 允许一个查询对应多篇相关论文，并给 0/1/2 级相关性；禁止只登记唯一目标路径。
3. 开发集用于模板和索引器修订，冻结测试集只用于最终比较。
4. 同时报告笔记级 Recall@5/10、nDCG@10、MRR，块级证据命中率、正确页码率、元数据过滤准确率、重复论文聚合准确率。
5. 分层报告中文、英文、跨语言、缩写、作者年份、公式、负证据和引用链，避免平均值掩盖失败类型。
6. 每次模板或索引合同变更记录版本、受影响笔记数、重建块数和指标差异。

## 技能路线裁决

### 两条路线比较

| 路线 | 优点 | 缺点 | 裁决 |
|---|---|---|---|
| 扩展 `source-command-zotero-notes`、`obsidian-source-ingestion`、`zotero-obsidian-bridge` | 复用成熟的全文读取、Zotero 元数据、证据记录和 Obsidian 写回原则 | 三个技能是跨项目通用能力，默认目标为 `Sources/Papers/`、`Knowledge/`、`Writing/`；写入本仓库特有的 `raw/wiki/INDEX/Git/索引重建` 会污染通用合同并影响其他项目 | 不推荐直接扩展全局技能承载本仓库流程 |
| 新建仓库级 `indexed-paper-reading` 薄编排技能 | 可精确绑定本仓库路径、Git 快照、SCHEMA、INDEX、Zotero 状态和检索自检；不影响其他项目 | 新增一个入口，若内容写成通用读论文教程会与现有技能重复 | **推荐，但必须只做仓库编排，阅读与证据方法继续调用现有技能** |

### 推荐技能规格

- 路径：`.agents/skills/indexed-paper-reading/SKILL.md`
- 建议触发描述：

> 当用户要求把一篇或一批论文正式纳入本仓库 `raw/papers/` 与 `wiki/papers/`、补全已有全文论文笔记并确保本地混合检索可检出时使用。不用于仅搜索候选、仅做普通 Zotero 摘要、通用 Obsidian 入库、相关工作综述或论文正文写作。

- 输入：本地 PDF、论文 URL、DOI、arXiv ID、Zotero item/collection 中至少一种；目标主题目录；预期检索意图；是否允许更新现有笔记。
- 输出：规范原件及哈希、唯一规范 wiki 笔记、更新后的方向 `INDEX.md`、Zotero 条目/附件状态、索引增量收据、检索自检收据。
- 分工：
  - `source-command-zotero-notes`：从 Zotero 取题录、全文、批注和既有笔记。
  - `obsidian-source-ingestion`：复用“来源中心、规范源笔记、索引更新”的一般原则，但本仓库路径由局部技能覆盖。
  - `zotero-obsidian-bridge`：复用 Evidence Record 与 Claim Promotion Gate，不采用其默认 `Sources/Papers -> Knowledge -> Writing` 目录。
  - `literature-hybrid-search`：只负责查询与候选发现，不负责入库。
  - `indexed-paper-reading`：只负责编排本仓库从原件到可检索笔记的完整收据。
- 模板版本：固定引用 `paper-note-search/v1`；技能不得内嵌另一份漂移模板，应从仓库模板文件加载。实施时建议模板落 `.Codex/docs/` 规范目录或 `wiki/templates/`，具体路径先由知识库维护者裁决。

### lint 规则

阻断项：

- YAML 可解析，`schema` 版本受支持。
- 必填字段存在且类型正确；`authors`、`aliases`、`tasks` 等必须是列表。
- `source_pdf` 指向存在的 `raw/papers/` 文件，全文核验状态为真。
- `doi/arxiv_id` 格式规范，且不与另一 `paper_id` 冲突；未知必须显式 `null`。
- `tags` 含 `类型/论文`；至少一个主题标签。
- 必须包含“论文可以支持”“论文不能支持”“实验结果与负证据”“与本课题的关系”。
- 关键公式和数值必须有印刷页或 PDF 页及式号/表号。
- 新笔记必须被对应 `INDEX.md` 或相关笔记引用。
- Zotero 未完成时可记录阻塞，但不得伪造 key。

警告项：

- 缺少中英文别名、可检索术语或显式关系类型。
- 单个正文块超过当前兼容预算，或短于能独立表达证据的完整句。
- 标题使用“方法”“结果”等脱离父级后无语义的泛化名称。
- `key_finding` 缺任务、数据、指标或边界。

### 端到端流程

1. **raw：** 查重 DOI/arXiv/题名，保存原始 PDF，计算哈希，不改原件。
2. **wiki：** 读取 `SCHEMA.md` 与 `wiki/AGENTS.md`，按 `paper-note-search/v1` 创建或补全唯一规范笔记；执行全文页级核验与 lint。
3. **INDEX：** 更新唯一对应方向的 `INDEX.md`，写清链接别名和一句话关系。
4. **Zotero：** 创建或复用条目与附件，记录 `zotero_key`；若 Zotero 已是输入源，则此步改为双向核对而非重复导入。
5. **索引更新：** 运行 `status`，执行增量构建；收据记录新增、变化、复用和重嵌入块。
6. **检索自检：** 使用写笔记前冻结的 3 至 5 个代表性意图做本地查询，检查论文级与证据块级命中；这些是入库自检，不纳入系统效果评估集。
7. **收据：** 报告原件、笔记、INDEX、Zotero、索引和自检路径，列出未关闭阻塞。

## Codex 自动触发建议

保留现有 `literature-hybrid-search` 作为“查找、相关工作、直接近邻、引用核验、研究空白”的检索入口。新增技能仅匹配“正式纳入、全文阅读并入库、补全论文笔记、让论文可检索”等动词，避免两个技能抢同一请求。

自动触发后必须机械执行：

1. `status --json`。
2. `stale=false` 才查询；`stale=true` 时报告具体差异并执行已授权的增量构建。
3. 本地查询默认 `--offline --scope local`。
4. 只有本地证据不足或明确要求近期外部候选，才启用在线来源。
5. 输出始终区分本地全文证据、在线摘要候选和题录核验候选。

## 评估与可观测性合同

### 离线效果

- 查询集至少覆盖：精确题名、中文概念、英文概念、跨语言、缩写、作者年份、方法加数据集、指标、公式、页码、支持点、不能支持点、引用邻域、负证据。
- 相关性允许多答案和分级标注。
- 指标：Recall@5/10、nDCG@10、MRR、块级证据命中率、正确页码率、去重准确率、过滤准确率。
- 对比：词法、向量、RRF；后续候选才加入分数融合、扩展或重排。
- 数据隔离：开发查询用于选择参数，冻结测试查询只用于最终报告。

### 运行可观测性

- 构建：来源数、合法论文数、排除数及原因、块数、token 分布、截断数、复用/重嵌入数、设备、吞吐、峰值内存、索引字节、合同哈希。
- 查询：模式、过滤器、候选数、各通道命中数、RRF 贡献、模型加载/查询编码/向量加载/点积/FTS/融合各阶段耗时、缓存命中。
- 在线：每来源认证状态、调用状态、HTTP 类别、延迟、结果数、去重后新增数、退避与缓存状态，不记录凭据。
- 质量告警：错误 DOI 身份、重复 `paper_id`、无效 `source_pdf`、缺页码证据、索引陈旧、嵌入合同不匹配、截断块。

## 风险与阻塞

- 本任务没有运行效果评估代理负责的冻结查询，因此所有“预期收益”均为待验证工程假设，不是已证实提升。
- 重复论文中存在合法多视图笔记，不能按 DOI 或题名自动删除；需要知识库治理裁决。
- OpenAlex 无密钥现在不可用；本任务未读取或输出任何凭据。
- 本机 MPS 当前不可用，CPU 批量最优值仍需后续真实基准确定。
- 本任务不修改生产代码、不更新 wiki、不访问 Zotero、不重建陈旧索引。
