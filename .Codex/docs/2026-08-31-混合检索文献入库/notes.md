## 1. Rank-K: Test-Time Reasoning for Listwise Reranking

- arXiv `2505.14432`，2025-05-20，cs.IR / cs.CL，15 页 4 图，无会议信息
- 作者：Eugene Yang, Andrew Yates, Kathryn Ricci, Orion Weller, Vivek Chari, Benjamin Van Durme, Dawn Lawrie
- 建议原件名：`2025-Yang-Rank-K-Test-Time-Reasoning-Listwise-Reranking-arXiv2505.14432.pdf`
- 裁决：**入库**。本批中方法论价值最高的一篇。

### 全文事实（锚点）

- 方法（3.2、3.3）：由 QwQ-32B 微调，蒸馏 DeepSeek-R1 的推理轨迹；输入查询＋带编号段落列表，
  输出形如 `[3] > [2] > [4] = [1] > [5]` 的序号排列，允许并列。
- 一阶段检索器：BM25、SPLADE-v3、PLAID-X、CoCondenser。
- 数据集（表 2）：TREC DL 2019（43 查询 / 8,841,823 文档）、DL 2020（54 / 同库）、
  NeuCLIR 波斯语（174 / 2,232,016）、俄语（171 / 4,627,541）、中文（167 / 3,179,206）、
  BRIGHT（12 个子集，推理密集型查询）。DL 为关键词查询，NeuCLIR 为自然语言跨语言查询。
- **表 3 主结果（nDCG@10，五数据集均值与相对增幅）**：
  - BM25 一阶段 `0.416` → RankZephyr `0.424 (+2%)`、Rank1-32B `0.506 (+22%)`、
    R1 教师 `0.543 (+30%)`、Rank-K `0.525 (+26%)`
  - SPLADE-v3 一阶段 `0.571` → RankZephyr `0.539 (−6%)`、Rank1-32B `0.609 (+7%)`、
    R1 教师 `0.645 (+13%)`、Rank-K `0.642 (+12%)`
- 表 4（BRIGHT，top-100 滑窗）：RankZephyr-7B 均值 `21.3`、Rank1-32B `29.4`、Rank-K `33.3`。
- 成本（3.2、表 1）：每次调用平均输入 `1,024.65` token、输出 `2,408.85` token，
  输出/输入比 `2.4×`，90 分位输出 `3,957` token；生成 10 万条训练样本约 `1,900` 美元、`36` 小时。
  推理实验统一把文档截断到 `450` token（第 4 节）。
- 局限（第 5、5.3 节）：蒸馏存在知识损失；推理轨迹过长；
  且明确写「improvements are small on the TREC DL 2019 and 2020 benchmarks,
  which have been heavily exposed in hyperparameter tuning」。

### 与本项目的对照

- **提升条件**：增益随一阶段强度**单调衰减**。同一个 Rank-K，在弱一阶段（BM25）上 `+26%`，
  在强一阶段（SPLADE-v3）上只剩 `+12%`。更关键的是 RankZephyr 在强一阶段上是 **`−6%`**，
  即弱重排器会主动**损坏**已经很好的一阶段排序。
- **语料与查询**：百万到千万级文档、跨语言、推理密集型查询。本项目 510 篇笔记、
  单一狭窄领域、模板高度统一，与其任一实验设定都不在同一量级。
- **基线强度**：其增益基线 BM25 均值 `0.416`（满分 1.0），离饱和极远。
  本项目 lexical 已 MRR `1.0000`，对应「一阶段已到顶」的极端，
  按该文自己的趋势外推，重排增益应为零或负。
- **可否被当前评测集检验**：**否**。评测集三法均近满分，任何重排都无处体现。
  该文自陈 DL19/DL20 因「被反复调参暴露」而增益很小，是同型现象的作者自证。
- **可迁移**：只迁移**判据**——「先测一阶段是否饱和，再决定要不要重排」，
  以及「弱重排器可能是负收益」。不迁移方法（32B 模型、每查询数千 token 推理，
  对 510 篇笔记的检索是数量级失配的成本）。

## 2. Blending Learning to Rank and Dense Representations for Efficient and Effective Cascades

- arXiv `2510.16393`，2025-10-18，cs.IR / cs.LG / cs.PF，无会议信息
- 作者：Franco Maria Nardini, Raffaele Perego, Nicola Tonellotto, Salvatore Trani
- 建议原件名：`2025-Nardini-Blending-LTR-Dense-Representations-Cascades-arXiv2510.16393.pdf`
- 裁决：**入库**。对本项目「lexical 已足够」的结论提供最直接的外部对照。

### 全文事实（锚点）

- 方法（图 1）：两阶段级联。一阶段稠密检索器 + FAISS IVF 近邻搜索（768 维）；
  二阶段 LambdaMART 重排 top-K。
- 特征集：共 `2,559` 维＝查询表示 `768` ＋ 段落表示 `768` ＋ 差值 `768` ＋ 余弦相似度
  ＋ 稠密相似度排名 ＋ `253` 个手工词法特征。
- 训练：MS-MARCO 段落集，约 `500k` 标注查询，每查询 30 个负例，
  共约 `15.6M` 查询/文档对。评测：MS-MARCO Dev、TREC DL19（43 查询）、DL20（54 查询）。
- **表 1 关键行（nDCG@10，Dev / DL19 / DL20）**：
  - STAR（20 probes）一阶段：`0.3317 / 0.5432 / 0.5381`
  - STAR（1,000 probes）一阶段：`0.3684 / 0.5793 / 0.5734`
  - CONTRIEVER（1,000 probes）一阶段：`0.3968 / 0.6037 / 0.6215`
  - STAR + LambdaMART full（20 probes）：`0.3627 / 0.5656 / 0.5527`，延迟 `23.31 ms`
  - STAR + LambdaMART full（1,000 probes）：`0.4089 / 0.6359 / 0.5925`，延迟 `268.97 ms`
  - CONTRIEVER + LambdaMART full（1,000 probes）：`0.4134 / 0.6131 / 0.6475`，延迟 `268.79 ms`
  - BM25 + MonoBERT：`0.3967 / 0.6362 / 0.6331`
  - BM25 + MonoELECTRA：`0.4078 / 0.6317 / 0.6832`
  - BM25 + ELECTRA-large：`0.4483 / 0.6768 / 0.7363`
- **消融（表 1，STAR 1,000 probes）**：
  - 只用词法特征：`0.4010 / 0.6259 / 0.5908`
  - 只用稠密特征：`0.3726 / 0.5797 / 0.5828`
  - 全特征：`0.4089 / 0.6359 / 0.5925`
- 特征重要性：top-20 中 `13` 个稀疏词法特征、`6` 个稠密特征、外加余弦相似度；
  作者称重要的稠密特征绝大多数属于**文档**表示而非查询表示。
- 摘要级主张：`nDCG@10` 最高提升 `11%`，平均查询延迟只增加 `4.3%`。
- 边界（第 6 节）：作者承认 ELECTRA-large 在三个数据集上**效果全面更好**，
  自己的优势是 CPU 上比 GPU 交叉编码器快 `7×` 到 `23×`。

### 与本项目的对照

- **「11%」的基线是什么**：是**稠密一阶段**，不是强词法基线。
  Dev 上 `0.3684 → 0.4089` 即 `+11.0%`（相对），但对照 `BM25 + ELECTRA-large` 的 `0.4483`，
  这个「最好结果」仍然落后。所以该文的增益属于**把弱一阶段补齐**，不是超越强基线。
- **混合到底加了多少**：把消融读到位——只用词法特征已达 `0.4010`，
  加满 2,559 维稠密特征后是 `0.4089`，**相对增益仅 `+2.0%`**；
  而只用稠密特征是 `0.3726`，比只用词法**低 `7.1%`**。
  即：词法信号承担了绝大部分效果，稠密信号的边际贡献很小。
  这与本项目「hybrid 相对 lexical 零提升、vector 单独更差」在**方向上完全一致**，
  差别只是本项目因评测饱和把 `+2%` 压到了 `0`。
- **语料与查询**：MS-MARCO 千万级段落、开放域、真实用户查询、`500k` 条人工标注训练查询。
  本项目 510 篇笔记、无标注训练集、无法训练 LambdaMART（`15.6M` 对的训练数据规模不存在）。
- **可否被当前评测集检验**：**否**。若把评测集换成难查询分层版本，
  该文的消融协议（词法-only / 稠密-only / 全特征三分对照）**可以直接照搬**，
  这是本批唯一一个协议层面可直接复用的东西。
- **可迁移**：三分消融协议 + 「报告混合增益时必须同时给出词法-only 上界」的口径要求。
  不可迁移：LambdaMART 级联本身（无训练数据）、253 维手工词法特征（为 MS-MARCO 设计）。

## 3. Establishing Strong Baselines for TripClick Health Retrieval

- arXiv `2201.00365`，2022-01-02，cs.IR / cs.CL，**ECIR 2022 接收**
- 作者：Sebastian Hofstätter, Sophia Althammer, Mete Sertkan, Allan Hanbury
- 建议原件名：`2022-Hofstatter-Establishing-Strong-Baselines-TripClick-ECIR-arXiv2201.00365.pdf`
- 裁决：**入库**。作为「弱基线导致虚高增益」的直接判例，以及评测集分层设计的模板。

### 全文事实（锚点）

- TripClick 集合（2.1）：`1.5M` 段落（平均 `259` 词），`680,000` 条点击训练查询（平均 `4.4` 词），
  `3,525` 条测试查询，按**查询频次**分为 Head / Torso / Tail 三档，**每档 1,175 条**。
  Head 用 DCTR 点击模型产生相关性信号，Torso 与 Tail 用原始点击。
- 训练配方（3.1）：每训练查询取 BM25 前 `500` 候选，每个正例随机采样至多 `20` 个负例，
  剔除相关池中的候选，丢弃位置信息，打乱后保留 `10M` 三元组。
- **原始 TripClick 基线 BM25（表 1 第 1 行，nDCG@10 / MRR@10）**：
  Head `.140 / .276`、Torso `.206 / .283`、Tail `.267 / .258`。
  作者指出原基线在 Tail 上「只比 BM25 高 1–3 个点」。
- **表 1 重排结果（BM25 top-200 上重排）**，Head / Torso / Tail 的 nDCG@10：
  TK `.232 / .300 / .345`；ColBERT-SciBERT `.270 / .326 / .374`；
  BERT_CAT-BERT-Base `.287 / .349 / .396`；BERT_CAT-SciBERT `.294 / .360 / .408`；
  BERT_CAT-PubMedBERT-Full `.298 / .365 / .412`；集成 `.303 / .370 / .420`（MRR@10 Head `.601`）。
- 表 2 稠密检索（仅 Head）：BM25 `J@10 31%`、nDCG@10 `.140`、MRR@10 `.276`、R@1K `.834`；
  BERT_DOT-SciBERT `J@10 41%`、nDCG@10 `.243`、MRR@10 `.530`、R@1K `.793`。
- **弱基线的根因（3.1）**：原始负采样把「未点击结果」当负例，产生大量假负例，
  「confusing the models during training」，表现为逐对训练准确率低、打分间隔无区分度。
  改进负采样后 MRR@10 从 `.41` 提到 `.6`、nDCG@10 从 `.21` 提到 `.30`，
  作者称 `45–50%` 的改进。
- 局限（2.1）：点击标签质量与生产界面的过滤机制未公开，作者拿不到排序方案与分面过滤数据。
- **复核注意**：Head 的 BM25 nDCG@10（`.140`）低于 Tail（`.267`），
  但两档用的是**不同的相关性构造方式**（DCTR 对原始点击），跨档绝对值不可直接比较。

### 与本项目的对照

- **提升条件**：其 `45–50%` 提升**不是模型改进带来的**，而是**修好了一个坏掉的训练协议**。
  这正是「大幅提升＝补齐弱基线」的教科书案例，而且是作者自己承认的。
- **对本项目的直接含义**：反过来说明——当一个报告显示混合检索大幅超越词法时，
  第一诊断不应是「混合有效」，而应是「词法基线是不是被做弱了」。
  本项目 lexical MRR `1.0000` 处在相反的极端，不存在这个解释空间。
- **唯一可迁移且值得做的东西：评测集按频次/难度分层**。
  TripClick 用 Head/Torso/Tail 各 1,175 条把单一评测集拆成三个难度档，
  使不同方法在 Tail 上仍能拉开差距。本项目 25 条查询、三法近满分，
  **当前评测集已饱和，任何改进都无从体现**——这是硬约束。
  分层本身不能凭空造出难查询，需要先扩充查询集并引入
  「低频词、跨笔记、同义改写、只出现在正文深处」这类困难面。
  这是**评测集重建工作**，不是检索算法工作，且属于主代理评测线的范围，此处只登记不执行。
- **不可迁移**：BERT_CAT / ColBERT / 领域预训练模型这条路线。
  其训练依赖 `10M` 三元组和 `680k` 条点击查询，本项目没有点击日志也没有相关性标注。

## 4. From Retrieval to Generation: Comparing Different Approaches

- arXiv `2502.20245`，2025-02-27，cs.CL，注释为 **"work on progress"**（未定稿）
- 作者：Abdelrahman Abdallah, Jamshid Mozafari, Bhawna Piryani, Mohammed Ali, Adam Jatowt
- 建议原件名：`2025-Abdallah-From-Retrieval-to-Generation-Comparing-Approaches-arXiv2502.20245.pdf`
- 裁决：**入库，但定位为背景性比较研究，证据权重低**。

### 全文事实（锚点）

- 比较对象（第 3 节）：稀疏检索 BM25；稠密检索 DPR、MSS、MSS-DPR、Contriever；
  生成式 GenRead；零样本 LLM 重排 UPR 与 RankGPT；以及检索＋生成的混合。
- 数据（4.1）：NQ（79,168 训练 / 3,610 测试）、TriviaQA（78,785 / 11,313）、
  WebQ（3,417 / 2,032）；证据库为 2018-12 维基百科，**超过 2,100 万段落**，每段 100 词。
  另有 TREC-DL19（43 查询）、DL20（54 查询）、BEIR（18 个任务）、WikiText-103（逾 1 亿 token）。
- **表 1（top-1 准确率）**：BM25 在 NQ `22.11%`、TriviaQA `46.30%`、WebQ `18.90%`；
  Contriever `22.16% / 34.16% / 19.98%`；DPR `48.67% / 57.47% / 44.83%`；
  MSS-DPR `50.17% / 61.64% / 44.24%`；GenRead `45.76% / 69.41% / 51.03%`。
- **表 5（BEIR nDCG@10 均值）**：BM25 `43.42` → BM25+RankGPT `49.37` →
  BM25+GenRead+RankGPT `52.59`。
- 表 6（WikiText-103 困惑度）：GPT-2 XL 无上下文 `20.0`、BM25 检索 `16.56`、
  纯生成 `24.91`、检索＋生成 `19.22`；OPT-13B 对应 `12.7 / 10.83 / 16.39 / 13.35`。
- 结论（第 8 节）：检索模型在事实准确性上强，生成模型上下文丰富但一致性差，
  混合在问答与重排上最好；但**在语言建模上混合与生成都没有稳定超过纯检索**。
- 局限：混合模型计算复杂度随语料规模与文档长度增长；稠密检索器效果高度依赖训练语料质量；
  评测局限于标准基准，未覆盖医疗、法律等领域场景。

### 与本项目的对照

- **提升条件**：全部在开放域、2,100 万段落、自然语言问句上取得。
  BM25 在 NQ 上 top-1 只有 `22.11%`——这是一个**极弱的绝对水平**，
  混合方法的空间几乎全部来自这里。本项目 lexical MRR `1.0000`，不存在同类空间。
- **`43.42 → 52.59` 的性质**：增益来自**加 LLM 重排（RankGPT）和加生成文档**，
  不是来自「稀疏＋稠密融合」。该文没有做「BM25 vs 稠密 vs BM25+稠密融合」的干净三分对照，
  因此**不能用它论证稀疏—稠密混合本身有效**。这一点必须写清，
  否则很容易被误引成支持 hybrid 的证据。
- **可否被当前评测集检验**：**否**。且本项目检索工具是纯检索、不做生成，
  该文一半以上的结论（GenRead、in-context learning、困惑度）对本项目无接口。
- **唯一有用的一条**：语言建模上纯 BM25 检索困惑度最低（`16.56` 对混合 `19.22`），
  即**加了语义/生成成分反而更差**，与本项目「vector 单独更差」同向。
  但这是不同任务上的弱类比，只能作为叙述性旁证，不能当作实验证据。

## 5. Advancing Retrieval-Augmented Generation for Structured Enterprise and Internal Data

- arXiv `2507.12425`，2025-07-16，cs.CL / cs.AI / cs.CE / cs.IR，无会议信息
- 作者：Chandana Cheerla（单作者）
- 建议原件名：`2025-Cheerla-Advancing-RAG-Structured-Enterprise-Data-arXiv2507.12425.pdf`
- 裁决：**入库，但仅作为反面教材登记；不得作为任何设计依据。**

### 全文事实（锚点）

- 管线（第 3 节）：递归字符切分（`2000` 字符块、`500` 字符重叠）；Camelot 抽表为 JSON；
  spaCy NER 做元数据标注；`all-mpnet-base-v2` 稠密向量存 FAISS HNSW，并与 BM25 并行；
  **融合公式（3.3.3）`Score = 0.6 × Score_dense + 0.4 × Score_sparse`**；
  `ms-marco-MiniLM-L-12-v2` 交叉编码器重排；LLaMA/Mistral 做查询改写与扩展；
  Mistral-7B 生成答案；`ConversationBufferMemory` 保留最近 10 轮。
- 数据（4.1）：「公开的 HR 政策」与「企业报告」，另提到 data.gov.in、UCI Adult、
  某 HR Analytics GitHub 仓库。
- **表 1（唯一结果表）**：Direct LLM / Naive RAG / Advanced RAG 的
  Precision@5 `62% / 75% / 90%`，Recall@5 `58% / 74% / 87%`，MRR `0.60 / 0.69 / 0.85`，
  Faithfulness `2.8 / 3.0 / 4.6`，Completeness `2.3 / 2.5 / 4.2`，Relevance `2.9 / 3.2 / 4.5`
  （后三项为 5 分李克特量表）。
- **二次定向核验（针对评测协议）结果，逐条为「论文未报告」**：
  - 未报告用于计算表 1 指标的**评测查询条数**；
  - 未说明**相关性标注由谁产生**（只提到定性评估有人工参与）；
  - 未报告**语料规模**（文档数或分块数均无）；
  - 未做显著性检验，也没有多次运行或方差；
  - **没有 BM25-only / 稠密-only / 混合的消融**，基线「Naive RAG」是稠密-only 且无重排。
- 局限（第 6 节）：静态索引需全量重建；嵌套表格处理差；反馈依赖用户显式点赞点踩；
  查询改写会误解意图；大语料下检索延迟与内存有压力。

### 与本项目的对照

- **提升条件无法核验**。语料规模、查询条数、标注来源、方差全部缺失，
  `62% → 75% → 90%` 这条链条**不可复现、不可比较**。
  按本仓库根 `AGENTS.md` 的证据纪律，这类结果只能记为「未验证」。
- **基线强度**：其基线是「无检索的 Direct LLM」和「稠密-only 无重排」，
  **完全没有词法基线**。所以 `90%` 对 `75%` 的提升与「混合是否优于纯词法」这个问题无关。
  本项目的 lexical 基线比它的任何基线都强得多。
- **融合权重 `0.6 / 0.4` 没有任何消融支撑**。按本仓库的魔法数字门禁，
  这个数值缺少机制依据与本数据可行性核验，**引用它去设定本项目的融合权重是违规的**。
  本项目若要定融合权重，必须自己用不读最终评测标签的诊断实验确定。
- **可否被当前评测集检验**：**否**，且不值得检验。
- **唯一价值**：作为「弱基线 + 缺失协议 → 报出大幅提升」的样本，
  与 TripClick 那篇构成一正一反的对照，用于说明为什么本项目要求报告词法-only 上界。

### 已核验事实（读了摘要与结果／消融部分，未通读全文）

- 官方盲测榜（表 3）：CVPD `0.935` 第一，Simplicity `0.931`，KMS `0.916`；
  指标 MIR-E 是五个阶段的加权组合（权重 `0.30 / 0.20 / 0.20 / 0.10 / 0.20`）。
- **检索侧没有任何标准 IR 指标**。第 4.4 节与表 4 只按来源做消融
  （PDF-only `0.718`、PDF+Web `0.591`、Web-only `0.463`，为「语义相似度＋关键词重叠＋TF-IDF」
  的自定义加权分 `S = 0.5·S_sem + 0.3·S_kw + 0.2·S_tfidf`），
  **没有 recall / nDCG / MRR，也没有把检索、重排、模式约束三者分离的消融**。

### 排除理由（三条，任一条即足以排除）

1. **没有可比的检索证据**。它不报告任何标准检索指标，也不分离混合检索的贡献，
   因此对「hybrid 是否优于 lexical」这个问题**提供零信息**。
2. **评价对象不是检索**。MIR-E 衡量的是继承份额计算的正确性，
   分数高低主要由符号计算器、合成数据和模式约束决定，与检索通道质量不可分离。
3. **领域与语料完全错配**。阿拉伯语法律推理、`100k` 条合成案例、结构化答案模式；
   本项目是中文为主的安全领域笔记检索，无生成、无模式约束、无符号求解器。

结论：**判为不相关，不下载、不建笔记**。补下命令见 `task_plan.md` 末尾，
