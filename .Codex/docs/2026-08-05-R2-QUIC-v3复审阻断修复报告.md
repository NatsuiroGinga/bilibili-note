# R2 QUIC v3 复审阻断修复报告

## 结论

v2 独立复审列出的三个重要问题和两个机器证据缺口已在全新 v3 合同中完成本地最小修复。目标测试 4/4 通过，Python 编译、Shell 语法和 JSON 精确合同检查均通过。旧 v2 配置与三轮结果未修改、未复用、未拼接；本报告不宣布端到端门禁通过，也不授权恢复字段矩阵。

## 变更内容

1. `r2_quic_controlled_collect.py`
   - 服务端退出码不再归零，`server_exit` 与 `server_raw_exit` 均保留 `Popen.wait()` 的原始结果。
   - 新增受控停止收据，记录 `controller_sent_signal`、`controller_signal_sent_at`、`poll_before_controller_signal`、`controller_signal` 与 `raw_exit`。
   - 只有原始退出码为 0，或原始退出码与本轮控制器发送的 `SIGTERM` 收据严格闭合时，服务端退出合同才成立。
   - quiche 客户端命令显式传入 `--source-port` 与冻结源端口。
   - 配置缺少 `client_timeout_seconds` 时恢复 900 秒默认值；v3 配置显式固定 240 秒。
   - v3 三轮允许序号 12、32、12，科学参数均固定为 `p03/seed43/bulk`，实现顺序为 `aioquic/quiche/aioquic`。
2. `run_r2_quic_controlled_collection.sh`
   - 启动器状态升级为 v3，持久化运行身份、输出根、配置路径、开始时间、结束时间和主管道两侧退出码。
   - 相对输出根在启动前转为服务端项目根下的绝对路径，供审计器逐轮绑定。
3. `audit_r2_quic_determinism_gate.py`
   - 分别核验非服务端退出码和服务端原始退出/受控信号来源，不再接受归一化退出码。
   - 逐项复算连接状态 `artifacts` 清单的相对路径、字节数和 SHA-256，并拒绝路径逃逸、重复路径、缺失文件、大小变化或哈希变化。
   - 强制读取三份启动器状态，核验恰好三个冻结运行身份、状态完成、主管道退出码、输出根绑定和时间区间严格串行。
   - 枚举同一启动器根下匹配 v3 前缀的状态目录，存在补跑、第四身份或遗漏身份即失败。
   - 核验三轮实现顺序精确为配置中的 `aioquic/quiche/aioquic`，并按实现核验各自冻结方向种子。
4. `r2_quic_controlled_determinism_repair_v3.json`
   - 发布全新 v3 配置，显式冻结 240 秒、固定四元组、双实现方向种子、三运行身份和服务端原始退出合同。
5. `test_r2_quic_v3_contract.py`
   - 新增仅依赖 Python 标准库的目标测试，覆盖四项复审阻断行为。

## 测试驱动开发证据

红灯命令：

```bash
python3 -m unittest thesis/experiments/llm_probe/tests/test_r2_quic_v3_contract.py
```

首次结果：退出码 1，4 个用例均按预期失败。失败原因分别为缺少 `stop_process_with_receipt`、quiche 命令缺少 `--source-port`、缺少 `client_timeout_seconds` 兼容解析器、审计器缺少制品清单与启动器合同核验接口。

绿灯使用同一命令。最终结果：退出码 0，运行 4 个用例，4/4 通过。
