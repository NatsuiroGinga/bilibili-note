## 官方字段与配置核验

- `UserPromptSubmit` 的实际用户字段是 `prompt`；脚本按此读取。
- `PreToolUse` 的 Bash 与 `apply_patch` 输入在 `tool_input.command`；脚本按此读取。
- 文件编辑的规范工具名为 `apply_patch`，但匹配器可使用 `apply_patch|Edit|Write` 别名；现有配置已如此注册。
- `additionalContext` 必须嵌套在 `hookSpecificOutput`；脚本输出符合该结构。
- Codex 默认每个处理器约 2,500 词元附加上下文阈值。本规则包全量为 3,785 字符，正常命中时实际更小，未提高 `additionalContextLimit`，避免扩大上下文占用。
- `UserPromptSubmit` 的 matcher 当前不生效；现有无 matcher 配置正确。
- `Read`、`Grep`、`Glob` 不是本次运行时已确认的 Codex 原生工具名，未为名称兼容而重复注册无效处理器。

## 风险与边界

- 参照型规则目前只能在 `apply_patch` 触碰文件时注入，不能复刻 Claude 的只读 `Read` 事件。这是 Codex 运行时工具模型差异；强行注册未证实名称会造成配置噪声，未实施。
- 去重状态使用“读 JSON 后临时文件替换”。多个并发工具事件同时首次触发不同参照规则时，存在极小概率丢失其中一个标记并在后续重复注入；原 Claude 实现也有相同边界。本轮未扩大为锁协议，因为未观测到实际重复，且会引入热路径延迟。
- 非托管用户级钩子按定义哈希信任。脚本已改变，现有信任记录会失效。

在新的 Codex 会话执行 `/hooks`，审查并信任变更后的 `~/.codex/hooks.json` 中规则注入处理器；未信任前 Codex 会跳过该非托管钩子。
