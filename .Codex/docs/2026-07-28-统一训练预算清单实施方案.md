# 统一训练预算清单实施方案

- **状态日期**：2026-07-28。
- **决策状态**：用户已批准，进入清单实现与冻结阶段。
- **适用范围**：第一创新点的统一基线、R1-R3 候选筛选、胜出方法正式训练、神经模型主表和树模型补充评测。
- **上位合同**：[统一数据冻结与 PINN 候选顺序实验合同](2026-07-24-统一数据冻结与PINN候选顺序实验合同.md)。
- **核心原则**：保留全量 `dataset-v1`，训练与主表评测通过额外的不可变预算清单控制成本；不得删除全量数据、按结果重采样或让不同方法使用不同清单。

## 1. 已批准预算

| 数据源 |                  全量制品 |                            统一正式训练预算 | 固定选择规则                                                   |
| ------ | ------------------------: | ------------------------------------------: | -------------------------------------------------------------- |
| GeNIS  | 开发训练清单 `151,324` 条 |                                 `30,000` 条 | 在开发训练清单内，按会话、时间、攻击家族和子类做确定性分层抽样 |
| TQH-C2 |   冻结的 `28` 个训练 cell | 每 cell 最多 `1,000` 条，合计约 `28,000` 条 | cell 内保持原二元标签比例；不足 `1,000` 条时全取               |
| ns-3   |      `2,421` 条四窗口序列 |                 全部 `2,421` 条，各出现一次 | 仅通过任务权重控制贡献，不复制、不重复采样                     |

正式统一训练清单预计约 `60,000` 条；理论上限为 `30,000 + 28,000 + 2,421 = 60,421` 条。TQH-C2 中不足 `1,000` 条的训练 cell 会使实际总数低于该上限，最终精确数量必须写入冻结清单和统计文件，不能通过复制样本补足整数目标。

## 2. 数据保留与预算清单的关系

1. `dataset-v1` 继续保存 GeNIS、TQH-C2 和 ns-3 的全部冻结记录、视图、角色掩码和划分，不因训练预算而裁剪、覆盖或删除。
2. 训练预算是全量主记录之上的 `sample_id` 选择层。任何预算记录必须能够回指 `master_records.parquet`，字段值、标签和角色不得在预算层重写。
3. 全量清单、统一正式训练清单、候选筛选清单、验证清单、神经主表评测清单和 GeNIS 开放集全量清单分别保存 SHA-256；不得用文件名或记录数代替哈希绑定。
4. 所有方法读取同一份预算清单和样本顺序。模型可以使用不同的确定性视图，但不得为模型单独抽样、补样、复制 ns-3 或重排后不记录顺序哈希。
5. 发现标签、主键、跨分区或哈希正确性缺陷时，按上位合同生成新数据主版本并重跑受影响基线；模型结果不好、训练较慢或某类指标不利都不是重采样理由。

## 3. GeNIS 训练清单

### 3.1 输入边界

- 唯一输入为冻结的 GeNIS 开发训练清单，共 `151,324` 条。
- 验证、域内测试、时间前向测试和未知攻击测试清单均不得进入训练抽样池。
- 会话标识、时间、家族和子类只用于分组、分层与审计，不进入模型推理输入。

### 3.2 确定性抽样

1. 在读取任何候选或基线结果前，固定会话、时间、家族和子类四类分层字段及其缺失值处理。
2. 依据全量开发训练清单的联合分布分配 `30,000` 条预算，不改变已有家族、子类和时间前向边界；同一实现、输入哈希和抽样种子必须逐字节复现相同 `sample_id` 顺序。
3. 同一分层单元内使用 `dataset_version`、固定抽样种子和 `sample_id` 的 SHA-256 排序作为唯一平局裁决，不依赖文件遍历顺序、进程数或模型结果。
4. 输出完整的分层前后统计，包括会话数、时间范围、家族数、子类数、各层记录数和相对占比。任何缺失子类、单会话异常集中或时间段丢失必须在冻结前人工复核。
5. 最终训练清单固定为恰好 `30,000` 个唯一 `sample_id`；不得通过重复记录达到目标数。

## 4. TQH-C2 训练清单

1. 只读取冻结为训练角色的 `28` 个完整 cell；验证、域内测试和加密条件留出 cell 不进入训练预算。
2. 每个 cell 的记录数不超过 `1,000`。若 cell 记录数不超过 `1,000`，全部保留；否则按该 cell 原始良性/恶意比例分配二元配额。
3. 二元配额使用确定性整数分配，余数按固定规则处理；标签内再按 `dataset_version`、固定抽样种子和 `sample_id` 的 SHA-256 排序选取。
4. 每个 cell 输出抽样前后总数、良性数、恶意数、比例偏差和 SHA-256。不得把不同 cell 合并后随机抽样，也不得为凑满约 `28,000` 条复制小 cell。
5. cell 标识继续只用于划分和审计，不进入模型输入。

## 5. ns-3 训练清单与任务权重

1. 冻结的 `2,421` 条四窗口序列全部进入统一预算清单，每条 `sample_id` 只出现一次。
2. ns-3 对联合目标的贡献只由预先冻结的任务权重控制，不通过过采样、复制文件、重复索引或扩大一个训练轮中的出现次数实现。
3. 数据加载器必须分别记录公开检测任务与 ns-3 物理任务的有效样本数、批次数和损失权重；任务权重变化视为训练配置变化，不能伪装成数据清单不变。
4. 星型数据一旦全部用于正式训练，不再作为未触碰最终物理测试；正式物理外部证据必须来自冻结的未见配置及哑铃、停车场等跨拓扑清单。

## 6. 候选筛选与正式训练

### 6.1 候选筛选

- 从统一训练预算中另行冻结一份约 `10,000` 条的候选筛选清单，使用固定样本顺序和 SHA-256。
- R1、R2、R3 及被门槛触发的条件增强候选共用该清单、相同信息预算、`200` 个优化步和单一种子 `42`。
- 候选清单的来源与任务构成在任何候选训练前冻结；不得根据前一候选结果修改后续候选的数据比例、顺序或哈希。
- 候选阶段只用于选择技术路线，不形成三种子稳定性、最终主表或跨数据泛化结论。

### 6.2 正式训练

1. 候选中只有按预注册门槛胜出的唯一方法进入约 `60,000` 条统一正式训练预算；落选候选不运行全量三种子。
2. 胜出方法使用种子 `42`、`43`、`44`，每个种子最多训练 `1` 轮，并使用固定验证清单早停。
3. 正式主表所需的普通 QLoRA、状态监督和标准 PINN 匹配基线使用同一正式训练清单、清单哈希和验证协议；这属于公平基线，不构成落选候选扩跑。
4. 早停只读取冻结验证清单。最终测试、GeNIS 开放集和跨拓扑结果不得参与训练轮数、检查点或超参数选择。
5. 正式运行必须绑定训练清单 SHA-256、样本顺序 SHA-256、代码、模型、种子、有效批量、最大步数/轮数、任务权重和验证清单 SHA-256。

## 7. GeNIS 开放集评测预算

1. GeNIS `1,179,168` 条开放集全量清单继续完整保存，不删除、不重切分、不改变标签。
2. 从该全量清单另行冻结 `30,000` 条神经模型主表评测清单。抽样必须在任何正式预测前完成，并按既有开放集分组、家族、子类、会话和时间信息做确定性选择。
3. 所有神经与生成方法的论文主表共用这 `30,000` 条、相同顺序和相同 SHA-256；禁止因模型成本或结果单独缩小、替换或补抽。
4. 树模型同时在固定 `30,000` 条主表清单和 `1,179,168` 条全量开放集清单上评测。主表的直接比较使用固定 `30,000` 条结果，全量结果作为树模型可扩展性与稳定性的补充证据单列报告。
5. 神经方法未运行全量开放集不能写成“全量结果”；树模型全量补充结果也不能替代共同 `30,000` 条主表比较。

## 9. 实施顺序

1. **B1 输入核验**：确认 `dataset-v1` 全量主记录、GeNIS `151,324` 条开发训练清单、TQH-C2 28 个训练 cell、ns-3 `2,421` 条清单和 GeNIS `1,179,168` 条开放集清单均已冻结且哈希可读。
2. **B2 清单生成**：实现无模型依赖的确定性预算生成器，一次生成训练、候选和评测清单及统计，不加载 Qwen、不申请 GPU。
3. **B3 再现审计**：在独立临时目录重复生成两次，要求所有清单与统计逐字节一致；检查唯一性、子集关系、数量、二元比例、分层覆盖和跨划分泄漏。
4. **B4 原子冻结**：先写 `.partial` 目录，全部门禁通过后原子发布；发布后把清单 SHA-256 写入基线、候选和正式训练配置。
5. **B5 低成本筛选**：只运行约 `10,000` 条、`200` 步、种子 42 的共同候选协议并裁决唯一胜者。
6. **B6 正式验证**：仅胜者及必要匹配基线进入约 `60,000` 条、种子 42/43/44、最多一轮和验证早停的正式协议。

## 10. 时间与算力预算

- RTX 5090 既有实测：旧 `15,000` 条训练样本的运行约 `22` 分钟。
- 新预算估计：普通 QLoRA 约 `1.5` 小时/种子；含物理目标的 PINN 约 `2` 至 `2.5` 小时/种子。
- 三种子正式预算据此约为：普通 QLoRA `4.5` GPU 小时，PINN `6` 至 `7.5` GPU 小时；候选筛选和评测另计。
- 上述新时长是由旧实测外推的计划值，不是完成事实。正式运行必须记录真实训练时间、吞吐、峰值显存、早停步和 GPU 小时，并在同一硬件档位内比较。
- 服务器按量计费。每个候选或种子完成后立即回收清单绑定、状态、摘要和预测索引；恢复检查点遵循[按量 GPU 服务器重启恢复协议](2026-07-28-按量GPU服务器重启恢复协议.md)。

## 11. 历史证据边界

1. 既有全量训练、旧 `15,000` 条/202 步实验和历史开放集结果继续作为方法演进、失败诊断和算力估计证据，不删除、不覆盖。
2. 历史运行若未使用本方案的训练或评测清单哈希，不进入新的统一主表，不与新预算结果混算均值、标准差或置信区间。
3. 新预算不追溯改变历史裁决；若旧方法需要进入正式主表，必须在新共同清单上按同一预算重跑，而不是复用异清单数值。
