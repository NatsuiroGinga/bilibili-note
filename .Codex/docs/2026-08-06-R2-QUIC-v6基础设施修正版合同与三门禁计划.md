# R2 QUIC v6 基础设施修正版合同与三门禁计划

## 冻结裁决

QUIC v5 的唯一正式第 1 轮因 aioquic 源码覆盖层缺少编译扩展 `_buffer` 而在首包发送前失败。v5 固定为 `NO-GO_KEEP_QUIC_UNKNOWN`，不补跑第 2、3 轮，不改写或删除其配置、日志和输出。

## v6 唯一修正

v6 不改变 v5 的实现顺序、连接索引、网络参数、容量、阈值、超时、数据报上限、端点节奏补丁或统计门槛。唯一变化是 aioquic 包装方式：

1. 从 v1 冻结虚拟环境复制完整 aioquic 1.3.0 安装包，包括 `_buffer.abi3.so` 和 `_crypto.abi3.so`。
2. 在独立 `r2-quic-controlled-v6` 工具根中只覆盖 `aioquic/asyncio/protocol.py`。
3. 运行时只把 v6 覆盖层加入 `PYTHONPATH`，不得直接暴露缺少编译扩展的源码根。
4. 绑定完整源包树、两个编译扩展、原始协议文件和覆盖后协议文件摘要。

## 聚焦红绿证据

- 红灯：v5 run1 的客户端日志出现 `ModuleNotFoundError: No module named 'aioquic._buffer'`，客户端退出码 1，代理收包和字节均为 0。
- 绿灯：v6 覆盖层必须能从隔离根导入 `aioquic._buffer`、`aioquic._crypto` 和协议模块，并用伪 QUIC 数据报实际产生一条合法端点节奏收据。

## 唯一三轮

1. `r2-quic-binary-overlay-v6-run1-aioquic`：aioquic，连接索引 12。
2. `r2-quic-binary-overlay-v6-run2-quiche`：quiche，连接索引 32。
3. `r2-quic-binary-overlay-v6-run3-aioquic`：aioquic，连接索引 12。

三轮严格串行、独立输出、不得重试或补第 4 轮。任一轮失败即 `NO-GO_KEEP_QUIC_UNKNOWN`；全部通过只授权继续扩充字段矩阵。QUIC 专家仍须达到至少 600 条独立正式连接并完成训练清单、真值、实现组和检查点绑定后才能在新版旁路实验中启用。
