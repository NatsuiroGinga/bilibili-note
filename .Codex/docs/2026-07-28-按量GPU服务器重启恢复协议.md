# 按量 GPU 服务器重启恢复协议

## 目标

GPU 服务器采用按量计费，默认只在实际计算时开机。本协议保证关机、普通重启或实例重新连接后，不依赖进程内存、临时会话和人工记忆恢复实验，并避免把中断运行误报为完整结果。

## 持久化边界

| 对象             | 服务端持久化位置                                            | 本机或外部恢复来源                                                          |
| ---------------- | ----------------------------------------------------------- | --------------------------------------------------------------------------- |
| 实验代码与入口   | `/root/autodl-tmp/thesis/experiments/llm_probe/`            | 本仓库 `thesis/experiments/llm_probe/`                                      |
| 运行制品与检查点 | `/root/autodl-tmp/thesis/experiments/llm_probe/runs/`       | 每阶段用 `rsync` 回收关键小型制品；大型权重另存本机或 Hugging Face 私有仓库 |
| 基座模型         | `/root/autodl-tmp/thesis/models/`                           | 原模型仓库或已登记的外部制品库                                              |
| ns-3 源码与构建  | `/root/autodl-tmp/thesis/ns3/`                              | 本机 `ns3/` 中的压缩包与官方文档                                            |
| 派生数据         | `/root/autodl-tmp/thesis/experiments/llm_probe/runs/data-*` | 原始数据、本机派生制品与生成脚本                                            |

`screen`、`/tmp/`、当前 Shell 环境和未落盘的 Python 状态均视为易失内容。它们可以辅助运行，但不能作为唯一恢复依据。

## 启动门禁

1. 重新探测 CPU、GPU、显存、磁盘、`uv`、Python、SwanLab 和所需命令，不沿用上次开机的能力结论。
2. 核对代码、配置、输入数据、样本清单与模型制品的 SHA-256；不一致时停止续跑并建立新运行。
3. 使用唯一输出目录，启动计算前写入配置快照、环境摘要、完整命令、随机种子、输入哈希和 `run_state.json`。
4. `run_state.json` 至少记录 `run_id`、阶段、状态、当前步、最近检查点、SwanLab 运行号、启动时间和最近更新时间。写入临时文件后原子替换正式文件。
5. 正式训练入口必须保存可等价恢复的模型或适配器、优化器、学习率调度器、随机数状态和当前步数。检查点间隔不得超过 20 个优化步或 10 分钟。
6. 不具备完整恢复能力的入口只能执行不超过 20 分钟、可确定性重跑的冒烟或低成本探针，不得启动长时间正式训练。

## 数据处理规则

1. 下载使用校验后续传；每个文件完成后立即记录大小与哈希。
2. 数据提取和物化写入独立 `.partial` 目录，阶段日志和计数随处理写盘。
3. 只有记录数、主键、标签连接、字段角色、泄漏审计和哈希全部通过后，才用原子重命名发布正式目录。
4. 重启后若发现 `.partial`，优先从已验证阶段继续；无法证明可续跑时保留失败目录并确定性重跑，不拼接新旧结果。

## 训练与评价规则

1. 长任务使用 `screen` 并把标准输出和错误同时写入持久化日志；`screen` 仅用于 SSH 断线保护。
2. 每次检查点完成后更新运行状态；检查点写入未完成时不得把路径登记为可恢复检查点。
3. SwanLab 在线日志之外必须保存本地逐步指标。重启产生新 SwanLab 运行时，报告中同时记录前后运行号及中断边界，不伪装为单次连续运行。
4. 评价和统计优先设计为幂等阶段；已有完整输出时拒绝覆盖，只有显式新目录才能重跑。

## 关机前检查

1. 查询 GPU 进程、Python 训练进程和全部 `screen` 会话。
2. 检查运行目录中的状态与最近完整检查点，并确认恢复命令已经落盘。
3. 没有活动实验时可直接关机。
4. 存在活动实验时，先等待或触发最近检查点完成，再停止实例；若实例被意外终止，按重启流程处理，不覆盖中断目录。
5. 每个独立阶段结束后立即回收配置、状态、日志、指标、清单、哈希和摘要到本机。

## 重启恢复顺序

1. 登录后执行 `source ~/.bashrc`，重新确认 `uv` 和项目环境。
2. 检查 `/root/autodl-tmp` 容量、GPU 能力、项目代码与输入哈希。
3. 扫描状态为 `prepared`、`running` 或 `interrupted` 的运行目录，核验最近检查点完整性。
4. 仅当代码、配置、数据清单、种子和科学超参数完全一致时，从最近完整检查点恢复。
5. 硬件适配只允许调整微批量、梯度累积、线程、精度和可选量化；变化必须写入状态和成本记录。
6. 恢复后先运行一个最小步验证全局步数、学习率与指标继续递增，再进入正式计算。
