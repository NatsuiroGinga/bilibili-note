# Claude Code hooks 迁移到 Codex 报告

## 结论

已将 Claude 用户级配置中的 8 个处理器迁移为 Codex 用户级 hooks。配置位于 `~/.codex/hooks.json`，脚本及规则包均位于 `~/.codex/hooks/`，不再引用 `~/.claude/hooks/`。为适配 Codex 的 `apply_patch`，原规则注入处理器拆为 Bash 与补丁两个匹配组；同时保留目标目录中已有的 `skill-forced-eval.js` 用户提示路由处理器，因此最终配置共 10 个命令处理器。

## 来源与目标

- 来源：`~/.claude/settings.json` 的 `hooks` 字段；未读取、记录或修改其中其他设置。
- 目标：`~/.codex/hooks.json`。
- 备份：`~/.codex/hooks.json.bak-20260907T113426`。
- 官方依据：<https://learn.chatgpt.com/docs/hooks>，用户级入口为 `~/.codex/hooks.json`；支持 `command` 与 `mcp_tool`；`prompt` 和 `agent` 被跳过；新增或修改的钩子须在 `/hooks` 中审核信任。

## 适配文件

- `hook-common.js`：去除 `~/.claude` 目录依赖，改查 `~/.codex` 的技能、代理、钩子和用户级 `AGENTS.md`。
- `security-guard.js`：保留确定性拒绝，删除 PreToolUse 中 Codex 当前不支持的 `ask` 输出。
- `rule-injector.js`：使用 Codex 的 `prompt`、`Bash` 和 `apply_patch` 事件结构，去重状态目录改为系统临时目录下的 `codex-rule-inject`。
- `kb-reindex.js`：替换 Claude shell 处理器，解析 Codex 补丁输入；保留原有后台重建与文件锁策略。
- `run-node-hook.sh`：将新脚本加入白名单，并保持 Node/NVM 查找回退。
- `rule-bundles/`：复制五个被规则注入器引用的规则包。

## 未迁移项

Claude 配置中没有 `prompt`、`agent` 或 `mcp_tool` 类型处理器，也没有 Codex 不支持的事件。因此未迁移项为 0。

## 验证

- `jq empty ~/.codex/hooks.json`：通过。
- `node --check`：所有新增及适配 JavaScript 脚本通过。
- `sh -n ~/.codex/hooks/run-node-hook.sh`：通过。
- 无副作用伪造事件：规则注入器正确读取 `prompt`；安全守卫对灾难性命令输出 `permissionDecision: deny`；知识库重建器对非目标补丁零输出且不启动任务。
- 已部署脚本的启动器复核：规则注入器与安全守卫均返回预期 JSON。
- 处理器唯一性检查：通过；规则注入器的两个 `PreToolUse` 处理器匹配对象不同，不是重复处理器。
- 配置中只包含 `command` 处理器，事件均在当前 Codex 官方支持表中；`~/.codex/config.toml` 不含内联 `[hooks]`，不存在跨层重复定义。

## 新会话操作

1. 结束当前 Codex 会话并创建新会话。
2. 输入 `/hooks`，逐项查看来自 `~/.codex/hooks.json` 的变更并选择信任。
3. 不使用 `--dangerously-bypass-hook-trust` 代替审核。
4. 审核后再用普通任务触发钩子；本次迁移没有触发真实钩子副作用。
