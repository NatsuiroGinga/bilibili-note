# 生成式恶意流量探针实验设计

## 1. 目的与边界

本实验先验证一个前置命题：小型生成式基座能否从统一的流量级表示中稳定学习恶意流量检测，并以严格结构化格式输出判别结果。

实验使用 Qwen3-1.7B 和参数高效微调完成良性/恶意二分类。它不用于证明第一创新点成立，也不在本阶段引入物理约束、强化学习、Stiefel-LoRA、mHC 或新算法名称。只有 H1 通过后，才进入 3B 至 4B 基座比较和创新机制实验。

## 2. 验收标准

### 2.1 H1 通过条件

三个主数据集分别满足以下条件：

1. 三个随机种子的宏平均 F1 均值至少比同一测试集的多数类基线高 5 个百分点。
2. 严格 JSON 输出合法率不低于 95%。
3. 微调结果相对同一基座的零样本结果有正向增益。
4. 测试集与训练集的分组标识无交集，且数据清单记录了划分依据。

若某数据集缺少可靠分组字段，则该数据集结果标记为“诊断证据”，不能计入 H1 的正式通过数量。取得可分组的数据版本前，H1 状态记为“证据不足”，而不是用随机逐行划分强行给出通过或失败结论。H1 的最终裁决必须同时报告通过项、失败项和数据限制，不能只报告平均值。

### 2.2 本阶段不设定的结论

- 不要求生成式模型优于所有传统机器学习方法。
- 不根据一个数据集或一个随机种子的最高准确率选择论文方案。
- 不把攻击家族多分类结果作为 H1 的必要条件。
- 不允许用增加输入字段、训练步数或样本量掩盖同预算比较。

## 4. 数据契约

### 4.1 统一样本结构

每条规范样本至少包含以下部分：

```text
sample_id
source_dataset
source_file
group_id
original_label
binary_label
attack_family
feature_view
features
```

- `sample_id`：由数据来源和原始行定位信息稳定生成，不包含标签。
- `group_id`：用于防止同场景、同文件或同会话泄漏。
- `binary_label`：只允许 `benign` 或 `malicious`。
- `attack_family`：保留用于后续攻击家族实验，本阶段不作为生成目标。
- `features`：按固定顺序保存规范字段，不允许适配器静默增加或删除字段。

### 4.2 字段视图

主实验使用 `canonical_core_v1`。其最终字段集合必须在三个数据集完成审计后，由共同可构造字段的交集确定，候选范围包括：

- 流持续时间；
- 前向、后向包数与字节数；
- 包长度的均值、最小值、最大值和标准差；
- 包到达间隔统计；
- 传输层协议；
- TCP 标志或其计数；
- 包速率和字节速率。

`dataset_full_v1` 保留数据集特有字段，只用于域内性能诊断。任何不能在全部数据集一致构造的字段都不得进入跨数据集主实验。缺失值必须显式记录，并输出缺失率审计；不得静默使用零值代替未知值。

### 4.3 标签映射

每个适配器维护显式标签表。未知标签导致任务失败并输出错误记录，不允许通过字符串包含关系自动猜测良性或恶意。标签表同时保留原始标签、二分类标签和攻击家族映射，便于后续审查。

### 4.4 数据划分

划分优先级如下：

1. 采集场景或攻击场景；
2. 源文件或采集日期；
3. 会话、设备或主机组；
4. 经审计确认不会跨集合复用的其他稳定分组。

训练、验证和测试集合的 `group_id` 必须两两无交集。若社区镜像缺少上述信息，可以生成平衡小样本用于管线和可学性诊断，但结果必须标记为低证据等级，不能冒充严格泛化实验。

## 5. 输入与输出

### 5.1 输入序列化

流量记录转换为固定顺序、短格式的键值文本。模板版本写入数据清单，数值使用统一精度和单位，类别字段使用固定词表。例如：

```text
任务：判断以下网络流是良性还是恶意。
流量：duration_ms=12.40;protocol=tcp;fwd_packets=8;bwd_packets=6;...
只输出 JSON：{"label":"benign"} 或 {"label":"malicious"}
```

字段名、顺序、数值精度、单位和缺失值符号均由序列化器固定。输入中不包含数据集名称、原始标签、攻击家族、文件路径或样本标识。

### 5.2 输出约束

Qwen3 关闭思考模式，最多生成 16 个新令牌。合法输出只有：

```json
{ "label": "benign" }
```

或：

```json
{ "label": "malicious" }
```

解析器只移除首尾空白后执行严格 JSON 解析。代码围栏、额外解释、未知键、未知标签和截断文本均计为非法输出，并在检测指标中按错误预测处理。首轮不生成解释和主观置信度。

## 6. 实验层级

### 6.1 数据管线冒烟

每个适配器使用小型固定夹具验证标签、单位、缺失值、序列化和分组划分。随后从每个真实数据集抽取少量记录，只运行清洗、数据清单生成和提示词构造，不启动训练。

### 6.2 GPU 冒烟

使用 Qwen3-1.7B、单一数据集和单随机种子完成：

1. CUDA 与 BF16 检查；
2. 4 位量化模型加载；
3. 一次前向生成；
4. 200 个训练样本的短训练；
5. 100 个测试样本的结构化评估。

任一步失败都停止后续长训练，并记录软件版本、显存占用和完整错误摘要。

### 6.3 正式探针

每个数据集构建平衡开发集：每类训练 4000 条、验证 1000 条、测试 1000 条，共 12000 条。若分组约束下无法满足数量，则保留真实可用数量并在数据清单中记录，不得通过重复采样补足。

此外，从未进入训练和验证的分组中保留一个不改变类别比例的自然分布测试集，最多 10000 条，用于报告误报率和类别不平衡下的实际表现。平衡测试集用于跨数据集可比的宏平均 F1，自然分布测试集不得与其重复。

正式探针先运行随机种子 42；通过数据、训练和解析检查后，再补跑随机种子 43、44。三个数据集分别训练和评估，不把来源字段输入模型。跨数据集评估只使用 `canonical_core_v1`，并单独报告训练来源和测试来源。

## 7. 训练配置

基座固定为 `Qwen/Qwen3-1.7B`，首轮采用 QLoRA：

- 4 位 NF4 量化；
- BF16 计算；
- LoRA 秩 16、缩放系数 32、丢弃率 0.05；
- 目标模块为全部线性层；
- 最大输入长度 512；
- AdamW 优化器，初始学习率 `2e-4`；
- 有效批量大小 64；
- 最多训练 3 轮，以验证集宏平均 F1 选择检查点。

训练步数、梯度累积、输入长度、输出上限和样本数写入每次运行配置。若 RTX 5090 兼容性测试表明某个量化组件不可用，只能在记录失败后切换到 BF16 LoRA；切换后的结果不得与 QLoRA 结果混为同一配置。

## 8. 对照与指标

### 8.1 对照组

- 多数类预测；
- Qwen3-1.7B 零样本生成；
- Qwen3-1.7B QLoRA；
- 逻辑回归作为非生成式诊断对照，不作为 H1 的唯一裁决标准。

所有学习方法使用相同的数据划分。逻辑回归只读取同一规范字段的数值编码，不额外使用源数据集字段。

### 8.2 效果指标

- 宏平均 F1；
- 良性与恶意类别的精确率、召回率和 F1；
- 误报率；
- 严格 JSON 合法率；
- 非法输出数量和类型；
- 三随机种子的均值、标准差和逐次结果。

### 8.3 效率指标

- 训练 GPU 小时；
- 峰值显存；
- 每秒训练样本数和令牌数；
- 总训练令牌数；
- 单样本推理 P50、P95 延迟；
- 批量吞吐率；
- 输入和生成令牌统计。

效率测量固定在同一 RTX 5090、相同批量大小和相同生成配置下。预热请求不计入延迟分位数，测量时记录驱动、CUDA、PyTorch、量化库和模型版本。

## 9. 错误处理与证据等级

- 压缩包必须通过来源记录中的校验值或本地 SHA-256 清单后才能使用。
- 必需列缺失、出现未知标签、分组交叉或样本标识重复时立即失败。
- 非关键数值缺失可以保留显式缺失符号，但必须输出逐字段缺失率。
- 结构化输出解析失败不重试、不静默修复，直接计为错误。
- 官方来源且具备场景分组的数据为主证据；缺少分组的社区镜像为诊断证据；合成数据不参与 H1 主性能排名。

## 10. 测试策略

实现遵循测试驱动顺序，至少覆盖：

1. 三个适配器的已知标签映射与未知标签拒绝；
2. 缺失字段不会被静默填零；
3. 序列化字段顺序、单位和精度固定；
4. 输入文本不包含数据集名、文件名和标签；
5. 分组划分无交集并可由同一随机种子复现；
6. 严格 JSON 解析拒绝解释、代码围栏、额外键和未知标签；
7. 固定预测夹具上的宏平均 F1、误报率和合法率计算正确；
8. 数据清单包含来源、哈希、样本数、标签分布、字段视图和划分依据。

本地单元测试不得要求 GPU 或下载模型。GPU 集成检查在服务器单独运行，并保存机器可读的结果摘要。

## 11. 复现与产物管理

版本管理中保留：

- 源代码和测试；
- `pyproject.toml` 与 `uv.lock`；
- 实验配置；
- 数据清单、字段审计和哈希；
- 指标摘要、效率摘要和失败记录；
- 不包含凭据的环境版本清单。

版本管理中排除：

- 原始数据和处理后的大文件；
- Hugging Face、`uv` 和量化缓存；
- 模型权重、适配器检查点和优化器状态；
- 逐样本大体积生成日志；
- SSH 命令、密码、令牌和环境变量值。

每次运行使用不可变运行标识，保存配置快照、代码提交标识、数据清单哈希、开始与结束时间、最终指标和退出状态。SwanLab 可以作为可视化副本，但本地 JSON 和 CSV 摘要是复现依据。

## 12. 服务器执行边界

- 通过当前进程的 `GPU_SSH` 和 `GPU_PWD` 连接，但不将其写入任何文件、日志或命令历史制品。
- GitHub 和 Hugging Face 下载可临时加载 `/etc/network_turbo`，下载结束后取消代理。
- Hugging Face 模型优先使用 `https://hf-mirror.com/`。
- 正式训练前必须依次通过：磁盘空间检查、数据完整性检查、`uv sync`、CUDA 检查、4 位加载和一次生成。
- 服务器只保存可重建的大体积产物；代码、锁文件、清单和指标最终同步回本地实验目录。

## 13. 完成定义

本设计对应的探针任务完成，需要同时满足：

1. 独立实验包及其单元测试在本地通过；
2. RTX 5090 上的环境、量化加载和训练冒烟通过；
3. 三个主数据集均生成可审计的数据清单；
4. 正式探针完成三个随机种子，或明确记录无法完成的具体数据阻塞；
5. 输出效果与效率指标，并按第 2 节裁决 H1；
6. 所有代码、配置、锁文件、清单和结果摘要回存 `thesis/experiments/llm_probe/`。
