## 实现内容

- `SUPPORTED_BASELINES` 统一登记 `logreg`、`random_forest`、`hgb`、`xgboost`、`mlp`、`distilbert` 和 `groupdro`。
- `E2BaselineBudget` 固定随机种子、最大迭代数、阈值来源、GroupDRO 步长和 L2 系数。
- 所有表格模型只用任务 1 的共同七字段矩阵。缺失填充器和标准化器只在源域训练样本上拟合；类别权重只由源域训练标签计算；阈值只允许固定值或源域校准集选择。
- HGB 和 XGBoost 直接复用 `tabular_baselines._build_model`，再把共同最大迭代预算写入对应参数，未复制旧训练主体。
- `SourceGroupDROClassifier.fit()` 只接收源域特征、源域标签、源域捕获组和源域类别权重。对抗组权重只按源域捕获组损失更新，不接收 C 域特征统计、标签或无标签样本。
- `E2Prediction` 统一保存模型、评价划分、样本标识、捕获组、域、稳定顺序、标签、恶意概率、阈值和预测类别。
- `E2DistilBertAdapter.fit_source_only()` 将普通 DistilBERT 的拟合输入限制为源域训练与源域校准文本；文本仅由固定七字段构造。
- `SharedB0DistilBertPredictor` 复用既有 `forward_probability_batch()`。完整 E2 普通 DistilBERT 训练适配器尚未配置时，调度器在任何模型训练前抛出 `DistilBertAdapterRequiredError`。
- `build_input_binding()` 和 `validate_e1_reuse_receipt()` 要求 HGB/XGBoost 的字段、面板、样本顺序、各划分特征与标签哈希及预算完全一致；不一致时明确要求重跑。
- 新增命令入口 `flow-probe-e2-hard-domain-baselines`。

## 最小验证

首次静态导入命令未进入项目代码：

```bash
PYTHONDONTWRITEBYTECODE=1 uv run --no-sync python -c 'import flow_probe.e2_hard_domain_baselines as module; ...'
```

结果：失败。原因是沙箱禁止写入 `uv` 默认缓存目录 `/Users/bilibili/.cache/uv`，不是项目导入错误。

将缓存切换到可写的临时目录后，执行同一最小静态导入：

```bash
UV_CACHE_DIR=/tmp/e2-task2-uv-cache PYTHONDONTWRITEBYTECODE=1 uv run --no-sync python -c 'import flow_probe.e2_hard_domain_baselines as module; assert module.SUPPORTED_BASELINES == ("logreg", "random_forest", "hgb", "xgboost", "mlp", "distilbert", "groupdro"); print("E2 任务2静态导入通过")'
```

结果：通过，退出码为 0，输出为 `E2 任务2静态导入通过`。
