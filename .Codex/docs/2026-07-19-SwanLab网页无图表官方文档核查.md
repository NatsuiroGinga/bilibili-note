# SwanLab 网页无图表官方文档核查

## 结论

`rd2jwog6` **不是没有上传指标，也不是没有生成图表面板**。

- 云端保存了 274 个自定义标量键。
- 274 个对应图表面板已经创建。
- 代表指标可以从网页实际使用的绘图接口取回。
- 问题由两部分组成：
  - **网页定位与展示问题**：SwanLab 当前使用项目共享看板。页面先显示历史 `diagnostic` 和 `baseline` 分区，目标运行的 `multiclass_baseline` 分区排在第三位；项目累计 495 个自定义图表，增加了定位和加载成本。
  - **实验跟踪设计问题**：当前脚本在全部计算结束后只调用一次 `swanlab.log(..., step=0)`，因此每个图表只有一个点；脚本也没有输出训练阶段日志，所以“日志”页只有 SwanLab 自身的 10 条初始化信息。

这两个问题必须分开处理。网页看不到不能再作为“实验指标丢失”的证据，但当前运行仍然不满足正式实验的逐步跟踪要求。

目标宏平均 F1 图表的服务端面板已存在，可先打开以下链接进行浏览器侧诊断：

[直接打开 `rd2jwog6` 的 family 直方图梯度提升树测试集宏平均 F1 面板](https://swanlab.cn/@mortiswang/malicious-traffic-llm/runs/rd2jwog6/chart#ZDRyaXhl-bWRoNms2cHk=)

```text
multiclass_baseline/family/models/hist_gradient_boosting/evaluations/test/metrics/macro_f1
```

该指标只有 `step=0` 的一个点，所以它是最终静态结果，不是训练曲线。

## 官方文档裁决

### `swanlab.log` 与图表

官方文档明确说明，`swanlab.log()` 应在训练循环中记录每一步指标；同名指标每记录一次，默认 `step` 递增。显式指定 `step` 可用于对齐不同记录频率的指标。[记录实验指标](https://docs.swanlab.cn/guide_cloud/experiment_track/log-experiment-metric.html)

官方 API 文档也明确说明，调用 `swanlab.log` 会记录指标、生成可视化图表并更新汇总值。[Python `log` API](https://docs.swanlab.cn/api/py-log.html)

当前源码只在结果生成完成后执行一次：

```python
scalar_metrics = flatten_scalar_metrics(summary, prefix="multiclass_baseline")
swanlab.log(scalar_metrics, step=0)
```

因此，274 个键都只有一个 `step=0` 点是代码的预期结果，不是 SwanLab 丢失后续数据。

### 网页“日志”不等于标量历史

官方文档区分了两类数据：

- `swanlab.log()` 记录标量历史。
- 网页“日志”选项卡记录进程的标准输出和标准错误。

`print_to_console` 默认值为 `False`。如果脚本没有 `print`、日志器输出或 `print_to_console=True`，标量不会自动出现在“日志”选项卡。[记录实验指标](https://docs.swanlab.cn/guide_cloud/experiment_track/log-experiment-metric.html)、[Python `log` API](https://docs.swanlab.cn/api/py-log.html)

`rd2jwog6` 与 `eghdg7z1` 的“日志”接口都只有 10 条记录，内容仅包括 SDK 版本、保存目录、项目地址和运行地址。这与当前脚本没有阶段输出完全一致。

### 斜杠键不是根因

官方文档明确支持用 `/` 前缀分组，例如 `train/loss` 和 `val/acc`。[记录实验指标](https://docs.swanlab.cn/guide_cloud/experiment_track/log-experiment-metric.html)

SwanLab 0.9.0 还提供 `CoreSettings.section_rule`，默认按第一个 `/` 分割分区与指标名，并允许选择第二个或最后一个 `/`。[Python 设置 API](https://docs.swanlab.cn/api/py-settings.html)

同项目对照运行 `szi0fzdi` 使用 `diagnostic/loss` 和 `diagnostic/accuracy`，每个键三个点，网页能够正常显示。因此多层 `/` 可能造成标题过深和面板数量膨胀，但不是数据不可见的直接原因。

### 274 个键没有触发官方硬上限

官方建议不同指标名少于 10000 个，每个标量少于 50000 个记录点；超过建议值仍会接收数据，但网页可能变慢。[限制与性能](https://docs.swanlab.cn/guide_cloud/experiment_track/limit-and-performance.html)

274 个键远低于 10000，不能据此认定触发服务端限制。不过当前项目共享看板累计有 495 个自定义图表，远多于实验分析真正需要的图表，因此仍然存在不必要的网页加载和人工定位成本。

### `summary`、`series` 与旧 `columns`

`summary` 返回每个标量的最小值、最大值、均值、中位数和最新值，是统计汇总，不是完整训练序列，也不是图表面板列表。[Python API](https://docs.swanlab.cn/api/py-api.html)

本机 SwanLab 0.9.0 已将 `columns` 和 `column` 标为弃用，并要求改用 `series`。实测结果如下：

- `rd2jwog6`：旧 `columns` 返回 0，当前 `series` 返回 274 个键。
- `eghdg7z1`：当前 `series` 返回 274 个键。
- 已知图表可见的 `szi0fzdi`：旧 `columns` 同样返回 0，当前 `series` 返回 2 个键。

因此，“旧 `columns` 返回 0”是错误诊断，不能说明图表数据不存在。官方文档仓库当前仍保留旧接口章节，和 SDK 0.9.0 的弃用状态存在文档更新时差。[命令行 API](https://docs.swanlab.cn/api/cli-swanlab-api.html)

## 最小修复方案

### 立即验证网页

1. 打开前述直达宏平均 F1 面板链接。
2. 在普通运行页清空图表搜索条件和正则开关。
3. 搜索完整指标键，或滚动到第三个 `multiclass_baseline` 分区。
4. 强制刷新页面；若仍为空，使用无痕窗口复核，排除旧前端缓存和本地视图状态。
5. 记录实际页面截图。只有云端接口和网页可见性都通过，才能把运行标为跟踪验收完成。

如果直达链接仍然完全空白，而绘图接口继续返回数据，应把问题归类为 SwanLab 前端渲染缺陷，并向官方提交：运行链接、浏览器版本、控制台错误、网络请求状态和本报告中的面板编号。此时不应重跑模型来修复网页。

### 后续实验跟踪改造

不要再把完整嵌套结果树展开成数百个图表键。建议采用两层记录：

- **图表白名单**：只上传 10 至 20 个论文直接使用的核心指标，例如宏平均 F1、已知类拒识率、未知攻击召回率、良性误报率、训练耗时和推理吞吐。
- **完整结果制品**：每类召回率、全部阈值、标签分布和预测明细继续保存为 JSON、JSONL 或表格制品，不自动变成图表。

传统基线不必伪造不存在的训练迭代曲线，但必须记录真实阶段：

```python
print("开始训练 family/hist_gradient_boosting")
swanlab.log({"progress/completed_models": completed}, step=global_step)
swanlab.log(
    {
        "family/test_macro_f1": macro_f1,
        "runtime/fit_seconds": fit_seconds,
    },
    step=global_step,
)
```

对于只有一次评估的最终指标，保留一个点是正确的，不要为了画线复制或伪造数据。阶段进度、累计耗时等本来随步骤变化的量，才应形成多点曲线。

后续大模型和 PINN 正式训练必须按真实 `global_step` 重复记录：

- `train/loss`
- `train/physics_loss`
- `train/data_loss`
- `train/learning_rate`
- `train/grad_norm`
- `eval/macro_f1`
- `eval/known_rejection_rate`
- `eval/unknown_recall`
- `eval/benign_false_positive_rate`

控制台同时输出简短的阶段、步号、耗时和异常信息。不要把数百个最终静态字段通过 `print_to_console=True` 一次打印到日志页。

## 后续验收标准

每次正式运行至少满足以下条件：

1. `series` 能返回预期核心指标键。
2. 训练型指标具有多个单调递增的真实步号。
3. 最终静态指标允许只有一个点，但必须能通过指标历史接口取回。
4. 网页“日志”页包含训练开始、阶段切换、结束和异常信息。
5. 关键图表在实际网页中可见，并保存验收截图。
6. 运行记录同时写明服务端输出目录、本地归档目录、SwanLab 运行编号、运行地址和结果文件位置。
