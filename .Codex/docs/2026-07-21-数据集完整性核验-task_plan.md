# 数据集完整性核验计划

## 目标

核验 GeNIS-2025、HIKARI-2021、DEDALE 2.0 在本机与服务器上的现有文件属于整套数据、完整组件还是抽样子集，并给出可复核的官方依据、当前可用性和下一下载优先级。

## 阶段

- [x] 阶段 1：恢复项目上下文并固定只读边界
- [x] 阶段 2：盘点本机和服务器文件、大小、校验和与解压范围
- [x] 阶段 3：核对官方数据页、文件清单、大小与校验和
- [x] 阶段 4：检查归档完整性、字段、标签和实验可用性
- [x] 阶段 5：交叉复核结论并完成报告

## 关键问题

1. 三套数据在本机和服务器分别保存了哪些原始归档、解压组件与派生抽样？
2. 现有归档是否通过官方校验和或结构完整性检查？
3. 当前文件是否足以支撑既定实验角色，缺少哪些元数据、标签或场景组件？
4. 哪些缺失项小于 3 GiB 且真正影响后续实验，应该优先下载？

## 决策

- 服务器仅执行只读清单、哈希和归档完整性检查，不解压、不下载、不占用 GPU。
- 不下载整套 DEDALE；发现小于 3 GiB 的必要缺失项时，先向主代理报告清单与预计空间。
- 官方数据页、官方仓库或官方发布平台作为文件清单和校验和的裁决来源。

## 错误记录

- 服务器加载 `~/.bashrc` 后仍无 `fd` 命令，首轮目录枚举未执行；先检查 `fdfind`，若不存在则用 `rg --files` 枚举文件并用已知顶层目录的 `ls` 补充目录信息，禁止使用 `find`。
