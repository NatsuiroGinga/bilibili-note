# R2 QUIC v5 端点节奏修复实施记录

## 修复内容

- v5 使用独立 `runs/tools/r2-quic-controlled-v5`，不覆盖 v1 工具、v3/v4 配置或历史结果。
- quiche 客户端两处发送路径兑现 `SendInfo.at`，并记录计划时刻、实际时刻、迟发量、字节数和连续序号。
- quiche 服务端的批量发送路径改为 v5 用户态节奏；版本协商和 Retry 控制报文记录即时发送收据，避免代理收到的包数与端点收据不闭合。
- aioquic 保留原事件循环调度，只记录 `_pacing_at`、实际 `sendto` 时刻和连续序号。
- v5 审计器在复用 v4 字节账审计的基础上，新增端点节奏收据、实现版本、工具补丁、包数和字节数与代理输入的一致性门禁。
- `80%` 只作为诊断；`2 MiB` 仍是本轮预注册工程硬容量；最大数据报仍为 aioquic `1200` 和 quiche `1350` 字节。

## 服务器工具只读核验

- aioquic `1.3.0`、quiche `0.24.5`、两端 quiche 二进制、tcpdump 和 screen 原本可用。
- 本机缺完整 aioquic/quiche 工具，因此真实三轮需要在服务器 CPU 环境执行；不需要 GPU，也不需要联网下载。
- 冻结 quiche 客户端确实忽略 `SendInfo.at`；服务端仅在 `SO_TXTIME` 与 GSO 路径传入计划时刻，且当前没有 ETF 绑定证据。因此不能直接运行旧工具声称节奏有效。

## 当前阻塞与恢复动作

本机代理失效后，四个白名单文件的首次 rsync 均退出 `255`，远端未修改。直连覆盖返回连接拒绝，说明当前入口依赖本地代理。按控制器要求停止重复远程重试。

代理恢复后只执行以下动作：

1. 一次性同步上述四个白名单文件并核对 SHA-256。
2. 启动服务器 CPU 的独立 v5 工具构建，等待状态变为 `finished`。
3. 运行 `--check-toolchain`，只有合同与工具均通过才允许启动三轮。
4. 严格串行执行 aioquic、quiche、aioquic 三轮，不重试、不补第四轮。
5. 运行唯一 v5 审计并输出 `GO_TO_NEW_FIELD_MATRIX_QUIC_SEED_ONLY` 或 `NO-GO_KEEP_QUIC_UNKNOWN`。
