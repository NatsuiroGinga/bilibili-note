# E2 ns-3 六方向计数实施报告

## 结论

E2 物理辅助缺少方向源的代码门禁已经解除。ns-3 场景现在在路由器瓶颈 IPv4 接口真实观测两个方向，主窗口模式从 `flow_probe_r2_ns3_protocol_windows_v2` 升级为 `flow_probe_r2_ns3_protocol_windows_v3`，逐运行收据升级为 `flow_probe_r2_ns3_protocol_dynamics_v2_run_receipt_v2`。新版正式物化器会把六个字段直接写入 `physics-targets-ns3-v2.parquet`；随后既有 E2 辅助物化器可以从同一物理表读取方向字段，不再需要推断或额外旁表。

本轮没有修改冻结的 512 项场景清单、参数组合、划分、运行顺序、TCP 合同或标签，也没有运行 SSH、服务器编译、服务器实验和 512 项重跑。

为解除最小 UDP 验收的选择阻断，公共运行器现在先严格验收完整冻结清单恰含 512 项、256 个 TCP/UDP 配对组，再按模式选择运行。原 TCP 模式仍必须选择五个 TCP 项并覆盖既定发送者组成；新增 UDP 单项模式只接受冻结清单中的一个精确行，配置给出的清单行号、协议 `UDP` 和物理组 SHA-256 必须同时匹配。它不允许重新抽样、任意搜索替代行、混合协议或放宽完整 512 清单约束。

服务器首次真实 UDP 启动进一步暴露出参数入口仍只注册 TCP 模式。当前实现已明确注册 `flow_probe_r2_ns3_tcp_truth_v2_params_v3` 与 `flow_probe_r2_ns3_udp_truth_v2_params_v3` 两个且仅两个参数模式，并把它们分别绑定到 TCP 五项闭合模式与 UDP 单项闭合模式。TCP 参数指向 UDP 闭合配置或 UDP 参数指向 TCP 闭合配置都会在选择运行前明确拒绝。

## 六字段精确定义

方向在每个运行内固定：发送端到受害端为 `orig`，受害端到发送端为 `resp`。观测点固定为路由器的瓶颈 IPv4 接口；该接口的 `Tx` 为 `orig`，该接口的 `Rx` 为 `resp`。

- `orig_bytes`：窗口内观测到的发起方向传输层有效载荷字节。TCP 以源地址、目的地址、源端口和目的端口区分连接，并按序列区间只累计首次观测的有效载荷；重传不重复增加。UDP 去除 IPv4 与 UDP 首部后按数据报载荷累加。
- `resp_bytes`：同样口径的响应方向传输层有效载荷字节。当前 TCP `PacketSink` 只产生确认包，因此应为零；实现仍能在以后存在真实响应载荷时按反向四元组和序列区间计数。当前 UDP 没有反向应用流，因此严格为零。
- `orig_pkts`：窗口内瓶颈观测点发起方向的 IPv4 包数，包含无有效载荷的 TCP 控制包和重传包。
- `resp_pkts`：窗口内瓶颈观测点响应方向的 IPv4 包数；当前 TCP 主要是确认包，当前 UDP 为零。
- `orig_ip_bytes`：窗口内发起方向所有 IPv4 包的总字节数，包含 IPv4 首部、传输层首部和重传。
- `resp_ip_bytes`：窗口内响应方向所有 IPv4 包的总字节数，口径同上。

该口径与 E2/TQH/Zeek 合同一致：传输层有效载荷与线上 IPv4 总量分开计算。TCP 有效载荷按序列范围去重，而 IP 包数和 IP 字节数保留线上实际重传。场景最大应用载荷为 1400 字节，现有 TCP/UDP 头部设置不会超过 1500 字节 MTU，因此冻结场景不产生需要另行归并的 IPv4 分片。

本机 `ns3/ns-3.48.tar.bz2` 的 3.48 源码核验表明，`Ipv4L3Protocol::TxRxTracedCallback` 参数为 `Ptr<const Packet>, Ptr<Ipv4>, uint32_t`；`Tx` 调用前会把 IPv4 首部加入包副本，`Rx` 在移除 IPv4 首部前触发。因此 `packet->GetSize()` 是所需的含 IPv4 首部字节数，副本移除 IPv4 与 TCP/UDP 首部后得到传输层有效载荷。

## 真值交叉门禁

- 每个方向的计数必须是有限非负整数。
- IP 字节数不得小于同方向有效载荷字节数。
- 包数为零时，有效载荷和 IP 字节必须同时为零；包数非零时 IP 字节必须非零。
- 当前单向 UDP 场景的三个响应方向字段必须全部为零，禁止用计划发送量或比例拆分伪造响应流量。
- `orig_pkts` 必须等于同窗口 `truth_qdisc_received_packets`，`orig_ip_bytes` 必须等于 `truth_qdisc_received_l3_bytes`。两者来自不同追踪链路，用于确认瓶颈入口方向观测没有漏包或重复。

## 模式、收据与兼容性边界

- 新主 CSV 模式：`flow_probe_r2_ns3_protocol_windows_v3`。
- 新方向语义：`flow_probe_e2_zeek_directional_windows_v1`。
- 新逐运行收据：`flow_probe_r2_ns3_protocol_dynamics_v2_run_receipt_v2`。
- 新正式物理池行模式：`flow_probe_r2_final_tcp_udp_physics_pool_v3`。
- 收据绑定主模式、六字段有序列表、方向语义版本、主 CSV 头部 SHA-256、完整主 CSV SHA-256、TCP 伴随 CSV SHA-256、场景源码 SHA-256 和既有 TCP 合同 SHA-256。
- 并行续跑只有在上述模式和哈希全部一致时才允许复用。旧 `main.csv`、旧收据、旧参数模式和旧 512 项运行目录会被明确拒绝，不会静默迁移或按比例补列。
- 旧正式池仍是历史证据；它没有六方向真值，不能用于 E2 物理辅助。文件名 `physics-targets-ns3-v2.parquet` 暂时保留以兼容既有 E2 输入路径，但其行内 `schema_version`、`schema.json`、汇总、状态、源锁和制品清单均升级为 v3，不能与旧文件混用。
- 现有 `configs/r2_ns3_tcp_truth_v2_runtime.json` 和 `configs/r2_ns3_protocol_dynamics_v2_parallel_runtime.json` 保持原样，作为历史运行证据。新运行必须另建 v3 参数文件，更新场景 SHA-256、字段闭合汇总 SHA-256、输出目录，并把首次字段闭合的 `resume_from_output_dir` 设为 `null`。

```bash
cd /root/autodl-tmp/thesis/ns3/ns-3.48
env USER=ns3builder ./ns3 build scratch/flow-probe-r2-dynamics-v2
```

2. 在项目根只运行一次新增目标测试：

```bash
cd /root/autodl-tmp/thesis/experiments/llm_probe
uv run --no-sync pytest -q tests/test_e2_ns3_directional_counters.py
```

3. 新建 v3 字段闭合参数，使用新场景 SHA-256、全新输出目录、`resume_from_output_dir: null`，运行五个冻结 TCP 字段闭合样本：

```bash
cd /root/autodl-tmp/thesis/experiments/llm_probe
bash scripts/run_r2_ns3_tcp_truth_v2.sh configs/r2_ns3_tcp_truth_v2_directional_runtime_v3.json
```

4. 验收五个 TCP 样本均为 v3 主模式和 v2 收据，发起方向计数为正、响应有效载荷为零、响应包数和 IP 字节为正，且发起方向与队列入口逐窗口相等。之后再生成并行 v3 参数；在这之前不要启动 512 项重跑。

5. 使用 UDP 单项闭合配置建立独立运行参数并执行一个冻结 UDP 项。它必须通过完整 512 清单门禁，产生恰好一个 UDP 收据；发起方向三项为正，响应方向三项严格为零，发起包数和 IP 字节与队列入口逐窗口相等。不得从清单外替换样本。

6. 仅在 TCP 与 UDP 最小验收均通过后生成并行 v3 参数。512 项完成后使用新的场景哈希、字段闭合汇总哈希和输入目录生成新的物化配置，运行正式物化器。成功输出必须包含六字段且行模式为 v3；随后运行 E2 辅助物化器，状态应从 `blocked_missing_directional_source` 变为 `published`。
