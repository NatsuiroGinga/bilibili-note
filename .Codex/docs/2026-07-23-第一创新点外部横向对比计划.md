# 第一创新点外部横向对比计划

- **状态日期**：2026-07-24。
- **当前状态**：TQH-C2 C/HTTP+AES 候选协议已经通过修复、独立审查和服务器验收；HGB 与 XGBoost 的三个随机种子公开默认配置均已完成，验证集宏平均 F1 均为 `0.931080`。该结果只建立单一加密条件下的首批门槛，不是完整基线矩阵或最终论文测试结果。A/TLS 与 B/QUIC 仍在下载，GeNIS、ns-3、判别式模型、生成式模型和已发表同输入方法仍待补齐。
- **目的**：补齐第三章的现有方法横向对比，防止用 S3、E1 和 E2 之间的内部消融替代外部竞争力证据。

## 1. 证据定位

1. S3、E1、E2 及移除双锚点或队列守恒的变体属于**内部消融**，回答组件是否有效。
2. 随机种子 42、43、44 属于**稳定性复现**，回答结果是否依赖初始化和样本顺序。
3. GeNIS、TQH-C2 和 ns-3 属于**跨证据源验证**：分别回答公开流量检测、跨加密条件检测和物理机制是否成立，三者不能相互替代。
4. Qwen、Llama 或 MiniCPM 之间的固定方法复现属于**跨基座验证**，不替代现有方法横向对比。
5. 只有在同一数据划分、同一输入信息预算和同一评价协议下运行的现有方法，才能作为**外部横向基线**。

## 4. 统一数据与公平性协议

1. GeNIS 主表必须共享相同的训练、验证、子类测试、时间前向和未知攻击清单，禁止为不同方法重新抽样。
2. 输入只能使用推理时可获得的公开字段。不得让任一基线读取攻击标签、ns-3 真值或未知攻击测试信息。
3. 同时报告家族和子类宏平均 F1、未知攻击召回率、良性误报率、已知类拒识率、校准误差和结构化输出合法率。
4. 同时报告可训练参数、训练时间、峰值内存/显存、推理吞吐量和延迟；CPU、通用 CUDA GPU 与 RTX 5090 必须分栏，不用不同硬件、串行与并行运行的墙钟时间直接作效率结论。
5. 使用 PCAP 字节序列而不能消费同一 CSV 流特征的方法，不得将其论文中异数据集数值抄入本文主表。只能先建立共享输入视图，或单列为不可直接比较的参考结果。
6. 每种外部基线至少运行种子 42、43、44，以种子级结果报告均值、标准差，并按 `allocation_group_id` 而不是独立行执行自助法置信区间。
7. 单一最终模型可以选择验证集表现最好的种子，但选择规则必须在最终测试前冻结：先要求该种子通过全部验证门槛，再按家族宏平均 F1 排序；差值小于 `0.001` 时优先物理残差更低者，再相同时优先推理延迟更低者。该单种子只用于最终模型制品、机理图和案例分析；主结果表仍必须报告全部种子。
8. 树模型使用统一主记录的数值视图，DistilBERT 与 Qwen 使用由同一字段、同一缺失掩码和同一顺序生成的确定性文本视图；不同表示可以适配模型结构，但不得增加额外信息。
9. 各模型可以采用论文推荐的优化器和批量大小，但训练数据、早停数据和调参预算必须对等；固定为一个公开默认配置加至多 10 次验证集调参，不能要求异构模型使用完全相同的学习率。
10. 公共检测主表、已发表同输入方法表和 ns-3 物理表各自共享样本与信息预算；不同表之间不强行合并排名。
11. 所有入口采用硬件能力探测并支持 `device=auto`。CPU 至少支持数据、树模型、评价和神经模型功能冒烟；正式神经训练若因成本不可行，必须显式记录而不是硬编码要求 5090。硬件降级不得改变有效批量、样本、步数、种子和评价清单。

## 5. 第三章固定实验结构

1. **3.6.1 实验设置**：数据角色、三级防泄漏划分、输入视图、硬件软件、模型超参数、随机种子、评价指标和统计方法。
2. **3.6.2 综合检测与物理性能对比**：分别给出 GeNIS/TQH-C2 公共检测主表、TQH-C2 FlowPic 同输入表和 ns-3 物理机理表；不同标签空间、输入视图和真值类型不强行合并成单一总分。
3. **3.6.3 训练稳定性与泛化分析**：训练损失、验证宏平均 F1、状态误差、物理残差、三种子分布、时间前向和跨加密条件趋势。
4. **3.6.4 消融实验**：普通监督、状态监督、标准 PINN 和本文完整 PINN 四级对照；R1-R3 选路后，只对最终实际冻结的内部机制做移除消融。只有实际采用条件增强结构时才增加对应结构消融。
5. **3.6.5 物理机理与可视化分析**：生成表征分布、状态轨迹、残差分布、边界违反和梯度路径；图必须由真实制品生成，不预设有界注意力或路由专家一定进入最终方法。
6. **3.6.6 物理强度敏感性分析**：容量、到达突发性、时延、抖动与队列上限逐级变化，观察检测性能和物理误差的退化曲线。
7. **3.6.7 细粒度与未知攻击分析**：高混淆子类、长尾类别、未知攻击和良性误报的混淆矩阵与逐类结果。
8. **3.6.8 真实加密条件与跨拓扑验证**：TQH-C2 的 TLS、QUIC/HTTP3、应用层加密留出，以及 ns-3 星型、哑铃和停车场拓扑外测；方法冻结后补充一个非 Qwen 基座。

这一结构直接参考朱焱雷第三章 `3.6.1` 至 `3.6.8` 的论证顺序，但把“对抗强度与物理填充”替换为本课题真实需要的“物理强度、加密条件和跨拓扑”验证。

## 8. 合规提高外部比较竞争力

1. **冻结与贡献一致的主问题**：本方法不以单一闭集 F1 为唯一目标，而是验证“已知检测不劣于强基线，同时提高队列物理一致性和分布偏移下的可靠性”。未知攻击、校准和效率必须继续报告，不得因指标不利而删除。
2. **匹配资源预算**：主对比使用相同训练样本、训练轮数、调参次数和大致参数规模，并在相同硬件档位内比较效率；更大模型只作为上界，单独报告成本，不与 1B 至 3B 方法或不同 CPU/GPU 档位混成一个无成本约束的排名。
3. **标准场景与压力场景双轨报告**：标准场景检查闭集家族和子类检测；压力场景固定为少标签状态监督、未见攻击、容量与时延分布偏移、星型/哑铃/停车场跨拓扑和加密流量外测。压力场景是方法理论的必要验证，不是用来回避标准场景。
4. **使用未触碰的最终测试集**：现有 GeNIS `eval300` 已多次用于方法选择，在最终论文中必须降级为开发裁决集。外部主表应从未使用的 GeNIS 完整数据中，按会话、时间和场景重新冻结一份不参与调参的最终测试清单，并以 TQH-C2 的完整采集单元与加密条件留出提供外部确认。
5. **调参对等**：外部基线先按论文推荐设置运行，再在共享验证集上给予与本方法相同的调参预算。不得精调本方法而只运行外部基线的默认参数。
6. **使用性能–成本帕累托前沿**：当本方法不在每一个检测指标上排名第一时，如果它能在检测非劣、物理一致性、参数量、延迟和显存之间形成不被支配的位置，仍可形成有效创新结论。权重和不劣界必须在最终测试前预先固定。
7. **失败时修改主张，不修改证据**：若外部强基线在主检测、开放集和成本上同时支配本方法，则不宣称整体优越；只能回到验证集改进方法，或将贡献收窄为物理一致性与可解释性。
8. **创新性通过因果证据凸显**：主结果顺序固定为“公共观测建立可辨识输入”、“R1-R3 胜出路线提供标准 PINN 之外的新增约束”、“完整方法在检测不劣前提下形成状态与物理收益”和“跨数据、拓扑、基座与成本证据限定适用范围”。条件增强结构只有实际通过门槛后才进入这条证据链，不以挑选单一最高数值代替因果论证。

## 9. 强基线下的理论创新证据合同

### 9.1 核心判定原则

当前只冻结**使用 PINN 研究恶意流量检测**这一方向，不冻结具体控制方程、边界条件、状态尺度、结构接口、算法名称或章节标题。R1 多尺度控制体、R2 TCP 流体和 R3 网络演算边界必须先在相同数据、状态头、训练预算和评价协议下比较，再依据预注册门槛选择；双锚点和有限队列残差仅属于已有正证据与候选构件，不自动进入最终方法。

强基线在单一域内任务上接近性能上限时，本文不通过削弱基线、改变输入或挑选最好种子制造优势。理论创新必须沿“预先诊断的失败场景 → 专用物理建模 → 理论性质 → 因果消融 → 外部有效性”证明。主张固定为：**在保持域内恶意流量检测性能非劣的前提下，本文 PINN 应提高跨加密条件、未知攻击或跨网络拓扑下的可靠性，并降低未观测状态误差与物理残差。**

单一 C/HTTP+AES 域内宏平均 F1 `0.931080` 只用于建立传统树模型门槛。它不能证明跨加密泛化，不能替代 GeNIS 多分类和开放集结果，也不能裁决 R1-R3 中任何 PINN 路线或内部机制。

### 9.2 预先固定的困难场景

1. **跨加密条件**：TQH-C2 采用留一加密配置，分别将 A/TLS、B/QUIC、C/HTTP+AES 的 12 个完整采集单元作为留出域；其余两个配置只能使用训练与验证单元。主报告三个留出域的平均宏平均 F1 和最差域宏平均 F1，不只报告最好配置。
2. **时间与未知攻击**：GeNIS 使用会话、时间和场景隔离的时间前向与未知攻击清单，报告未知召回、良性误报、已知拒识和校准，不能用闭集高分掩盖开放集失败。
3. **跨网络拓扑**：ns-3 的星型拓扑用于冻结方法后，以哑铃和停车场拓扑作为未见外测；这些外测不参与训练、归一化和调参。
4. **稀疏物理监督**：状态监督密度和公共观测字段在验证前固定，用于检验候选 PINN 物理建模是否在少量状态监督下仍有效；不得把最终测试真值回填为输入。

### 9.3 必须完成的因果对照

1. 普通监督 Qwen：建立无物理信息的生成式基线。
2. 仅状态监督：隔离新增状态标签和观测字段的收益。
3. 标准 PINN：建立“仅加入通用可微物理残差”的直接对照。
4. R1-R3 路线对比：多尺度控制体、TCP 流体和网络演算边界使用相同状态头、预算和清单，只用于选择具体物理公式体系。
5. 胜出路线的单机制变体：只拆除该路线实际采用的边界、残差、尺度或状态接口，不把其他落选路线拼入消融。
6. 完整方法：验证胜出路线内部机制组合后是否同时形成检测、状态和物理收益。
7. 打乱包序、方向或时间的负对照：确认收益来自动力学信息而不是参数增加或数据来源暗示。

### 9.4 结果成立条件

1. 域内检测必须满足预注册非劣界；具体数值须在完整 `dataset-v1` 的最终测试开放前冻结。
2. 跨加密条件的平均与最差域宏平均 F1 应相对最强同输入基线形成正向效应，并报告按采集单元配对的 95% 置信区间。
3. 未知攻击收益必须与良性误报率、已知拒识率和校准误差联合报告；不能靠放宽拒识阈值单独提高召回。
4. 三个随机种子的未观测状态误差和物理残差均须相对同分区状态监督或标准 PINN 改善至少 `10%`。
5. 完整方法必须优于对应单机制删减版本；没有独立消融证据的机制不得进入算法名称或贡献点。
6. 若本方法不在所有检测指标上第一，只有在检测非劣且物理一致性、跨域可靠性或性能－成本上形成不被支配位置时，才能主张综合优势。

### 9.5 与代表性论文的论证方式对应

- 朱焱雷论文在不同逃逸强度、稳定性、细粒度类别和真实受限环境中验证目标鲁棒性，而非只比较普通分类准确率；本文只借鉴这种“围绕目标失败场景组织证据”的方式。
- 交通网络 PINN 同时报告状态误差、守恒误差、稀疏观测、敏感性和计算代价，说明物理方法不能只给一个任务分数。
- ConFIG 在相同步数和相同墙钟预算下比较困难方程及外部多任务基准，支持本文冻结同预算比较和机制消融。
- TCBench 揭示同源切分与采集偏移会显著改变流量分类结果，因此本文按完整采集单元和父组统计，不用流级随机划分制造高分。

### 9.6 失败边界

若最终方法在跨加密、未知攻击和公开数据检测上均不能优于标准 PINN 或强检测基线，即使物理残差下降，也只能声称改善物理一致性或状态估计，不能声称提出了性能更强的恶意流量检测方法。此时应依据未触碰测试集之外的验证证据修改方法，或收窄论文主张，不得更换指标、降低门槛或删除不利结果。
