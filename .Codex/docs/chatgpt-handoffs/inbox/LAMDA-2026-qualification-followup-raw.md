【推论】

**2016：排序与阈值错误并非同步崩溃。**较高 ROC-AUC 与较高 FNR 可以同时出现，值得区分阈值迁移、校准变化及局部恶意子群退化；但缺少 FPR、阈值来源和分组结果，不能指定其中某一种为原因。

**不能由 AP 判断相对随机基线的差距，也不能指定新家族为病因。**前者还需要该评价集合的恶意率；后者需要家族及首次出现时间的对应关系。

这些解释不建立模型有效性、统计显著性或严格时间外推资格；也不能据此推断未经提供的其他年份结果。

4.3 DRIFT 的三个公开复现缺口
（一）分片名称不等于时间角色

【在线全文·官方数据卡】“Recommended Evaluation Protocol”明确说明：年度 train/validation/test 是打包分片。原文源期为 2017—2019；源年份使用 train+test、保留 validation，后续评价年份使用全年分片。按文件名只取源期 train 和后期 test，并不等价于该卡说明的论文协议。
Hugging Face

**【推论】**这与 LAMDA 的关键教训一致：**信息资格由时间截止点和拟合用途决定，不由文件名决定。**这只是官方协议解释，不能据此改写发起方可能已经冻结的较小源期或抽样合同。

（二）家族字段有公开文档差异

**【在线全文】**GitHub README 说公开发布不包含 test_type=family 所需家族评价集；但当前 HF 数据卡声明 raw_including_TLD 具有 family，eSLD 模型输入则没有这一列。
Hugging Face

**【推论】**应把此前“家族数据未公开”的笼统结论收窄为：

直接可用的论文家族评价集尚未核准；官方数据卡声明了另一 raw 视图中的家族字段，但还没有证明其与模型输入及原家族评价集合一一对应。

本轮没有读取实际数据字节，不能确认去后缀、去重后是否出现跨家族合并或映射歧义。

（三）打包时使用全期规模，与分词器读取未来语料不是一回事

【在线全文】数据卡称固定年度训练分片大小由全时期最小年度类别文件决定；这是全期规模参与打包的证据。另一方面，make_tokenizer.py 的 train(file_paths, ...) 没有自身的年份截止检查，语料范围取决于调用方。

【推论】前者不能被升级成“未来标签泄漏”，也不能被误称为“已证实 WordPiece 使用未来语料”。但它说明，严格历史可实施性需要分别审查打包规则、语料选择、分词器拟合，不能只看到训练年份就自动认证整个流水线。

五、方法家族只映射真实缺口

以下全部为 【推论·外部研究候选】，不表示新增实验已获授权。

方法家族	有依据的适配对象	必须保留的对照	失败门
