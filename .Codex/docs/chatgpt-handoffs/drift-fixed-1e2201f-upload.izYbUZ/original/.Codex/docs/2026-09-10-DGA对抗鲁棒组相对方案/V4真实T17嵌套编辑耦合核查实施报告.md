# V4 真实 T17 嵌套编辑耦合核查实施报告

## 结论

**当前 production 不满足 V4 的共享前缀前提。** `official_p2p3.py` 的 `gen_variants_L` 在每个 epoch 只为当前档位生成四个变体，缓存键为 `(样本索引, epoch)`；它没有为同一原域名构造或保存 1 位、2 位、半替换三档输出的同一随机编辑流。因此，理论命题包 `T3`／`T4` 的条件不能写成当前 production 已满足。

这是一项实现前提核查，不修改公式、候选、训练合同或论文结论。

## production 身份与读取方式

核查对象为 `.Codex/docs/2026-09-10-DGA对抗鲁棒组相对方案/official_p2p3.py`，文件 SHA-256 为 `1f103880b4095ef081f6235364877f49f3ed3f88f26f50f6907cd355977dd079`。

核查器没有导入该脚本顶层模块，避免其顶层 `torch.device(...mps...)` 选择；而是从同一源码 AST 精确提取 `perturb1`（115--127 行）、`perturb2`（85--96 行）和 `perturb_half`（99--112 行）的纯字符串函数定义，在 CPU 上调用。因而输出遵循 production 的编辑逻辑，同时不占用 MPS。

三算子的实际改动位置数均与声明预算一致：1 位 `30,000/30,000`，2 位 `30,000/30,000`，半替换 `30,000/30,000`；半替换的平均实际改动位置数为 `7.870233`。这只说明各自落在预算集合中，**不**说明不同预算输出由同一随机流耦合。

## 三种命题必须分开

| 命题 | 本次证据 | 是否可用于当前 V4 |
| --- | --- | --- |
| 集合包含 | 三个算子各自在其声明编辑预算内 | 不可；集合包含没有逐样本共享随机性 |
| 后验可构造耦合 | 用一条无重复位置编辑流取 1 位、2 位、半替换前缀 | 不可；这是替代构造，不是当前 production |
| 当前 production 同一编辑流 | `gen_variants_L` 单档调用，未生成跨档三元组、未保存共享流 | 不满足 |

## 真实成员上的位置／字符核查

由于当前 production 没有跨档联合生成路径，核查器另做了**反事实顺序重放**：对同一原域名依次调用 production 的 1 位、2 位、半替换函数，只连续共享 `Random` 状态。此重放保留各函数的真实输出算法，但不是 production 训练路径；它用于观测若把不同独立抽样输出并列，位置与替换字符是否恰好嵌套。

| 算子对 | 可观测输出嵌套率 | 嵌套失败数 | V4 Hamming 界满足率 | 代表性脱敏失败类型 |
| --- | ---: | ---: | ---: | --- |
| 1 位 vs 2 位 | `0.005200` | `29,844` | `0.005200` | 低预算编辑位置未出现在高预算输出 `24,829`；同位置替换字符冲突 `5,015` |
| 1 位 vs 半替换 | `0.014267` | `29,572` | `0.014267` | 编辑位置缺失 `15,380`；同位置替换字符冲突 `14,192` |
| 2 位 vs 半替换 | `0.000133` | `29,996` | `0.000133` | 位置缺失 `7,478`；字符冲突 `6,465`；两类同时发生 `16,053` |
| 三对同时成立 | `0.000000` | `30,000` | `0.000000` | 无逐样本三档共享前缀 |

表中只包含聚合计数和脱敏故障类别，不包含任何原始域名、逐样本输出或逐样本分数。

## 最小数学自检

同一批真实 T17 成员上，另以一条明确的随机编辑流生成三个预算的前缀。这一**后验可构造**版本在三对上均为 `30,000/30,000` 可观测嵌套，Hamming 界亦均为 `30,000/30,000`。它验证了“若显式共享位置与替换字符流，T3 条件可机械满足”；它不为当前 production 提供追溯性证据。
