## WEB-IDS23 证据

### 来源与版本

- 数据 DOI：<https://doi.org/10.26249/FK2/MOCIY8>。
- Dataverse API：<https://osnadata.ub.uni-osnabrueck.de/api/datasets/:persistentId/?persistentId=doi:10.26249/FK2/MOCIY8>。
- 技术报告：<https://arxiv.org/abs/2502.03909>，只有 v1，2025-02-06 提交。
- 发布者：osnaData；发布日期 2025-02-07；Dataverse 版本 1.0。
- 官方 README 的 MD5 为 `1ab1be0995e6b089e853ef3b96e7ed3b`，与 API 一致。

### 数据与环境

- OpenStack 虚拟环境分为外部区和内部区，经运行 Zeek 的路由器相连。
- 外部区有 5 个客户端，内部区有 Web、SMTP、SSH、DNS 和 FTP 共 5 个服务器。
- 各客户端在不同迭代中均执行良性与攻击模式，作者的目的是降低客户端身份捷径。
- 发布仅含按类拆分的 CSV，没有 PCAP、攻击运行清单或生成器代码。
- 每行是 Zeek FlowMeter 流。论文声称 80 个 FlowMeter 特征加 `service`、`traffic_direction`，共 82 个特征；README 还列出 `uid`、`ts`、双向主机和两个标签字段。

### 加密范围

- 六种 Web 攻击各有 HTTP 与 HTTPS 配对：暴力破解、拒绝服务、SQL 注入、反向 Shell、服务端请求伪造和跨站脚本。
- HTTPS 六类合计 1,021,519 条，SSH 两类合计 68,525 条；这只是攻击文件计数，良性文件未按协议公布分布。
- 没有 QUIC、HTTP/3 或 VPN 流量。

### 明确限制

- 数据是全合成虚拟环境流量，不含生产网络真实流量。
- 反向 Shell 和服务端请求伪造至少需要两条流才能保证检出，但发布方没有记录结果流与触发流之间的因果关系。
- 论文未提供分类基线、随机种子、训练/验证/测试协议。

## VisQUIC 证据

### 来源与版本

- arXiv：<https://arxiv.org/abs/2410.03728>，v1 至 v6，本次以 2025-05-24 的 v6 为准。
- 官方代码与数据入口：<https://github.com/robshahla/VisQUIC>。
- 本次审计的默认分支提交：`e5febcc6a4867ba33a450a793d291869133bef31`，日期 2026-04-07；仓库没有版本标签。
- PDF 题名页的作者顺序为 Gahtan、Shahla、Cohen、Bronstein；arXiv Atom 元数据将后两位调换。引用时应保留该差异记录。

### 数据和标签

- 论文表 I 合计 44,514 个网页项、100,664 条迹线、5,408,166 张 0.1 秒窗口图像和 1,932,275 张 0.3 秒窗口图像。
- Cloudflare 组占 44,700 条迹线（44.41%），前五个服务器组合计占 83.32%。
- 图像以到达时间和包长为两轴，服务器到客户端为红通道，客户端到服务器为绿通道，像素强度为包密度。
- 监督信号是解密后得到的窗内 HTTP/3 响应数，不是恶意标签。
- 官方 README 说全量数据为多个 ZIP：PCAP/KEY 分卷使用 `VisQUIC` 前缀，PNG 分卷使用 `rgb_images` 前缀。仓库样例来自 `VisQUIC1.zip` 和 `rgb_images1.zip`。
- 官方 README 声称 `all_websites.txt` 有 9,075 条链接，与论文表 I 的 44,514 个网页项口径不一致；没有版本化数据清单解释该差异。

### 基线与切分

- 论文声称：每个服务器组的迹线随机 80:20 分为训练与测试，重复 5 次。
- 32×32 RGB 图像使用 0.1 秒和 0.3 秒窗口。论文称使用复合损失、Adam、`ReduceLROnPlateau` 和早停。
- 窗口级 CAP 容差指标在 5 次切分中的最高值为：0.1 秒窗 `CAP±2=0.98`，0.3 秒窗 `CAP±2=0.97`。
- 迹线级累积响应数在 ±3 容差下：0.1 秒窗 92.6%，0.3 秒窗 71.0%。
- 当前 GitHub 代码的 `deep-model/dataset.py` 对图像执行无固定种子的 `random_split`；`main_deep.py` 使用交叉熵、SGD 和固定 1000 轮。这与论文的迹线切分、复合损失和 Adam 不一致，当前仓库不能直接复现论文数字。

### 泄漏风险

1. 同一网页有多次顺序请求，迹线级随机切分仍可把同一 URL/内容放入两侧。
2. 同一 PCAP 被切成多个图像；代码若在图像层随机切分，会直接交叉同迹线窗口。
3. 图像生成器同时支持 0 和 0.9 重叠率；对 90% 重叠窗口做图像级切分会产生近重复样本。
4. 论文只说两个住宅网络、四个月和全时段采集，未公布精确日期、采集地编号或官方分区清单。
5. 仓库 README 承认部分迹线无法使用配套密钥解密，标签完整性需要逐迹线审计。

## 与现有接口的证据化推论

### WEB-IDS23

- Zeek FlowMeter 字段与 HIKARI 高度同源，可映射当前 `canonical_core_v1` 的 8 个字段，但需新适配器处理 `id.orig_h`/`id.resp_h`、`attack`/`attack_type` 命名。
- 当前 GeNIS 分层家族只允许 `benign`、`bruteforce`、`dos`；SQL 注入、XSS、SSRF、反向 Shell、扫描和枚举不能直接进入现有家族任务。
- 可以在不改变标签空间的前提下作为冻结模型的二元域外测试；不应直接混入当前分层训练。
- 只有流统计，没有队列、链路容量、入队、出队和丢弃真值，不能直接监督 PINN 状态或守恒残差。

### VisQUIC

- PCAP 可派生公开可观测的包数、字节、包长、到达间隔和速率，但现有代码没有 PCAP/图像适配器。
- 无恶意标签，不能映射到当前二元、攻击家族或子类生成任务。
- 没有队列、容量、入队/出队/丢弃真值，不能监督当前 PINN；只能作为 QUIC 公开观测边界和表征方法参考。
