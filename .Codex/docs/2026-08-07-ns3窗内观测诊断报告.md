# ns-3 窗内观测诊断报告

## 结论

**预注册判据 `G-diag` 不通过，「窗内涨落被首尾采样抹平」假设被否决。**

诊断同时给出了比判据本身更有价值的信息：物理监督退化的根因**不是观测粒度**，而是**该 ns-3 场景在绝大多数窗口里根本没有产生排队**。因此缩短窗口时长或增加窗内采样点**不会创造任何信息量**，原计划的 v4 重物化方向应当放弃。

## 预注册判据原文（运行前冻结，未事后修改）

在 `traffic_mode = dos` 且 `offered_load_ratio ≥ 1.05` 的窗口子集上：

- 通过：`diag_queue_peak_l3_bytes > 0` 的窗口比例 **≥ 50%**，且 `diag_queue_nonzero_seconds` 的中位数 **> 0**；
- 失败：上述任一不成立。

## 分布：双峰，且两峰都说明缩窗无用

| 统计量 | 值 |
| --- | ---: |
| `diag_queue_nonzero_seconds` 均值 | `0.002504` |
| 中位数 / p75 / p90 | `0.0` / `0.0` / `0.0` |
| p99 / 最大 | `0.100000` / `0.100000` |
| 非零占用 > 0 的窗口比例 | `0.0266` |
| `diag_queue_peak_l3_bytes` 中位 / p90 / 最大 | `902` / `1228` / `157184` |
| `diag_queue_time_avg_l3_bytes` 均值 / p90 / 最大 | `2471.46` / `0.00` / `156543.01` |

两个峰：

1. **约 `97.3%` 的窗口**：峰值队列中位数 `902` 字节，**不到一个 `1200` 字节的包**，占用时长为 `0`。包到达即被发走，**不存在排队**。这些窗口没有任何窗内动力学可供更细的采样去捕获。
2. **约 `2.66%` 的窗口**：占用时长 p99 与最大值均为 `0.100000`，即**整窗持续非空**，峰值最大 `157184` 字节（顶到 `128` 包上限）。这些窗口是**持续拥塞**，其首尾队列本来就非零，**不会被首尾采样抹平**。

因此两个峰都不支持「缩短窗口或加采样点能提高信息量」：无排队的窗口没有东西可捕获，持续拥塞的窗口已经被现有采样完整捕获。

该 `2.66%` 与此前在 `e2-physics-auxiliary-v1` 全体 `train-fit` 上测得的「净流入非零占 `0.95%`」量级一致（本次是 dos 过载子集，基数更有利）。

## 被否决与被排除的解释

| 解释 | 状态 | 证据 |
| --- | --- | --- |
| 窗内队列涨起又排空，被 `0.1 s` 首尾采样抹平 | **否决** | 峰值中位数不足一个包；有真实占用的窗口是整窗持续非空 |
| 相位对齐：突发周期与窗口周期整除，边界系统性落在间歇 | **不成立为主因** | 若成立，应看到大量「峰值高但边界为零」的窗口；实际是峰值就一个包 |
| 瓶颈错位：被测 qdisc 不在真实拥塞链路 | 先前已排除 | 队列曾顶到 `128` 包上限，说明被测 qdisc 就是拥塞点 |
| 归一化偏离台账 F2 | 独立的合同违规，非本退化的原因 | 记账恒等式使零边界窗口的净流入精确为零，换分母不改变零 |
| **场景产生的持续拥塞事件过于稀疏** | **当前最强解释** | `97.3%` 的过载窗口无排队；UDP DoS 为突发式带相位偏移，突发间歇足以排空 |

## 追加诊断：残差类物理量恒为零，状态类物理量信息丰富

诊断裁决后直接统计上游 ns-3 真值表。`tcp-sender-truth-v2.parquet` 的 `train-fit` 共 `122880` 行：

| 物理量 | 非零占比 | 中位 | p90 |
| --- | ---: | ---: | ---: |
| 队列守恒净流入（`e2-physics-auxiliary-v1` 全体 `train-fit`） | `0.0095` | `0` | `0` |
| `truth_tcp_ack_residual_normalized_mse` | **`0.0000`** | `0.0` | `0.0` |
| `truth_tcp_loss_residual_normalized_mse` | **`0.0000`** | `0.0` | `0.0` |
| `truth_tcp_rtt_mean_ms` | `0.9746` | `50.42976` | `747.737860571` |
| `truth_tcp_cwnd_contraction_event_count` | `0.1256` | `0.0` | `1.0` |
| `truth_tcp_rtt_sample_count` | `0.9746` | `11` | `30` |

**更正（2026-08-07，经 Fable 5 裁定并由本机制品核验）**：初稿据此写「所有残差类物理量都恒为零」，这是**范畴错误，已作废**。`truth_tcp_ack_residual_*` 与 `truth_tcp_loss_residual_*` 由场景 `.cc` 在仿真侧直接计算，全过程不存在被训练的模型，它们是 ns-3 NewReno 实现与解析模型的**自洽性验证列**；恒为零说明数据管线**成功**，不能作为「残差类平凡」的证据，须从证据链剔除。

结论经另一条证据链依然成立：E2 实际使用的唯一**模型对真值**残差（队列守恒）确实平凡，原因是真值侧在该观测系统下退化，而 G-diag 已证明这是队列动力学的双稳本性、非粒度问题。

必须区分两种残差，不可混谈：

- **E2 的守恒残差**是 `predicted_change - normalized_net_input`，`predicted_change` 来自模型、`net_input` 来自 ns-3 真值，属**模型对真值**的比较，形式上是合法 PINN 残差。它退化的原因是**真值一侧本身平凡**（净流入 `99%` 为零），不是形式错误。
- **`truth_tcp_ack_residual_*` 等是纯真值列**，完全由 ns-3 数据算出，衡量 ns-3 的 NewReno 实现与解析模型是否自洽。恒为零说明 ns-3 自洽，属**验证制品，本就不应作为监督目标**。

该区分是否改变「应改用状态监督」的结论，已提交 Fable 5 裁定，**尚未定论**，此处只记录已核验数据。

## 对后续路线的含义

- **v4 的「缩短窗口 / 增加窗内采样点」方向应放弃**，它不解决信息量问题。
- 若仍要让共享守恒律带上信息量，必须**改变被观测的物理过程**——提高持续拥塞窗口的比例（如提高持续负载、缩小队列上限、改突发参数使间歇短于排空时间）。这属于**改变冻结物理网格**，是比原 v4 更大的合同变更，须用户单独裁决。
- 归一化回归台账 F2 仍应执行，但定性为**独立的合同违规修复**，不得宣称它能解决退化。
- 本诊断只裁决观测粒度假设，**不裁决物理监督是否有检测增益**。

## 实施过程中的两处缺陷与修正

1. **正式并行运行器不可复用**：它硬绑 v3 输出身份、固定 scratch 源与可执行名、字段闭合绑定 v3 场景哈希。用户裁定不改该运行器，改写独立驱动脚本，并使用独立 scratch 名 `flow-probe-r2-dynamics-v3-diag.cc`，使 v3 编译产物完全不受影响。
2. **主表列数与冻结校验冲突**：`_validate_main` 对表头做精确相等校验（`MAIN_COLUMNS` 为 46 列），原诊断场景把主表加到 50 列会使每个运行抛错、CSV 滞留 `.partial`。已改为旁车方案。
3. **编译需隔离 CMake**：系统 `cmake` 为 `3.22.1`，低于 ns-3.48 要求的 `3.25`。必须使用 `/root/autodl-tmp/thesis/ns3/.tools/ns3-cmake-3.25.2/bin`。加上后 `13` 秒完成单目标编译。
