## 重要问题

### 1. `Path.resolve()` 先于 `O_NOFOLLOW`，实际未拒绝配置符号链接

位置：

- `src/flow_probe/r2_final_physics_fit.py:228-230`
- `src/flow_probe/r2_final_physics_fit.py:244-258`
- `src/flow_probe/r2_final_physics_fit.py:268-274`
- `src/flow_probe/r2_final_physics_fit.py:470-473`
- `src/flow_probe/r2_final_distilbert_probe.py:168-170`
- `src/flow_probe/r2_final_distilbert_probe.py:184-198`
- `src/flow_probe/r2_final_distilbert_probe.py:212-214`
- `src/flow_probe/r2_final_distilbert_probe.py:604-618`
- `src/flow_probe/r2_final_distilbert_probe.py:637-655`

两个模块的稳定打开器都设置了 `O_NOFOLLOW`，但配置解析函数 `_resolve_path`、拟合配置加载器及探针制品读取器会先执行 `Path.resolve()`。原始配置路径若是符号链接，链接会在进入 `os.open(..., O_NOFOLLOW)` 前变成目标路径；打开器看到的是普通目标文件，因而不会拒绝原始符号链接。角色清单与 Parquet 路径在物理拟合配置解析时已经按相同方式规范化，拟合 YAML、绑定 JSON 和检查点在探针配置解析及加载前也经过同样处理。

独立最小复现得到 `SYMLINK_PRE_RESOLVE_ACCEPTED 3`：

1. 指向真实拟合 YAML 的临时符号链接被 `load_config` 接受。
2. 把角色清单路径替换为指向同一真实清单的符号链接后，`_verify_physics_role_manifest` 接受。
3. 探针侧 `_read_verified_artifact_bytes` 接受带正确摘要的符号链接制品。

当前摘要校验及“同一已打开对象完成哈希和使用”仍能阻止不同内容在哈希后被重新按路径加载，因此本轮没有重现第二轮的哈希后替换漏洞；但实现不能声称已经满足第二轮明确的符号链接拒绝门槛，冻结路径来源仍允许可变别名。

修复门槛：保留配置中待打开路径的词法身份，在任何 `resolve()` 跟随链接之前对该路径执行安全打开并拒绝符号链接；从该已打开普通文件句柄取得身份、哈希和内容。规范路径比较如仍需要，应从已验证句柄或不跟随链接的路径信息派生，不能为了比较路径而先解引用再打开。五类冻结输入应共同应用这一规则，并增加直接传入符号链接的故障注入。

## 已确认闭合

### 1. 不可变绑定清单原子且不覆盖发布

- `r2_final_physics_fit.py:1092-1125` 使用 `mkstemp(dir=path.parent)` 在最终目标同一目录创建唯一临时文件，因此源与目标处于同一文件系统。
- 规范 JSON 字节完整写入后执行 `flush`、文件 `fsync`、回卷和同句柄逐字节及 SHA-256 核对。
- `os.link(temporary, path)` 在声明的 Linux/POSIX 正式环境中以单次硬链接创建最终名称；目标已存在时返回失败，不会覆盖既有 inode。发布后刷新父目录，删除临时名称后再次刷新父目录。
- 已有最终文件只通过稳定普通文件句柄读取；同内容幂等接受，差异内容拒绝，既有字节不变。
- 独立故障注入结果为 `ATOMIC_NO_REPLACE_FAULT_INJECTION_OK`：链接发布失败后最终名称不存在且临时目录为空；正常发布、同内容幂等、差异内容拒绝及既有符号链接目标不被覆盖均通过。

硬链接发布依赖文件系统支持硬链接及目录 `fsync`。同目录 `mkstemp` 已满足同文件系统前提；项目正式运行环境固定为 Linux，因此本轮不把 Windows 或不支持硬链接的文件系统兼容性计为问题。在不支持这些原语的平台上只可安全失败，不能宣称跨平台可用。进程被强制终止或掉电时可能残留隐藏临时文件，但最终名称不会指向半写内容；普通异常路径会在 `finally` 中尝试清理临时文件。

### 2. 五类冻结输入的哈希与使用绑定

- 物理角色清单：一次稳定读取形成不可变字节快照，快照同时用于 SHA-256 与 JSON 解析。
- 物理 Parquet：同一普通文件句柄先计算 SHA-256、回卷，再传给 `pd.read_parquet`；上下文退出前复核设备、inode、大小、修改时间和状态变更时间。
- 拟合 YAML：物理拟合侧一次读取的快照同时用于文件摘要和 YAML 解析；探针侧先从一次稳定打开取得已验证快照，再把该快照传入拟合配置解析器，不按路径重开。
- 绑定 JSON：一次稳定打开读取完整快照，快照同时用于 SHA-256 与 JSON 解析。
- 正式物理检查点：同一普通文件句柄先计算 SHA-256、回卷，再传给 `torch.load`；退出前复核文件身份。

路径在打开后被原子替换不会改变已打开描述符所指 inode；原地改写会由结束时 `fstat` 身份复核拒绝。本轮定向搜索发现的 `run-binding.json`、物理训练恢复检查点、探针训练恢复检查点和最佳分类模型读取属于可恢复运行制品，不是本轮受冻结摘要约束的五类输入，未把它们误计为第二轮问题复发。
