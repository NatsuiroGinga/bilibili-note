# R2 TCP 残差与检查点阻断最小修复

## 结论

本轮已完成独立复审确认的三项核心代码阻断修复：TCP 残差预测事件自门控、检查点未绑定实际实现、以及中途检查点重复训练批次。种子 42 正式物理拟合配置的 TCP 残差维数已从 3 改为 4，三份最小探针配置中的拟合配置摘要已同步更新。

本轮未修改、复制或读取三个 TCP/UDP v2 Parquet，也未读取任何公开检测最终测试。缺失的 `detection-view-train-fit.parquet` 由独立代理回收与核验，不属于本报告范围。

## TCP 四段残差

- 新增 `ResidualObservationContext`，只接收训练期或 G3 评价期的观测真值与观察掩码。
- TCP 阶段门只由 `observed_state.detach()` 和 `observed_mask.detach()` 生成，不再读取预测的 `loss_event_count` 或 `timeout_event_count`。
- 固定优先级为 `RTO > loss > growth`；无事件增长窗口再由观测的 `cwnd_start < ssthresh_start` 区分慢启动与拥塞避免。四个掩码逐窗口互斥。
- 慢启动使用窗口级 ACK 字节增长近似；拥塞避免使用 `acked_bytes * MSS / cwnd_start`；损失与 RTO 分别约束阈值终点、拥塞窗口终点和在途字节终点。合同名称收窄为 `tcp_sender_newreno_mutually_exclusive_window_v3`，不声明事件时刻的精确 NewReno 轨迹。
- RTT 只作为停止梯度、严格正的观测条件尺度，不成为可学习分母或预测门。
- 零坍缩收据升级为 v2，逐项记录慢启动、拥塞避免、损失和 RTO 的非平凡残差与预测状态梯度；另行验证 `cwnd_end`、`ssthresh_end`、`bytes_in_flight_end` 均有非零梯度、四段掩码各激活一次、观测门停止梯度，以及任意修改预测 loss/timeout 状态都不改变残差。
- 无物理真值的分类特征生成只编码表示，不计算 TCP 残差；正式训练和 G3 评价显式传入观测上下文。

## 正式运行暴露的数据加载修复

首次正式运行越过环境与 Python 入口后，在 TCP/UDP 帧拼接处触发 `InvalidIndexError`。只读核验确认三份冻结 Parquet 的物理模式均无重复列。根因是 `udp_dynamics.observed_fields` 合法地让六个状态复用同一 `truth_udp_observed` 掩码，而旧加载器按配置列表直接投影，人工产生六个同名列。

加载器现按首次出现顺序稳定去重投影字段，不改变状态到观察掩码的语义映射。同时在三份原始 Parquet、TCP/UDP 合并结果、拼接前协议帧和最终拼接帧执行列唯一性门禁；失败信息使用 `r2_column_uniqueness_failure_v1`，明确记录来源与重复列名。

限定行为验证直接读取三份冻结开发物理 Parquet，得到 207,360 行、95 个唯一列，其中 TCP 184,320 行、UDP 23,040 行，与两份伴随真值行数一致。没有修改数据、公式、配置或其他实现文件。

旧正式尝试已经写入绑定旧实现摘要的物理输出根。重新启动前必须整体归档该失败输出根并保留日志与收据，再创建空的新输出根；新加载器会拒绝在旧 `run-binding.json` 上继续训练，禁止覆盖或删除失败证据。

## 跨协议非适用掩码修复

第三次正式启动在 `_build_split` 暴露跨协议非适用字段为空的问题。按最新要求采用测试驱动开发，新增目标测试 `tests/test_r2_final_physics_fit_protocol_masks.py`，SHA-256 为 `db26244046706f67772cb27d9cb38e78cff22f3426c91d587e888253367ce0c5`。

红灯命令：

```bash
.venv/bin/pytest -q tests/test_r2_final_physics_fit_protocol_masks.py::test_cross_protocol_masks_allow_na_but_applicable_masks_remain_strict
```

首次结果为 `1 failed`。失败位于 `_strict_bool_series`，证明跨协议空值把整列提升为 `object` 后，旧实现会误拒绝筛回的原生布尔值。第一次最小生产修改后，同一测试继续失败于 UDP 适用真值为空；进一步追踪确认公共窗口与伴随真值字段碰撞生成 `_x/_y`，而无后缀列只含对侧协议占位。

最终最小修复包括：

- 合并前从公共协议帧移除对应协议专属字段，使伴随真值成为唯一权威来源；
- `_build_split` 只对共享专家和当前路由适用专家解析真值，非适用专家生成零状态与全假掩码；
- `object` 列逐值只接受原生布尔或精确数值 `0/1`，继续拒绝空值、字符串和其他数值。

绿灯使用同一命令，最终结果为 `1 passed in 1.56s`，无警告。测试同时证明 TCP 行的 UDP 掩码和 UDP 行的 TCP 掩码均为全假，并证明 UDP 同协议观察掩码为空时仍明确失败。
