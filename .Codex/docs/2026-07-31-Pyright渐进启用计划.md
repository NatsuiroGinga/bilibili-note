# Pyright 渐进启用计划

## 目标

在不重写现有训练代码、不阻塞正在运行实验的前提下，为 `llm_probe` 建立可复现的 Python 静态类型检查，并为后续高可靠数据物化组件评估 Rust 留出边界。

## 边界

- 训练、推理、Transformers、LoRA、SwanLab 和 GPU 实验继续使用 Python。
- Pyright 首先覆盖 `src/flow_probe`，服务器 Python `3.10` 为最低解释器基线。
- 先建立现有错误基线，再逐步把新建或重构模块提升到严格检查；不为清零历史告警大范围修改生产代码。
- Pyright 是代码交付检查，不是服务器实验启动门禁。
- 后续新建的确定性物化、哈希校验、并发下载或清单生成组件可以单独评估 Rust；本轮不引入 Rust 工具链。
- 不运行格式化工具，不运行本机测试。

## 首次基线

- Pyright 版本：`1.1.411`。
- 全仓 `src/flow_probe`：分析 73 个文件，得到 737 个既有错误；主要为参数类型、属性访问、缺少可选 GPU 依赖、调用参数和索引类型问题。
- `shared_b0_physics_sidecar.py`：4 个既有错误。
- `r2_protocol_contract.py`：3 个既有错误。
- 默认检查范围先固定为上述两个高风险新模块。清零这 7 个错误后，新增或实质重构模块必须先达到单文件零错误，再加入默认范围。
- 全仓结果只用于历史债务审计，不得因 737 个既有错误停止当前服务器实验。

## 使用规则

1. 日常默认检查使用 `uv run --no-sync pyright`。
2. 新增或实质重构模块先使用 `uv run --no-sync pyright src/flow_probe/模块名.py`。
3. 单文件错误必须区分本轮新增与历史遗留；不得为清零无关模块而扩大修改范围。
4. Pyright 检查是代码交付门禁，不是实验启动门禁；已经开始运行的实验不因类型债务中止。
5. Pyright 不能替代目标测试、数据哈希、物理量纲检查或实验结果验证。

## 验收

- `uv run --no-sync pyright --version` 可运行。
- Pyright 能定位 `src/flow_probe`，不会扫描 `.venv`、运行制品、数据集或模型目录。
- 基线报告区分历史类型债务与本轮新增错误。
- `pyproject.toml` 和 `uv.lock` 保持可由 `uv` 解析。
- 不因历史类型债务停止当前实验。
