# R2 QUIC v4 突发与队列容量实现报告

## 结论

QUIC v4 的通用字节服务、三类字节账、实现级数据报上限、逐事件节奏收据、收集绑定、启动器模式和事件重放审计已完成本地实现。聚焦目标测试 3/3 通过，Python 编译与 Shell 语法检查通过。

当前代码候选已具备白名单同步条件，但**尚不具备正式三轮门禁启动资格**：旧分析文档仍把 `65,535` 错写为最大数据报，并把 80% 峰值写成硬门禁。正式运行前必须先由主代理修订预注册合同；本任务未启动任何 QUIC 连接、远程运行或 GPU 工作。

## 官方证据后的合同修订

- aioquic 1.3.0 的配置上限固定为 `1,200` 字节。
- quiche 0.24.5 的配置上限固定为 `1,350` 字节。
- `65,535` 只作为 UDP 接收调用缓冲大小记录，不再解释为合法 QUIC 数据报上限。
- 每方向 `2,097,152` 字节仍是工程硬容量。
- `1,677,721` 字节仅为 80% 诊断阈值，超过时记录诊断失败，但不单独判定运行失败。
- 待服务字节显式拆分为 `waiting_bytes` 与 `in_service_bytes`，传播阶段单独使用 `delay_inflight_bytes`。

## 修改文件

1. `thesis/experiments/llm_probe/scripts/r2_quic_udp_proxy.py`
   - 新增 v4 工作保守调度分支。
   - 每次准入前结算服务完成事件。
   - 记录等待、服务中、传播中三类字节账。
   - 记录服务开始、服务完成、计划释放、实际转发与滞后收据。
   - 支持实现级最大数据报与配置驱动的接收缓冲。
   - 80% 阈值只输出诊断，不参与容量准入。
2. `thesis/experiments/llm_probe/scripts/r2_quic_controlled_collect.py`
   - 绑定 aioquic `1200`、quiche `1350` 与 `65535` 接收缓冲。
   - 将 v4 参数写入障碍配置、代理命令、就绪收据和统计门禁。
   - 关停门禁检查三类字节账、包/字节守恒及零非预期丢弃。
3. `thesis/experiments/llm_probe/scripts/audit_r2_quic_determinism_gate.py`
   - 新增 `audit_v4_event_log`，从 JSONL 重放服务分类、容量准入、序列化积分、传播出队、峰值和守恒。
   - 80% 阈值输出 `queue_diagnostic_passed`，不作为硬失败条件。
   - 支持 v3/v4 启动器与摘要模式并存。
4. `thesis/experiments/llm_probe/scripts/run_r2_quic_controlled_collection.sh`
   - 根据配置写入 v3 或 v4 启动器模式，继续保留主管道与 `tee` 双退出码。
5. `thesis/experiments/llm_probe/configs/r2_quic_controlled_burst_capacity_v4.json`
   - 冻结三轮 aioquic 12、quiche 32、aioquic 12 身份。
   - 冻结实现级数据报、工程容量、诊断阈值和事件重放语义。
6. `thesis/experiments/llm_probe/tests/test_r2_quic_v4_contract.py`
   - 覆盖等容量准入、超一字节拒绝、传播阶段不占待服务容量、三类字节账、事件重放及冻结配置。
