# TQH-C2 v1.2.0 README 捷径与评价协议分析

## 结论

TQH-C2 作者明确警告，按流直接随机训练会利用采集环境捷径。地址和连接状态属于应排除的显式捷径；大小和时序字段不属于作者禁止字段，但在 A、B、D 上本来就接近完美可分，因此 pooled 域内高分缺少方法判别力。第三章不能把域内随机或捕获混合结果作为主要创新证据，必须以 C 困难域、A+B→C 或 A+B+D→C 分组外推、B↔D 受控协议迁移及间隔/抖动留出为主要评价面板。

## README 的直接证据

- 第 261—270 行：每个测试床的 C2 目的端是单一内部地址，良性目的端为外部地址；`orig_h` 和 `resp_h` 可以完美分离，必须删除。
- 第 272—275 行：B 的旧版本存在单向流和 `S0/OTH` 连接状态捷径；v1.1.0 已修复。v1.2.0 仍不应把连接状态作为主输入。
- 第 277—286 行：删除 IP 和连接状态后，仅用大小与时序特征的随机森林在 A、B、D 上仍约为 1.00，在 C 上约为 0.98。
- 第 288—300 行：B 与 D 虽只改变协议栈，但均可被大小和时序近完美分离；真正影响难度的是 C2 行为是否模仿良性分布，而不是协议或加密层本身。
- 第 302—309 行：作者建议逐测试床报告，并把 C 或 A/B→C 跨测试床迁移作为主要困难基准。

README 仍有版本文字滞后：总览继续写 3 个测试床、36 个单元，但 v1.2.0 实际增加 D，正式制品为 4 个测试床、48 个单元。实验以制品清单和 E0 审计为准。

## E1 首轮结果的正确解释

E1 使用的 7 个字段为：

- `duration`
- `orig_bytes`
- `resp_bytes`
- `orig_pkts`
- `resp_pkts`
- `orig_ip_bytes`
- `resp_ip_bytes`

这些字段没有包含作者明确禁止的 IP、`conn_state`、测试床身份、捕获身份、间隔、抖动或标签。因此首轮宏平均 F1 为 0.999618 不能直接判为标签泄漏。但是，它与作者报告的 A/B/D 大小时序近天花板现象一致，只能作为域内执行健全性结果，不能证明复杂模型或物理机制有效。

## 修正后的 E1 裁决协议

1. 逐测试床报告 A、B、C、D，不使用 pooled F1 代替困难组结果。
2. 主困难域执行 A+B→C 和 A+B+D→C，全部按捕获单元整组迁移。
3. B→D 和 D→B 只作为同 Merlin 框架下的受控协议栈迁移，不称为普遍跨加密。
4. 执行四个测试床逐一留出、7 个单字段和7 个逐字段去除审计，确认模型依赖的具体大小或时序捷径。
5. 最终测试继续不分配、不读取；当前诊断只使用开发区。
6. 若 C、A+B→C、A+B+D→C 和 B↔D 的共同预算强基线全部进入统计不可区分的天花板，则停止扩展复杂检测机制，不削弱基线或修改样本制造提升。

## 第三章论证方式

加密恶意流量论文通常从多个彼此独立的证据轴论证创新：

- 与随机森林、梯度提升、支持向量机、卷积或循环网络等强基线比较域内性能；
- 按恶意家族、捕获、时间、场景或数据来源整组留出，验证未知或分布偏移；
- 使用可实际落实到报文或 C2 行为的对抗修改，区分特征空间攻击和真实攻击；
- 删除关键表示、上下文、交互结构、序列或增量模块，验证机制消融；
- 在固定低误报工作点报告召回、外部误报和校准，而不是只报告准确率；
- 报告长时间运行、吞吐、延迟、内存和攻击者开销；
- 对持续学习报告旧类保持、新类适应和全量训练上界。

本课题应把创新性集中在：有界物理条件专家是否在 C 与分组外推面板上提高宏平均 F1 和最差组 F1，同时保持良性误报、校准和推理成本；真实物理旁路还必须优于置换与随机旁路。域内 pooled 结果只放入健全性表，不承担主要创新主张。
