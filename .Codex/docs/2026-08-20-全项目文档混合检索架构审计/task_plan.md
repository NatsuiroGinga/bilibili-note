# 全项目文档混合检索架构审计计划

## 目标

在不修改生产代码、知识库和实验的前提下，判断现有本地混合文献检索扩展到当前项目全部文档时所需的架构调整，并给出可验证的分级实施建议。

## 边界

- 只读审计当前工作树的源码、配置、技能、既有计划与报告。
- 机械盘点 `.Codex/docs`、`wiki`、`thesis`、`output`、`Research`、根目录及其他实际文档。
- 不索引或读取凭据、原始二进制、大型缓存、`runs` 与历史归档正文。
- 只修改并提交本审计目录中的三份 Markdown 文档。

## 阶段

- [x] 阶段一：读取根规则、局部规则与适用技能，建立审计计划。
- [x] 阶段二：定位并读取混合检索计划、评估、优化、P0/P1 报告、源码与配置。
- [x] 阶段三：机械盘点文档数量、大小、类型、目录与潜在敏感面。
- [x] 阶段四：分析作用域、元数据、分块、排序、陈旧检测、权限与扩展阈值。
- [x] 阶段五：形成 P0/P1/P2 建议、最多三项立即实现建议及验证方案。
- [x] 阶段六：自检文档、核对计数与 Git 范围，提交独占目录。

## 必答问题

1. 默认查询是否应混排论文与过程文档？
2. 如何防止旧恢复卡和历史方案压过当前真源？
3. 查询接口如何明确 `scope`？
4. 现有 SQLite 与 NumPy 架构是否仍足够？
5. 规模达到什么条件时应启用近似最近邻索引或分库？

## 验收

- `架构建议.md` 覆盖任务要求的全部主题和五个必答问题。
- 所有规模数字都可由记录在 `notes.md` 的命令复核。
- 建议区分事实、推断与建议，并给出收益、成本、风险和验证。
- `git diff --cached --name-only` 只包含本审计目录。

## 决策

- 当前任务为只读架构审计，不调用构思技能改变冻结生产行为，也不运行真实索引构建。
- 盘点历史归档时只统计路径和元数据，不读取归档正文。

## 错误记录

- 读取 `scripts/AGENTS.md` 时发现该文件不存在；根规则仅要求“涉及 `scripts/` 时继续读其 `AGENTS.md`”，当前工作树无该局部规则，后续以根规则和实际存在的更近层规则为准。
