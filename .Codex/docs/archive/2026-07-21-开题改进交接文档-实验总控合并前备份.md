## 1. 当前结论

1. **研究对象固定**：研究同一个生成式恶意流量检测基座模型的训练方法，不再采用两个独立检测器串联，也不得转回传统分类器课题。
2. **第一创新点方向固定**：第三章采用 PINN，研究物理信息或物理一致性约束如何改善生成式基座的训练、泛化或少样本能力。实验只裁决连续状态、物理残差、辅助结构和约束优化机制，不再裁决是否采用 PINN。
3. **第二创新点承接第一创新点**：第四章沿用第三章的主基座、任务、数据协议和评价方法，解决困难样本、长尾攻击、未知攻击或训练计算低效问题。GRPO 只是候选实现，不是预设答案。
4. **主基座与跨基座验证顺序固定**：H1 和 M0 至 M5 使用 `Qwen/Qwen3-1.7B` 完成主机制裁决；只有最小有效 PINN 组合冻结后，才选取一个非 Qwen、1B 至 3B 的开放权重解码器执行跨基座验证。跨基座验证是第三章定稿前的必做证据，不是当前并行探索项。
5. **第一创新点会由实验收敛到具体内容**：按数据协议、基座裁决、数学有效性、M0 至 M5 机制消融、跨数据验证和章节冻结六个阶段推进，最终冻结算法名称、状态向量、核心残差、训练算法、理论命题、适用边界和贡献句。
6. **目前可以开始写第三章的稳定部分**：研究问题、任务定义、符号体系、基座与流量序列表示、PINN 基本原理、数据角色、防泄漏协议、评价指标和实验环境可以正式撰写。算法名称、最终公式、定理、引理和结果性贡献句暂不定稿。
7. **正式检测任务采用分层多分类**：一级保留良性/恶意检测，二级执行良性、暴力破解、拒绝服务三类家族分类，三级区分已见攻击子类并拒识未见攻击。二分类结果只作为安全基础指标，不再代表完整研究任务。

## 2. 强制研究边界

- 第三、四章最终都必须形成相对基础算法具有可验证机制增量的新算法；先做对照和消融，再命名，禁止直接重命名基础算法。
- 第一创新点不是“输入侧手工残差 + 分类损失”。PINN 约束必须作用于模型预测的可微连续状态，并对共享模型参数形成非零梯度。
- 第三章的具体组件尚未定稿。连续状态辅助头、多时间尺度残差、观测可靠性门控和自适应约束权重均需通过消融裁决。
- Stiefel-LoRA 和 mHC 只能在主 PINN 机制成立后作为训练稳定性补充消融，不能替代物理约束成为第一创新点。
- 公开数据集承担检测性能和跨域泛化证据；ns-3 承担物理真值和受控机制证据。两类证据不可相互替代。
- Mininet 当前暂缓，仅在 ns-3 和公开数据均证明候选约束有效后考虑真实协议栈补充验证。
- GPU 实验固定使用单块 RTX 5090 32GB，依赖和环境统一由 `uv` 管理。扩大模型前必须先证明小模型上的机制增益。
- 仅在 Qwen3-1.7B 上取得增益不能表述为模型可移植性。最终方法冻结后，必须在一个非 Qwen 的 1B 至 3B 解码器上至少复现监督基线、状态辅助和最终 PINN 方法；数据划分、序列表示、物理公式、主要损失权重和评价协议保持一致，只允许调整批量大小等硬件适配参数。
- 所有正式运行必须使用 SwanLab 在线模式，保存完整日志与本地制品，并在云端接口和图表页双重验收。
- 服务器地址、密码、令牌和其他凭据不得写入仓库、配置、文档或实验清单。

### 分层多分类任务协议

1. 一级任务输出 `benign` 或 `malicious`，用于计算恶意召回率和误报率。
2. 二级任务输出 `benign`、`bruteforce` 或 `dos`，作为当前 GeNIS 主多分类任务。
3. 三级已见子类为 `ftp`、`smb`、`ssh`、`hulk`、`slowloris`，良性统一为 `benign`；`icmp`、`pushack`、`udp` 不进入训练，专门检验未知攻击拒识。
4. 未知攻击不是一个可直接用测试样本监督训练的普通类别。拒识阈值只能用域内验证集校准，域外测试标签不得用于调参。
5. 正式生成结果采用分层 JSON，至少包含一级检测、攻击家族、攻击子类和是否拒识；评价同时报告一级指标、家族宏平均 F1、已见子类宏平均 F1、未知攻击召回率及混合域外误报率。

## 5. 第一创新点当前方法骨架

以下内容是待实验裁决的**候选骨架**，不是已定稿算法：

1. 把独立流记录组织为保持时间顺序的多粒度窗口序列。
2. 由生成式基座的共享表示同时驱动分类输出和连续网络状态辅助头。
3. 使用 ns-3 的队列、到达、离开、丢弃和链路容量真值监督状态头，并构造离散守恒残差。
4. 在公开数据缺少物理真值时，使用显式观测掩码或可靠性门控，不得把缺失量静默填零。
5. 比较固定权重与自适应约束权重，检查分类目标、状态拟合和物理残差的梯度方向与尺度。
6. 用正常高负载、容量突变、随机丢包和攻击流量做受控反例，防止把所有高负载都判成攻击。

该骨架只有通过 M0 至 M5 和跨数据验证后，才能转化为正式算法名称、公式与贡献句。

## 7. PINN 公式与理论纪律

1. 设计状态、控制方程、边界条件或残差前，必须回读 `raw/papers/pinn/`、`wiki/papers/pinn/` 和相关攻击检测论文。
2. 可使用 Consensus、Scite、Sider Scholar 等工具发现论文与引文链，但最终结论必须回到原始论文、出版社全文或本地全文核验。
3. 公认守恒律可以作为有引用的理论起点；方法公式必须针对恶意流量的可观测性、时间尺度和生成模型梯度路径进行实质性重构。
4. 禁止照抄论文公式，禁止只替换符号、改下标、增加常数权重或机械拼接损失后宣称创新。
5. 每个候选公式必须记录来源语义、原公式不适用原因、本课题实质修改、变量可观测性、量纲、归一化、梯度路径、极端条件、数值测试和对应消融。
6. 只由输入字段计算、对模型参数梯度为零的常数残差不得称为 PINN；将其作为 GRPO 同组常数奖励还可能被中心化抵消。
7. C 阶段必须建立 `.Codex/docs/PINN公式证据台账.md`。未通过量纲、非零梯度、极端条件和数值单元测试的公式不得进入 GPU 实验或论文正文。

## 8. 第三、四章编排

- **第一章 绪论**：恶意流量大模型训练问题、研究现状和贡献框架。
- **第二章 相关技术与数据基础**：生成式基座、流量序列表示、PINN、课程或强化训练、数据集和评价协议。
- **第三章 第一创新点**：面向恶意流量检测的物理一致性约束训练方法。组织顺序为引言、问题与威胁模型、任务形式化、总体框架、连续状态与物理残差、可靠性或约束优化机制、训练算法、理论分析、综合与消融实验、跨基座可移植性实验、本章小结。
- **第四章 第二创新点**：面向困难与未知攻击的计算预算感知自适应训练方法。以第三章模型为起点，从奖励均值与方差、输出合法率、损失或梯度等真实训练信号诊断困难样本，再比较固定预算、可微课程、RLOO、GRPO 或其他策略。
- **第五章**：原型系统或工程验证。
- **第六章**：总结与展望。

第三、四章必须使用同一个主要基座和同一个恶意流量检测任务，分别证明独立增益，再验证组合效果。第四章只能解决第三章尚未解决或新引出的可测量问题，不能另起一个无关模型。

朱焱雷论文只用于工作量和组织参照：其第三章约 26 页，含 33 个编号公式、1 个算法、2 个定理、1 个引理、11 幅图和 7 张表。本课题参照的是“单章单问题、章内机制协同、理论与实验共同支撑”的论证完整度，不机械复制公式、图表、方法或篇幅。
