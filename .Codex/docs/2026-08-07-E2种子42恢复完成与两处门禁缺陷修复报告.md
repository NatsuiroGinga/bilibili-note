# E2 种子 42 恢复完成与两处门禁缺陷修复报告

## 结论

E2-A/S/P/X 种子 42 已在服务器全部完成 `200` 优化步，结果有效，裁决为「进入唯一一次 E4」，详见[E2-A/S/P/X 种子 42 路线裁决](2026-08-07-E2-ASPX种子42路线裁决.md)。

## 缺陷一：历史启动器证据的 schema 漂移

### 触发条件

`scripts/run_e2_hard_domain.sh` 在原始 formal 运行之后新增了 `binding.txt` 的 `mode=` 行；恢复门禁 `_legacy_zero_step_tracking_failure` 用当前五键集合做全等比较。

### 已确认根因

种子 42 原始 formal 启动器 `runs/launchers/e2-hard-domain-e2_hard_domain_seed42-20260807T051339Z-1971/binding.txt` 实际只有 `config`、`output`、`screen`、`run_id` 四键，共 `181` 字节，`sha256=618f3acf64f7282153c277d66d7e5c7a323b08ed2238208f3931da4ac7bf440b`；写它的 wrapper 版本为 `code-config.sha256` 中记录的 `2bbdda64…`。全等比较必然返回 `False`，随后根 `failure.json` 已被上一次恢复覆盖为 `unsafe_zero_step_recovery`，主路径也无法证明 `401`，于是抛出 `unsafe_zero_step_recovery`。

已排除的相近原因：`launcher.log` 证据本身完好——`3181` 字节、`sha256=9539b2e224cf963b19baf2b664cda3a9c02801c8023c6c1aac7f2f0443336863`，其中恰有 `1` 条 JSON 记录同时满足 `status=failed`、`code=unhandled_exception`、含 `unauthorized`、`_swanlablogger`、`swanlab.init`，四项条件全部成立。

### 修复

`src/flow_probe/e2_hard_domain_train.py`：

- 对历史证据只强制必需键子集 `{config, output, screen, run_id}` 并限制允许集合为其加 `mode`；
- `mode` 缺失时取安全默认 `formal`，存在时仍强制等于 `formal`；
- 新增 `FORMAL_LAUNCHER_PREFIX` 常量并断言原 formal 启动器目录名不以 `e2-hard-domain-resume-` 开头，由目录命名承担 `mode` 缺失时的 formal 身份判定。

### 验证

先把服务器上的真实 `binding.txt` 与 `launcher.log` 以 base64 取回本机，核对解码后 `sha256` 与远端 `sha256sum` 逐字节一致，再据其真实四键形态编写具名参数化回归用例 `legacy_four_key_binding`，与 `current_five_key_binding` 并列长期保留；另加 `mode=resume` 的否定用例。

## 缺陷二：制品枚举未关闭忽略规则

### 触发条件

`validate_completed_output` 用 `rg --files --hidden` 枚举 `swanlog` 与 `checkpoints`。

### 已确认根因

`variants/*/swanlog/.gitignore` 内容为 `*`，且服务端项目根 `git rev-parse --is-inside-work-tree` 为 `true`，忽略规则生效。实测每变体 `swanlog` 默认枚举 `0` 个文件、`--no-ignore` 枚举 `6` 个文件；`checkpoints` 目录因无 `.gitignore` 默认枚举 `10` 个文件，属侥幸未触发。

### 修复

`scripts/run_e2_hard_domain.sh` 的两条枚举语句加入 `--no-ignore`，并新增测试 `test_output_validation_enumerates_artifacts_without_ignore_rules`，断言脚本内所有 `rg --files` 语句都含 `--no-ignore`。

### 复发分析与规则修正

该规则在故障手册中**已经存在**，仍然复发，原因有二，均已修正：

1. 规则被挂在 `## SwanLab` 子节下，而 `thesis/experiments/llm_probe/AGENTS.md` 的手册路由触发词只有「SwanLab 故障」等十项，不含「制品枚举」。违规发生在编写任意包装器的后置验收时，此时不会被路由读到。现已把该节提升为独立章节「制品枚举与忽略规则」，并在路由触发词中加入「制品枚举」「恢复门禁」及一条显式前置读取要求。
2. 规则只有散文、没有可执行断言，第一次修复（DistilBERT 启动器）只改了当时报错的那一行，同一文件 `run_e2_distilbert_formal.sh:70,73` 至今仍未加 `--no-ignore`。现已加入脚本级断言测试。

全仓扫描 `rg -n --no-ignore "rg --files" scripts/ src/` 发现的其余同类潜伏点已列入故障手册，需逐个核验语义后处理：`run_shared_b0_physics_baselines.sh:220`、`run_e2_distilbert_formal.sh:70,73`、`run_e2_seed42_baseline.sh:116`、`run_shared_b0_distilbert.sh:120`、`archive_r2_minimal_physics_fit_failure.sh:39`、`archive_r2_physics_fit_checkpoint_for_rebind.sh:53`。
