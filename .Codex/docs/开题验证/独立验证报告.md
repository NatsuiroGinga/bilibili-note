# 开题方案与初步实验独立验证报告

- **验证日期**：2026-07-16
- **验证对象**：CI-PRD、PIC-GRPO、两级架构及 `thesis/experiments/` 中 v1-v8 初步实验
- **验证方式**：理论审查、源码逐行审查、关键实验复现、数据与官方修订资料交叉核验
- **原始材料边界**：未修改 `raw/`、论文正文和实验源码

## 一、结论

**当前结果不足以证明 CI-PRD、PIC-GRPO 或两级架构有效。**

更准确的状态是：

1. **I2 单向度是一个对特定攻击有用的流量特征，证据等级 C。**它在 IDS2018 的 HOIC/LOIC-UDP 日表现出较强关联，但同一阈值跨日正常流误报从 0.6% 上升到 33.7%-35.5%，不能称为稳定守恒不变量。
2. **v7 证明了合成连续场上的 PINN 残差机制可以跑通，证据等级 C。**MPS 可复现 3.6 倍近区残差，但 CPU 只有 2.4 倍且未通过脚本自己的三倍判据，结果对计算后端敏感，且检测区域使用了已知注入位置。
3. **v8 反证了当前 PINN 不能处理离散网络拓扑。**CPU 与 MPS 的近区/远区残差均约 0.9 倍，与脚本定义 I1 差值的相关系数为 -0.021/-0.023。
4. **当前 I1 实验测到的是受害端流量体积，不是质量守恒被破坏。**核心转发节点在正常和 DDoS 时的差值都为 0；服务端作为流量汇，本来就有入流大于出流。
5. **v6 的“物理约束提升 33%”无效。**代码梯度不对应声明的损失函数，实验又存在日期域偏移、错误标签、单次运行和近 70% 误报，不能支持 OOD 泛化结论。
6. **PIC-GRPO 证据等级 D。**目前只有提纲，没有实现、训练日志、检查点、结果或消融；残差奖励还存在循环验证问题。
7. **“小样本优势”“跨集泛化”“毫秒级”“过滤 90% 良性流量”均未验证。**这些表述应从当前结论中删除或明确标成研究目标。

这不等于研究方向已经被否决。可保留的核心假设是：**协议/统计先验可能帮助检测特定攻击，图上的正常流量动力学残差可能为异常检测提供辅助信号。**但需要重新定义 I1、修正实验设计，并完成真正的图结构模型和 PIC-GRPO 小规模闭环实验。

## 三、关键问题

### P0-1：I1 的物理解释错误

现有离散式只减去丢包和队列变化，没有包含端系统的本地流量产生与应用交付。对节点应至少满足：

$$
\Delta Q_v = B_{in}+B_{local\_generated}-B_{out}-B_{local\_delivered}-B_{drop}.
$$

转发节点在 DDoS 下仍应满足守恒，只是通量、队列或丢包发生变化。受害服务端是合法流量汇，`bytesIn-bytesOut` 增大不能解释为质量守恒被破坏。

源码证据：

- `ns3_testbed.cc` 把 I1 定义为 `|bytesIn-bytesOut|`，未记录本地生成、应用交付和队列变化。
- 数据中核心节点 `x=0.5` 在 `t=3` 与 `t=7` 的差值均为 0，说明 DDoS 流量通过核心节点时没有破坏守恒。
- 服务端 `x=0.7` 的差值从约 8.6M 增至 26.8M，与接收流量同步增长，说明它主要是体积代理量。

**裁决**：必须重写 I1 理论和测试床采集。异常目标应改为未知源汇、队列/丢包动力学或偏离正常条件模型的创新残差，而不是原始入出差。

### P0-2：v6 的损失梯度实现错误

脚本声明：

$$
L_{constraint}=\lambda\max(0,v-p),\quad p=\sigma(z).
$$

当 $v>p$ 时，正确的 $\partial L/\partial z$ 应为 $-\lambda p(1-p)$。代码直接把 `-lambda/n` 加到 `grad_z`，漏掉了 $p(1-p)$，因此实际优化过程不对应文档公式。

此外，该项直接要求“不变量违反度高时提高攻击概率”，本质更接近弱标签正则，不是让预测流量场满足物理方程的 PINN 约束。

**裁决**：v6 的 0.343 对 0.257 结果不能使用。修正公式后必须重新训练、调参并设置独立验证集。

### P0-3：v5/v6 的 OOD 测试受到错误标签和域混杂影响

v5/v6 训练于 2 月 21 日 DDoS，测试于 2 月 14 日 FTP/SSH。这个设计同时改变攻击类型、日期、正常流量分布和服务协议，不能把差异单独归因于“未见攻击泛化”。

更严重的是，[Liu 等 2022 年独立复核](https://intrusion-detection.distrinet-research.be/CNS2022/index.html)指出 2 月 14 日 FTP Patator 的目标端口关闭，攻击者没有机会执行凭证暴力破解，相关流应标为尝试失败。v5 随机抽取的 15000 个攻击样本中有 7687 个 FTP 流，占 51.2%。硬阈值的高分因此大量来自失败连接的单向特征。

**裁决**：0.723 的硬阈值 F1 和 v6 的相对提升均不能作为 OOD 证据。至少应换用修订标签，并做“同日留攻击类型”“跨日同攻击类型”“跨数据集”三个分开的协议。

### P0-4：两个创新点尚未形成完整实现

- CI-PRD 没有图结构 PINN，没有 I1-I4 联合可微模型，没有训练/验证/测试协议，也没有盲测阈值。
- PIC-GRPO 没有任何可运行实现和实验产物。

**裁决**：当前开题中只能写“拟提出”和“计划验证”，不能写“已验证”“实验背书”或“形成互补分工”。

### P1-1：v4 没有验证正确攻击目标

恢复的 PCAP 主机为：

- `172.31.64.46`
- `172.31.68.6`
- `172.31.68.8`

[CSE-CIC-IDS2018 修订说明](https://intrusion-detection.distrinet-research.be/CNS2022/CSECICIDS2018.html)给出的 GoldenEye 和 Slowloris 受害主机均为 `172.31.69.25`。现有 PCAP 不包含正确目标主机。

按官方攻击时段重新分组后，两个长 PCAP 的非攻击时段仍分别有 51 和 101 个 `I3>50%` 窗口。高比例窗口还常由 1-5 个 SYN 构成，分母过小。

**裁决**：v4 只能支持“脚本可计算该统计量”，不能支持“暴露了攻击异常”。

### P1-2：I2 不是普适守恒不变量

正常协议天然可能高度不对称，例如软件下载、视频传输、备份上传、DNS 查询和遥测上报。固定 `[0.05,0.95]` 区间只是在检测极端单向流。

复现结果说明同一阈值对正常流不稳定：

| 日期       | 正常流误报率 |
| ---------- | -----------: |
| 2 月 21 日 |         0.6% |
| 2 月 14 日 |        33.7% |
| 2 月 15 日 |        35.5% |

**裁决**：应将 I2 改名为“协议条件化双向不对称残差”，按协议、端口、客户端/服务端角色和业务基线估计区间。

### P1-3：Slowloris 不应映射到未完成 TCP 握手

[修订数据说明](https://intrusion-detection.distrinet-research.be/CNS2022/CSECICIDS2018.html)确认 Slowloris 在建立连接后持续发送不完整 HTTP 请求并保持连接。它主要破坏应用层资源与请求完成性，不等同于 SYN flood。

**裁决**：I3 可覆盖 SYN flood 和连接建立异常，但不能把 Slowloris 作为主要目标。Slowloris 需要 HTTP 请求进度、连接驻留时间、并发连接数或服务器资源指标。

### P1-4：v7 是机制演示，不是检测实验

v7 的数据生成、近区定义和阈值都知道注入点 `(0.7,0.5)`。没有无攻击对照、未知位置注入、噪声、多个攻击强度、多随机种子、阈值验证集或定位误差指标。

复现结果：

| 后端 | 近区残差 | 远区残差 | 倍数 | 脚本判定 |
| ---- | -------: | -------: | ---: | -------- |
| CPU  |   0.1665 |   0.0692 |  2.4 | 失败     |
| MPS  |   0.2103 |   0.0589 |  3.6 | 成功     |

**裁决**：允许写“自动微分和残差计算机制已跑通”，不允许写“成功检测 DDoS 注入”。

### P1-5：PIC-GRPO 的难度与奖励定义存在循环

- 当前公式把物理残差幅度称为 $\sigma^2_{phy}$，但没有说明方差针对样本、时间、模型还是重复生成计算。
- 残差越大通常表示异常越明显，未必表示样本越难；真正的灰区难度更可能与阈值距离、模型不确定性或多检测器分歧相关。
- 用 CI-PRD 残差超阈作为“可验证奖励”，只能验证输出与第一级一致，不能验证攻击类型、证据链和语义推理正确性。
- 第一级的误报会被奖励机制固化到第二级，形成循环确认。

**裁决**：物理残差可作为课程特征或证据之一，不能单独作为语义正确性奖励。奖励至少需要真实标签、可执行规则、攻击场景约束或外部工具校验。

### P1-6：没有有效统计推断

现有实验没有同时满足以下条件：

- 预注册主指标和阈值；
- 独立训练、验证、测试划分；
- 按攻击场景、时间段或主机分组，避免把相关流当独立样本；
- 多随机种子或重复测试床运行；
- 置信区间、效应量和多重比较控制；
- 与可比较基线的相同数据、相同预算评测。

因此当前所有百分比只能作为描述性结果，不能使用“显著提升”措辞。

## 五、文档一致性问题

1. README 将 ns-3 仿真数据称为“真实数据”，应改为“可控仿真测试床数据”。
2. README 写 7 节点乘 20 窗口，实际 CSV 为 7 节点乘 19 时间步，共 133 行。
3. `rho=bytesIn/DELTA` 的单位是字节每秒，不是“字节/0.5秒”。
4. README 写 v7 为 3.6 倍成功，但未说明 CPU 为 2.4 倍失败，缺少后端可复现性边界。
5. 方法章仍把 v6 写成物理约束有效证据，必须撤回。
6. 方法章把 v4 标为待办，而 README 和交接文档称已完成，状态不一致。
7. 交接文档写“方案 B + 两级分工，实验背书”，证据强度过高。

## 六、最小重做方案

### P0：先修理论和数据

1. 将 I1 改为包含本地注入、应用交付、丢包和队列变化的完整节点平衡式。
2. 只在转发节点计算守恒残差；对端系统单独建模源汇强度，不再把 `|in-out|` 当守恒破坏。
3. 使用 Liu 等发布的修订 IDS2018 标签，排除 `Attempted`、启动/停止伪影和错误协议流。
4. 获取正确受害主机 `172.31.69.25` 的 PCAP；若无法获得，撤销 v4 攻击验证结论。

### P1：完成 CI-PRD 最小可信实验

1. 建立图结构模型：节点为路由器/交换机，边为链路，输入为 per-port 通量、队列和丢包。
2. 正常数据训练；攻击数据仅用于验证和测试，避免模型在训练时同时拟合攻击又压低残差。
3. 采用按场景分组的训练/验证/测试划分，并增加无攻击、突发合法流量、链路拥塞和故障反例。
4. 基线至少包括流量阈值、孤立森林、逻辑回归、梯度提升树、图自编码器和无物理约束模型。
5. 每个配置运行至少 5 个随机种子或 5 次独立仿真，报告均值、标准差、95% 置信区间和效应量。
6. 主指标采用精确率-召回率曲线下面积、宏平均 F1、误报率和检测延迟；阈值只在验证集选择。

### P1：完成 PIC-GRPO 最小闭环

1. 先构造 500-2000 条灰区样本的小规模数据集，明确输入、攻击标签、证据和可执行校验规则。
2. 把难度定义为阈值距离、模型不确定性和奖励历史，而不是直接把残差幅度当难度。
3. 奖励拆成标签正确性、证据字段一致性、规则校验、格式合规和残差一致性；残差奖励不得主导。
4. 对比标准 GRPO、RCS、仅课程、仅残差奖励和完整 PIC-GRPO。
5. 报告奖励作弊率、语义准确率、宏平均 F1、训练样本效率与计算成本。

## 七、当前可安全写入开题的结论

建议暂时只保留下面三句话：

> 初步探索表明，前后向字节极端不对称与 CSE-CIC-IDS2018 中部分单向洪泛流量存在关联，但该特征的正常基线具有明显跨日漂移，尚不能作为普适守恒不变量。

> 在一维合成连续场上，基于自动微分的连续性方程残差能够对局部注入产生响应；该结果目前仅验证计算机制，尚未证明真实离散网络拓扑上的检测有效性。

> 基于物理残差的课程式 GRPO 目前属于待实现和待验证的方法设想，其难度定义、奖励正确性与跨级误差传播仍需通过对照实验检验。
