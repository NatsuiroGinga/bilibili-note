# AGENTS.md 规则钩子化审计

日期：2026-07-30

## 结论

当前四层规则不能整体迁入生命周期钩子（Hook）。最合适的分工是：Hook 负责在受支持的工具调用前阻止绕过，仓库包装器和静态检查负责确定性验证，独立文档或项目技能承载长流程，`AGENTS.md` 只保留需要模型持续判断的研究边界、授权边界、恢复顺序和证据纪律。

当前字节基线为：

| 活动链或文件 | 字节数 | 默认 32,768 字节下余量 |
| --- | ---: | ---: |
| 根 `AGENTS.md` | 8,035 | 不单独计算 |
| `thesis/AGENTS.md` | 6,202 | 不单独计算 |
| `llm_probe/AGENTS.md` | 16,456 | 不单独计算 |
| `llm_probe` 三层活动链 | 30,693 | 2,075 |
| `scripts/AGENTS.md` | 1,641 | 不单独计算 |
| `scripts` 四层活动链 | 32,334 | 434 |

在保留必要短路由和语义门禁的前提下，机械规则与长流程后续具备约 **8,000 至 11,000 字节**的净迁移潜力。该范围不是本轮已实现收益，也不能把下表各行直接相加；正式收益必须以逐阶段差异重新计算。`remote-script-execution-contract.md` 另有 6,857 字节，它当前不在默认活动链中，因此迁入包装器不会减少启动上下文，但可使“只运行已验证入口”的任务不再需要加载整份合同。

本轮只完成审计。未修改任何 `AGENTS.md`、Hook、配置、包装器、实验代码或运行状态，也未进入既有治理 P2 及以后阶段。

## 分类口径

| 分类 | 含义 | 适用边界 |
| --- | --- | --- |
| A | 可由 Codex 官方原生机制在生命周期内强制 | 主要是项目级 `PreToolUse`、`Stop`、`SessionStart`、`PreCompact` 和 `.rules`；只覆盖官方列明的工具路径和受信任、未禁用的 Hook |
| B | 可由仓库包装器、预检脚本、模式校验、测试或静态检查近似强制 | 适合命令、路径、状态、哈希、清单、格式和退出码；调用方仍可能绕过入口，因此通常与 A 的入口阻断组合 |
| C | 只能按需路由到独立文档、项目技能、配置或历史记录 | 适合长流程、当前状态、故障背景和低频操作；模型选择技能不等同于强制执行 |
| D | 必须常驻 `AGENTS.md` | 需要模型在生成答案、解释证据、作出科学裁决或判断用户授权时持续遵守，不能由确定性程序完整判断 |

同一原规则可能含有两层职责。例如“凭据不得写入仓库”中的明文模式可由 A/B 检查，但“任何形式的凭据都不得进入说明和结论”仍属于 D。表中以主分类为准，并明确必须保留的 D 摘要。

## 官方机制核验

本次先按 `openai-docs` 流程运行 Codex 手册获取器，但网络域名解析失败；随后使用 OpenAI 官方文档页面核验。依据截至 2026-07-30 的官方说明：

- Codex 可从 `~/.codex/hooks.json`、用户配置、`<repo>/.codex/hooks.json` 或项目配置加载 Hook。项目 Hook 只在仓库受信任时加载；非托管 Hook 必须按精确哈希审查和信任，定义变化后会重新进入待审查状态。[官方 Hook 文档](https://learn.chatgpt.com/docs/hooks)
- 当前真正执行的处理器只有 `type: "command"`；`prompt` 和 `agent` 处理器虽可解析但会被跳过。不能照搬 Claude Code 的提示型 Hook。[官方 Hook 文档](https://learn.chatgpt.com/docs/hooks)
- `PreToolUse` 可检查并拒绝 Shell、统一执行工具、`apply_patch`、MCP 和多数本地函数工具；`spawn_agent` 也匹配 `Agent`。托管网页工具不经过该路径，部分专用工具可能选择绕过，因此 Hook 是防护栏，不是完整安全边界。[官方 Hook 工具覆盖](https://learn.chatgpt.com/docs/hooks)
- `SubagentStart` 已经发生在代理启动之后，`continue: false` 不能阻止启动。子代理命名必须在 `PreToolUse` 检查 `spawn_agent|Agent`，不能放在 `SubagentStart`。[官方 Hook 文档](https://learn.chatgpt.com/docs/hooks)
- `PreToolUse` 当前只支持 `systemMessage` 和专用的拒绝、放行或改写输出。若返回不支持的 `continue`、`stopReason` 或 `suppressOutput`，Codex 会把该 Hook 标记为失败并继续工具调用。[官方 Hook 输出](https://learn.chatgpt.com/docs/hooks)
- `PostToolUse` 无法撤销已发生的副作用；格式化和测试更适合由 `Stop` 触发确定性验证，或由包装器在交付入口执行。[官方 Hook 文档](https://learn.chatgpt.com/docs/hooks)
- 项目 `.rules` 可对确定的命令前缀设置 `allow`、`prompt` 或 `forbidden`，但不能承载研究边界、恢复协议或文档写回语义。[官方 Rules 文档](https://learn.chatgpt.com/docs/agent-configuration/rules)
- `AGENTS.md` 项目规则默认累计上限为 32 KiB，嵌套文件按启动工作目录发现；这仍是保留短路由的原因。[官方 AGENTS.md 文档](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

本地 `hook-development` 技能存在与当前官方行为不一致的内容，包括把提示型 Hook 作为推荐方案、使用 `.Codex/settings.json`、假定 `CLAUDE_ENV_FILE` 和旧事件字段。后续实现必须以当前官方 Hook 页面和实际 `codex-cli 0.144.5` 契约为准，不能以该技能示例为验收依据。旧的 `codex-hook-emulation` 只适用于原生 Hook 不可用时；当前仓库已经有原生 Hook，不应再增加一套人工仿真协议。

## 现有 Hook 审计

仓库已经存在 `.codex/hooks.json`、`server_launcher_guard.py` 和 `precompact_snapshot.py`，不是从零开始。

| 发现 | 影响 | 裁决 |
| --- | --- | --- |
| `server_launcher_guard.py` 的中性和拒绝输出都包含 `continue`、`suppressOutput` | 这些字段不受 `PreToolUse` 支持。按官方行为，该次 Hook 可能失败开放，拒绝结果不能视为已强制 | Hook-P0 必须做真实 Codex 集成反例；Hook-P1 首先修复输出契约，再谈扩展规则 |
| `.codex/hooks.json` 用 `python3 .codex/hooks/...` 相对路径 | 官方说明 Hook 命令以会话 `cwd` 执行。从 `llm_probe` 或 `scripts` 启动时，相对路径可能不存在 | Hook-P1 应从 Git 根解析脚本路径，并对根、`llm_probe`、`scripts` 三个启动目录做冒烟 |
| 当前远程守卫只检查 `source ~/.bashrc` 与 `nounset` 顺序 | 尚未检查统一启动器、字面量 `\\n`、直接 `rsync`、`--delete`、能力清单、日志父目录或管道状态 | 不能用现有 Hook 宣称远程合同已机械化 |
| `PreCompact` 已把活动计划摘要写入两份恢复文档 | 它提高恢复制品的新鲜度，但不会自动完成服务器实况核对，也不能裁决文档、日志和研究边界冲突 | 保留为 A/B 辅助；恢复入口、顺序和冲突优先级仍为 D |
| 现有单元测试只检查 Python 返回对象 | 测试没有证明 `/hooks` 已信任、匹配器实际命中、拒绝被 Codex 执行或子目录路径可用 | Hook-P0 必须增加运行时契约验证，不以单元测试通过代替集成证据 |
| 项目未发现 `.codex/config.toml` 或项目 `.rules` | 当前没有项目级命令前缀策略或结构化 Hook 配置叠加 | 后续如新增必须单独审查来源和优先级，不能假定已存在 |
