# R2 TCP v2 事件配对修复与正式重跑报告

## 结论

TCP v2 的固定 NewReno 事件级残差失败已完成最小修复。修复后的 11 项限定验证全部通过，随后以同一新源码锁从零重跑完整 512 项矩阵，结果为 512/512 成功、失败 0、复用 0，并形成 256/256 个严格 TCP/UDP 配对。

当前正式矩阵状态为 `review_pending`。在新的独立审查通过前，不将该矩阵物化为正式物理池，也不据此启动后续模型训练。

## 旧失败与根因

旧正式运行服务器根为：

`/root/autodl-tmp/thesis/experiments/llm_probe/runs/ns3-data/r2-protocol-dynamics-v2-formal-attempt3/`

旧 `matrix-state.json` 记录成功 501、科学合同失败 6、因分片遇错未运行 5。六个失败索引为 `461`、`470`、`475`、`486`、`502`、`508`；五个未运行索引为 `485`、`494`、`499`、`509`、`510`。失败均发生在 TCP RTO 路径，ACK 残差为零，固定 NewReno 损失残差非零。

根因是阈值候选创建时只保存了阈值，没有冻结同一事件的 `bytes_in_flight_before_loss`。到 `CA_LOSS`、`CA_RECOVERY` 或 `Retransmission` 消费候选时，当前 `BytesInFlight` 已变化为 0 或 1 个 MSS，导致阈值与在途字节来自不同事件时刻。该问题不是 `1e-18` 容差、单位或 NewReno 方程错误。
