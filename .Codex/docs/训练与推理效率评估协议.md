# 训练与推理效率评估协议

> 状态：实验前协议，2026-07-17。阈值用于筛除明显不经济的候选方案，不代表实验结论。

## 1. 结论

基座、第一创新点和第二创新点均按“检测效果—训练成本—推理成本”三类证据共同裁决。不能只选宏平均 F1 最高的方案，也不能把所有指标任意加权成一个总分。正式结论使用约束条件与帕累托前沿：

1. 先检查检测效果、未见攻击和跨数据集泛化是否达到最低要求；
2. 再排除训练或推理成本明显更高且没有额外效果的被支配方案；
3. 对剩余方案分别报告同预算性能和同性能成本；
4. 只有效果增益、机制消融和成本证据同时成立，候选方法才能写成正式创新点。

## 2. 朱焱雷论文提供的章节参照

[朱焱雷论文](../../raw/papers/attack-detection/朱焱雷.pdf)第四章将第三章高强度对抗训练产生的计算开销直接定义为第二创新点的问题，而不是在实验末尾附带报告耗时。

其论证结构包括：

- 用前向、反向与多步扰动生成次数建立训练成本模型；
- 将鲁棒性最大化写成受计算预算约束的优化问题；
- 推导样本过滤比例与缓存周期对应的理论加速比；
- 报告单轮耗时、总训练耗时、加速比、峰值显存和耗时组成；
- 用性能—时间帕累托前沿比较不同方法；
- 对两个加速机制分别消融，并分析关键参数对精度和速度的影响。

论文报告 DF-ACR 相对 PGD-AT 约 4.6 倍训练加速，ET-BERT 训练峰值显存为 14.2 GB。需要注意，该章的强证据主要针对**训练效率**；它没有形成与训练实验同等完整的推理 P50/P95 延迟、在线吞吐率和单位流量成本评测。因此，本课题不能把“可部署”只等同于显存能装下模型，必须补充生成式检测模型的推理成本协议。

## 3. 成本边界

### 3.1 数据成本

记录以下指标：

- 原始下载体积与实际下载时间；
- 本地、传输中间件和 GPU 服务器上的占用空间；
- PCAP 到统一样本的 CPU 墙钟时间、峰值内存和输出体积；
- 上传服务器的数据量与传输时间；
- 损坏包、解析失败和重试比例。

数据下载或预处理成本不并入模型训练 GPU 小时，但必须单列，防止选择一个实验得分高却无法重复处理的数据集。

### 3.2 训练成本

每次运行至少记录：

- GPU 型号与数量；
- 墙钟时间与 GPU 小时；
- 峰值已分配显存和峰值保留显存；
- 可训练参数量与检查点体积；
- 训练样本数、输入令牌数、监督输出令牌数和在线生成令牌数；
- 每秒样本数、每秒训练令牌数和每秒生成令牌数；
- 达到预先指定验证集宏平均 F1 的步骤数与时间；
- 内存溢出、数值异常、中断和重试次数；
- 实验当日服务器每小时价格与实际租用成本。

强化学习实验必须额外记录每个样本的组内生成数、平均输出长度、有效优势组比例和零方差组比例。只报告训练步数而不报告生成令牌数，会掩盖固定组大小带来的真实成本。

### 3.3 推理成本

分别报告模型本体和端到端两组结果：

- 模型本体：从已经分词的输入张量到结构化结果；
- 端到端：从统一流量样本读取、序列化、分词到结构化结果；
- 若论文讨论实际 PCAP 部署，再增加从 PCAP 解析到检测结果的完整链路。

每组至少报告：

- 批量大小 1 的 P50、P95 与 P99 延迟；
- 一个不溢出且具有实际意义的批量大小下的吞吐率；
- 峰值显存与模型加载后常驻显存；
- 平均输入令牌数、输出令牌数和非法结构输出率；
- 每百万流量样本的估算 GPU 租用成本。

每百万样本推理租用成本按实际吞吐率计算：

\[
C_{\mathrm{1M}}
=\frac{10^6}{3600\,Q_{\mathrm{flow}}}\,p_{\mathrm{hour}},
\]

其中 \(Q_{\mathrm{flow}}\) 为每秒处理流量样本数，\(p_{\mathrm{hour}}\) 为实验当日同型号服务器小时价格。

## 4. 公平测量条件

- 所有主要方案在同一块 RTX 5090、相同驱动与训练框架版本上测量；
- 固定数据划分、随机种子、输入长度、输出结构和最大输出长度；
- 同预算比较时固定 GPU 小时或总生成令牌数，不固定可能代表不同实际成本的训练步数；
- 同性能比较时预先确定目标宏平均 F1，再比较达到目标所需时间；
- 推理先预热，再对固定测试集重复至少三轮；计时期间不包含模型首次下载；
- 批量大小 1 与吞吐批量分开报告，不用大批量吞吐掩盖单流高延迟；
- 失败运行也进入成本日志，不能只统计成功的最优运行；
- 若无法可靠读取功耗，则不估算能耗，不用额定功率乘时间冒充实测能耗。

## 5. 章节准入条件

### 5.1 基座模型

基座不按单一数据集最高分选择。优先保留同时满足以下条件的非支配方案：

- 三个主数据集上结构化输出合法率达到 95%；
- 宏平均 F1、未见攻击召回率和跨数据集平均秩没有明显短板；
- 3B 至 4B 模型能在 32 GB 显存内完成规定的 QLoRA 训练；
- 推理延迟与吞吐率满足后续重复实验预算。

如果两个基座效果置信区间重叠，选择 GPU 小时、峰值显存和推理延迟更低者，而不是选择参数量更大者。

### 5.2 第三章候选方法

第一创新点的物理一致性与可靠性调节应尽量只在训练期使用。正式保留需要同时满足：

- 至少两个主数据集及跨数据集测试稳定优于普通 QLoRA；
- 完整组合优于两个单机制变体；
- 训练 GPU 小时原则上不超过普通 QLoRA 的 1.5 倍，超过时必须有显著跨域收益作为理由；
- 推理不增加第二个模型或额外模型前向；
- 同一基座、相同输出约束下，P95 推理延迟相对 QLoRA 的稳定增幅不超过 10%。

### 5.3 第四章候选方法

第二创新点使用两类等价准入路径：

- **同预算路径**：固定 GPU 小时或总生成令牌数，困难、长尾、未见攻击或跨数据集性能显著提高；
- **同性能路径**：宏平均 F1 下降不超过预先设定的容许值时，GPU 小时至少下降 25%。

同时必须验证：

- 奖励均值—方差诊断优于只按低分筛选；
- 自适应组内生成数优于固定组内生成数；
- 已掌握、学习前沿和全错样本的更新路由各有可解释贡献；
- 监督课程、RLOO 与 GRPO 在相同预算下公平比较；
- 训练期预算分配不在推理期引入额外模型调用。

25% 是当前实验前筛选阈值。首轮探针完成后可以依据测量噪声调整，但不得看到完整结果后为保留某个方案而反向修改。

## 6. 第四章候选成本模型

设第 \(t\) 轮参与训练的样本数为 \(N_t\)，样本 \(i\) 的组内生成数为 \(K_i\)，输入长度为 \(L_i^x\)，输出长度为 \(L_{ij}^o\)。生成成本近似为：

\[
C_t
\approx
\sum_{i=1}^{N_t}\sum_{j=1}^{K_i}
\left(c_pL_i^x+c_dL_{ij}^o\right)
+C_{\mathrm{update}}.
\]

固定组大小基线令所有 \(K_i=K\)。候选方法先用小探测组估计奖励均值、方差和约束可靠性，再在总预算 \(B_t\) 下分配额外生成：

\[
\max_{\{K_i,a_i\}}
\sum_{i=1}^{N_t}U_i(K_i,a_i)
\quad
\mathrm{s.t.}\quad C_t\le B_t,
\]

其中 \(a_i\) 表示跳过、监督纠正、RLOO 或 GRPO 等更新路径，\(U_i\) 表示预计检测收益。实际形式必须由探针实验确定，当前不能把未知的收益函数写成已经证明有效的方法。

## 8. 当前执行顺序

1. 在本地完成数据最小样本、标签和统一序列化审计，不为下载大文件提前租用 GPU。
2. 用 1.7B 模型验证任务可学性、输出长度和推理协议。
3. 用固定小预算比较 3B 至 4B 基座，淘汰性能—成本被支配者。
4. 在入选基座上完成第三章四组消融与三个随机种子。
5. 只有第一创新点同时通过效果与成本门槛，才扩展到全部主数据集并开始第二创新点探针。
6. 租用价格只用于换算，不影响算法比较；核心比较量仍是 GPU 小时、令牌数、显存和吞吐率。

## 9. 实现边界

- 可缓存确定性的 PCAP 解析、流量序列化、分词结果和长度分组。
- 未经重要性修正，不复用旧策略生成的回答参与同策略强化学习更新。
- 不通过减少随机种子、消融组或跨数据集测试换取表面低成本。
- 不把 4 位量化、梯度检查点或通用推理引擎直接命名为论文创新；它们是统一工程配置，除非研究问题和实验能证明新的算法机制。
- 不让训练期可用的队列、拓扑或标签特权变量成为实际推理的必需输入。
