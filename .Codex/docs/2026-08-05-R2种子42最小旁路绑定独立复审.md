# R2 种子 42 最小旁路绑定独立复审

## 裁决

**不通过。严重问题 1，重要问题 3，次要问题 1。**

当前不允许把种子 42 物理拟合作为正式有效运行，也不允许独立启动 `F-A`。现有 v2 三份物理制品、物理角色清单、种子 42 配置和源码可以继续做白名单同步与远端静态准备；实际物理拟合及 `F-A/F-P/F-S` 训练必须暂停，直至严重和重要问题完成最小修复并重新复审。

本裁决不否定已经通过独立复审的 TCP/UDP v2 数据池。已只读确认物理角色清单、种子 42 拟合配置和三份 v2 Parquet 的当前 SHA-256 与既有报告一致，非自引用载荷 Merkle 也一致。阻断来自物理残差计算图和正式检查点证据链。

## 严重问题

### 1. TCP 残差存在可门控坍缩，且把拥塞避免公式错误地施加到全部窗口

- 文件：`thesis/experiments/llm_probe/src/flow_probe/r2_final_experts.py`
- 位置：第 365 至 383 行；零坍缩收据位于第 762 至 839 行。
- 根因：
  - `loss_gate` 和 `timeout_gate` 来自模型预测状态本身，再经 `clamp` 作为残差乘数。模型可把两者压到 0，直接关闭损失与超时方程，形成显式零残差流形。
  - `ack_balance` 在所有窗口都使用 `acked_bytes * MSS / cwnd_start` 的拥塞避免增长式，没有区分慢启动、正常拥塞避免、丢失恢复和重传超时窗口；发生拥塞窗口收缩时仍同时要求拥塞窗口按 ACK 增长，方程互相冲突。
  - `ssthresh_start`、`bytes_in_flight_end` 和 RTT 不进入固定残差。当前收据只验证一个构造样本的总残差范数与总梯度范数大于 0，不能证明每条方程不可坍缩，也不能证明关键终点状态均有梯度。
- 影响：TCP 物理损失不能被称为已闭合的发送者级 NewReno 固定残差；由该损失训练出的检查点不能进入正式物理拟合、`F-A`、`F-P` 或 `F-S` 证据链。
- 最小修复：
  1. 用停止梯度的已观测事件与阶段掩码选择慢启动、拥塞避免、损失和重传超时方程，不得用模型预测的事件计数自身开启或关闭残差。
  2. 将各阶段残差设为互斥或明确组合，避免同一丢失或超时窗口同时受到纯 ACK 增长约束。
  3. 若现有窗口真值不能支持事件时刻的在途字节或阶段判定，必须收窄为可证实的窗口近似合同，不得继续声明精确 NewReno 动力学。
  4. 零坍缩收据改为逐方程验证非平凡残差、逐关键预测终点状态验证非零梯度，并验证事件门不能由预测状态归零关闭。

## 重要问题

### 1. 检查点和不可变绑定清单未绑定实际实现源码

- 文件：`thesis/experiments/llm_probe/src/flow_probe/r2_final_physics_fit.py`
- 位置：第 1415 至 1440 行、第 1563 至 1589 行。
- 根因：`checkpoint_binding` 只记录配置语义摘要、拟合配置文件摘要、输入 Merkle、种子和模式；没有记录 `r2_final_experts.py`、`r2_final_physics_fit.py`、`r2_final_distilbert_probe.py` 及正式包装器的内容 SHA-256。
- 影响：相同配置和数据可由不同残差或训练实现生成检查点。探针加载时只能复算有限的零坍缩收据，无法证明训练检查点确由当前实现产生；尤其慢启动分段等修复可能保持构造收据数值不变，却改变真实训练语义。
- 最小修复：将上述实现文件及正式包装器 SHA-256 写入运行绑定、检查点内部绑定和不可变清单；探针必须在加载检查点前复核当前文件摘要与冻结摘要完全一致。

### 2. 中途检查点不能精确恢复，会改变正式训练预算

- 文件：`thesis/experiments/llm_probe/src/flow_probe/r2_final_physics_fit.py`
- 位置：第 1688 至 1708 行、第 1712 至 1749 行。
- 根因：检查点只保存 `epoch`、`step`、模型和优化器，不保存下一批位置、数据采样顺序以及 Python、NumPy、PyTorch CPU/CUDA 随机状态。周期检查点把当前 epoch 写回；恢复后从该 epoch 第一批重新训练。
- 影响：服务器中断后会重复已经完成的批次，改变优化步数、样本暴露次数和随机轨迹，违反三组共享冻结训练预算及远程可恢复运行合同。
- 最小修复：保存并恢复 `next_epoch`、`next_batch`、确定性采样器状态，以及 Python、NumPy、PyTorch CPU 和全部 CUDA 随机状态；恢复后必须从下一未完成批次继续，不能重放已完成批次。

### 3. `F-A/F-P/F-S` 的训练拟合检测视图没有本地可恢复副本

- 文件：
  - `thesis/experiments/llm_probe/configs/r2_final_distilbert_f-a_seed42.yaml`
  - `thesis/experiments/llm_probe/configs/r2_final_distilbert_f-p_seed42.yaml`
  - `thesis/experiments/llm_probe/configs/r2_final_distilbert_f-s_seed42.yaml`
- 位置：三个配置的 `data.detection_views.train-fit`。
- 根因：三组都引用 `runs/data-prepared/r2-final-sidecar-candidate-v1-server/detection-view-train-fit.parquet`，预期 SHA-256 为 `98224268bfeff83a710c9739ef8294624e379c094ac68e23337cb58f67692ae9`，但本地该路径不存在；启动报告的待同步白名单只列 v2 三份物理制品，没有列该检测视图。
- 影响：若当前服务器没有既有副本，`F-A` 会在数据哈希门禁前失败；若服务器存在而本地不存在，则服务器成为唯一副本，不符合恢复合同。该问题不阻止纯物理拟合读取 v2 三表，但阻止拟合后直接进入任何探针组。
- 最小修复：把精确 SHA-256 的训练拟合检测视图恢复到本地规范路径，并纳入明确的白名单同步与运行时摘要核验；不得从最终测试或其他视图替代。

## 次要问题

### 1. 三份探针配置回填是失败关闭的一致性门禁，不是真正的跨文件原子事务

- 文件：`thesis/experiments/llm_probe/src/flow_probe/r2_final_distilbert_probe.py`
- 位置：第 494 至 583 行；三份种子 42 配置的 `physics.checkpoint`。
- 根因：当前设计要求人工分别把三份 YAML 的 `ready`、检查点 SHA 和绑定清单 SHA 改为一致值。多个文件无法通过现有逻辑一次性发布。
- 影响：部分回填会被同种子一致性门禁拒绝，因此不会产生错误正式结果，但会造成启动竞态和操作失败。
- 最小修复：提供持久化回填脚本，在临时目录生成并核验三份配置，再以事务标记发布；正式入口只接受完整事务标记。现有逐文件一致性检查继续保留。

## `F-A` 独立启动裁决

**不能独立启动。**

1. 三份配置当前均为 `checkpoint.ready=false`，探针入口会直接拒绝。
2. `r2_final_distilbert_probe.py` 第 494 至 583 行要求冻结比较集合中的三份配置绑定同一检查点；只回填 `F-A` 会失败关闭。
3. `F-A` 的统一支路在 `r2_final_physics_fit.py` 第 1226 至 1235 行与路由支路一起训练，并包含当前有缺陷的 TCP/UDP 固定残差；它不能绕过本次 TCP 残差阻断。
4. 即使物理拟合完成，缺失的训练拟合检测视图仍会阻止 `F-A` 正式运行。
