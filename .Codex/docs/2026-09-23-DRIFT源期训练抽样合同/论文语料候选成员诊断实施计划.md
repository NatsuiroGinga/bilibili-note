# DRIFT 论文语料候选成员诊断实施计划

**历史目标：** 在不物化数据、不启动模型训练的前提下，从原始 DRIFT 官方角色生成可复算的“年份×类别×用途”固定行位置候选样本，并输出覆盖、交集、成员根和资源收据，为冻结第三章论文训练／验证／测试语料提供真实数据证据。

## 状态更正（2026-09-23）

本文以下“固定行位置／按选中位置读取”方案仅是**已完成的元数据阶段设计快照**，未执行真实数据扫描，且不得作为当前审计的启动、运行或验收语义。用户后来授权的唯一待运行语义以[《全量流式候选审计实施简报》](./全量流式候选审计实施简报.md)为准：对每个角色按 exact eSLD 去重，以 `SHA256(length_prefix_encode(data_revision, corpus_namespace, exact_esld))` 选取哈希最小的 `count` 个唯一实体，并用两遍全量只读流式扫描分别完成候选选择和选中实体重复／标签核验。

本次在真实扫描启动前发现旧快照与现行实现不一致，因此暂停启动并先修正文档。该事实是**合同不一致，实验未启动**，不是候选结果、资源结果或方法效果。

## 边界

- 本章主问题是离散规避攻击下的低误报 DGA 鲁棒训练；本工具只选择共同论文语料，不评价方法效果。
- 固定原始角色：源训练池为T17–T19 `train+test`，源验证池为T17–T19 `val`，逐年测试池为T20–T25目标角色。
- 每个角色的成员位置由 `SHA256(length_prefix_encode(data_revision, corpus_namespace, purpose, role, row_index))` 的计数器无偏采样生成；不接受 `member_seed`、模型分数、目标标签结果或文件行序前缀。
- 行位置均匀抽样保证的是**行级**固定样本；工具须对已选成员做跨用途／跨角色 exact eSLD 重合与标签冲突审计，不把未扫描总体的实体唯一性写成已证明。
- 只输出 JSON／JSONL 聚合收据与根摘要；不得写域名、成员清单、Parquet 副本、缓存、索引、模型或攻击数据。
- 具体样本数不在工具中硬编码。诊断配置的候选数量是实验自变量，最终论文数量只能在覆盖／资源结果和用户确认后写入正式合同。

## 任务 1：历史候选成员诊断工具设计（不可用于当前启动）

**文件：**

- 新建 `thesis/experiments/llm_probe/tools/ch3_drift_paper_corpus_diagnostic.py`
- 新建 `.Codex/docs/2026-09-23-DRIFT源期训练抽样合同/paper-corpus-diagnostic-report.md`
- 新建 `.Codex/docs/2026-09-23-DRIFT源期训练抽样合同/paper-corpus-diagnostic-skill-receipt.json`

**接口：**

```text
python tools/ch3_drift_paper_corpus_diagnostic.py \
  --config configs/ch3-drift-formal-evaluation-v1.json \
  --run-dir runs/diagnostics/<new-identity> \
  --candidate-spec <仓库相对JSON> \
  --audit
```

`candidate-spec` 只包含 `corpus_namespace`、每个用途的角色列表和每角色行数；拒绝未知键、绝对路径、`member_seed`、模型字段、攻击字段、阈值字段和样本列表。用途只能为 `source_train`、`source_validation`、`target_test`。

**行为：**

1. 读取现有评价配置，核对角色路径、revision、Parquet 元数据行数和 `domain,label` 模式。
2. 对每个请求角色，使用行数与无偏位置采样生成固定且无重复的位置集合；按 Parquet 行组只读拉取所需行，域名仅在进程内参与根摘要、长度／字符统计、交集／冲突检查。
3. 每个角色输出位置根、selected-row root、域名哈希根、长度直方图、字符类别统计、选中行内重复／空值／标签冲突计数、耗时和峰值RSS；不输出具体行号或域名。
4. 在候选的训练／验证／测试用途之间检查所选 exact eSLD 重合和标签冲突。任一选中样本跨用途标签冲突失败关闭；同标签重合按合同只披露，不擅自删除。
5. 只允许已选角色的有限读取；运行目录已有任何制品即拒绝覆盖。真实诊断由主代理运行，工具实现者不得启动数据审计。

**验收：**

- 同一 `candidate-spec`、revision 和角色元数据复算得到相同位置根／域名哈希根；不同批读取大小不改变根。
- 样本位置不依赖模型、攻击、自由种子或原始行序前缀。
- 选中成员可审计，但工具不声称全源实体唯一、总体代表性或最终论文合同已冻结。

## 任务 2：历史分阶段诊断设想（未执行，已废止）

本节原拟先运行小候选规格并读取位置根等收据，再决定是否增加候选规模；该设想未执行，现已由全量哈希最小 `top-k` 两遍流式审计取代。任何一次结果仍只说明该候选规格，不按模型效果调整成员。

全源实体去重、完整源总体分布、全源容量和最终论文规模仍需要额外收据；无服务器时不得把局部候选审计冒充全源覆盖。
