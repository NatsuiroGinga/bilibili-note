# DRIFT 全量流式候选语料审计实施简报

## 用户授权与边界

用户于2026-09-23选择“一次性、本机只读流式扫描原始 DRIFT 30 个 Parquet”。本次扫描的唯一目标是根据候选规格生成可复核的论文语料候选根、覆盖统计、选中样本内重复和跨用途重合统计。它不训练、不调用 MPS、不修改模型或攻击、也不写出任何成员／域名／Parquet 副本。

尽管扫描规模超过本机常规资源阈值，本次由用户明确授权；实现必须严格批读、常数级批缓存和每角色至多候选数量级内存，不创建缓存、索引、数据库、临时排序文件或物化成员表。

## 精确算法

1. `--audit` 在元数据审计后对 `candidate-spec` 每个角色流式读取 `domain,label` 批。
2. 固定候选键为 `SHA256(length_prefix_encode(data_revision, corpus_namespace, exact_esld))`；同一角色内先以 exact eSLD 去重，再保留哈希最小的 `count` 个唯一候选。键不含模型、攻击、阈值、年份外自由种子或行序。
3. 第一遍全量流式扫描使用容量为 `count` 的最大堆与仅限当前候选集合的字典；不保存全体域名或全体去重集合。被淘汰或高于当前阈值的成员立刻释放。
4. 第二遍全量流式扫描只对第一遍选中的 exact eSLD 复核原始出现次数、重复计数与标签合法性；记录候选根、长度和字符统计。行号与行组信息即使出现在辅助读取收据中，也不参与成员选择，不构成“行位置抽样”。
5. 完成所有角色后只在内存中对各角色候选集合作训练／验证／目标用途间 exact eSLD 重合与标签冲突审计；输出聚合计数和根，不输出任何成员或成员哈希列表。相同实体跨用途但同标签只披露，冲突标签失败关闭；不得静默删除。
6. 每个角色开始／完成写原子小型状态；两遍扫描均按已读行数、总行数、耗时、吞吐、当前候选数和 RSS 限频输出心跳。被终止时保留最后完整角色的收据和当前角色 `running` 状态。

## 真实运行与验收

实现代理只运行语法、帮助、导入隔离和静态入口检查。主代理随后用现有 `candidate-spec-diagnostic-v1.json` 启动完整扫描。该规格仍是诊断规格，不是最终论文规模。

通过条件：30 个角色均完成、候选数量等于请求数量、无非法标签、无跨用途标签冲突、输出不含域名／成员明文／成员表。失败或资源异常只说明候选审计未完成，不改为行序前缀或改变候选规格。
