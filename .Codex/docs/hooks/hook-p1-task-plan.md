# Hook-P1 实施计划

## 目标

仅把审计中已经判定可机械执行的 P1 规则迁入项目原生 Hook 或持久包装器，并在真实 Codex 拒绝、三目录正反例和绕过测试全部通过后，逐条精简完全等价的 `AGENTS.md` 细节。

## 范围

- 可处理：子代理命名、远程入口、`rsync` 路径与危险参数、日志管道状态、本机实验目录 `pytest`、`uv` GPU 训练依赖保护、验证收据。
- 必须保留：研究判断、用户授权、恢复冲突、科学参数等价、凭据总禁令、实验结论写回语义。
- 禁止处理：P2 及以后技能治理、实验源码与数据、服务器状态、Git 历史。
- 任何 `AGENTS.md` 精简必须晚于对应门禁的真实运行时、三目录、允许、拒绝和绕过验证。

## 阶段

- [x] 阶段一：回读审计、P0 报告、当前规则、远程合同和钩子技能。
- [ ] 阶段二：证明当前项目 Hook 在真实 Codex 中能够拒绝工具调用。
- [ ] 阶段三：实现并验证 P1 策略分发器和必要包装器。
- [ ] 阶段四：按等价性逐条精简机械规则，计算活动链字节差异。
- [ ] 阶段五：格式化、静态检查、完整回归、独立复核和实施报告。

## 立即停止条件

- 项目 Hook 未加载、未信任或被配置禁用。
- 错误命令未被真实拒绝。
- 正确命令出现不可接受误阻塞。
- 当前工具字段与策略合同不符。
- 子目录不能定位 Hook，或脚本输出任何凭据原文。

## 当前状态

**阶段三准备中**：已证明普通配置下真实 Codex 能拒绝错误命令并放行安全命令；开始实现策略分发器和三个持久包装器，暂不精简规则。

## 实现文件

- `.codex/hooks/project_policy_guard.py`：顺序分发子代理命名、远程入口、同步、本机 `pytest` 与 `uv sync` 规则。
- `.codex/hooks/tests/test_project_policy_guard.py`：策略正反例与常见绕过测试。
- `.codex/hooks/tests/test_hooks_integration.py`：三个工作目录的配置级集成矩阵。
- `thesis/experiments/llm_probe/scripts/guarded_remote_stage.py`：能力清单、输入哈希、日志和退出状态包装器。
- `thesis/experiments/llm_probe/scripts/guarded_rsync.py`：白名单单文件同步、父目录和双端哈希包装器。
- `thesis/experiments/llm_probe/scripts/guarded_uv_sync.py`：固定 GPU 可选组、先干运行和关键依赖移除检查。
- 对应包装器测试只放 `.codex/hooks/tests/`，不修改实验生产模块和现有实验入口。

## 验收矩阵

- 每条策略至少包含允许、拒绝、常见包装绕过三类样例。
- 配置级测试从仓库根、`llm_probe`、`scripts` 三个工作目录执行同一 Hook 命令。
- 包装器仅用临时目录和伪命令验证，不连接服务器、不执行真实同步或依赖更新。
- 修改后用真实 Codex 临时只读会话重新验证一条允许和一条拒绝。
- 只有对应矩阵全部通过后才精简完全等价的机械说明；无法机械证明的部分原样保留。

## 已有证据
