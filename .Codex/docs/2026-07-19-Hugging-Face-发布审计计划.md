# Hugging Face 发布审计计划

## 目标

在不修改主实验代码、交接文档和运行目录的前提下，核验当前可发布的 QLoRA 适配器、自有派生制品与复现材料，明确第三方数据许可边界，并形成模型仓库、数据集仓库、上传清单和卡片草案。

## 阶段

- [x] 读取仓库规则、交接文档、当前实验计划与 Hugging Face 命令行技能。
- [x] 审计本地模型、数据处理制品、运行归档及文件完整性。
- [x] 在不泄露凭据的前提下审计服务器产物和 Hugging Face 身份条件。
- [x] 从官方来源核验 GeNIS、HIKARI-2021、DEDALE 2.0 的再分发许可。
- [x] 生成逐文件上传清单、建议仓库结构、模型卡与数据卡草案。
- [x] 格式化并执行差异检查，汇报可上传项与阻塞项。

## 关键问题

1. 哪些运行已经保存可独立加载的 QLoRA 适配器，而不是仅有指标或检查点引用？
2. 哪些处理脚本、清单、哈希、配置和评估结果不包含第三方原始记录或敏感信息？
3. 三个第三方数据集是否有允许公开再分发原始数据或派生行级数据的明确条款？
4. `HF_TOKEN` 是否存在，当前 Hugging Face 归属能否通过非敏感身份查询确认？
5. 服务器产物是否已经完整归档，且上传前具备路径、大小、SHA-256 和许可依据？

## 决策

- 不上传 Qwen 基座权重，只考虑项目自行训练的 QLoRA 适配器。
- 第三方数据许可不明确、禁止再分发或只允许研究使用时，不上传原始数据和可还原的行级派生数据。
- 方法尚未完成正式裁决，模型卡必须标记为研究探针或预发布制品，不宣称正式算法效果。
- `HF_TOKEN` 缺失或仓库归属不能确认时，只完成发布准备，不执行仓库创建和上传。

## 错误与阻塞

- 本机未设置 `HF_TOKEN`；服务器执行 `source ~/.vimrc` 后确认已设置，但服务器未安装 `hf` 命令行工具。
- 服务器访问 Hugging Face 首页返回 `curl` 退出码 28 和状态码 000，身份接口也无法返回用户名，因此仓库归属不能确认，禁止上传。
- 一次本地 `rg` 命令因引号不匹配失败，已改用单引号字面量重试，未修改文件。
- 一次远程哈希命令因 Tcl 提前展开变量失败，已改用花括号保存远程脚本重试，未修改服务器文件。
- DEDALE 的 `zeek_orange_dmz.zip` 仍是不完整归档，审计时观察到 93,322,696 字节；不计算完成哈希，不上传，不修改。
- 系统没有全局 `prettier`，改用可用的 `npx prettier`；首次沙箱内原子写入被拒绝，获得工作区格式化权限后重试通过。
- 模型卡草案的外层 Markdown 围栏与内部示例围栏冲突，已删除外层围栏并重新执行格式化与围栏检查。
- 一次清单补丁因 Prettier 已调整表格空格而无法匹配，使用 `rg` 重新定位精确行后补入运行配置哈希。

## 当前状态

审计、许可核验、发布结构、上传清单、模型卡、数据卡和验证均已完成。实际上传因 Hugging Face 网络不可达且仓库归属未确认而阻塞。
