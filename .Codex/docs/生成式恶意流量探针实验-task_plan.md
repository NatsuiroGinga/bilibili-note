# 任务计划：生成式恶意流量探针实验

## 目标

建立与旧实验隔离、可在单张 RTX 5090 上复现的生成式恶意流量探针实验包，先验证 Qwen3-1.7B 能否从统一流量表示中稳定学习二分类任务，再决定是否进入 3B 至 4B 基座比较和创新机制实验。

## 优先级

- **P0**：固化设计、数据契约、泄漏防护、验收规则和复现边界。
- **P1**：用测试驱动方式实现独立 `uv` 工程，并在本地完成无 GPU 单元测试。
- **P1**：同步至 RTX 5090，完成环境、模型前向和小样本训练冒烟测试。
- **P1**：完成三个主数据集的正式探针实验和三随机种子复验。
- **P2**：在 H1 通过后比较 3B 至 4B 基座；当前不实现强化学习和论文创新机制。

## 已作决策

- 采用独立子工程 `thesis/experiments/llm_probe/`，不向旧的 macOS/MPS 环境追加 Linux/CUDA 大模型依赖。
- 探针只验证生成式模型的任务可学性，不把首轮结果包装成创新点，也不提前使用 GRPO、PINN、Stiefel-LoRA 或 mHC。
- 主结果使用跨数据集共有的规范字段视图；数据集特有字段视图只作域内诊断。
- 主任务为良性/恶意二分类；攻击家族保留为元数据，待 H1 通过后再做多分类。
- 结构化输出只生成标签，不要求模型生成解释或主观置信度。
- 本地代码、配置、数据清单和指标摘要留档；原始数据、模型权重、缓存和大体积运行产物不进入版本管理。

## 风险

- CICIoT2023 当前可直接使用的是社区镜像；若缺少采集场景或源文件分组字段，只能用于任务可学性诊断，不能支持严格跨域结论。
- 不同数据集的字段缺失模式可能泄漏数据来源，因此不能把带有不同 `NA` 模式的全字段表示作为跨数据集主结果。
- RTX 5090 对 PyTorch、CUDA 和量化库版本有兼容要求，必须先通过量化加载和前向测试，再启动长训练。
- 三个数据集尚未全部下载并通过校验，正式探针不能使用不完整压缩包。

## 错误记录
