# 统一数据冻结与 PINN 候选顺序实验合同

- **状态日期**：2026-07-28。
- **当前状态**：文献层协议 `data-protocol-v1.0-rc1` 已通过六阶段审查；统一训练与评测预算已经用户批准，但完整 `dataset-v1`、预算清单与哈希尚未生成，因此不得启动正式基线或候选训练。
- **目标**：一次完成 GeNIS、TQH-C2 与 ns-3 的数据处理和版本冻结，使全部基线、PINN 物理建模候选、条件增强候选与最终方法使用同一数据版本；随后依据同协议基线选择一条理论完整的 PINN 公式体系。若该 PINN 已具有充分机制、消融和收益证据，则直接冻结第三章，不强制拼接独立第二结构。
- **文献依据**：[数据协议决策报告](sdd/task-dataset-protocol-review/decision-report.md)、[PINN 与 PCAP 技术路线决策报告](sdd/task-pinn-pcap-ideation/decision-report.md)、[第三章实验证据映射](sdd/task-pinn-pcap-ideation/chapter3-experiment-evidence-map.md)和[第一创新点外部横向对比计划](2026-07-23-第一创新点外部横向对比计划.md)。训练与评测预算的执行细节见[统一训练预算清单实施方案](2026-07-28-统一训练预算清单实施方案.md)。

## 1. 不可变研究边界

1. 数据源只包含 GeNIS 2025、TQH-C2 1.0.1 与 ns-3，不增加第四个数据集。
2. 所有实验读取同一个版本化派生数据包 `dataset-v1`，其文献定义遵循 `data-protocol-v1.0-rc1`。原始数据只用于生成该数据包，冻结后训练与评估代码不得直接读取原始 CSV、JSONL 或 PCAP。
3. 数据包包含字段超集、缺失掩码和协议适用掩码。某个模型可以读取字段子集，但不得读取其他模型不可获得的额外语义信息。
4. 同一评测层内，所有方法使用完全相同的 `sample_id`、标签、划分和样本顺序清单；禁止为不同方法重新抽样。
5. 树模型使用确定性数值视图，DistilBERT、Qwen 与已发表序列模型使用确定性文本或包序列视图。允许表示形式适配模型结构，但字段来源和值必须来自同一主记录。
6. 地址、原始端口、文件名、路径、采集单元编号、场景名、拓扑名和标签派生描述只用于审计或分组，不进入推理输入。
7. 数据冻结后，要求新增原始字段、重新定义标签或重新切分测试集的候选方法直接退出本轮，不返回数据处理阶段。
8. `dataset-v1` 永久保留全量冻结记录；训练和神经主表只通过其上的不可变预算清单控制成本，不得把预算抽样写回或裁剪全量主记录。
9. 所有方法共享相同训练预算、候选预算、验证预算和评测预算清单及 SHA-256；禁止根据任何模型结果重采样。

## 3. `dataset-v1` 主记录

目标目录为 `thesis/experiments/llm_probe/runs/data-frozen/dataset-v1/`。冻结制品至少包含：

1. `master_records.parquet`：唯一主记录，每行以稳定 `sample_id` 标识。
2. `schema.json`：字段名、类型、单位、归一化、来源、可观测性、模型输入资格和缺失语义。
3. `label_contract.json`：GeNIS 分层标签、TQH-C2 二元标签、未知类定义及禁止映射。
4. `field_roles.json`：`model_input`、`physics_target`、`label_target`、`split_metadata` 和 `audit_only` 五类字段角色。
5. `source_checksums.json`：原始文件、提取脚本、主记录和全部清单的 SHA-256。
6. `freeze_manifest.json`：数据版本、生成命令、代码提交、记录数量、类别统计、分组统计、泄漏审计和冻结时间。
7. `views/`：从主记录确定性派生的数值、文本、包序列、多尺度状态和协议专用视图。
8. `manifests/`：所有训练、验证、测试、压力测试和协议子集的不可变 `sample_id` 清单。

### 3.1 字段超集

1. **共同流级观测**：持续时间、双向包数与字节数、总包数与总字节数、包长统计、到达间隔统计、包速率、字节速率和方向比例。
2. **共同包序列观测**：相对时间、有符号包长、方向、相邻到达间隔、累计包数、累计字节数、突发边界与多尺度窗口索引。
3. **协议观测**：协议族、TCP 标志、可验证的重传/乱序/往返时延，以及 QUIC 可见首部、版本和旋转位有效性；不可见字段使用显式掩码，不补造数值。
4. **物理真值**：五锚点占用、区间到达量、成功服务量、入队前与出队后丢弃量、有效容量、时延、抖动和队列上限，仅 ns-3 记录可作为监督。
5. **网络演算派生量**：累计到达、到达包络、服务曲线、积压和时延边界；公开数据缺少服务曲线时只保留缺失掩码，不计算伪真值。

## 4. 冻结清单

1. **GeNIS**：训练、验证、域内测试、时间前向测试和未知攻击测试；按会话、时间和采集场景分组，目标样本比例约为 `8:1:1`，分组隔离优先于精确比例。
2. **TQH-C2**：训练、验证、域内测试和加密条件留出；按完整采集单元分组，禁止按行随机拆分。TLS、QUIC/HTTP3 与 HTTP+AES 均保留未触碰单元。
3. **ns-3**：训练、校准、未见配置、范围外队列、星型测试、哑铃测试和停车场测试；任何 `group_id` 不得跨清单。
4. **协议子集**：`tcp_eligible`、`quic_visible`、`common_observation` 和 `network_calculus_truth` 在数据冻结时一次生成。协议专用实验只能使用这些清单，不得事后按结果筛选。
5. **主比较配对**：同一指标的两种方法必须读取同一清单和相同样本顺序；不共享标签空间或真值的数据不合并成单一总分。

### 4.1 统一训练预算清单

1. **GeNIS**：保留开发训练全量 `151,324` 条，按会话、时间、家族和子类确定性抽取恰好 `30,000` 条用于统一正式训练。
2. **TQH-C2**：只从冻结的 28 个训练 cell 抽取；每 cell 最多 `1,000` 条并保持该 cell 原二元比例，不足上限时全取，不复制小 cell，合计约 `28,000` 条。
3. **ns-3**：全部 `2,421` 条四窗口序列各出现一次；只用任务权重控制物理任务贡献，禁止复制、过采样或重复索引。
4. 三源统一正式训练预算约 `60,000` 条，理论上限为 `60,421` 条；实际精确总数、来源统计、样本顺序与 SHA-256 在物化时冻结。
5. 候选筛选另用固定约 `10,000` 条清单、`200` 个优化步和单一种子 42；只有唯一胜者进入统一正式预算并运行种子 42、43、44。
6. 正式训练最多一轮，检查点和早停只读取冻结验证清单。必要匹配基线与胜者共享正式训练清单和哈希，落选候选不得扩跑全量三种子。

## 6. PINN 物理建模候选与匹配基线

### R1：PCAP 增强的多尺度控制体状态 PINN

- **输入**：共同流级观测、包方向、包长、到达间隔、突发和多尺度累计量。
- **基线**：常数状态预测器、现有五字段四窗口预测器、同容量的 PCAP 状态预测器、打乱包序和方向的负对照。
- **比较**：R1 必须相对“同 PCAP 字段 + 同状态监督 + 无物理残差”的 M4 证明物理残差有独立收益。
- **进入门槛**：三个种子的未观测状态误差均相对五字段预测器改善至少 `10%`，且打乱时序后收益显著收缩；每个关键状态退化不超过 `5%`。

### R2：协议感知 TCP 流体 PINN

- **输入**：冻结的 `tcp_eligible` 子集及 TCP 标志、重传、乱序和可验证往返时延。
- **基线**：同字段普通状态回归、同字段无流体残差模型和 R1 控制体模型在完全相同 TCP 清单上的结果。
- **比较**：只报告 TCP 子集，不外推到 QUIC；宏观流体动力学和 TCP 协议动力学合并为这一条路线。
- **进入门槛**：三个种子的状态误差与流体残差均改善至少 `10%`，检测和校准不劣；跨拥塞控制算法或采集点后不得出现系统性失效。

### R3：网络演算边界 PINN

- **输入**：共同累计到达量，以及 ns-3 提供的服务曲线、容量和拓扑真值。
- **基线**：普通状态回归、只加入网络演算特征但无边界损失的模型、R1 控制体模型在同一 `network_calculus_truth` 清单上的结果。
- **比较**：公开数据缺少服务曲线时只做冻结模型外测，不施加伪边界。
- **进入门槛**：三个种子的状态误差与边界违反率均改善至少 `10%`；若仅加入上界特征即可获得同等收益，则该路线降级为特征基线而非 PINN。

### 不作为独立 PINN 候选

- 时间点过程只作为包到达表征或统计基线，因为似然损失通常不是物理残差。
- 统一 QUIC 拥塞窗口动力学不进入实验，因为普通旁路 PCAP 无法可靠观察确认关系和拥塞窗口。
- 现有有限队列和单尺度控制体公式作为 R1 的基础基线，不另立重复路线。

## 7. 条件增强候选与匹配基线

S1 与 S2 不再是第三章冻结的必需第二结构。R1 至 R3 先决定预测哪些状态、采用什么物理残差；若选定 PINN 已具有两个或多个责任独立的内部机制、充分理论性质、独立消融和组合收益，则直接进入正式验证。只有它仍缺少检测与物理联合收益，或者物理状态无法进入生成主输出时，才允许从 S1、S2 中选择一个条件增强项。

### S1：有界物理条件交叉注意力

- **结构**：状态头产生状态与增量词元，经零初始化、恒等旁路和范数上限约束的交叉注意力注入 Qwen 中后层。
- **基线**：普通监督 Qwen、选定 PINN 但无条件注入、只有同参数量非物理交叉注意力、完整 S1。
- **已有证据**：旧 `eval300` 上三个种子的检测方向稳定，但未观测状态和物理收益不稳定；只能作为待复核候选，不能直接冻结。
- **重新进入门槛**：必须使用 `dataset-v1`、选定 PINN 公式和未触碰测试清单；三个种子的检测与校准通过非劣门槛，未观测状态误差和物理残差均改善至少 `10%`。

### S2：物理状态路由适配专家

- **结构**：沿用已实现的共享低秩基底物理状态编码专家。序列级路由只消费模型预测的物理状态，最多使用平稳传输、队列累积和容量饱和三个专家；大类检测任务的专家门控固定为 0。
- **前置门槛**：选定的 PINN 路线必须通过三种子状态可辨识性门槛。路由器不得读取攻击标签、数据来源、场景号、拓扑名、队列真值、容量或通量。
- **固定对照**：冻结检测适配器、单私有物理适配器、三个专家静态同权组合、三个专家序列级 Top-1 路由。四者共享 `dataset-v1`、样本顺序、训练步数和评估脚本；后三者保持相同总秩、可训练参数与实际激活参数预算。
- **50 步探针门槛**：任一专家使用率不得低于 `0.05`，归一化使用熵不得低于 `0.50`；每个专家条件梯度非零，三乘三条件损失矩阵逐行对角最优，对应专家移除后只在对应预测潜态上出现选择性退化；子类生成验证损失相对同预算单适配器改善至少 `1%`，未观测状态误差和物理残差至少一项改善 `1%` 且另一项恶化不超过 `1%`。
- **正式门槛**：家族宏平均 F1 下降不超过 `0.01`，子类宏平均 F1 不低于单适配器，未知攻击平均召回提高至少 `0.10`，良性误报率降低至少 `0.05`，未观测状态误差和物理残差均改善至少 `10%`，子类校准误差增量不超过 `0.02`。
- **停止条件**：专家坍缩、无物理专门化、同总秩预算不优于单适配器、路由由标签或来源解释、或者效率代价超过联合收益时永久停止，不增加第四个专家或扫描 Top-K、秩、层位与专家数。

完整设计与既有实现状态见[物理状态路由适配专家备选路线](2026-07-22-物理状态路由适配专家备选路线.md)和[共享低秩基底物理状态编码专家阶段报告](sdd/task-physics-routed-experts-probe/report.md)。

## 8. 固定执行顺序

1. **D0 数据验收**：完成 A/B/C PCAP 提取与标签连接，物化 `data-protocol-v1.0-rc1`，通过 12 项 P0 后生成全量 `dataset-v1`、全部划分、统计和哈希。
2. **D1 预算冻结**：按[统一训练预算清单实施方案](2026-07-28-统一训练预算清单实施方案.md)生成统一正式训练、候选筛选、神经主表和开放集全量清单；两次独立生成必须逐字节一致。
3. **B0 同协议基线**：运行 `hgb`、`xgboost`、`distilbert` 和 `qwen_sft`，随后运行 `state_supervision`、`standard_pinn` 及通过字段适配门禁的 FlowPic。全部配置绑定同一预算清单与 SHA-256；任何 PINN 候选不得在同协议基线完成前进入正式 Qwen 训练。
4. **P0 三条物理建模路线低成本探针**：R1、R2、R3 固定使用同一约 `10,000` 条清单、`200` 步和种子 42。不得因前一条结果修改后续候选数据。
5. **P1 冻结 PINN 公式体系**：先按各自预注册门槛判定通过或失败，再在共同清单上比较未观测状态误差、物理/边界违反、训练成本和失败范围；只选一条 PINN 路线，不直接比较不相交协议子集的绝对分数。
6. **P2 内部机制诊断**：使用普通监督、状态监督、标准 PINN 和选定 PINN 四级对照，再移除该 PINN 中最终拟写入方法名称的每项内部机制。若它已满足检测非劣、状态与物理收益及章级理论完整度，则跳过条件增强并进入正式训练。
7. **C0 条件增强诊断，仅按缺口触发**：只有 P2 暴露明确剩余缺口时，才在相同 Qwen、相同候选清单和相同参数预算下，从 S1 与 S2 中选择一个有因果针对性的候选；不得为凑“两个结构”同时扫描两者。
8. **Q0 正式训练**：候选中只有唯一胜者进入约 `60,000` 条统一正式清单，运行种子 42、43、44、最多一轮和验证早停；落选候选不得扩跑。完成内部机制消融、TQH-C2 加密留出和未见配置/哑铃/停车场外测。
9. **F0 方法冻结**：完成公共检测主表、FlowPic 同输入表、GeNIS 神经主表与树模型全量补充、ns-3 物理表、效率和一个非 Qwen 基座验证后，冻结 PINN 公式、算法名称、章名和第三章结果表；未实际采用的条件增强项不得进入名称或贡献点。

## 9. 选择与停止规则

1. R1、R2、R3 都接受同一约 `10,000` 条、`200` 步、种子 42 的低成本探针，但最多选择一条 PINN 物理建模路线。
2. 选定 PINN 若已具备充分理论责任、独立消融、组合收益和检测价值，则直接冻结章级方法，不运行 S1、S2。
3. 只有预先记录的剩余缺口才能触发一个条件增强候选；候选先看自身门槛，再看共同清单的联合收益和训练推理成本，不得按最终测试集最高分事后选路。
4. 若 R1 至 R3 均未通过，则停止公式扩展，将 PINN 主张收窄为 ns-3 物理机制约束，不增加第四条路线。
5. 条件增强候选失败不会自动否定理论完整的 PINN；若 PINN 本身也未形成检测非劣、状态与物理联合收益，则收窄章节主张或重新讨论方法，而不是继续扫描相似融合模块。
6. 若候选只降低残差而不降低独立状态误差，判定为残差捷径并淘汰。
7. 若候选的收益可由新增字段但无物理残差的 M4 完全解释，不得声称 PINN 带来检测提升。
8. 若候选依赖标签、场景、拓扑、地址、文件路径或采集单元泄漏，结果无效并停止该路线。
9. 正式结果报告全部三个种子及均值、标准差和置信区间；最佳种子仅按冻结验证集规则选择模型制品。
10. 候选筛选结束后不得因差距大小、方向或训练速度重抽约 `10,000` 条清单；正式胜者和匹配基线也不得分别生成约 `60,000` 条清单。

## 10. 禁止返回数据处理阶段

1. `freeze_manifest.json` 和全部 SHA-256 生成后，数据版本即锁定；后续不得添加字段、改变归一化、重抽样或替换测试清单。
2. 新候选若不能使用 `dataset-v1` 的字段超集、协议子集和缺失掩码，直接淘汰，不创建 `dataset-v1.1` 迁就方法。
3. 唯一允许重新处理数据的情形是发现可复现的正确性缺陷，例如标签连接错误、哈希不一致、样本跨分区或单位换算错误。此时必须冻结旧版本、记录根因、生成新主版本，并重跑所有受影响基线，禁止只重跑本文方法。
4. 数据规模变化只允许来自预先列明的 A/B/C 完整采集单元，不允许根据实验结果追加有利样本。

## 11. 运行、日志与空间门槛

1. 每次正式运行保存配置、环境、输入清单与 SHA-256、样本顺序、控制台日志、逐步指标、预测、摘要、成本和 SwanLab 运行信息。
2. 低成本探针在硬件容量允许时可以并行两个进程，但必须先探测实际 CPU/GPU、内存/显存和支持精度，并使用不同输出目录与预先固定的资源上限；不得假定一定存在 RTX 5090。
3. 原始 TQH-C2 PCAP 保留在本机；服务器只接收派生 Parquet、清单和必要缓存。
4. 服务器数据盘使用率达到 `80%` 或可用空间不足 `10 GiB` 时通知用户；达到 `90%` 或不足 `5 GiB` 时停止新增文件并等待扩容。
5. 所有入口使用 `device=auto` 和能力探测。CPU、通用 CUDA GPU 与 RTX 5090 都是允许的运行档位；CPU 模式不得因缺少 `nvidia-smi`、CUDA 或 bitsandbytes 直接失败。硬件降级只能调整微批量、梯度累积、线程、精度和可选量化，不能改变数据、有效批量、步数、种子和评价清单。
6. 训练时间、吞吐、延迟、内存和显存只在同一硬件档位内比较；不同档位分栏报告，禁止混合排序。
7. GPU 服务器按量计费并允许随时重启。正式训练必须把完整恢复检查点、运行状态、启动命令、配置与输入哈希写入 `/root/autodl-tmp/thesis/`，检查点间隔不超过 20 个优化步或 10 分钟；数据物化使用 `.partial` 临时目录与原子发布。每个独立阶段结束后立即把小型关键制品同步回本机，具体执行[按量 GPU 服务器重启恢复协议](2026-07-28-按量GPU服务器重启恢复协议.md)。
8. RTX 5090 上旧 `15,000` 条训练样本的实测运行约 `22` 分钟。新统一预算的计划值为普通 QLoRA 约 `1.5` 小时/种子、PINN 约 `2` 至 `2.5` 小时/种子；这些是启动预算，不是完成事实，正式运行必须记录真实 GPU 小时。
9. 既有全量训练和旧预算运行继续保留为历史证据，不删除、不覆盖；未绑定新预算清单 SHA-256 的旧结果不得进入新的统一主表。
