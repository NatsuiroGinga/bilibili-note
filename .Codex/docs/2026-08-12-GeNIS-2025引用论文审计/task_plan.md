# GeNIS-2025 引用与实际使用论文查全审计计划

## 目标

系统查全、去重并全文核验引用或实际使用 GeNIS-2025 数据集的论文，形成 A/B/C 分类、逐篇实验协议审计、可承接工作矩阵，以及同协议复现与严格防泄漏两套评价建议。

## 范围与证据门槛

- 锁定数据论文 DOI、Zenodo 概念 DOI、版本 DOI 与版本链。
- 检索题名、简称、DOI、作者、数据文件名、官方仓库及 GitHub 引用链。
- A 类：实际实验使用 GeNIS；配置、结果与缺陷必须由全文或源码核验。
- B 类：只在方法、相关工作或数据集综述中引用 GeNIS。
- C 类：同名、误匹配或与网络入侵数据集无关的噪声。
- 摘要、搜索摘要和索引元数据只能用于发现与初筛，不能支撑 A 类实验配置。
- 合法新增全文按 `raw/papers/` → `wiki/papers/` → 方向索引 → Zotero 闭合；付费墙或不可得全文进入阻塞清单。

## 关键问题

1. 截至 2026-08-12，哪些可验证作品真正使用了 GeNIS 数据进行实验？
2. 每篇 A 类论文使用哪个数据版本、哪些样本/类别/字段、何种预处理与拆分？
3. 同协议下的最强模型与最好指标是什么，是否有源码足以复现？
4. 哪些指标不可横向比较，哪些缺陷构成可承接研究切口？
5. 如何同时给出忠实复现表与更严格防泄漏协议表，避免把协议变化误写成方法提升？
6. 除随机行级分类外，哪些任务能由 GeNIS 的 PCAP、场景、时间、标签层级和版本链真实构造，且尚未被现有结果饱和？

- 首次在受限文件系统中创建任务目录返回 `Operation not permitted`；已通过受控权限申请在用户指定路径创建，未触及其他目录。

- Sider Scholar 的 OpenAlex 查询返回若干空题名，导致插件结构化输出校验失败；其 Google Scholar 式简称查询又产生大量 `genis`/`genistein` 同名噪声。
- Zotero 的正式 arXiv/identifier 导入分别遭遇 HTTP 429 和读取超时；已降级为两个 arXiv 网页条目，键为 `SS6IHSUE`、`CN7XAI2P`，但它们是弱源网页条目，不等于规范论文条目或 PDF 附件闭合。
- Springer 正式 FPS 论文元数据与 DOI 已核验，但正式 PDF 受订阅访问限制；当前全文证据来自内容一致的开放 arXiv 作者稿。
- Zenodo/DataCite 已锁定版本 DOI `10.5281/zenodo.14919237`、概念 DOI `10.5281/zenodo.14919236` 和版本号 `1.0.0`；继续请求官方 `versions` 端点时受限网络中 DNS 解析失败，完整版本列表尚未封口。
- 恢复后重试 Zenodo `versions` 端点：`size=100` 返回 HTTP 400，改用受支持的 `size=10` 后成功；端点总计只返回 1 个版本，因此版本链已经封口，不再是阻塞。
