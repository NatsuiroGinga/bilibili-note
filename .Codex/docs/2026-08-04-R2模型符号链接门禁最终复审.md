# R2 模型符号链接门禁最终复审

**请求修改，第四轮符号链接门禁未通过最终复审；任务 5 继续保持 `NO-GO`。**

本轮仅核对受冻结摘要约束的物理拟合配置、物理角色清单、物理 Parquet、检查点绑定清单、正式物理检查点和正式探针配置的符号链接与稳定读取门禁。最终计数为 **严重问题 0 项、重要问题 2 项、次要问题 0 项**。

## 重要问题

### 1. 受信任根由待审配置路径自我派生，任意绝对配置树可成为新的“受信任根”

位置：

- `src/flow_probe/r2_final_physics_fit.py:321-327`
- `src/flow_probe/r2_final_distilbert_probe.py:445-450`
- `scripts/run_r2_final_physics_fit.sh:11-12`
- `scripts/run_r2_final_physics_fit.sh:25-26`
- `scripts/run_r2_final_probe.sh:11-13`
- `scripts/run_r2_final_probe.sh:34-36`

两个加载器先从调用方提供的配置路径计算 `config_path.parent.parent`，再把这个结果当作 `project_root` 或 `trusted_root`。因此检查只能证明后续路径属于“配置自己所在的两级父目录”，不能证明配置及其冻结制品属于启动器已经确定的项目根。两个正式包装器虽然各自持有固定的 `project_root`，但只执行 `cd`，随后把任意位置的参数 `config` 原样交给 Python；它们没有把固定根传给加载器，也没有限制配置必须来自固定 `configs/` 或核对配置的外部冻结摘要。

独立最小复现把未修改的正式拟合配置和同种子五份探针配置复制到临时任意根后，两个生产加载器均接受，并把该临时目录登记为自己的项目根：

```text
SELF_DERIVED_ROOT_ACCEPTED True True
```

这不是固定根下 `..` 检查失效；固定根一旦真实给定，现有 `commonpath` 检查能拒绝穿越。问题在于入口没有外部固定根，调用方可直接通过新的绝对配置路径改变根本身。这样一来，六类冻结路径的词法归属、五组同种子配置一致性和后续发布位置都可以在另一棵普通文件树内自洽通过。

修复门槛：项目根必须来自生产入口的外部固定值，而不能从待审配置路径推导。加载器应接收或使用固定项目根，先要求拟合配置和探针配置的词法绝对路径位于该根的固定 `configs/` 下，再执行逐级安全打开；包装器也应把同一根显式传入。受冻结配置还应由外部清单或固定文件名与摘要绑定，不能只让配置内部声明自己的制品摘要。

### 2. 逐级 `lstat` 后重新按完整路径打开，读取和原子发布均接受父目录替换

位置：

- `src/flow_probe/r2_final_physics_fit.py:263-303`
- `src/flow_probe/r2_final_distilbert_probe.py:204-232`
- `src/flow_probe/r2_final_physics_fit.py:1160-1186`

两个稳定读取器先用完整路径逐级执行 `os.lstat`，随后调用 `os.open(path, O_NOFOLLOW)` 重新解析整条路径。`O_NOFOLLOW` 只保护最终组件，不保护在这两步之间被替换的父目录。打开后的 `fstat` 与 `lstat(path)` 比较也只证明描述符和**替换后的当前路径**指向同一 inode，不能证明打开对象仍从先前检查过的父目录链取得。

检查点绑定清单发布存在相同窗口。实现先按完整路径检查父组件，再以完整 `path.parent` 打开最终父目录；之后的临时文件创建、硬链接发布和清理确实固定在这个目录描述符上，但该描述符没有从受信任根目录描述符逐级取得，可能已经是替换后的父目录。因此当前实现只能称为“最终父目录内使用同一 `dirfd`”，不能称为“由受信任根锚定的原子发布”。

独立故障注入在最后一次父组件 `lstat` 之后、首次 `os.open` 之前原子交换父目录。两个读取器都接受替换目录中的不同字节；发布器也把清单发布到替换目录并正常返回 64 位摘要，而原先检查过的目录没有清单：

```text
FIT_READ PARENT_SWAP_ACCEPTED replacement
PROBE_READ PARENT_SWAP_ACCEPTED replacement
PUBLISH PARENT_SWAP_ACCEPTED True False 64
```

摘要绑定会让角色清单、Parquet、已有绑定清单和检查点的**不同内容**在更高层继续失败，但不能补足明确要求的父目录身份门禁；拟合配置和探针配置在入口又没有外部预期摘要，故替换内容可直接成为本次运行的配置快照。即使替换文件字节相同，当前实现仍无法证明它来自已检查的父目录链。

修复门槛：先以 `O_DIRECTORY | O_NOFOLLOW` 打开外部固定受信任根并固定其设备号和 inode；随后只以相对单组件名称和上一级 `dir_fd` 逐级打开目录，每级核对 `fstat`、不跟随的相对 `stat` 及目录类型；最终文件也只从最后一个已固定父目录描述符以相对名称和 `O_NOFOLLOW` 打开。读取期间保留所需目录描述符和文件描述符。绑定清单的临时创建、非覆盖硬链接发布、既有文件读取、清理和目录 `fsync` 必须继续使用由这条根锚定目录链取得的同一最终父目录描述符，不能重新按完整父路径打开。

## 已确认闭合

### 1. 不再预先解引用符号链接

- 两个生产模块中 `.resolve()` 调用为 0。
- `_resolve_path` 与 `_lexical_absolute` 只执行词法展开和 `abspath` 规范化，不跟随符号链接。
- 物理拟合配置和正式探针配置的最终组件符号链接、父目录符号链接均在 YAML 解析前拒绝。
- 共用稳定打开器对角色清单、Parquet、绑定清单和检查点执行相同的最终组件及父组件检查。

### 2. 固定根下的路径归属检查有效

- 在显式固定临时根的最小复现中，`..` 穿越和根外绝对路径均被两个稳定读取器拒绝。
- 位于根内的普通绝对路径可正常打开。
- 3 份正式物理拟合配置和 15 份正式探针配置使用普通路径全部可解析；相对入口路径与绝对入口路径均通过。

### 3. 哈希与消费保持同句柄或同快照

- 物理拟合配置：一次稳定读取的字节快照同时用于 SHA-256 与 YAML 解析。
- 物理角色清单：一次稳定读取的字节快照同时用于 SHA-256 与 JSON 解析。
- 物理 Parquet：同一文件描述符先计算 SHA-256、回卷，再交给 `pd.read_parquet`；退出前复核文件描述符元数据。
- 探针侧拟合配置：一次稳定读取并核对摘要后的字节快照直接传给拟合配置解析器，不按路径重开。
- 检查点绑定清单：同一稳定读取快照用于 SHA-256 与 JSON 解析。
- 正式物理检查点：同一文件描述符先计算 SHA-256、回卷，再交给 `torch.load`；退出前复核文件描述符元数据。

这些闭合项可防止已经打开的 inode 在哈希后被重新按路径加载，但不能消除打开前的父目录替换窗口。
