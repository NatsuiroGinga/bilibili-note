# R2 QUIC v7 方向级数据报上限修复计划

## 目标与根因

v6 run1 使用 aioquic 客户端与固定 quiche 服务端。代理在 `server_to_client` 方向收到合法的 `1350` 字节 quiche 数据报，却沿用 aioquic 客户端的全局 `1200` 字节上限，写出 `datagram_exceeds_frozen_maximum` 后停止转发。原始证据位于旧服务器：

- 运行根：`runs/data-raw/r2-quic-binary-overlay-v6-run1-aioquic/`
- 首个失败事件：`connections/b74dd9cdddca8667358671db/proxy-events.jsonl`
- 事件语义：`server_to_client`、实际 `1350`、冻结上限 `1200`、合同 `flow_probe_r2_quic_four_tuple_contract_v6`

根因不是队列容量或链路动力学，而是 v4-v6 单值 `max_datagram_bytes` 接口错误地把受测客户端上限复制给两个发送方向。

## v7 冻结映射

- `client_to_server`：按受测客户端实现冻结，aioquic 为 `1200`，quiche 为 `1350`。
- `server_to_client`：按实际发送端固定 quiche 参考服务端冻结为 `1350`。
- 禁止统一放宽到 `1350`：这会掩盖 aioquic 客户端发送超过 `1200` 的回归。
- 禁止统一收紧到 `1200`：v6 已实测固定 quiche 服务端合法发送 `1350`。

映射依据绑定到实际发送端，而不是测试结果：aioquic 1.3.0 的 `quic/configuration.py` 定义 `SMALLEST_MAX_DATAGRAM_SIZE=1200` 并用于发送侧数据报上限；quiche 0.24.5 的 `apps/src/client.rs` 第 39 行定义 `1350`，第 117–118 行将其绑定到最大接收与发送 UDP 载荷；`apps/src/bin/quiche-server.rs` 第 54 行定义 `1350`，第 114–115 行同样绑定最大接收与发送 UDP 载荷。v5 审计器原有实现级检查也已分别约束客户端与服务端，不是 v7 事后新增的数值。RFC 9000 只支持端点各自独立设置传输参数及最小 UDP 载荷为 `1200`，不用于证明两个具体实现的精确默认值。

## 改动范围

1. 新增 v7 配置，网络合同显式写入客户端实现上限、参考服务端实现和方向级派生规则；不修改 v4-v6 配置或证据。
2. 采集器将方向级上限写入 `impairment-config.json`，并以两个独立参数传给代理。
3. 代理为两个 `DirectionState` 分别绑定上限；`proxy-ready.json`、`proxy-stats.json`、逐方向统计和失败事件均记录对应值。
4. 审计器按实际发送端重放事件，核对配置、收据、方向统计和复制配置哈希。
5. 旧单值接口保留为 v4-v6 兼容路径；只有 v7 配置启用方向级接口，历史审计结果不可改变。

精确修改文件为：

- `configs/r2_quic_controlled_directional_datagram_v7.json`
- `scripts/r2_quic_controlled_collect.py`
- `scripts/r2_quic_udp_proxy.py`
- `scripts/audit_r2_quic_determinism_gate.py`
- `scripts/audit_r2_quic_v7_gate.py`
- `tests/test_r2_quic_v7_directional_datagram.py`

## 防泄漏与兼容边界

上限只由受测实现与固定参考服务端实现派生，不读取标签、预测、最终测试、qlog 结果或流量类别。修复不改变延迟、丢包、速率、容量、种子、负载、超时、拆分或统计门槛。

## 一次最小红灯与绿灯

- 唯一目标测试：`UV_CACHE_DIR=/tmp/uv-cache uv run --project thesis/experiments/llm_probe python -m pytest thesis/experiments/llm_probe/tests/test_r2_quic_v7_directional_datagram.py -q`。
- 红灯：同一测试先在未修改生产代码时失败，记录缺少 `max_datagram_bytes_by_direction`。
- 绿灯：同一测试证明 aioquic 为 `1200/1350`、quiche 为 `1350/1350`、`server_to_client=1350` 被接受、`client_to_server=1201` 被拒绝、缺失或半份方向映射失败、真实 v4-v6 配置仍走原单值路径。
- 配置到收据闭合：审计器独立从复制后的冻结配置派生方向映射，不信任代理自报；`impairment-config.json`、`proxy-ready.json`、`proxy-stats.json` 和逐方向统计必须一致。篡改任一方向值或发送端身份时目标测试必须失败。
- 工具链边界：v7 只复用 v6 工具根及其精确树哈希，不重建 aioquic/quiche 工具链。
- 交付检查只执行一次：`black` 格式化本轮 Python 文件，`python -m py_compile` 检查同一组文件，随后运行上述 v7 目标测试与既有真实 v4 目标测试；不运行全仓测试或重复格式化。

## 远端运行门禁
