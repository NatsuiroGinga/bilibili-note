## 已冻结决策

官方 Codex Hook 文档说明：`spawn_agent` 可由 `PreToolUse` 的 `Agent` 匹配器拦截。因此本实现注册同步原生 Hook，不以人工预检冒充自动拦截。守卫仍可从标准输入单独调用，供排查或显式预检使用。

任务名称仅允许小写字母、数字和下划线，而模型标识本身带有连字符和点号；因此名称中的模型后缀使用无歧义规范化形式：`gpt_5_6_sol`、`gpt_5_6_terra`、`gpt_5_6_luna`、`gpt_6_astra`，并逐项映射到实际 `model` 参数。

## 实现内容

- `.Codex/hooks/agent_dispatch_guard.py` 在 `PreToolUse` 输入为 `Agent`、`spawn_agent` 或 `collaboration.spawn_agent` 时校验：
  - `task_name` 的四段格式、模型映射、推理强度一致性和泛名职责段；
  - 文件与责任所有权、非独占工作树声明、不得回滚他人改动、`required_skills` 和 JSON 收据路径；
  - 唯一绝对工作树、预期分支，以及首个动作核对 `pwd` 与 `git branch --show-current`；
  - Astra 的 Sol 制品路径、真实数据或实验制品路径和明确裁决问题。
- `.Codex/hooks.json` 增加同步 `PreToolUse` 的 `Agent` 匹配器，调用上述守卫。该增量与已有实验临时路径守卫并存，未覆盖其配置。
- 拒绝时守卫输出 Codex 规定的 `permissionDecision: "deny"`；放行时零输出且无副作用。

## 局限与启用条件

- Codex 只在信任项目 Hook 后执行该配置；需在 Codex 的 `/hooks` 审核并信任当前定义。未经信任时不会声称已自动拦截。
- 此守卫校验派发参数和简报声明，不能替代派发后的收据验收，也不能证明代理实际执行了简报。
- `.Codex/hooks.json` 同时含另一代理的临时路径门禁增量；本任务不暂存或提交该共享文件，交由主代理统一复核。
