## 加载行为与优先级

- Codex 每次启动从项目根走到当前工作目录。
- 每层只加载 `AGENTS.override.md`、`AGENTS.md` 或已配置回退文件中的第一个。
- 越接近当前工作目录的规则优先。
- Codex 不会因随后编辑子目录文件而动态重新发现规则。因此根 `AGENTS.md` 明确要求：从仓库根启动且任务涉及子域时，先完整读取对应局部规则。
- `.rules` 只控制命令执行权限，不承载内容规则。本次验证使用 `--ignore-rules` 只排除执行权限规则，不排除 `AGENTS.md`。

## 实际加载验证

### 方法

从七个目录分别启动独立的 `codex-cli 0.144.5` 只读临时进程：

```bash
codex exec --ephemeral --sandbox read-only --ignore-rules \
  -c 'model_reasoning_effort="low"' \
  -C <目标目录> -o /tmp/agents-final-<名称>.txt \
  '<只根据启动时注入指令输出 NOTE_*_20260724 哨兵，禁止工具和磁盘读取>'
```

每个 `AGENTS.md` 含唯一哨兵。子进程禁止读磁盘，因此只有实际注入到指令上下文的规则才能被回报。哨兵与文件的映射见“最终层级”。

## 验证限制与环境告警

- 官方 Codex 手册助手在沙箱内因 DNS 失败；经批准联网后返回 HTTP 403，未取得本地手册缓存。本次采用任务给定的官方行为基线、本机 CLI 和实际启动结果。
- CLI 没有直接输出可靠的逐文件指令源元数据。初轮要求模型列路径时，部分嵌套目录出现路径推断错误；最终验证只使用实际注入的唯一哨兵，不把模型生成的路径当证据。
- 验证进程出现模型缓存字段不兼容、重复代理角色、部分 MCP 404 或认证失败、WebSocket 重置和钩子失败告警；进程均回退到 HTTPS、输出目标 JSON 并以 0 退出，未影响 AGENTS 加载判定。
- 本次验证覆盖当前实际层级，没有人为创建 `AGENTS.override.md` 或回退文件冲突，因此“同层只取第一个”和覆盖优先级采用官方行为基线，未做破坏性模拟。
- 当前 `.gitignore` 的第 12 行忽略整个 `.Codex/`。因此本次新增的 `.Codex/docs/AGENTS.md`、计划和报告不会出现在普通 `git status` 中，但文件存在且实际加载验证通过；本任务没有擅自修改忽略规则或强制暂存。
