# E2 任务 2 与任务 3 独立代码复审

## 总体裁决

**请求修改后再把 E2 结果作为路线裁决证据。** 当前实现没有发现直接读取最终测试清单的路径，普通表格模型和 DistilBERT 的拟合接口也没有接收 C 域样本；但统一指标、DistilBERT 基座绑定以及共享 PINN 的负对照与运行门禁仍有会使结论失效的问题。

复审不阻塞已经满足运行条件的拟合任务。HGB、XGBoost、随机森林、MLP 和 GroupDRO 可以继续运行并保留逐样本预测；受影响指标应在修正后从预测重新计算。DistilBERT 与 `E2-A/S/P/X` 在下列阻断项关闭前只能标记为 `review_pending`，不得据此冻结第三章路线。

## 阻断问题

### 1. `PR-AUC` 实际实现为受同分样本顺序影响的逐秩平均精度

- 位置：`thesis/experiments/llm_probe/src/flow_probe/e2_hard_domain_metrics.py:69-78`、`thesis/experiments/llm_probe/src/flow_probe/e2_hard_domain_metrics.py:111`。
- 现象：实现先按概率稳定排序，再对每个正样本所在秩计算精度。这不是按唯一阈值聚合并处理同分样本的标准 `PR-AUC`，同一组标签与概率只要改变同分样本的输入顺序就可能得到不同结果。
- 现有测试进一步固化了错误口径：`tests/test_e2_hard_domain_metrics.py:19-31` 对标签 `[0,1,0,1]`、概率 `[0.1,0.9,0.9,0.1]` 期望 `0.75`；按同分样本整体处理的平均精度为 `0.5`。
- 影响：任务 2 和任务 3 的统一指标、捕获组指标及后续路线门槛会使用不可与标准库或论文结果比较的数值。该问题属于指标错误，现有 `PR-AUC` 结果不能作为论文证据。
- 必须修复：冻结口径后二选一：使用标准平均精度并把字段明确命名为 `average_precision`，或使用精确率—召回率曲线积分实现真正的 `PR-AUC`；增加同分样本重排不变性检查，并重新计算所有受影响结果。

### 2. `E2-X` 可以用身份置换伪装成“分层置换物理”

- 位置：`thesis/experiments/llm_probe/src/flow_probe/e2_shared_pinn.py:381-410`、`thesis/experiments/llm_probe/src/flow_probe/e2_shared_pinn.py:497-500`。
- 现象：`permute_e2_physics_supervision()` 只检查索引是全排列，不检查固定点；传入 `range(batch_size)` 会原样返回全部物理真值，却把 `provenance` 改成 `stratified_permuted`。`compose_e2_variant_loss()` 随后只检查这个可由调用者直接构造的字符串，因此会把未置换监督接受为 `E2-X`。
- 影响：`E2-X` 可能与 `E2-P` 使用相同物理监督，真实物理优于置换物理的核心因果对照失效。
- 必须修复：置换入口拒绝任何固定点；训练入口同时核验置换收据、源样本标识顺序和置换摘要，不能只信任 `provenance` 字符串。最好让“已验证置换监督”只能由置换构造器产生，而不能由公开数据类任意声明。

### 3. 普通 DistilBERT 没有证明加载的是冻结基础模型而非旧微调检查点

- 位置：`thesis/experiments/llm_probe/src/flow_probe/e2_distilbert.py:199-221`、`thesis/experiments/llm_probe/src/flow_probe/e2_distilbert.py:384-396`。
- 现象：`model_identifier` 虽固定，但 `model_source` 只检查目录是否存在，随后使用 `ignore_mismatched_sizes=True` 加载任意目录。实现没有调用已有的模型来源核验，也没有把权重哈希写入训练摘要；若目录恰好是同架构、同二分类头的旧微调检查点，其分类头会被直接继承。
- 影响：无法证明对比项是“普通 DistilBERT”，还可能把既有任务知识带入 E2，破坏共同预算与可复现性。
- 必须修复：对本地镜像执行模型指纹和权重哈希绑定，并与预注册基础模型制品核对；显式保证分类头从同一种子重新初始化，或只加载已核验的基础骨干再新建分类头；将来源绑定哈希写入运行收据。

## 重要问题

### 4. 共享 PINN 没有在代码入口强制共同七字段和源域训练边界

- 位置：`thesis/experiments/llm_probe/src/flow_probe/e2_shared_pinn.py:139-171`、`thesis/experiments/llm_probe/src/flow_probe/e2_shared_pinn.py:661-680`。
- 现象：模型允许任意 `input_size` 和任意注入编码器；单步训练器只接收匿名张量，不检查特征宽度、字段顺序、样本域或划分。它因此无法拒绝额外协议、测试床或标签派生字段，也无法拒绝把 C 域或最终测试标签放入检测批。
- 影响：任务 2 的七字段和源域隔离门禁不会自动延伸到 `E2-A/S/P/X`，四组结果可能与基线不在同一输入预算，甚至发生目标域泄漏。
- 必须修复：正式训练入口绑定 `E2_FEATURE_FIELDS` 及数据视图哈希，检查检测批和物理批的模型输入均精确为七列；检测批必须携带并核验 `sample_id/profile/split_id`，只允许源域训练清单。任务 4 包装器若承担该门禁，必须在启动正式运行前提供运行时断言和收据。

### 5. 物理特征与物理监督仍依赖不可审计的行位置

- 位置：`thesis/experiments/llm_probe/src/flow_probe/e2_shared_pinn.py:203-219`、`thesis/experiments/llm_probe/src/flow_probe/e2_shared_pinn.py:661-680`。
- 现象：`E2PhysicsSupervision` 没有物理样本标识或顺序哈希；`train_step()` 分别接收 `physics_features` 和监督张量后按行直接组合。检测批与物理批确实是两个独立前向，但物理特征和其真值是否一一对应无法验证。
- 影响：一次排序漂移就会把真实 `E2-P` 变成未声明的置换训练；反过来，人工设置 `provenance` 又能掩盖这种错配。物理批内部的错配会直接使状态误差、残差和检测增益失去解释性。
- 必须修复：为物理特征批和监督批携带相同的样本标识序列或绑定哈希，训练前精确比较；`E2-X` 则记录原序列、置换序列和置换哈希。不得用隐式行号作为唯一关联证据。

### 6. 四组“共同预算”只核对结构，未核对实际训练预算和初始状态

- 位置：`thesis/experiments/llm_probe/src/flow_probe/e2_shared_pinn.py:22-44`、`thesis/experiments/llm_probe/src/flow_probe/e2_shared_pinn.py:183-200`、`thesis/experiments/llm_probe/src/flow_probe/e2_shared_pinn.py:661-694`、`thesis/experiments/llm_probe/src/flow_probe/e2_shared_pinn.py:718-724`。
- 现象：`max_steps` 和 `batch_size` 只做数值合法性检查，训练器没有步数计数或批大小断言；参数签名只绑定名称、形状和可训练状态，不绑定初始化权重；优化器类型、学习率和采样计划也不在共同签名中。
- 影响：四组即使通过 `assert_shared_parameter_budget()`，仍可能从不同初值出发、使用不同批量、步数或优化器。此时性能差异不能唯一归因于物理监督开关。
- 必须修复：正式运行收据绑定同一初始化检查点哈希、优化器配置、检测与物理采样清单、批大小和总更新步数；训练器或包装器在运行时拒绝偏离预算，并在四组结束后核对实际优化步数。

### 7. 物理梯度门禁只证明进入状态头，未证明进入共享检测表示

- 位置：`thesis/experiments/llm_probe/src/flow_probe/e2_shared_pinn.py:532-558`、`thesis/experiments/llm_probe/src/flow_probe/e2_shared_pinn.py:682-692`。
- 现象：当前只计算守恒与边界目标到 `state_head` 的梯度。若任务 4 注入的编码器被冻结、意外 `detach()`，或物理分支与检测分支没有共享可训练表示，该门禁仍可能通过。
- 影响：能够证明状态头拟合物理量，却不能证明物理监督改变了检测所依赖的表示；这不足以支撑“物理信息进入检测模型”的机制解释。
- 必须修复：除状态头梯度外，记录并要求物理目标到共享编码器可训练参数的有限非零梯度；运行收据同时证明检测头和状态头确实引用同一编码器对象与同一参数集合。

## 已核实的安全边界

- `e2_hard_domain_data.py:102-146` 会拒绝目录中出现最终测试或未分配清单，并要求开发清单与 `samples.parquet` 完全一致。
- `e2_hard_domain_baselines.py:482-508` 只把源域训练和源域校准文本传入 DistilBERT 适配器；C 域只在拟合结束后进入概率前向。
