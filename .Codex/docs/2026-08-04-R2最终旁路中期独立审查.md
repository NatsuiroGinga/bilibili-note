# R2 最终旁路中期独立审查

## 审查结论

**中期裁决：存在 7 项重要问题，正式候选训练前必须修复或由正式入口提供不可绕过的运行时门禁；当前问题不阻塞实现代理继续开发。未发现已经落盘代码直接把 QUIC 回退到 UDP，也未发现 F-S 显式读取标签或 F-R 显式从校准、验证、最终测试池取供体。**

本报告是实现仍在继续变化时的只读快照，不替代实现结束后的全量独立复审。

审查快照：

- `src/flow_probe/r2_final_experts.py`：576 行，SHA-256 `9dd307512505bea75cc5882f6ea1361e14839e73c6c1aa043e570a4fabeab7b1`。
- `src/flow_probe/r2_final_views.py`：616 行，SHA-256 `1208756be6e9a6bdc4e55f5b19b9835074afc3b7e14a7d34829ee80ae5971e49`。
- 审查方式：只读静态审查与调用点检索；未运行格式化、测试、静态检查、Git、服务器或实验命令。

## 重要发现

### 1. QUIC 监督掩码可被调用方传入的专家名绕过

位置：`src/flow_probe/r2_final_experts.py:554`、`src/flow_probe/r2_final_experts.py:567`

`expert_state_supervision_loss` 同时接收带有 `output.expert_name` 的输出和独立的 `expert_name` 参数，但没有确认二者一致。是否施加 `qlog_truth_available` 完全由外部参数决定。若 QUIC 输出被误传为 TCP、UDP 或任意字符串，代码会跳过 qlog 可用性掩码，仍然计算状态监督损失。

影响：训练期特权 qlog 监督边界不是不可绕过的；调用错误可让 QUIC 专家使用不满足 qlog 门禁的真值，破坏“qlog 只作合格训练监督”的合同。

修复门槛：从 `output.expert_name` 唯一决定专家类型，或先严格断言外部参数与输出身份相等；未知专家名必须拒绝。QUIC 损失还应与冻结的真值字段适用掩码共同过门。

### 2. 最终测试保护是读取后拒绝，而不是读取前拒绝

位置：`src/flow_probe/r2_final_views.py:252`、`src/flow_probe/r2_final_views.py:255`、`src/flow_probe/r2_final_views.py:259`、`src/flow_probe/r2_final_views.py:300`

`load_base_views` 只检查调用方提供的 `final_test_visible` 布尔值，随后验证哈希并打开三个 Parquet；直到数据已经读入内存后才检查 `split_id`。冻结清单也只验文件哈希，没有解析其中的制品角色、开发边界与哈希绑定。

影响：配置误绑最终测试制品时，函数会在报告错误前完成禁止的文件读取。调用方把布尔值写成 `false` 不能证明真实路径属于开发区。

修复门槛：打开数据制品前解析并验证冻结清单，要求三个制品以开发区角色和预期哈希显式登记；规范化路径、制品标识和划分集合必须在任何 Parquet 打开前过门。最终测试路径或角色不得仅靠文件内 `split_id` 事后发现。

### 3. F-S/F-R 使用原始路由分层，会跨越 QUIC 的有效路由

位置：`src/flow_probe/r2_final_views.py:393`、`src/flow_probe/r2_final_views.py:399`、`src/flow_probe/r2_final_views.py:424`、`src/flow_probe/r2_final_views.py:513`

`_sample_stratum` 只使用来源和原始 `route_indices`。它没有纳入逐样本 `quic_applicable`，也不知道检查点级 `quic_expert_ready`。因此原始路由同为 QUIC 的样本会进入同一供体层，即使一个样本实际进入 QUIC 专家、另一个样本结构关闭后实际进入 UNKNOWN。

影响：F-S 可能把真实 QUIC 专家输出与 UNKNOWN 回退输出互换，违反“不跨来源、路由、划分”的整段置换合同；F-R 也可能从不同有效路由的开发训练样本抽取随机旁路。这会混淆物理对照的归因。

修复门槛：供体分层必须绑定专家系统实际使用的 `effective_route_index`。若视图层自行推导，必须同时输入并冻结 `quic_expert_ready`，且推导结果与专家前向收据一致；不能只增加原始 QUIC 名称。

### 4. 统一序列和物理序列没有样本身份与顺序绑定

位置：`src/flow_probe/r2_final_views.py:476`、`src/flow_probe/r2_final_views.py:487`、`src/flow_probe/r2_final_views.py:547`、`src/flow_probe/r2_final_views.py:562`

`build_variant_views` 接收按划分命名的裸 `np.ndarray`。当前只检查键集合、形状与有限值，没有携带或验证 `sample_id`、稳定顺序、生产配置、专家检查点或数组语义哈希。只要长度与维数相同，错序数组、错划分数组或其他检查点数组仍会通过，并在输出侧生成看似完整的新哈希。

影响：五组可能在表面样本清单一致时消费错位旁路；F-R 声称的开发训练供体也可能只是键名为 `train-fit` 的错误数组。该问题会直接使配对比较失效。

修复门槛：将序列包装为带 `sample_id` 顺序摘要、划分、模型或检查点摘要、字段语义和数组哈希的不可变制品；进入 `_variant_split` 前逐项绑定到 `BaseSplit`。不接受无法证明来源和顺序的裸数组。

### 5. 推理路由可见证据没有机器绑定，布尔转换还会把字符串 false 解释为 true

位置：`src/flow_probe/r2_final_views.py:208`、`src/flow_probe/r2_final_views.py:227`、`src/flow_probe/r2_final_views.py:287`

路由制品只要求最终路由名、置信度和 `quic_applicable`，代码没有解析证据来源或生成器合同，无法证明这些值只来自推理可见协议证据而非 qlog、标签、采集配置或路径。与此同时，`window_valid` 与 `quic_applicable` 使用 pandas `.astype(bool)`；字符串 `"false"` 或 `"0"` 都会变成 `True`。

影响：特权信息生成的 QUIC 适用位可以无痕通过；合法含义为假的字符串列也会错误激活 QUIC 专家或无效窗口。

修复门槛：冻结清单必须绑定路由生成器、允许的可见证据字段和禁止字段审计摘要；读取时严格要求布尔架构或精确的整数 `0/1`，拒绝字符串、空值和其他数值。路由制品必须提供可审计但不进入分类输入的证据类型。

### 6. `quic_expert_ready` 已与逐样本 qlog 分离，但仍是未绑定检查点的普通布尔值

位置：`src/flow_probe/r2_final_experts.py:381`、`src/flow_probe/r2_final_experts.py:389`、`src/flow_probe/r2_final_experts.py:434`、`src/flow_probe/r2_final_experts.py:454`

当前版本已经正确把 `quic_expert_ready` 改为独立构造参数，不再等同于逐样本 `qlog_truth_available`。但该状态只是普通 Python 布尔属性，不进入 `state_dict`，也没有与 QUIC 训练连接清单、实现或配置分组、检查点摘要和门禁收据绑定。`ExpertConfig.enabled` 与 `required_truth_fields` 也没有形成一致性断言。

影响：调用方可对未训练、仅用现有 59 条机制检查连接训练、错检查点或配置上禁用的 QUIC 专家传入 `true`，从而在推理期正式启用。现有 59 条连接不具备这一授权；新 600 条连接也必须按实现与配置分组形成训练门禁。

修复门槛：就绪状态必须来自检查点内不可分离的元数据和正式运行时断言，至少绑定训练清单摘要、独立连接数、实现或配置分组、所需真值字段、检查点摘要和门禁版本。现有 59 条连接只能生成 `ready=false` 的机制检查收据；调用参数不得覆盖失败收据。

### 7. F-A 等参数容量目前只能计数，不能执行硬对照

位置：`src/flow_probe/r2_final_experts.py:535`、`src/flow_probe/r2_final_views.py:500`、`src/flow_probe/r2_final_views.py:547`

专家模块提供通用 `count_parameters`，视图模块也为 F-A 接收统一序列，但当前没有等容量统一支路的构造、参数匹配算法、容差或相等断言，也没有把参数收据绑定到 F-A/F-P 视图。F-H/F-P/F-S/F-R 的张量末维可以一致，但张量形状不能证明可训练容量和训练预算公平。

影响：当前接口可以接入任意规模的 F-A 统一分支；若正式入口只记录输出形状，就无法排除 F-P 的额外参数容量解释。

修复门槛：正式入口必须构造明确的等容量 F-A 分支，在优化器建立前同时记录 F-A/F-P 总参数、可训练参数和冻结阶段参数，并以事先冻结的精确相等规则或容差硬拒绝不匹配。收据需绑定配置和检查点，不能只在日志中打印。

## 已确认正确的中期性质

- `r2_final_experts.py:437-440` 对路由索引、置信度和 `quic_applicable` 调用停止梯度。
- `r2_final_experts.py:454-458` 在 QUIC 不适用或专家未就绪时把有效路由改为 UNKNOWN。
- `r2_final_experts.py:493-498` 有显式断言，QUIC 请求不得进入 UDP 专家。
- `r2_final_experts.py:511-529` 提供分类阶段冻结全部物理参数和可训练参数检查接口。
- `r2_final_experts.py:567-571` 的设计意图是只让 `qlog_truth_available` 影响训练监督损失，未把它传入专家推理前向；修复发现 1 后可以满足该边界。
- `r2_final_views.py:399-421` 的 F-S 供体选择没有读取标签，且原始实现已按来源、原始路由和划分分层并避免自配对。
- `r2_final_views.py:519-524` 与 `r2_final_views.py:574-577` 的 F-R 生产调用显式只传 `base.train` 和 `physics_sequences["train-fit"]`；修复发现 4 的身份绑定后，可证明训练池边界。
- `r2_final_views.py:492-498` 为五组统一旁路末维提供相同形状与有限值检查；这能证明张量接口一致，但不能代替信息来源、顺序与参数容量证明。
- `r2_final_views.py:558-564` 冻结组别、种子 42/43/44 和三个开发划分键集合。

## 正式入口仍需复审的门禁

以下内容尚未在本次两个文件中形成完整调用链，不能提前判为通过：

- 物理训练结束后必须先冻结专家，再建立或启动分类优化；分类反向后检查物理专家参数无梯度、参数摘要不变，路由生成器不可训练。
- 外层分类模型调用 `.train()` 后不得重新开启物理专家的训练模式；冻结专家输出应在分类阶段保持确定性。
- F-P 输出目前已在专家内部按路由置信度缩放，视图又导出 `sidecar_gate`；训练入口必须证明不会再次对同一信号重复加门。
- 单组单进程要求需要由正式包装器硬拒绝，而不是只依赖 `build_variant_views` 的文档字符串。
- 所有五组必须绑定完全相同的文本、标签、样本顺序、训练预算、检查点选择规则和分类阈值，并生成机器可读收据。
- 最终测试必须在配置解析和制品打开前保持不可见；不能把“读取后抛错”当成防泄漏成功。
