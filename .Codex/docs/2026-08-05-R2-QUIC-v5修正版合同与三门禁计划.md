# R2 QUIC v5 修正版合同与三门禁计划

## 目标

依据 QUIC 官方规范、`aioquic`/`quiche` 实现证据和 v4 通用字节账实现，建立不追溯修改旧 v3/v4 证据的新 v5 合同，并执行唯一一次 `aioquic → quiche → aioquic` 三轮端到端门禁。

## 冻结修正

- 最大数据报由实现与配置派生：`aioquic 1.3.0` 为 `1200` 字节，`quiche 0.24.5` 为 `1350` 字节；`65535` 仅为接收缓冲，不得作为合法数据报上限。
- 每方向用户态代理容量固定为 `2 MiB`，只作为本轮预注册工程硬上限；`80%` 仅报告余量诊断，不作为科学通过条件或物理定容结论。
- 字节账严格拆为 `waiting_bytes`、`in_service_bytes`、`delay_inflight_bytes`；服务完成后才进入传播阶段，逐事件收据使用单调纳秒时间并可离线重放。
- 记录端点计划发送时间、实际发送时间、迟发量和节奏有效性；`quiche` 必须处理或显式记录 `SendInfo.at`，不得把未核验突发直接解释为网络拥塞。
- 随机丢包与用户态容量丢包分账；冻结 `p03/seed43/bulk` 三轮中二者都必须为零，响应、收发和三类字节账必须守恒。

## 三轮身份

1. `run1`：`aioquic`，方向种子 `12`。
2. `run2`：`quiche`，方向种子 `32`。
3. `run3`：`aioquic`，方向种子 `12`，用于重复性核验。

三轮严格串行，每轮使用新进程、空状态、新数据根和独立启动器目录；不得复用旧 v3/v4 运行结果，不重试失败轮次，不补第四轮。

## 单轮门禁

1. 固定四元组、源端口、实现版本、方向种子、64 MiB 响应和配置哈希与合同一致。
2. qlog、PCAP、状态摘要、逐事件账本、节奏收据和制品清单存在，大小与 SHA-256 可重算。
3. `waiting + in_service + delay_inflight` 的逐事件变化可重放，容量不超过 `2 MiB`，最终全部归零。
4. 随机丢包、用户态容量丢包、截断、重复发送和无法归账字节均为零；响应完整且收发守恒。
5. `80%` 仅输出诊断；超过不自动失败，只要不超过硬容量且全部账目守恒。

## 总体裁决

- 三轮全部通过且身份、顺序、版本和制品绑定一致，状态为 `GO_TO_NEW_FIELD_MATRIX_QUIC_SEED_ONLY`。
- 任一轮失败，状态为 `NO-GO_KEEP_QUIC_UNKNOWN`；不得调容量、改阈值、补跑或接受少量丢包。
- 即使通过，也只授权新的 QUIC 种子字段矩阵。达到 600 条正式连接、来源与真值审计及实现/配置组冻结前，QUIC 仍不得进入正式专家效果主张。

## 新版旁路实验接入目标

- v5 三轮通过后立即物化新的 QUIC 字段矩阵，并扩充到至少 600 条相互独立、来源可审计的正式连接；实现、配置组、方向、拥塞与非拥塞状态必须有明确覆盖和分组收据。
- 在新版旁路实验启动前，只有连接数、来源/真值审计、字段缺失率、实现/配置组、训练清单、检查点和 v5 门禁全部绑定通过，才允许设置 `quic_expert_ready=true` 并加入 QUIC 专家。
- 条件未满足时继续使用 `UNKNOWN`，不得把 UDP 当作 QUIC 回退，不得在实验运行中途补数据或切换专家。是否启用必须在训练前冻结并写入配置与运行清单。
- QUIC 专家加入后必须单独报告 QUIC 路由覆盖、状态误差、残差、检测增益和置换对照；不能只用 TCP/UDP 总体指标代替。
