## 1. 实施边界

本任务只实现前 80% 四段开发可见区。测试全部使用人工成员、人工标签和人工特征；未读取真实 LSPR24 标签、攻击叙事、最终 20% 内容或全量数据，未运行正式全量物化。

实现不提供最终测试范围类型、最终输出路径或最终物化调用。`G0-A12` 和最终哈希状态在 G0-D 阶段固定为 `NOT_READY`。

## 2. 实施结果

- 开发路由器只持有无标签开发选择收据；收据摘要绑定当前合同、开发成员、源行号和四段标识。
- 标签行先按成员标识验证是否属于开发选择，未入选行在标签规范化前静默丢弃，不产生排除原因、计数或哈希。
- 开发成员标签规范为 `benign/malicious` 二元闭集；非法开发标签失败关闭。
- 以原始流摘要定义重复类；同类规范标签冲突时整类开发成员隔离，只统计开发区内部冲突类和成员。
- 物化器只连接已经路由的开发标签与对应特征；非开发特征在计数、哈希和序列化前丢弃。
- 开发行按开发段和成员稳定键确定性输出；收据只保存开发行数、开发语义 SHA-256 和无标签切分收据 SHA-256。
- 正式输出使用既有 `PartialOutput` 排他发布；验证失败发生在创建暂存文件之前，写入或发布失败由资源守卫清理 `.partial`。
- 原始门禁映射不再把 `checks`、`status` 或 `evidence.complete` 等生产者布尔值当作独立证据；未接入独立谓词的项目全部失败关闭为 `NOT_READY`。
- 新增开发专用命令入口和 v4 开发配置；入口只接受四种开发段，不含最终测试范围或输出字段。
- 已删除旧 G0-F sealer 模块、sealer 目标测试、`ring` 直接依赖、`seal_committed` 前置和旧 `formal-v3` 配置。

## 3. 测试驱动证据

### 3.1 开发路由红灯

命令：

```bash
cargo test --manifest-path tools/lspr24_g0/Cargo.toml --locked --test development_router_contract
```

首次有效结果：退出码 `101`。编译器报告 `E0432`，缺少 `DevelopmentLabelRow`、`DevelopmentMemberId`、`DevelopmentRouter`、`DevelopmentSegment`、`DevelopmentSplitReceipt` 等新版 G0-D 接口。

### 3.2 开发物化红灯

命令：

```bash
cargo test --manifest-path tools/lspr24_g0/Cargo.toml --locked --test materialize_contract
```

首次运行发现测试自身使用了非法非 ASCII 字节串字面量，该结果不计作有效红灯。只修正该测试字面量后重跑，退出码 `101`；首个有效失败为 `E0432`，缺少 `DevelopmentFeatureRow` 等新版接口，且旧 `materialize_development` 仍要求已废弃的四参数 G0-F 签封前置。

### 3.3 生产者布尔值回归红灯

首轮实现转绿后，在同一物化目标中补充 `A02 evidence.complete=true` 不得成为原始证据的承重断言。测试退出码 `101`，`2 passed; 1 failed`；失败显示实际状态为 `PASS`、预期为 `NOT_READY`。随后删除该布尔捷径，未接入独立谓词时统一失败关闭。

### 3.4 最终绿灯

两条精确命令在最终生产代码上重新执行：

- `development_router_contract`：退出码 `0`，`3 passed; 0 failed`。
- `materialize_contract`：退出码 `0`，`3 passed; 0 failed`。

编译与测试输出无警告。

移除 `ring` 直接依赖后，首次 `--locked` 绿灯尝试在编译前因锁文件需要同步而退出 `101`；只执行一次离线 `cargo generate-lockfile`，随后继续使用上述两条 `--locked` 目标命令。
