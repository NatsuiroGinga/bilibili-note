## 三、关键实现裁决

1. 源 CSV 仅通过 `pyarrow.csv.open_csv` 逐批解析，`ConvertOptions.include_columns` 按字段名投影，83 字段显式为 `float64`，不使用全量 `read_csv`。
2. Raw83 只将非有限值和有全文数据定义的结构非法值变为规范 NaN。普通字段的有限负值保留并单独计数。端口要求整数且在 `[0,65535]`，两个协议字段要求整数，三个粗拓扑字段要求 `{0,1}`。
3. 原始 IP 只在批内计算无向对 SHA-256，不落入模型数据根。流侧车只保存 `uint32` 实体编号，实体表只保存不可逆摘要。
4. 标签只在流式解析进程内归一为二元值，记录内容 SHA-256 与正负聚合，不写任何逐样本标签文件。`LabelResolver` 还会依照 `train/validate` 序列行反算允许流位图，拒绝跨用途读标签。
5. P2 对旧 `I/M/E/T` 每个文件计算 SHA-256，复制后再验哈希，并重算冻结的 `208598/22444` 序列划分。同时验证掩码尾置、流全覆盖无重复、实体一一映射、序列内时间单调和 `T23` 首流身份。
6. A 臂两遍扫描训练有效流：先得均值，后按均值填补并分批 `StandardScaler.partial_fit`。保存 `mean_/var_/scale_`，常量列 `scale=1`，全年视图裁剪到 `[-10,10]`。
7. B 臂先生成 76 列训练均值填补 `float32` 映射，逐列用 `np.std(...,ddof=0)` 得标准差。一次 `default_rng(42).standard_normal((n_train,76),dtype=float64,out=...)` 写 C 行主序映射，再按官方 `1e-3/max(std,1e-3)` 原位加入 `float32` 训练映射。此后逐列拟合共同 `references_` 与地标，每列有原子收据。
8. P1、P4 和 P5 分别保存批/列收据。源 ZIP 续跑时从头重放，已完成批重算内容、累计统计与标签哈希后才跳过写入。最终文件改名与阶段状态封印之间中断时，续跑直接重验最终文件，不会新建空部分文件。

### 4.1 环境实测

本工作树独立 `.venv` 没有 NumPy、PyArrow 和 scikit-learn。本轮只读复用主工作区既有环境，实测为：

- NumPy `2.2.6`；
- PyArrow `25.0.0`；
- scikit-learn `1.7.2`。

该组版本与当前 `uv.lock` 在 Python 3.10 的解析一致，但它不能代替 B76 运行前的真实版本门。

### 4.2 实测签名

```text
pyarrow.csv.open_csv(input_file, read_options=None, parse_options=None, convert_options=None, memory_pool=None)
numpy.random.Generator.standard_normal(size=None, dtype=float64, out=None)
StandardScaler.partial_fit(self, X, y=None, sample_weight=None)
QuantileTransformer(*, n_quantiles=1000, output_distribution='uniform', ignore_implicit_zeros=False, subsample=10000, random_state=None, copy=True)

```

Context7 的首次 PyArrow 查询返回空输出，因此未把它冒充为已核证来源。随后使用官方文档核对：

- Apache Arrow 25 文档确认 `open_csv` 为单线程流式读取，`ConvertOptions` 支持 `include_columns` 和 `column_types`。
- NumPy 官方文档确认 `standard_normal(size=None,dtype=np.float64,out=None)`，`out` 必须与 `size` 和 dtype 匹配。
- scikit-learn 官方文档确认 `StandardScaler.partial_fit`、总体方差 `ddof=0`、`QuantileTransformer` 参数及 `quantiles_/references_` 属性。

## 七、真实运行前未关闭风险

1. B76 必须先运行同一 `--validate-config`，并核对实际 NumPy、PyArrow 和 scikit-learn 版本等于锁定环境。
2. 官方单次行主序随机映射与内存一次生成的逐位一致性必须由真实目标版本门验；当前只有签名和静态实现证据。
3. 旧 `I/M/E/T` 的完整 SHA-256、行全覆盖、实体映射、冻结计数和时间顺序要在 P2 真实运行后才能确认。
4. P4 需要约 `9.26 GiB` 噪声临时映射和 `4.63 GiB` 加噪训练映射；启动器按实际已存文件重算“尚未存在”空间，但真实排序峰值仍须资源收据核验。
5. 当前只是数据产品实现，不证明 A/B 输入臂、表格 ResNet、FT-Transformer 或任何第三章机制有效。
