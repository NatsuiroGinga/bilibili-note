# RWKV 方案数据与实验独立复审

- 日期：2026-08-05
- 审查性质：独立、只读、数据与实验可行性复审
- 审查边界：未运行训练，未下载数据，未修改生产代码、恢复文档或实验制品
- 当前前提：RWKV 是 PINN/R2 最终失败或用户明确切换路线后的替代主题，不是已冻结主线

## 1. 直接裁决

**总体裁决：有条件可启动。当前只能启动 CPU 数据门禁，不能启动 RWKV 模型实现、GPU 训练或正向效果主张。**

| 对象 | 裁决 | 原因 |
| --- | --- | --- |
| 现有冻结 GeNIS/TQH-C2 直接训练 | **不可启动** | 模型就绪视图没有同父会话长度 4/16/32 的序列；GeNIS 逐包身份映射已被硬否决 |
| 现有 TQH-C2 逐包数据重新物化 | **有条件可启动 CPU 审计** | 包数足以形成候选序列，但 16/32 的序列语义、标签时点、父键和防泄漏清单尚未冻结 |
| UGR'16 v3 官方特征数据审计 | **可启动 CPU 门禁** | 分钟级连续状态和攻击计数标签与“网络攻击状态检测”匹配，但尚未下载、哈希和字段审计 |
| CTU-13 官方双向 NetFlow 审计 | **可启动 CPU 门禁** | 官方提供逐流标签和 13 个场景，但父序列定义、场景隔离与地址捷径尚未审计 |
| 单卡 RTX 5090 先导 | **当前不可启动** | 数据门禁、序列入口、强基线和 2×2 消融均未闭合 |
| RWKV 替代论文路线 | **有条件成立** | 必须先改正任务单位和题目，并由 CPU 门禁证明长历史相对当前窗口确有可检验价值 |

推荐题目改为：

> **《面向长时网络流量的 RWKV 多尺度攻击状态检测与时间漂移校准方法研究》**

该题目允许 UGR'16 承担分钟级攻击状态主证据，也避免把分钟聚合误写成单连接、单流或加密流检测。

若题目必须保留“恶意流量检测”，则应改为：

> **《面向恶意流量时序建模的 RWKV 状态检测与跨场景校准方法研究》**

采用第二个题目时，CTU-13 必须成为逐流主证据；UGR'16 只能作为网络级长时状态外部面板。

## 2. 同一父会话 4/16/32 序列裁决

### 2.1 现有模型就绪视图：不能形成

| 数据 | 已核验证据 | 裁决 |
| --- | --- | --- |
| GeNIS | `runs/data-audit/r2-genis-global-assignment-v0/run_manifest.json` 的 3,973 个候选中，身份缺失 163、持续时间不匹配 94、重复 `FlowID` 候选 3,056，`semantic_decision=NO-GO` | 不得用时间邻近、标签或重复 `FlowID` 补拼序列 |
| TQH-C2 冻结协议 | `tqhc2_cell_indomain` 训练 27,235 条、验证 4,000 条；父会话数分别也是 27,235 和 4,000，长度至少 4/16/32 的父会话均为 0 | 每个允许父会话只有一条 `full_flow`，不能直接训练序列模型 |
| TQH-C2 物化语义 | `src/flow_probe/tqh_c2.py` 将每条样本写为 `sample_unit=full_flow`、`parent_session_id=session.uid`、`window_ordinal=0` | `parent_session_id` 存在不等于已经存在多窗序列 |
| GeNIS 冻结模型列 | `src/flow_probe/genis_candidate.py` 只保留聚合模型字段及缺失掩码，没有足以恢复冻结会话顺序的起止时间列 | 当前冻结分类视图不能反向恢复有序历史 |

直接答案是：**当前批准的冻结模型视图不能形成同一父会话长度 4/16/32 的无泄漏序列，RWKV 数据门禁仍未通过。**

### 2.2 已有逐包数据：存在重物化潜力，但不能写成已通过

TQH-C2 逐包制品提供 `sample_id`、`packet_index`、`delta_time_us` 和网络层长度，可在同一完整流内重物化因果包序列。已有只读审计给出两组证据：

| 审计范围 | 总样本数 | 现有四窗全有效 | 至少 16 包 | 至少 32 包 | 限定 |
| --- | ---: | ---: | ---: | ---: | --- |
| 旧开发试点 | 2,560 | 2,502 | 1,672 | 1,230 | 四窗全有效实际要求至少 9 包 |
| 当前 TQH `train-fit` | 3,606 | 3,486 | 2,268 | 1,646 | 现有合同只冻结了四窗 |
| 当前 TQH calibration | 2,000 | 1,993 | 1,735 | 1,354 | 三拆分 `sample_id` 交集为 0 |
| 当前 TQH dev-validation | 2,000 | 1,909 | 1,027 | 660 | 尚无 16/32 序列合同 |

关键边界如下：

- “至少 32 包”只证明可以构造 32 个包标记或若干包块，不证明存在 32 个固定时长窗口。
- 2,560 条试点流的持续时间中位数仅 46.61 毫秒，75 分位约 0.472 秒，95 分位约 8.05 秒。它可验证包级因果状态，不足以支撑“长时网络状态”主张。
- 当前四窗合同采用 `[0,2)`、`[2,4)`、`[4,8)`、`[8,end)`，不能事后把它解释成 4/16/32 三个长度档。
- 若新建 16/32 序列，必须先固定标记单位、决策时点、短流掩码、父键、标签时点、分割顺序和重叠窗口统计，再从逐包源确定性双物化。
- 不得删除短流来制造长度 32 的平衡样本。短流与 `profile`、协议和标签有关，按长度筛样会改变任务分布。

因此，TQH-C2 的正确状态是：**可重物化候选，不是已有长序列。**

## 3. UGR'16 与 CTU-13 的职责

### 3.1 UGR'16 v3 能支持什么

UGR'16 官方特征仓库说明 v3 包含：

- 训练输入 `72,644 × 134`，训练标签 `72,644 × 8`。
- 测试输入 `43,200 × 134`，测试标签 `43,200 × 8`。
- 每行对应一分钟，八维标签是该分钟内八类攻击的流计数。
- v3 使用双向流生成特征，并从训练期排除了已知存在污染问题的六月部分。

这组标签可以支持：

- 分钟级是否存在攻击的二分类，定义为 `sum(Y_t) > 0`。
- 分钟级八类攻击的多标签检测或攻击计数回归。
- 按连续分钟构造 4/16/32 分钟的因果历史。
- 按天、周和时间前向块评价漂移、最差时段、误报率与发现延迟。

这组标签不能支持：

- 判断某一条 NetFlow 是否恶意。
- 判断某个单连接或父会话是否恶意。
- 报告逐流精确率、逐连接召回率或逐包定位能力。
- 把相邻滑窗当成相互独立的统计样本。

因此，UGR'16 **不能补齐“同一父会话”这一原门禁**。若采用推荐题目，应把门禁明确改为“同一连续采集段的 1/4/16/32 分钟因果序列”，并用 `continuous_segment_id` 或周级时间块作为父组。此时 UGR'16 可以成为主开发数据，不只是外部验证。

UGR'16 还存在一个必须先关闭的来源门禁：数据论文登记的许可证为 `CC-BY-NC`，官方特征仓库的 `LICENSE.txt` 则是 `GPL-3.0`。下载前必须确认具体数据文件适用的许可证，并保存发布页、版本、文件大小和 SHA-256；不能把仓库代码许可证自动当成数据许可证。

### 3.2 CTU-13 能支持什么

CTU-13 官方页确认：

- 数据由 13 个恶意软件捕获场景组成。
- 官方发布包含带标签的双向 NetFlow，标签覆盖 Botnet、Normal 和 Background。
- 官方总包约 1.9GB，数据集采用 `CC-BY`。
- 标签是逐流写入的，适合验证恶意流量或僵尸网络流检测。

CTU-13 尚未证明：

- 同一五元组的多行一定属于同一连接，而不是端口复用、超时切流或 Argus 更新记录。
- 13 个场景可以在不共享恶意软件、主机、地址和采集配置捷径的前提下形成训练、校准、开发验证和最终测试。
- Background 可以无条件并入 Normal。官方定义中 Background 是不能确定为正常或恶意的其余流量，应作为单独标签或敏感性面板。

CTU-13 应先审计“场景内按主机或稳定行为实体组成有序流序列”，不应先假定可以恢复单连接 4/16/32 窗口。

### 3.3 推荐职责划分

| 数据 | 推荐职责 | 统计单位 | 禁止用途 |
| --- | --- | --- | --- |
| UGR'16 v3 | 主开发、主长时攻击状态面板、时间漂移与校准 | 天或周级连续时间块 | 逐流、逐连接恶意检测主张 |
| CTU-13 | 冻结方法后的逐流外部复现、跨场景与僵尸网络面板 | 场景或恶意软件组 | 与 UGR 行级混合、共享一个主分数 |
| TQH-C2 | 包级因果递归机制诊断 | 完整父流或采集单元 | 长时网络状态主证据 |
| GeNIS | 重新冻结前暂停 | 未定 | 绕过 `NO-GO` 直接补拼历史 |

UGR 与 CTU 的 134 维分钟计数和逐流 NetFlow 字段不同。外部验证应重新训练同一算法和冻结机制，或预先定义共同字段适配器；不能默认把 UGR 检查点直接迁移到 CTU，并把失败或成功写成跨域迁移结论。

## 4. 两个创新点的最小实验矩阵

### 4.1 可证伪假设

| 假设 | 最小可证伪条件 |
| --- | --- |
| 创新一：多尺度 RWKV 状态 | `R10` 相对普通 `R00` 在预注册困难时间块改善主指标，并优于历史置乱/状态重置负对照 |
| 创新二：漂移感知校准 | `R01` 相对 `R00`、`R11` 相对 `R10` 同时改善校准或风险覆盖，并保持检测指标在冻结非劣界内 |
| 组合协同 | `R11` 同时优于 `R10` 和 `R01`；若只等于其中一个，不能声称两个机制形成组合创新 |
| RWKV 架构价值 | 普通 `R00` 必须先相对任务适配的 GRU、因果 Transformer 和 Mamba 证明准确率或预先选择的效率优势 |

四个必要方法组为：

| 组 | 多尺度状态 | 漂移校准 | 责任 |
| --- | --- | --- | --- |
| `R00` | 关闭 | 关闭 | 普通 RWKV 基线 |
| `R10` | 开启 | 关闭 | 创新一独立贡献 |
| `R01` | 关闭 | 开启 | 创新二独立贡献 |
| `R11` | 开启 | 开启 | 完整方法和协同 |

### 4.2 强基线

最小公平基线不能只包含 HGB、GRU、轻量 Transformer 和普通 RWKV。还必须包含与当前证据最接近的线性状态空间基线。

| 类别 | 必须包含 | 公平要求 |
| --- | --- | --- |
| 平坦传统 | HGB、XGBoost | 当前窗口下界和同历史预算的展平/因果摘要版本分开报告 |
| 递归神经 | GRU | 参数量、输入、训练步数和调参次数与 RWKV 匹配 |
| 注意力 | 因果 Transformer | 不读取未来分钟，使用相同历史长度和标记 |
| 线性状态空间 | Mamba 或同等级实现 | NetMamba 是当前最直接的网络流量相邻证据，缺失会形成弱基线风险 |
| 校准 | 温度缩放、保序回归或冻结共形方法中的至少两项 | 只能用 calibration，不得用开发验证或最终测试拟合 |
| 因果负对照 | 历史置乱、状态重置、当前窗口 `k=1` | 排除模型只利用当前分钟或容量正则化的解释 |

现有 `llm_probe` 只能复用部分基础设施：

- `src/flow_probe/tabular_baselines.py` 有 HGB/XGBoost 平坦入口和既有运行记录，但当前读取的是全流平坦字段，不是同历史预算序列。
- `observability_diagnostic.py`、`r2_final_experts.py` 和 `r2_final_distilbert_probe.py` 中的 GRU 是物理回归或旁路组件，不是参数匹配的独立序列分类基线。
- 当前源码没有面向本门禁的普通 RWKV、Mamba 或因果 Transformer 分类入口。
- `thesis/experiments/rwkv_probe/` 当前不存在，不能把计划中的模型矩阵写成“入口已就绪”。

### 4.3 分阶段矩阵

| 阶段 | 矩阵 | 运行数 | 裁决作用 |
| --- | --- | ---: | --- |
| D0 数据门禁 | UGR v3 与 CTU-13 来源、标签、字段、父组、时间、拆分、泄漏和哈希 | CPU，不训练 | 任一硬门禁失败即停止 |
| P1 单种子筛错 | GRU、因果 Transformer、Mamba、`R00` × `k=1/4/16/32` × 种子 42 | 16 个 GPU 运行 | 只允许淘汰，不允许正向结论 |
| P1 传统基线 | HGB、XGBoost × `k=1/4/16/32` | 8 个 CPU 运行 | 给出当前窗口和同历史预算强下界 |
| P2 机制确认 | 最强非 RWKV 基线、`R00/R10/R01/R11` × `k=32` × 种子 42/43/44 | 15 个单元，13 个新增 GPU 运行 | 2×2 独立效应与协同 |
| P3 长度交互 | 最强非 RWKV 基线、`R00`、`R11` × `k=4/16` × 三种子 | 18 个单元，14 个新增 GPU 运行 | 证明收益随历史长度变化，而非只来自容量 |
| P4 因果负对照 | `R11` 的历史置乱与状态重置，先种子 42，必要时补三种子 | 2 至 6 个 GPU 运行 | 排除非时序解释 |
| E1 CTU 外部面板 | 最强非 RWKV 基线、`R00`、`R11` × 固定长度 × 三种子 | 9 个 GPU 运行 | 逐流/跨场景外部复现 |

去除阶段间重复后，小型完整矩阵约为 **54 至 58 个 GPU 运行**。其中 UGR 决策级门禁在 P1、P2 和最小负对照完成后即可裁决，不需要等待 CTU 外部面板。

P1 的配置筛选和“最强非 RWKV 基线”选择只能使用 calibration。开发验证在配置、阈值、检查点和成功轨全部冻结后只评价一次，不能成为逐阶段反复选择的公开排行榜。

不得同时展开“两个数据集 × 四个长度 × 全部模型 × 全部消融 × 三种子 × 多档参数规模”。该笛卡尔矩阵会在调参前就超过 150 个 GPU 运行，不能称为最小先导。

### 4.4 指标和统计单位

UGR 主面板建议采用：

- 主指标：分钟级二分类 `AUPRC`，或预注册的多标签宏平均 `AUPRC`，二者只能预先选择一个主指标。
- 安全指标：每小时误报数、事件级召回率、检测延迟、最差周性能。
- 校准指标：Brier 分数、校准误差和风险覆盖曲线。
- 长历史指标：`k=1` 对 `k=4/16/32` 的配对差异，以及历史置乱差异。
- 统计单位：天或周级连续时间块，不是重叠分钟窗。

CTU 外部面板建议采用：

- 主指标：Botnet 对 Normal 的宏平均 F1 或 `AUPRC`，预先固定其一。
- Background：单独报告，不能静默并入 Normal。
- 统计单位：场景或恶意软件组，不是 NetFlow 行。

三个训练种子不能当作三个独立数据样本。应采用两层配对重采样：第一层训练种子，第二层 UGR 的天/周块或 CTU 的场景组，并报告原始种子结果、效应量、95% 区间和失败项。

## 5. 单卡 RTX 5090 可行性

### 5.1 结论

**单卡 32GiB RTX 5090 可以完成小型矩阵，算力不是当前主阻塞。数据定义、基线实现和无泄漏统计才是主阻塞。**

### 5.2 推荐规模

| 项目 | 先导上限 | 理由 |
| --- | --- | --- |
| RWKV 参数量 | 首轮不超过 100M | UGR v3 只有 72,644 个训练分钟，450M 容易过参数化且不增加数据证据 |
| 序列长度 | `1/4/16/32` 个一分钟状态 | 当前数据门禁是 32，不应无依据写成 512/2048 |
| 精度 | `bf16` | 与 5090 兼容并保留数值审计 |
| 峰值显存 | 小于 26GiB | 为 32GiB 保留约 20% 余量 |
| 优化器 | 普通或 8 位优化器均可，但全矩阵冻结一致 | 不能只为某一模型改变有效批量或步数 |
| 模型保存 | 每运行保留冻结最佳检查点、配置、预测和资源记录 | 不保存无用逐步副本，预计需约 20 至 60GB |

现有资源估计为每个小模型每种子约 15 至 30 分钟，CTU 约 10 至 25 分钟。这些数字是计划假设，不是 5090 实测。

按 54 至 58 个运行估算：

- 纯 GPU 时间约 13 至 28 小时。
- 加上每族最多两个仅使用 calibration 的调参试验、失败留痕、资源采样和进程切换，建议预留 20 至 45 小时。
- 单卡顺序执行的日历时间约 2 至 4 天。
- UGR CPU 物化预计 1 至 4 小时，CTU CPU 审计预计 2 至 8 小时；二者必须先完成。

450M、长度 512/2048 或多档参数规模只能在 100M 小矩阵通过后单独授权。若小矩阵失败，不得用增大模型补救研究假设。

## 6. 主要风险

### 6.1 P0 数据泄漏风险

| 风险 | 当前证据 | 强制处置 |
| --- | --- | --- |
| 滑窗跨分割重叠 | UGR 是单条分钟级时间流 | 先按周/时间块分割，再构窗；边界清除至少 `k-1` 分钟 |
| 相邻窗伪重复 | 长度 32 的相邻窗共享 31/32 输入 | 统计按天/周聚类；不得按窗口行重采样 |
| 官方测试提前可见 | UGR 仓库把 `Xtest/Ytest` 与训练文件同目录发布 | 加载器在打开文件前拒绝测试路径；仅在方法冻结后解除 |
| 标签进入特征 | UGR 的 `Y` 是八类攻击计数；时间和周期字段也可形成攻击日程捷径 | 审计 134 个 `X` 字段，禁止任何由 `Y`、攻击者/受害者地址、绝对时间或攻击日程派生的字段 |
| UGR 训练污染 | 数据论文明确指出不同数据版本和未标异常会显著改变结论 | 固定 v3，不按结果切换 v1/v2/v4；记录未标异常敏感性 |
| CTU 场景捷径 | 13 个场景包含固定主机、地址和恶意软件配置 | 场景/恶意软件组隔离，地址、捕获名和场景标识不得进入输入 |
| CTU 标签折叠 | Background 不等于已验证 Normal | 分开报告或做预注册敏感性分析 |
| TQH 长度筛样 | 长流比例与 `profile`、协议和标签有关 | 保留短流和有效掩码；不得只训练长度 32 子集后宣称总体收益 |
| GeNIS 身份补拼 | 已有 163 身份缺失、94 时长不匹配、3,056 重复 `FlowID` | 保持 `NO-GO`，除非从原始包重新冻结并通过独立审计 |

### 6.2 P0 弱基线风险

- 省略 Mamba 会避开当前最直接的线性状态空间网络流量证据。
- 让 HGB/XGBoost 只看当前分钟、而神经模型看 32 分钟，会把信息预算差异误写成架构贡献。
- 把 R2 内部 GRU 旁路直接当独立序列分类基线，会混入不同任务头、参数量和监督信号。
- 只比较普通阈值而不比较温度缩放、保序回归或冻结共形校准，会夸大第二创新点。
- UGR 的官方任务接近网络异常检测。若采用监督攻击标签，还应增加至少一个公开协议一致的异常检测基线，不能只和监督分类器比较。

### 6.3 P0 不可证伪风险

- 长度 32 表示 32 分钟，但只有 32 个标记。可以称“长时状态”，不能直接称“超长上下文能力”。
- 若主门槛允许“准确率提升、吞吐提升、显存下降三者任一成立”，则存在事后选择成功口径的风险。必须在训练前选择准确率轨或效率轨。
- 准确率轨应要求相对最佳匹配基线的主指标点估计至少提高 0.01，且配对区间下界大于 0。
- 效率轨应要求检测非劣下界大于 `-0.005`，并预先选择吞吐至少 1.5 倍或峰值显存至少降低 25% 中的一个主条件。
- 创新二若读取未来标签、域标识、官方测试分布或模型预测后的难度排序，就不是部署可用的漂移校准。
- `R11` 若只优于 `R00`，但不优于 `R10/R01`，只能说明增加容量或正则化，不能说明两个创新协同。

### 6.4 P1 工作量失控风险

- 当前没有 RWKV、Mamba 和因果 Transformer 的任务入口，工程工作量不能按“只改配置”估算。
- UGR 与 CTU 的输入单位不同，需要两个数据适配器和两套泄漏审计，但应共享模型、日志和统计框架。
- GeNIS、TQH-C2、UGR、CTU 同时成为主数据会把替代路线变成四套数据工程。当前只保留 UGR 主开发、CTU 外部面板，TQH 机制诊断，GeNIS 暂停。
- `output/第一创新点实验总控.md` 仍把 R2 标为 `NOT_READY`，不是最终失败。没有用户明确切换或 R2 最终裁决前，不得把 RWKV 备选变成并行正式主线。

| G10 外部证据 | UGR 主结果通过后，CTU 以独立场景协议复现；不与 UGR 混合计分 | 结论收窄为单数据集攻击状态检测 |

## 8. 最终建议

**推荐执行，但只执行一条窄路径：**

1. 先冻结推荐题目和“分钟级攻击状态”任务单位。
2. 只审计 UGR'16 v3 官方特征数据，完成许可冲突、字段、标签、连续时间段和 1/4/16/32 分钟无泄漏门禁。
3. UGR 门禁通过后，先做 16 个单种子架构筛错；普通 RWKV 未过门槛立即停止。
4. 普通 RWKV 通过后，再做 `R00/R10/R01/R11` 三种子 2×2 矩阵和长度交互。
5. 完整方法通过后，才审计并运行 CTU-13 外部逐流面板。

**当前状态不是“RWKV 已可训练”，而是“数据路线有现实解锁路径”。** 若用户坚持“同一父会话 4/16/32”且不接受分钟级连续状态作为父组，UGR'16 只能作外部验证，当前方案应继续保持不可启动，直到 CTU-13 或重新物化的 TQH-C2 通过真正的父序列门禁。
