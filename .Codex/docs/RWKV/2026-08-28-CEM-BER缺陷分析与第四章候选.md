# CEM-BER 缺陷分析与第四章候选

<!-- RESEARCH_ROUTE=RWKV -->

- 日期：2026-08-28
- 对象：基于因果实体记忆（CEM）与预算感知实体排序（BER）的跨年低误报检测方法（CEM-BER）
- 证据等级：**设计层面缺陷分析**。空间代价由已核实的实测常数推算，训练与推理时间待
  服务器 C10 实测回填。**方法有效性尚未验证**——若 C10 相对 C00 无正增益，本文档整体作废。

## 零、前置声明

本文档分析的是**设计固有代价**，不是运行缺陷。所有数值来自：

- 实体数 `150,680`、观测跨度 `6.73` 天：`ch3-lspr23-entity-history-availability-v1` 收据；
- 裸 FT 参数 `924,283`、CEM 新增 `150,913`（R=8，占 16.33%）、C10 合计 `1,074,428`：
  机制一实现报告的闭式与实测双核对；
- 袋规模 `2,475,228`、恶意实体 `239`、验证正实体 `20`：同上实体历史收据与源年切分。

## 一、状态无界增长（空间）——**最强的第四章候选**

### 实测代价

| 项 | 值 |
| --- | ---: |
| 单实体状态（`R=8`，`d=192`，FP32） | **6.0 KB** |
| LSPR23 全部实体状态 | **0.93 GB** |
| 状态 ÷ 模型权重（`1,074,428 × 4B = 4.3 MB`） | **215 倍** |
| 新实体速率 | **22,389 个/天** |
| 外推 1 个月 | `671,679` 实体 → **4.1 GB** |
| 外推 1 季度 | `2,015,037` 实体 → **12.4 GB** |
| 外推 1 年 | `8,172,095` 实体 → **50.2 GB** |

推算式：`实体数 × R × d × 4 字节`；速率取 `150,680 / 6.73 天`。

### 为什么是研究问题而不是工程问题

CEM 的部署形态要求为每个见过的实体托管一份严格过去状态，而实体集合**随时间线性无界
增长**，当前设计**没有任何淘汰机制**。一旦引入淘汰，就得回答：**给定状态预算 `M`，
保留哪些实体的记忆才能最大化检出率？** 淘汰错了直接损失检测能力——这是带约束的优化
问题，不是加个 LRU 就完事。

与第四章现有框架**同构**：第四章当前做的是「给定误报预算下最大化检出」，本问题是
「给定空间预算下最大化检出」。已建成的 CVaR、分层证书与 Clopper-Pearson 工具可迁移。

与第三章形成自然递进：第三章证明实体记忆有用，第四章解决记忆装不下。

### 朱式结构对位：一个瓶颈，拆成两个维度

**核实结论（原件全文提取，非推断）**：朱焱雷第四章也**只提出一个缺陷**，靠拆维度形成
工作量，不靠堆缺陷数量。其 4.1 节原文：

> 上一章提出的 DS-RGO 方法虽显著提升了模型的抗逃逸能力，但高强度的对抗迭代引发了
> 计算开销的指数级增长。深入剖析发现，该算力瓶颈根源于对抗训练中的**时空双重冗余**：
> 空间上，长尾分布导致大量简单样本被无效计算；时间上，扰动在相邻轮次间的慢变性被忽略。

| 层级 | 朱第四章 | 本章第四章候选（对位） |
| --- | --- | --- |
| 缺陷（**各 1 个**） | 第三章 DS-RGO 的算力开销指数增长 | 第三章 CEM 的实体状态无界增长 |
| 空间维度 | 长尾分布致简单样本被无效计算 | 实体链长极度长尾，多数实体记忆不值得留——**存量分配** |
| 时间维度 | 扰动在相邻轮次的慢变性被忽略 | 旧实体记忆边际价值随时间衰减——**时效淘汰** |
| 两个机制 | 动态流过滤 `DF`／自适应缓存复用 `ACR` | 各配一个，待定名 |
| 联合算法 | `DF-ACR` | 两机制缩写拼接 |
| 效果表述 | 训练速度 `4.6` 倍、显存峰值显著下降 | 状态占用下降倍数，检出率不劣 |

**本拆法的数据依据（均为已核实实测）**：

- 空间维度长尾：实体链长 P50=`2`、P75=`3`、P90=`8`、最大 `2,475,228`；恶意实体链长
  中位 `112` 对良性 `2`。多数实体只有两三条流，其记忆的信息量与占用不成比例。
- 时间维度衰减：观测跨度仅 `6.73` 天，新实体以 `22,389` 个/天持续涌入；旧实体在长期
  部署中占据状态却可能长期不再出现。

**另一处可援引的先例**：朱在第四章**主动缩小了研究对象**——「本章的研究对象将不再
包含轻量级 CNN 模型，而是聚焦于计算密集型的 ET-BERT」，理由是效率瓶颈具有模型
特异性。本章第四章同样可只聚焦 FT＋CEM，不覆盖其他骨干，有体例先例。

**章间连贯性**：朱第四章开篇即回指第三章（「上一章提出的 DS-RGO 虽显著提升……但……」），
两章强连贯。本课题若采纳本候选，第三章与第四章亦形成「证明记忆有用 → 解决记忆装不下」
的递进；若维持现有第四章合同（MLP 底座＋Tong），则第四章与重锚后的第三章缺少这条连接。

### 重定向代价（须用户裁决）

第四章当前冻结合同是 MLP 底座 ＋ Tong 路径预算控制（M1′ 已 SUPPORTED，`+3.77` 点）
＋ MalMoE 朱式改造线。改做 CEM 状态淘汰属**主线重定向**，须用户明确决定，本文档只提出
候选，不自行改动第四章合同。

## 二、时间复杂度：**不是瓶颈**

交叉注意力每条流新增 `O(R·d) = O(8 × 192)`；FT 自注意力为 `O(T²·d) = O(84² × 192)`。
新增计算约占自注意力的 **0.1%**，可忽略。参数量增幅 `16.33%` 亦不构成负担。

真正影响吞吐的是**训练调度约束**：CEM 要求按实体链顺序推进，禁用随机片段采样
（设计规约 4.3 节）。后果有二——破坏随机梯度的 i.i.d. 假设；限制数据并行。
这是机制的必然代价而非缺陷，**实际幅度待服务器 C10 步速实测回填**。

## 三、检查点不含记忆状态——**纯工程，不进第四章**

机制一实现报告的遗留风险：调度器游标与记忆状态未纳入检查点，`--resume` 与 `z1=1`
的组合被**显式拒绝**（不会静默出错，这一点处理得对）。后果是长训练中断须从头重跑。

修复范围是检查点序列化，数十行代码。**不构成研究贡献，不得占用第四章篇幅。**

## 四、BER 侧的两条

### 4.1 袋规模不可行（已有对策）

最大实体袋 `2,475,228` 条流，单步预算 `8,192` 条——差 **302 倍**；恶意实体 P99 链长
`238,024` 亦超出两个数量级。三种处置（完整袋／因果前缀截断／分层加权）已在
`tools/ch3_ft_entity_ranking_loss.py` 实现并可**同批并行诊断**，等 C00 的源年前缀曲线
裁决。**不留给第四章。**

### 4.2 正实体基数（数据限制，无方法解）

源区恶意实体 `239` 个，源年验证仅 `20` 个。这限制排序目标的有效样本与选轮分辨率，
**任何方法都无法解决**。只能在正文如实写明统计精度边界，不得包装成方法优势。
