# 三骨干消融本机筛选重跑实施计划（U6 执行，筛选级）

日期：2026-08-27。状态：**活动**。依据：研究问题卡 U6（全注意力重跑＋门控循环修协议重跑，
一维卷积定案剔除）；用户 2026-08-27「本机空闲重跑三骨干」指令。

## 一、证据边界（先说死）

- 本机运行为 `screening_only`（fp32、MPS、非冻结精度合同），**结果不进正文**。
- 用途＝决策先导：某骨干本机四格通过纳入判据（单机制均正＋联合最佳）→ 才投入服务器
  按冻结 BF16 合同做正式重跑（正文候选）；本机仍 FAIL → 按 U6 预注册建议定案剔除，
  是否免掉服务器正式重跑由用户最终拍板。
- 执行排队在第四章本机链（D0→D1/D2）之后，同一时间本机只跑一条训练线
  （单 GPU、16GiB 内存，X23 常驻 5.4GB 不允许双进程各载一份）。

## 二、范围与协议

- 骨干：全注意力（Transformer）、门控循环（GRU）。一维卷积不重跑（U6 定案）。
- 四格语义沿用 `tools/ch3_backbone_protocolA_v2.py:98-99`：C10=仅 CPA、C01=仅 ELP。
- 数据：本机 `runs/diagnostics/dijk-repro/cache` 源年六数组（与 O11 谱系同源）；
  LSPR24 零读取（本机无目标年文件）。
- 训练配方：沿用协议 A-v2 冻结值（seed42、批 64、序列 128、20 epoch×1000 步、
  实体不相交验证 argmax 选择），唯一修订＝**学习率不再全骨干硬编码 2e-3**：
  - 每骨干 lr 网格 = {2e-3（原协议值，保偶然性对照）} ∪ {该骨干在
    `2026-08-17-第三章实验台账.md`「等参数基线」章节登记的择优 lr}；
    精确择优值由实现代理从台账读出并在配置中登记出处行号，读不到标 `NEEDS_CONTEXT`。
  - lr 选择只用 LSPR23 验证集、只在 C00 上比（argmax 验证逐流 AP），
    胜出 lr 冻结后四格齐跑；选择过程与结果全部落收据。
- 判据（预注册，与 U6 一致）：C01>C00 且 C10>C00 且 C11≥max（源年实体 AP 口径，
  本机无目标年——**此为与正式判据的口径差异，收据显式登记**；源年通过只作
  「值得上服务器」信号，不等于正式通过）。仍 FAIL 即定案，不再追调。

## 三、交付物（sonnet 实现代理）

- `tools/ch3_backbone_2x2_local_screen.py`：单文件双骨干入口
  `--backbone {transformer,gru}`、`--stage {lr-select,cells}`、`--device auto`；
  模型类从 `ch3_backbone_protocolA_v2.py` import 复用（禁止复制重写），
  剥离 CUDA/精度运行时依赖（fp32 直跑），X23 常驻 CPU 逐批上卡
  （模式照 `ch4_mlp_o11_oof_fold_models_local_screen.py`）。
- 运行根 `runs/diagnostics/ch3-backbone-2x2-local-screen-v1/{transformer,gru}/`：
  lr 选择收据、逐格选择收据与检查点、源年四格实体 AP 结果、判据布尔、
  `screening_only=true`、`target_year_arrays_read=0`。
- 断点：逐格完成即落盘，重入幂等跳过已完成格。

## 四、验收（实现代理执行）

1. `py_compile`＋venv 导入通过；模型类确系 import 复用（报告贴 import 行）。
2. 无 X23 时清晰诊断退出（当前 X23 可能仍在拉取）。
3. GRU/Transformer 各跑通首个 optimizer step 的最小真实检查（有限非零损失与梯度，
   不算科学验证）——若 X23 未到位则此条顺延并在报告标明。
4. 台账择优 lr 的出处行号登记进配置或收据。

## 五、调度

实现完成 ≠ 立即执行。执行顺序由主进程控制：D0→D1/D2 完成后串行启动
（预计今晚），先 Transformer（翻盘概率高）后 GRU（含 lr 网格多 2 个 C00 单元）。
