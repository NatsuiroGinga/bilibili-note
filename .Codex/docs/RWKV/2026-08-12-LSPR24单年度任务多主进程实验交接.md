# LSPR24 单年度任务多主进程实验交接

<!-- RESEARCH_ROUTE=RWKV -->

- **日期**：2026-08-12
- **用途**：把三个 LSPR24 单年度任务分别交给三个独立主进程实现和运行。
- **当前主进程保留职责**：LSPR23→LSPR24 跨年度泛化实验；其他主进程不得修改或启动该任务。
- **证据等级**：各方案册均为设计可行、实验待证；快速实验结果不得直接写入论文正式结果表。

## 1. 启动总则

每个新主进程收到本文件后，先按以下顺序完整恢复：

1. 根 `AGENTS.md`。
2. `.Codex/docs/AGENTS.md`。
3. `.Codex/docs/RWKV/AGENTS.md`。
4. `.Codex/docs/RWKV/RWKV路线总控.md`。
5. `.Codex/docs/RWKV/RWKV当前恢复卡.md`。
6. `.Codex/docs/RWKV/2026-08-08-第三章候选方案登记册.md`。
7. 本交接文件。
8. 自己负责的任务方案册、LSPR24 G0 合同和方案册链接的证据。

新主进程必须在自己的第一份实施计划中原样写明：

```text
本进程只负责一个 LSPR24 单年度任务；不负责跨年度泛化，不修改其他任务源码、配置、启动器、运行根或报告。
```

## 2. 共同数据合同

三个任务若只使用一个数据集，均固定使用 **LSPR24**。不得改用 LSPR23，也不得把 LSPR23→LSPR24 的跨年度 Q0 数字当作本任务基线。

LSPR24 以活动秒时间秩固定为：

| 分区 | 秩范围 | 允许用途 |
| --- | --- | --- |
| `train-fit` | `0%–40%` | 拟合数据变换、模型和训练统计 |
| `architecture-selection` | `40%–50%` | 种子 42 的架构、历史长度和超参数选择 |
| `dev-validation` | `50%–60%` | 冻结候选的一次性开发验证，不再调参 |
| `calibration` | `60%–80%` | 骨干冻结后的概率校准与阈值冻结，不再选结构 |
| `final-test` | `80%–100%` | 所有方法、字段、阈值、种子和统计模板冻结后的唯一最终评价 |

正式合同为 [LSPR24 G0 数据与切分合同](2026-08-05-LSPR24-G0数据与切分合同.md)。在 `final-freeze.json` 通过前，任何主进程均不得访问、统计、哈希、持久化或推断 `final-test` 的成员、特征、标签、事件或派生值。

共享候选筛选视图只读根为：

```text
runs/data-prepared/lspr24-screen-wide-v1/
```

该视图当前仅有 `screen_ready=true`、`formal_evidence=false`、`final_accessed=false`，可用于 Q0 快速筛选，不能冒充正式 G0-D 数据产品。每个主进程必须先通过清单发现真实文件，不得猜路径；若任务所需接口不在共享视图中，只允许新增本任务有界派生缓存，不得扫描或复制最终区。

## 3. 并发隔离规则

### 3.1 只读共享文件

以下文件由所有主进程只读使用，不得修改：

```text
.Codex/docs/RWKV/RWKV路线总控.md
.Codex/docs/RWKV/RWKV当前恢复卡.md
.Codex/docs/RWKV/2026-08-08-第三章候选方案登记册.md
.Codex/docs/RWKV/2026-08-05-LSPR24-G0数据与切分合同.md
thesis/experiments/llm_probe/src/flow_probe/lspr24_screen_dataset.py
thesis/experiments/llm_probe/tools/lspr24_g0/
runs/data-prepared/lspr24-screen-wide-v1/
```

如共享加载器确实缺少接口，任务主进程不得直接修改它。先在自己的实施报告记录缺口，优先在任务专属模块中实现只读适配；只有无法保持语义一致时，才向当前根主进程申请统一接口变更。

### 3.2 独占写入

每个任务只能修改其方案册指定的新源码、配置、启动器、实施报告和运行根。禁止：

- 覆盖、回滚、暂存或格式化其他主进程的文件。
- 使用通配符删除、清理上级目录或执行 `rsync --delete`。
- 共用同一个状态文件、锁、日志、SwanLab 运行名或检查点目录。
- 让多个主进程同时修改 `pyproject.toml`、`uv.lock` 或共享虚拟环境；缺依赖时先记录精确包和版本，由当前根主进程统一处理。
- 直接更新路线总控、恢复卡或第三章登记册。各任务只写专属报告，统一写回由当前根主进程完成。

### 3.3 服务器与图形处理器

- 远程连接只从路线总控规定的环境变量读取，禁止在文档、命令清单和日志中写入连接地址、密码或令牌。
- 每个主进程启动前只读核验服务器身份、项目根、数据、依赖、磁盘、主存、图形处理器、持久会话和冲突进程。
- 独立变体在数据只读、输出独立且资源安全时默认并行；最大并发写入任务配置和状态收据。
- 正式 Python 入口统一使用 `uv run --no-sync python`，禁止系统级 `python` 或 `python3`。
- SwanLab 固定为 `mortiswang/malicious-traffic-llm`，只能上传聚合指标与协议元数据，不上传逐样本数据、路径或凭据。

### 4.1 唯一职责

实现并运行**当前窗口完成后的流式攻击状态检测**。该任务回答“当前已完成流是否属于红队关联恶意状态”，不回答未来事件、真实攻击动作起点或跨年泛化。

方案册：

- [任务方案册：LSPR24 流式行为检测](candidates/任务方案册-LSPR24流式行为检测.md)

若方案册尚未落盘，主进程 A 只能完成规则恢复与只读接口核验，禁止自行猜测方案后启动。

### 4.2 建议独占命名空间

### 4.3 首个交付检查点

1. 证明当前窗标签、输入支持区间和状态重置均严格因果。
2. 在相同成员上完成 XGBoost、XGBoost+手工因果历史、GRU、因果 Transformer、Mamba 和完整官方 RWKV 的共同预算门禁；无法运行的基线必须给精确阻塞，禁止弱化。
3. 概率先封存，再由独立评价器连接标签。
4. 输出 `screening_only=true`、`formal_paper_evidence=false`、`final_accessed=false`。

### 5.3 首个交付检查点

1. 目标窗必须位于同一端点、连续段和分区，且在当前输入之后；跨边界、重置后无预测或缺失目标必须显式删失。
2. 生成头只在 `train-fit` 中输入历史与目标窗标签均为 0 时反向传播；标签只作损失掩码，不入模型。
3. 强基线至少覆盖持续值、滑动统计、Markov 或 n-gram、XGBoost 回归/分类、GRU、因果 Transformer、TCN 或 TimesNet、RWKV-TS/PLM-NIDS 式 RWKV。
4. 只有预测器超过强朴素与树模型基线，且预测惊异度给强检测基线带来独立增量，才允许晋级。

## 6. 主进程 C：LSPR24 攻击早期预警

### 6.1 唯一职责

分别实现并评价两个不可混淆的任务：

1. **事件前缀早期检测**：红队关联阳性事件已经开始后，评价首次告警延迟。
2. **未来红队关联阳性窗预测**：仅在当前窗标签为 0 时，预测同端点未来固定范围内是否首次变正。

第二项不是已证实的真实攻击动作预测；攻击叙事未完成唯一映射前，禁止使用“真实攻击先兆”或“动作起点”表述。

### 6.3 首个交付检查点

1. 先发布仅含前 80% 的未来目标清单与删失收据；未来关系不得跨分区、连续段或最终边界。
2. 先运行中央处理器可学习性门：常数风险、离散时间风险、当前窗 XGBoost、XGBoost+手工历史。手工历史若无独立增量，停止未来预测支路，不启动神经模型。
3. 事件前缀检测至少比较固定阈值首次越界、连续 `k` 次越界、CUSUM、SPRT 和固定观察长度分类器。
4. 有界 RWKV 历史残差只在强 XGBoost 锚上运行；正常预测惊异度必须先超过其自身强基线，才能作为可信门。

## 8. 每个主进程的完成回报合同

每个任务只在以下内容齐全时报告完成：

1. 修改文件与未修改共享文件的精确清单。
2. 数据/字段/标签/分区/样本清单和代码配置哈希。
3. 编译、导入和命令入口检查；这些只证明可运行，不证明科学有效。
4. 真实开发区运行根、启动器状态、日志、概率封存、独立评价、SwanLab 标识和资源收据。
5. 所有预注册基线、消融、指标、失败项和未筛选数字，不只报告最好结果。
6. `final_accessed=false`、`formal_paper_evidence=false` 与是否晋级的机械裁决。
7. 若失败，明确区分实验无效、实现阻塞、资源阻塞、弱证据不利和科学否决。

三个主进程均不得自行访问最终测试或把 Q0 写入论文正式章节。完成后只把专属报告路径和原始制品根交回当前根主进程，由当前根主进程统一更新候选索引、登记册、恢复卡和路线总控。
