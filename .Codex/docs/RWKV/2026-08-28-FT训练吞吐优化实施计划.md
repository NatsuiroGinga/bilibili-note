## 科学身份硬门（违反即使四格不可比）

- **有效批 `64`、学习率 `1e-4`、权重衰减 `1e-5`、`20` 轮 × `1000` 步一律不得改动**——
  它们是 FT 官方配方，改了 C00 就无法与历史 FT `C00=0.7508` 比较，四格之间也不公平。
- **X23 显存常驻是数值等价变换**（同样的值、同样的取用顺序，只改存放位置），安全。
- **`torch.compile` 不保证逐位等价**。C00 已在**无 compile** 下完成。因此：
  **除非任务 3 的逐位等价核验通过，否则不得对任何后续臂启用 compile**；
  若核验不通过而仍想用 compile，必须连 C00 一起重跑（约 75 分钟），四格全用同一路径。

### 任务 2：X23 显存常驻（数值等价，优先做）

**接口**
- 配置新增 `runtime.resident_feature_matrix: bool`。为真时启动阶段把 `X23` 一次性
  搬到 GPU，训练与验证的取行改为在显存内索引；为假时保持现有主机 gather 路径。

- [ ] **步骤 1：腾出显存**

`X23` 需 `5.43 GB`，当前仅余约 `2.3 GB`。把验证批从 `128` 降到 `32`
（验证只占总时长约 `11/81`，代价可接受）。预期占用：
`30.3 − 约 10（验证批降低）＋ 5.43 ＝ 约 25.7 GB`，留约 `6.9 GB` 余量。
**实际占用以运行收据为准**；若超过 `30 GB` 则把验证批再降到 `16`。

- [ ] **步骤 2：实现常驻与索引**

```python
if config["runtime"].get("resident_feature_matrix"):
    # X23 一次性驻留：与主机路径取同样的行、同样的顺序，数值逐位相同
    feature_matrix = torch.from_numpy(np.asarray(X)).to(device)  # (16353511, 83) float32
    def gather(indices: torch.Tensor) -> torch.Tensor:           # indices: (B*128,)
        return feature_matrix[indices]                            # -> (B*128, 83)
else:
    def gather(indices: torch.Tensor) -> torch.Tensor:
        return torch.from_numpy(X[indices.cpu().numpy()]).to(device)
```

- [ ] **步骤 3：数值等价核验（必须逐位）**

同一批索引下比较两条路径的取值与模型 logits：`torch.equal` 必须为真，
**不是 `allclose`**。不等即停止并报告。

### 任务 3：torch.compile（仅在任务 1 通过时执行）

**接口**：配置新增 `runtime.torch_compile: {enabled: bool, mode: str}`。

- [ ] **步骤 1：按任务 1 核验到的签名接入**

只编译 FT 主干前向，不编译数据取用与指标计算。形状固定
（`micro_batch=64`、`seq=128`、`token=84`），适合 `mode="max-autotune"` 或
`"reduce-overhead"`；具体取值按任务 1 查到的文档决定，不凭记忆填。

- [ ] **步骤 2：逐位等价核验（决定能否用于正式臂）**

同一权重、同一批，比较 compile 与 eager 的 logits：
- `torch.equal` 为真 → 可用于后续臂，**且不需要重跑 C00**；
- 不为真 → 记录最大绝对差，并**默认关闭 compile**；除非用户明确决定连 C00
  一起重跑，否则不得在正式臂启用。
