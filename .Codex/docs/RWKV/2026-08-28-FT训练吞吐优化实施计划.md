## 优化动机的实验裁决（2026-08-28，服务器实测）

原假设：利用率在 31%–95% 间波动来自每步从主机 gather `8,192 × 83` 的 `X23` 行。
**该假设已被服务器实测否决**（`tools/ch3_ft_data_path_benchmark.py`，收据
`runs/diagnostics/ch3-ft-data-path-benchmark-v1/data-path-benchmark.json`）：

| 数据路径分项 | 服务器实测 |
| --- | ---: |
| 索引构造（常驻后仍需） | `0.00030` 秒 |
| 主机取行（常驻可消除） | `0.00222` 秒 |
| 主机到设备（常驻可消除） | `0.00023` 秒 |
| 数据侧合计占单步 `0.208` 秒 | **`1.3%`** |
| **X23 常驻收益上限** | **`1.2%`** |

`1.2%` 远低于本计划任务 4 的 `5%` 采纳门槛，**任务 2（X23 显存常驻）就此作废**，
不实现、不分派。5.43 GB 显存留给其他用途。

**跨机基准的警示**：同一测量在本机 M1 上为 `76.6` 毫秒、占比 `36.8%`，与服务器的
`2.75` 毫秒、`1.3%` 相差 `28` 倍。原因是本机 16 GB 内存装不下 5.4 GB 的 mmap 导致缺页，
服务器内存充裕、`X23` 全在页缓存。**本机基准不能外推到服务器**；涉及内存与 I/O 的
优化判断必须在目标机测量。

剩余唯一候选是 `torch.compile`（减少小模型的核启动开销），见任务 3。

## 科学身份硬门（违反即使四格不可比）

- **有效批 `64`、学习率 `1e-4`、权重衰减 `1e-5`、`20` 轮 × `1000` 步一律不得改动**——
  它们是 FT 官方配方，改了 C00 就无法与历史 FT `C00=0.7508` 比较，四格之间也不公平。
- **X23 显存常驻是数值等价变换**（同样的值、同样的取用顺序，只改存放位置），安全。
- **`torch.compile` 不保证逐位等价**。C00 已在**无 compile** 下运行。
  **用户 2026-08-28 明确裁决：不重跑 C00。** 因此判据是二值的——
  任务 3 的逐位等价核验通过则启用 compile，不通过则**整个放弃 compile**，
  不存在"重跑 C00 让四格统一路径"这个选项。

if config["runtime"].get("resident_feature_matrix"):

    feature_matrix = torch.from_numpy(np.asarray(X)).to(device)  # (16353511, 83) float32

### ~~任务 3：torch.compile~~（**2026-08-28 实测否决，不执行**）

服务器实测（`tools/ch3_ft_compile_equivalence_probe.py`，微批 4，
`PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`，与 C10 训练并发）：

| 项 | 实测 |
| --- | ---: |
| **逐位等价（`torch.equal`）** | **`False`** |
| 最大绝对差 | `8.940697e-07` |
| 首次编译耗时 | `7.9` 秒 |
| 前向提速 | `1.138×` |
| **训练步提速** | **`1.316×`** |

**裁决：放弃 compile。** 依据是预注册的二值门——非逐位等价即不可用于四格，
因为 C00 已在无 compile 下完成且用户裁决不重跑 C00；编译臂的训练轨迹会自第一步
起与 C00 分叉，机制效应与编译效应混淆。`8.94e-07` 的单步差异在 20 轮 × 1000 步中
会被放大为完全不同的轨迹，而本课题为单种子（U4），无法区分机制效应与轨迹噪声。

**代价核算**：放弃 compile 使 C01 与 C11 各多约 20 分钟，合计 `40` 分钟；
若为省这 40 分钟而启用，须连 C00 重跑 `81` 分钟，净亏。

**附带记录**：日志提示 `TensorFloat32 tensor cores available but not enabled`。
TF32 同样改变数值路径，且 C00 未开启，四格须保持一致，**同样不得启用**。
