## 五、精度接入与 LayerNorm 的 FP32 归属（核验记录）

精度全部经 `tools/neural_precision_runtime.py` 接入，未自写 autocast、梯度累积、
资源采集或检查点状态：`resolve_precision_profile`、`autocast_context`、
`fp32_island`、`create_grad_scaler`（BF16 下必须返回 `None`，返回非 `None` 即抛错）、
`EffectiveBatchAccumulator`、`build_checkpoint_runtime_state`、
`validate_checkpoint_runtime_state`、`collect_resource_receipt`、
`validate_resource_receipt`、`validate_model_optimizer_fp32`。

计划第七节要求 LayerNorm 保持 FP32。经 Context7 取 `pytorch/pytorch` 主干
`aten/src/ATen/autocast_mode.h` 核验：`layer_norm` 与 `native_layer_norm` 均在
`AT_FORALL_FP32` 宏内，autocast 无视输入类型强制以 FP32 执行；
`binary_cross_entropy_with_logits`、`logsumexp`、`log`、`pow` 同样在该清单内。
因此残差块的 `nn.LayerNorm` 不需要额外 `fp32_island`，该事实已写进
`PreNormResidualBlock.forward` 的注释并在张量上界中按 FP32 计账。
因果前缀累积（`cumsum` 归约）与 `sigmoid`、ELP 池化仍显式进 `fp32_island`。

## 六、微批与累积（本机解析实算，非继承他人数值）

精度合同 `integration_example` 自身写明 `do_not_inherit_batch_values`，其批量是
N-12 的实验合同。本工具按 N-13 同一机械规则独立冻结：在有效批 `64` 的全部机械因子
中取「单微批前向保留激活解析上界」不超过 `minimum_free_gpu_memory_mib / 10 = 2048 MiB`
的最大因子。

本机实跑：`retained_activation_bytes(64, 128, 2) = 96.016 MiB ≤ 2048 MiB`，
因此 `micro_batch_sequences = 64`、`gradient_accumulation_steps = 1`。
`validate_config` 会用同一函数复算并与配置登记值比对，不一致即抛错。
该天花板是工程资源余量而非科研阈值，服务器第一次真实 `optimizer.step()` 的显存
收据到手后须复核（`revisit_after_first_step_memory_receipt: true`）。

## 八、指标键名与实际可达 FPR（需 Codex 知悉的一处口径说明）

与既有四格工具**逐字同名**的键全部保留：`flow_average_precision`、`flow_roc_auc`、
`entity_average_precision`、`maximum_entity_average_precision`、
`dr_at_fpr.fpr_0.001` 至 `fpr_0.08`、`maximum_dr_at_fpr.*`、`flows_scored`、
`entities_scored`、`evaluation_seconds`、`target_evaluation_call`；
交互项 `interaction.<指标>.causal_prefix_effect`（`C10−C00`）、`.elp_effect`
（`C01−C00`）、`.combined_effect`（`C11−C00`）、`.interaction`
（`C11−C10−C01+C00`）；资源项 `resource.*`。交互项在三个 AP 指标之外，
另对六档 `dr_at_fpr.<档>` 也计算了同四项。

关于「六档 DR 必须使用实际可达 FPR」：既有四格工具（TabM32、FT-Transformer、
ResMLP2）的工作点规则是按负类实体降序取下标
`min(int(len(negative) * target_fpr), len(negative) - 1)` 处的分数作阈值。
该阈值本身是一个真实存在的负类实体分数，工作点可达；但其**名义标签**与实际误报率
不等：无并列时实际误报实体数为 `k+1`，实际 FPR 略高于名义值；有并列时可能高得多。

本工具**不单方面改动该共享指标的计算规则**——改了会使本骨干的六档数字与既有四格
工具不可并表，而计划第八节同时要求并入第三章全模型指标总表。采取的做法是：

1. `dr_at_fpr.*` 与 `maximum_dr_at_fpr.*` 的计算与既有工具逐字相同，可直接并表。
2. 新增 `dr_at_fpr_realized.*` 与 `maximum_dr_at_fpr_realized.*`，给出每个工作点
   **重新计数得到的真实 FPR**，绝不把名义 `4%` 当真实值。
3. 新增 `dr_at_fpr_detail.*`，逐档记录 `nominal_fpr`、`realized_fpr`、
   `nominal_index`、`n_false_positive_entity`、`n_negative_entity`、
   `within_nominal_budget`。
4. 实际 FPR 越出名义预算时写 `WARNING` 日志，点名该档与真实数字。
5. 完整可达告警预算曲线本就同时保存 `nominal_fpr` 与 `realized_fpr` 两列。

**请 Codex 知悉**：若希望第三章总表改用「实际 FPR 严格不超过预算」的工作点规则，
那是一次涉及全部既有四格工具的口径变更，不属于 N-14 的文件所有权范围，需另立任务。

## 十、遗留风险与待服务器验证项

1. **待服务器验证**：实例化后的 `sum(p.numel() ...)` 是否为 `387,074`（本机无 `torch`）。
   `build_model` 不一致即抛错，不会静默通过。
2. **待服务器验证**：BF16 autocast 下 `nn.LayerNorm` 实际以 FP32 执行（源码级已核验，
   运行时未核验）；第一次 `optimizer.step()` 的显存收据会记录 `allocated`、`reserved`、
   `max_allocated`、`max_reserved` 与外部进程显存。
