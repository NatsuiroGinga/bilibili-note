# GRANDE 可微树骨干 LSPR23 源年 Q0 实施计划

> **撤销声明（强制）：**提交 `dafdd2a` 中记录的“实体不相交三折 C00”版本已被用户明确否决，现已撤销，禁止实现、启动、恢复或引用。本文当前版本只允许原 MLP 协议 A 的固定实体不相交训练/验证单次 C00。

## 一、结论与状态

本计划把 GRANDE 冻结为一次**资源资格优先、性能 C00 后置**的 LSPR23 源年 Q0。Q0 只回答三个问题：

1. 固定的 GRANDE 硬轴对齐树结构能否在当前真实 83 字段流批次上完成有限、非零、可回到全部核心树参数的反向传播。
2. G-A 与 G-B 两个固定结构能否在合计 4.5 GPU 小时内完成 LSPR23 实体不相交 C00 源年筛选。
3. C00 是否在固定验证逐流 AP 上严格优于当前全容量 MLP 冻结结果；只有存在完全相同固定划分的 XGBoost-C00 收据时，才附加判断是否缩小 XGBoost 差距。

当前状态为**设计可行、实验待证**。本计划不写代码、不访问服务器、不启动 SwanLab、不读取 LSPR24，也不授权 CPA/ELP 四格或目标年评价。

## 五、模型与树结构候选冻结

Q0 最多有两个预注册结构，按顺序运行。二者共享相同数据、折、训练步数、损失和评价；只改变文献/官方来源支持的树深与树数。

### 5.1 G-A：论文最大数据集结构

| 参数 | 冻结值 | 依据 |
|---|---:|---|
| `depth` | 4 | GRANDE 论文表 25 的 numerai28.6 行 |
| `n_estimators` | 512 | 同上；这是论文最大数据集使用的结构 |
| `dropout` | 0.2 | 当前官方 PyTorch 默认，统一到两结构 |
| `selected_variables` | 0.8 | 当前官方 PyTorch 默认 |
| `data_subset_fraction` | 1.0 | 不按论文 96K 配置的 `0.8998` 缩减 LSPR23 标签暴露 |
| `bootstrap` | false | 当前官方默认 |
| 数值/类别嵌入 | false | 保持 83 字段输入合同不变 |

G-A 的深度与树数来自全文，不是根据 LSPR 指标选择。它只借用论文最大数据集的较小树结构，**不借用论文运行时间作资源预测**。

### 5.2 G-B：当前官方默认结构

| 参数 | 冻结值 | 依据 |
|---|---:|---|
| `depth` | 5 | 固定提交 README 当前示例 |
| `n_estimators` | 1024 | 固定提交 README 当前示例 |
| 其余结构/预处理 | 与 G-A 相同 | 只检验树容量，不同时改表示与采样 |

G-B 只在 G-A 完整资源标定后，剩余 4.5 GPU 小时预算足以完成 G-B 单次 C00 时才启动。预算不足时记 `not_started_due_to_preregistered_resource_cap`，不是科学否决。

### 5.3 共同优化配方

| 项 | 冻结值 | 依据 |
|---|---:|---|
| 优化器 | Adam | GRANDE 论文附录与当前官方默认 |
| `lr_weights` | `0.001` | 当前官方 PyTorch 默认 |
| `lr_index` | `0.01` | 当前官方 PyTorch 默认 |
| `lr_values` | `0.05` | 当前官方 PyTorch 默认 |
| `lr_leaf` | `0.05` | 当前官方 PyTorch 默认 |
| 批量 | 64 条序列 | GRANDE 论文附录和现有 LSPR 神经公平协议共同支持 |
| 周期/步数 | 20 周期，每周期 1000 步 | 现有 LSPR 源年公平筛选合同 |
| 梯度裁剪 | `1.0` | 现有神经公平合同 |
| 调度器 | 无 | 避免把当前仓库后更新的调度与树容量同时变化 |
| 焦点损失 | false | 不新增第二个不平衡机制 |
| 类别权重 | true | GRANDE 论文对不平衡任务使用；只由固定训练集计算 |
| SWA | false | 当前官方默认；不与检查点选择规则叠加 |

类别权重只能从固定训练序列可达的有效流标签计算；固定验证标签不得参与权重。禁止根据第一结构的 AP 改学习率、树数、树深、损失、随机失活或变量比例。

### 5.4 参数量与结构收据

运行前必须逐参数组记录形状、可训练标志和数量，并以框架 `sum(p.numel() for p in model.parameters() if p.requires_grad)` 计算总量。至少分列：

- 分裂特征索引参数；
- 分裂阈值/值参数；
- 叶概率或叶值参数；
- 实例级叶权重参数；
- 输出头与其他适配参数。

参数量只作资源与复现事实，不设 90K 上限。G-A/G-B 的结构签名在看到任何标签指标前写入 `structure-candidates-frozen.json`。

## 六、可微梯度与机制挂载接口

### 6.1 C00 输出合同

实现不能调用会转为 NumPy 或包裹 `no_grad` 的 `predict_proba` 作为训练入口，必须直接使用 PyTorch 核心前向。每批输出：

```text
flow_logits:   (B,T)
valid_mask:    (B,T)
tree_outputs:  (B,T,E)  # 仅在资源允许时用于诊断和后续机制接口
tree_weights:  (B,T,E)  # 仅诊断，不持久化逐样本值
```

C00 训练与性能筛选只使用 `flow_logits`。C00 实体分数为有效流概率最大值。

### 6.2 核心梯度门

第一批真实 LSPR23 流必须执行一个正式优化步，并在清零梯度前记录：

- 每个核心参数组的参数数、获得梯度数、非零梯度数、有限梯度数；
- 梯度范数最小值、中位数、最大值；
- 分裂选择熵、左右路由占比、空叶比例、有效树比例；
- 损失、前向时间、反向时间、优化器时间和 CUDA 峰值。

通过条件：所有核心参数组都有有限、非零梯度，模型损失有限，优化后至少一个核心参数发生有限变化。任一核心组无梯度、全零、非有限或优化后不变，判 `gradient_gate_failed`，不得训练第二批。

### 6.3 最终实体梯度诊断

虽然 Q0 只训练 C00，第一批还必须在**不执行优化器更新**的独立诊断图上验证：

1. `logit-cpa-v1`：对 `flow_logits` 做严格过去、含当前位置的掩码因果前缀均值，并与当前 logit 通过固定可训练二输入线性头融合。
2. `elp-v1`：对融合后概率使用一个共享 `p_log` 做实体幂平均。
3. 对实体损失调用 `autograd.grad`，证明梯度能到达 GRANDE 的分裂索引、阈值、叶值和实例权重。

该诊断不改变 C00 权重，不报告性能，不授权机制有效性。它只证明未来实体目标存在到骨干的有限、非零路径。

### 6.4 后续机制版本边界

- Q0 冻结的最小挂载接口是 `flow_logits + valid_mask`。
- `tree-state-cpa` 若直接使用 512/1024 维树输出，会显著增加状态与融合成本，不在本轮授权；必须另立资源与机制合同。
- C00 通过后，下一轮才可在同一冻结骨干上运行 C00/C01/C10/C11。
- CPA/ELP 可按轮次替换，但修订机制必须在 LSPR23 开发证据上预注册；禁止由 LSPR24 失败分面反向设计。

## 七、实验阶段与 4.5 GPU 小时停止门

### 7.1 阶段 P0：静态准备

只允许检查固定源码、许可证、项目锁、配置、缓存六数组身份、父基线收据和代码中目标年字面零命中。P0 不读取大数组内容，不创建实验运行。

### 7.2 阶段 R0：第一批真实流标定

顺序只从 G-A 的固定协议 A 训练集 C00 开始：

1. 加载正式 64 条源年训练序列，按 `I23/M23` 取有效流。
2. 执行一次前向、反向和优化步，完成第六节全部梯度与机制路径诊断。
3. 记录真实批次有效流数、数据读取、主机到设备传输、前向、反向、优化器、峰值显存与峰值主存。
4. 该批次属于正式 G-A 单次 C00；通过后继续同一运行，不建立独立冒烟身份。

R0 只做准入，不从一个批次外推完整资源。

### 7.3 阶段 R1：首个完整周期标定

G-A 完成第一个 1000 步周期及一次完整固定验证集评价后，使用真实周期墙钟、评价墙钟和峰值资源投影：

- G-A 剩余 19 个周期的总 GPU 小时；
- G-B 单次 C00 的 20 个周期总 GPU 小时；
- 数据读取、验证重推理、聚合和最终收据的固定开销。

只有完整周期投影可用于 4.5 GPU 小时门。禁止使用 GRANDE 论文的 96K 运行时间、参数倍率或单批吞吐线性外推。

### 7.4 总预算门

- 从首次模型加载开始累计 GPU 占用墙钟，断点恢复前后的用时相加，不能因重启重置。
- G-A 单次完整 C00 的校准总量若超过 4.5 GPU 小时，立即 `engineering_rejected_resource_cap`，不减少流、步数、周期数、树数或深度。
- G-A 完成后，只有剩余预算足以覆盖 G-B 单次完整 C00 才启动 G-B。
- 达到 4.5 GPU 小时时在当前原子检查点后停止，不开始新单元；未完成结构记资源否决或未启动，不用部分指标比较。
- 默认串行，`actual_parallelism=1`。G-A 与 G-B 不并发，避免资源收据不可比。

## 八、LSPR23 协议 A 固定实体不相交 C00 性能筛选

### 8.1 固定训练/验证划分

逐字沿用全容量 MLP 协议 A 的源年划分，不重新设计：

1. 从 `E23` 取得 `150,680` 个唯一实体，以种子 42 的固定排列取前 `10%` 实体作为验证实体。
2. 从 `T23` 计算源年时间的 `85%` 分位切点；时间尾 `15%` 不进入本轮训练或固定验证。
3. 训练序列为“非验证实体且不在时间尾”的序列；固定验证序列为“验证实体且不在时间尾”的序列。
4. 机械断言训练序列 `208,598`、验证序列 `22,444`，训练与验证实体交集为 0。
5. G-A、G-B、全容量 MLP 和 90K MLP 锚必须使用完全相同的训练/验证成员与内容摘要。

禁止按正负实体重新分层、重新随机划分、交叉验证、轮转留出或根据 GRANDE 结果修改验证比例与时间尾比例。

### 8.2 单次训练与检查点选择

- G-A 只训练一次 C00；资源允许时 G-B 也只训练一次 C00。
- 每周期在固定验证集计算逐流 AP；选择全精度最高周期，完全相等取最早周期。
- 固定验证逐流 AP 参与周期与结构选择，因此只能用于 Q0 源年筛选，不能写成独立泛化结论。
- 验证实体 AP、最大池化实体 AP、六档检测率、完整预算曲线和资源全部报告，但不参与周期或结构选择。

### 8.3 结构选择

若 G-A 与 G-B 都完整有效，唯一选择指标为固定验证逐流 AP：

1. 较高者胜出；
2. 全精度完全相等时，较少树者胜出；
3. 仍相等时按预注册顺序 G-A 胜出。

不得用实体 AP、DR、参数量或运行时间在非完全相等时改选结构。

### 8.4 C00 推进门

冻结胜出结构后，只有同时满足以下条件才记 `grande_c00_source_qualified`：

1. 胜出结构固定验证逐流 AP 严格高于全容量 MLP 源年冻结胜者的固定验证逐流 AP。
2. 胜出结构固定验证逐流 AP 严格高于 90K MLP 同协议 A 两配方中的最佳锚点。
3. 若存在完全同一固定训练/验证成员的 XGBoost-C00 收据，则 GRANDE 到该 XGBoost 的逐流 AP 差距必须小于全容量 MLP 到 XGBoost 的差距；若不存在，不得用其他划分的 XGBoost 数字补门，本项记为不可判且不阻塞 C00 资格。
4. 梯度、资源、输入、固定划分、父基线和零目标读取收据全部有效。

未满足时记 `grande_c00_source_rejected`，不生成 CPA/ELP 性能入口，并触发 NODE 回退计划。

## 九、XGBoost 与 MLP 基线及完整指标

## 十一、通过、否决与 NODE 回退

### 11.1 运行无效

以下任一出现，运行无效而非科学失败：目标年读取非零、字段/形状/固定划分不符、验证标签参与训练损失或类别权重、依赖身份漂移、父基线无效、检查点身份不符、CUDA 静默回 CPU、指标实现错误或非有限指标。

修复只能恢复冻结合同，不能改树结构或超参数。看到任何有效 AP 后不得借“修复”重新选参数。

### 11.2 工程否决

- 当前 PyTorch 2.13 与固定官方核心不能通过真实批次兼容门；
- G-A 核心参数梯度门失败；
- G-A 完整周期投影超过 4.5 GPU 小时；
- 峰值资源不通过既有准入门，且不存在不改变科学合同的分批验证方式；
- G-A 固定结构无法完成单次协议 A C00。

工程否决不证明 GRANDE 模型族无效，只证明当前固定源码、环境、结构与预算不可执行。

### 11.3 科学否决

完整有效 C00 运行未通过第 8.4 节推进门，即 `grande_c00_source_rejected`。它只否决 G-A/G-B 两个预注册结构与共同配方，不外推至全部可微树。

### 11.4 通过边界

`grande_c00_source_qualified` 只授权：

1. 冻结唯一 GRANDE 结构与共同配方；
2. 另立同骨干 C00/C01/C10/C11 源年机制计划；
3. 在机制计划中以目标合同 A/B/C 和完整指标裁决；
4. 选择与配方写入 `backbone_selection_frozen.json` 后，允许另立独立的 LSPR24 描述性入口合同。

它不表示超过 `XGBoost + CPA + ELP`，不授权当前 Q0 直接读取 LSPR24，也不进入论文结论。后续 LSPR24 入口只能描述冻结结构，任何结果都不得返回修改树数、树深、学习率、周期、机制或阈值。

### 11.5 NODE 回退触发

以下任一发生即写 `node-fallback-required=true`：

- 上游 PyTorch 兼容门失败；
- GRANDE 梯度门失败；
- G-A 因 4.5 GPU 小时或显存门工程否决；
- 所有已完整运行的 GRANDE 结构被 C00 科学否决；
- 固定源码存在无法在不改变算法的情况下修复的数值/接口错误。

若 G-A 已通过推进门但 G-B 仅因剩余预算不足未启动，不触发 NODE。NODE 不自动运行；它只生成回退收据，后续按已审计的 `Qwicen/node` 固定提交另立计划。
