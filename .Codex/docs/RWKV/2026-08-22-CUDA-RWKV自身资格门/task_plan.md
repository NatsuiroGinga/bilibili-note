# CUDA-RWKV 自身资格门实施计划

> **执行技能**：按 `writing-plans`、`subagent-driven-development`、`daily-coding` 的约束实施；当前任务已由主进程分派给唯一实现代理，禁止再次分派实现所有权。

**目标**：为小型容量 CUDA-RWKV 建立不读数据、不训练、不创建跟踪运行的独立自身资格门，并提供静态可验收的配置与持久启动器。

**架构**：单个 Python 工具负责配置门、官方源码身份门、CUDA 扩展加载、确定性与数值门、六输入微扰门、外层掩码门、最小模型单次优化更新门及资源收据。Shell 启动器只建立持久运行身份、锁、日志、状态与失败证据，不访问数据或训练入口。

**技术栈**：Python 3.10、PyTorch `2.13.0+cu130`、CUDA `13.0`、NVCC、Ninja、Bash。

**规范来源**：`.Codex/docs/RWKV/2026-08-22-CUDA-RWKV独立Raw83资格/实施方案.md`（提交 `334ed1d19827ea5eb791f84900a020916e11354a`）。

## 全局约束

- 固定官方提交 `952102498e9ed367ea0a59ee64106916d474d30f`，CUDA 计算核不修改。
- 固定 `B=2`、`T=128`、`C=112`、头大小 `16`、低秩维 `8`，六输入为 BF16、CUDA、连续张量。
- 只执行固定构造输入上的实现资格检查和一个 `optimizer.step()`；不读任何数据，不执行训练循环。
- 不创建 SwanLab 身份，不包含数据路径、训练轮数或目标年度配置。
- 构建根与运行根持久化；相同执行身份幂等返回，失败保留状态、日志和已生成制品。
- 本地只执行 `py_compile`、导入、帮助、配置、`bash -n`、供应商摘要和差异检查、`git diff --check`；CUDA 实测前状态始终为“实验待证”。
- 禁止运行 `black`、人工夹具、单元测试、服务器命令和训练命令。

## 实施任务

### 任务 1：冻结静态合同与配置门

- [ ] 定义配置模式、固定形状、环境、构造输入、微扰、优化器、制品和禁止字段。
- [ ] 实现 `--validate-config`、`--print-contract` 与 `--help`，导入和帮助不得初始化 CUDA 或编译扩展。
- [ ] 配置门递归拒绝数据路径、训练轮数、目标年度和 SwanLab 字段。

### 任务 2：实现 CUDA 自身数值与掩码门

- [ ] 固定种子生成六个有界 BF16 CUDA 连续叶张量，同进程重复两次前向/反向。
- [ ] 机械断言输出、损失和六梯度有限，六梯度各自至少一项非零，重复结果逐位一致。
- [ ] 分别微扰六输入，断言输出或损失发生有限变化。
- [ ] 通过外层独立模型的掩码实现有效前缀不变与全零掩码零贡献。

### 任务 3：实现最小模型单步更新与环境收据

- [ ] 建立输入投影、CUDA 块和输出头均含 FP32 参数的最小模块。
- [ ] 执行一次真实 `optimizer.step()`，断言三模块参数有限且各至少一项更新。
- [ ] 记录 torch、CUDA、NVCC、C++、计算能力、构建日志、扩展二进制 SHA-256、显存与本门吞吐。

### 任务 4：实现持久启动器与幂等失败保留

- [ ] 启动器使用固定运行身份、非阻塞锁、持久构建根、日志、原子状态和输入摘要。
- [ ] 完成收据与当前执行身份一致时幂等跳过；失败目录和原退出码保留。
- [ ] 启动器不接受数据、训练或跟踪参数。

### 任务 5：静态验收与提交

- [ ] 执行本地允许的语法、导入、帮助、配置、Shell、供应商和差异检查。
- [ ] 扫描六个目标文件，确认禁止字段与非本门比较内容为零命中。
- [ ] 完成实施报告，明确未运行 CUDA、未训练、未读数据、未创建跟踪身份。
- [ ] 只暂存并提交六个目标范围中的新增文件，返回提交 SHA。

## 决策记录

- 资格门使用官方 CUDA 核的既有独立加载接口；新工具不复制或修改 CUDA 计算核。
- 掩码语义由外层独立模型在输入、输出和损失处执行，避免声称核内存在未实现的掩码接口。
- 本地环境不具备目标 GPU，因此本轮只交付静态实现；真实资格结论只能由目标环境收据给出。
