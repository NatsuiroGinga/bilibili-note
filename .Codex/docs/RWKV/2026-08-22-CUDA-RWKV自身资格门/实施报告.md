## 三、资格门实现

| 门 | 实现与机械断言 |
| --- | --- |
| 六输入合同 | 固定 `B=2,T=128,C=112`、头大小 `16`、头数 `7`、低秩维 `8`；`r,w,k,v,a,b` 均须为 BF16、CUDA、连续、可求梯度且有限。 |
| 同进程确定性 | 固定种子生成同一组有界输入，重复两次前向和反向；输出、损失和六梯度用 `torch.equal` 逐位比较。 |
| 有限与非零梯度 | 输出和损失有限；六梯度分别检查 `[2,128,112]`、BF16、CUDA、连续、有限且非零元素数大于零。 |
| 六输入微扰 | 在固定位置分别只改变一个输入；其余五个逐位不变，输出或损失必须发生有限变化。 |
| 外层掩码 | CUDA 核接口不声称具有掩码；独立模型在输入、隐藏输出和损失处应用掩码，断言有效前缀逐位不变、全零掩码输出与损失贡献严格为零。 |
| 单次优化更新 | 独立最小模型包含输入投影、低秩六路 CUDA 块和输出头；全部参数保持 FP32，执行一次 `AdamW.step()` 后三模块均有限且至少一个参数更新。 |
| 环境与资源 | 记录 torch、CUDA、NVCC、Ninja、活动 C++ 编译器、设备、BF16、`sm_120`、当前/峰值 allocated 与 reserved 显存、动态库路径与 SHA-256。 |
| 本门吞吐 | 固定预热三次、测量二十次，只记录本门序列/秒与时间步/秒，不与任何实现比较。 |
| 身份与失败 | 输入文件、当前环境和扩展二进制共同生成执行身份；三层身份一致才幂等跳过。每次失败写独立 `attempt-N/failure.json`，启动器保留预检日志、运行日志、原命令和 `tee` 退出码。 |

## 五、第三方接口核验

Context7 命令未返回可用正文，随后使用 PyTorch `2.13` 官方文档完成接口核验：

- `torch.utils.cpp_extension.load`：确认 `sources`、`extra_cflags`、`extra_cuda_cflags`、`build_directory`、`is_python_module` 与 `TORCH_CUDA_ARCH_LIST` 行为。
- `torch.use_deterministic_algorithms(True, warn_only=False)`：确认无确定性实现时应抛错，且仍需本门自行做逐位复核。
- `torch.cuda.is_bf16_supported()`：确认 BF16 能力返回布尔值。
- `torch.cuda.memory_allocated()`、`memory_reserved()`、`max_memory_allocated()`、`max_memory_reserved()`：确认当前和峰值显存口径。

官方文档路径已写入 `notes.md`。目标版本固定为 `torch==2.13.0+cu130`，实际运行版本不符即失败。

## 七、风险与下一门

1. 本机 `uv run --no-sync` 环境没有 PyTorch。工具已改为仅 `--run` 延迟导入，使静态入口可验收；目标运行缺少 PyTorch 时仍会失败并保留证据。
2. CUDA 计算核、六梯度、逐位确定性、六输入微扰、掩码、单步更新、二进制和显存收据均未在 `sm_120` 上实测，不能由静态检查推断通过。
3. 后续只能在用户授权的目标环境执行固定启动器。失败应保留并停止资格推进，不得据此启动数据训练链。
