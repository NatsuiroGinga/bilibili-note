**Goal**：使 `C10`／`C01`／`C11` 三个带机制的臂都能从 `inflight.pt` 原子恢复，
且恢复后的训练轨迹与不中断运行一致。

### 任务 1：各状态对象补 `state_dict` / `load_state_dict`

- [ ] **步骤 1**：为 `EntityMemoryState` 实现两个方法。逐实体状态可能很大
  （`150,680` 实体 × `R=8` 槽 × `d=192` × 4 字节 ≈ `0.93 GB`），
  **只保存已激活的实体**（`n > 0`），用稀疏表示（实体 id 张量 ＋ 紧凑状态张量）。
  记录已激活实体数，恢复时按 id 还原。

- [ ] **步骤 2**：为 `EntityChainScheduler` 实现游标序列化——当前实体链位置、
  已推进的实体集合或指针、轮次内偏移。

- [ ] **步骤 3**：为 `CvarThresholdState` 与分层采样器实现序列化

- [ ] **步骤 4**：状态往返核验——构造非平凡状态 → `state_dict()` → 新对象 `load_state_dict()`
  → 所有张量 `torch.equal` 为真，标量与 RNG 状态字典完全相等。不等即停止报告。

- [ ] **步骤 5**：提交（pathspec 形式）

- [ ] **步骤 1**：对 `z1=1`（C10 配置，小 `R`、小微批、小 `steps_per_epoch` 以便快速跑完）：
  - **A 组（不中断）**：连续跑 `N + M` 步，记录每步 loss 与最终权重哈希；

## 阻断条件（出现即停止报告，不自行绕过）

- 任一状态对象的往返核验不逐位相等；
- 任一配置的「中断—恢复」轨迹与「不中断」不一致；
- 稀疏实体状态还原后与保存前不一致；
- 恢复时机制开关或身份不一致却未被拒绝；
- 需要改动科学身份（有效批 `64`、学习率、轮数、步数）。
