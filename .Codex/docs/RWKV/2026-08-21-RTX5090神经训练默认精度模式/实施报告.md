# RTX 5090 神经训练默认精度模式实施报告

## 结论

已建立独立、可复用且默认不影响现有训练入口的神经训练精度与等效微批脚手架。默认配置标识为 `cuda-bf16-amp-fp32-sensitive-v1`：CUDA 前向使用 BF16 autocast，模型参数与优化器状态保持 FP32，BF16 不使用 `GradScaler`；softmax、对数、概率归一化、损失、归约、指标和模型声明的递归状态或路由计算使用禁用 autocast 的 FP32 敏感区。

当前状态是**工程默认已冻结、静态合同已验证、真实精度效果实验待证**。该配置由 RTX 5090 的 BF16 能力、项目既有 FP32 显存溢出和速度压力共同选择，不是本项目全模型精度效果 A/B 已证明的最佳配置。后续须用 LSPR23 源年代表模型补做同一模型、同一数据、同一预算的精度对照，才能讨论效果与效率权衡。

## 配置合同

### 默认与回退

| 设备或条件 | 配置 | autocast | 缩放器 | 依据 |
| --- | --- | --- | --- | --- |
| CUDA 且支持 BF16 | `cuda-bf16-amp-fp32-sensitive-v1` | BF16 | 无 | 工程默认，效果 A/B 待证 |
| CUDA 不支持 BF16 | `cuda-fp16-amp-gradscaler-v1` | FP16 | `torch.amp.GradScaler("cuda")` | 只作硬件回退，必须有收据 |
| CUDA 数值异常 | `cuda-fp32-numerical-fallback-v1` | 关闭 | 无 | 只作数值异常回退，必须有收据 |
| CPU | `cpu-fp32-v1` | 关闭 | 无 | 默认 FP32 |
| MPS | `mps-fp32-v1` | 关闭 | 无 | 默认 FP32 |

activation checkpointing 默认关闭；只有 BF16 加数学等效微批仍无法满足显存安全门时，才允许由模型入口显式开启并记录重算范围与代价。`torch.compile` 与 TF32 默认关闭，共享工具不会静默开启。

## 等效微批语义

`EffectiveBatchAccumulator` 固化以下顺序：

1. 原始优化步先确定该步全部实际有效单位数，归一化单位由模型显式声明为 `flow`、`sequence` 或 `entity`。
2. 只调用一次 `optimizer.zero_grad(set_to_none=True)`。
3. 每个微批在 FP32 敏感区生成 `loss_sum`，再除以该原始步全部有效单位数并反向传播。
4. 全部微批完成后，FP16 路径先反缩放；随后只执行一次梯度裁剪和一次优化器更新。
5. 尾批按真实对象数使用 `ceil(actual/microbatch)` 个微批，最后一个微批可以更小，不补齐、不丢弃。

有效批对象数来自每个实验的冻结合同。共享配置中的 `64` 序列、微批 `4`、累积 `16` 只是 N-12 已有合同的接入示例，已机械标记 `example_only=true` 和 `do_not_inherit_batch_values=true`；其他模型不得继承这些数值。

## 接入方法

现有入口须显式接入，推荐最小顺序如下：

```python
from neural_precision_runtime import (
    EffectiveBatchAccumulator,
    autocast_context,
    create_grad_scaler,
    fp32_island,
    load_and_validate_contract,
    validate_microbatch_plan,
    validate_model_optimizer_fp32,
    validate_runtime_profile,
)

contract = load_and_validate_contract(config_path)
profile_id = "cuda-bf16-amp-fp32-sensitive-v1"
profile = validate_runtime_profile(contract, profile_id, device.type, torch)
validate_model_optimizer_fp32(model, optimizer, torch)
scaler = create_grad_scaler(profile, torch)

plan = validate_microbatch_plan(
    effective_batch_items=effective_batch_items,
    microbatch_items=microbatch_items,
    accumulation_steps=accumulation_steps,
    normalization_unit=normalization_unit,
    is_tail_batch=is_tail_batch,
)
accumulator = EffectiveBatchAccumulator(
    total_valid_units=total_valid_units,
    normalization_unit=normalization_unit,
    torch_module=torch,
    expected_microbatches=plan["accumulation_steps"],
)
accumulator.begin(optimizer)

for microbatch in microbatches:
    with autocast_context(profile, device.type, torch):
        logits = model(microbatch.inputs)
    with fp32_island(logits, device_type=device.type, torch_module=torch) as (logits32,):
        loss_sum = loss_function(logits32, microbatch.targets.float(), reduction="sum")
    accumulator.backward(loss_sum, microbatch.valid_units, scaler=scaler)

accumulator.finish(
    model.parameters(),
    optimizer,
    torch,
    max_grad_norm=frozen_max_grad_norm,
    scaler=scaler,
)
```

检查点接入调用 `build_checkpoint_runtime_state(...)`，并把返回字典与模型、优化器、调度器和采样器状态一起保存。该函数拒绝 `optimizer_step_boundary=False`，同时记录配置、缩放器、有效批、微批、累积、归一化单位、尾批身份和 Python/NumPy/PyTorch CPU/CUDA 随机状态。半步中断仍须从原始优化步起点重放。

资源接入先在最坏候选第一完整优化器步前调用 `reset_cuda_peak_memory(...)`，完成后调用 `collect_resource_receipt(...)`。启动器须把外部 `nvidia-smi` 进程峰值作为参数传入；共享模块不自行启动子进程。收据同时保存当前与峰值的 allocated/reserved、外部显存、处理有效单位、耗时和吞吐。

## 第三方接口核验

- 目标运行时：项目锁和既有环境收据为 PyTorch `2.13.0+cu130`；本任务按要求不访问服务器，没有重新探测。
- Context7 官方库：`/pytorch/pytorch`；固定网页最高提供 PyTorch 2.12，没有 2.13 精确页面。
- 已核验统一接口：`torch.amp.autocast(device_type, ...)`、`torch.amp.GradScaler(device="cuda", ...)`、`torch.cuda.is_bf16_supported(...)`、`scaler.unscale_(optimizer)` 后裁剪、CUDA 当前与峰值 allocated/reserved 资源接口。
- 版本边界：本地静态检查不能证明 2.13 CUDA 运行时行为。每个实际接入入口仍须在正式环境先过配置能力门和第一完整优化器步收据。

## 资源选择依据

- RTX 5090 环境收据记录显存总量 `32607 MiB` 和计算能力 `12.0`。
- TabM4 回收的外部进程峰值为 `14644 MiB`，双年常驻数组占显存大头，证明只按参数量估算不成立。
- GRANDE G-B 的 FP32 路由展开在约 `30.05 GiB` 进程显存下仍需额外约 `3.04 GiB`，说明 FP32 全展平批次已超过单卡容量。
- RWKV-7 明确要求递归矩阵状态与相关张量保持 FP32，证明全模型无差别低精度同样不成立。
- 全容量 MLP 现有收据只覆盖部分内部峰值字段，新合同新增 reserved、max reserved、外部显存和吞吐，不能追溯性补写旧结果。
