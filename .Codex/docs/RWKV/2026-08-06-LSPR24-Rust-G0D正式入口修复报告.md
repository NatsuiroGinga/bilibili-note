## 1. 单一根因

原入口缺少从原始 Parquet 到正式开发制品的完整信任链：命令行接受调用者提供的成员选择，物化器未把来源文件、切分算法、切点和开发成员摘要绑定到外部收据，发布事务又在清理临时文件和同步父目录前报告成功。三项表面缺陷都源于同一个问题：生产入口把调用者对象和生产者自报状态当成了可信事实。

## 2. 修复内容

1. 新增严格的 Parquet 正式入口配置，使用 `deny_unknown_fields` 拒绝 `selection`、调用者标签、调用者特征和其他未登记字段。
2. 第一阶段只投影无标签切分所需列，独立计算来源 Parquet SHA-256、切分算法 SHA-256、四个切点、开发成员数和开发成员语义摘要，并排他发布外部切分收据。
3. 第二阶段在打开 `Label` 前重新核验收据自哈希、来源 Parquet SHA-256、切分算法、切点、开发成员数和开发成员摘要。
4. 对满足 `last >= cut80` 的记录先执行固定丢弃分支，再访问标签和特征；该分支不规范化、不序列化、不计数、不哈希最终区成员或标签。
5. 删除命令行的无条件 `G0-D_READY` 输出。当前入口固定报告 `G0-D=NOT_READY`、`G0-F=NOT_READY`、`G0-A12=NOT_READY` 和 `final_access_authorized=false`。
6. 修复 `PartialOutput` 提交状态机。只有正式硬链接创建、临时文件删除和父目录同步全部成功后才标记发布成功；任一后发布步骤失败时，析构会同时清理正式路径和临时路径，使相同正式路径可安全重试。

## 4. 真实 Parquet 只读模式盘点

只读取 `/Users/bilibili/personal/note/thesis/experiments/llm_probe/data/raw/lspr24-v1/lspr24_v2.parquet` 的 Parquet 页脚，没有读取任何行值、标签列页或攻击叙事。页脚确认：

- 总行数为 `20,227,356`，模式包含 `101` 列；
- `mTimestampStart`、`mTimestampLast` 为可空 `Int64`；
- `External_src`、`External_dst` 为可空 `String`，不是当前正式入口断言的 `Boolean`；
- `Label`、`SrcPort`、`DstPort`、`Protocol` 为可空 `Int32`；
- 原始合法流量字段主要为 `Int32` 或 `Double`；除两个时间列外，页脚中的其他 `Int64` 只有 `Bwd Bulk Rate Avg` 和禁入的 IDS 字段 `Severity`；
- 既有数据接入证据将原始时间说明为微秒整数，而当前正式入口按纳秒除以 `1_000_000_000` 计算活动秒，时间单位合同尚未在该入口正确实现。

因此不能把测试夹具中的 `Boolean External_*`、纳秒时间和单个 `Int64` 特征直接套用到真实 LSPR24。

## 5. 完整 G0-D 的剩余阻断项

当前新增入口只产生前 80% 原始开发行 JSONL 和一个切分收据，不等同于合同要求的完整 `G0-D`。至少还缺少：

1. 按真实字符串语义解析 `External_src/External_dst`，并生成端点解析器清单、受限映射和机器收据；
2. 正确执行微秒到规范纳秒的时间转换、无效时间隔离、无标签去重、重复标签冲突整类隔离、会话连通分量和跨边界隔离；
3. 支持真实 `Int32/Double` 合法原始字段，并冻结逐列 `dedup-projection-manifest.json`；
4. 按合同第 6.1 节生成完整 `field-manifest.json`、字段谱系、5 秒窗口聚合和 `development-windows.parquet`，而不是单字段原始行 JSONL；
5. 生成历史长度 `1/4/16/32` 的样本索引、边界守卫、事件簇、非重叠推断锚点、评价簇和全部 `G0-D` 核心收据；
6. 独立归约全部开发门禁并完成独立审查。只有这些收据真实通过后，`G0-D` 才能从 `NOT_READY` 变为开发基线放行状态。

这组差距会直接影响科学有效性，不能用单个 `Int64` 原始列、空数组或生产者自报布尔值替代。
