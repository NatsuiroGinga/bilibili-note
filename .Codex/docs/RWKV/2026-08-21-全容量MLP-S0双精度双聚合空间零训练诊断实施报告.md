## 二、独立审查根因

1. `index_array` 与 `mask_array` 被重复 `del`，会在首个检查点前触发 `UnboundLocalError`。
2. 源门按各臂同名名义 FPR 键比较，但完整并列组使各臂实际 FP 不同；首次告警也没有共同 FP 预算和共同曝光轴。
3. `build_manifest` 先哈希 `status.json`，收尾随后又把状态改成 `complete`，清单哈希必然失真。
4. 源数组未绑定父 `source_data_inventory` 及其 SHA-256，也没有逐数组内容哈希；源与目标共用一份收据，会相互覆盖。
5. `finalize` 把 target 目录视为可选，无 target 单元也可标记 `complete`。
6. 病灶分类用 `any(improved.values())` 放行类别，任意不对位臂的改善都能投票。
7. 跟踪发布未上报 `group/tags`，也未调用中央 20 码点标签门。

## 三、修订内容

### 3.1 公共整数 FP 预算

- 六档锚点投影为 `floor(nominal_target_fpr * negative_entity_denominator)`。
- 每臂只取自身完整并列组曲线中 `FP <= 公共整数预算` 的最后可达点，不插值、不拆并列组。
- 首次告警从各臂在线前缀分数的实体路径最大值构造预算曲线，在同一整数 FP 预算下冻结阈值。
- 候选与强基线在两者精确 `exposure_index` 断点的并集轴上逐点比较，未告警恶意实体仍保留在固定分母。

### 3.2 输入与恢复

- 源输入必须匹配父 `selection_frozen.json#/source_data_inventory`，并复算父 inventory SHA-256。
- 每个 `.npy` 计算内容 SHA-256，逐数组内容 inventory 哈希纳入单元身份。
- 收据拆为 `input-validation-receipt-source.json` 与 `input-validation-receipt-target.json`。已有收据只能在逐字段一致时复用，不一致即停止，不覆盖。

### 3.3 状态、收尾与分类

- 删除重复数组释放。
- `finalize` 强制核验目标年收据、四个 target 单元、重算单元身份、同检查点哈希和同权重哈希。
- 先写最终 `complete` 状态，再生成清单；清单是工具最后一个写入的生产文件。
- 推理精度、聚合空间和交互类别分别只认 `fp32_probability_mean`、`bf16_logit_mean` 和 `fp32_logit_mean` 的对位改善。

### 3.4 冻结科学合同未变

- 仍只读 `B00/B10/O01/O11`，同一精度的概率与对数几率聚合臂共享同一份前向对数几率。
- BF16 与 FP32 只改计算精度，权重 SHA-256 必须相同；聚合算术统一为 `float64`。
- 训练次数、参数更新、优化器步和新检查点写入均为零。
- 年度顺序仍为 `source → seal → target → finalize`；当前配置或代码哈希与源封印不同时拒绝读取 LSPR24。
