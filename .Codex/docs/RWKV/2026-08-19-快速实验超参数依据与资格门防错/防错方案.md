# 快速实验超参数依据与资格门防错方案

## 结论

本次事故应由一个最小机制防止：**任何比例、预算、网格、置信水平或其他魔法数字在进入冻结配置前，必须同时取得“直接文献依据、数学／统计推导、真实数据或源侧实验依据、适用边界、无标签资格收据、风险／功效样本量收据”；启动器只接受这些依据的哈希绑定，缺一项即在创建运行身份、资源门、跟踪、模型加载和预测之前退出。**

单纯在实现中补“实体数为零时报错”不能防复发。它只能把同一个错误从运行后段移到稍早位置，仍允许无依据参数进入方案和配置。

## 一、超参数来源分类与禁止条件

### 1.1 来源分类

本方案把“魔法数字”定义为：**任何未由冻结数据、接口合同或已证明公式唯一决定，却会改变数据成员、模型行为、搜索空间、阈值、停止、统计误差、计算预算或实验裁决的数值。** 数据清单中的精确行数、模式版本和由公式唯一计算出的派生值不是自由选择，但仍须绑定来源和哈希。数值只是运行身份的一部分且改变它不改变统计分布时，应明确登记为标识符，不能借“标识符”掩盖种子数、重复数或预算等真实实验选择。

| 类别 | 定义 | 能否冻结 | 必备证据 |
| --- | --- | --- | --- |
| `A-DATA` 数据事实 | 从冻结输入用不含标签的确定性统计得到，如实体首末时间分位数、可用实体计数 | 可以，但只能支持资格或边界可行性，不能支持效果 | 数据清单哈希、统计入口哈希、字段与单位、聚合规则、收据 |
| `B-LIT` 直接文献 | 原始论文或正式全文明确给出公式、条件或数值 | 满足适用前提后可以 | DOI／原件路径、页码／公式、原始语境、前提差异 |
| `C-INHERIT` 同语义继承 | 从已冻结前代实验继承，统计单位、角色、数据权限和用途完全相同 | 可以 | 前代配置／收据哈希、逐字段语义等价证明 |
| `D-PROJECT` 项目预注册假设 | 为成本、敏感性或工程覆盖人为设定，没有直接文献数值 | 可以做 Q0，但必须写明“人为假设”并预注册敏感性与停止条件 | 选择理由、候选集合、禁止看标签声明、裁决门 |
| `E-DIAGNOSTIC` 事后诊断值 | 看过目标标签、结果或失败后选出的值 | 禁止进入同一比较的正式冻结配置 | 只允许保留为诊断，不得迁移为依据 |
| `F-LEGACY` 旧形态／便利默认 | 从旧脚本、旧比例、默认参数或相似任务复制，但未证明语义等价 | 禁止，重新取得 `A/B/C/D` 资格后才可使用 | 迁移差异表与新收据 |

`10%` 在旧 PBC 中属于 `D-PROJECT`，迁移到“完整实体选择段”后因角色语义改变自动降为 `F-LEGACY`。不能因为数值未变而继续标为已冻结。

来源类别只说明数值从哪里来，**不能代替完整验证**。每个魔法数字还必须同时通过以下四轴门：

| 依据轴 | 必须登记 | 通过条件 |
| --- | --- | --- |
| `L` 直接文献 | 正式全文、DOI／原件、页码／公式、支持对象、与本项目差异 | 原始来源能支持该数值、公式或明确的选择范围，且适用前提没有被静默外推 |
| `M` 数学／统计推导 | 公式、输入量、计算器哈希、精确结果、取整与误差界 | 能从冻结目标与输入唯一复算该值或候选范围 |
| `E` 真实／源侧证据 | 冻结真实数据无标签统计或仅源侧实验制品、哈希、样本单位、标签权限 | 证据没有读取目标评价标签，且直接验证该值在当前数据合同上可执行或有源侧信号 |
| `B` 适用边界 | 数据版本、统计单位、角色、范围、独立性／交换性、失效条件 | 当前实验逐项落在边界内；任一前提变化会自动使收据过期 |

四轴状态只有 `passed/missing/failed`。四项全为 `passed` 才能得到 `verified`；任一 `missing` 时必须标为 `unverified`，任一 `failed` 时标为 `rejected`。`unverified/rejected` 均不得进入快速或正式实验冻结配置。禁止用 `not_applicable`、专家经验、旧脚本默认值或“先跑再说”绕过任一轴。

### 1.2 机械禁止条件

出现任一项，方案状态只能为“未具备冻结资格”：

1. 缺 `parameter_id`、来源类别、证据路径／DOI、适用前提或责任人。
2. `C-INHERIT` 的统计单位、角色、标签权限、时间定义或用途任一不同。
3. 直接方法来源仍标为待检索，却已把公式、置信水平或数值写入冻结配置。
4. 参数由目标标签、评价结果、失败结果或后验最优点选择。
5. 比例没有用生产实体键和生产边界谓词做无标签资格计数。
6. 风险预算没有给出比较族、校正后 `δ`、最小分母和功效假设。
7. 预注册网格没有确定性选择规则，允许看计数后人工挑一个“看起来够用”的边界。
8. 资格或统计收据与配置、数据清单、生产入口哈希不一致。
9. 任一魔法数字的 `L/M/E/B` 四轴不全为 `passed`，或注册表没有覆盖配置中的全部数值自由度。

### 1.3 `10%/10%/80%` 反例

这组比例必须登记为本事故的禁止样例：

- `L=missing`：没有直接文献给出 LSPR24 完整实体选择／确认／评价的该比例；
- `M=missing`：没有由风险界、功效或尾部分辨率推导先导段所需规模；
- `E=failed`：真实无标签资格诊断显示四组早期边界的选择与确认完整实体均为 `0`；
- `B=failed`：旧 PBC 的无标签流前缀语义不等于新方案的完整实体双段语义，全局时间比例也没有覆盖实际实体活动区。

因此总状态是 `rejected`、`freeze_eligible=false`。旧配置、恢复卡或已经存在的生产实现都不能覆盖该裁定。

## 二、冻结前无标签资格门

### 2.1 单入口与顺序

资格门必须是正式工具的只读子命令或与正式工具共享同一核心函数，执行顺序固定为：

`配置草案 → 无标签资格门 G0 → 方案边界封印 → 段内标签分母门 G1 → 实现／启动绑定 → 资源与跟踪门 → 模型评分 → 阈值封印 → 评价`

`G0` 只允许读取生产数据清单、实体键所需字段和时间字段。必须满足：

- 不读取标签、模型、分数、结果或攻击叙事；
- 不创建正式运行身份、运行目录或 SwanLab 运行；
- 不加载模型、不做预测；
- 使用与生产路径完全相同的无向 `2-IP` 实体键、首末时间计算、边界包含关系和跨界处理；
- 输出原子 JSON 收据，不持久化实体成员表；
- 逐组报告选择、确认、评价、跨界计数，验证和为总实体数且集合两两不交叉；
- 对每一角色执行必要规模检查，而不只是 `>0`。

当前事故数据在 `10/20`、`15/30`、`20/40`、`25/50` 四组边界上均为选择 `0`、确认 `0`，因此所有四组必须在 `G0` 直接拒绝，禁止进入正式运行。

### 2.2 预声明边界与选择规则

资格门可以扫描多个边界，但只有在扫描前已冻结以下内容时才允许机械选择：

1. 候选边界集合；
2. 边界参数化单位，例如全局墙钟比例、活跃秒秩或实体完成秩；
3. 必要计数门；
4. 确定性选择规则，例如“选择满足全部必要门且评价保留最多的最早边界”；
5. 全部失败时的停止动作。

扫描后临时新增比例、扩大窗口或改用另一时间单位，必须新建方案版本并重新取得依据；不得在同一 Q0 身份中补救。

### 2.3 无标签门的能力边界

无标签 `G0` 只能证明总实体数在拓扑上可能满足要求，不能知道良性实体分母。因此还需要 `G1`：在边界已经封印后，只读取方案允许的选择／确认段标签，聚合良性实体数，**在任何模型加载、预测、阈值构造和跟踪初始化之前**比较 `n_selection`、`n_confirmation` 与样本量门。

`G1` 失败时只能停止或按预注册合同直接使用源阈值；不得依据标签计数扩展边界。这样既不把标签用于选比例，也避免全量预测后才发现统计上不可能。

## 三、由风险界与功效反推样本量

### 3.1 风险界必要门

对预算 `p`、族错误率 `α_F` 和同族候选数 `m`，令 `δ=α_F/m`。观察到 `k` 个误报、`n` 个独立良性实体时，单侧 Clopper–Pearson 上界为：

`U_CP(k,n,δ)=Beta^{-1}(1−δ;k+1,n−k)`。

零误报是最有利情况，必要样本量为：

`n_risk=ceil(log(δ)/log(1−p))`。

当前“每预算 `7` 候选、`α_F=0.05`”的 P0 门为：

| 实体 FPR 预算 | `G1` 最少良性确认实体 |
| ---: | ---: |
| `1%` | `492` |
| `2%` | `245` |
| `4%` | `122` |

若确认实体少于对应门，即便零误报也不可能通过风险上界，必须在预测前停止。若三个预算也属于同一同时覆盖比较族，数字应改为 `602/299/148`，但该口径须先由用户冻结。

### 3.2 功效充分门

风险界门只回答“最好情形是否可能通过”，不回答“一个真实 FPR 为 `q` 的合格方法有多大概率通过”。功效门必须额外冻结 `q<p` 与 `β`：

`k_max(n)=max{k: U_CP(k,n,δ)≤p}`

`Power(n;q)=BinomCDF(k_max(n); n,q)`

`n_power=min{n≥n_risk: Power(n;q)≥1−β}`

配置若缺 `q_design` 或 `beta_design`，只能声明“风险界可计算”，禁止声明“样本量充足”或“确认段有足够功效”。计算器应穷举整数 `n`，保存首个通过点及前一个失败点，避免浮点或取整歧义。

### 3.3 选择段分辨率门

设候选尾率最小值为 `r_min`，要求尾部至少有 `h` 个良性实体，则：

`n_selection_resolution=ceil(h/r_min)`。

当前 `r_min=0.001`，即便 `h=1` 也至少需要 `1,000` 个良性选择实体。`h` 不是统计文献自动给出的常数；缺少预注册 `h` 时不得声称最小尾率候选有足够分辨率。

### 3.4 风险收据必填字段

至少保存：预算、比较族定义、候选数、预算数是否纳入校正、`α_F`、`δ`、`n_risk`、`q`、`β`、`n_power`、`r_min`、`h`、`n_selection_resolution`、实际选择／确认良性实体数、误报数、上界、独立性单位、交换性边界、计算器哈希、通过／失败与原因。

## 四、三层断言

### 4.1 方案层

方案负责人必须在写实施计划前断言：

- 每个超参有唯一 `parameter_id` 和来源类别；
- 继承参数存在逐字段语义等价表；
- 直接方法来源已核验到页码／公式，广泛原创性检索可并行；
- 边界候选、选择规则、统计单位、标签权限、比较族、样本量、功效和停止条件齐全；
- 无标签资格收据已经通过并与方案版本绑定。
- 魔法数字注册表覆盖配置中全部数值自由度，每项 `L/M/E/B` 均为 `passed`，`unverified_count=0`、`rejected_count=0`。

### 4.2 实现层

实现入口必须断言：

- 资格诊断和正式运行调用同一实体键与分段函数；
- `role_total=N_entity`、角色两两不交叉、每段计数达到必要门；
- `target_labels_loaded=false`、`model_predictions_run=false` 直到 `G0` 通过；
- 边界封印后才允许 `G1` 聚合标签分母；
- `G1` 通过前不加载模型、不预测；
- 风险计算公式、校正口径和配置一致；
- 样本不足时精确执行预注册停止或源阈值回退，不得改比例；
- 收据原子写入，并含数据、配置、工具和方案哈希。
- 配置解析器枚举全部数值字段，与魔法数字注册表的 `config_json_pointer` 做双向全等检查；未登记、多登记、值不等或四轴未通过均立即退出。

### 4.3 启动器层

启动器必须在资源门和跟踪门之前：

1. 执行或读取 `G0` 无标签资格收据；
2. 核对收据非空、状态通过、标签／预测／运行身份均为假；
3. 核对收据中的数据清单、配置、工具、方案哈希；
4. 执行 `G1` 分母门，失败时写状态并退出；
5. 只有两门通过才进入内存、GPU、SwanLab 与正式工作进程。

在上述步骤之前，启动器还必须验收 `magic-number-gate.json`：

- `registry_complete=true`；
- `unregistered_numeric_count=0`；
- `unverified_count=0`；
- `rejected_count=0`；
- `literature_missing_count=0`、`derivation_missing_count=0`、`empirical_missing_count=0`、`boundary_missing_count=0`；
- `config_numeric_digest` 与当前配置逐数值规范化摘要一致；
- 注册表、方案、数据清单、计算器和源侧制品哈希均匹配。

任一断言失败，状态固定写为 `failed/magic_number_gate/<具体原因>`，并在创建运行目录、资源门和 SwanLab 之前退出。

后置检查仍要复核阈值封印、评价标签读取顺序和必要制品，但不能用后置失败代替前置资格门。

## 五、并行边界与不得阻塞项

### 5.1 可并行

- `B-LIT` 的方法原始来源核验、`G0` 无标签资格统计和样本量计算三者互不依赖，可以并行。
- 完整 D3 直接近邻与原创性检索可以与已过资格门的 Q0 并行；新近邻只收缩原创措辞，不自动证明实验无效。
- 不同实验身份的数据只读、输出独立且各自通过门禁时，不因本事故复盘阻塞。

### 5.2 必须串行

- 方案冻结必须等待参数依据、`G0` 和样本量必要门都通过。
- `G1` 必须在边界封印之后、模型评分之前。
- 启动必须等待方案、实现和启动器三层哈希一致。

### 5.3 不得阻塞

- 宽泛文献补链、Zotero、格式化、归档和非阻断性复审不得延迟已经通过三类 P0 门的真实 Q0。
- 某一边界资格失败只阻断该实验，不阻断无关实验或其他数据合同。
- 资格门不读取效果，因此不能用来否决机制有效性；它只裁定实验是否可执行、风险界是否可能成立。

## 六、责任归属与停止条件

| 责任人 | 唯一责任 | 不得转嫁 |
| --- | --- | --- |
| 方案负责人 | 参数来源、角色语义、比较族、功效目标、候选边界与停止条件 | 不能让实现者替方案补依据 |
| 数据／统计负责人 | 生产语义的无标签资格收据、风险与功效样本量收据 | 不能用全局行数代替实体分母 |
| 实现负责人 | 共享分段函数、前置标签门、风险计算和原子收据 | 不能把“运行后报错”当资格门 |
| 启动器负责人 | 哈希绑定、门禁顺序、失败状态和零副作用退出 | 不能只核对配置可解析 |
| 主代理／实验负责人 | 在启动前签署三层通过，确认失败身份不复用 | 不能因机器已开或代码已同步绕过门禁 |

任一条件触发立即停止受影响实验：

1. 参数来源为 `E-DIAGNOSTIC` 或未重新取得资格的 `F-LEGACY`。
2. 任一魔法数字缺直接文献、数学／统计推导、真实数据或源侧实验依据、适用边界中的任一项。
3. `G0` 任一必要角色为零、计数不足、集合不互斥、总数不守恒或哈希不符。
4. `G1` 的良性选择／确认实体低于 `n_selection_resolution`、`n_risk` 或已冻结的 `n_power`。
5. 风险计算不可复现，或比较族、`δ` 与配置不一致。
6. 资格诊断与正式实现的实体键／边界谓词不同。
7. 门禁前已经创建运行身份、初始化跟踪、加载模型、预测或读取评价标签。
8. 失败后试图在同一身份中扩大比例、改时间单位、减少候选数、放宽置信水平或改预算。

失败后允许的唯一动作是：保留失败证据；新建方案版本；在不看效果的前提下重新取得参数依据与资格；使用新运行身份。当前四组早期边界全部为零实体，不能继续从同一网格试更大比例；若要改用实体完成秩或活跃时间秩，必须由用户先裁决新语义。

## 七、一页快速实验前检查表

### A. 方案冻结前

- [ ] 每个比例、网格、预算、置信水平和功效参数都有 `parameter_id`。
- [ ] 来源已归为 `A-DATA/B-LIT/C-INHERIT/D-PROJECT`；没有 `E-DIAGNOSTIC/F-LEGACY` 混入冻结配置。
- [ ] 继承值的统计单位、角色、标签权限、时间定义和用途逐项相同。
- [ ] 直接方法来源已核验到 DOI、原件、页码或公式；没有“待查文献”数值进入冻结配置。
- [ ] 边界候选集合和确定性选择规则在资格扫描前写定。

## 八、可立即采纳的 P0 规则

1. **参数换角色即失去继承资格**：数值相同也必须重做依据和无标签资格门。
2. **魔法数字四轴缺一不可**：直接文献、数学／统计推导、真实数据或源侧实验依据、适用边界任一缺失即“未验证”，禁止进入快速或正式实验冻结配置。
3. **先数实体，后开运行**：资格门必须在运行身份、资源、跟踪、模型和预测之前完成。
4. **样本量由公式反推**：当前预算内七候选口径下，确认段良性实体少于 `492/245/122` 时，`1%/2%/4%` 风险界分别不可能通过。
5. **无标签门不冒充负类分母门**：边界封印后必须在预测前补 `G1`；不足时不得看结果改边界。
6. **三层都要断言**：方案给来源与门槛，实现给同语义计算，启动器给哈希与顺序；任一层缺失不得启动。
