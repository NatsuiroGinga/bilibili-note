# SSH 255 与远程同步静默失败根因报告

- **日期**：2026-08-08
- **范围**：`thesis/experiments/llm_probe/tools/remote_exec/`
- **网络探测**：未执行；全部结论来自失败链、源码和本机无网络回归。

## 结论

1. 直接执行两个 `.exp` 返回 `126` 的根因是文件模式为 `0644`。解释器首行不能替代执行位；Shell 在启动 `expect` 前已经以 `Permission denied` 失败。现已将两文件改为 `0755`。
2. `expect tools/remote_exec/gpu_env_quiet.exp ...` 返回 `255` 时，`expect` 没有把状态改坏。Expect 5.45 的 `wait` 返回四元组 `pid spawn_id os_error_flag status`，原实现读取索引 3，正常传播了 `ssh` 子进程的 `255`。SSH 用 `255` 表示连接、认证或主机密钥等 SSH 层错误；旧包装器设置 `log_user 0`，又只打印成功标记，因此把具体 SSH 诊断全部吞掉，形成“退出码 255、输出为空”。旧运行的具体 SSH 错误类型已不可恢复，不能无证据归因为服务器离线或密码错误。
3. “`rsync` 返回 0 但目标不存在”不是一次真实的 `rsync=0`。该命令同样直接执行了 `0644` 包装器，实际在启动 `rsync` 前返回 `126`；调用方只展示嵌套结果的 `output`，未检查 `exit_code`，因空输出而误报成功。远端文件不存在正是 `rsync` 从未启动的预期结果。
4. 当前 `GPU_SSH_A44` 经脱敏结构检查为四个简单词元，包含合法 `-p` 数字端口，末词元为 `用户@主机` 形态，不含引号、`-o` 或 `-i`，所以当前 `split` 不会制造 `255`。不过原 `gpu_rsync_push.exp` 只重建 `ssh -p <端口>`，会丢失以后新增的 SSH 选项；现已改为保留目标主机之前的全部词元。
5. Expect 运行在本地伪终端中，足以响应 SSH 密码提示；是否分配远端伪终端由 SSH 的 `-t` 决定，本次短命令与 `rsync` 不需要远端伪终端。macOS 使用 `/usr/bin/rsync`，实现为 `openrsync`、兼容协议版本 29；本次失败发生在它启动前，不是 `openrsync` 传输成功后漏写文件。

## 可证伪根因

### 假设一：`255` 是 SSH 子进程状态，不是 Expect 的 `wait` 解析错误

- **证据**：本机 `expect` 对退出 `37` 的子进程返回四项状态，错误标志为 `0`、索引 3 为 `37`。
- **回归**：用 `/bin/sh -c 'exit 255'` 代替 SSH 后，修复后的包装器退出 `255`，并输出 `远程命令失败，SSH 退出码：255`。
- **证伪条件**：若真实失败时包装器退出码不等于裸 SSH 的退出码，或 `wait` 的第三项非零，则需转向 Expect 子进程回收错误调查。

### 假设二：所谓 `rsync=0` 是调用方遗漏 `exit_code` 的观测错误

- **证据**：失败链中的同步包装器当时为 `0644` 且被直接执行，与已复现的 `126` 条件完全相同；没有任何 `rsync` 启动证据。
- **证伪条件**：只有提供同一次调用中明确的 `exit_code=0`、`rsync` 启动输出以及随后目标存在性检查，才能推翻该结论。

## 最小修复

- `gpu_env_quiet.exp`
  - 文件模式改为 `0755`，恢复直接入口。
  - 增加参数与必需环境变量门禁。
  - 增加首次主机密钥确认提示处理。
  - 在 EOF 输出远端业务文本，并按当前连接参数脱敏密码、目标、主机与端口字面量。
  - 对异常 `wait` 返回使用保留退出码 `125`；对子进程非零状态输出明确 SSH 退出码；超时输出 `124`。
- `gpu_rsync_push.exp`
  - 文件模式改为 `0755`，恢复直接入口。
  - 增加必需环境变量门禁。
  - 保留目标主机之前的完整 SSH 参数，不再只重建端口。
  - 对异常 `wait` 返回使用保留退出码 `125`；对 `rsync` 非零状态输出明确退出码。

仍保留 `log_user 0`，避免 `spawn` 回显连接命令；远端业务输出只在脱敏后打印。调用方必须同时检查 `output` 与 `exit_code`，任何非零都不得报告同步或远程执行成功。

## 回归验证

以下命令只使用本机伪子进程，不联网，也不读取真实凭据值：

```bash
cd /Users/bilibili/personal/note/thesis/experiments/llm_probe

tools/remote_exec/gpu_env_quiet.exp
tools/remote_exec/gpu_rsync_push.exp

GPU_SSH_ACTIVE='/bin/sh -c' GPU_PWD_ACTIVE='dummy' \
  tools/remote_exec/gpu_env_quiet.exp 'exit 255'

GPU_SSH_ACTIVE='/bin/sh -c' GPU_PWD_ACTIVE='dummy' \
  tools/remote_exec/gpu_env_quiet.exp \
  'printf "__CODEX_RESULT_BEGIN__ok__CODEX_RESULT_END__"'

GPU_SSH_ACTIVE='/bin/sh -c' GPU_PWD_ACTIVE='dummy-secret' \
  tools/remote_exec/gpu_env_quiet.exp \
  'printf "REMOTE_OK credential=dummy-secret\n"'

GPU_SSH_ACTIVE='/usr/bin/false -p 22 fake@host' GPU_PWD_ACTIVE='dummy' \
  tools/remote_exec/gpu_rsync_push.exp \
  tools/remote_exec/gpu_env_quiet.exp /unused
```

实测结果：

- 两个无参数直接入口均退出 `2` 并打印用法，不再返回 `126`。
- 模拟 SSH 失败退出 `255`，标准错误明确显示 `SSH 退出码：255`。
- 成功标记路径退出 `0`，标准输出为 `ok`。
- 普通业务输出路径退出 `0`，业务行可见，测试凭据字面量被替换为 `<已脱敏>`。
- 模拟 `openrsync` 远端 Shell 失败退出 `1`，标准错误明确显示 `rsync 同步失败，退出码：1`。

## 局限

- 没有执行真实网络探测，因此未验证当前服务器的在线、认证或主机密钥状态，也没有影响正在运行或即将运行的实验。
- `GPU_SSH_ACTIVE` 目前按空格拆分。当前规范值不含引号或带空格参数，已满足该前提；若以后需要此类参数，应把连接配置改为结构化参数列表，不能继续依赖 Shell 字符串拆分。
- 修复后首次真实同步仍必须按合同执行远端父目录存在性检查、同步后目标存在性检查和 SHA-256 核对；包装器退出 `0` 不能替代这些后置验收。
