# LSPR24 Rust `G0-D/G0-F` 分阶段实施计划

> **代理执行要求：**使用 `subagent-driven-development` 逐任务实施；每个实现代理在自己的任务边界内使用一次 `test-driven-development`，只运行精确目标测试。

**目标：**先实现 LSPR24 前 80% 开发可见区的受限标签路由、确定性物化、机器收据和 `G0-D` 裁决，为公平基线与方案 A/B 提供同一冻结开发视图；最终 20% 的严格封存和一次性评价推迟到配置冻结后的 `G0-F`。

**架构：**在 `tools/lspr24_g0/` 建立独立 Rust 包，以开发受限路由、开发物化和门禁三个二进制隔离权限。首轮先实现不读取标签的 Parquet 时间扫描；当前任务 5 的受限路由器只输出前 80% 标签和合法特征，对后 20% 执行零输出丢弃。`AES-256-GCM`／`Ed25519` 最终封存器不属于当前任务 5，待 `final-freeze.json` 通过后单独实现。

**技术栈：**Rust 2024、Rust 1.85 以上、Arrow/Parquet 55.2.0、Serde、SHA-256、Python/PyArrow 小样本参考。

## 全局约束

- 分阶段合同：[LSPR24 G0 数据与切分合同](2026-08-05-LSPR24-G0数据与切分合同.md)，规范版本 `lspr24-g0-v4-staged`，SHA-256 `6ba37e7be3765d876977e95114adebd0b185d05b1b2311ed0c7c6236e0ca8389`。
- 第一遍只读取合同允许的时间列和稳定分组字段，不读取标签、攻击叙事或最终测试内容。
- 不修改现有 R2 Rust 包，不建立根 Cargo 工作区。
- 每个任务只运行列出的目标测试；格式化、全仓检查和独立复审不得阻塞下一项可并行实现。
- 正式输出拒绝覆盖，所有运行绑定输入、合同、配置、代码和开发制品哈希。
- `G0-D` 不创建最终特征、最终标签、最终行选择、最终成员清单、最终计数或最终哈希；`G0-A12` 保持 `NOT_READY`，不得伪造 `PASS`。
