# RWKV 方案审查笔记

## 当前方案

- 用户已放宽加密约束，首选主题应改为面向长时恶意流量或网络异常状态的 RWKV 检测与漂移校准。
- 第三章责任：多尺度因果状态表示。
- 第四章责任：时间前向漂移与开放集状态校准。
- 计划基线：HGB、GRU、轻量 Transformer、普通 RWKV，以及机制删减版本。

## 已核验证据

- RWKV 原始论文只支撑并行训练与递归推理等通用架构事实。
- PLM-NIDS 提供 RWKV-4 用于非载荷网络入侵检测的直接相邻证据，但没有多尺度同父会话、时间前向漂移或开放集校准合同。
- NetMamba 支撑线性状态空间模型用于网络流量分类，不直接支撑 RWKV 在当前数据上的性能优势。
- RWKV-TS 支撑连续时间块与异常检测的相邻设计，但其公开结果并不证明 RWKV 必然优于 Transformer。

## 数据事实

- 现有 GeNIS 候选连接映射存在身份缺失、持续时间不匹配和重复 FlowID，当前不可用于长序列先导。
- 现有 TQH-C2 冻结开发视图中，同父会话长度至少 4、16、32 的样本数均为 0。
- UGR'16 特征版适合分钟级长时异常状态，不是单连接序列，也不是加密流数据。
- UGR'16 官方原始合同包含真实 ISP 背景流量与人工注入、签名或异常检测得到的多类攻击标签，能够支撑网络异常检测；其特征版一行对应一分钟内混合流量，不能写成逐流分类。
- UGR'16 原始校准区主要承担正常行为建模。若采用官方时间协议，RWKV 更适合做因果预测或密度式生成异常评分；若改做监督分类，必须按攻击批次和连续时间块重新冻结开发、校准和最终测试，不能随机切分分钟行。
- UGR'16 的重叠滑窗不能当作独立样本做统计推断；统计簇至少应按日期、周或攻击事件定义。
- CTU-13 可能支持连接级恶意流序列，但必须先审计父连接键、时间单调性、场景隔离和泄漏。

## 待独立审查

- 核心论文是否足以支持两个创新点的研究空白。
- UGR'16 是否只能作为主题改名后的主数据，或仅适合作外部长时验证。
- 100M 至 450M RWKV 与公平基线的单卡三种子预算是否现实。
- 现有实验矩阵是否能区分“长历史有用”“RWKV 架构有用”和“漂移校准有用”。

## 主审初步问题

- 普通 RWKV 加多尺度切窗仍是应用适配，不足以单独构成结构创新；需要明确改变状态更新、跨尺度融合或生成目标的计算图，并与普通 RWKV 独立消融。
- 漂移校准若只是阈值或温度缩放，难以支撑一章；应冻结为时间前向、自适应阈值或覆盖率控制问题，并以误报率、检测延迟、校准误差和开放集指标裁决。
- 当前计划未说明使用预训练语言 RWKV、从头训练数值 RWKV，还是 RWKV-TS。三者的数据规模、基座含义和论文定位不同，必须在实现前唯一化。
- HGB 只看当前分钟不是公平强基线；需要增加相同历史预算的滞后特征树模型、GRU、TCN、轻量 Transformer、Mamba 或 RWKV-TS，以及适合正常行为建模的异常检测基线。
