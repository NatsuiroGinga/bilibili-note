## 统一接口

- `Lspr24ScreenDataset` 只接收名为 `dataset-manifest.json` 的路径，验证合同版本 `lspr24-screen-6-2-2-v1`，并只经清单的 `wide_table`、`labels`、`field_manifest` 与 `temporal_relations` 制品键发现输入。
- 加载器从字段清单的 `entries` 与清单 `model_feature_columns` 一致性确认允许特征，支持字段组、字段名、`H=1/4/16/32`、`train/validation` 和任务投影参数。当前快速基线只实现 `binary_detection`；它拒绝最终切分。
- 训练与验证抽样仅按 `window_row_index` 的 SHA-256 稳定排序，最多分别保留 200000 与 50000 个样本，不读取标签决定入样。
- 基线固定运行 HGB/XGBoost 的 `H=1/H=4` 四个配置。每个配置写出 PR-AUC、宏平均 F1、平衡准确率、精确率、召回率、良性误报率、样本数、训练与推理耗时、原始预测和逐模型指标。
- 每次运行要求唯一输出目录，保存配置、环境、控制台输出、指标、汇总、压缩原始预测和 SwanLab 结果。SwanLab 初始化或上传失败会写入失败状态，但不会删除或遮蔽本地结果。

## 服务器开机后的顺序

1. 在项目根先运行 Rust 宽表物化入口，并传入冻结配置 `tools/lspr24_g0/configs/lspr24-development-wide-screen-v1.json`。
2. 确认物化运行根生成 `dataset-manifest.json`，其制品 SHA-256、训练/验证切分与字段清单通过生产端收据核验。
3. 在 `thesis/experiments/llm_probe` 运行：

```bash
bash scripts/run_lspr24_screen_baselines.sh \
  runs/data-prepared/lspr24-screen-wide-v1/dataset-manifest.json \
  runs/baselines/lspr24-screen-tabular-seed42-<唯一标识> \
  lspr24-screen-tabular-seed42-<唯一标识>
```

## 风险

- 真实运行前必须核验环境中 `xgboost`、`swanlab` 与项目 `uv` 环境可用；SwanLab 失败不影响本地制品，但需在运行记录中保留失败原因。
- 本轮没有真实宽表，无法验证类别值、训练/验证样本量、历史完整率和四项指标；这些只能由一次真实服务器运行确认。
- 加载器故意不暴露最终切分。任何需要最终评价的入口必须在后续冻结合同授权后独立实现，不能放宽本加载器的限制。
