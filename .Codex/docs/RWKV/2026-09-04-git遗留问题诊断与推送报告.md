### 2.2 为什么 `.gitignore` 没挡住（根因已查清，且和问题一属于同一类规则缺陷）

`.gitignore` 第 56 行确实写了：

```
.claude/logs/
```

但用 `git check-ignore -v` 实测验证：

- `git check-ignore -v ".claude/logs/anything.md"` → **命中**该规则（仓库根级 `.claude/logs/` 有效）。
- `git check-ignore -v "thesis/experiments/llm_probe/tools/.claude/logs/session-20260813-068bbd7d.md"`
  → **不命中**（exit code 1，无匹配）。

原因是 gitignore 语义：`.claude/logs/` 这条模式**中间含斜杠**（`.claude` 和 `logs` 之间），
按 git 官方规则，只要模式里除末尾外还含斜杠，就被视为**相对于 `.gitignore` 所在目录（仓库根）的锚定路径**，
不会像不含斜杠的模式那样自动匹配任意深度的同名目录。也就是说这条规则**只保护仓库根目录下的
`.claude/logs/`**（现状核实：根目录 `.claude/logs/` 下当前有 2 份日志文件，均为未跟踪状态，
规则确实生效），**完全保护不到** `thesis/chapters/.claude/logs/`、
`thesis/experiments/llm_probe/tools/.claude/logs/` 这类嵌套在子目录里的同名目录。
这是一个可复现、可验证的规则锚定 bug，不是人为强制加入。
