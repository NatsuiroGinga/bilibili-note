# 神经模型统一 BF16 重训注册表

## 裁决

自本注册表生效起，第三章神经模型的**新**训练统一使用 `cuda-bf16-amp-fp32-sensitive-v1`：CUDA BF16 自动混合精度，参数、优化器状态及模型声明的敏感区保持 FP32，BF16 不使用 `GradScaler`。旧 FP32 运行仅作历史证据，不进入本注册表完成后形成的同精度结构排行。该工程合同尚不证明 BF16 改善模型效果。

**两级规则：**开发阶段复用已封印的胜出配置，只完成尚未封印的必要候选比较；封印后 BF16 重训只覆盖最终配置。只有候选比较、机制或结构优劣论断要写入正文时，才要求该比较族全员同一 BF16 profile 正式重跑。正文若只报告最终固定配置对基线，只重训最终配置与正文基线，并披露该配置来自 LSPR23 开发选择，不重跑淘汰的 R/K/输入候选。

不统一模型输入、优化器、容量、有效批量或归一化单位。每个模型只能在自己的冻结合同内确定这些项；微批量与梯度累积只允许作为保持有效批量和归一化语义不变的机械资源调整。所有单元先在 LSPR23 Protocol A 选择，封印后才可对 LSPR24 作描述性评价，两年度结果必须分表。无人工墙钟或 GPU 小时上限。

## 共同调度合同

| 项 | 固定要求 |
| --- | --- |
| 精度 | `cuda-bf16-amp-fp32-sensitive-v1`；BF16 autocast，FP32 参数、优化器、损失、归约、softmax、对数、指标及模型敏感状态 |
| 缩放器 | BF16 禁止 `GradScaler` |
| 有效批 | 各模型沿用各自冻结合同；仅机械拆分微批，不补、不丢尾批 |
| 归一化 | 每个原始优化步按该步全部有效单位归一化；序列模型按有效流或其原合同定义，禁止跨模型强行统一 |
| 收据 | 首个完整优化步记录精度、敏感岛、微批/累积、FP32 参数/优化器、CUDA 内外峰值、吞吐和恢复边界 |
| 评价 | LSPR23 选择表与 LSPR24 描述性评价表独立；旧 FP32 不参与新 BF16 同精度结构排名 |
| 状态 | `pending` 表示尚无可运行 BF16 入口，不得推定已实现或已运行；正式重跑范围由正文使用范围决定 |

## 执行门

1. 顺序固定为 GRANDE、合法 Raw83 数据门后的独立 CUDA RWKV、N-12 TabM32、N-13 FT-Transformer、全容量 MLP/表格 ResNet，最后已发表 CNN/GRU/Transformer；正式重跑集合由正文使用范围决定，不把淘汰候选误列为必跑。
2. 每个 `pending` 项先建立独立入口、配置、启动器、计划和报告，再进行服务器准入；本注册表不构成可执行命令。
3. 同一模型的新 BF16 运行完成后，登记源年选择收据与 LSPR24 描述性评价收据；缺任一项保持 `实验待证`。
4. 正文需要候选族优劣时，该族才需全员同 profile 重跑并进入 BF16 结构排行；只报告最终配置对基线时，排行范围仅为最终配置与正文基线，旧 FP32 单元另列历史表。
