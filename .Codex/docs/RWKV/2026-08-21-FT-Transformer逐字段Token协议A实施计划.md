> **执行方式**：按 `subagent-driven-development` 逐任务派发实现代理，每个实现代理执行 `daily-coding` 与 `pytorch-patterns`。步骤用 `- [ ]` 跟踪。

## 一、论文配方与官方源码的核验结果

### 1.1 已逐行核验的结构事实

下列各项均已对官方源码 `bin/ft_transformer.py` 核验，非从论文文字推断：

| 项 | 事实 | 源码位置 |
| --- | --- | --- |
| `[CLS]` 参数化 | **不单独设参数**，与数值字段共享同一张权重矩阵的第 `0` 行 | 第 42 行 `nn.Parameter(Tensor(d_numerical + 1, d_token))`，第 41 行注释 `take [CLS] token into account` |
| 数值字段 Token | 每字段独立权重向量与偏置，`T_j = b_j + x_j · W_j` | 第 42 至 43 行；论文 PDF 第 4 页 |
| 类别字段 Token | 每字段独立查找表，`T_j = b_j + e_j^T W_j` | `nn.Embedding(sum(categories), d_token)` |
| 注意力投影 | `W_q`/`W_k`/`W_v` 为 `nn.Linear(d, d)`，`W_out` 仅 `n_heads > 1` 时存在；**四者默认带偏置** | 第 89 至 92 行 |
| ReGLU 前馈 | 首层输出宽度**翻倍** | 第 216 至 217 行 `nn.Linear(d_token, d_hidden * (2 if activation.endswith('glu') else 1))` |
| 归一化 | Pre-Norm，LayerNorm；**首块去掉第一处归一化** | 论文 PDF 第 4 至 5 页与附录 E.1 第 17 页 |
| 预测头 | `Linear(ReLU(LayerNorm(T_L^[CLS])))` | 论文 PDF 第 5 页 |

### 1.2 论文默认配置（表 12，PDF 第 18 页，逐行抄录）

```
块数 3                    Token 宽度 192           头数 8（论文明写不调参）
激活与前馈放大 (ReGLU, 4/3)  注意力失活 0.2          前馈失活 0.1
残差失活 0.0               初始化 Kaiming           参数量 929K（100 个数值特征下）
优化器 AdamW               学习率 1e-4              权重衰减 1e-5
权重衰减例外：特征标记器、LayerNorm 与偏置一律取 0.0
```

训练侧：早停耐心 `16`；**无学习率调度**；数值特征默认用 sklearn 分位数变换。

### 1.3 参数量闭式及其双路验证

```
Total = d·(2F + C + 1 + Σv_j)                 特征标记器（含共享的 CLS 行）
      + L·[4d² + 5d + h·(3d + 2)]              L 个块的注意力与前馈，h = ⌊d · ffn_factor⌋
      + 4·d·L                                  全部 LayerNorm 的闭式合计
      + d_out·(d + 1)                          预测头
```

**验证一，对论文自报锚反推**。以 `F=100`、`C=0`、`d=192`、`L=3`、`ffn_factor=4/3` 代入，逐一枚举偏置与激活组合：

| 变体 | 参数量 | 对 `929K` 偏差 |
| --- | --- | --- |
| 含 ReGLU 的四个变体 | `925,825` 至 `930,241` | `0.1%` 至 `0.3%` |
| 不含 ReGLU 的四个变体 | `778,369` 至 `782,017` | `16%` |

**`929K` 这个锚独立锁死了 ReGLU 计入参数量**，与源码第 217 行的双倍宽度互相印证。偏置细节在 `0.3%` 内，取整精度分辨不了，已按源码取「注意力四投影带偏置」。

**验证二，块的边际成本**。本课题配置下 `L=1/2/3` 分别为 `332,097`、`629,249`、`926,401`，等差 `297,152`，与闭式的 `L` 系数吻合。

**未查明项**：论文自报 `929K` 与按源码结构实算的 `930,241` 相差 `1,241`（`0.13%`）。论文只给取整值，未说明 `d_out` 取值或配置版本，PDF 内找不到消解依据。**标为未查明口径差异，不得据此反向修改公式去凑数。**

## 二、核心设计问题：词表策略决定同参数对照是否成立

这是本计划最重要的一节。Codex 在 4.12-8 明令「**先实现同参数普通整向量投影对照，证明任何收益来自字段身份而非容量**」。而该对照能否成立，完全取决于离散字段的词表策略。

### 2.1 两种情形的实算对比

沿用 N-12 已取回的训练区实测基数（`SrcPort=61057`、`DstPort=6041`、`Protocol=7`、`L3/L4=5`，三个粗拓扑字段均为 `2`，七字段缺失率全为 `0`），按 `d=192`、`L=3` 实算：

| 情形 | FT-T 总参数 | 标记器 | 标记器占比 | 主干加头 | 同参数对照所需宽度 |
| --- | --- | --- | --- | --- | --- |
| **甲**：两端口走数值线性 Token | `925,633` | `33,984` | `3.7%` | `891,649` | `d=194`，偏差 `-0.09%` |
| **乙**：五个离散字段全建词表 | `13,808,449` | `12,916,800` | `93.5%` | `891,649` | `d=756`，即 `3.9×` |

### 2.2 判断

情形乙下，`SrcPort` 一张嵌入表就是 `11,723,136` 参数，是三块主干的 `15.7` 倍、占标记器的 `90.8%`。此时给对照组配同样的总参数量，等于**逼它把宽度从 `192` 拉到 `756` 去追平一张端口表**——对照比的不再是「字段身份有没有用」，而是「谁更会浪费参数」。**同参数对照在情形乙下失效。**

情形甲下标记器只占 `3.7%`，参数量绝大部分在主干，同参数对照比的确实是字段身份，且 `d=194` 就能把偏差压到 `0.09%`，对位干净。

### 2.3 与 N-12 已有裁决的一致性

Codex 在提交 `8229562` 已就同型问题裁决过：**否决 `SrcPort=61057` 与 `DstPort=6041` 的全独热候选**，理由是「缺少原始语义、产生 `37.7×` 容量混杂和显存代价」。

逐字段 Token 下的端口嵌入表与独热是**同一个病换了形式**：那边是宽 `61,058` 列，这边是高 `61,058` 行。分布证据也未变——`SrcPort` top-1000 仅覆盖 `8.26%`，是临时源端口形态；`DstPort` top-10 覆盖 `92.08%`，是真类别量。

**显存这次不是瓶颈**：微批 `4`、序列 `128`、`84` 个 Token 时，Token 张量 `32 MiB`、注意力矩阵 `110 MiB`，远小于 N-12 候选二的 `4.10 GiB`。所以本节纯属科学问题，不是工程问题。

### 2.4 本方建议与待裁决项

**建议按情形甲实现**，即 `SrcPort` 与 `DstPort` 并入数值字段走线性 Token，只有 `Protocol`、`L3/L4 Protocol` 与三个粗拓扑字段建训练区词表。依据是 Codex 对同型问题的既有裁决、端口的分布证据、以及同参数对照的成立条件。

**待 Codex 裁决项一**：情形甲是否为最终口径。若裁定情形乙，则同参数对照的参数对位口径必须一并改为「**主干同参数**」而非「总量同参数」，否则对照无意义——请一并明确。

**待 Codex 裁决项二**：粗拓扑字段（`Int/Ext Dst IP`、`External_src`、`External_dst`，基数均为 `2`）建词表还是按 `{0,1}` 直通。N-12 在同一处留下过口径歧义，本计划按「建词表含越界桶」实现并在配置留显式常量，裁决到达后只改常量。

## 三、LSPR 模型适配表

### 3.1 字段分组与 Token 布局

| 组 | 数量 | 处置 | Token 数 |
| --- | --- | --- | --- |
| 数值 | `76` | 逐字段独立权重与偏置的线性 Token，训练区分位数变换 | `76` |
| 端口（建议并入数值） | `2` | 同上 | `2` |
| 离散协议 | `2`（`Protocol`、`L3/L4 Protocol`） | 训练区词表嵌入，含越界桶 | `2` |
| 粗拓扑 | `3` | 训练区词表嵌入或 `{0,1}` 直通，待裁决 | `3` |
| `[CLS]` | `1` | 共享权重矩阵第 `0` 行，不单独设参 | `1` |
| **合计** | `83` 字段 | | **`84`** |

七字段 `missing_fraction` 全为 `0`，故不引入缺失指示位。缓存 `X23.npy` 存的是标准化浮点而非原值，词表键统一用 `float32` 位模式，只要求映射单射且确定。

### 3.2 因果边界

- 序列长度 `128`，逐流 `84` 个 Token。**字段内注意力只在同一条流的 `84` 个 Token 之间进行，绝不跨流**。
- 跨流时间轴由因果前缀聚合承担，只读取当前及严格过去时刻。
- 实体划分实体不相交，训练与验证实体交集为零，另切时间尾部。协议 A 切分身份：实体 `150680`、训练序列 `208598`、验证序列 `22444`、交集 `0`。

### 3.3 机制接入位置

统一合同第 111 行记载的历史拟议接口为「在 `[CLS]` 后外接 CPA、在分类概率后外接 ELP」，并注明「未来机制可进入字段注意力、训练目标或其他合规位置，**不强制使用该拟议接口**」。本计划采用该拟议接口作为四格的机制位置，理由是与既有四格骨干保持同一机制语义以便对表；采用而非强制这一点在报告中记明。

### 任务 2：特征标记器与输入变换

- [ ] **步骤 1**：数值字段线性 Token，逐字段独立权重与偏置，`T_j = b_j + x_j · W_j`。分位数变换只在 LSPR23 训练区有效流上拟合，`NaN` 不参与估计。
- [ ] **步骤 2**：离散字段词表嵌入，只由训练区取值构成，含固定越界桶。词表键用 `float32` 位模式，`±0.0` 先经 `+np.float32(0.0)` 规范化再入表——N-12 实测裸位模式会把 `±0.0` 算成两个键，导致词表长度断言比收据多一。
- [ ] **步骤 3**：`[CLS]` 按官方语义共享权重矩阵第 `0` 行，**不单独设参数**。
- [ ] **步骤 4**：变换状态哈希覆盖分位数网格、词表、越界桶位置与缺失填充值。
- [ ] **步骤 5**：入口检查并提交。

### 任务 3：Transformer 块与整向量投影对照

- [ ] **步骤 1**：Pre-Norm 块，`Block(x) = ResidualPreNorm(FFN, ResidualPreNorm(MHSA, x))`，`ResidualPreNorm(M, x) = x + Dropout(M(Norm(x)))`。**首块去掉第一处归一化**。
- [ ] **步骤 2**：多头注意力，`n_heads=8`，四个投影均为 `nn.Linear(d, d)` 且带偏置。
- [ ] **步骤 3**：ReGLU 前馈，首层 `nn.Linear(d, 2h)`，`h = ⌊d · 4/3⌋`，门控后第二层 `nn.Linear(h, d)`。
- [ ] **步骤 4**：预测头 `Linear(ReLU(LayerNorm(T_L^[CLS])))`。
- [ ] **步骤 5**：**整向量投影对照分支**。把 `83` 维整体投影成单一 Token，过同样的块结构，无逐字段权重、无嵌入表、无 `[CLS]` 拼接（序列长度为 `1`）。宽度由参数对位搜索确定，使总参数量逼近 FT-T 主口径。该分支必须在日志与封印中明确标注为**对照，不是候选**，其结果不得用于否决 FT-Transformer 模型族。
- [ ] **步骤 6**：参数量三方比对——闭式、配置登记值、实际 `sum(p.numel())`，任一不等即抛错。对照分支同样比对。

### 任务 4：训练循环与协议 A 选择

- [ ] **步骤 1**：梯度累积用 `neural_precision_runtime` 的 `EffectiveBatchAccumulator`，先经 `validate_microbatch_plan` 校验有效批、微批与累积步数自洽。**这三个数由本任务独立冻结**，按真实资源选择机械微批因子，不继承共享示例数值。
- [ ] **步骤 2**：BF16 autocast 走 `autocast_context`；敏感计算放 `fp32_island`——损失、概率归一化、ELP 的幂运算、CPA 的 `cumsum`（属 `reduction`）。**注意力的 softmax 属 `softmax`，同样入 FP32 岛**。
- [ ] **步骤 3**：协议 A 选择——跑满固定轮数不早停、无学习率调度，每轮在实体不相交验证集算逐流 AP，严格大于更新最优以保留最早轮次。
- [ ] **步骤 4**：切分与形状断言，与 N-12 同值。
- [ ] **步骤 5**：资源采集四量加外部进程占用，张量上界按展开维度乘积写明。

### 任务 5：三层断点恢复、封印与 LSPR24 评价
