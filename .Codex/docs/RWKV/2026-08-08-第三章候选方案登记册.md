### 1.3 2026-08-12 并发内存事故（工程缺陷，不改变证据等级）

三个实验并发导致 C56 容器内存耗尽、整机重启，TL1 `rerun1`、LSPR24 方案册 A 线（流式检测误差解剖）与 C 线（攻击早期预警 B 子任务 CPU 门）同时中断。**该事故不构成任何候选的科学失败，不得据此调整证据状态。**

根因是三个启动器的资源门禁只检查磁盘与显存，且余量读宿主机 `free`（报 `754 GiB`）而非容器 cgroup 上限（实为 `90 GiB`）。完整时间线、内存核算与幸存结果见[C56 三进程并发内存耗尽事故取证](2026-08-12-C56三进程并发内存耗尽事故取证.md)；可复用规则见[故障预防手册](../agents-split/llm-probe-failure-prevention-handbook.md)「容器内存上限、并发准入与大矩阵载入」。**重启任何实验前必须先过 `tools/memory_admission_gate.sh`。**

事故中幸存的有效证据（C 线 `run.log`，已核验）：

1. **共享视图切分键核验失败**：按去重活动窗起始推导的 60% 边界 `1709758690000000000` 与视图实际 `validation_min=1709774230000000000` 不一致，`核验=失败`。共享筛选视图的切分口径需独立复核。
2. **修正边界后早期预警 B 任务硬门禁通过**（`新边界 gate_b pass=True`）：三段严格正风险锚点为 `2,883 / 1,968 / 356`，独立前体簇为 `1,025 / 753 / 158`，全部满足方案册 §8.1.5 的 `512 / 128 / 128` 与每段 `≥10` 簇。旧行分位边界下 seg1 仅 `150` 正锚点 `62` 簇，**先前“B 门濒临不过”的判断被推翻**。
3. 正类连续段 `11,125` 个，`G_event=1` 合并后事件 `9,221` 个；`lag<=4` 关系 `103,213,263` 行、冲突 `0`；历史掩码跨端点剔除 `0`、跨切分剔除 `4,470`。

## 2.1 共享筛选视图数据陷阱（2026-08-12 实测，所有消费该视图的任务强制执行）

来源：[LSPR24 同年基线天花板与标签删失诊断](2026-08-12-LSPR24同年基线天花板与标签删失诊断.md)。视图根 `runs/data-prepared/lspr24-screen-wide-v1`，合同 `lspr24-screen-6-2-2-v1`。

1. **标签三值，`label=-1` 占 `60.4075%`**（`4,800,524` 窗口）。`label=0` 占 `37.9779%`、`label=1` 占 `1.6145%`；**可评价窗口仅 `3,146,375 / 7,946,899 = 39.59%`**。任何实验必须先 `np.isin(label, (0, 1))` 过滤，否则训练直接崩（实测 `ValueError: Expected: [0 1 2], got [-1 0 1]`）或把 `-1` 当数值算出"正类率 `-0.587`"。
2. **训练区与验证区正类率相差 `2.15` 倍**（`0.048423` vs `0.022486`）。时间前向切分下先验本身漂移，**LSPR24 同年任务亦非平稳**，阈值冻结与概率校准必须考虑该漂移。
3. **`final_split=final-not-materialized`**：最终 20% 未物化，泄漏风险为零，无需额外封存即满足最终测试隔离。
4. **同年强树基线天花板**：XGBoost 验证 AP=`0.9690348794483452`、ROC-AUC=`0.9956477692756596`，可用余量 `1−AP=0.03096512055165479`。流式行为检测方案册 §8.2 的 `Delta_AP>=0.005` 门槛**可满足**，且恰等于该基线下 `16.1%` 错误相对下降。
