# 第三章候选方案登记册

- **日期**：2026-08-08
- **路线**：`RESEARCH_ROUTE=RWKV`（论文主线）
- **用途**：登记全部候选方案与各自的**证据状态**，作为逐条实验筛选的唯一台账。
- **纪律（用户 2026-08-08 明令）**：**不得因为对话中的一句话就否决尚未筛选的方案。** 只有实验才能淘汰候选；文字论证只能改变优先级，不能改变存废。

## 0. 证据状态的定义

| 状态 | 含义 | 允许的动作 |
| --- | --- | --- |
| `未筛选` | 尚无任何针对性实验 | 排队等实验 |
| `弱证据不利` | 有 1 次代理实验不利，但实验为免训练代理或存在设计缺陷 | **保留**，需正式实验复核 |
| `弱证据有利` | 有 1 次代理实验有利，未达正式标准 | 保留，提高优先级 |
| `实验无效` | 实验本身崩了（泄漏、任务设计错误、数据缺失） | **不得据此淘汰任何候选**，重做实验 |
| `已证伪` | 正式实验在合格设计下否决 | 淘汰，写入消融表作负结果 |
| `已支持` | 正式实验在合格设计下支持 | 进入主线 |

**当前没有任何候选处于「已证伪」或「已支持」状态。** 全部实验都是免训练 HGB 代理或合成实验。

## 1. 候选清单

### C1 受序双尺度动态记忆（原方案 A 机制一）

- **内容**：RWKV-7 状态更新外增加每头可证明受序的快、慢保留门，两条状态共享移除/写入/值内容，只在保留尺度上不同。
- **来源**：`2026-08-05-方案A第三章-受序动态记忆与正常状态生成.md`
- **证据状态**：`弱证据不利`
- **证据**：LSPR24 窗口级 HGB 代理，快（lag1-4）0.9601 / 慢（lag8-32）0.9560 / 快+慢 0.9624，双尺度相对最佳单尺度仅 **+0.2%**。
- **为什么不能据此淘汰**：这是**免训练滞后特征**的代理，不是学习型双状态门；HGB 的两组滞后特征天然冗余，学习型快慢门可能表现不同。且只在 LSPR24 一个数据集、一个尺度上测过。
- **待做实验**：在 TQH-C2 的 `interval × jitter` 网格上重测（多尺度动机在信标场景可能成立）；正式实验需学习型双状态。

### C2 正常状态生成（原方案 A 机制二，方案 B 亦含）

- **内容**：生成头只在经审计的连续正常历史与正常目标上拟合，用预测似然辅助检测。
- **证据状态**：`未筛选`
- **说明**：HGB 代理无法代理生成式辅助目标，至今**一次实验都没做过**。不得因方案 A 其他机制不利而连坐。
- **待做实验**：单变量消融（同骨干 + 有/无生成头），需真实训练。

### C3 状态条件字段交互（原方案 B 机制一）

- **内容**：语义字段组表示为当前窗字段标记，由上一时刻 RWKV 状态摘要调节字段交互。
- **证据状态**：`弱证据有利`
- **证据**：LSPR24 窗口级，无历史时纯可加 0.6978 → 交互 0.9078（错误相对下降 **69.5%**）；给足 lag1-4 后 0.9240 → 0.9601（**47.5%**）；强交互 leaf=127 再降 31.8%。
- **旁证**：三篇独立工作显示包头字段是主信号、载荷贡献接近零（NetMamba 表VI 去头部降 15.5–48.8%、去载荷仅降 0.16–0.84%）。
- **局限**：HGB 树分裂交互 ≠ 状态条件字段注意力。
- **待做实验**：状态条件 vs 无条件字段注意力的消融。

### C4 时间尺度课程训练

- **内容**：难度 = `(interval_s/窗长, jitter_pct)` 二维外生网格，从短周期零抖动推进到 3600 秒 70% 抖动，同时调度衰减谱下限 `w_min(t)` 使每阶段最小可积累周期 ≤ 有效记忆长度 `L_eff = 1/(1−w_min)`。
- **证据状态**：`未筛选`
- **说明**：训练方法层面的创新点，需真实训练才能测，**至今无实验**。
- **待做实验**：同骨干同注入下，课程 vs 常规混合训练，多种子。

### C5 端点窗口序列维的 delta 规则状态注入

- **内容**：注入不发生在窗内 token 维，而在跨窗/跨连接的端点序列维；LLaMA-Adapter 式零初始化门控保证「注入前 = 原骨干」。
- **证据状态**：`实验无效`
- **证据**：E-INJ（TQH-C2 跨 testbed）B0 骨干only 0.9522 / B1+EMA 0.6406 / B2+对角 0.8864 / B3+delta 0.3430。
- **为什么无效**：**泄漏审计 delta 状态特征反预测 testbed AUC = 0.9998**——随机投影状态累积端点专属统计量，而每端点只属一个 testbed，状态退化为 testbed 指纹。这是实验设计缺陷，不是注入无效的证据。
- **待做实验**：重做，需 (a) 端点内标准化去除端点身份信息 (b) 同 testbed 内划分或多 testbed 交叉 (c) 学习型而非随机投影注入。

### C6 时间感知（连续时间）衰减

- **内容**：把 RWKV-7 的 per-step 衰减改为壁钟时间感知 `w_k = exp(-Δt_k · softplus(κ(x_k)))`，使状态半衰期以秒计而非步数计。
- **证据状态**：`未筛选`
- **动机（实测）**：TQH-C2 testbed 背景率仅 12 事件/小时，而真实 soho 端点连接率中位 **67/h**、p90 **198/h**；同样的 3600 秒信标，真实背景下要跨 ~200 步（p90 593 步）而 testbed 只跨 12 步。步数尺度与壁钟尺度在此严重脱钩。
- **待做实验**：E1 背景率扫描（soho 混入），测 K_min 随 λ_bg 的关系。

### C7 ROSA / RWKV-8 后缀自动机注入 ★新增

- **内容**：RWKV-8 "Heron" 的 **ROSA（Rapid Online Suffix Automaton）**——可微、在线、常数内存的后缀自动机，做精确模式匹配与复制。注入基础模型用于加密流量的结构重复模式发现。
- **来源**：本机 `BlinkDL/RWKV-LM` 快照 `952102498e...`（Apache-2.0）的 `RWKV-v8/` 与 `RWKV-8.md`
- **证据状态**：`未筛选`
- **官方实测能力**：`251105_reverse_run.py` RWKV7+ROSA **4 万参数**（L2-D32）反转 1–60 位数字 **99.8% 位准确率**；`251024_rosaQKV_run.py` **100 万参数** 40 位加减法 **99% 位准确率且无需 CoT**；`260212_rosa1bitLM_L12.py` 纯 ROSA1bit+FFN（无 RWKV）仅 minipile 1.5B token 已能 copy & count。实现核心：`matched 1 => e, matched 0 => -e, unmatched => 0`。
- **为什么与本课题契合**：GoldFinch 实测纯 Finch 在 MQAR 多查询联想召回上随长度失效——**精确模式匹配是 RWKV-7 的能力缺口**，而 ROSA 正是补这个缺口的。恶意流量检测的本质之一就是模式匹配（重复 C2 载荷结构、周期信标签名、协议指纹序列），签名检测干的就是这件事。
- **风险**：RWKV-8 **无正式论文**，只有官方仓库实现与设计文档；一切效果主张须本课题独立验证。安全领域 247 篇 RWKV 生态论文中**零篇涉及 ROSA**。
- **待做实验**：ROSA 在流量序列上能否发现重复结构；相对普通 RWKV-7 的增量。

### C8 骨干替换：NetMamba 的 Mamba → RWKV-7

- **内容**：NetMamba 是 Mamba(SSM) 骨干、约 6.5M 参数、权重 26.2 MB 可下载。把 Mamba 块换成 RWKV-7 time-mixing，数据管线、MAE 目标、参数规模全不变——**变量最干净的对照实验**。
- **证据状态**：`未筛选`，但有**强不利旁证**
- **不利旁证（实测，来自 NetMamba 论文表VI 与 NetMamba+ 表V）**：序列骨干本身收益很小——vanilla Transformer vs Mamba 差距仅 **0.5–2.6 个百分点**，且 CICIoT2022 与 ISCXTor 上 Transformer 反而更好；**Linear Transformer 直接崩溃**（0.6413 / 0.4226 / 0.3754）。
- **含义**：换骨干的天花板很低，而线性递归有真实崩溃风险。若做此实验，须正面回应"过度压缩注意力的代价"。
- **风险**：NetMamba 许可证未标注；仓库钉死 torch 2.1.1+cu121，RTX 5090（sm_120 需 CUDA 12.8+）有兼容风险。

### C9 骨干替换：netFound 的 flow 级注意力 → RWKV 状态递归

- **内容**：netFound 层次化结构中，flow 编码器**只在 ≤12 个 burst 的 CLS token 间做注意力**——序列长度仅 12，是替换为固定状态递归的天然位置。
- **证据状态**：`未筛选`
- **优势**：netFound 是唯一「权重可下（HF `snlucsb/netFound-small` 53.4M）+ 许可证 MIT + 2026-03 仍维护 + 抗捷径实测过关」的骨干。netFound 表2 显示删掉捷径字段后 ET-BERT 99.82→32.83、YaTC 99.69→63.48，而 **netFound-large 保持 99.98 不变**。
- **输入形态**：netFound 是唯一「匿名化包头协议字段 + 数值型运营元数据（IAT/burst 字节数/包数/方向）」输入，与本课题字段+统计数据最同构。
- **风险**：flow 级序列只有 12 步，替换成状态递归的收益空间可能很小（与 C1/C6 的"长历史无用"证据一致）。

### C10 表格形态的小规模自监督预训练

- **内容**：在 Annotated-Encrypted-Traffic-2026 的 **140.5 万条 TLS 连接**上做掩码重建预训练（`tls.rec` 长度序列 + 元数据字段），骨干用 RWKV/Transformer 混合小模型从头训。
- **证据状态**：`未筛选`
- **动机（实测）**：流量领域**没有任何权重可下载的预训练骨干原生支持表格形态**，而我们三类数据里两类是表格/元数据形态。这是真实空位，FlowSem-MAE（2026-03）刚开始填但未开源。
- **优势**：注入即架构本体而非补丁；数据量足够；完全绕开形态不匹配。
- **风险**：`tls.rec` 固定截断 20 条，无长序列。

### C11 跨加密协议不变表示

- **内容**：利用 TQH-C2 的 **B(Merlin/QUIC/HTTP3) 与 D(Merlin/HTTP2/TLS) 受控对照对**——同框架同 kill-chain 只差传输加密层——学习协议变换下守恒的行为表示。
- **证据状态**：`弱证据有利（短间隔）／不利（长间隔）`
- **证据**：A→D 跨协议仅时序特征，i=300 子集 err 1.000→0.227（错误相对下降 **+77.3%**），pooled 最优 +21.8%（超 16.1% 门槛）；但 i=1800 最多 +22.5%、**i=3600 仅 +5.3%**。
- **已知障碍（实测）**：D 组 HTTP/2 复用把连接级信标周期完全抹掉（c2 连接 gap 中位 ≈10.5 秒，与 `interval_s` 完全脱钩，CV 2.7–4.4）。长间隔跨协议主张在连接级不成立，须下到 TLS 记录级。
- **B 组统计功效不足**：每格正例仅 24–30。

## 2. 已知的数据缺陷与实验陷阱（所有实验都必须规避）

1. **TQH-C2 A 组单元格内含流级捷径**：5 个流特征即 `err = 0`。任何有意义的实验必须跨 testbed 或只用时序特征。
2. **jitter 疑似在长间隔失效**：A 组 j70 单元格实测信标间隔 CV 仅 0.006–0.058，理论均匀 ±70% 应为 **0.404**（i=30 时实测 0.305 正常）。需从 pcap 层核实，否则"抖动鲁棒性"主张会被数据反杀。
3. **端点身份泄漏**：跨连接状态会累积端点专属统计量 → 退化为 testbed 指纹（E-INJ 实测 AUC 0.9998）。必须做端点内标准化 + 泄漏审计。
4. **输入模态 >> 骨干**：NetMamba+ 表VII，CipherSpectrum 上 Byte Only 0.8779 / Size Only 0.8906 / Interval Only 0.7556 / All 0.9652（**+71.5%**）。**任何骨干替换实验必须先固定输入模态作为混淆控制变量**，否则测的是模态不是骨干。
5. **二手数字必须回原文核验**：本会话已发生一次事故——把 FlowSem-MAE §1.1 的「冻结编码器 >90%→<47%」误记为 Demystifying (arXiv:2509.23089) 的结论，而后者全文无此说法（其表 6 线性探针 Macro-F1 为 YaTC 0.47 / ET-BERT 0.46 / NetMamba 0.62 / netFound 0.97，是不同任务不同量纲）。

## 3. 筛选原则

- **一次实验只淘汰它真正测过的东西。** 代理实验（免训练 HGB、随机投影、合成数据）只能改优先级，不能判死。
- **实验设计崩了（泄漏、任务无效、数据缺失）时，结论作废，候选状态回退到实验前**，不得顺势淘汰。
- 淘汰必须写明：用了什么实验、什么设计、什么门槛、精确数字。
- 提升幅度口径固定为**错误相对下降** `(err_base − err_method)/err_base`，参照朱焱雷第三章 **16.1%**。
