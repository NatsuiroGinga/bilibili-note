## 关键问题

1. 原始特征的因果前缀统计是否仍可称为 CPA，还是必须定义为树模型专用适配算子？
2. ELP 的指数 `p` 如何只用 LSPR23 合法验证区选择，并避免目标年选优？
3. GPU XGBoost 的无机制格如何与双机制格保持相同设备、字段、预算和随机性？
4. 主评价是否同时覆盖实体平均精确率、告警预算曲线与冻结工作点检出率？
5. 哪些结果支持“跨树模型适配”，哪些结果只能说明任务特定工程适配？

## 已作决定

- 不复用上次失败的 Fable 方案代理；该代理未产生可验收制品。
- XGBoost 无机制格和机制格必须统一使用 GPU，不能把 CPU 历史值直接作为唯一公平对照。
- `p` 只能使用 LSPR23 源年信息选择；LSPR24 仅在全部配置冻结后评价。
- 原始特征前缀聚合是新的挂载点适配，不能冒充神经表示层公式的原样复用。
- 方案获用户批准前不进入实现或真实实验。
