# SwanLab 统一标签门与 GRANDE 发布修复实施报告

## 结论

统一 SwanLab 最终标签机械门和 GRANDE 零重训发布修复已完成本地静态实施与验收。实现状态为“静态就绪、服务器发布待执行”，没有访问服务器、训练数据或 GPU，也没有创建 SwanLab 云端运行。

计划提交为 `b9a3704`。实现与本报告使用独立后续提交。

## 变更内容

### 统一标签合同

`src/flow_probe/tracking.py` 新增并接入唯一合同：

- 最终 `tags` 容器必须严格为 `list` 或 `tuple`。
- 每项必须严格为 `str`，首尾不得有空白且不得为空。
- 标签按 Unicode 码点计数，单项最多 20，总数最多 50。
- 原标签、有效标签分别禁止重复；NFC 规范化后分别禁止冲突。
- 非 NFC 标签不自动改写，必须通过预注册别名修正。
- 别名表必须单射，别名自身满足 NFC、长度和冲突门；禁止截断。
- `workspace`、`project`、`name`、`group`、`mode` 均严格检查；工作区和项目可绑定本轮显式授权。
- 若环境存在 `SWANLAB_TAGS`，仅接受与最终有效标签顺序和值完全一致的 JSON 列表或逗号分隔值；否则拒绝运行。
- 配置校验与运行时初始化均调用 `validate_swanlab_contract`。新运行只经 `initialize_swanlab_run` 调用 `swanlab.init`，并在初始化前写有效标签收据。

预注册别名表覆盖三项真实审计违规：

| 原标签 | 有效标签 |
| --- | --- |
| `official-pytorch-postpaper` | `official-pytorch` |
| `same-precision-selection` | `same-precision` |
| `cuda-fused-numeric-variant` | `cuda-fused-numeric` |

### 全配置扫描器

`tools/validate_swanlab_contracts.py` 使用 `fd` 枚举真实 JSON 配置，使用 `rg` 扫描直接初始化入口。扫描器不改写旧配置或源码。

本地真实扫描结果：

- JSON 中共发现 34 个 `swanlab` 映射。
- 20 个可确定最终目的地的合同全部通过，非法合同为 0。
- 14 个静态配置缺少扫描器无法可靠推导的最终目的地字段，作为 `unresolved_runtime_destinations` 保留。
- 53 个直接 `swanlab.init` 入口尚未迁移，全部写入 `remaining_direct_init_entries`。
- `migration_blocked=true`，表示全仓统一入口迁移尚未完成，不表示本次独立修复配置无效。

### GRANDE 零重训发布修复

新配置冻结独立运行身份 `ch3-grande-swanlab-publish-repair-v1`，只读绑定父运行 `ch3-grande-c00-protocolA-source-q0-seed42-v1-bf16-v1`。

发布前机械核验：

- 父生产配置和父运行冻结配置 SHA-256 均为 `af4b8cac2f4322498149d271ad8c93f3b118a31b718408038dfddef85c8d84a1`。
- `source-screen-results.json` 中 G-A、G-B 均有 20 轮历史和 20000 个优化步，G-B 选中第 9 轮。
- G-A、G-B 选择收据中的检查点 SHA-256 与实际选中检查点逐字节一致。
- 聚合曲线与曲线收据 SHA-256 一致。
- 资源收据、选择封印、父 manifest 和原 `failed/exit1` 状态均绑定到 `parent-binding.json`。
- 发布前后重新核验全部父绑定制品大小和 SHA-256，任何漂移即失败。

运行时只允许：父制品哈希核验、`swanlab ping`、`swanlab verify`、统一入口初始化、上传已有聚合指标。工具不导入 `numpy`、`torch`，不枚举或读取训练数组，不查询 GPU，不调用 `prepare`、`resource-calibrate`、`train-unit` 或 `aggregate`，不写父运行目录。

独立输出目录将生成：

- `parent-binding.json`
- `tag-receipt.json`
- `tracking-gate-receipt.json` 及两份门禁日志
- `swanlab-receipt.json`
- `status.json`
- `manifest.json`
- `publish-repair.log`

父运行原配置、状态、检查点、聚合结果、manifest 与失败证据均不修改。

## 风险与后续阻断

1. 服务器上的父制品只有在唯一启动命令执行时才会逐字节核验；本地静态通过不能证明云端发布成功。
2. 53 个直接初始化入口仍可绕过统一函数；全仓迁移完成前，统一标签门只能保证已接入入口和本次发布修复。后续必须按扫描报告逐入口迁移，不能用本次文件范围扩大声明。
3. 14 个未决静态目的地须由各运行工具在构造最终 `name`、`group`、工作区和项目后接入同一合同；禁止扫描器猜测动态身份。
4. Context7 本次没有返回可用文档文本。服务器运行仍以锁定的 SwanLab 0.9.0、现有生产签名和 `ping`/`verify` 门为准；接口不一致时保留失败证据并停止，不回退到凭记忆改接口。
