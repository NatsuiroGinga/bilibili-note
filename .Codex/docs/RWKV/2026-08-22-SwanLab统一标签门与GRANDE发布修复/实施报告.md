## 标签与目的地合同

`src/flow_probe/tracking.py` 对已接入入口执行以下机械门：

- 最终 `tags` 必须显式为 `list` 或 `tuple`，每项严格为 `str`、非空且首尾无空白。
- 标签按 Unicode 码点计数，单项最多 20，总数最多 50。
- 原标签和有效标签分别禁止重复，NFC 规范化后分别禁止冲突。
- 非 NFC 标签不自动改写，只能通过预注册单射别名修正；禁止截断。
- `project` 长度为 1 至 100，只允许 `[0-9A-Za-z_+.-]`。
- `workspace` 长度为 1 至 25，只允许 `[0-9A-Za-z_-]`。
- `name` 和 `group` 长度为 1 至 512；`mode` 必须属于冻结枚举。
- 请求 `mode=cloud` 时，标签收据同时记录 `requested_mode=cloud` 与 `effective_mode=online`，实际初始化使用 `online`。
- `SWANLAB_TAGS` 若存在，必须与最终有效标签按顺序和值完全一致。
- 运行收据记录 SwanLab 锁定版本和实际版本 `0.9.0`、别名文件路径与 SHA-256、请求目的地和有效目的地。

别名文件 SHA-256 为 `d2bf7212068e6d7ced2fa916cd327dd24fea26bbb3bd3cbd9fd241c77a3f7a16`，覆盖三项真实违规：

## 幂等与 401 恢复

- 完成 manifest 显式记录 `publish_completed=true`；失败 manifest 为 `false`。
- `status=complete` 不能单独构成幂等成功。工具和启动器的 `ALREADY_COMPLETE` 都调用 `--verify-completed`，复核 manifest、全部登记输出文件哈希、配置、别名、工具、跟踪模块和启动器身份。
- `status=complete` 后若 manifest 尚未写出或任一登记文件漂移，重新启动不得返回成功。
- 每次尝试保存独立状态、日志、标签收据及 `ping`/`verify` 收据。
- 只有首次在 `swanlab-init` 阶段出现包含 `401` 的零步失败才允许第二次尝试。启动器以全新 Python 进程重新执行 `ping`、`verify` 和一次初始化。
- 非 401 错误不重试；第二次失败后停止；不存在第三次初始化路径。
- 成功 `finish()` 后不再在后置核验异常中二次 `finish()`。

工具不导入 `numpy` 或 `torch`，不读取训练数组，不查询 GPU，不调用 `prepare`、`resource-calibrate`、`train-unit` 或 `aggregate`，不写父运行目录。

## 风险与边界

1. 父制品完整绑定只有在服务器执行唯一启动命令时才能实际通过；本地静态验收不能证明云端发布成功。
2. 当前 52 个直接初始化入口和 25 个动态目的地未决项仍是全仓迁移阻断，后续须由各自所有者逐入口接入。
3. 首次初始化 401 只允许一次全新进程重试；第二次失败需要人工核验凭据、权限或连通性，禁止继续重试。
4. 任何代码、配置、别名或启动器变化都会使既有完成 manifest 的身份复核失败，必须使用新修复身份而不是静默接受漂移。
