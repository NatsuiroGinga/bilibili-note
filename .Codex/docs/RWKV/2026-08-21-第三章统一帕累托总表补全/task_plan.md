# 第三章统一帕累托总表补全实施计划

## 目标

把现有“逐列冠军标记”扩展为同一评价池内可审计的完整多指标帕累托判定，并为 GRANDE、RWKV-7、TabM32 及后续可微候选提供版本化接入接口。不得手工修改生成表，不得把 LSPR23 选择信号与 LSPR24 描述性评价混入同一前沿。

## P0：生成合同

1. 在 `ch3_build_metrics_table.py` 中新增源年完整性能表，保留现有 `lspr23-selection` 仅作选模证据。
2. 规范性能向量：逐流 AP、实体 AP、最大池化实体 AP、六档实体 DR、完整告警预算曲线、六档未告警率、按时检出曲线和首次告警时延摘要。
3. 规范工程向量：参数量或树规模、模型权重字节、训练/选模/评价/纯推理/端到端时间、吞吐、峰值显存、峰值主存、检查点字节、恢复次数与重复计算量。
4. 完整曲线必须读取实际数组，在同一评价池的共同可达负实体预算上逐点比较；只保存路径或摘要不能参与完整前沿。
5. 输出 `pareto_status`、`dominated_by`、`dominates` 与 `pareto_missing_reasons`。任一必要性能分量缺失时标记“证据不完整”，不得被判为完整前沿或完整支配。
6. 性能前沿和工程前沿分开，不构造加权总分、平均排名或事后容差。

## P0：候选适配

1. 增加 RWKV-7 资源键兼容和完整曲线收据适配。
2. 增加 GRANDE 源年 `complete_metrics` 与其曲线收据适配；没有目标年评价时只进入源年完整性能表。
3. 为 TabM32 预留版本化模式，但在其真实制品形成前保持 `pending`，不得伪造空结果。
4. 来源继续由受控清单显式注册，不无约束扫描 `runs/`。
5. 新训练入口缺首次告警制品时必须在结果中明确缺失，不能由 AP 或 DR 推导。
