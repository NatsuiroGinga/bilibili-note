## 零、总裁定

**设计有阻断。** EAS 的动机是真的（空活动集确实存在、确实白算），但被审文档的三条支柱有两条不成立：

1. **EAS-lite 的「正确性平凡、逐位精确」不成立**——阈值状态 `ξ` 在活动集为空时仍收到**精确非零**梯度
   `1/(N_p·|K|) = 1/12`，跳过反传会同时跳掉 `ξ` 更新，改变训练轨迹。按字面实现还会直接触发
   宿主的 `require(xi.grad is not None, ...)` 断言、非零退出。**这是阻断项，但可修复。**
2. **§1 的因果叙事（「模型排序学得越好 ⟹ 活动集变空」）是误归因**，且「单调增强」被第 9、10 轮实测证伪。
   真正的驱动量是 `ξ` 的 bang-bang 追踪动力学；空活动集是 `ξ` 高于 `L_pn` 分布的**暂态**，不是收敛终态。
   **这条同时决定了 EAS-lite 不是「加零」——它切断的正是把系统拉出空活动集的负反馈。**
3. **§3.2 的证书路线在预算上不成立**（不是「界太松」，是「维护费太贵」）：全局负例上界的一次全量刷新
   实测折合 `168.5` 秒，等于该轮排序前向阶段的 `1.64` 倍、整轮墙钟的 `37.3%`；而 EAS-full 在最好的
   第 8 轮也只省 `92.9` 秒。**刷新周期须 ≥ 1.81 轮（1,814 步）才可能不亏本**，而这恰好是松弛项
   `ε(Δθ)` 最不可能成立的区间。

**未被推翻的部分**：空活动集本身是实测事实；空步的 `∂L_rank/∂θ` 实测精确为 `0`；空步当前确实按满价计算。
EAS-lite 在**补上 `ξ` 闭式更新**后是一个正确、可实现、收益约 `1.068×` 的工程整改。
但被审文档自己已承认「工程整改不足以单独作为章级机制」，而 EAS-full 这条使它够格的路线现已被预算证伪。

## 一、维度一：地基（「活动集为空 ⟹ 排序损失梯度恒为零」）

**裁定：对 `θ` 成立，对 `ξ` 不成立。文档的「逐位精确」结论破了。**

### 1.1 对共享参数 `θ`：成立，且有实测

代码路径 `thesis/experiments/llm_probe/tools/ch3_ft_entity_ranking_loss.py:510-511`：

```
hinge = torch.relu(pairwise - xi_k.unsqueeze(1))
r_k = xi_k + hinge.sum(dim=1) / float(k)
```

活动集判据（同文件 `:514`）是 `pairwise > xi_k`，**严格不等号**；`relu` 在 `0` 点的子梯度取 `0`。
故「全部档活动率为 `0`」⟺「全部 `hinge` 为 `0` 且其梯度为 `0`」，`pairwise` 一侧对 `θ` 的梯度通道整体关闭。
`_cvar_pauc_loss_stratified`（`:811`）用同一条 `relu`，结论一致。

**实测佐证**（不是推演）：第 8 轮 `last_step_snapshot` 恰好落在空步上，
`empty_active_set_step = true`，同一步 `gradient_control.grad_norm_rank = 0.0`（精确零，非小量），
`grad_norm_rank_projected = 0.0`，`inner_product = 0.0`，`c_scaling = 0.0`。

其余可能的非零来源已逐条排除：

| 可能来源 | 结论 | 依据 |
| --- | --- | --- |
| 正则项 | 不存在 | `cvar_pauc_loss` 无任何正则项 |
| 诊断分支 | 不产生 `θ` 梯度 | `per_budget_active_rate` 等全在 `torch.no_grad()` 内（`:513`）；`entity_score_source_row` 已 `detach` |
| `nonargmax_grad_share` 的诊断反传 | 只在 `alpha is not None` 时触发，本臂 `alpha = None`，实测 `diagnostic_backward = 0.012 s/千步` | `ch3_ft_c00_dual_selection.py:2811` |
| `c_scaling` | 空步为 `0`，`combined = g_flow`，不改变更新 | `ch3_ft_gradient_controller.py:75-80` |
| **阈值 `ξ`** | **非零，见 1.2** | — |

### 1.2 对阈值状态 `ξ`：**精确非零**，这是阻断项

宿主 `ch3_ft_c00_dual_selection.py:2779-2825` 走的是**子梯度 SGD** 路径（2026-09-01 从水库分位数回退）：

```
xi = xi_state.get(positive_entity_ids).to(device)   # requires_grad=True 的叶张量
xi.retain_grad()
...
loss_rank.backward()
require(xi.grad is not None, "xi 未接收到梯度…", EXIT_RUNTIME)
xi_updated = (xi.detach() - float(ranking_cfg["xi_learning_rate"]) * xi.grad).cpu()
xi_state.commit(positive_entity_ids, xi_updated)
```

按 `cvar_pauc_loss` 的字面公式，`loss = mean_K mean_p (ξ_{p,K} + Σ_n[·]_+ / K)`，于是

```
∂L/∂ξ_{p,K} = (1/(N_p·|K|)) · (1 − n_active(p,K)/K)
```

活动集为空时 `n_active = 0`，梯度**精确等于** `1/(N_p·|K|)`。冻结配置 `n_pos = 2`、六档预算，故该值为
`1/12 = 0.0833333`，`xi_learning_rate = 1e-4`（`config.json` 实读），每个空步把 `ξ` 下压 `8.333e-6`。

**后果有三，都不是措辞问题**：

1. **按字面实现会崩**：跳过 `loss_rank.backward()` 后 `xi.grad is None`，`:2823` 的 `require` 立即以
   `EXIT_RUNTIME` 终止。被审文档 §2.1 写的「在调用反传之前检查 `|A| = 0`，成立则跳过主反传」
   在当前宿主上不可运行。
2. **验收判据 1 会失败**：跳过后 `ξ` 停更，后续步的活动集判据随之改变，逐轮指标不可能 `torch.equal`。
3. **可修复**：空步的 `ξ` 梯度是**闭式常数**，不需要反传即可施加
   `ξ ← ξ − lr/(N_p·|K|)`。要做到逐位相等，须按与 autograd 相同的浮点算子顺序复现该常数
   （`(1/|K|)·(1/N_p)` 的乘法次序、FP32 舍入）。这是可完成的工程任务，但**必须写进方案，
   并作为判据 1 的前置条件**，不能继续称「正确性平凡」。

**建议改写**：把 §2.1 的「正确性：平凡」改为「正确性：对 `θ` 平凡，对 `ξ` 需闭式补偿；
逐位精确以补偿实现为条件」。

## 三、维度四：收益是否高估（连同 §7.1 未测量的分母）

**裁定：分母是可测的，文档的「不得报告端到端加速比」过度保守；但收益本身被高估约 1 个百分点。**

### 3.1 整轮墙钟：已由收据 mtime 独立测出

十份 `entity-ranking-diagnostics-{1..10}.json` 的落盘时刻（服务器 `ls --time-style=full-iso` 实读）
相邻差值即整轮墙钟：

```
451.41  451.10  450.81  452.98  449.71  450.69  450.71  454.60  452.90
均值 451.66 s   中位 451.10 s   极差 [449.71, 454.60]
```

九个间隔的极差只有 `4.9` 秒，说明这是稳定的整轮周期而非偶发抖动。
**§7.1 说「分母尚未测」并禁止报告端到端加速比，是不必要的自我设限**——该量无需任何新实验，
读收据落盘时刻即可得，且与主代理另行给出的 `451` 秒一致。

排序阶段五段合计均值 `262.18` 秒，占整轮墙钟 `58.05%`；前向＋主反传 `249.85` 秒，占墙钟 `55.32%`。

### 3.2 空步当前确实按满价计算（这是对 EAS 有利的实测）

第 1 轮 `empty_frac = 0.000`，第 8 轮 `empty_frac = 0.395`，而两轮的前向与主反传耗时几乎不变：

| 轮 | `empty_frac` | 前向（千步合计 s） | 主反传（千步合计 s） |
| ---: | ---: | ---: | ---: |
| 1 | `0.000` | `103.667` | `148.749` |
| 8 | `0.395` | `102.303` | `146.732` |

空步比例从 `0` 涨到 `39.5%`，两段耗时只降了 `1.3%`。**这直接证明当前实现没有任何隐式短路，
空步与非空步同价**，EAS 要省的那部分计算确实还在。这是本审核找到的、最有力的支持 EAS 的证据。

### 3.3 收益复算（独立于主代理）

主代理口径（前 8 轮均值外推）：`empty` 均值 `0.1675` → EAS-lite `1.058×`、EAS-full `1.107×`。
**复算结果与之接近但不相同**，差异来自两处：

| 口径 | EAS-lite | EAS-full | 说明 |
| --- | ---: | ---: | --- |
| 主代理（前 8 轮均值） | `1.0576×` | `1.1021×` | 与其自报 `1.058/1.107` 一致，可复现 |
| **本审核（全 10 轮逐轮加权）** | **`1.0682×`** | **`1.1218×`** | 用 `Σ_e empty_e × stage_e / Σ_e wall_e`，不做均值外推 |
| **本审核（扣除必付的正例前向）** | `1.0682×` | **`1.1142×`** | EAS-full 仍须前向 2 个正实体，见维度三 |

十轮全程口径反而比八轮**高**（`empty` 十轮均值 `0.1966` > 八轮 `0.1675`），
但这不能读成「收益比文档说的更好」——第 9、10 轮的 `empty_frac` 已经在**回落**（`0.354`、`0.272`），
再往后外推是第三次犯同一个错（见「额外发现乙」）。

### 3.4 优化器仍走一步，逐流分支照常

`_combine_and_step`（`:3015-3035`）无条件执行：`combine_gradients` → 写回 `.grad` → `optimizer.step()`。
空步上 `g_rank = 0` ⟹ `c = 0` ⟹ `combined = g_flow`，更新照常。
`_flow_phase_bare` 也照常执行。**故 EAS 只省排序阶段，不省优化器步与逐流分支**——
文档没有在这一点上夸大，但实现时须注意：跳过反传后 `.grad` 为 `None`，
必须合成一个与 `_flat_grad_from_params` 同形状的零向量，否则 `combine_gradients` 的形状断言会失败。

### 3.5 `stage_timing_seconds` 能否兑现

计时后端为 `cuda_event`（`resolved_step_count = 1000`），`elapsed_time()` 只在轮末 resolve 一次，
训练步内不做设备同步（`:2903-2906` 的设计与 `:2939-2941` 的实现一致）。
CUDA 事件测的是同一条流上两个事件之间的 GPU 时间线间隔，**包含等待主机的空档**，
故这 `262.18` 秒是真实占用而非纯 kernel 时间，跳过后可兑现为墙钟。
**未发现「计时虚高、跳过也省不下来」的证据。**

## 四、维度三：§3.2 证书路线可行性

**裁定：不成立——但被审文档指出的失败原因（Lipschitz 界太松）不是主要原因，
真正的杀手是全局负例上界的维护费。**

### 4.1 `n_pos = 2` 恒定：成立

`config.json` 的 `mechanism.entity_ranking.n_pos = 2`，十轮 `last_step_snapshot.batch_composition.positive_entity_count`
全为 `2`。采样器 `_draw_positive_entities` 是不放回轮转，恒定抽 `n_pos` 个。**这条没问题。**

### 4.2 「正例前向只占 3%」：**证伪，实测低估 4.50 倍**

服务器 CPU 侧只读统计（`/tmp/eas_probe.py`，全 `E23` 口径，`271,815` 片段 / `150,680` 实体，
截断参数取宿主实际值 `max_segments = ceil(8192/128) = 64`）：

| 池 | 规模 | 片段数均值 | 中位 | p90 | p99 | 最大 | 截断后均值 | 流数均值 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 正实体 | `239` | `54.498` | `1` | `14` | `1860` | `2486` | `6.126` | `6881.2` |
| 负实体 | `150,441` | `1.720` | `1` | `1` | `4` | `19338` | `1.211` | `97.8` |

**正实体的袋比负实体大 32 倍**（片段数均值 `54.5` vs `1.72`）。故一个 `2 正 + 64 负` 的批里：

- 期望：正例贡献 `12.25` 段、负例贡献 `77.53` 段 → **正例占前向的 `13.65%`，不是 `3%`**；
- 最坏（抽到最长的两个正实体）：正例 `128` 段 → **占 `62.28%`**。

文档写的 `2/66 ≈ 3%` 用错了两处：分母应是**片段数**而非实体数；且假定了各实体等长，
而实测袋长分布极度右偏（正实体 p99 达 `1860` 段）。
任务简报预判的「因果前缀截断与变长袋会破坏『与序列条数成正比』」**成立**。

收据侧的独立佐证：十轮末步的截断后片段数为 `66, 108, 88, 75, 73, 69, 111, 86, 196, 77`，
第 9 轮末步截断前高达 `1077` 段、最长袋 `120,960` 流、`truncated_entity_count = 1`。
**批规模本身逐步波动 3 倍，任何「固定 3%」的成本估计都不成立。**

一处对 EAS-full 有利的修正：正例前向不必是**额外**开销——把前向拆成「先正例、后负例」即可复用，
非空步不浪费。故 4.3 的收益按「只省负例前向的 `86.35%`」计，得 `1.1142×`（见 3.3 表）。

### 4.3 全局负例上界 `Ŝ_n` 的维护费：**这是决定性的证伪**

由 4.2 的实测可直接标定单位成本：每批期望 `89.76` 段、每轮千步共 `89,756` 段前向、耗 `102.9` 秒
→ **每段前向 `1.1467` 毫秒**。

负实体池规模取**训练区**口径而非全 `E23` 口径：由收据的 `effective_budgets` 反解
`N_pop = K · n_neg / K_eff`，六档一致给出 `121,336`
（例：`121 × 64 / 0.06382277312586536 = 121,336.0`），而不是全 `E23` 的 `150,441`。于是：

```
一次 Ŝ_n 全量刷新 = 训练区负实体池 121,336 × 截断后 1.211 段 = 146,938 段
                  = 146,938 × 1.1467 ms = 168.5 秒
```

对照：

- `= ` 该轮**整个排序前向阶段**的 `1.64` 倍；
- `= ` 整轮墙钟的 `37.3%`；
- 而 EAS-full 在**最好的第 8 轮**也只省 `92.9` 秒。

**破产点**：刷新周期须 ≥ `1.81` 轮（`1,814` 步）才可能不亏本。而松弛项 `ε(Δθ)` 必须覆盖这
`1,814` 个优化器步累积的参数漂移才能保持 `Ŝ_n` 为真上界——文档 §3.3 第 2 条自己承认
Transformer 的 Lipschitz 常数没有紧估计。**在最需要它紧的区间上，它最松。**
两个条件（刷新够稀疏 ∧ 界够紧）在本课题的池规模下方向相反，不存在同时满足的工作点。

### 4.4 我认为它会失败的具体场景（按简报要求给出）

1. **刷新即亏本**：按「每轮刷新一次」实现，`168.5 − 92.9 = 75.6` 秒/轮净亏，
   EAS-full 反而比不开更慢，端到端 `0.79×`。
2. **分桶不救场**：按档位分桶维护 `Ŝ_n` 只减小界的松弛，不减小刷新的**样本数**——
   刷新费与桶数无关，仍是 `146,938` 段。
3. **陈旧分数不可用**：§3.3 第 1 条已承认每步重新分层抽样，`77.7%` 的负实体轮内只出现一次
   （文档 §5 自述），故无法用「上一次见到该实体时的分数」代替池级上界。
4. **正例侧也不稳**：证书需要 `s_p^min`，而正实体袋长 p99 达 `1860` 段，
   遇到长袋时「只前向 2 个正例」本身就要 `128` 段（占满价批的 `62%`），证书当步几乎不省。
5. **`ξ` 是移动靶**：违序判据是 `L_pn > ξ` 而非 `L_pn > 0`，证书必须同时给 `ξ` 的下界。
   而 `ξ` 每步都在被子梯度更新（且空步与非空步方向相反，见「额外发现乙」），
   文档 §3.2 的三条不等式里**完全没有出现 `ξ`**——这是证书构造的一处实质遗漏，不只是参数问题。

## 五、额外发现甲：主代理未解释的 `c_scaling` 异常（简报未列此维度）

**裁定：不是 bug，是三个中位数被跨量比较造成的假象。但澄清后暴露出一个对第三章有意义的真事实。**

简报提出的疑点：第 8 轮 `c_scaling_median = 0.00492`、`grad_norm_flow_median = 0.5804`、
`grad_norm_rank_median = 0.0389`，由 `0.5804/0.0389 ≈ 14.9` 应得 `c = 1`。

**`c` 的定义确认无误**（`ch3_ft_gradient_controller.py:74-80`）：

```
norm_r_plus = g_rank_plus.norm()
c = min(1.0, float(norm_f) / float(norm_r_plus))  if norm_r_plus > 0 else 0.0
```

**假象的来源**：`min(1, median(a)/median(b)) ≠ median(min(1, a/b))`。三个中位数是**同一批步上
三个反向相关量的同秩序统计量**，不能相除。第 8 轮的真实分布由收据的另外两个计数直接给出：

```
空步（g_rank ≡ 0 ⟹ c = 0）        395 步
c = 1（‖g_r^+‖ ≤ ‖g_f‖）          229 步   ← c_equal_one_step_count
0 < c < 1（排序梯度压过逐流梯度）   376 步   ← 1000 − 395 − 229
投影触发（⟨g_r,g_f⟩ < 0）          194 步   ← projection_triggered_step_count
```

中位数（第 500 位）恰好落在中间那 `376` 步里，`0.00492` 是**该带内第 105/376 分位**，
而 `grad_norm_rank_median = 0.0389` 是全体中的第 105 个**正**值——两者取的是同一分布的两端。
**不存在「差三个数量级、方向相反」的矛盾。**

**澄清后浮出的真事实（对第三章有影响，请第三章负责人过目）**：

1. 排序梯度在 `376/1000` 步上**大于**逐流梯度并被范数上限压制，压制幅度在中位处约 `200` 倍。
   这不是缺陷（上限是 spec 5.5 的设计），但意味着**BER 每步的实际贡献被钳在 `‖g_f‖` 以内**。
2. 加上 `395` 个精确零步，**BER 排序梯度以满强度进入更新的步只有 `229/1000 = 22.9%`**。
3. 放大来源可定位：`r_k = ξ_k + Σ[·]_+/K`，而最低档 `K_eff = 0.0638`，
   单个活动对被放大 `1/0.0638 ≈ 15.7` 倍，六档平均后仍足以让 `‖g_r‖` 跃升几个量级
   （第 1 轮 `grad_norm_rank_median = 989.0`，第 8 轮 `0.0389`，跨轮五个数量级）。
4. **这不构成对第三章机制主张的否定**：范数上限保方向不保幅度，一阶不变量
   `⟨g,g_f⟩ ≥ ‖g_f‖²` 每步实测成立（`_combine_and_step` 的 `require` 未触发，运行 `exit_code = 0`）。
   但第三章正文若要陈述「BER 参与每一步更新」，须按上述计数收窄为「以满强度参与 `22.9%` 的步」。

### 8.3 一处朝**不利于自己**方向的失实（须改）

### 8.4 Ogawa：「同构」是过度断言

被审文档 §2.2 写：「与 Ogawa 的 SVM 安全样本筛选**同构**——先给最优解划一个可行域，
再由此推出「某些样本必不活动」的充分条件。」

**事实层准确**：Ogawa 的 Ball Test 确实是「构造一个已知最优解必落于其中的球形区域 `Θ`，
用该区域上线性目标的最小/最大值给出 `y_i f(x_i)` 的上下界，若下界 > 1 则该样本必为非支持向量」
（本地全文笔记 `method` 字段，对应原件几何论证章节）。

**「同构」不成立，差在构造的来源**：

| | Ogawa（凸） | EAS（非凸） |
| --- | --- | --- |
| 可行域从哪来 | **凸问题的对偶间隙**：最优解唯一且可被一个已知可行解的对偶间隙围住 | 无最优解可围。只能围**当前参数到下一步的移动量**，靠 Lipschitz／信赖域论证 |
| 被筛对象的稳定性 | 最优解处的支持向量身份是**固定**的 | 活动集随 `θ` 与 `ξ` 每步变化，是**移动靶** |
| 判据阈值 | 常数 `1`（合页 margin） | `ξ`，本身在被子梯度更新（见「额外发现乙」） |

即：两者共享的是「可靠但不完备的充分条件」这一**性质**，不是**构造**。
建议把「同构」改为「共享安全筛除的可靠性—完备性分工，但可行域的来源不同：
Ogawa 用凸对偶间隙，本机制只能用参数移动量的信赖域」。**这是家族归属的准确表述，也不削弱定位。**

### 9.1 判据 2 是最严重的一条：同一机制在不同轮数下得三种不同结论

### 9.2 判据 1「逐位相等」：前置条件从未论证

三个问题，按严重度排列：

1. **基线自身的逐位可复现性从未验证。** 宿主 `ch3_ft_c00_dual_selection.py` 中
   **没有任何 `torch.use_deterministic_algorithms`、`cudnn.benchmark` 或确定性设置**（`rg` 零命中），
   而精度 profile 为 `cuda-bf16-amp-fp32-sensitive-v1`（`autocast=true`、`compute_dtype=bfloat16`、
   参数 FP32、`float32_matmul_precision=highest`、`torch_compile` 关闭）。
   **「A 与 B 逐位相等」在 B 自己重跑都未必逐位相等时无意义。**
2. **`ξ` 通道使它先验地不可能成立**（维度一 1.2）。补上闭式补偿前，判据 1 必然失败，
   且失败原因与 EAS 的正确性无关，属实现缺陷。
3. **「逐轮指标」未指明是哪些指标。** 收据里的候选量有几十个，

**一处可以放心的地方**：空步上 `combined = g_flow + 0.0 × 0` 与直接取 `g_flow` 的差别
只在 `−0.0 → +0.0` 这一种情形，而 `torch.equal` 与 Adam 的更新对 `±0` 不敏感，
**不构成额外风险**——前提是 EAS 分支仍然走 `combine_gradients`（传入零向量），而不是整段旁路。

**关闭条件**：先跑「同配置重跑一次、比对逐轮指标」的确定性前测（见 §十的 E1），
确认基线逐位可复现后，判据 1 才有意义；若不可复现，判据 1 须降级为「指标差异 < 容差」并给出容差来源。

### 9.3 判据 3 的支持与证伪不互补

「支持：证书覆盖 ≥ 半数空步」「证伪：所需松弛超过分数间隔」——

**但按维度三 4.3 的预算分析，这条判据已经没有必要跑了——路线在维护费上先破产。**

而它自己又一次在时间维上外推了单调性。**这是同一错误的第三次发生。**

### 6.2 因果叙事误归因：真正的驱动量是 `ξ`

文档 §1 写「模型排序学得越好，违序对越少，`A` 越小；到训练后期，相当比例的步上 `A` 直接为空」。
按 1.2 节推出的 `ξ` 梯度，真实机理是一个 bang-bang 分位数追踪器：

```
活动集为空： ∂L/∂ξ = +1/(N_p·|K|) = +0.0833      → ξ 每步下移 8.333e-6（慢）
有 1 对活动（最低档 K_eff = 0.0638）：
             ∂L/∂ξ ∝ 1 − 1/0.0638 = −14.67       → ξ 单步上跳（快）
```

即：`ξ` 被活动对**猛推高**，随后在空步上**缓慢衰减**，直到重新低于 `L_pn` 分布、再次激活。
**空活动集是 `ξ` 高于 `L_pn` 分布的暂态，不是「模型学好了」的稳态。**

量化核对（`xi_learning_rate = 1e-4`，`config.json` 实读）：
十轮共 `1966` 个空步，`ξ` 累计下移 `1.638e-2`；
对照第 8 轮 `pair_loss_batch_mean = 3.911e-3`、末步 `pairwise_loss_mean = 3.369e-6`。
**漂移量比 `L_pn` 的均值还大 4 倍**，故这个负反馈足以（也确实）把系统拉回非空，
这正是第 9、10 轮回落的机制解释。
`mechanism-coupling-8.json` 的 `cv_xi ≈ 0.906–1.016`（六档，各 `2000` 样本）同样指示 `ξ` 高度波动，
与 bang-bang 图像一致，与「收敛后静止」不一致。

### 6.3 对 EAS 的直接后果（比 1.2 的技术性问题更严重）

**EAS-lite 跳过的正是这个负反馈。** 空步不反传 ⟹ `ξ` 不下移 ⟹ 活动集继续为空 ⟹ 继续跳过。
这是一个自锁循环：**开启 EAS 后，排序损失可能在见到第一个空步后就永久失效**，
而外部观测到的现象将是「训练更快了，指标略降」——极易被误读为「EAS 无损提速」。

因此 1.2 提出的闭式 `ξ` 补偿**不是可选优化，是 EAS 成立的必要条件**；
且它必须补偿的量恰恰是把系统拉出空状态的那一项。
**补上之后，空活动集的持续时间不变，EAS 的收益估计仍然有效**（收益来自不算白算的前向反传，
不来自改变 `ξ` 轨迹）——这是本审核给出的唯一一条使 EAS-lite 可救的路径。

### E0（已完成）`ξ` 梯度的合成输入公式核验

按 `llm_probe/AGENTS.md`「允许用有构造真值或解析解的合成输入验证公式实现」执行，
CPU 单线程、`CUDA_VISIBLE_DEVICES=""` 硬隔离、不创建任何运行身份、产物已清理。

构造：`N_p = 2`、`N_n = 64`、六档 `K_eff` 取冻结实测值、正例分数 `+20` 负例 `−20`、`ξ ≡ 1.0`
⟹ `pairwise = softplus(S_n − S_p) ≈ 0 ≤ ξ`，活动集为空。

```
活动集为空（六档活动率全 0）: True
∂L/∂θ 全零              : True   (max|grad| = 0.000e+00)
∂L/∂ξ 解析期望           : 0.0833333333        ( = 1/(N_p·|K|) = 1/12 )
∂L/∂ξ 实测（全部 12 项） : 0.0833333358 ~ 0.0833333358   （FP32 表示的 1/12）
最大偏差                 : 0.000e+00
对照（把 ξ 压到 0 使全部对活动）: 活动率 1.0，∂L/∂ξ 最低档 = −83.4814
```

**结论（实测，非推导）**：

1. 维度一 1.1 的地基对 `θ` **成立**：空活动集下 `∂L/∂θ` 精确为零，无任何残留通道。
2. 维度一 1.2 的阻断 **成立**：空活动集下 `∂L/∂ξ` 精确等于 `1/12`，非零。
3. 「额外发现乙」的 bang-bang 图像 **成立且量化**：空步 `+0.0833` 对全活动步 `−83.48`，
   **不对称度 `1002×`**。该值可逐位对上闭式：
   `∂L/∂ξ = (1/|K|)(1/N_p)(1 − n_active/K_eff) = (1/12)(1 − 64/0.06382) = −83.48`，
   即不对称度由**最低档的 `n_neg/K_eff = 64/0.0638 ≈ 1003`** 决定。
   `ξ` 被活动对猛推高、在空步上缓慢衰减，空活动集因此**必然是暂态**。

## 十二、总裁定与替代建议

### 12.1 总裁定：**设计有阻断**

- **不是「整体不成立」**：空活动集是实测事实（十轮 `0`–`39.5%`）；空步对 `θ` 的梯度实测精确为零；
  空步当前按满价计算（第 1 轮与第 8 轮耗时只差 `1.3%`）。三条支柱都站得住。
- **不是「设计可行」**：`ξ` 通道使「逐位精确」当前不成立且按字面实现会崩（B1、B2）；
  `empty_frac` 的单调性被证伪（B3）；因果叙事误归因（B4）；
  `3%` 低估 `4.5` 倍（B5）；EAS-full 的维护费超过其收益（B6、B7）。
- **九个阻断项中 B1、B2、B3、B4、B5 可在文档层面修订关闭**（改述＋补闭式补偿设计），
  **B6、B7 是路线级的，只有 X3 实测能翻案**。

### 12.2 对 EAS-full 的建议：**删掉，不要修**

维护费与松弛紧度在本课题的池规模（训练区 `121,336` 负实体）下方向相反，不存在同时满足的工作点。
继续在 `ε(Δθ)` 上花力气是把成本花在**第二个**失败原因上。

### 12.3 最强替代建议（按预期收益排序）

**替代一：把「空活动集」换成「负例池的静态安全筛除」——同一家族，但把刷新费摊掉。**

EAS-full 之所以破产，是因为它每步都要一个**动态**的全局上界。
但本课题有一个 EAS 没有利用的结构：**负实体池的袋只有 `1.211` 段（截断后），
而正实体袋有 `6.126` 段——负例极短且极多**。
与其证明「本步没有违序对」，不如证明「**这个负实体永远不可能成为违序对**」，
把它移出采样池。这是 Ogawa 安全样本筛选的**原始形态**（筛样本，不筛步），
刷新费可以摊到整轮而不是每步，且被筛掉的负例是**永久**收益。
- 最小验证：用现有检查点给负例池打一次分（一次 `168.5` 秒的刷新），
  统计有多大比例的负实体分数低于「历史最低正例分数 − margin」。
  若比例 ≥ `50%`，则负例池可永久减半，排序阶段前向成本直接对折——
  **`1.29×` 端到端，一次刷新即可回本，且与 EAS-lite 可乘。**
- 这条路线的风险是它改变了采样分布，需要论证不引入选择偏差；
  但那是**统计问题**，比 Lipschitz 常数好处理得多。

**替代二：保留 EAS-lite 作为工程整改，不作为章级机制。**
收益 `1.068×`，正确性在补上闭式 `ξ` 更新后成立，实现量小。
按被审文档自己的判断「不足以单独作为章级机制」，它应当写进第四章的实现细节或效率表，
而不是占据机制一的位置。

**替代三：把章级机制的位置让给数据侧。**
候选文档 §8.4 第 3 条已经指出：残差 `425` 秒/轮可能来自
`view.gather_sequences`／`view.features` 的 numpy 取数与 H2D 搬运，
**「针对数据侧的机制反而是收益最大的一支，而它目前不在四张卡里」**。
本审核的实测支持这一判断——排序阶段五段合计只占墙钟 `58.05%`，
另外 `41.95%`（`189.5` 秒/轮）完全在四张候选卡的射程之外。
`2.384×` 的硬上限只对「删掉整个排序阶段」成立；而数据侧那 `189.5` 秒
**没有任何候选在处理**。

### 12.4 给主代理的一句话

**EAS 的动机是对的，账算错了，故事讲反了。**
动机（空活动集白算）经十轮实测确认；
账（`3%`、`Ŝ_n` 免费、`39.5%` 会继续涨）三处都高估；
故事（模型学好了 ⟹ 活动集空）与实测的 `ξ` bang-bang 动力学方向相反，
而**恰恰是这个反了的故事，掩盖了 EAS-lite 会切断负反馈这一真实风险**。
先关 B1–B5（文档层可改），再用 X3 一次前向计时决定 EAS-full 的生死。
