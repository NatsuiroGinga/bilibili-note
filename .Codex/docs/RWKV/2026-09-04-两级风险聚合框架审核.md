### 2.1 `§四` 第 3 项（`α` 的梯度是否被 `c` 缩放）：**是，逐位成立；但不致命**

`【推论】`先给闭式，再给实测。`_combine_and_step`（`ch3_ft_c00_dual_selection.py:3015-3035`）
把 `combine_gradients` 的输出按 `_shared_parameters(model)` 顺序切片写回 `.grad`。
逐流损失不含 `α`，故 `g_flow[α] = 0`；单向 PCGrad 投影
`g_r⁺ = g_r − (⟨g_r,g_f⟩/‖g_f‖²) g_f` 在该坐标上不改变任何东西（被减项含因子 `g_flow[α] = 0`）。
于是

```
combined[α] = g_flow[α] + c · g_rank⁺[α] = c · g_rank[α]
```

`【实测】`两种步都逐位相等：

| 情形 | `c` | `g_flow[α]` | `g_rank[α]` | `combined[α]` | `combined[α] == c·g_rank[α]` |
| --- | ---: | ---: | ---: | ---: | :---: |
| `ξ = 0`，活动集非空 | `0.096705` | `+0.000000e+00` | `−2.1598233283e−01` | `−2.0886618644e−02` | **逐位相同** |
| `ξ = 1e4`，活动集全空 | `0.000000` | `+0.000000e+00` | `+0.000000e+00` | `+0.000000e+00` | **逐位相同** |

**所以简报担心的机制确实存在：`c = 0` 的步上 `α` 的梯度精确为 `0`。**
按恢复卡记载，C11 第 `8` 轮 `c_scaling_median = 0`、空活动集率 `0.559`
（`RWKV第三章恢复卡.md:139-146`），即**过半的步 `α` 收不到任何梯度**。

**但这与已证伪方案不同型，差别是决定性的**：

- 已证伪方案是 `torch.ceil` 的导数**恒为零**，Adam `200` 步位移精确 `0.000000e+00`——**永远学不动**。
- 本方案是**占空比**问题。`【实测】`（`alpha_param_bitwise.py` R3）Adam 在
  **`90%` 的步梯度为零**、每 `10` 步才给一次 `grad = −1` 的极端占空比下，
  `50` 步后 `α` 位移 `+0.161854`；而梯度**恒为零**时 `50` 步位移精确 `0.0`。

**裁断：`§四` 第 3 项的风险属实，但它是「`α` 的有效学习率被一个不受控的全局标量 `c` 调制」，
不是「`α` 学不动」。** 需要在方案里明写这一条并给 `α` 独立的学习率，
不能沿用共享参数的 `lr`——`c` 在实测里取到 `0.0967`，即 `α` 的步长被压了约一个数量级，
且该压缩量逐步变化、不可控。

### 2.2 `§四` 第 4 项（边界数值行为）：**发现会翻转梯度符号的缺陷**

`【推论】`闭式：`S_e = (Σ_{i<k} s_i + f·s_k)/t`，`t = α·m`，则
`∂S_e/∂t = (s_k − S_e)/t`，`∂t/∂α = m`，故

```
∂S_e/∂α = (s_⌊t⌋ − S_e) / α     且  s_⌊t⌋ ≤ S_e  ⟹  ∂S_e/∂α ≤ 0 恒成立
```

`【实测】``200` 组随机 `(m, s, α)` 严格内点，自动微分与闭式不符或梯度为正的组数 = **`0`**。
**在严格内点上，`α` 对每个实体都是单调的分数压低算子。**

**但在 clamp 的打平点上，PyTorch 会漏出一个不该存在的梯度，且符号相反：**

| `m_e` | `α` | `t` | `软 S` | `硬 S` | 逐位同 | `∂S/∂α` |
| ---: | ---: | ---: | ---: | ---: | :---: | ---: |
| `0` | `0.5` | `1.0000` | `+0.00000000` | `+0.00000000` | 是 | `0.0` |
| `1` | `0.5` | `1.0000` | `+2.60184336` | `+2.60184336` | 是 | `0.0` |
| **`1`** | **`1.0`** | `1.0000` | `+2.60184336` | `+2.60184336` | 是 | **`−1.3009`** |
| **`2`** | **`0.5`** | `1.0000` | `+0.54956013` | `+0.54956013` | 是 | **`−3.4531`** |
| **`2`** | **`1.0`** | `2.0000` | `−0.31372389` | `−0.31372389` | 是 | **`+0.1569`** |
| **`3`** | **`0.5`** | `1.5000` | `−0.00253450` | `−0.10393868` | **否** | `−0.8112` |
| `3` | `1.0` | `3.0000` | `−0.60500598` | `−0.60500598` | 是 | **`+0.3025`** |

三个问题，按严重度：

1. **`α · m_e = m_e`（上夹打平）处 `∂S/∂α` 为正**（`m=2` 时 `+0.157`，`m=3` 时 `+0.303`）。
   这违反上面刚证明的「恒 `≤ 0`」。根因：`t = min(α·m, m)` 在打平点被 PyTorch 按平局
   分摊梯度，漏出 `−S/α` 这一支，其符号是 `−sign(S)`；**对分数为负的实体（负实体的常态）
   该项为正。** 数学上正确的单侧导数是 `(s_{m−1} − S)/α ≤ 0`。
   **这是实现缺陷，不是设计选择**，且只在 `α → 1` 附近发作——恰是 §1.3 指出的端点。
2. **`α · m_e = 1`（下夹打平）处同样漏梯度**：`m_e = 2`、`α = 0.5` 得 `−3.4531`，
   而左导数应为 `0`（`α` 略降时 `t` 仍被夹在 `1`）。**`α = 0.5` 正是初始化点，
   而 `m_e = 2` 占训练实体的 `21.59%`**——即第一步的 `α` 梯度里混进了
   五分之一实体的单侧次梯度，`α` 一旦离开 `0.5` 该项立刻消失。
   起步方向因此不可复现地依赖于打平点的平局规则。
3. **`m_e = 3`、`α = 0.5` 时软算子与硬算子不逐位相同**（`−0.00253` 对 `−0.10394`）。
   见 §2.5。

**A1 不是我的复现引入的，对被审文档的字面写法同样成立**（`clamp_tie_check.py`，
把 `soft_k_probe.py` 第 `7`–`17` 行的写法与向量化写法逐点对拍）：

| `m` | `α` | `α·m` | 打平 | `soft_k_probe.py` 写法 | 向量化写法 | 数学单侧导数 |
| ---: | ---: | ---: | --- | ---: | ---: | --- |
| `1` | `1.00` | `1.00` | 下＋上 | `−1.540996` | `−0.770498` | 左 `≤0`，右 `0` |
| `2` | `0.50` | `1.00` | 下夹 | `−3.770721` | `−3.770721` | **左 `0`**，右 `≤0` |
| `2` | `1.00` | `2.00` | 上夹 | **`+0.258046`** | **`+0.129023`** | 左 `≤0`，右 `0` |
| `3` | `1.00` | `3.00` | 上夹 | **`+0.052407`** | **`+0.026204`** | 左 `≤0`，右 `0` |
| `9` | `1.00` | `9.00` | 上夹 | `−0.200659` | `−0.100329` | 左 `≤0`，右 `0` |
| `3` | `0.50` | `1.50` | 内点 | `−0.435522` | `−0.435522` | `−0.4355` ✓ |
| `7` | `0.50` | `3.50` | 内点 | `−1.472799` | `−1.472799` | `−1.4728` ✓ |

**决定性的一行是上夹那几行：两种数学上完全等价的写法，在打平点给出的梯度相差恰好 `2` 倍**
（`torch.clamp(min,max)` 与 `torch.minimum` 的平局分摊规则不同）。
**一个量的值取决于它被写成哪一种等价形式，说明它不是被定义的导数，是实现产物。**
内点上两种写法则与闭式逐位一致，佐证问题只出在打平点。

**处置**：`t` 的两侧夹紧必须写成显式 `detach` 的分支（夹住时把 `t` 从图上摘掉），
不能依赖 `clamp` / `minimum` 的平局梯度。这是开工前必须先改的实现细节。

### 2.3 `§四` 第 1、2 项：可以通过，但各带一个必须机械核验的前置条件

`【实测】`**第 1 项（生产路径下 `α` 梯度非零）**：`ξ = 0` 的步上 `g_rank[α] = −2.16e−01`，
经 `c` 后 `combined[α] = −2.09e−02`，非零。**通过。**
**但有一个会静默吃掉全部位移的陷阱**：若 `α` 不在 `model.parameters()` 里，
`_combine_and_step` 的 `optimizer.zero_grad(set_to_none=True)` 之后
`optimizer.step()` 根本不遍历它——`【实测】`该情形下 `α` 反传拿到 `grad = −0.7834`，
`step()` 后位移**精确 `0.0`**，**不报错、不告警**。与已证伪方案的失败现象完全一样，
根因却完全不同。**`α` 必须注册进 `model.parameters()` 且在优化器构造之前完成。**

`【实测】`**第 2 项（`z1 = 0` 四格臂逐位一致）**：两条独立风险，一条安全一条不安全。

- **控制器侧安全**：给 `g_flow` / `g_rank` 各追加一个恒零坐标后，
  `c` （`0.34104203917057513`）、内积、`‖g_r⁺‖`、投影触发标志**全部逐位不变**，
  合成梯度前 `P` 个坐标逐位相同，新增坐标合成梯度精确为 `0`。
  即 `alpha=None` 的臂上多挂一个不接梯度的参数，**不改变任何既有数值**。
- **初始化侧不安全**：`【实测】`若 `α` 用消耗随机数的方式构造（`torch.randn`）
  且排在其他参数之前，`Linear.weight` 与基线**不再逐位相同**；
  用常量 `torch.tensor(0.5)` 构造则逐位相同。
  **`α` 必须用不消耗 RNG 的常量初始化**，否则四格逐位断言会以一个与 `α` 无关的原因失败。

### 2.4 新发现：AdamW 的权重衰减会单独把判据 3 推过证伪线

**被审文档没有提到优化器。** 生产优化器是 **AdamW**
（`ch3_ft_transformer_field_token_protocol_a.py:3139`），分组由
`resolve_weight_decay_groups`（同文件 `:2545-2584`）**按参数角色**决定，
排除清单只有 `tokenizer.*`、`LayerNorm`、`*.bias`、`p_log` 四类。
**一个名为 `alpha` 的标量参数不在排除清单里，会落进 `with_decay` 组**，
拿到冻结的 `weight_decay = 1e-5`（候选一）或 `3.1622776601683794e-05`（候选二）。

**仓库对这件事已有先例**：同一函数的注释写着
「ELP 的共享标量 `p_log` 是机制指数不是权重矩阵……不衰减」。
**同型的 `α` 需要同样处置，方案文本里没有这一条。**

AdamW 的解耦权重衰减每步执行 `p ← p − lr·wd·p`，**与梯度无关**。
`【实测】`（`adamw_decay_on_alpha.py`）梯度**恒为零**时 `α` 的位移：

| 优化器候选 | `2,000` 步 | `6,000` 步 | `10,000` 步 | `20,000` 步 |
| --- | ---: | ---: | ---: | ---: |
| 候选一（`wd = 1e-5`） | `1.000e−06` | `3.0e−06` | `5.000e−06` | `1.0e−05` |
| 候选二（`wd = 3.16e-5`） | `3.162e−06` | `9.5e−06` | `1.581e−05` | `3.2e−05` |
| 放进 `without_decay` 组 | — | — | — | **`0.000e+00`**（`50,000` 步仍为 `0`） |

**判据 3 的证伪线是「位移 `< 1e-6`」。** C11 那一类臂的预算是
`epochs = 10 × steps_per_epoch = 1000`＝**`10,000` 步**
（`configs/ch3-ft-c11-entitybce-halfwidth-screening-v1.json:117-118`），
四格共同预算的正式臂是 `20` 轮 ＝ `20,000` 步。

**在任何一个已冻结的预算下，仅靠权重衰减就能产生 `5`–`32` 倍于证伪线的位移。**
即：**`α` 一步没学，判据 3 也会判「`α` 确实移动」。**
更糟的是衰减方向恒为**趋零**，而判据 2 把 `α → 0` 解释为
「相容点就在 ETA 关闭处」这一有信息量的科学结论——

而不是 `1e-6` 这个与预算无关的常数。

### 5.1 「相容点存在」（判据 2）

  内点只能靠正负两类的**逐袋落差之差**恰好抵消而产生，这是一个比「符号不定」弱得多的条件；
  ② Shapiro ORL 2012 的 Lemma 2.1／Theorem 2.1 指出，若把「级间相容」形式化为律不变性，

  不再是方案可以默认的前提。**
- **判据不可用**：判据 2 写「末轮源年实体 AP `> 0.918431` 即相容点存在」。
  该运行相对 C01 同时改了两件事——**换了聚合算子**（硬 → 软，`α = 0.5` 处即对

  **单臂无法把增益归给哪一个。** 而框架的主张是关于后者的。
  最小修法是补一个 `α` 冻结在软算子某定值的对照臂，或把判据改写成
  「存在某个 `α` 优于 C01」——后者**用现有硬算子做 `α ∈ {0.2, 1/3, 0.4}` 的定值扫描即可测，
  不需要任何新代码**（实测这三点相对 `α=0.5` 的行为改变面分别为
  `0.3219 / 0.2696 / 0.1485`，确实是三个不同的工作点）。

  **「不需要新代码」是核实过的，不是估计**：`α` 已经是配置键
  `mechanism.entity_aggregation.alpha`，经
  `entity_tail_aggregation_alpha_from_config`（`ch3_ft_c00_dual_selection.py:1018-1028`）
  读入，`tail_aggregate` 接受 `(0, 1]` 内任意浮点（`ch3_ft_entity_ranking_loss.py:209`）。
  **改配置即可跑定值扫描，零实现风险、零 A1/A3/A4 暴露面。**

  两条路线的代价对比（`【推论】`，单臂时长按 `第三章定案.md` 登记的 `≈7.6 h`）：
  可学 `α` 需 `1` 个学习臂 ＋ `1` 个冻结 `α*` 的确认臂 ＝ `2` 臂；
  定值扫描需 `3` 臂。**可学路线省一臂，但要先关掉 A1/A3/A4 三个实现阻断项。**
  哪条更划算由用户裁决，本审核只给两边的真实成本。

### 5.2 「软 top-`k` 新颖性」

**裁断：不新颖。该算子是 Rockafellar-Uryasev (2002) 式 (25) 在等概率经验分布下的直接代入，
其可微性是同文 Proposition 13。** 依据见 §3.1，并已由主代理独立数值复核
（`73` 组对拍，最大相对误差 `1.247e−15`，全部落在 `float64` ULP 量级内）。
简报提出的最关键一问——「RU 的 CVaR 在离散样本上是否本就含分数权重项」——**答案是肯定的**，
RU 自己把它称作「劈开概率原子」。

**收窄后，本方案还剩的真实差量（四条，前两条站得住、后两条不成立）**：

1. **`【实测】`把 ETA 的袋内聚合从有偏的 `top-k` 均值换成精确的经验 `CVaR`**，
   消除仓库早先登记的、影响 `17.5%` 实体的估计偏差（§1.2 三角印证）。**这是真贡献，但是修正不是创新。**
2. **`【实测】`消除硬算子在 `α` 方向上的平台区**（`α = 0.40` 处作用面由 `14.85%` 升到 `32.19%`），
   使 `α` 的网格搜索或梯度搜索在中间取值上真正有效。
3. **不成立**：算子新颖性、`α` 可微性的新颖性、「两级/嵌套风险聚合框架」的新颖性
   （TCCO NeurIPS 2023 的应用即 multi-instance two-way partial AUC；SoRR §6 是两级参数独立设置的范例，**均为本地 `L1`**）。
4. **不成立**：§二 把「`z1=0` 硬断言不受威胁」列为本算子优势（A6，归因错误）。

**并须改名**：`「软 top-k」名实不符`——该算子对分数的权重是 `(1/t,…,1/t, f/t, 0,…,0)`，
除边界一项外仍是硬选择，**不缓解梯度稀疏**。
建议直接称「**袋内经验 CVaR（非整数水平的精确形式）**」，既准确又自带文献锚点。
