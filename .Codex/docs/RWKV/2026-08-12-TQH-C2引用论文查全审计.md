## 1. 结论

1. **原始发布对象是版本化 Zenodo 数据记录，不是已识别出的独立伴随论文。**规范题名为 *TQH-C2: An Encrypted Command-and-Control Traffic Dataset Across Protocols and Encryption Layers*，作者为 Deokjo Jeon、DongGue Park。概念 DOI 是 [`10.5281/zenodo.21330094`](https://doi.org/10.5281/zenodo.21330094)，截至截止日的最新版是 v1.2.0，[`10.5281/zenodo.21523144`](https://doi.org/10.5281/zenodo.21523144)。
2. **截至 2026-08-12，在本审计实际可达并完成的来源中，没有发现精确前向引用或实验使用作品：`A=0`、`B=0`。**这里的 A 类表示正文、补充材料或代码明确处理 TQH-C2；B 类表示只引用或讨论。语义检索器返回约 195 个原始结果行，含大量重复，均因早于数据集公开、题名或 DOI 不匹配、主题无关而批次归为 C 类；它们不是 195 篇唯一候选。
3. **零命中不是全球绝对“无人使用”。**Semantic Scholar 的题名批次触发 HTTP 429；Scite 只有 v1.0.0 与 v1.2.0 完成查询，其余四个对象受月度额度限制；GitHub 匿名代码接口受限。这些状态均保留为“未完成/阻塞”，没有伪报为 0。
4. **被引 DOI 不能自动确定实际使用版本。**v1.0.1、v1.0.2、v1.1.0 和 v1.2.0 的 README 引用块都沿用 v1.0.0 DOI `10.5281/zenodo.21330095`。未来出现引用时，必须把“被引版本”和“由文件、行数、成员或校验和判定的实际版本”分开。
5. **当前七字段域内汇总指标接近饱和，但这不自动否决同协议研究。**现有单种子开发诊断中，HGB/XGBoost 域内宏 F1 为 `0.999618`，A+B→C 与 A+B+D→C 的宏 F1 只有 `0.128186–0.146574`，恶意召回为 `0–0.003272`。候选先在相同版本、划分、字段、预算和指标下判断是否仍有最差组、低误报、校准或效率余量；如果没有，再转向更严格的跨成员稳健性验证。按现有证据，完整捕获分组的跨成员泛化仍是最强论文章级候选。
6. **前三任务依次为**：严格分组的跨成员泛化；跨域校准、固定告警预算与选择性拒识；协议异构下的流前缀早识别。前两项可由当前制品直接构造，第三项只能作为继承完整流标签的弱构造，不能声称攻击链开始时延。

### 2.2 分类标准

- **A 类：实际使用。**正文、补充材料或代码明确使用 TQH-C2 的一个或多个成员进行训练、验证、测试、基准评估或实质统计分析。
- **B 类：仅引用/讨论。**只引用、介绍或比较数据集属性，没有发现实际处理 TQH-C2 的证据。
- **C 类：误命中。**同名缩写、分词噪声、语义邻近但无书目关系、早于数据集公开或重复版本结果。
- 引用计数只用于召回；A 类必须回到全文或代码，不能由索引引文边、摘要或搜索片段自动判定。

### 6.2 两轨研究机会与原创性门禁

用户最终裁决不要求候选创造新场景；已有论文覆盖同一任务或场景也不构成自动否决。候选必须先沿两条轨道判断：

| 轨道 | 进入条件 | 必要对照 | 允许贡献 | 失败门槛 |
| --- | --- | --- | --- | --- |
| 同协议直接改进 | 相同数据版本、划分、字段、训练/推理预算和指标下，强基线仍有可重复余量 | HGB/XGBoost/线性或同输入神经强基线；相同调参和种子预算 | 在冻结协议内改善主指标、最差组、低误报告警、校准或效率 | 提升落在不确定区间内、来自字段/预算变化或削弱基线，即否决 |
| 更严格稳健性验证 | 汇总指标饱和，或部署相关问题只在 capture/成员留出、跨 C、固定告警预算、风险—覆盖、因果前缀下显现 | 原协议结果 + 更严格协议下同一组强基线 | 证明既有结论在更安全评价下成立/失效；可形成评价或稳健性贡献 | 只换测试而没有清晰问题、误差结构或可复现发现，不能包装成方法原创 |

已有机制只能作为来源与基线：领域对抗、组分布鲁棒优化、上下文聚合、图交互、温度缩放、选择性拒识和流前缀都已有先例。若主张新的方法贡献，必须同时具备：

1. **新增机制**：明确指出相对最近机制新增的可识别变量、约束、目标或状态，而不是改名组合。
2. **强基线**：相同输入、版本、划分、预算和调参机会；不得人为削弱传统或已有深度基线。
3. **独立消融**：单独移除新增机制，区分收益来自机制还是容量、训练时长、字段或阈值。
4. **失败门槛**：预先规定主指标、最差组、误报/告警预算、资源和多种子一致性门槛；未达到即缩小、重构或否决。

### 7.2 前三推荐与否决门槛

#### 第一：严格分组的跨成员泛化——最适合论文章级贡献

- **可观测标签**：逐流 `malicious_c2` 对非 C2；完整 `capture_id` 是划分原子；默认只用七个共同大小/计数字段。
- **强基线**：逻辑回归、HGB、XGBoost、同预算多层感知机；再与 CORAL、组分布鲁棒优化、领域对抗和简单重加权比较。模型族不预先锁定 RWKV。
- **理论创新空间**：捕获组与协议/框架变化下的不变表示、困难 C 域的最差组风险、B/D 同框架异传输对的条件不变性。论文主张必须由真实实验而非公式类比决定。
- **最小证伪实验**：七字段、capture 分组、A+B→C 与 A+B+D→C、3 种子；报宏 F1、恶意召回、良性误报、最差 capture/成员与置信区间。
- **否决门槛**：同预算候选不能在不提高良性误报的前提下，多种子稳定改善 C 的宏 F1 与恶意召回，即否决；只改善域内饱和分数不晋级。
- **两轨定位**：可以在完全冻结的 A+B→C/A+B+D→C 协议内做直接改进；也可以把“随机/域内近满分是否能在完整 capture 与成员留出下成立”作为更严格稳健性验证。已有跨域论文不否决该任务，但领域对抗、CORAL 和组分布鲁棒优化必须列为强基线而非新机制。

#### 第二：跨域校准、固定告警预算与选择性拒识

- **可观测标签**：逐流二元标签、模型分数、`capture_id` 和 manifest 捕获时长；独立 capture 用于校准。
- **强基线**：原始概率、Platt、保序回归、贝塔/温度缩放、最大概率/边际拒识、树/深度集成分歧。
- **理论创新空间**：组偏移下的最差组校准、有限告警预算和风险—覆盖联合选择；域内 ECE 接近 0 不提供跨 C 保证。
- **最小证伪实验**：在同一未见 C 上比较 Brier、NLL、逐组 ECE、风险—覆盖曲线，以及固定良性误报/告警每小时下的恶意召回。
- **否决门槛**：不能同时降低跨 C Brier/NLL 并改善同告警预算召回，或低风险依赖拒绝几乎全部 C，即否决。
- **两轨定位**：事后校准/选择性拒识已有机制可做同协议直接改进，但不能重包装为原创；若新增方法，须有跨组校准或告警约束的明确新机制及独立消融。更严格轨验证域内 ECE 近零是否在跨 C 和固定告警预算下失效。

#### 第三：协议异构下的流前缀早识别

- **可观测标签**：从 PCAP 按包数、时间或字节比例物化因果前缀；前缀继承完整流标签。只能称“完整流标签下的前缀识别”。
- **强基线**：固定前 N 包 HGB/XGBoost、因果 TCN/GRU、序贯概率比与完整流 oracle。
- **理论创新空间**：B 的长 QUIC 连接与 D 的较短 TCP 连接之间的统一前缀风险/早停；不得虚构攻击阶段或开始时刻。
- **最小证伪实验**：B/D 各两个开发 capture，10%/25%/50% 包前缀和完整流；报 PR-AUC/召回、决策包数/时间/字节、告警预算、吞吐和相对 oracle 保留率。
- **否决门槛**：25% 前缀在同误报预算下不能保留至少 80% 的完整流恶意召回，或收益使用终局字段、没有决策时间收益，即停止扩大。
- **两轨定位**：先比较固定前 N 包强基线与完整流 oracle；若同协议有余量，可研究新增早停机制。若前缀方法已有覆盖，仍可验证它在 B/D 异构传输和完整 capture 隔离下是否成立，但不能把“首次用于 TQH-C2”本身当作算法原创。
