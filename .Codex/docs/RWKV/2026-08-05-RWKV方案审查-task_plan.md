# RWKV 方案审查计划

## 目标

形成两套互不覆盖、均可独立验证的 RWKV 第三章与第四章方案，冻结公平二选一实验合同，并由新的独立代理给出可执行裁决。

## 阶段

- [x] 阶段 1：恢复课题边界并定位 RWKV 当前方案与证据。
- [x] 阶段 2：建立文献证据审查和实验可行性审查两个独立任务。
- [x] 阶段 3：形成第一创新点候选公式、算法、理论义务和证伪门槛。
- [x] 阶段 4：汇总第一轮独立审查，裁决原生方案为“修改后保留”。
- [ ] 阶段 5：修订方案 A 的 RWKV-7 算子、正常密度语义、标签和消融合同。
- [ ] 阶段 6：形成方案 B 的第三章、第四章和双方案公平筛选合同。
- [ ] 阶段 7：完成双方案独立审查，形成“分别保留、修改或否决”的裁决。

## 关键问题

1. 首选主题是否与可获得数据的真实语义一致？
2. 两个创新点是否各自有理论责任、计算图连接和独立消融？
3. 当前数据是否能形成无泄漏的长度 4、16、32 因果序列？
4. 是否存在足够强且公平的传统、循环、状态空间与 Transformer 基线？
5. 单张 RTX 5090 是否能在限定周期内完成三种子先导？

## 已作决定

- 当前只做审查，不启动训练、不下载数据、不修改既有方案。
- 文献新意与数据实验可行性分别由独立子代理审查，主代理负责最终一致性裁决。
- RWKV 路线仍是 PINN/R2 失败后的备选主题，不得在 R2 正式失败前覆盖当前论文主线。
- 用户已明确不要求优先验证加密流量，允许先以一般恶意流量或网络异常任务验证 RWKV 路线。
- 第一创新点详案已写入 `2026-08-05-RWKV第一创新点理论与算法设计.md`，当前仍是待审候选，不是已冻结贡献。
- 已启动独立方案审查；审查可综合文献代理的全文核验结果，但不能用生态目录题名代替原始论文证据。
- UGR'16 下载范围已扩展为六个官方候选版本的 CSV；官方测试文件只做字节与哈希封存，版本选择期不得打开内容。
- 用户决定采用“基线困难版本”主实验。版本必须在本方法运行前，只依据固定基线面板的 `version-selection` 结果冻结；不得按本方法与基线的最大差值选数据。
- 用户要求保留原有方案，不凭主观判断提前淘汰；新增混合架构方案，通过同数据、同头部、同参数量和同训练预算的先导实验二选一。
- 方案 A 为“RWKV-7 原生受序多尺度状态＋正常状态生成预测”；方案 B 为“字段交互编码器＋RWKV-7 动态时序记忆＋同一正常状态生成预测”。
- 正式可复现基座采用 RWKV-7 Goose。RWKV-8 仅有探索文档、实验代码和早期测试检查点，尚无正式论文与冻结训练合同，故只设条件升级门，不进入当前主实验身份。

## 已发现问题

- 系统方案把“长时加密流”列为首选，但数据审计认定 UGR'16 只支撑长时网络异常，不支撑加密流主张。
- 补充检索文档的执行清单全部完成，但底部状态仍写“目录枚举与初筛阶段”，状态记录不一致。
- 现有 GeNIS 与 TQH-C2 冻结视图均未通过同一父会话长度 4、16、32 序列门禁。
- UGR'16 能解除长时间轴门禁，但会把样本单位从单连接改为一分钟全网聚合状态，不能直接沿用现有父会话序列合同。
- 当前方案没有唯一确定 RWKV 基座、输入表示和训练范式，尚不能进入代码实现或 GPU 训练。
