# C12 统一跨年度加载器实现任务简报

> **执行方式**：本任务是 `C12-跨年度种子42快速消融.md` 的任务 2B。使用 `superpowers:subagent-driven-development` 分派唯一实现代理；实现代理必须应用 `daily-coding`。本任务禁止人工夹具、单元测试、集成测试、独立复审和远程运行。

## 目标

新增一个与候选模型无关的 Python 统一加载器，只从 Rust 跨年度物化器发布的正式清单发现和校验制品，并为后续传统基线、神经基线和候选方法提供同一份四角色只读缓存接口。

## 必读依据

- 冻结数据合同：`.Codex/docs/RWKV/2026-08-11-LSPR23-LSPR24共同字段审计与跨年度数据合同.md`
- 快速实验计划：`.Codex/docs/RWKV/candidates/C12-跨年度种子42快速消融.md`
- Rust 实现报告：`.Codex/docs/RWKV/2026-08-11-C12跨年度Rust物化器实现报告.md`
- Rust 生产模式：`thesis/experiments/llm_probe/tools/lspr24_g0/src/lspr_crossyear.rs`
- 可复用加载器模式：`thesis/experiments/llm_probe/src/flow_probe/lspr24_screen_dataset.py`
- 实验规则：`thesis/experiments/llm_probe/AGENTS.md`

## 文件所有权

本代理只负责以下文件，不得修改 Rust 物化器、C12 模型、训练器、配置、启动器、候选文档或路线总控：

- 新建 `thesis/experiments/llm_probe/src/flow_probe/lspr_crossyear_dataset.py`
- 新建实施报告 `.Codex/docs/RWKV/2026-08-11-C12统一跨年度加载器实现报告.md`

你不是独自在仓库工作。不得覆盖、回滚、格式化、暂存或提交其他代理与用户的既有改动。

## 冻结入口

```python
def prepare_crossyear_cache(
    config_path: Path,
    output_dir: Path,
) -> dict[str, object]:
    """校验 Rust 正式制品并发布四角色只读训练缓存。"""
```

入口返回值必须至少给出：正式缓存根、数据集清单与实验清单 SHA-256、77 字段有序清单、归一化器元数据、四角色对象、选择收据哈希、`final_accessed=False`。角色固定为 `source-train`、`source-validation`、`target-prefix`、`target-development`。

## Rust 制品合同

1. `dataset-manifest.json` 的模式版本必须是 `lspr-crossyear-dataset-manifest-v1`，并含 `artifacts`、四角色行数/序列数/缓存行数、角色语义哈希及 `final_accessed=false`。
2. `experiment-manifest.json` 的模式版本必须是 `lspr-crossyear-experiment-manifest-v1`，字段数必须为 77，字段顺序必须与 `model_fields` 完全一致，最大序列长度必须为 128，`labels_outside_features=true`、`group_key_outside_features=true`、`final_accessed=false`。
3. 只允许从两个清单的绝对路径发现制品；所有路径经 `resolve()` 后必须位于配置声明的项目根或正式输出根内。拒绝相对路径、符号链接越界、缺失文件、哈希不符、未知角色和模式版本漂移。
4. 四角色缓存列固定为 `sample_id`、`year_role`、`sequence_id`、`position`、`valid_length`、`available_ns`、`delta_t_us`、`x_value[77]`、`x_missing[77]`、`padding_mask`、`group_key_ref`。模型输入只包含 `x_value`、`x_missing`、`delta_t_us` 和 `padding_mask`；样本、序列、时间、角色与分组键只作路由或审计。
5. 标签侧车仅有 `sample_id`、`label`。`target-prefix` 不存在标签制品，且其公开角色类型或映射中不得出现 `labels`、`label_path` 或可延迟读取标签的属性。
6. 分组侧车仅有 `sample_id`、`pair_key`，只供按序列自助区间和分面统计，不进入模型张量。
7. 归一化器直接消费 Rust `normalizer.json`，不得在 Python 重新拟合、重算或依据 LSPR24 评价数据更新。

## 加载与发布要求

1. 复用现有 `lspr24_screen_dataset.py` 的清单哈希、路径边界、PyArrow 分批列投影、原子目录发布和只读数组模式，但不得调用其旧两角色接口或继承旧 G0 标签语义。
2. 读取时按序列顺序保持 Rust 语义；验证每个角色内 `sequence_id/position` 连续、`valid_length<=128`、首位置为 0、角色不跨序列、样本标识唯一，缓存行数与清单一致。
3. 输出使用磁盘映射或等价只读有界数组，禁止把全部两年度 Parquet 构造成 Python 对象列表。数组至少包含 `x_value`、`x_missing`、`delta_t_us`、`padding_mask`、`sample_id`、`sequence_id`、`position`、`valid_length`；有标签角色另含通过 `sample_id` 一对一连接的标签数组。
4. `source-train` 必须保留“含恶意流序列池/全良性序列池”的选择收据信息，供训练器按序列等量取批；不得把实际行数强行改成相等。
5. 若快速 `source-validation` 缓存中的恶意流少于 200，只允许在任何 LSPR24 评价前扩大为**完整 `source-validation` 角色的全部序列和全部行**；源标签只用于判断是否触发，不得只追加恶意序列或据标签选择成员。使用完整主产品、样本/序列清单和标签侧车生成独立扩展收据，记录触发计数、扩大前后行数/序列数、完整成员 SHA-256 和 `target_label_used=false`。不得按目标标签补样，也不得静默扩大。
6. `target-development` 预测阶段只能暴露无标签特征角色；评价标签连接必须是单独的显式方法或对象，并在预测冻结后调用。该限制与 `target-prefix` 的彻底无标签接口不同，需由类型和命名清楚表达。
7. 发布目录必须含缓存清单，登记源制品哈希、数组路径/模式/形状/数据类型/哈希、角色行数/序列数、字段哈希、归一化器哈希、选择或扩展收据哈希和 `final_accessed=false`。已有完整输出拒绝覆盖；失败保留诊断并清理未发布暂存目录。
8. 预计超过一分钟的真实读取必须有阶段日志和限频心跳；日志报告已处理量、吞吐、累计耗时和可计算的剩余时间，不输出标签值、分组键、凭据或敏感路径解析值。

## 实现边界

- 不访问服务器，不同步文件，不运行真实全量物化或 GPU。
- 不读取、推断或登记 LSPR24 最终 20% 的任何成员、计数、标签、路径或哈希。
- 不创建 `tests/`、人工夹具或伪造 Rust 清单，不运行 `pytest`、全仓检查、格式化器或 Git 命令。
- 不修改候选公式。C12 文献查重正在收窄原创边界，本加载器必须保持模型无关。
- 未确认第三方接口时按 `daily-coding` 使用 Context7；仓库已有且版本锁定的同构 PyArrow 调用直接复用，不做形式查询。

## 最小验收

1. 对新文件执行一次 Python 编译检查。
2. 在项目正式虚拟环境中执行一次真实导入检查，确认冻结函数和无标签角色类型可导入。
3. 若本机不存在 Rust 正式物化制品，不创建伪制品绕过；报告将真实首批读取列为服务器物化后的下一门禁。
4. 实施报告记录修改文件、公开类型与函数、实际命令与退出码、未运行项、已知风险以及服务器真实制品生成后的最小调用方式。

## 返回格式

返回 `DONE`、`DONE_WITH_CONCERNS`、`NEEDS_CONTEXT` 或 `BLOCKED`，并附报告路径、修改文件清单、编译/导入摘要和关键风险。完整细节只写实施报告。
