## 一、为什么重跑

旧运行的 `build_target_view` 从 `runs/diagnostics/dijk-repro/cache/X24.npy` 读特征。
`ch3-cuda-rwkv-lspr24-inmemory-descriptive-eval-v1` 的诊断在 LSPR23 上实测该缓存数组
不是 Dijk 83 字段原值，而是 dijk 复现管线自己标准化后的特征矩阵：有限值不同的单元
`1,224,589,881`，产品侧 NaN `18,276,864` 而缓存侧 `0`，前 20 万行最大绝对差
`251799984.0`，相对差 `>1e-3` 的单元占 `0.913`。ResNet 按 `raw83 → 候选A → 候选B`
变换链训练，喂缓存矩阵等于给模型从未见过的输入分布，旧读数口径无效。

旧运行根与制品保留作证据，本次使用独立运行身份，不覆盖。

## 二、改走的路线

与 CUDA-RWKV 评价同一条正确路径：直读冻结 Parquet，内存内重建胜出臂视图，零物化。

1. 从 `data/raw/lspr24-v1/lspr24_v2.parquet` 按行组流式读 83 个 Dijk 字段、
   `SrcIP`/`DstIP`、`mTimestampStart`、`Label`。
2. 逐批 `_canonicalize_raw83` → `_transform_a` → `_transform_b`，用源年冻结的
   `candidate-a-standard.npz` 与 `candidate-b-official-quantile.npz`，结果只驻内存
   （`20,227,356 × 83` float32，约 `6.7 GiB`）。
3. 序列结构用 `I24.npy` / `M24.npy`——被 `configs/ch3-protocol-a-raw83-target-v1.json`
   以冻结 SHA-256 登记为目标年序列数组。
4. 实体口径不再用缓存 `s24`/`d24`，改为直接从 Parquet 地址列按无向地址对归并。
5. 打分沿用旧工具骨架（父工具 `selected_model`、`entity_aggregate`、`terminal_curve`、
   `budget_points`），只替换数据来源。

## 四、三道证据的设计

1. **变换重建逐单元验证**：从冻结 `lspr23-raw83.npy` 按胜出臂重建视图，与已封印
   `source_view_b` 逐单元比对，要求 `mismatched_cells = 0`。
2. **源年复算对表**：同一套打分与聚合代码在 LSPR23 验证区（`22,444` 序列）复算四格，
   批量与父工具 `score_source` 一致（`64`），标签走冻结 `StreamingLabelResolver`，
   与 `source-cells-sealed.json` 的 `source_validation` 对表；比较三项 AP 与六档
   `actual_fpr` / `detection_rate`，门限 `1e-12`，同时记录是否严格等于 `0.0`。
3. **LSPR24 实体常量命中**：实体 `47,115`、正实体 `752`、逐流正例率与冻结
   `0.0257073138` 差 `< 1e-9`；另断言缓存 `y24` 等于 Parquet 标签、`t24` 等于 Parquet
   开始时刻（这是 `I24`/`M24` 能索引 Parquet 行序的关键对齐证据）。

额外两条披露项（不阻断）：

- 第一批 Parquet 原值与缓存 `X24` 前 `262,144` 行对照，就地留下"缓存不是 raw83"的收据。
- 目标年 `raw_content_sha256` / `label_content_sha256` / 候选B视图内容摘要与
  CUDA-RWKV 运行记录的 `b4f5a307…` / `a66d9f97…` / `614f66b3…` 交叉核对。

## 七、遗留风险

1. 源年复算能否严格取到 `0.0` 未经本运行实测。CUDA-RWKV 同类运行取到 `0.0`，
   但那是另一套模型与 `evaluate_dataset` 路径。本工具把门限设在 `1e-12` 并同时
   记录 `all_exactly_zero`，不把"接近零"写成"等于零"。
2. 描述性评价不是独立最终测试：LSPR24 此前已被本课题多次访问，
   `independent_test=false`，结果只能用于机制对比与量级判断。
3. 目标年 P6 产品仍未物化，输入臂封印仍为 `null`，合法性来自 Parquet 摘要、
   `I24`/`M24` 冻结摘要、变换状态摘要与源年复算等价性，而非 P6 清单。
4. `runs/diagnostics/dijk-repro/cache/` 的 `X23`/`X24`/`s24`/`d24` 不可作为 raw83 或
   实体来源。GRANDE 的 LSPR24 评价经核对是自洽的（`tools/ch3_grande_lspr24_zero_train_descriptive_eval.py:268`
   已注明它本来就在该标准化表示上训练），不属于同一缺陷。
5. **待核查的同类嫌疑**：`tools/ch3_tabm32_paper_recipe_protocol_a.py:1001` 与
   `tools/ch3_ft_transformer_field_token_protocol_a.py:1843` 都从该缓存读 `X23.npy`，
   并在文档字符串中称其为「`(n, 83)` 的 float32 原值」「协议 A 源年冻结数组」，随后在其上
   拟合分位数变换与离散字段词表。若确实是标准化矩阵，端口不再是 `0..65535` 整数、协议不再是
   类别码、二元列不再是 `0/1`，字段角色划分与统一 83 字段预算的公平合同都会受影响。
   他人提交 `72efe91` 已给多个工具补上缓存身份注释，但**未覆盖这两个正在运行的工具**。
   已开出独立任务核查，本任务不动这两个实验。
