## 一、任务前提被实验推翻

原任务假定「LSPR24 原始数据在 `runs/diagnostics/dijk-repro/cache/X24.npy`，直读即可」。实测否决该假定。

诊断脚本：`runs/diagnostics/ch3-cuda-rwkv-lspr24-inmemory-descriptive-eval-v1/diagnostics/diagnose_cache_vs_product.py`
与 `diagnose_x23_nature.py`，日志 `diagnose.log`、`diagnose-x23.log`。

在 LSPR23 上把缓存 `X23.npy` 与协议A冻结 `lspr23-raw83.npy` 逐单元比对（两者同为
`float32 (16353511, 83)`，文件字节数相同）：

| 观测 | 数值 |
| --- | --- |
| 有限值不同的单元数 | `1,224,589,881` |
| 只有产品侧非有限（NaN）的单元数 | `18,276,864` |
| 缓存侧非有限单元数 | `0` |
| 与 raw83 的最大绝对差（前 20 万行样本） | `251799984.0` |
| 相对差 `>1e-3` 的单元比例 | `0.913` |

逐列样例（第 0 列 `SrcPort`）：缓存 `-0.3009…`，raw83 `48778.0`，协议A候选A视图 `0.0932…`。

结论：`dijk-repro` 缓存的 `X23.npy` / `X24.npy` 是 dijk 复现管线自己拟合的标准化特征矩阵，
不是 Dijk 83 字段原值，也不等于协议A的任一候选视图。把它送进按 `raw83 → 候选A → 候选B`
拟合的 CUDA-RWKV，会让模型看到训练时从未见过的输入分布，结果无效。

同时确认缓存与协议A产品在**流行序上一致**：`I23`、`M23` 逐字节相同；`y23` 转 `int8` 后的
内容摘要等于源年清单登记的 `label_content_sha256`；`t23_flow` 只是把同一开始时刻列存成
`float64`（值相同，故文件摘要不同）。

## 二、改走的路线

不做物化、不写任何数据制品，改为**直读冻结 Parquet 并在内存内重建候选 B 视图**：

1. 从冻结的 `data/raw/lspr24-v1/lspr24_v2.parquet`（`sha256=1d96f0a0…`，`20,227,356` 行，
   `21` 行组，`101` 字段）按行组流式读取 83 个 Dijk 字段、`SrcIP`/`DstIP`、`mTimestampStart`、`Label`。
2. 逐批 `_canonicalize_raw83` → `_transform_a` → `_transform_b`，用源年冻结的
   `candidate-a-standard.npz` 与 `candidate-b-official-quantile.npz`，结果只驻内存
   （`20,227,356 × 83` float32，约 `6.7 GiB`）。
3. 序列结构直接用 `I24.npy` / `M24.npy`——它们被 `configs/ch3-protocol-a-raw83-target-v1.json`
   以冻结 SHA-256 登记为目标年序列数组，本次核验通过。
4. 序列侧车（序列实体、序列开始时刻）按 `materialize_qualified_year_product` 的语义在内存派生。

因此把 `evaluate_dataset` 尾部的聚合与曲线逻辑逐句保留、只替换数据来源，并用第 3.3 节的
源年复算证明两条路径数值等价。

## 七、遗留风险与边界

1. 这是描述性评价，不是独立最终测试：LSPR24 此前已被本课题多次访问，`independent_test=false`。
   结果可用于机制对比与量级判断，不得当作未见测试集成绩。
2. 未生成 P6 目标年产品，也未做输入臂封印（源年清单 `source_input_arm_sha256` 为 `null`，
   目标物化配置仍处于 `blocked-until-source-arm-seal`）。本次评价的合法性来自
   Parquet 摘要、`I24`/`M24` 冻结摘要、变换状态摘要与源年复算等价性，而非 P6 清单。
   若日后正式物化 P6 并用标准入口重跑，应核对本报告数值。
3. `result_sha256` 与源年封印文件不一致属于口径差异（见 3.3），不代表数值差异。
4. 时间与显存为并发条件实测，不得用于严格效率支配。
5. `dijk-repro` 缓存的 `X23`/`X24` 不可作为 raw83 使用。任何后续工具若需要 Dijk 83 字段原值，
   必须回到 `lspr23-raw83.npy` 或 LSPR24 Parquet；本条应写入故障手册避免复发。
