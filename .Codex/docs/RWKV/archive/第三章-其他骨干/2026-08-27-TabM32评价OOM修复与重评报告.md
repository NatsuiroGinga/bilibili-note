## 一、故障现场与根因

故障发生在 `evaluate` 阶段（08-26 16:42），`evaluate.log` 末尾：

```
torch.OutOfMemoryError: CUDA out of memory. Tried to allocate 8.00 GiB.
GPU 0 has a total capacity of 31.36 GiB of which 3.06 GiB is free.
```

栈顶指向 `tools/ch3_tabm32_paper_recipe_protocol_a.py:1393`
（`LinearBatchEnsemble.forward` 内 `projected * self.s...`），调用链
`score_target → shared_batch_flow_probability → expand_to_members → forward`
（第二层 `hidden_layer`）。

**根因**：`score_target`（原第 2803 行）写死 `batch_sequences = 2048`，这是从同族
k=4 成员工具 `tools/ch3_resmlp2_tabm_protocol_a_2x2.py` 的 `score_target`
（同一行常量，同一用途）原样搬来的，未按 TabM32 的 k=32 成员重新核算。

该常量控制多少条流共享同一次前向调用；`forward` 内部把每条流按
`shared_batch_flow_probability → expand_to_members` 展开出完整成员维（展开后
成员维与批维同阶，不是均摊）。三层 BatchEnsemble 中 `hidden_layer` 的隐藏张量
实际形状是 `(batch_sequences, ensemble_members, sequence_length, hidden_size)`。
按精度合同计算类型（bf16，2 字节）展开：

```
2048(batch) × 32(members) × 128(length) × 512(hidden) × 2(bytes)
  = 8,589,934,592 字节 = 8.00 GiB
```

与故障日志 `Tried to allocate 8.00 GiB` 逐位相符。对照同族工具在 k=4 时的同一
常量：`2048 × 4 × 128 × 512 × 2 = 1,073,741,824 字节 = 1 GiB`，不会触发 OOM——
这正是该常量在 k=4 工具上跑得通、被原样搬到 k=32 工具后才暴露的隐患：成员数放大
8 倍，隐藏张量随之放大 8 倍，从安全的 1 GiB 变成危险的 8 GiB。

## 二、修复内容（唯一改动）

文件：`thesis/experiments/llm_probe/tools/ch3_tabm32_paper_recipe_protocol_a.py`
第 2803 行（修复后含注释共 24 行，落在约 2803-2826 行）。

将：

```python
batch_sequences = 2048
```

改为：

```python
batch_sequences = config["training"]["effective_batch_size"]
```

（`effective_batch_size = 64`，来自冻结训练合同 `_EXPECTED_TRAINING`。）

**选择依据**：本文件同一模块内的 `evaluate_validation_flow_ap`（第 1892-1893 行）
已有明确注释与已验证行为——"推理批取有效批的序列数：同一批对象数下 `no_grad`
保留的显存严格低于训练步，因此不需要另立一个未经依据的推理批常数"。该函数在
`train_cell` 的每轮验证中反复调用同一 `shared_batch_flow_probability` 前向，
同样是 32 成员、128 长度、512 隐宽，已在四格训练全程稳定跑通，是本仓库内唯一
对 TabM32 该前向路径已核验安全的批量取值。复用它而不是另设新常量，既满足仓库
"禁止另立未经依据的推理批常数"的既有设计意图，也不需要为新数字单独登记魔法数字
依据。

按同一公式核算修复后的张量上界：

```
64(batch) × 32(members) × 128(length) × 512(hidden) × 2(bytes)
  = 268,435,456 字节 = 256 MiB
```

较此前的 8.00 GiB 上界低 32 倍。

**数学等价性**：`batch_sequences` 只是 `score_target` 循环的分块大小，不改变
计算内容。每条流的推理只依赖其自身 `I24`/`M24`/`X24` 行与训练区拟合状态，
32 个成员概率的算术平均（`member_mean_probability`）与实体聚合
（`entity_scores`）均逐流/逐实体独立计算，不跨批边界耦合；不同分块大小只改变
`for start in range(0, len(I), batch_sequences)` 的循环次数与每次处理的行数，
不改变任何逐流概率值或最终指标。修复未触碰训练、选择、聚合口径、指标公式或任何
冻结数值，未新增门禁。
