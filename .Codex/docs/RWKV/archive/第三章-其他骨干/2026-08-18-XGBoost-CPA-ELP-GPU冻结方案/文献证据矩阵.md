# XGBoost 版 CPA–ELP 文献证据矩阵

> 状态：六阶段审计完成。本文只划定来源、原创边界、强基线、工程接口与失败条件；所有效果结论均为“实验待证”。
>
> 代理映射：`xgboost_cpa_elp_literature_sol_max → gpt-5.6-sol → effort=max`。核验日期：2026-08-18。

## 一、结论摘要

1. **部件均有全文来源，但完整组装不是既有方法的直接复现。** 历史连接统计、实体级原始流聚合、树模型逐流分类后的主机告警、归一化幂平均、梯度学习幂指数、训练域模型选择以及 XGBoost 的 GPU 量化直方图，各自都有强证据。
2. **CPA 的原创边界必须收窄到任务特定适配。** “跨流统计附加到当前分类样本”并不新；可主张的新适配是：沿 Dijk 等的无向 2-IP、稳定时间顺序和 128 流边界，只使用 `i≤t` 的合法原始数值字段构造含当前流的前缀上下文，把地址仅作分组键，再将上下文与当前行拼接给 XGBoost。该精确组合未在核验全文中出现。
3. **ELP 不是可学习范数池化的原样迁移。** Gülçehre 等与 Revaud 等支撑可微模型里通过反向传播学习幂次；本方案是对冻结 XGBoost 概率分数做实体幂平均，并仅用源年验证集离散选 `p`。应称“源年验证选择的实体级幂平均指数”，不能称“端到端可学习参数”。
4. **没有发现完整同构近邻。** 在最后一次新增核心全文后，连续两轮直接同构复检均无新增；但该结论只适用于已记录的数据库、查询式和日期，不能改写为“绝无先例”，也不能单独证明原创性。
5. **四格只需两次 XGBoost 拟合。** raw 模型的同一份逐流分数生成 `B0` 与 `ELP`；context 模型的同一份逐流分数生成 `CPA` 与 `CPA+ELP`。ELP 是冻结分数上的后处理，不产生第三、第四次拟合。
6. **GPU 方案有官方接口依据，但单卡双拟合并发没有官方加速保证。** 两次拟合均可用相同的 `device="cuda"`、`tree_method="hist"` 和 `QuantileDMatrix`；只有联合显存、主存与实测吞吐门禁通过才并发，否则串行 GPU 拟合。`DataIter`／`ExtMemQuantileDMatrix` 是容量路径，不是默认提速保证。

## 四、强基线与公平比较边界

### 4.1 四格与实际拟合次数

| 展示格 | 设计矩阵与逐流分数 | 实体聚合 | 是否新增拟合 | 直接检验的问题 |
| --- | --- | --- | ---: | --- |
| `B0：raw+max` | raw XGBoost 分数 `s^(raw)` | 精确最大值 | 是：raw 拟合 | 当前同数据 raw XGBoost 的强基线 |
| `ELP：raw+M_p` | 复用 `s^(raw)` | 源年验证选择的 `M_{p_raw*}` | 否 | 只改变实体后处理是否有增量 |
| `CPA：context+max` | context XGBoost 分数 `s^(context)` | 精确最大值 | 是：context 拟合 | 只改变输入上下文是否有增量 |
| `CPA+ELP：context+M_p` | 复用 `s^(context)` | 源年验证选择的 `M_{p_context*}` | 否 | 两个部件组合及交互是否有增量 |

因此，冻结预算是**两份设计矩阵、两次模型拟合、四种评价映射**。raw 与 context 可各自从同一冻结候选集选出不同 `p`，只要选择算法、源年验证数据、目标函数与并列规则完全相同；若方案要求共享一个 `p`，也必须在看目标年结果前冻结。

### 4.2 raw／context 模型的公平性约束

- 两次拟合必须使用相同的训练行、标签连接、源／目标年度划分、样本权重、XGBoost 超参数、`device`、`tree_method`、`max_bin`、随机种子、行采样、列采样、提前停止规则和最大拟合轮数。
- 唯一预定差异应是特征矩阵：raw 只含合法当前流字段；context 在完全相同的 raw 字段上追加冻结的 CPA 字段。地址、实体键、标签衍生字段和目标年统计不得进入预测列。
- Dijk 等在同一数据上给出的 OP 原始 XGBoost 是最近的外部基线来源；正式复现仍须以当前冻结数据清单和 GPU 配置重跑，不能把历史 CPU 数值直接当成同预算对照。
- Grinsztajn 等支持把 XGBoost 视为表格数据强基线，但其研究排除了流式／时序和不平衡任务，故不能代替本数据上的共同预算比较。

### 4.3 ELP 必须保留的锚点

- **最大值锚点**：`p=∞` 使用精确最大值分支，是 `B0` 与 `CPA` 的共同主对照；不得用一个随意的大有限数冒充。
- **均值锚点**：`p=1` 检验简单平均是否已经足够，也是 Pevný 与 Somol 等固定池化先例覆盖的边界。
- **源年选阶**：对每个分支只用独立源年验证预测计算 `p_b*`；候选集、目标 `J_src-val` 与确定性并列规则必须预注册。不得用模型拟合样本的原位预测、LSPR24 标签或目标年分布统计选 `p`。
- **迁移固定值锚点**：既有神经方案的 `p=1.223554` 最多作为“迁移固定指数”辅助对照。没有 XGBoost 分支自己的源年选择收据时，不得称为 XGBoost 版 ELP 的已选参数。
- **实体计数基线**：Gehri 等的主机恶意流计数阈值是强后处理近邻。若数据合同允许复现，应与幂平均并列，而不是只比较最大值和自选 `p`。

### 4.4 评价与报告边界

- 主评价至少同时报告平均精确率、完整告警预算曲线和 `DR@4%FPR`；只在单一工作点改善不足以支持“告警预算普遍改善”。
- CPA 主效应比较 `CPA` 对 `B0`；ELP 在 raw 分支的主效应比较 `ELP` 对 `B0`；组合比较 `CPA+ELP` 对 `CPA`，并计算交互差分：

  `Δ_interaction=[J(CPA+ELP)-J(CPA)]-[J(ELP)-J(B0)]`。

- 通过／失败门槛、种子数量、置信区间方法和困难分面须在目标年揭盲前冻结。文献只证明这些对照有必要，不提供本任务应取得的效果数值。

### 4.5 GPU 与容量路径的公平性

- raw 与 context 均优先使用相同版本的 CUDA `hist` 与 `QuantileDMatrix`；验证／测试量化矩阵引用各自训练矩阵，`max_bin` 与训练参数一致。
- 首选内存内量化矩阵。只有容量门禁失败时才评估 `DataIter`／`ExtMemQuantileDMatrix`；外存路径仍须维持相同数据、特征和训练语义，并单列吞吐、峰值显存与主存。
- 单卡上两个独立拟合是否并发只是调度选择。并发若导致溢出、抖动或吞吐下降，应改为串行 GPU 拟合，同时并行不争用显存的 CPA 物化、`p` 网格聚合和指标计算；这一变化不改变四格科学合同。

## 五、可证伪失败条件

以下条件用于冻结实验的事前裁决；本审计没有运行实验，也不预判任何一项已经发生。

| 条件 | 类型 | 裁决与处置 |
| --- | --- | --- |
| 当前行获得 `t` 之后的流、整束最终统计或跨 128 边界的非冻结历史 | **设计无效：因果泄漏** | 受影响的 CPA 结果全部无效；修复物化合同后重跑，不能把 Hindy 等的整束回填当因果证据 |
| IP、2-IP 键、实体标识、目标年频次或标签衍生字段进入预测列 | **设计无效：标识／目标泄漏** | 停止受影响比较；键只允许分组和连接，不得作为模型特征 |
| 使用 LSPR24 标签、目标年指标或目标分布统计选择字段、`p`、轮数或阈值 | **设计无效：目标域 oracle** | 该选择及其结果无效；恢复到源年训练／验证协议 |
| 用 XGBoost 原始对数几率直接计算非整数幂，或允许负分数进入 `M_p` | **数学合同无效** | 改用明确的非负概率分数；若研究 raw margin，必须另定义合法变换，不能沿用当前 ELP 名义 |
| 网格含 `0<p<1` 却把算子称为 Lp 范数，或把有限大 `p` 当成精确最大值 | **表述／实现无效** | 改称幂平均；为 `p=∞` 实现独立精确分支，并在清单中固定 |
| raw 与 context 使用不同训练行、标签、预算、GPU 树方法、`max_bin`、种子或采样率 | **比较无效：预算不公平** | 不能解释为 CPA 效应；先恢复共同预算与数据合同 |
| 验证／测试 `QuantileDMatrix` 未按训练矩阵 `ref` 构造，或目标机版本不支持冻结接口 | **工程门禁失败** | 不启动正式比较；先核验实际 XGBoost／CUDA 版本和接口，再使用等义支持路径 |
| `CPA` 对 `B0` 在预注册主指标、种子一致性和不确定性门槛下无正增量 | **CPA 科学失败** | 否决或收缩当前 CPA 字段合同；不得用新增公式替代结果裁决 |
| 源年选择的 `p` 总是落到 `∞`，或 `ELP` 未超过同分数的精确最大值锚点 | **ELP 无独立增量** | ELP 退化为最大池化或未获支持；保留最大值基线，停止宣称选阶贡献 |
| 源年验证选出的 `p` 在目标年低于同分支最大值，即使源年上更好 | **跨年迁移失败** | 记录为源年选阶不能迁移；不得事后改 `p` 或查询目标年重新选择 |
| `Δ_interaction≤0`，或其不确定性不支持正交互 | **组合交互未获支持** | 可以分别报告主效应，但不能声称 CPA 与 ELP 产生正协同 |
| 只有 `DR@4%FPR` 单点改善，而完整告警预算曲线没有一致优势 | **适用范围失败** | 只能报告该冻结工作点，不得推广为一般告警预算收益 |
| 单卡同时运行两次拟合导致显存溢出、上下文争用或总耗时高于串行 | **调度失败，不是科学失败** | 改为两次串行 CUDA 拟合；继续并行 CPU／不争用显存的后处理 |
| `ExtMemQuantileDMatrix` 不受目标版本支持，或外存因 PCIe／磁盘变慢 | **容量路径失败，不是科学失败** | 回退内存内 `QuantileDMatrix`、减小合法批量或串行处理；不据此否决 CPA／ELP |

## 六、完整同构近邻检索结论

### 6.1 判定合同

“完整同构”要求一篇全文同时满足：

1. 输入单位是原始逐流表格特征；
2. 在同一网络实体内构造严格 `i≤t` 的因果前缀上下文；
3. 把该上下文作为 XGBoost 的附加输入；
4. 把逐流概率分数以幂平均汇成实体分数；
5. 幂指数只在源年度以非梯度协议选择并冻结到目标年度。

联网第 2 轮新增 Hindy 等后，第 3、4 轮直接同构复检均无新增核心全文；本地 `raw/wiki`、Zotero 只读检索和经典引用链也没有得到五项齐备的全文。因此停止条件已经满足，裁决为：**截至 2026-08-18，在记录的检索范围内未检索到完整同构近邻。**
