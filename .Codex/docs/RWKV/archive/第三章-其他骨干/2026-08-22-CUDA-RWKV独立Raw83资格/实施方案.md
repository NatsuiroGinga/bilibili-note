- **日期**：2026-08-22
- **路线**：`RESEARCH_ROUTE=RWKV`
- **状态**：`DESIGN=READY`、`IMPLEMENTATION=NOT_STARTED`、`EXPERIMENT=NOT_RUN`

## 一、结论

CUDA-RWKV 按独立训练与数值身份从共享 Raw83 源年产品开始。当前方案由官方固定 CUDA 核、中性命名的独立后端、独立模型/训练/评价代码、统一精度模块和统一跟踪模块组成。

当前选择严格分三段：先固定中性适配与小型容量选择 A/B，再固定胜出视图选择 R1/R2，最后固定视图与适配选择容量包。每段只改变一个预注册因素，完全相同的已训练单元直接复用，不形成 A/B、R1/R2 与容量包的笛卡尔积。

所有输入、适配、容量、epoch 与四格检查点只按 LSPR23 固定验证逐流 AP 选择。四格源年模型、代码、配置、评价程序和制品全部封印后，才允许首次打开 LSPR24，并只作一次分表描述性评价。

## 二、不可变实现边界

### 2.1 允许依赖闭包

活动训练入口只允许导入以下本项目模块：

1. 新建的 CUDA-RWKV 模型、训练、评价和官方融合后端模块。
2. `src/flow_probe/protocol_a_raw83.py` 与 `src/flow_probe/protocol_a_preprocessing.py` 提供的共享数据清单、视图和阶段权限接口。
3. `tools/neural_precision_runtime.py` 提供的统一精度、有效批、随机状态、检查点与资源收据接口。
4. `src/flow_probe/tracking.py` 提供的统一 SwanLab 目的地、标签和初始化接口。
5. Python 标准库以及配置中固定版本并经官方文档核验的 NumPy、PyArrow、scikit-learn、torch 和 SwanLab。

启动器生成 `dependency-closure.json`，记录所有本地导入文件的仓库相对路径和 SHA-256。集合必须与配置白名单精确相等；出现额外训练工具、绝对路径逃逸、符号链接或未登记导入即失败。

### 2.2 独立身份

- 模型、优化器、调度器与随机状态均由当前配置从随机初始化创建。
- 数据身份只接受共享 Raw83 清单、状态和语义哈希。
- 运行根、检查点根、扩展构建根、跟踪身份和配置摘要均为当前方案独立生成。
- 实现失败时保留精确失败证据并停止该候选。

### 2.3 效果证据边界

本方案只能说明设计可执行。官方源码、文献、编译通过、数值稳定或首步更新均不证明 CUDA-RWKV 在 LSPR 上有效；只有合法 Raw83、真实源年选择、四格消融、完整指标和资源制品可以形成实验裁决。

### 3.2 特殊字段处理

| 字段角色 | 索引 | CUDA-RWKV 输入处理 |
| --- | --- | --- |
| 端口数值 | `0,1` | 保持 A/B 共享视图中的连续数值表示，不独热、不分桶、不建 65,536 词表 |
| 协议数值 | `2,79` | 保持共享视图数值；训练有效流记录原始唯一值和频数只作结构收据，不生成模型词表 |
| 连续/计数 | `3..78` | 按胜出 A/B 共享视图读取，不由模型再次拟合 |
| 二元粗拓扑 | `80..82` | 原始结构必须属于 `{0,1}`；模型读取 A/B 共享视图中的对应数值 |

### 3.5 序列、开始时刻与因果

| 项 | 冻结合同 |
| --- | --- |
| 序列索引 | `I[s,p] -> raw_row_index`，`M[s,p]` 为有效位，形状 `[N,128]` |
| 排序 | 同一无向实体内按 `mTimestampStart` 稳定升序，稳定并列键沿用共享清单 |
| 开始时刻 | 只用于排序、`T[s]` 身份与审计，不作为第 84 个特征 |
| 位置 | 位置 `p` 只通过 CUDA-RWKV 的递归顺序体现，不增加未来位置、实体最终长度或目标统计 |
| 因果 | 有效位置 `p` 的输出只依赖同块 `0..p` 的有效流；补零位输入、状态贡献、输出和损失均为零 |
| 块间状态 | 每个长度 128 块开始时状态清零；状态不跨块、实体、批次、训练/验证或年度 |
| 状态消融边界 | 跨块连续状态与实体内打乱属于后续独立机制，不进入本资格选择或四格 |

### 3.6 标签与损失权重

- 逐流正类权重只由 `I23[train_rows][M23]` 对应标签计算。
- 序列或实体辅助权重只由 `train_rows` 中实际训练单元计算。
- `validation_rows` 标签只计算每轮逐流 AP及选中检查点的源年完整指标，不进入权重、采样、变换或梯度。
- 类别权重收据保存正负分子、分母、训练有效流哈希和标签内容哈希；任何全年度 `labels.mean()` 或验证成员参与均失败。

### 3.7 模型输入、输出、状态与梯度

```text
共享视图 [B,128,83] + M
  -> R1 或 R2 [B,128,C]
  -> 独立 CUDA-RWKV 块
       六输入 r,w,k,v,a,b: BF16、连续、CUDA
       递归/分块状态: FP32，块首清零
       六梯度 dr,dw,dk,dv,da,db: BF16
  -> 逐流隐藏 [B,128,C]
  -> 逐流 logit [B,128]
  -> 可选因果前缀模块和可选实体池化模块
```

首个真实完整优化步必须证明：

1. 六个 CUDA 输入、输出和六个返回梯度形状、设备、连续性与精度符合合同。
2. 六个梯度全部有限，且每个张量至少一个元素非零。
3. 输入适配、每个 CUDA-RWKV 块、逐流输出头均至少一个 FP32 参数发生有限更新。
4. 启用某模块的格还必须证明该模块参数更新；未启用模块不得获得梯度或更新。
5. 损失、梯度范数、裁剪前后范数、优化器步号和参数更新摘要写入 `first-complete-step-receipt.json`。

### 3.8 参数公式与模型哈希

小型容量固定 `C=112`、头大小 `16`、低秩维 `8`、一个 CUDA-RWKV 块，共同部分参数 `82,322`：

```text
P_small(R1) = 82,322 + (97q + 12qC + 3C + 1), q=15, C=112 = 104,274
P_small(R2) = 82,322 + (C^2 + 84C), C=112 = 104,274
```

论文尺寸容量固定 `C=768`、头大小 `64`、低秩维 `32`、三个 PreLN CUDA-RWKV 块：

```text
P_common(C,r) = 14C^2 + 22Cr + 49C + 2
P_large(R1) = P_common(768,32) + (1456 + 183C) = 8,977,842
P_large(R2) = P_common(768,32) + (C^2 + 84C) = 9,490,178
```

`model-spec.json` 以规范 JSON 登记字段/组 SHA、视图、适配、容量、层数、宽度、头大小、低秩维、四格位、参数公式、公式值和 `sum(p.numel())` 实测值。公式值与实测值不等即失败；规范 JSON 生成 `model_spec_sha256`，进入配置、检查点、结果和清单。

## 四、分阶段最小源年选择

### 4.1 共同选择规则

- 数据：仅 LSPR23 `train_rows` 训练、`validation_rows` 选择。
- 机制格：选择阶段全部固定 C00。
- 训练预算：20 轮，每轮 1000 个完整优化步，有效批 64；微批和累积只按资源机械拆分，保持有效批和按有效流归一不变。
- epoch 规则：每轮验证逐流 AP 全精度最大者胜出，完全相等取最早 epoch。
- 候选规则：候选选中 epoch 的验证逐流 AP 全精度最大者胜出，完全相等按预注册的简单/低参数顺序。
- 其他指标只报告，不参与任何选择。
- 每一阶段封印前断言 LSPR24 模式、特征和标签读取均为 0。

20 轮、1000 步、有效批 64、种子 42 是现有 Protocol A 的共同任务化预算，无直接文献精确依据；本轮只在未读取目标年的同一源年协议中复用，不能根据结果追加训练机会或改变预算。

### 4.2 阶段 S1：只选择 A/B

固定 R2、小型容量和 C00，按 `A -> B` 各训练一次。唯一变化因素是共享数值视图。胜出写入 `seals/source-transform-selection.json`，包含两视图与状态哈希、两个检查点、逐流 AP、并列规则和目标读取零计数。

### 4.3 阶段 S2：只选择 R1/R2

固定 S1 胜出视图、小型容量和 C00。R2 直接复用 S1 胜出臂对应的同身份检查点，只新增一次 R1 训练。唯一变化因素是输入语义适配；二者适配参数均为 `21,952`。胜出写入 `seals/source-adapter-selection.json`。

### 4.4 阶段 S3：只选择容量包

固定 S1 胜出视图、S2 胜出适配和 C00。小型容量直接复用前一阶段完全同身份检查点，只新增论文尺寸容量训练。唯一变化因素是预注册容量包；胜出写入 `seals/source-capacity-selection.json`。

论文尺寸三层、宽度 768 来自已核 RWKV 时序论文配置，只用于构成有来源的容量上限候选，不证明适合 LSPR。小型容量来自官方核当前已审计的固定形状和 R1/R2 同参方程，只作最小资格点。

### 4.5 训练单元上界与停止

分阶段选择最多新增 `2 + 1 + 1 = 4` 个训练单元：S1 两个，S2 一个，S3 一个。不存在 `2×2×2` 的八组合搜索，更不存在与四格相乘的展开。

若任一阶段出现数据无效、CUDA 无效、非有限值、资源安全失败或所有候选不可训练，停止受影响候选并保留收据。候选性能不佳是有效科学结果；不得通过增加新视图、新适配、新容量或读取 LSPR24 改写既定选择。

## 五、官方 CUDA 资格门

### 5.1 供应商与可执行身份

新供应商清单固定：官方仓库、提交 `952102498e9ed367ea0a59ee64106916d474d30f`、`Apache-2.0`、官方 C++/CUDA 原件 SHA-256、派生注册文件 SHA-256、编译宏、编译参数、目标架构、torch/CUDA/NVCC/C++ 版本和扩展二进制 SHA-256。

每个容量包使用独立注册命名空间和扩展名，避免算子覆盖。官方 CUDA 计算核逐字不改；派生 C++ 只允许更改注册命名空间与格式，并在文件头和清单中显式声明。

### 5.2 编译门

1. 官方原件、许可证和派生文件摘要与清单一致。
2. 目标环境版本与配置精确匹配，CUDA 可用、BF16 可用、计算能力为 `12.0`。
3. `nvcc`、`ninja`、C++ 编译器存在，构建根位于持久运行目录且可写。
4. 只为当前预注册容量包编译，宏满足 `T=128`、`T % CHUNK_LEN == 0`、`C % HEAD_SIZE == 0`。
5. 加载后只出现预期注册算子；扩展二进制与构建日志进入清单。

### 5.3 独立数值稳定门

资格门只检验 CUDA-RWKV 自身：

- 固定种子、固定有界输入重复两次前向和反向，输出、损失和六梯度均有限，重复结果逐位一致。
- 对 `r,w,k,v,a,b` 分别施加预注册的单张量微扰，输出或标量损失必须发生有限变化，且其余五个输入不变。
- 全零掩码块输出和损失贡献严格为零；有效前缀后追加补零不会改变此前有效位置输出。
- 连续执行两个独立块时，第二块结果不受第一块状态污染，证明块首状态重置。
- 同一进程第二次加载不得重新注册冲突算子；新进程从清单构建根加载同一二进制身份。

该门只输出“实现稳定/不稳定”和偏差量，不创建 SwanLab 身份，不进入论文效果结果。

### 5.4 首个真实优化步门

每个容量包第一次真实训练在完整 `optimizer.step()` 后立即写收据，覆盖六梯度、各模块参数更新、BF16/FP32 身份、损失、梯度裁剪、CUDA 内外显存和资源。门未通过不得进入第二个优化步。

## 六、精度、训练和恢复

### 6.1 BF16/FP32 岛

| 区域 | 精度 |
| --- | --- |
| 参数与优化器状态 | FP32 |
| 常规线性层激活 | `cuda-bf16-amp-fp32-sensitive-v1` 下自动混合精度 |
| CUDA 核六输入、输出与六梯度 | BF16 |
| CUDA 递归状态、分块状态与核内累加 | FP32 |
| LayerNorm、向量归一化、衰减构造、门函数 | FP32 敏感岛 |
| 类别权重、逐流/实体损失、CPA 前缀和与除法、ELP 对数/幂、指标与阈值 | FP32 敏感岛 |

BF16 不创建 `GradScaler`。有效批起点只调用一次 `zero_grad(set_to_none=True)`；微批损失按有效流求和，全部微批结束后除以该完整优化步实际有效流数，再裁剪并执行一次更新。尾批按实际有效流数归一，不补样本、不丢样本。

### 6.2 每 20 步原子断点

每个训练单元在完整优化步 `20,40,60,...` 以及每个 epoch 结束后保存：

- 模型、优化器、调度器状态和已完成 epoch/优化步。
- Python、NumPy、torch CPU/CUDA 与采样器随机状态。
- 精度 profile、微批、累积、实际有效流归一化和梯度裁剪状态。
- Raw83 清单、视图、切分、标签、模型规格、代码、配置、官方 CUDA、扩展二进制和评价程序哈希。
- 验证历史、当前最佳 epoch/AP、并列裁决和完成单元集合。
- 累计资源、SwanLab 发布状态和失败次数。

断点先写 `.partial.<pid>`，文件同步后原子替换；状态文件不得早于断点封口。半步中断从该完整优化步起点重放，不恢复部分累计梯度。

### 6.3 同 CUDA 身份恢复

`cuda_execution_identity_sha256` 覆盖官方提交与源码、派生注册文件、后端代码、编译宏和参数、扩展二进制、torch/CUDA/NVCC/C++ 版本、计算能力、设备名称和 GPU UUID。恢复时该哈希以及数据、模型、配置和精度哈希必须全部相同；任一漂移即拒绝拼接。已完成单元按完整清单幂等跳过，未完成单元只从最后一个合法 20 步断点继续。

### 6.4 资源安全门

| 资源 | 启动门 | 运行门 |
| --- | --- | --- |
| GPU 显存 | 当前单任务空闲显存至少 `20 GiB`，且不存在未授权并发训练 | 首步记录 `allocated/reserved/max_allocated/max_reserved`；OOM 停止并保留原退出码 |
| cgroup 主存 | 可用至少 `40 GiB` | 每 5 秒采样当前值与峰值；逼近限制时在最近完整断点后停止 |
| 磁盘 | 使用率 `<80%`；可用空间至少为“剩余检查点＋扩展＋最大原子临时文件＋10 GiB”，且不得低于 `25 GiB` | 达到 80% 或不足 10 GiB 通知；达到 90% 或不足 5 GiB 停止新增大文件 |

`20/40/25 GiB` 是 B76 与既有神经训练的工程准入值，不是科研阈值。训练没有墙钟、GPU 小时或日历日上限；运行变慢本身不构成停止原因。

### 6.5 SwanLab 生命周期

本节逐项继承提交 `89ddecf`、`d6313ca` 与 `70a8a2b` 已关闭的资源增量、单运行恢复和尝试目录标签摘要合同：

- 科学日志、检查点和指标先原子保存在唯一运行目录；云端不是唯一事实源。
- 完整资格链使用一个最终在线聚合运行，调用统一 `initialize_swanlab_run`，不直接拼接第三方初始化参数。

- 最多 `attempt-1/attempt-2`；只有首次零步初始化 `401` 返回专用退出码 `91`，启动器才可用全新 Python 进程进行第二次尝试。

- `finish()` 后立即写尝试目录成功收据。成功收据存在但顶层清单缺失时只恢复本地封口，不再次创建云端运行。

## 七、四格训练与源年封印

### 7.1 四格定义

| 格 | 因果前缀模块 | 实体可学池化模块 | 作用 |
| --- | --- | --- | --- |
| C00 | 关闭 | 关闭 | 胜出 CUDA-RWKV 骨干基线 |
| C01 | 关闭 | 开启 | 只检验决策层模块 |
| C10 | 开启 | 关闭 | 只检验表示层模块 |
| C11 | 开启 | 开启 | 检验双模块组合 |

C00 只有在视图、适配、容量、模型规格、训练预算、精度、代码和检查点身份逐项相同时才复用 S3 胜出检查点。C01、C10、C11 各自从种子 42 独立初始化，不能从 C00 或其他格继续训练。每格仍按 LSPR23 验证逐流 AP 的最早最大 epoch 封印。

### 7.2 源年完整制品

四格每格输出：逐轮验证历史、选中检查点、梯度收据、20 步断点、逐流 AP、实体 AP、最大实体 AP、完整共同整数 FP 终端曲线、完整共同整数 FP 首次告警曲线、六档锚点、资源收据、日志和清单。

源年公共整数 FP 轴以固定验证池良性实体数为分母。对每个整数预算 `k`，每格只取自身全部完整并列组中 `FP<=k` 的最后可达点；不拆并列、不插值。六档 `0.1%/0.5%/1%/2%/4%/8%` 由同一公共整数预算轴投影，并同时报告名义 FPR、实际 FP/FPR、阈值、并列组和下一可达点。

首次告警从实体第一条合法可观测流开始，横轴为 1 基 `exposure_index`。每个公共 `k` 同报未告警比例、及时检出阶梯、实际 FP/FPR 和完整并列组；未告警实体保留在分母。

### 7.3 `source-qualification-seal.json`

只有以下全部满足才签发：

1. 共享 Raw83 源产品和 A/B 视图清单完整。
2. S1/S2/S3 三个选择封印及所有候选检查点哈希完整。
3. C00/C01/C10/C11 四格训练、选择、梯度、资源和源年完整指标齐全。
4. 模型、训练、评价、官方 CUDA、统一精度、统一跟踪、配置和启动器哈希冻结。
5. 禁止逐样本标签/预测制品门通过。
6. `target_schema_reads=0`、`target_feature_rows_read=0`、`target_label_rows_read=0`。

封印后任何输入、容量、epoch、机制、指标或代码变化均产生新源年身份，不允许拼接原封印。
