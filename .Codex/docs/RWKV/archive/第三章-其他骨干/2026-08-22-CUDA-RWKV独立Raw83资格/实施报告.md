## 二、实施计划

### 任务 1：官方供应商快照与独立后端

- 归档固定提交的 `LICENSE`、C++ 和 CUDA 原件，保存逐文件 SHA-256 与 Apache-2.0 身份。
- 新增中性注册文件；官方 CUDA 计算核不改字节。
- 小型容量 `C=112/H=16/T=128`与论文尺寸容量 `C=768/H=64/T=128` 使用独立扩展名、算子命名空间和构建根。
- 后端机械核验源码、编译环境、宏、算子、二进制文件和 GPU 身份，并生成 `cuda_execution_identity_sha256`。

### 任务 2：独立模型

- 实现 R1 的 12 语义组与 R2 同参对照，机械断言 12 组不重不漏地覆盖 `0..82`。
- 实现六输入 CUDA-RWKV 块、PreLN 多层容量、因果前缀模块、实体可学池化和逐流输出头。
- 参数实测必须分别等于小型 R1/R2 `104274/104274`以及论文尺寸 R1/R2 `8977842/9490178`。
- 全部参数保持 FP32，CUDA 核六输入、输出与六梯度固定 BF16，状态与敏感计算保持 FP32。

### 任务 3：训练、评价与断点

- 只通过共享清单和 `purpose=fit/train/validate/target-evaluate` 能力读数据，权重只使用 `train_rows` 聚合收据。
- 实现有效流求和后归一的微批累积，每 20 个完整 `optimizer.step()` 和每轮末原子更新最新断点。
- 首个真实完整优化步检查六梯度、输入适配、每个 CUDA-RWKV 块、输出头和已启用模块的有限更新。
- 评价只写聚合结果：逐流 AP、实体 AP、最大实体 AP、完整共同整数 FP 终端曲线、首次告警曲线、六档锚点与资源；不持久化分数、标签或成员。

### 任务 4：分阶段选择、四格与目标隔离

- S1 只训练 `A/R2/small/C00` 和 `B/R2/small/C00`。
- S2 复用 S1 胜出 R2 的同身份检查点，只新增胜出视图的 `R1/small/C00`。
- S3 复用前一阶段完全同身份小型检查点，只新增胜出视图与适配下的论文尺寸容量。
- 最终 C00 仅在全身份一致时复用；C01/C10/C11 均从种子 42 独立初始化。
- 只用 LSPR23 验证逐流 AP 选轮次和候选；源年三段选择和四格全部封印后，目标年配置和 P6 读取才可达。

### 任务 5：入口、跟踪与启动器

- 配置冻结依赖白名单、供应商身份、容量公式、选择单元、四格、精度、断点、资源、目标门和 SwanLab 尝试合同。
- 入口支持静态配置验证、依赖闭包生成、源年资格、目标年描述性评价和最终在线聚合发布。
- 启动器在读数据前执行依赖、显存、cgroup、磁盘、并发和跟踪健康门；只有首次零步 `401` 才能以新进程进入第二次尝试。
- 不设墙钟、GPU 小时或日历日上限。

## 四、已完成结果

### 4.1 供应商与 CUDA 后端

- 新增 `vendor/cuda_rwkv_official/` 六个文件。`LICENSE`、官方 C++ 和 CUDA 原件分别固定 SHA-256 `c71d239f...15d6`、`f6781ada...2628`和 `a879dd47...bbfb`；CUDA 原件未修改。
- 中性派生注册文件 SHA-256 为 `db73fa2e...30c6`，只通过编译宏注入容量专用算子命名空间。
- `tools/cuda_rwkv_official_backend.py` 固定 `small` 与 `large` 的独立扩展名、算子命名空间和构建根，并把官方源码、派生注册、编译宏、编译器、PyTorch/CUDA、GPU UUID 和扩展二进制文件纳入 `cuda_execution_identity_sha256`。
- `small` 自身门只登记 `703c3d3` 为实现资格输入，`effect_evidence=false`；`large` 首次编译必须执行同类自身门。

### 4.2 模型、训练与断点

- `src/flow_probe/cuda_rwkv_model.py` 实现 12 语义组 R1、同参 R2、六输入 CUDA-RWKV 块、三层 PreLN 容量、因果前缀与实体可学池化。静态公式值分别为 `small/R1=104274`、`small/R2=104274`、`large/R1=8977842`、`large/R2=9490178`；真实构造时还会以 `sum(p.numel())` 再检查一次。
- `src/flow_probe/cuda_rwkv_training.py` 只从共享清单取得 `purpose=train/validate` 能力，流和序列正类权重只使用 `training_weight_aggregate()`。每个完整有效批按真实有效流总数归一，只清梯度一次、裁剪一次、更新一次。
- 首步门检查每层六梯度的 BF16、有限性与非零元素，并分别检查输入适配、每个 CUDA-RWKV 块、输出头和已启用机制的有限更新；关闭的机制位必须零更新。
- 最新与最佳断点只在完整优化步边界原子更新，每 20 步及每轮末保存模型、优化器、调度器、随机状态、采样器、精度、微批、资源、已完成单元和全部身份。任何 CUDA、数据、模型、配置或精度漂移均拒绝续训。
- 运行期每个完整断点检查磁盘与 cgroup；达到停止线时先封口最近断点再中断。不设墙钟上限。

### 4.3 选择、评价与跟踪

- `tools/ch3_cuda_rwkv_raw83_qualification.py` 严格按 S1 `A/B`、S2 `R1/R2`、S3 `small/large` 逐因素执行，选择阶段最多新训练四个单元。S2/S3 和最终 C00 只返回同一检查点路径和 SHA-256；C01/C10/C11 各自从种子 42 初始化。
- 每轮和每阶段只按 LSPR23 验证逐流 AP 选择，完全相等按最早轮次及预注册简单顺序裁决。
- `src/flow_probe/cuda_rwkv_evaluation.py` 在内存中计算逐流 AP、实体 AP、最大实体 AP、完整共同整数 FP 终端曲线和首次告警曲线，不拆并列组、不插值、不持久化分数、标签或成员。
- 只有 S1/S2/S3、四格、代码与评价全部封印且目标读取计数为零，才签发 `source-qualification-seal.json`。目标入口先验该封印，之后才触及 P6 清单。
- SwanLab 只在源年和目标年聚合结果都存在后创建一个最终在线运行。初始化返回后立即写云端 ID 收据；只有首次零步 `401` 返回专用退出码 `91`，才允许新进程执行第二次尝试。

### 4.4 数据与资源硬门

- 配置同时固定 final manifest 文件 SHA-256 `703b3e20...43929`与内容 SHA-256 `93be34eb...7abc`。正式源入口还必须验证 `launcher-product-validation.json`、`status=finished`、`sealed_through_stage=P5` 和 `current-source` 指针内容哈希。消费者只从 final manifest 解析最终路径，不读阶段收据中的发布前路径。
- 启动器在第一个 Python 入口前强制 `OMP_NUM_THREADS=1`，激活项目环境后再次强制。
- 启动磁盘门同时检查配置下限 `25 GiB` 和“全部剩余断点＋扩展/日志＋最大原子临时文件＋`10 GiB`”公式上界。已知 B76 精确可用空间为 `21,235,464 KiB`，约低于当前下限 `4.75 GiB`；它会在任何 `torch` 导入、CUDA 编译或训练前阻断，本任务未清理任何旧制品。

## 七、唯一修订复审结果

### 7.1 不可绕过的资源准入

- 启动器在静态门前以 `mkdir` 原子获取运行锁，锁所有者绑定 `run_id`、动作、唯一令牌和启动器 PID；正常返回、错误退出和信号退出均通过 `EXIT` 清理自己的采样进程与锁。
- source/target 的启动器在锁内原子生成一次性准入收据。收据同时绑定配置文件 SHA-256、依赖闭包文件/内容 SHA-256、600 秒有效期、GPU UUID/名称/显存/计算 PID、cgroup 上限/当前值/可回收页、磁盘完整检查点上界和项目并发进程实测。
- Python `--run-source`/`--run-target` 在任何 `torch`、CUDA 或数据消费导入前必须验该收据、当前锁与启动器祖先 PID，并用 `O_EXCL` 创建消费收据。缺失、过期、身份漂移或已消费都硬失败。
- 采样器在顶层清单哈希前执行 stop/stopped 双收据握手，防止后台追加破坏刚封印的资源文件 SHA-256。

### 7.2 源身份、目标缓存与完成清单

- source 只在依赖闭包不存在时首次生成；既有闭包只校验不改写。target/publish 始终只校验。源封印新增配置 SHA-256、依赖闭包文件/内容 SHA-256、评价代码 SHA-256、资源准入/消费 SHA-256、全部四个选择单元清单和全部四格单元清单。
- 每个训练单元在 `completed/status` 封口后最后写 `unit-manifest.json`，严格列举并反向验训练身份、模型规格、优化器分组、首步六梯度、latest/best 检查点、验证历史、源指标、资源汇总、完成收据、状态以及实际存在的恢复/警告文件。完成快路径必须反向验全部文件数、大小和 SHA-256。
- 每个单元首次启动时持久化全局采样文件的完整行起始偏移和时刻，续训不改起点。单元最终评价后以完整行终止偏移截取字节窗，原子写入单元本地 `resource-samples.tsv`，并用 `resource-window.json` 绑定起止偏移/时窗、全局字节窗 SHA-256 与本地文件 SHA-256。单元资源汇总只读本地切片；后续单元追加全局日志不会改变前一单元制品。数值行、单调时标、行数或字节窗无法机械证明时明确写 `fair_evidence=false`，单元清单验证会阻断资格。source 顶层只聚合已通过该门的单元本地切片。
- target 在首次评价前重算并保存目标 manifest 文件/内容 SHA-256、所有制品闭包 SHA-256 和数据收据 SHA-256。每格缓存同时绑评价代码、依赖闭包、源封印、检查点和单元清单；追加身份/资源后会排除旧哈希并重算规范 `result_sha256`。正常和幂等返回均把业务结果原样放入外层 envelope，action manifest 与幂等 marker 只写 envelope 元数，不再扁平追加到已含 `result_sha256` 的业务对象。任何字段漂移都禁止幂等复用。
- source/target 成功时先写顶层 `status`，再末写动作全文件 manifest；幂等入口先核验状态、生产身份、列举集、大小和全部 SHA-256，不再凭 summary/seal 单文件返回完成。

### 7.3 首次告警、恢复和精度

- 首次告警 path-max 仍输出完整共同整数 FP 曲线：每个预算点保存实际 FP/FPR、DR、阈值、完整并列组、下一可达 FP 和 `unalerted_fraction=1-detection_rate`。及时检出右连续压缩阶梯只对六个预注册共同实际 FP 锚点生成，按锚点阈值去重；阶梯标明 `exposure_index_base=1`、`right_continuous=true`、正实体分母固定和 `anchor_only=true`。六个 anchor 引用阶梯索引与 SHA-256，代码硬断言阶梯数不超过 6、总点数不超过 `6×正实体数`。禁止为所有可达阈值生成二维稠密阶梯，不伪造秒、不拆并列、不插值。
- 覆盖 `training-identities.json`、模型规格或优化器分组前会先读并比对现有身份。无 latest 但有旧首步收据时，只有同身份才记录旧收据 SHA-256、精确删除旧收据并重做首步；身份不可验或漂移则停止。volatile 进度与断点进度的差值记为重复优化步。
- `g` 门函数的第一次矩阵乘、sigmoid 和第二次矩阵乘已全部进入禁 autocast FP32 敏感区；输出才转回当前活性精度，参数仍为 FP32。

### 7.4 SwanLab 终态

- 最终发布仍只调用中央 `initialize_swanlab_run`，不复制目的地、别名、标签长度或第三方初始化逻辑。工具层生产身份另外绑定 config、依赖闭包、评价代码、source/target 完整动作清单、中央跟踪模块、别名文件和最终目的地。
- 成功快路径必须反向验 inflight 与 success 的云端 ID/步数、ping/verify 日志大小与 SHA-256、标签收据文件/合同 SHA-256 以及生产身份。已有 terminal failure 的同一 attempt 不再初始化；attempt2 必须精确绑定 attempt1 的零步 `401`、专用退出码 `91` 与相同生产身份；非预期第三尝试目录直接失败。
- publish 终态先写 `publish-status.json`，最后写 `tracking-manifest.json`。后者是所有 attempt 文件和顶层状态的完整列举/大小/SHA-256 清单，不再复制一份未验的 success 当作清单。
