## 一、为什么先做等参数深度门

现有约 90K 参数的 GRU、跨流全注意力和因果卷积没有超过 XGBoost，不能仅归因于容量不足。LSPR 的 83 个固定语义字段首先构成异质表格轴；树模型的轴对齐分裂更适合非平滑边界和无信息字段，通用时序混合还会与 CPA 重叠并压缩 ELP 的实体峰值差异。现有发布级大 GRU 和大 Transformer 同样没有在实体 AP 上超过 XGBoost，进一步否定“只需增大模型”的解释。

残差表格多层感知机是更小的可证伪改动：保持字段轴、CPA 与 ELP 接口不变，只改变同参数预算下的非线性深度和梯度路径。如果它不能在源年把现有多层感知机的 C11 往 XGBoost-C11 方向推进，就没有理由先付出 TabM 或 FT-Transformer 的额外计算成本。残差深度实验的结论只能是“该固定等参数实例有／无源年资格信号”，不能写成深层网络普遍优于浅层网络。

## 二、候选结构与精确参数预算

### 2.1 共同 CPA/ELP 外壳

所有候选都保留以下接口：

1. 逐流输入 `values: (B,T,83)`，掩码 `valid: (B,T)`。
2. 骨干输出 `hidden: (B,T,d)`；补零位置严格置零。
3. C00 的 `context=zeros_like(hidden)`；C11 的上下文为沿 `T` 轴、含当前位置的因果前缀均值。
4. 将 `[hidden, context]` 送入 `2d -> d` 融合层，再用 `d -> 1` 输出逐流分数。
5. C00 用实体最大值；C11 使用一个共享 `p_log`，按第三章公式训练并按该折学得的 `p` 汇总实体分数。

### 2.2 现有多层感知机参照

- 结构：`83 -> 192` 编码、CPA 拼接、`384 -> 192` 融合、`192 -> 1` 输出。
- 参数量：`90,242`。
- 已有源年 E1 pooled OOF：C00=`0.5109066464488172`，C11=`0.5447784766847485`。
- 参照制品：`runs/diagnostics/ch4-e1-source-entity-oof-gate-seed42-v1/aggregate-results.json` 及其 `manifest.json`。
- 不重训该参照；新聚合器必须核验上述全精度值、六单元完成、三折覆盖和 `target_year_arrays_read=0` 后才能比较。

### 2.3 等参数残差深度网格

“残差 2/4/6 层”专指逐流编码器中新增的残差分支仿射层数，不把输入投影、CPA 融合和输出层计入该名称。每个残差块固定为：

```text
x = x + Dropout(Linear2(Dropout(ReLU(Linear1(LayerNorm(x))))))
```

每块有两个 `d -> d` 仿射层和一个 `LayerNorm(d)`，参数量为 `2d^2 + 4d`。共同外壳参数量为 `2d^2 + 86d + 2`，故含 `B` 个残差块的总参数量为：

```text
P(B,d) = (2 + 2B)d^2 + (86 + 4B)d + 2
```

| 运行键 | 残差块 | 残差层 | 隐藏宽度 | 精确参数量 | 相对 90,242 |
| --- | ---: | ---: | ---: | ---: | ---: |
| `resmlp2` | 1 | 2 | 139 | 89,796 | -0.494% |
| `resmlp4` | 2 | 4 | 115 | 90,162 | -0.089% |
| `resmlp6` | 3 | 6 | 100 | 89,802 | -0.488% |

固定细节：

- 使用预归一化残差；`LayerNorm` 的可训练缩放和偏置计入参数量。
- ReLU、dropout=`0.1`、残差系数=`1.0`，不增加可调门或宽度倍率。
- `LayerNorm` 参数与偏置、`p_log` 不做权重衰减；其余矩阵沿用 `0.01`。该分组在所有三个深度上相同。
- 2 层是首个最小深度门；只有它出现预注册的正向信号才允许启动 4 层。6 层只在 4 层继续改善时启动。

### 2.4 固定 TabM 式候选

本候选是“TabM 式两层参数高效集成多层感知机”，不是对 ICLR 2025 全尺寸默认配置的复现。结构依据官方 `LinearBatchEnsemble` 和独立输出头，固定官方源码提交 `28e47ae301c92ec37787dde1ce923a0793f405b4`，不得运行时下载或导入外部 `tabm` 包。

- 集成成员 `k=4`，隐藏宽度 `d=186`。
- 两个共享权重层分别为 `83 -> 186` 与 `372 -> 186`；每层含成员专属输入缩放 `r`、输出缩放 `s` 和偏置。
- 第一层 `r` 用随机符号初始化；后续缩放初始化为 1；同层成员偏置从同一初值开始；输出使用四个独立 `186 -> 1` 线性头。
- 训练时固定 `share_training_batches=false`：每步仍只编码 64 条序列，重排为 `16 x 4`，每个成员接收不同序列，不能把集成成员数偷换成四倍标签暴露。
- 推理时每条序列展开到四个成员，对四个 sigmoid 概率作算术平均，再进入实体最大值或 ELP；不得在源年比较后改成平均 logits、最大成员或加权集成。
- CPA 在每个成员内部沿时间轴独立计算；ELP 只保留一个共享 `p_log`，不为四个成员分别选幂次。

参数量公式与冻结值：

```text
P(k,d) = 2d^2 + 83d + k(84 + 7d) + 1
P(4,186) = 90,175
```

相对现有多层感知机为 `-0.074%`。选择 `k=4` 是为了在 90K 参数与单卡快速门内保留接近现有 192 的基础宽度，并限制四倍推理成本；这是看到任何源年标签结果前冻结的资源决定。若该实例失败，只否决 `tabm4/d186` 固定候选，不外推为整个 TabM 家族无效。

FT-Transformer 仍是第二备选，但本轮不实现：它需要独立冻结字段令牌维、头数、层数及约 90K 参数解，不能在本轮源年结果之后临时补成新的调参分支。

## 五、预注册的推进、通过与否决门

所有比较使用 JSON 中的全精度浮点值，不设置事后百分点容差。

### 5.1 残差深度顺序门

先运行 `resmlp2`。定义：

```text
depth_gain = candidate_C11_pooled - current_mlp_C11_pooled
xgb_gap = xgb_C11_pooled - candidate_C11_pooled
current_xgb_gap = xgb_C11_pooled - current_mlp_C11_pooled
```

`resmlp2` 只有同时满足以下三项才算“有深度信号”，允许启动 `resmlp4`：

1. `depth_gain > 0`。
2. 三折各自 `candidate_C11 - candidate_C00 > 0`，不存在机制方向翻转。
3. `xgb_gap < current_xgb_gap`，即相对现有多层感知机确实缩小到 XGBoost-C11 的源年差距。

任一不满足，立即停止 `resmlp4/resmlp6`，记录 `reject_residual_depth_family_at_resmlp2`。这是否决当前预注册深度路线，不是证明所有深层多层感知机无效。

`resmlp4` 只有同时满足以下三项才允许启动 `resmlp6`：

1. `resmlp4_C11_pooled > resmlp2_C11_pooled`。
2. 三折各自 `resmlp4_C11 - resmlp4_C00 > 0`。
3. `resmlp4` 到 XGBoost-C11 的差距严格小于 `resmlp2`。

任一不满足，停止 6 层并记录 `stop_depth_escalation_at_resmlp4`。若 6 层被启动，其结果照报，不再增加 8 层或新宽度。

### 5.2 单候选源年资格通过门

残差候选或 TabM 式候选只有同时满足以下条件，才记为 `source_qualified`：

1. C11 pooled OOF 实体 AP 严格高于同折 XGBoost-C11 pooled OOF。
2. C11 pooled 严格高于自身 C00 pooled。
3. 三折各自 `C11-C00 > 0`。
4. 三折中至少两折的候选 C11 严格高于对应折 XGBoost-C11。
5. 参数量、六训练单元、实体覆盖、本次五数组与多层感知机 E1 的输入哈希、上述 XGBoost 基线身份、资源收据与零目标年读取全部有效。

通过后立即冻结该候选，不再利用源年尝试别的宽度、成员数、归一化、激活、学习率或聚合方式。若两个候选都通过，源年不负责从中挑一个；二者只能在新的独立漂移域按预先冻结协议比较。

### 5.3 科学否决与运行无效分开记录

**科学否决：**完整有效运行中，C11 不高于 XGBoost-C11、C11 不高于自身 C00、任一折机制增量不为正，或少于两折超过 XGBoost，任一项即 `source_rejected`。

**运行无效：**读取目标年数组、折交叉、少于六个完成单元、参数量超出 `±1%`、父基线身份不符、非有限指标、检查点/哈希不匹配、CUDA 静默退回、标签或指标实现错误。运行无效不得解释为模型失败；修复只能恢复冻结合同，不得改变架构或超参数。看到任何有效源年指标后，不得借“修复”改模型。

**工程否决：**在满足资源准入后，固定候选仍无法完成一个训练单元，或峰值超出单卡安全预算且不存在不改变科学合同的分批推理方式，记为 `engineering_rejected`；不得看结果后缩宽度或减少成员数。

## 六、资源估计与 GPU 要求

真实门必须使用服务器 GPU。本机数据规模超过 1,600 万流和 1 GiB，禁止本机启动。估计依据是既有 E1 六单元约 `0.5-1.0` GPU 小时及等参数乘加量；以下均是启动前工程估计，不是实测：

| 候选 | 六单元估计 GPU 时间 | 主要额外成本 | 预计峰值显存 |
| --- | ---: | --- | ---: |
| `resmlp2` | 0.6-1.2 GPU 小时 | LayerNorm 与残差保存 | 10 GiB 内 |
| `resmlp4` | 0.6-1.2 GPU 小时 | 深度增加但宽度降为 115 | 10 GiB 内 |
| `resmlp6` | 0.6-1.2 GPU 小时 | 深度增加但宽度降为 100 | 10 GiB 内 |
| `tabm4` | 0.9-1.8 GPU 小时 | 留出推理展开四成员 | 12 GiB 内 |

- 最小首门仅 `resmlp2`：`0.6-1.2` GPU 小时。
- 残差三档全部被顺序开通：累计 `1.8-3.6` GPU 小时。

- 若资源门允许两个训练单元并行，墙钟可能低于 GPU 小时之和，但不得在真实资源收据前承诺加速比例。
