# C56 远程门禁误用系统 Python 记录

- **日期**：2026-08-12
- **影响阶段**：候选 B、C12-R 与 LSPR 完整基线矩阵启动前的集中门禁
- **科学影响**：无。错误发生时三个实验均未启动，未产生部分训练、指标或结果制品，最终区未访问。

## 现象

主进程在远端集中门禁中使用裸 `python -m json.tool` 解析四份配置。C56 不提供系统级 `python` 命令，因此命令以 `python: command not found` 退出。该命令启用了 `set -euo pipefail`，失败后立即停止，后续三个启动入口均未执行。

## 根因

项目已经明确使用 `uv` 和项目虚拟环境，但临时拼接的主进程门禁没有复用项目统一入口，错误地假设系统级 `python` 存在。这是执行入口选择错误，不是依赖缺失、配置损坏或实验代码故障。

## 修正与验证

1. 将配置解析和模块导入统一改为 `uv run --no-sync python`。
2. 四份配置解析通过。
3. `torch`、`transformers`、`scikit-learn`、`xgboost`、`swanlab` 及三个实验模块导入通过。
4. 候选 B、C12-R 和完整基线矩阵随后分别进入独立 `screen`。
5. 首次有效运行核验显示 `final_accessed=false`，没有重复启动或沿用部分运行目录。

## 防复发规则

- 在 `llm_probe` 项目根内执行 Python、模块入口、配置解析、导入检查或一次性诊断时，统一使用 `uv run --no-sync python`。
- 禁止通过裸 `python`、`python3` 或系统解释器探测来决定项目依赖是否存在。
- 远端启动器和主进程临时门禁必须复用同一项目环境入口；环境入口失败时停止并报告，不得临时回退到系统解释器。
