## 1. 结论

**RWKV/Mamba 的 `nvcc`/PATH/`ninja`/PyTorch CUDA 扩展发现前置阻塞已解除，但不等于 RWKV、Mamba 或 `causal-conv1d` 官方源码已经构建成功。**

服务器镜像在本任务前已安装 `cuda-compiler-13-0=13.0.3-1` 和 `cuda-libraries-dev-13-0=13.0.3-1`，`nvcc` 绝对路径已存在。原问题是默认 PATH 未包含 CUDA `bin`，而不是缺少编译器软件包。

最终方案不保留 NVIDIA APT 源或系统 profile，也不保留 Ubuntu `ninja-build`。项目级环境收据显式设置：

```bash
export CUDA_HOME=/usr/local/cuda-13.0
export VIRTUAL_ENV=/root/autodl-tmp/thesis/experiments/llm_probe/.venv
export PATH="$VIRTUAL_ENV/bin:$CUDA_HOME/bin${PATH:+:${PATH}}"
export LD_LIBRARY_PATH="$CUDA_HOME/lib64${LD_LIBRARY_PATH:+:${LD_LIBRARY_PATH}}"
```

在该环境下，项目 `.venv` 的 `ninja 1.13.0` 成功调用 CUDA 13.0 `nvcc`，以 `-arch=sm_120` 编译、链接并运行了独立 CUDA 小程序。GPU 结果为 42，PyTorch 继续识别 CUDA 13.0 和计算能力 `12.0`。

## 8. 剩余兼容风险

1. **官方源码尚未实编**：本次只证明 CUDA 13.0、`sm_120`、项目 `ninja` 和 PyTorch CUDA 路径可用。RWKV CUDA 核、Mamba 与 `causal-conv1d` 仍可能因源码宏、PyTorch 接口、C++ ABI 或 `sm_120` 假设失败。
2. **正式 `.venv` 仍缺少 `wheel`**：2026-08-06 复核的 `importlib.util.find_spec("wheel")` 为 `None`。若上游 PEP 517 构建硬依赖 `wheel`，需先按冻结依赖合同补齐，不得批量升级现有环境。
3. **存在既有 OpenMP 环境警告**：登录 Shell 的 `OMP_NUM_THREADS='0'`，某次 PyTorch 导入触发 `libgomp` 无效值警告。本任务没有修改该既有配置，但正式编译或 CPU 基线前应单独处理。
4. **项目环境需显式加载**：系统默认 PATH 不保证命中 `nvcc`。后续构建包装器必须先加载 `cuda13-runtime.env.sh`，或等价地注入同样的冻结变量。
5. **服务器可回收**：服务器重启、切换或回收后，必须重新核验预装 CUDA 目录、驱动、PyTorch、GPU 能力和制品哈希，不得沿用本次运行事实。
