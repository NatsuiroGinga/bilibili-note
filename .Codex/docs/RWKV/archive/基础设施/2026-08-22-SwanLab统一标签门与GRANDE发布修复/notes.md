# SwanLab 统一标签门与 GRANDE 发布修复笔记

## 已核事实

- RWKV 第三章恢复卡与跨进程看板一致记录：GRANDE G-A 已完成；G-B 已完成 20 轮、20000 个优化步，选中第 9 轮，选中检查点 SHA-256 前后缀为 `fa695ee5...ac15`。
- 父运行失败发生在最终 SwanLab 发布阶段，触发标签为 `same-precision-selection`，按 Unicode 码点长度超过 20；训练和骨干选择不需要重做。
- 故障手册已规定最终动态标签逐项不得超过 20 个字符，且 SwanLab 0.9.0 的新正式在线运行前必须执行 `swanlab ping` 与 `swanlab verify`。
- 修复前 `tracking.py` 会把非字符串标签通过 `str()` 静默转换，只检查单标签长度，不检查总数、重复、NFC 冲突、别名单射、环境漂移，也没有可复用的标签收据。
- 现有 GRANDE `publish_aggregate` 直接调用 `swanlab.init`，且会在发布前原地改写父 `source-screen-results.json`；这不符合本次只读保留父运行和失败证据的边界。
- 项目锁定 SwanLab `0.9.0`。Context7 查询未返回可用文本，因此本次只复用仓库中已存在且与锁定版本运行过的 `init`、`log`、`finish` 调用形态，不访问未核验属性。

## 根因假设

最终标签构造和 SwanLab 初始化分散在各工具中，配置校验没有消费与运行时完全相同的标签结果，因此静态配置可通过、动态发布仍失败。把最终标签规范化、目的地验证、环境漂移拒绝和收据生成集中到同一纯函数，并要求新发布入口只经统一初始化函数，可在创建云端运行前机械阻断同类故障。

## 设计决定

- 别名表是显式一对一映射；别名自身也必须满足全部标签规则，两个原标签不得映射到同一有效标签。
- Unicode 长度使用 Python `len()`，对应 Unicode 码点数量；不按字节或字素簇计数。
- NFC 只用于冲突检测和收据，不静默改写最终标签；非 NFC 原标签必须通过显式别名映射。
- `SWANLAB_TAGS` 未设置时通过；设置时仅接受与最终有效标签按相同顺序、JSON 列表或逗号分隔形式完全一致的值。
- 全仓直接初始化迁移不在本次文件所有权内；扫描器必须把剩余入口作为阻断清单公开。
- 发布修复输出独立于父运行目录，父运行的失败状态、日志、配置和制品保持逐字节不变。

## 修订复审结果

- 父生产配置和冻结配置分别绑定不同 SHA-256，并机械断言 JSON 深度全等。
- 父 manifest 的 23 项文件完成反向核验；只允许结果、资源和状态三项已核历史后置漂移。
- `source-screen-results.json` 与 `grande-c00-source-results.json` 都保留 `launcher_admission_receipt`；前者 22 键、后者 15 键。差异精确为 7 个训练完成后资源键，共同键值全等，前者完整收据与当前 `resource-receipt.json` 全等。
- 完成态只有在 `publish_completed=true`、全部登记文件和五个生产身份文件通过哈希复核后才幂等返回。
- 首次零步初始化 401 的第二次尝试固定为全新 Python 进程；非 401 和第二次失败均停止。
- 真实扫描覆盖 98 个 JSON 和 102 个 YAML 文件、131 个 `swanlab`/`tracking` 节点；有效 106、非法 0、未决 25。
- 独立审查基线有 53 个直接初始化入口；并行任务迁移 1 个后，最终扫描为 52。本任务未迁移旧入口。
- 三项预注册违规别名均被真实配置命中：`official-pytorch-postpaper`、`same-precision-selection`、`cuda-fused-numeric-variant`。
