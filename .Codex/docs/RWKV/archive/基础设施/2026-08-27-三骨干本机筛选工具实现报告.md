## 三、Model 类的“import 复用”如何做到（验收第 1 条）

`ch3_backbone_protocolA_v2.py` 没有 `if __name__ == "__main__":` 守卫：argparse 在模块顶层解析
（第 109 行），LSPR23 六数组在模块顶层用硬编码服务器路径加载（第 93-94 行 `ROOT=
"/root/autodl-tmp/..."`，第 271 行起 `np.load`），`Model` 类反而定义在这些顶层语句**之后**
（第 502-578 行）。裸 `import` 该模块会先因缺 `--backbone` 报错退出，即便绕过也会在 `np.load`
里因服务器路径本机不存在而崩溃——且都发生在 `Model` 类被定义之前。

`import_protocolA_v2_reused()`（工具文件第 193-255 行）用以下受控方式做到真实 import 而非
复制重写：

1. `importlib.util.spec_from_file_location` 按磁盘路径构造模块对象，自己持有引用，不经
   `import` 语句、不写 `sys.modules`。
2. 临时接管 `sys.argv`，传入 `--cells ""`（空格集合）。源码里 `CELL_SEL/CELLS` 由此变成空
   列表，`len(CELLS) < len(ALL_CELLS)` 恒真，源码第 833-839 行会在“阶段闸门”之前干净
   `raise SystemExit(0)`——闸门之前从不触碰 LSPR24，四格训练循环也不会执行。
3. 临时把 `numpy.load` 重定向到本机真实缓存目录（源码硬编码前缀是服务器路径，本机不应该
   在文件系统里伪造这个绝对路径）。
4. `exec_module` 期间只捕获 `SystemExit(0)`；发生在 `Model` 类定义（502-578 行）与训练循环
   入口（833 行）之间的这次退出，不会撤销退出前已执行的顶层语句——`Model`、`RWKV7TimeMix`、
   `lp_pool`、`npar_formula`、`hid_of`、六个 LSPR23 数组、切分、损失权重全部已写入
   `module.__dict__`。退出后立刻断言 `module.__file__ == PROTOCOL_A_V2_PATH`。
5. 复用完毕立刻恢复 `sys.argv`、`numpy.load`。

**运行时实测证据**（而非静态推断）：两次 `--smoke-test` 真实调用均打印

```
import 复用成功：module.__file__=/Users/.../tools/ch3_backbone_protocolA_v2.py，
module.Model=<class '_ch3_backbone_protocolA_v2_reused_for_local_screen.Model'>（确系同一份代码，非复制重写）
```

且顺带真实跑了一次 `_impl_verify()`（源文件自带的合成数据掩码决定性/因果性检查）：
transformer 与 gru 的掩码决定性、补零位输出、因果性三项均为 `0.000e+00`（判据 `<1e-6`/`=0`），
五个骨干的参数量公式与 torch 实测全部一致（mlp 90,242 / gru 90,134 / transformer 90,631 /
cnn 91,082 / rwkv7 91,730）。收据落在

## 五、协调者 2026-08-27 续接指令的落实

协调者指出本骨干池选轮指标（逐流 AP）实测已饱和（格间差 `3.39e-06` < 格内波动 `6.37e-06`），
要求**仍按原冻结选轮规则实现**（未更换指标），但每格收据额外持久化逐轮验证逐流 AP 序列，
并在成本允许时加逐轮源年实体 AP。落实方式：

- 新增 `evaluate_epoch()`（工具文件第 328-379 行）替换原先分离的两个评价函数，**单次前向**
  同时算出 `flow_ap`（真正驱动 `if val_ap > best["ap"]` argmax 选择的信号，未改动选择规则）
  与 `entity_ap`（源年实体 AP 代理，纯诊断）。这是效率设计：不合并会让每 epoch 对 22,444 条
  验证序列多扫一遍，合并后只多算一次实体聚合（numpy 向量化 `np.maximum.at`，代价可忽略）。
  验证集本身的前向计算量相对每 epoch 1000 步的训练前向+反向而言是小头，因此“成本允许”。
- `train_cell()` 的 `history` 现在每 epoch 一条字典：`epoch/validation_flow_ap/p/
  source_year_entity_ap/source_year_entity_ap_n_entities`；`best` 同时记录选中 epoch 的
  `entity_ap`/`entity_ap_detail`。
- `lr_select_stage()` 的每条 duel、`cells_stage()` 的每格结果都携带完整 `epoch_history`，
  供事后诊断选轮盲区；`cells_stage()` 不再需要重建模型重跑一遍评价（直接复用
  `payload["entity_ap"]`），比早期设计更省一次全量前向。

## 六、源年实体 AP 代理口径（判据用指标，与正式口径的差异）

`evaluate_epoch()` 文档字符串完整登记：正式判据用的 `ent_ap()` 按 LSPR24 的 `s24/d24` 拼出
流级实体键聚合流级分数；LSPR23 缓存只暴露序列级实体号 `E23`（切分用途，非逐流实体键），
本工具改为两级聚合代理——序列内按 `agg,lp` 语义池化成序列级分数（lp=True 用模型自身学到的
p 做 Lp 池化，即 ELP 机制本身；lp=False 取序列内最大值，与正式 `ent_ap` 的 max 口径一致），
序列间按同一实体（`E23` 相同）取多条验证序列分数与标签的最大值。`criterion.note` 与
`entity_ap_metric` 字段都固定标注 `source_year_proxy`，防止与正式判据数字混用。

## 八、遗留状态与建议顺序

- `runs/diagnostics/ch3-backbone-2x2-local-screen-v1/transformer/lr_selection.json` 已就绪
  （`selected_lr=0.002`），可直接执行 `--backbone transformer --stage cells --device auto`

- 断点续训：`train_cell()` 逐 epoch 落 `inflight.pt`（含模型/优化器/RNG 状态），逐格完成落
  `selected.pt`；`lr_selection.json`/`ch3_backbone_2x2_local_screen_results.json` 存在即视为
  该阶段完成并幂等跳过，符合实施计划“逐格完成即落盘，重入幂等跳过已完成格”的要求。
- 已知放松：MPS 算子（如 Dropout）内部随机状态未单独快照（torch 2.13.0 未公开逐设备 MPS
  RNG 状态 API），screening_only 场景下可接受，断点恢复后不保证逐位相同，只保证训练能继续
  推进，已在 `rng_restore()` 注释中登记。
