# GRANDE 运行上限撤销说明

## 结论

用户已明确要求 GRANDE 协议 A 源年 Q0 不设置运行时长或累计 GPU 小时上限。本说明撤销既有实施计划中的工程停止条件，不改变本次运行身份、数据、模型、训练预算或指标合同。

## 已撤销的停止行为

- Python 不再因累计 GPU 小时达到阈值而中止 G-A 或 G-B。
- R1 完整周期仍记录实际用时和投影值，但仅作资源观测，不再否决 G-A 或阻止 G-B。
- 启动器不再按 R1 投影跳过 G-B，且不再设置外部超时限制。
- 运行和聚合结果不再写入 GPU 小时上限字段；累计 GPU 小时继续作为实际资源指标记录。

## 保持不变的合同

- `run_id=ch3-grande-c00-protocolA-source-q0-seed42-v1` 保持不变；该运行尚未启动。
- G-A 与 G-B、每个结构 `20` 个周期和每周期 `1000` 步均保持不变。
- 逐流 AP、实体 AP、最大池化实体 AP、六档检测率、完整告警预算曲线、梯度诊断和资源采样均保持不变。
- 启动准入继续要求至少 `12 GiB` 可用显存、`30 GiB` 可用控制组主存和 `10 GiB` 可用磁盘；并发度固定为 `1`。
- 检查点、优化器状态、随机状态和恢复校验保持不变。

## 验证范围

本次仅执行本地配置、Python 语法与入口、Shell 语法检查；未启动远程实验，未读取 LSPR24 数组。
