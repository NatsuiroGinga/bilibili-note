# N-15/N-16 SwanLab 单运行恢复修复计划

## 目标

只修复 N-15 与 N-16 最终聚合发布的 SwanLab 生命周期和幂等恢复，不改变模型、分数、共同整数 FP 预算、首次告警、年度隔离或科学裁决。

## 根因

1. 两个工具都在最终阶段创建一个在线 SwanLab 运行，但没有冻结云端初始化尝试状态。
2. 若 `finish()` 成功后、本地收据或最终清单落盘前中断，重启会再次调用 `init`，产生重复云端运行。
3. 初始化 `401` 没有按故障手册保留首次失败证据、以全新 Python 进程重新执行 `ping`/`verify` 并只重试一次。
4. 现有完成幂等主要依赖最终 `manifest.json`，不能处理“云端已完成、本地清单未封口”的中间状态。

## 冻结实现接口

- 首次零步 `init 401` 使用专用退出码 `91`；其他失败保持非 `91`。
- 尝试证据统一进入 `swanlab-attempts/attempt-1` 或 `attempt-2`，健康门、标签、在途、失败和成功收据均逐项哈希登记。
- `init` 返回后第一项本地写入必须是包含云端运行 ID 的原子 `inflight-receipt.json`；没有合法 `success-receipt.json` 的在途状态一律拒绝再次初始化。
- 第二次尝试只由启动器在收到首次退出码 `91` 后执行；它重新运行健康门并用新的 `uv run --no-sync python` 进程调用 `finalize`。
- 合法成功收据存在但清单缺失时只完成本地顶层收据、状态和清单，不调用 `initialize_swanlab_run`。
