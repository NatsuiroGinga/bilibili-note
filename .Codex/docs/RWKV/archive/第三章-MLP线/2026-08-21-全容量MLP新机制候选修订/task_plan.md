# 全容量 MLP 新机制候选修订计划

## 目标

基于全容量 MLP BF16 的最新严格分析结果、RWKV 第三章冻结合同和已核验全文证据，撤销三折、OOF 与交叉验证设想，将第三章新机制压缩为最多两个可证伪主候选，并给出从 S0 零训练诊断到 S1/S2 快速实验的唯一推荐路径。

## 任务边界

- 文件所有权仅限本目录的 `task_plan.md`、`notes.md` 与 `候选与快速实验.md`。
- 不修改旧机制审计、路线总控、第三章恢复卡、实验代码、配置或运行制品。
- 不访问服务器，不启动实验，不把当前 LSPR24 结果用于机制参数选择。
- 使用固定的 LSPR23 实体不相交开发划分与 S0/S1/S2 合同；撤销新增三折、OOF 与交叉验证。
- 本轮只形成设计与快速实验合同；没有新运行制品的判断标为“实验待证”。

## 关键问题

1. O11 的实体级排序改善与逐流迁移失败，究竟主要来自 BF16/FP32 数值量化，还是概率空间池化导致的排序病灶？
2. 完整实体概率、严格过去完整候选、ForkMerge/分支过滤三条线中，哪些已有支持、哪些已被否决、哪些只剩交互线索？
3. 如何保证所有机制选择只读取 LSPR23，而 LSPR24 只用于提出目标域病灶假设与最终冻结评价？
4. 最小两臂实验如何同时报告实际可达 FPR 曲线与首次告警实际 FPR，避免把名义 4% 当成实际 4%？

## 决策记录

- 用户任务简报已明确研究目标、数据边界、候选方向、文件范围和验收条件，视为本轮设计范围确认，不另行扩张需求。
- 严格遵守固定 LSPR23 实体不相交开发划分和 S0/S1/S2 分级，不新增三折、OOF 或交叉验证。
- S0 优先比较 BF16/FP32 推理，以及概率空间与对数几率空间聚合；S0 未能区分病灶时不进入复杂机制训练。
- 完整实体幂平均降为 S0 对照；严格过去 CPA 的完整候选保持源年否决；ForkMerge 启发的共享辅助更新过滤升为第二主候选。
- 第一主候选为流头不变的独立因果实体排序头，先以冻结 B10 骨干执行 S1 双臂筛选。
