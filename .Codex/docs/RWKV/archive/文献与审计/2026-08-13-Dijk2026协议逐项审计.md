## 一、Dijk 2026 协议原文

### `sample_pool`

【Dijk 从未报告评价样本池的流数与正类数——这是最关键的空白】

1) 全文唯一给出的池规模是表 8 的「Train seq.」（训练序列数）与 π，没有任何验证/评价池的流数、序列数或正类数。表 8 标题（提取文件行 2887-2891，印刷第 36 页）：「Sequence dataset overview by evaluation dataset and sequence construction strategy. π: positive class ratio. Train seq.: number of training sequences.」

2) 池的构造链（§5.8「Dataset Preparation and Splitting」，行 1792-1817，印刷第 23-24 页）：
   - 「The dataset was partitioned into training and validation sets」——**只有 train/validation 两分，全文没有独立测试集**。
   - 「Train and validation splits were performed at the sequence level based on unique grouping keys (conn_key), ensuring that no sequence—and therefore no flow belonging to the same grouping key—appears in both splits.」——**按分组键切分，不是按时间切分**。
   - 「To mitigate extreme class imbalance in validation data, we applied a controlled stratified sampling procedure at the sequence level with a fixed random seed (42).」——**验证集被有意做了序列级分层采样以缓解不平衡**，这就是阳性率被「诱导」抬高的直接机制。
   - 全文未给出 train:val 比例，也未给分层采样的保留率。

3) 对 XGBoost 没有行数截断。§5.6，行 1761-1763，印刷第 23 页：「No explicit cap was imposed on the number of training or validation rows (xgb_max_train_rows=0, xgb_max_val_rows=0).」对比我方 role_row_limits 四角色全部 = 262144（硬截断）。

4) 神经模型侧有训练预算截断（不是评价池截断）：limit_train_batches=1000，max_steps=5000（transformer）/20000（GRU），max epochs 50（表 2，印刷第 20 页；§5.9 行 1846-1858，印刷第 24 页）。表 8 的 Cov./epoch 与 Passes/epoch 就是这个预算下的覆盖率。

5) 规模量级对比（可推算，非原文直给）：LSPR24 在 OP 构造下 Train seq. = 126,421，p50/p90/p99 全 = 128，故训练侧覆盖约 126421×128 = 16,181,888 条流。我方 target-development 池 = 261,839 条流，**相差约 61.8 倍**。

6) 原始数据集真实阳性率的交叉参照（不来自 Dijk，来自同族文献 Leoste 2025，`raw/papers/datasets/LSPR24/2025_Leoste_Comparative_Analysis_ML_DL_LSPR23_LSPR24.pdf`，pdftotext -layout 行 3112-3115，印刷第 83 页）：「The LSPR24 dataset is larger and more imbalanced, comprising 20,227,356 flows, with benign flows constituting approximately 97.43% of the total (19,707,365 flows), and malicious flows accounting for only 2.57% (519,991 flows).」
   实算：519991/20227356 = 0.02570731439146075。
   → Dijk 的 0.0707 是 LSPR24 原始逐流阳性率的 **2.7502 倍**；我方 0.0077147 是原始阳性率的 **0.3001 倍**。两边都偏离原始基率，方向相反。

【结论】评价样本池是本次不通过的最大嫌疑点，但 Dijk 全文不足以复原他的池：他既没给池大小，也没给分层采样的保留比例。

### `splits`

训练/验证两分，**无测试集**，**单一划分、无多种子**。

- 切分单元：序列级，按唯一分组键 conn_key（§5.8，行 1796-1798，印刷第 23 页）。同一 conn_key 的所有流不跨切分，防泄漏。
- 验证集另做「controlled stratified sampling procedure at the sequence level with a fixed random seed (42)」（行 1808-1810，印刷第 24 页），目的明写为「To mitigate extreme class imbalance in validation data」。
- **不是时间切分**。全文没有任何「按时间顺序切前 X% 作训练」的表述；OP 只是把全体流按时间排序后切块，与 train/val 划分是两回事。
- 只有一次划分。§5.11，行 1968-1978，印刷第 26 页：「The reported bootstrap intervals therefore quantify evaluation uncertainty conditional on the chosen train/validation split, but do not capture split-to-split variability. This single-split design is a limitation of the present study... repeating all experiments across multiple random seeds was computationally prohibitive within the available budget of 1,608 GPU-hours.」
- 跨年度设置是**零样本迁移**：模型在 X 年训练，直接在 Y 年评价。证据一：表 6（印刷第 33 页）第一列表头即「Train / Eval.」，取值形如「23 / 23」「24 / 25」。证据二：表 5 中 LSPR23→24 的 XGB「AP next」= 0.2416，而表 3（印刷第 27 页）中在 LSPR24 上训练评价的 XGB AP = 0.9923，两者不同，说明 AP next 不是重训值。
- 「fair-selection」含义（行 2419-2424，印刷第 30 页）：「configurations are selected based on their performance on a same-year dataset and subsequently evaluated on the next available year.」
- 全文未给 train:val 比例，未给随机划分与分层采样的保留率。

【与我方对比】我方是**时间切分**：source-train 截至 1678360570000000000 ns，source-validation 在其后（收据 splits.algorithm = ceil-active-second-rank-v1）。后果已在收据中可见：source-train 逐流阳性率 = 0.07740604917328904，source-validation = 0.4934690389721366，两者相差 6.4 倍——因为 Locked Shields 前一天是无攻击的熟悉阶段（Dijk 印刷第 7 页行 548-550：「two operational days: a familiarisation phase without active attacks, followed by an attack phase」）。Dijk 的 conn_key 随机切分让训练集覆盖两个阶段，我方的时间切分让训练集主要落在熟悉阶段。这是与「评价池定义」并列的第二个重大协议差异，且直接影响模型能力而非只影响分母。

### `sequence_construction`

【八种策略，统一五步框架】§4.1「Generic sequence-construction framework」，行 754-760，印刷第 10 页：
(i) assign each flow to one or more grouping keys; (ii) collect flows per key; (iii) sort each group chronologically; (iv) optionally split each ordered group into sessions using an inactivity threshold ∆; (v) partition each resulting ordered list into chunks of length at most L.

**分块不重叠**：原文用 partition（划分），得到的是 contiguous 非重叠块；行 813-815「each resulting ordered list is transformed into sequences using the chunking operator Chunk_L(G_u)」。全文没有任何 stride / overlap / sliding-window 的分块描述。

**序列长度 L = 128 条流**（表 2，印刷第 20 页：「Maximum sequence length (L) 128 flows」；§5.4，行 1663-1668，印刷第 22 页：「the chunk size was fixed to L = 128 flows, so the maximum sequence length in all experiments was 128 by design. Sequences shorter than L were padded, and padding positions were excluded from model computation and evaluation where applicable.」）。

**会话不活动阈值 ∆ = 300 秒**（表 2，印刷第 20 页；§4.1，行 766-770，印刷第 10 页）。注意：正文第 18-19 页的玩具示例用 ∆ = 60 s，仅为图解，非实验取值。

**八种策略与分组键**：
- OP（Original Position，§4.1.1，印刷第 11 页）：Φ_OP(f) = {1}，所有流归入一条全局时间流，按时间排序后切 128 块；不做会话切分。并列断点用原始行序打破。
- 5-T（5-Tuple，§4.1.2，印刷第 12-13 页）：canonical 双向 5 元组（IP 对与端口对各自字典序排序 + 协议）；不做会话切分。
- 1-IP（§4.1.4）：**每条流同时归入源 IP 与目的 IP 两个组**（Φ_1IP 返回两个键），即流被复制。
- SesIP（1-IP-Session）：1-IP 基础上按 ∆ 切会话。
- 2-IP（§4.1.5，行 1035-1064，印刷第 14 页）：χ(a,b) = sortlex{srcIP, dstIP} = (p,q)，Φ_2IP(f) = {χ(...)}，**每条流恰好一个无向 IP 对键**；不做会话切分。这与我方 group_key_ref_2ip_undirected_keyed 语义一致。
- Host（1-Hostname，§4.1.6，印刷第 15-16 页）：Φ_Host(f) = {ρ_src(f), ρ_dst(f)}，**同样把流复制到两个端点组**。
- SesH（1-Hostname-Session，§4.1.7）：Host 基础上按 ∆ 切会话。
- 2-H（2-Hostnames，§4.1.8，印刷第 16 页）：无向 Expoid 对，每流一个键。

**ρ 映射（hostname 系列专用，印刷第 15 页，行 1105-1120）**：
  ρ_src(f) = SrcExpoid(f) if SrcLabel(f)=0 else SrcIP(f)
  ρ_dst(f) = DstExpoid(f) if DstLabel(f)=0 else DstIP(f)
即**分组键的构造读取了端点标签 SrcLabel/DstLabel**。作者在第 39 页辩称「the ρ mapping does not use flow-level malicious/benign labels; it uses infrastructure-role metadata」，但公式字面上就是用 Label。我方 FORBIDDEN_FIELDS 明确禁用 Label_src、Label_dst、Expoid_src、Expoid_dst，所以 2-H/Host/SesH 在我方合同下不可复制。

**AP 算在逐流单元上，不是逐序列**（§5.3「Flow-Level Classification and Loss」，行 1674-1682，印刷第 22 页）：「Classification is performed at the flow level: a shared linear layer is applied independently to each token embedding, yielding one logit per valid flow. Sequence padding positions are masked and excluded from both loss computation and metric evaluation. Predictions therefore correspond to individual flows within structured sequences rather than to aggregated sequence-level labels.」
以及 §5.11，行 1960-1964，印刷第 26 页：「Although predictions are generated at the flow level, performance metrics (AP, AUROC, F1, Precision, Recall, Accuracy) were computed over the aggregated set of flows in each bootstrap sample.」

**表 5 的 XGBoost 行与序列构造无关**：表 5 标题末句「XGBoost does not use sequence construction.」（行 2376-2377，印刷第 30 页）；§5.6 行 1748-1751：「flows are treated independently without sequence modelling; Original Position is used only as the corresponding baseline representation.」所以 0.2416 是纯逐流指标，可与我方 flow_ap 直接对位——**前提是评价池相同，而这正是不成立的地方**。

### `feature_budget`

【Dijk = 83 维；我方 = 155 维，但基础字段是 77 个，差额恰好是 6 个我方禁用字段】

Dijk 侧：
- §5.8，行 1817，印刷第 23 页：「The complete list of the 83 used input features is provided in Appendix A.」
- 附录 A（提取文件行 3924-3968，印刷第 48 页）逐条列出。我按项枚举实算 = 83，与正文自称一致：
  6 + 4 + 8 + 4 + 5 + 5 + 4 + 2 + 2 + 5 + 8 + 4 + 6 + 4 + 4 + 8 + 2 + 2 = 83。
- 全部来自 CICFlowMeter 数值特征 + 4 个位置指示（L3/L4 Protocol、Int/Ext Dst IP、External_src、External_dst）+ SrcPort/DstPort/Protocol。
- 印刷第 9 页（行 656-668）自述：「Raw identity-like identifiers, including IP addresses and hostnames, are not used directly as model inputs... together with coarse non-identity indicators such as External_src, External_dst, and Int/Ext Dst IP... we additionally verified through feature-level leakage checks that they do not deterministically encode the malicious label.」

我方侧（配置 `/Users/bilibili/personal/note/thesis/experiments/llm_probe/configs/crossyear-entity-eval-q0-seed42-v1.json`）：
- features.definition = "x_value(77)+x_missing(77)+log1p(max(delta_t_us,0))"，dimension = 155。
- 77 个基础字段清单在 `/Users/bilibili/personal/note/thesis/experiments/llm_probe/tools/lspr24_g0/src/lspr_crossyear.rs` 行 47-121（COMMON_FIELDS）。

**逐条比对结论（实算，非推测）**：83 − 77 = 6。Dijk 有而我方 COMMON_FIELDS 没有的，恰好是 6 个：SrcPort、DstPort、L3/L4 Protocol、Int/Ext Dst IP、External_src、External_dst。这 6 个字段**全部出现在我方 FORBIDDEN_FIELDS**（同文件行 127-151，共 24 个禁用字段）。其余 77 个 CICFlowMeter 数值字段两边完全一致（含 Flow IAT / Fwd IAT / Bwd IAT 全部 14 个 IAT 特征）。

**这一差异不可忽略**：LSPR 的标签定义就是「源或目的 IP 属于红队基础设施」，而 External_src / External_dst / Int/Ext Dst IP 是由演习基础设施推导的网络位置指示，与红队 IP 的相关性极高。Dijk 只做了「不确定性地编码标签」的检查（not deterministically encode），没有做互信息或跨年度稳定性检查。我方按合同禁用这 6 个字段，因此**即使评价池对齐，我方 flow_ap 也不应期望等于 0.2416**。

我方多出的两部分（77 个缺失指示 x_missing + 1 个 log1p(delta_t_us)）是 Dijk 没有的；Dijk 未说明缺失值处理方式（正文只说 normalisation，未提 NaN 策略）。

### `label_definition`

【逐流二值标签，基于红队基础设施 IP；无删失处理】

- 印刷第 8 页（行 577-582）「Ground truth and labelling consistency」：「Flow-level labels are derived from official exercise role metadata and red-team infrastructure identifiers, as formally defined in the LSPR23 dataset paper [23]. A flow is labelled malicious if its source or destination IP corresponds to red-team infrastructure during the exercise. The same labelling procedure is applied consistently across LSPR23, LSPR24, and LSPR25.」
- 印刷第 9 页（行 611-615）「Class imbalance and labelling granularity」：「Labels are assigned at the flow level: each individual flow record receives a binary benign/malicious label based on whether its source or destination IP belongs to red-team infrastructure. This flow-level granularity propagates through all sequence construction strategies and evaluation metrics.」
- **无删失/纠偏处理**，只做了口头声明。印刷第 8-9 页（行 587-589、594-598）：「Known limitations, such as the inability to label certain stepping-stone attacks, are transparently documented in the dataset publications.」「we do not assume perfect label purity. Known limitations (e.g., stepping-stone attacks) may introduce conservative false negatives, but the labelling mechanism is consistent and reproducible across all datasets.」
- 承认标签会漏（conservative false negatives），但没有任何 PU 学习、标签平滑、删失建模或不确定标签剔除。
- 序列级标签不存在：所有序列策略下标签仍逐流附着（见上「flow-level granularity propagates through all sequence construction strategies」），序列只是上下文容器。

【我方】收据 dropped_non_binary_label_rows = 0，四个角色都没有非二值标签行被丢弃；标签在打分密封之后才 join（alignment-gate.json 的 seal.sealed_before_label_join = true）。两边标签定义口径一致，**标签口径不是本次差距来源**。

### `metric_definition`

【AP 在逐流单元上计算；自助法在逐序列单元上重采样】

- §5.10，行 1888-1893，印刷第 25 页：「Average Precision (AP): Primary ranking metric, equivalent to the area under the Precision–Recall curve.」
- 单元 = 流。§5.3，行 1674-1682，印刷第 22 页：「Classification is performed at the flow level... one logit per valid flow. Sequence padding positions are masked and excluded from both loss computation and metric evaluation.」
- §5.11，行 1954-1964，印刷第 26 页：「Resampling was performed at the sequence level to preserve the temporal and structural dependencies induced by the grouping strategies, rather than resampling individual flows i.i.d. For each bootstrap replicate, entire sequences were sampled with replacement, and all flows contained within the sampled sequences were included in the evaluation set. Although predictions are generated at the flow level, performance metrics (AP, AUROC, F1, Precision, Recall, Accuracy) were computed over the aggregated set of flows in each bootstrap sample.」B = 10,000，报告 2.5/97.5 分位。
- AP Lift 定义（§5.10，行 1895-1906，印刷第 25 页）：「APLift = AP / π where π denotes the positive class prevalence in the evaluation dataset. AP Lift therefore measures how many times better the model ranks malicious events compared to random guessing.」——**原文明确 π 是「评价数据集」的阳性率**。

**我实测验证了表 8 的 π 就是 AP Lift 的分母（即评价池逐流阳性率）**，用表 4 的 AP/Lift 两列反算：
  同年（LSPR23）2-H：0.988/106.16 = 0.009307；0.982/105.56 = 0.009303；0.996/107.05 = 0.009304；0.996/107.09 = 0.009301；0.973/104.57 = 0.009305 → 全部落在表 8 的 LSPR23 2-H π = 0.0093。
  同年（LSPR23）SesIP：0.972/23.02 = 0.042224；0.970/22.97 = 0.042229；0.967/22.90 = 0.042227；0.974/23.07 = 0.042219；0.952/22.54 = 0.042236 → 表 8 LSPR23 SesIP π = 0.0422。
  次年（LSPR24）2-H：0.027/6.33 = 0.004265；0.034/7.87 = 0.004320；0.056/13.00 = 0.004308；0.074/17.25 = 0.004290；0.057/13.18 = 0.004325 → 表 8 LSPR24 2-H π = 0.0043。
  次年（LSPR24）SesIP：0.031/1.15 = 0.026957；0.029/1.05 = 0.027619；0.042/1.56 = 0.026923；0.052/1.92 = 0.027083 → 表 8 LSPR24 SesIP π = 0.0273。
→ 表 8 的 π **确实是逐流阳性率，并且次年评价用的就是次年自己的构造池的 π**。这条链是实算证据，不是推测。

【推论，需标注】次年评价池是否等同于次年的验证切分（同样经过 seed 42 分层采样），原文没有明说。因为分层采样后 train 与 val 的 π 若一致，用表 8 单一 π 无法区分。**标为待验证假设。**

【与我方对比】我方 flow_ap 同样是逐流 AP，单元一致；不一致的是分母池。我方 ap_over_prevalence_lift = 0.037727224830474186 / 0.007714664354813454 = 4.890326149696302；Dijk = 0.2416 / 0.0707 = 3.4172560113154176。**我方相对各自基率强 43.1%。**

### `op_meaning`

【OP = Original Position（原始位置）】

定义位置：§4.1.1「Original Position (OP)」，提取文件行 815，印刷第 11 页；形式化定义在印刷第 12 页（行 852-860）。

原文语义（印刷第 11-12 页，行 816-860）：
- 「The Original Position strategy sequences flows according to their global timestamps, using the chronological order provided in the raw dataset... By chunking flows directly from this global temporal stream, the method preserves the overall timeline of network activity across all hosts.」
- 「In our experiments, flows are globally sorted once by their recorded start timestamps prior to sequence construction, resulting in deterministic offline ordering. We do not simulate streaming ingestion; rather, OP represents a batch chronological baseline. Ties in timestamp are broken by the original dataset row order.」
- 形式化：Φ_OP(f) = {1}。「Thus, all flows are assigned to one common ordered stream... Session splitting is not applied for OP.」
- §5.1，行 1563，印刷第 20 页：「The Original Position (OP) strategy serves as the baseline representation.」

【阳性率为何会被「诱导」——三条机制，前两条有原文直接支撑】

机制 1（**主因，原文直给**）：验证集序列级分层采样。§5.8，行 1807-1810，印刷第 24 页：「To mitigate extreme class imbalance in validation data, we applied a controlled stratified sampling procedure at the sequence level with a fixed random seed (42).」——作者**主动**抬高了评价池的阳性率。这是「诱导」一词的字面来源。原文未给保留比例。

机制 2（**原文直给**）：分组键重分布。印刷第 9 页行 621-623：「Under entity-based grouping strategies, induced π values change further due to redistribution of flows across sequences.」印刷第 38 页行 2135-2141 进一步说：「Induced positive-class prevalence partially mediates this effect: strategies that dilute the malicious signal through fine-grained grouping (e.g., 5-Tuple π ≈ 0.002) perform consistently worse than those that preserve higher prevalence (r = 0.42 between π and best AP).」注意 1-IP 与 Host/SesH 会把同一条流复制到源、目的两个组（Φ 返回两个键），因此这些策略下流的多重计数直接改变 π 的分母。

机制 3（**推论，待验证**）：OP 下 Φ 只有一个全局键、无流复制、无会话切分，所以「重分布」对 OP 不起作用。换言之 OP 的 π 理应等于池内原始逐流阳性率。但实测 0.0707 = LSPR24 原始 0.0257 的 2.75 倍，因此 OP 的抬升**只能**来自机制 1（分层采样）或来自 train/val 划分本身相对标签非随机。原文两者都没有量化。**标为待验证假设，无法从全文复原。**

【定量结论】
- 0.0707 / 0.0257073... = 2.7502（Dijk 池相对原始基率富集 2.75 倍）
- 0.0077147 / 0.0257073... = 0.3001（我方池相对原始基率稀释 3.33 倍）
- 0.0707 / 0.0077147 = 9.1644（两侧总差 9.16 倍，与实测事实中的 9.2 倍一致）
- 我方 lift 4.8903 vs Dijk lift 3.4173：**在各自基率下我方排序能力反而高 43.1%**，与「差距来自评价样本池定义而非模型能力」的判断一致。但见阻塞点 4——特征预算差异同样会独立影响 AP，不能把全部差距归给池定义。

## 二、本课题现行协议（代码与收据）

### `pair_hash_logic`

【机制】label-blind 的 2-IP 无向对哈希抽样，本质是"按 IP 对哈希空间保留 64/256 = 25%"。

实现位置（唯一判据函数，2 行）：
`thesis/experiments/llm_probe/tools/lspr24_g0/src/lspr_crossyear.rs:1412-1413`
```rust
fn pair_hash_prescreened(config: &CrossyearConfig, role: YearRole, pair_key: &[u8; 32]) -> bool {
    u16::from(pair_key[0]) < config.pair_hash_keep_thresholds[role.name()]
}
```

pair_key 定义在同文件 `916-931`：
- `canonical_ip()`（909-914）把 IPv4 转 IPv6-mapped 16 字节，IPv6 取 16 字节；
- 对 (src,dst) 按 16 字节字典序排序成 (low,high)，**无向**；
- `tuple_encode([Utf8("lspr-crossyear-2ip-v1"), Ip16(low), Ip16(high)])` 后取 SHA-256。
- 编码规范在 `tools/lspr24_g0/src/canonical.rs:176-212`：每字段 = 1 字节类型标记 + 4 字节大端长度 + 值字节；`UTF8_TAG=0x06`、`IP16_TAG=0x08`。
- 常量 `PAIR_KEY_DOMAIN` 在 `lspr_crossyear.rs:36`。

调用点：LSPR23 在 `1497-1504`，LSPR24 在 `1612-1615`；两处都在**时间门禁与角色路由之后、标签读取之前**，所以它是标签盲的（收据里也自述 `target_label_used_for_selection=false`）。被剔除的行按 `format!("{}-pair-hash-prescreen-excluded", role.name())` 计入隔离计数（1498 / 1613）。

配置约束：`239-407` 的 `validate()` 中，`349-362` 要求四角色阈值齐全且取值在 `1..=256`。收据自述算法名见 `2565-2570`：`"label-blind-pair-key-sha256-leading-byte-v1"`、`"keep_when": "pair_key[0] < role_threshold"`、`"denominator": 256`。

【耦合的副作用】外排分桶键也是 `pair_key[0]`（`1181`：`let bucket = usize::from(row.pair_key[0])`），BUCKET_COUNT=256（`39`）。阈值 64 意味着**只有 000..063 号桶会被写入**，其余 192 个桶文件恒为空。预筛与分桶共用同一字节，不是两个独立机制。

【剔除了什么：实测复现，与冻结收据逐位吻合】

### `row_limit_origin`

【来源】不是外部给定，也不是缓存实现的物理上限，而是 **Rust 配置门禁里硬编码的两档"预算等级"之一**。

即：`role_row_limits` 不是自由参数。配置里写什么值都必须与 `budget_tier` 完全对上，否则解析即失败。当前配置 `configs/lspr-crossyear-c12-seed42-q0-v1.json` 的 `budget_tier` = `"Q0"`。

【谁定的】本课题自己定的，且 **Q0 是对既有设计合同的一次下调**。
- 设计合同 `.Codex/docs/RWKV/2026-08-11-LSPR23-LSPR24共同字段审计与跨年度数据合同.md:380-387` 的角色表规定：`source-train` 1,048,576、`source-validation` 262,144、`target-prefix` 262,144、`target-development` **1,048,576**，总缓存上限 2,621,440。这正是代码里的 Q1。
- 实现报告 `.Codex/docs/RWKV/2026-08-11-C12跨年度有界快速缓存实现报告.md:13` 明写："Q0 首次快速筛选固定为四角色各 `262,144` 条实际流上限，总计不超过 `1,048,576`。原较大预算保留为 Q1 确认配置"。第 28 行、35 行给出两档的角色上限与临时目录上限（Q0 12 GiB / Q1 18 GiB）。第 70 行记录裁决："授权后只启动 Q0，不先运行 Q1"。

所以 262,144 = 2^18，是**为首次快速筛选人为压缩的一次性预算**，不是内存或磁盘的物理上界（本次 Q0 实跑 `temporary_bytes` 仅 6,212,952,090 字节，约 5.79 GiB，配置上限 12 GiB）。

【预算怎么消耗的】`select_sequences()`（2466-2577）按角色分配：
- `source-train`：预算 /2 = 131,072，恶意池与良性池各一半（2481-2511）；
- `source-validation` / `target-development`：预算 /64 = **每个活动秒秩分层 4,096 行**（2512-2531）；
- `target-prefix`：整块预算按最早时间序（2532-2540）。
序列不可拆分（`select_with_budget` 2433-2449 只在整条序列能塞进剩余预算时才收），所以实际选中略低于预算：target-development 261,839 < 262,144。

【解除的代价】
1. 改到 Q1（target-development 1,048,576，per-stratum 16,384）：只需改配置，但连带门禁要一起改 —— `389-394` 要求 `quantile_sample_per_field >= role_row_limits["source-train"]`，当前配置该值为 262,144，Q1 下必须提到 ≥1,048,576；`320-323` 要求 `temporary_directory_limit_gib` 在 1..=24（报告建议 Q1 用 18）。**必须重跑整条物化**，四角色缓存、清单哈希、normalizer、selection-receipt 全部作废重生成，下游所有 SHA-256 校验（`crossyear_entity_eval_data.py:272-285`）随之失效。
2. 超出 Q1（例如想评满 4,994,113 行）：**必须改 Rust 源码**的 `validate()` 匹配臂，没有任何配置路径可以绕过。
3. 关键量级判断：即使升到 Q1，target-development 1,048,576 仍只是预筛后 4,994,113 行的 21.0%；要恢复到自然评价池 13,918,045 行，还必须同时把 `pair_hash_keep_thresholds` 提到 256（合法上限，`357-362`），两者是**独立的两道收缩**，只放开一道不够。

### `invalid_time_logic`

【判据】四个互斥条件之一即整行隔离，位置 `tools/lspr24_g0/src/lspr_crossyear.rs:1585-1600`（LSPR24 分支）：

## 六条不可重建理由

### A. 我从 Table 8 反推出了 Dijk 的 80/20 切分——结果让问题更严重，不是更轻

两年**精确命中**。推论：train:val = 80:20（提案称"比例空白"是错的）；OP 用全量流无丢弃；我方与 Dijk 的流宇宙一致。

进一步**可以证明** π=0.0707 只能是评价集阳性率：

### B. 我方评价池不是"另一个阳性率"，而是**另一种测度**——这条使方案 A/B 的数学基础同时失效

`lspr_crossyear.rs:2510-2527`：`source-validation` 与 `target-development` 用
`label-blind-64-active-second-rank-strata-stable-hash-v1`，`per_stratum_row_budget = 262144/64 = 4096`；
`lspr_crossyear.rs:2363-2379`：stratum = 活动秒**排名**均分 64 份。
实际取 `261,839 / 262,144 = 99.884%` → **上限在几乎全部 64 层都是紧的**。

而同一份 `protocol-difference-audit.json` 的开发区十分位阳性率：
`0.04344672 / 0.04009581 / 0.02002557 / 0.00009141 / 0.00008734 / 0.00008978 / 0.00008916 / 0.00009758 / 0.00082661 / 0.04409173`

攻击密集时段与阳性率不足万分之一的时段拿到**完全相同的 4,096 行预算**。这不是抽稀，是把时间轴压平。π 由 `0.013277554559784466` 变到 `0.007714664354813454`（比 1.7210800041482202），但更要命的是**负类的总体构成**被按数量级重新加权。

> 因此提案 R1 的"log-lift 位置不变"投射、以及方案 B"对负类子采样到 π=0.0707"，**都只修分母、不修分子的总体**，在数学上不成立。这两条是提案的第一、第二推荐动作。

### C. 155 维不是"83 减 6"，是**不同的函数**
