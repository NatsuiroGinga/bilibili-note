# LSPR23→LSPR24 跨年度强基线工程接入勘察

- **日期**：2026-08-11
- **范围**：只读勘察。目标是为冻结的 LSPR23 源年度训练、LSPR24 无标签前缀校正和目标开发评价，确定强基线的最短接入路径。
- **结论状态**：工程可行性勘察，不是训练结果。`CONTRACT=READY`，但真实共同缓存、加载器首次真实读取和所有模型训练仍未完成；LSPR24 最后 20% 未访问。

## 结论

最快且不破坏合同的路径是：先完成一次 Rust 跨年度真实物化和 `prepare_crossyear_cache` 的首次真实读取，再以该加载器生成的四个角色数组作为唯一模型输入，新增一套跨年度训练入口。不能直接把同年 `lspr24_rwkv_screen.py` 的缓存或训练入口接到本合同上。

最先可运行的共同强基线是 HGB、XGBoost、GRU 与参数匹配因果 Transformer；前三者只需跨年度适配层，其中 GRU 和 Transformer 可复用 PyTorch 训练骨架。普通 RWKV-7、DeltaNet、Gated DeltaNet 必须各自增加状态核适配，但不得将现有候选筛选中的简化 `Rwkv7CoreBlock` 冒充官方 RWKV-7。DeltaNet 与 Gated DeltaNet 的官方仓库和固定提交均已核验；DeltaNet 固定提交归档已回收本机，但两者仍缺正式环境导入与真实前向、反向收据。

## 已核对的合同与可复用接口

### 跨年度数据边界

- 统一实验清单固定 77 个有序共同输入字段、`X_value[77]`、`X_missing[77]`、相对 `delta_t`、2-IP 最长 128 流的非重叠序列与填充掩码。
- 四个角色固定为 `source-train`、`source-validation`、`target-prefix`、`target-development`。只有前两个角色对训练器公开标签；目标前缀没有标签接口；目标开发标签只由预测冻结后的评价器显式使用。
- 所有模型必须复用相同 `sample_id`、序列边界、位置、有效长度、字段顺序、训练区归一化器、源验证阈值收据和角色行预算。LSPR24 最后 20% 不得出现在清单、缓存、统计或模型输入中。
- 跨年度加载器的公开入口是 `prepare_crossyear_cache(config_path, output_dir)`，并提供 `CrossyearFeatureRole`、`CrossyearLabeledRole` 和 `TargetDevelopmentEvaluation`。其缓存采用只读 NPY 磁盘映射数组，不构造全量 Python 行对象。

## 基线接入矩阵

| 基线 | 首轮状态 | 最短适配范围 | 共同输入与训练角色 | 主要阻塞 |
| --- | --- | --- | --- | --- |
| HGB | **可先跑，待真实缓存** | 新增跨年度表格视图适配器；把每个有效序列末位的 `77` 值、缺失掩码和允许的相对时间摘要展平，并复用跨年度标签旁车 | 只在 `source-train` 拟合；`source-validation` 冻结阈值；仅预测后评估 `target-development` | 必须预先冻结表格化规则，不能让树模型得到序列模型没有的历史或身份信息 |
| XGBoost | **可先跑，待真实缓存** | 与 HGB 共用同一适配器和特征矩阵；复用现有 `XGBClassifier` 的 CPU `hist` 配置 | 同 HGB | 正式环境需确认 `xgboost` 可导入；不可因模型不同改列、样本或归一化 |
| GRU | **可先跑，待真实缓存** | 新增通用跨年度序列训练入口和小型 GRU 编码器 | `x_value` 与 `x_missing` 拼接，`delta_t_us` 作为相对时间通道，严格使用 `padding_mask`；源年监督训练，目标前缀只在已冻结的在线校正变体中使用 | 需要先冻结是否把缺失和相对时间作为每个基线的共同输入；普通 GRU 不应获得 C12 专属状态更新 |
| 参数匹配因果 Transformer | **可先跑，待真实缓存** | 从现有 `CausalTransformerTimeMixer` 迁移为 `H=128`、带填充掩码的通用编码器；新增位置/相对时间处理 | 与 GRU 完全相同 | 现有模型未处理跨年度缓存的掩码和无标签前缀角色，必须适配；它是 C12 的接收基座，应先于 C12 完成 |
| 普通 RWKV-7 | **需适配后运行** | 使用独立 CUDA 融合实现接收同一 `[B,128,F]` 张量与掩码，并接入共享 Raw83 加载器 | 与 GRU/Transformer 相同；不允许专属字段、额外历史或不同训练样本 | 固定 `RWKV-LM` 来源、版本和许可证；CUDA 扩展不可用时记录失败并停止，不切换其他训练实现 |
| DeltaNet | **需适配后运行** | 新增并行 DeltaNet 状态核包装器，显式固定状态维度、头数和投影维度 | 与普通 RWKV-7 相同 | 作者主页指向 `fla-org/flash-linear-attention`；固定提交 `7843b328b0d3860a66de4eb07ba28bb020ceb1d8` 的 MIT 源码归档已回收本机，但尚未在正式环境导入或运行，不能自行把 C12 公式当作 DeltaNet 实现 |
| Gated DeltaNet | **需适配后运行** | 新增门控 DeltaNet 包装器，并把全局遗忘门仅作为公开基线机制 | 与 DeltaNet 完全相同 | `NVlabs/GatedDeltaNet` 官方仓库与固定提交 `b53d6d3a161267432a79c1c04af69fa52bddc921` 已核验；本机快照、正式环境导入和运行收据仍待补齐 |

## 训练预算与公平条件

跨年度合同只要求相同参数、训练步数、输入字段和序列构造，尚未冻结数值预算。因此不得沿用同年筛选的 `100,000/20,000`、`H=4`、5 轮、`256/512` 批量作为跨年度默认值。实现前应把以下内容写入唯一跨年度实验配置，并由所有七类模型读取：

1. 固定源训练样本清单和源验证样本清单哈希；所有神经基线使用同一 `H=128`、77 字段、缺失掩码、相对时间、序列边界与训练区归一化器。
2. 固定单卡批量、混合精度、优化器、学习率计划、总优化步数、早停规则和检查点选择规则。参数匹配以实际可训练参数量收据校验，不以层数或模型名称代替。
3. 普通序列基线先执行纯源年度监督训练；若测试“目标前缀校正”，必须将其定义为额外同预算消融，统一限制前缀长度、更新次数、可更新对象和当前批先预测后更新顺序。
4. HGB 与 XGBoost 采用同一展平特征和源年样本。首轮可延续现有每模型 100 棵迭代树的工程默认值，但这不是与神经网络的“训练步数相等”；报告中应分别声明树迭代预算与神经优化步数，且两树模型参数完全相同。
5. 阈值只在 `source-validation` 冻结。`target-development` 只用于预先登记的评价，不能用于选择训练步数、阈值、字段、状态维度或候选基线超参数。
6. C12 的最小比较仍为 `B0/M1/M2/M1+M2`，但公共强基线至少包括 HGB、XGBoost、GRU、因果 Transformer、普通 RWKV-7、DeltaNet 和 Gated DeltaNet。C12 不能把既有 Delta 状态式或普通门控误写成原创机制。

## 推荐实施顺序与最短文件范围

### P0：先解除数据门禁，不改模型

1. 在 C56 对 Rust 物化器执行只读预检，然后一次真实物化跨年度主产品与 `c12-seed42-2ip-v1` 清单。
2. 在正式环境调用 `prepare_crossyear_cache`，确认四角色数组、标签侧车隔离、源验证扩大收据、`final_accessed=false` 与目标前缀无标签接口。

这两步失败时，所有基线均不得启动；不应使用合成制品或同年候选缓存替代。

### P1：先交付共同 HGB/XGBoost 和通用序列入口

最短新增文件范围建议为：

- `src/flow_probe/lspr_crossyear_baselines.py`：唯一训练/评价入口，消费 `lspr_crossyear_dataset.py` 的缓存角色；负责预算检查、源训练、源验证阈值冻结、目标前缀路由、目标开发预测和制品收据。
- `src/flow_probe/lspr_crossyear_models.py`：只存无状态表格适配、GRU、参数匹配因果 Transformer 与后续状态核的统一模型接口。
- `scripts/run_lspr_crossyear_baselines.sh`：只作绝对路径、运行目录、最终区禁入和 `uv run --no-sync` 包装。
- `configs/lspr23_lspr24_crossyear_seed42_v1.json`：冻结样本清单哈希、预算、模型名、参数目标、阈值与角色权限。

不应修改 `lspr24_rwkv_screen.py`、`lspr24_rwkv_screen_models.py`、`traditional_baselines.py` 或既有同年启动器；它们保留为历史同年筛选证据。若希望复用其函数，应迁移无数据集依赖的最小代码，而非让新入口反向依赖同年合同。

### P2：按同一接口加入状态核

1. 从 `RWKV-LM` 提交 `952102498e9ed367ea0a59ee64106916d474d30f` 固定官方 RWKV-7 最小状态模块，记录源码归档、许可证、导入路径和可用内核。
2. 使用已经回收本机的 Parallel DeltaNet 官方 `fla-org/flash-linear-attention` 提交 `7843b328b0d3860a66de4eb07ba28bb020ceb1d8`，完成正式环境导入与标准 DeltaNet 包装器。
3. 重新定位或回收 Gated DeltaNet 官方 `NVlabs/GatedDeltaNet` 提交 `b53d6d3a161267432a79c1c04af69fa52bddc921`，再接入门控 DeltaNet。
4. 对三者统一提交一次真实前向、反向、H=128 填充掩码和参数量收据检查后，再进入同一种子 42 训练矩阵。

## 当前阻塞项

1. **真实数据制品缺失**：本机没有 Rust 正式跨年度物化制品；加载器报告明确标为 `DONE_WITH_CONCERNS`，不能验证真实 Parquet 列表转换和侧车连接。
2. **训练入口缺失**：`lspr_crossyear_dataset.py` 只生成缓存，尚无消费四角色、冻结阈值和控制目标前缀权限的训练模块。
3. **官方状态核工程接入未完成**：DeltaNet 官方固定提交归档已回收本机，Gated DeltaNet 官方仓库与固定提交已核验但本机快照尚未补齐；两者都没有正式环境导入、前向或反向收据，不能声称已可直接运行。
4. **预算未数值冻结**：跨年度合同冻结了公平原则，尚未冻结总步数、批量、参数目标、早停和目标前缀校正预算。先冻结这些配置，才可比较模型。
5. **方法边界**：C12 原广义 Delta 递推与 DeltaNet 同式，门控 DeltaNet 与 RWKV-7 已覆盖自适应遗忘和定向改写；基线接入不得推进“新 Delta 规则”主张。
