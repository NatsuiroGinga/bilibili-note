# LSPR23→LSPR24 P0 跨年度迁移实验工程接口勘察

## 结论

- P0 候选应以“**XGBoost 叶表示上的稀有恶意质量保护非对称部分最优传输，配合无标签负迁移停机/回滚**”进入首次真实 Q0；分数空间只保留为成本更低的消融和停机信号，不能承担主传输表示。
- 现有共同缓存可以直接只读复用；现有 Q0 表格基线的目标开发概率、模型制品均不能直接作为 P0 输入。必须从相同冻结缓存重新训练并封存本候选专属 XGBoost 强锚，随后在未打开目标开发标签的情况下生成目标前缀和目标开发的叶表示、概率及封印。
- 用户已明确批准在当前空闲 GPU 上运行。XGBoost 固定为 `tree_method="hist", device="cuda"`，启动前必须执行最小真实拟合、预测和叶编号提取门禁；CUDA 失败时阻塞，禁止静默回退 CPU。部分最优传输可按实现依赖选择 CPU 或 GPU，但必须记录设备与资源收据，所有候选共享同一个 GPU XGBoost 锚。
- 当前结论是工程可行性判断，不是方法有效性结论。所有 P0 运行仍为 `screening_only=true`、`formal_paper_evidence=false`、`final_accessed=false`。

## 首轮表示裁决

### 推荐：叶表示空间

P0 首轮应固定训练共同 XGBoost 强锚，再以 `XGBClassifier.apply`（或等价 Booster 叶索引接口）对四角色的同一 155 维输入生成每棵树的叶索引。原因如下：

- 单一恶意概率只保留最终排序的一维投影，无法区分“相同分数、不同规则支持”的样本；部分最优传输将退化为一维质量重分配，难以表达源私有支持拒绝。
- 叶索引保留固定树集的分段规则归属，可用稀疏独热、按树归一化汉明距离或稳定哈希嵌入构造传输成本；不改变 XGBoost 排序锚的训练输入。
- 强锚当前为 300 棵树，因此原始叶表示宽度约为 300，远小于全量序列视图；对约 26 万目标前缀和 26 万目标开发流，必须采用固定大小、分块和可复现抽样，禁止构建完整 `n×m` 传输成本矩阵。
- 源恶意质量下限可直接按真实源标签约束源恶意叶簇的保留质量；目标侧只使用叶索引、锚概率和无标签前缀统计，不打开目标标签。

### 分数空间的限定角色

分数空间仍应实施为一个预注册对照：同一锚、同一源恶意质量下限和同一停机规则，仅把传输成本换成锚概率差。它用于证伪“叶表示提供额外可迁移支持信息”，同时可低成本计算候选间预测率包络、扰动稳定性和 EnsV 类共识信号。它不得作为主 P0 表示，也不得以目标开发 AP 决定叶表示或传输超参数。

## 最小接口设计

### 共享输入

- 缓存加载必须沿用现有四角色、数组 SHA-256、普通文件路径与 `formal_cache_root` 检查；不得复制或放宽 `flow_probe.lspr_crossyear_dataset` 的标签隔离语义。
- 强锚拟合输入仅为 `source-train` 的 155 维特征和标签。`source-validation` 只用于冻结阈值、源恶意排序质量与保护质量下限收据；不得用目标开发标签选树参数、传输质量、成本权重或停机阈值。
- 适应输入允许 `target-prefix` 的 155 维特征、强锚概率和叶表示。目标开发只允许在所有候选参数固定后生成预测、封印并评价；最终 20% 严格禁止访问。

### 必须新增的候选专属制品

- `anchor-model.joblib`：XGBoost 模型、特征定义、训练角色、种子、XGBoost 版本和模型 SHA-256。
- `representations/<role>-leaf.npy`、`representations/<role>-score.npy`：四角色叶索引与锚概率，均须写入样本 ID 哈希、形状、数据类型和来源模型哈希。
- `transport/source-prototype-receipt.json`：固定抽样/原型规则、每类源样本数、源恶意保留质量下限、未匹配质量、分块大小和随机种子。
- `transport/target-prefix-decision.json`：仅由目标前缀无标签量计算的候选比较、支持拒绝率、预测率包络、扰动稳定性、源恶意质量与停机/回滚决定。
- `predictions/target-development-*.npy` 及对应封印：锚、无保护 POT、恶意质量保护 POT、保护加停机四个预注册变体分别封存。

## 依赖与资源

### 依赖门禁

运行前通过项目环境执行以下导入检查，不得使用系统 Python：

```bash
source tools/env/activate.sh
PYTHONPATH="$PWD/src" uv run --no-sync python -c 'import joblib, numpy, scipy, sklearn, swanlab, xgboost; print("P0 依赖可用")'
```

- 已有强锚所需依赖：`numpy`、`scikit-learn`、`xgboost`、`joblib`、`swanlab`。
- 非平衡/部分最优传输若选择 Python Optimal Transport（`ot`）实现，必须在启动前单独固定版本、安装并验证 `import ot`；不能在正式启动器内自动同步或下载。
- 更稳妥的首轮实现是仅依赖已核验的 `numpy`/`scipy`，并将 Sinkhorn 迭代、收敛阈值、最大迭代和数值失败条件写入配置。两种实现不得在同一运行身份内混用。

### 资源裁决

- 首轮 CPU：XGBoost 已在约 14.2 万源训练流上完成训练约 4.344 秒，目标开发推理约 0.286 秒；P0 新增成本主要是叶表示、原型化及分块传输，不能从旧耗时外推。
- 禁止完整样本两两成本：约 26 万目标前缀与 14 万源训练样本形成约 370 亿对，单精度成本矩阵约 138 GiB，违反内存边界。
- 首轮配置必须固定每类源原型/样本上限、目标批大小、叶表示宽度、每批成本矩阵上限、最大迭代数和峰值内存估算；推荐先以确定性分层源原型与目标前缀分块运行，再由真实 `resource-usage.json` 决定是否扩容。
- GPU：`gpu_required=true`。正式运行前重新核验 C56 身份、项目根、磁盘、内存、GPU、缓存、依赖、SwanLab 和无活动冲突运行；至少保留 8 GiB 空闲显存。XGBoost CUDA 门禁失败时停止，不回退 CPU。

## 入口检查与真实运行门禁

### 入口检查

1. 配置 JSON 可解析，运行根不存在，或仅存在带 `state=finished` 的同身份收据时幂等退出；存在不完整目录必须拒绝覆盖。
2. 缓存清单路径、SHA-256、四角色集合、77 字段、155 维输入和 `final_accessed=false` 全部匹配；确认 `target-prefix` 无标签文件。
3. 强锚配置固定 GPU `hist/cuda`、种子和特征定义；模型、叶表示、概率与样本 ID 哈希按顺序写收据。与历史 CPU v2 只核对样本数、顺序哈希、数据清单哈希和有限值，概率差异只作诊断；候选同时比较同轮 GPU 锚与历史 CPU 绝对门槛。
4. 目标开发标签路径在适应和停机阶段不可打开；预测封印写完并校验后，才由评价阶段读取标签。
5. SwanLab 目标必须严格为 `mortiswang/malicious-traffic-llm`；不一致则不读取缓存、不创建运行、不上传。

### 真实 Q0 门禁

- 先运行锚、无保护 POT、恶意质量保护 POT、保护加停机四个预注册变体；各变体使用同一强锚、同一缓存、同一源原型预算和独立输出目录。
- 停机/回滚只读目标前缀：至少联合源恶意排序保持、恶意质量下限、未匹配质量、目标前缀扰动稳定性、预测率包络与候选集共识。任一预注册硬失败即回滚到冻结 XGBoost 锚，不得读取目标开发标签作决定。
- 真实运行结束后才一次性评价目标开发 PR-AUC、固定告警预算召回、恶意 F1、校准、拒绝质量、源恶意质量保持和资源。Q0 仅决定是否值得进入多种子与正式冻结，不得据单次目标开发结果追参。
- 首轮的通过/失败门槛必须在实施计划和配置内冻结。基线参照为共同 XGBoost 目标开发 PR-AUC=`0.038902589823969644`；不得在看到 P0 指标后更改该基线、样本、字段、预算或门槛。
