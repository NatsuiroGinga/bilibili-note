# LSPR23-LSPR24 共同字段审计与跨年度数据合同

- **日期**：2026-08-11
- **研究路线**：`RESEARCH_ROUTE=RWKV`
- **任务**：LSPR23 源年度监督训练到 LSPR24 目标年度无标签校正与开发评价
- **合同状态**：`CONTRACT=READY`、`MATERIALIZATION=READY_AFTER_REMOTE_PREFLIGHT`、`SEED42_ABLATION=BLOCKED`
- **最终区状态**：`LSPR24_FINAL_20_PERCENT=NOT_ACCESSED`

## 0. 结论

1. LSPR23 与 LSPR24 原始流表的字段集合一致，均为 **101 列**，但最后 9 列的物理顺序不同。读取器必须按字段名投影，禁止按位置绑定。这只证明字段集合一致，不证明类型、缺失、单位和生成软件语义在两年间自动一致。
2. 首轮跨年度实验冻结 **77 个共同模型输入字段**：`Protocol`，以及从 `Flow Duration` 到 `Idle Std` 的 76 个流级统计字段。完整流统计只在 `mTimestampLast` 后可见。绝对时间值不入模。
3. `Flow ID`、IP、端口、主机名、服务名、网段、EXPO 身份、内外网标记、年份、IDS 输出、标签及其派生字段一律不入模。无向 2-IP 键只保存在受控侧车中用于分组，绝不进入张量、词表、频次特征或嵌入。
4. 首轮种子 42 的四变体 `B0/M1/M2/M1+M2` 固定使用 **2-IP、最长 128 流、非重叠、按完整流可用时刻排序**的序列。该选择来自 Dijk 等全文中 2-IP 跨年中位退化最小的先验证据和身份泄漏纪律，不得再依据 LSPR24 标签改选 OP、2-H 或其他构造。
5. 数据设计分两层：开发主数据产品保存两年度开发范围内全部合法、因果、可复用字段的**并集**；跨年度四变体通过统一实验清单只选择语义一致的**交集**。不得把主产品误做成 77 字段窄表。
6. LSPR24 时间协议冻结为：最早 10% 活动秒只作无标签校正前缀，随后 70% 作开发评价，最后 20% 保持不可见。LSPR23 按活动秒前 80% 训练、后 20% 源年度验证。
7. 本合同允许进入数据物化准备；种子 42 训练仍被阻塞，直至共同缓存、样本清单、阈值收据、标签隔离和 `final_accessed=false` 门禁通过。

## 2. 两年度原始字段审计

### 2.1 物理类型

LSPR23 是 CSV，所有列的物理载体均为 UTF-8 文本。下表中的 LSPR23 类型是 128 行样本的词法解析结果，不是全表证明。LSPR24 类型来自完整 Parquet 模式。

两年从第 0 列到第 91 列的顺序一致；第 92–100 列不同。LSPR23 依次为 `Label_src`、`Label_dst`、`Label`、`External_src`、`External_dst`、`Segment_src`、`Segment_dst`、`Expoid_src`、`Expoid_dst`，LSPR24 则依次为 `External_src`、`External_dst`、`Segment_src`、`Segment_dst`、`Expoid_src`、`Expoid_dst`、`Label_src`、`Label_dst`、`Label`。任何按位置拼接都会把标签和身份元数据错配，必须使模式门禁失败。

| 字段集合 | LSPR23 词法类型 | LSPR24 物理类型 | 规范化类型 |
| --- | --- | --- | --- |
| `Flow ID`、`SrcIP`、`DstIP` | 字符串 | `string` | 仅受控侧车，不入模 |
| `SrcPort`、`DstPort`、`Protocol` | 整数 | `int32` | 端口仅侧车；`Protocol` 规范为 `uint8` 类别 |
| `mTimestampStart`、`mTimestampLast` | 整数 | `int64` | UTC 微秒 `int64`，受检查乘 1000 得 UTC 纳秒 |
| `Flow Duration`、包数、标志、头长度、Bulk/Subflow、初始窗口和活动包数等计数字段 | 整数 | 多数为 `int32`；`Bwd Bulk Rate Avg` 为 `int64` | `int64` 后转模型 `float32` |
| 速率、长度统计、IAT、方差、比例、Active/Idle 等连续字段 | 浮点 | `double` | `float64` 清洗和拟合，模型缓存为 `float32` |
| `SigID revision`、`Category`、`Anomaly_event`、`Conn_state`、`Service`、`Label_src/dst`、`External_src/dst`、`Segment_*`、`Expoid_*` | 字符串或空字符串 | `string` | 不进入首轮共同输入；标签与身份放侧车或拒绝物化 |
| `Severity` | 128 行均为空，无法词法判型 | `int64` | IDS 输出，禁入 |
| `L3/L4 Protocol`、`Int/Ext Dst IP`、`Label` | 整数 | `int32` | 派生协议、IP 派生标记或标签，禁入 |

LSPR24 的 `Bwd Bulk Rate Avg` 范围超过 32 位且含负值，跨年规范类型必须使用 `int64`；不得按 LSPR23 样本把它收窄为 `int32`。`Label_src/dst` 和 `External_src/dst` 在 LSPR24 是字符串，不能因为 LSPR23 样本看起来像整数而静默转换成模型数值。

### 2.3 缺失、非有限值和非法值

| 年度 | 审计结果 | 合同处理 |
| --- | --- | --- |
| LSPR23 | 128 行流式样本中，77 个首轮共同字段均为 `0/128` 空字符串；`SigID revision`、`Category`、`Severity`、`Anomaly_event`、`Segment_src`、`Expoid_src` 为 `128/128` 空字符串；其余样本字段非空。**这不是全局缺失率。** | 正式物化逐列输出 `null_count`、空字符串数、非有限数、非法范围数和总行数；未得到收据前不得宣称 LSPR23 无缺失 |
| LSPR24 | Parquet 页脚显示数值首轮共同字段的 Arrow 空值均为 0；`Conn_state` 空值 12,287,355/20,227,356（60.746224%）；`Service` 5,960,527（29.467653%）；四个 IDS 列约 99.73%–99.81%；`Segment/Expoid` 源端 40.080706%、目的端 58.720650% | Arrow 非空不等于有效。已有候选视图报告 588,676 条流含非有限数；所有 `NaN/Inf` 必须转为缺失并带显式掩码 |
| LSPR24 非法范围 | 页脚已见 `Flow Duration` 最小 -39,711 微秒、若干 IAT 负值、速率含负值/`Inf/NaN`；候选视图另报告 1,945,836 条时间顺序被修正的流 | 正式合同不沿用未经证明的静默修正。`start_ns > last_ns` 进入时间隔离；物理非负字段小于 0 进入字段缺失并计数；不得按年度使用不同修补规则 |

统一缺失规则如下：

1. 空字符串、Arrow `NULL`、`NaN`、正负无穷和违反冻结物理范围的值统一转为缺失，但分别计数，不可把来源原因合并掉。
2. 每个模型字段同时输出 `value` 与 `is_missing`。训练区中位数只填充值槽，掩码保留；目标年度不得重新拟合填充值。
3. 某列在 LSPR23 训练区全缺失、常量或无法证明两年单位一致时，从**实验交集**删除，但仍保留在主产品并集、可用性清单和删除收据中。删除规则只能由 LSPR23 训练区触发。
4. 时间非法行整行隔离，不能仅把时间填补后继续生成序列；标签不可规范化的行进入标签隔离，不用 `Label_src/dst` 修补主标签。

### 2.4 标签与时间语义

- 两年的主标签均只使用官方行级 `Label`：规范整数 0 表示良性，1 表示与红队基础设施或跳板活动相关的恶意流。它不表示攻击家族、攻击成功或造成破坏。
- `Label_src`、`Label_dst` 只用于重复类标签一致性审计，不进入主标签修补、输入、采样键、序列键或生成目标。
- 完整流统计只能在 `mTimestampLast` 后使用。统一定义 `available_ns = mTimestampLast * 1000`；乘法溢出、时间不可解析或 `mTimestampStart > mTimestampLast` 时整行隔离。
- `mTimestampStart` 只参与时序有效性、Dijk 复现实验的差异说明和审计。首轮因果序列按 `available_ns` 排序，不按开始时间排序。
- 绝对时间、日期、星期、时刻、演习日程、年度编号及其周期编码均不进入模型。相邻完整流的非负 `delta_t` 可作为相对时间输入，但必须在同一年度、同一分区和同一 2-IP 序列内计算，并在边界处重置。

## 5. 八种序列构造比较与预注册裁决

| 构造 | Dijk 定义与证据 | 身份/因果风险 | 首轮裁决 |
| --- | --- | --- | --- |
| OP | 全局时间顺序；不复制流；是逐流基线。Dijk 的 LSPR23→LSPR24 XGBoost AP 从 1.0000 降到 0.2416 | 不含身份键，但全网并发流被串成单序列，跨主机状态语义混杂 | 保留为固定非选型参考，不用于挑选四变体构造 |
| 5-T | 双向五元组；大量序列极短 | 使用端口，形成服务/会话身份碎片；与首轮端口禁入纪律冲突 | 排除 |
| 1-IP | 每条流同时进入两个端点序列 | 复制流，评价相关性和端点身份记忆风险高 | 排除 |
| SesIP | 1-IP 加 300 秒会话边界；Dijk 报告大量长度 1–7 序列和极低每轮覆盖率 | 同时存在复制、端点身份和极短序列问题 | 排除 |
| 2-IP | 无向源/目的 IP 对；不复制流；Dijk 的全部构造中跨年中位退化最小，为 -0.0675 | 仍是身份分组，因此键必须侧车化且不得输入 | **冻结为首轮唯一构造** |
| Host | Expoid/主机资产身份的单端点序列；复制流 | 直接使用演习资产身份 | 排除 |
| SesH | Host 加 300 秒会话边界 | 演习身份、复制和极短序列三重风险 | 排除 |
| 2-H | 无向逻辑资产身份对；Dijk 同年 Transformer 常最优 | 依赖 Expoid/主机映射，优势与资产身份抽象混杂 | 排除，不作为“上界”读取目标标签 |

Dijk 的正文按 `mTimestampStart` 排序。本合同使用完整流统计，部署时只有 `mTimestampLast` 后才可见，因此为保证因果性，明确改为按 `available_ns` 排序。该差异必须写入实验报告，不能把本结果表述为对 Dijk 协议的逐项复现。

### 5.1 冻结的 2-IP 算法

1. 严格解析源、目的 IP 为规范字节；解析失败整行隔离。
2. 按字节序得到 `ip_low=min(src,dst)`、`ip_high=max(src,dst)`。
3. 受控侧车键固定为 `sha256(tuple_encode("lspr-crossyear-2ip-v1", ip_low, ip_high))`。哈希不是匿名化证明，仍按身份数据权限管理。
4. 每个年度、每个时间角色内按 `(pair_key, available_ns, start_ns, source_row_index)` 稳定排序。排序前强制切断年度和分区，任何序列不得跨边界。
5. 每个 `pair_key` 的流按最长 128 条切成连续、非重叠块；尾块保留；一条流只属于一个块。长度不足 128 使用填充掩码，不复制流。
6. 2-IP 键、原始 IP、序列号和年度不进入输入张量。状态在年度、时间角色、2-IP 键或序列块变化时清零。
7. 四变体共享同一有序序列清单哈希。目标年度标签只在预测持久化并冻结后由评价器连接。

## 6. 精确时间协议

对年度 `y`，先在不读取标签的条件下取得所有通过时间和去重审计的活动 UTC 秒，严格升序为：

```text
S_y = (s_0, s_1, ..., s_(N_y-1))
b_y(p) = ceil(p * N_y)
cut_y(p) = s_(b_y(p)) * 1_000_000_000
```

切点是较晚分区第一个活动秒的起点；不按流行数、标签比例、墙钟插值、行组或序列数移动。

### 6.1 LSPR23 源年度

| 角色 | 活动秒秩 | 允许用途 |
| --- | --- | --- |
| `source-train` | `[0, b_2023(0.80))` | 字段有效性判断、缺失统计、归一化拟合、监督训练和训练内早停 |
| `source-validation` | `[b_2023(0.80), N_2023)` | 单种子模型选择、源域诊断、温度校准和阈值冻结；不得反向更新归一化器 |

序列块不得跨 `cut_2023(0.80)`。同一 2-IP 对可在时间前向的两段中再次出现，但键从不入模；另行报告源验证中“训练期见过/未见过 2-IP 对”两个分面，用于检查身份记忆，不用该分面重选字段或构造。

### 6.2 LSPR24 目标年度

| 角色 | 活动秒秩 | 标签可见性 | 允许用途 |
| --- | --- | --- | --- |
| `target-prefix` | `[0, b_2024(0.10))` | 对训练器、校正器和评价器均不可见 | 四变体共同因果预热；仅 M2/M1+M2 可更新可信正常状态；禁止监督损失、阈值选择和早停 |
| `target-development` | `[b_2024(0.10), b_2024(0.80))` | 仅冻结预测后的评价器可见 | 一次开发评价、预注册指标和困难分面；不能回改字段、构造、阈值或目标前缀长度 |
| `final-test` | `[b_2024(0.80), N_2024)` | 当前完全不可见 | 方法与程序冻结后的独立封存和唯一最终评价 |

该比例是事前冻结的用途预算，不是由 LSPR24 标签或最终结果选出的最优值：前 10% 为有限冷启动期，使 C12 能观察新年度但不能长期占用目标数据后才开始检测；中间 70% 用于覆盖低基率攻击和不同业务阶段，稳定估计 AP、误报与校准；最后 20% 保留足够时间跨度与事件数作为独立最终评价。切点按活动秒秩而非流行数计算，避免高流量突发改变各角色的时间含义。后续可在方法与主协议不变时报告 `5%/10%/20%` 无标签前缀敏感性，但该诊断不得用于改写 10% 主结果、移动最终 20% 或选择最有利比例。

`target-prefix` 可能含恶意流，但不得读取标签后清洗。M2 的可信门必须只读取源模型概率、不确定度、扰动一致性和当前合法输入。若无标签污染导致性能下降，这是机制的有效负结果，不能用目标标签挽救。

所有变体必须按相同顺序消费目标前缀。B0 只做输入/位置预热，M1 更新漂移状态，M2 更新可信正常状态，M1+M2 更新两者；评价从 `target-development` 的第一条完整序列开始。

## 7. 四变体共同缓存、预算和训练协议

### 7.1 缓存模式

共同缓存使用 Parquet 列式主表加 Arrow 可映射张量分片，不保存四份重复数据。最小模式为：

| 字段 | 类型 | 说明 |
| --- | --- | --- |

| `year_role` | 枚举 | 路由，不入模 |
| `sequence_id`、`position`、`valid_length` | 整数/固定字节 | 序列索引，不入模 |
| `available_ns`、`delta_t_us` | `int64` | 绝对值仅排序；模型只可读取分区内非负、截断后的相对 `delta_t_us` |
| `x_value` | `fixed_size_list<float32>[77]` | 固定列序数值 |

### 7.2 种子 42 快速预算

物化主产品不采样。快速缓存只做一次确定性有界抽样，四变体共享结果：

| 角色 | 最大实际流行数 | 抽样规则 |
| --- | ---: | --- |
| LSPR23 `source-train` | 1,048,576 | 以完整 2-IP 序列为单位；源标签允许用于建立 1:1 的“含恶意流序列/全良性序列”训练池；池内按冻结哈希排序，不拆序列 |
| LSPR23 `source-validation` | 262,144 | 标签盲、按 64 个活动时间秩分层、序列哈希确定性抽样；指标按自然样本计算，不做类别重加权 |
| LSPR24 `target-prefix` | 262,144 | 从最早前缀开始保留完整序列，达到上限后停止；不读取标签 |
| LSPR24 `target-development` | 1,048,576 | 标签盲、按 64 个活动时间秩分层、序列哈希确定性抽样；预测冻结后才连接标签 |

总缓存上限为 2,621,440 条实际流，不含填充。若某角色不足上限则全部使用。若源验证抽样后恶意流少于 200 条，可按预注册规则扩大到完整源验证区；该扩展只使用 LSPR23 标签，必须在任何 LSPR24 评价前完成并固定收据。目标开发区不得按类别补样。

训练批次以序列为单位，源训练每批等量抽取两个训练池，不在序列内部删除或复制流。四变体使用相同批次顺序、训练步数、优化器、参数预算、早停规则和混合精度。快速结果只改变候选优先级，不构成论文结论。

### 7.3 归一化

1. 只在 LSPR23 `source-train` 拟合每列中位数和四分位距。
2. 非有限或非法值先转缺失；值槽用源训练中位数填充。
3. 数值字段使用 `(x - median) / max(IQR, epsilon)`，再裁剪到 `[-10, 10]`。`epsilon`、裁剪界和字段列序写入配置，不从目标数据调整。
4. `Protocol` 使用 LSPR23 训练区出现值的冻结词表，另设 `UNK` 和 `MISSING`；LSPR24 新协议只能进入 `UNK`。
5. 年份、分区、2-IP 键、目标前缀统计均不得参与归一化。M2 的正常状态校正不是归一化器重拟合。

### 7.5 阈值与指标

- **主指标**：目标开发区逐流平均精确率（AP，即经验 PR-AUC）。同时报告 `AP/prevalence` 提升倍数。
- **冻结阈值**：仅在 LSPR23 源验证区选择。对全部唯一分数阈值和 `+Inf`，选择满足良性流每百万误报不超过 100 的阈值中召回率最高者；召回并列时选择阈值更高者。目标标签不得改变阈值。
- **阈值指标**：宏平均 F1、恶意类 F1、精确率、召回率、每百万良性流误报、每小时误报、固定 100 次/百万告警预算下召回率。
- **校准与效率**：Brier 分数、15 个等频箱 ECE、吞吐量、峰值显存、训练墙钟和每百万有效流的推理时间。
- **统计**：按 2-IP 序列作 10,000 次非参数自助重采样，固定统计种子 42，报告 AP 和阈值指标的 95% 分位数区间。单种子自助区间不替代后续种子 42/43/44。
- **组合门禁**：`M1+M2` 的 AP 必须超过 B0 和两个单机制；M1 与 M2 各自在预注册的 AP、每百万误报、ECE 三项之一对 B0 产生方向一致的独立增量。否则只记录为未支持或负结果，不调整数据构造。

## 9. 传输与物化成本

### 9.1 本机边界

- LSPR23 ZIP 为 1.925 GB，解压后 CSV 为 10.588 GB；LSPR24 Parquet 为 2.776 GB。
- 本机当前可用空间约 52 GiB、磁盘占用约 88%。本地完整扫描超过 1 GiB，且解压、外部排序和中间 Parquet 会产生约 25–55 GiB 临时 I/O，违反本项目大规模任务移交服务器的门禁。
- 因此本机只做表头、页脚、配置和收据审计，不全量解压或物化。

### 9.2 传输估算

若当前 C56 服务器已保有 LSPR24 原始 Parquet 和现有 5 秒视图，只需传输 LSPR23 ZIP。理论传输时间为：

| 实测吞吐 | 1.925 GB ZIP 纯传输时间 |
| ---: | ---: |
| 10 MiB/s | 约 184 秒 |
| 25 MiB/s | 约 74 秒 |
| 50 MiB/s | 约 37 秒 |

实际还需连接、校验和落盘开销。不得传输 10.588 GB 解压 CSV；服务器应直接从 ZIP 流式读取。同步必须支持续传，不使用 `--delete`，完成后核对大小和 MD5。

### 9.3 Rust 与 Python 路径比较

| 路径 | 预计成本与风险 | 裁决 |
| --- | --- | --- |
| Python/Pandas 全量加载 | CSV 解压后 10.59 GB，加上 LSPR24 2022 万行和对象开销，内存容易达到数十 GiB；还需二次排序和复制 | 禁止作为正式物化路径 |
| Python/PyArrow 或 Polars 流式 | 可行，但跨批 2-IP 键、全局稳定排序和多尺度索引仍需显式磁盘分区；若临时状态无固定上界，不能启动 | 只适合参考实现和小样语义核对 |
| Rust 流式解析 + 哈希分桶 + 桶内稳定外排 | 可直接读取 ZIP/Parquet，按 256 个稳定哈希桶落盘，再逐桶排序和写 Parquet；批大小、桶数、每键历史长度均可固定 | **最快正式路径** |

按约 4000 万级两年流行的量级估算，Rust 在服务器 NVMe 上的解析、分桶、排序和 Parquet 写出预计为几十分钟级，而不是训练时重复扫描。启动前必须在运行配置中给出：256 个桶、每批最多 65,536 行、每条历史最多 128 流、每桶内存上限、临时目录上限 60 GiB、总 I/O 估算和磁盘低水位。若真实输入行数明显高于估算，物化器按空间门禁失败退出，不自动扩大内存。

### 9.4 最快可执行顺序

1. 只读核验 C56 机器身份、实验根、磁盘、内存、LSPR24 原始 Parquet和 `lspr24-screen-wide-v1/dataset-manifest.json`；不得沿用 A44 或其他旧服务器假设。
2. 若 LSPR24 原始 Parquet 已在 C56，只同步 1.925 GB LSPR23 ZIP并复核 MD5；否则比较 2.776 GB Parquet 额外传输与本地计算代价后再同步。
3. 用 Python 小样参考实现核对 101 列解析、77 列交集、缺失规则、2-IP 键和序列顺序；不产生人工训练夹具。
4. 用 Rust 一次流式物化并集主产品、标签/分组侧车和全部索引；不为四个变体重复扫描原始数据。
5. 从主产品列裁剪生成一次共同缓存，复算样本、序列、标签隔离和最终区零访问收据。
6. 门禁通过后通知用户 GPU、显卡、并行数、预计时长和费用，再启动四变体种子 42 快速消融。
