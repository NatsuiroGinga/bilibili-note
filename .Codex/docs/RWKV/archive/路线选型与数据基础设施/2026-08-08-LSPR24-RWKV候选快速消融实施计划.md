# LSPR24 RWKV 候选快速消融实施计划

> **执行要求：** 使用 `subagent-driven-development` 按任务实施；每个实现代理读取 `daily-coding`。本计划以真实开发区实验为验收，不创建人工测试，不让格式化或复审阻塞运行。

**目标：** 在同一 LSPR24 5 秒候选筛选视图、同一数据预算和同一训练预算下，比较普通因果 Transformer、无条件字段交互、RWKV 状态条件字段交互和原生 RWKV 时间递归，判断 C3 是否具有进入正式实验的真实信号。

**架构：** 统一加载器输出 `H=4` 的五个连续时间步，每步包含同一组合法字段。所有神经变体共享训练集归一化、字段嵌入、分类头、优化器、批量、轮数和评价程序；只替换字段交互或时间混合机制。候选筛选只读取训练与验证切分，最终 20% 保持不可见。

**技术栈：** Python、PyTorch、PyArrow、scikit-learn 指标、SwanLab 在线记录、A44 单卡。

## 全局约束

- 数据清单固定为 `runs/data-prepared/lspr24-screen-wide-v1/dataset-manifest.json`。
- 历史长度固定 `H=4`，即四个历史窗加当前窗，共五个时间步。
- 快速消融固定种子 `42`、训练上限 `100000`、验证上限 `20000`、最多 `5` 轮、批量 `512`。
- 主指标为验证集 `PR-AUC`，同时报告宏平均 F1、平衡准确率、精确率、召回率、良性误报率、参数量、训练耗时、推理吞吐和峰值显存。
- 所有变体共享训练样本、验证样本、字段顺序、归一化统计、优化器 `AdamW`、初始学习率 `3e-4`、权重衰减 `1e-2` 和余弦退火调度。
- 只在训练集计算均值和标准差；非有限值用训练中位替换后裁剪到标准化区间 `[-10,10]`。
- 不读取最终测试，不解析 `attack_narratives.json`，不使用 IP、端口、演习身份、既有 IDS 输出或标签派生字段。
- 快速消融只产生候选排序证据，不写成论文正式结论；不得因单种子结果直接宣称支持或证伪。

## 变体矩阵

| 编号 | 变体 | 唯一变化 | 对应问题 |
| --- | --- | --- | --- |
| `B1` | `causal_transformer` | 字段标记加和池化后进入两层因果 Transformer | 普通神经接收基座 |
| `B1F` | `field_attention_transformer` | 每个时间步先做无条件字段自注意力，再进入同一时间 Transformer | 字段交互本身是否有效 |
| `A2` | `rwkv_conditioned_field_transformer` | 上一时间步的 RWKV 状态以零初始化有界门调制当前字段自注意力 | C3 的 RWKV 状态条件是否提供独特增量 |
| `B3` | `rwkv_time_mixer` | 保留同一字段交互，将时间 Transformer 换为参数匹配的 RWKV-7 核心递归 | 原生状态递归对照 |

`A2` 的必要裁决是同时优于 `B1` 与 `B1F`；只优于 `B1` 不能证明 RWKV 状态条件有效。`B3` 只判断原生时间递归在当前短历史上的相对表现，不代表完整官方大模型。

## 任务 1：统一神经输入与模型组件

**文件：**

- 新建 `thesis/experiments/llm_probe/src/flow_probe/lspr24_rwkv_screen_models.py`
- 复用 `thesis/experiments/llm_probe/src/flow_probe/lspr24_screen_dataset.py`

**接口：**

- `reshape_history(features, history_length, feature_count) -> np.ndarray`：把扁平特征恢复为 `[N,H+1,F]`。
- `TrainNormalizer.fit(train_sequence)`：只使用训练数据产生每字段替换值、均值和标准差。
- `TrainNormalizer.transform(sequence)`：输出有限 `float32` 数组并执行固定裁剪。
- `build_screen_model(name, feature_count, field_group_ids, config) -> nn.Module`。
- 每个模型 `forward(x) -> logits`，输入 `[B,5,F]`，输出 `[B]`。

**实现边界：**

1. 共享字段标记器由标量投影、字段嵌入和语义组嵌入组成。
2. `B1` 不做字段间自注意力；`B1F` 使用同一层字段自注意力。
3. `A2` 的状态门初始化为零，使初始行为等于 `B1F`；门值经 `tanh` 或 `sigmoid` 有界，状态只能调制字段交互，不能直接读取标签。
4. `B3` 实现并注明为用于候选筛选的 RWKV-7 核心时间混合，不冒充官方完整语言模型；状态更新必须是按时间顺序的固定状态递归。
5. 记录每个变体可训练参数量；若最大与最小参数量之比超过 `1.15`，启动器必须拒绝运行并输出具体参数量。

**验收：** 只执行 Python 编译和一次真实清单小批加载/前向入口；不创建人工测试。

## 任务 2：统一训练、评价和 SwanLab 入口

**文件：**

- 新建 `thesis/experiments/llm_probe/src/flow_probe/lspr24_rwkv_screen.py`
- 新建 `thesis/experiments/llm_probe/scripts/run_lspr24_rwkv_screen.sh`
- 新建 `thesis/experiments/llm_probe/scripts/remote_launchers/run_lspr24_rwkv_screen_seed42_v1.sh`

**接口与行为：**

1. 运行入口接受数据清单、唯一输出目录和运行名称；种子和快速预算由明确命令行参数保存到 `config.json`。
2. 只加载一次训练与验证数组，四个变体复用相同内存数据和固定样本顺序。
3. 每轮输出变体、轮次、训练损失、验证 PR-AUC、宏平均 F1、累计耗时、吞吐、峰值显存和预计剩余时间。
4. 每个变体按验证 PR-AUC 保存最佳检查点；候选选择只依赖验证区。
5. 输出 `metrics_<variant>.json`、`predictions_<variant>.jsonl.gz`、`training_history.jsonl`、`summary.json`、`environment.json` 和 `checkpoints/`。
6. SwanLab 使用在线模式，每个变体使用独立运行名称并逐轮记录；本地日志与制品是事实源，云端失败不得删除本地结果。
7. 远程启动器使用唯一 `screen` 名与目录，记录 `running/finished/failed`、主命令和 `tee` 退出码；失败不自动覆盖或重跑。

**验收：** 在 A44 上执行真实 `seed=42` 四变体快速消融；运行前通知用户将占用一张 GPU，预计训练阶段 `20–45` 分钟，数据加载时间另计。

## 任务 3：结果裁决

**文件：**

- 更新 `.Codex/docs/RWKV/RWKV路线总控.md`
- 更新 `.Codex/docs/RWKV/2026-08-08-第三章候选方案登记册.md`

**裁决规则：**

1. `A2 > B1F` 才能归因于 RWKV 状态条件；`B1F > B1` 只说明字段交互有效。
2. 同时报告绝对增量与错误相对下降，不以 `16.1%` 作为机械硬门槛。
3. 若 `A2` 的增量小于 `0.005` PR-AUC、训练不稳定或效率代价超过 `1.5` 倍，则保持“未筛选/弱证据”并优先转测 C1 或 C2，不追加事后样本修改。
4. 若单种子出现方向一致且可解释的增量，才进入种子 `42/43/44` 和更大预算；最终测试仍不解封。
