# Task Plan：第三章方案确定与实验筛选

## Goal

在候选登记册的 11 个候选中，用**合格设计的实验**逐条筛选，选出能支撑第三章（26 页 / 33 公式 / 1 算法 / 2 定理 / 1 引理 / 11 图 / 7 表）且提升幅度达到错误相对下降 ≥16.1% 的方案。

## 硬约束（用户已裁决，不再讨论）

- 论文题目可改，只需应用场景与安全相关。
- 必须复用已下载数据集：TQH-C2 v1.2.0、Annotated-Encrypted-Traffic-2026、LSPR24、QUIC-MedNetCom。
- 骨干不锁死，可用大模型 / 编码模型 / CNN；核心思路是**基础模型 + RWKV 机制注入**，而非直接用 RWKV 预训练模型。
- **RWKV-8（ROSA）已放开**，可进入候选与实验。
- 提升口径固定为错误相对下降 `(err_base − err_method)/err_base`，参照 16.1%。
- **不得因对话中的一句话否决未筛选的候选**；只有实验能淘汰候选。

- [x] Phase 1：数据资产盘点与先导筛选（LSPR24 窗口级）
- [x] Phase 2：文献边界核验与骨干调研（12 篇流量基础模型 + 8 篇 RWKV 时序 + 17 份资源笔记）
- [x] Phase 3：候选方案登记册建立（11 个候选，标注证据状态）

- [ ] Phase 6：方案裁决 → 更新路线总控 → 进入第三章写作与建模

## Key Questions

1. ROSA（后缀自动机）在加密流量的结构重复模式发现上是否有效？相对普通 RWKV-7 增量多少？
2. 跨连接状态注入在**去除端点身份泄漏后**是否还有增量？（E-INJ 需重做）
3. 真实背景率（soho 67–198 事件/小时）下，检测 3600 秒信标所需记忆步数 K_min 是多少？是否 >32？
4. 输入模态固定后，骨干替换（Mamba→RWKV-7）的真实增量是多少？（NetMamba 旁证显示仅 0.5–2.6 个百分点）
5. 表格形态的小规模自监督预训练能否绕开"无现成骨干"的空位？

## Decisions Made

- **PINN/R2 路线判死，RWKV 转为论文主线**（用户 2026-08-07）。
- **提升门槛口径改为错误相对下降**，不用绝对百分点——朱的基线 60–72% 而本课题 PR-AUC 已 >0.93，绝对百分点不可比。
- **RWKV-8 放开**（用户 2026-08-08）；无正式论文，引用须标为"官方仓库实现与设计文档"。
- **禁用 TDD**，改 `executing-plans`；审查并行不阻塞实验（仓库 AGENTS.md 强制）。
- **大规模实验上服务器**（208 核 / 754 GB）；本机只留分钟级诊断。规模阈值已写入 `llm_probe/AGENTS.md`。
- **候选只能被实验淘汰**，代理实验只改优先级。

## Errors Encountered

| 错误 | 后果 | 处置 |
| --- | --- | --- |
| 计划全文用 TDD，违反仓库明令禁用 | 计划返工、stage 1 首轮作废 | 全文改为先实现后验证 |
| 把成本主因归为 effort（实为缓存写 53% + 缓存读 35%，输出仅 12%） | 用户按错误归因决策 | 实测更正，改为压制工具调用与上下文 |
| 历史特征拼接写成逐行 Python 循环 | 20 分钟白跑 | 改 `searchsorted` 向量化，44.5 秒 |
| 未 source profile 就断言凭据不存在 | 错误决定在本机跑 | 远程凭据检查一律先 `source ~/.zshrc` |
| 服务器环境探测路径错误（漏 `experiments/`、`find -maxdepth 3` 深度不足） | 重复造 venv，浪费 5 分钟 | 用现成 `llm_probe/.venv` |
| 向 expect 传复杂嵌套内联命令 | 进程静默失败 | 改传脚本 + `bash -n` |
| `/tmp/gpu-exec.exp` 被 macOS 清理 | 推送与启动静默失败 | 重建并在仓库留持久副本 |
| E-INJ 只扫 `features/` 漏掉 `features_D/` | 测试集为空，四组全跳过 | 同时扫两个目录 + 断言 D 存在 |
| E3 合成任务信标与良性边缘分布可分 | 无状态基线碾压，结论无效 | v2 修正后仍有计数泄漏，暂停 |
| E-INJ 状态特征退化为 testbed 指纹（泄漏审计 AUC 0.9998） | 注入组全线崩溃，结论无效 | 需端点内标准化 + 重做 |
| 转述二手数字未回原文（Demystifying 的 ">90%→<47%" 实为 FlowSem-MAE §1.1） | 向用户传递了错误事实 | 已更正；二手数字一律回原文核验 |
| 会话开头判"No skills needed"后不再重扫技能 | 未按规使用 `planning-with-files` 等 | 本文件即补建的持久计划 |
