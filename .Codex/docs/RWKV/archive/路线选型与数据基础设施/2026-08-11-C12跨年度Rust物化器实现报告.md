## 实现内容

### 输入与流程

- LSPR23 通过系统 `unzip -p` 从 ZIP 成员流式读取；内置 CSV 状态机处理引号、双引号转义和跨行字段，不把 10.59 GB CSV 全量解压到磁盘。
- LSPR24 通过 Arrow/Parquet 读取器按字段名建立投影，不依赖物理列位置。
- 原始输入先做仅时间列活动秒扫描，再做开发区行分桶；后续候选选择、精确归一化拟合和正式写出均复用磁盘桶，不为四个变体重复扫描原始输入。
- LSPR24 行先读取和验证时间并计算角色；`available_ns >= target_final_cut_ns` 时立即跳过，之后不读取该行 IP、标签或特征值，不进入开发制品、成员哈希、角色计数或统计。

### 字段、标签与分组隔离

- 共同缓存固定为 `x_value[77]`、`x_missing[77]`，字段顺序来自冻结清单。
- `Protocol` 使用源训练词表；索引 `0` 为缺失、`1` 为未知、词表从 `2` 开始。
- 标签只写独立侧车；目标前缀不创建标签制品且物化时不读取目标前缀标签值。
- 规范 IP 先转 16 字节形式，再按字节序排序为无向端点对，并复用规范元组编码计算 `sha256(tuple_encode("lspr-crossyear-2ip-v1", ip_low, ip_high))`。原始 IP 不写入任何制品。
- 绝对时间、年度、角色、源行号、样本标识和 `2-IP` 键仅用于路由、审计或侧车，不进入 `x_value`。

### 排序与序列

- 四角色先隔离到 256 个稳定哈希桶。
- 每个角色按 `(pair_key, available_ns, start_ns, source_row_index)` 使用既有 `stable_external_sort` 确定性外排。
- 每个 2-IP 对切为最长 128 的连续非重叠块，保留尾块；年度和角色在分桶前已切断。
- 样本清单、序列清单和四角色缓存来自同一最终排序遍历；每个角色记录由各桶稳定排序摘要组合得到的语义 SHA-256。

### 快速缓存选择

- `source-train`：按完整序列是否含恶意流分成“含恶意流序列池”和“全良性序列池”；两个池使用相同行预算，池内按冻结选择哈希排序，不拆序列。收据分别记录两池行数、序列数和成员 SHA-256。
- `source-validation` 与 `target-development`：按各自活动秒秩划分 64 层，层内按冻结序列哈希抽样；选择候选不携带或读取标签，收据固定 `target_label_used_for_selection=false`。
- `target-prefix`：按序列首个可用时刻和稳定哈希排序，从最早完整序列开始保留，不读取标签。
- 四角色选择均以完整序列为最小单位，达到行预算时不拆分；收据记录候选数、入选序列数、实际行数和整体成员哈希。

### 归一化

- 归一化在选择集合冻结后，重新遍历 `source-train` 桶，只观察最终入选源训练序列。
- 对每个数值字段保留所有有效入选值并排序，使用 `round((n-1)*p)` 的最近索引定义计算 Q1、中位数和 Q3；这是精确算法，近似秩误差上界为 `0`。
- 配置把精确分位数容量绑定为不小于 `source-train` 行预算；超过容量立即失败，不使用哈希保留样本或无说明近似。
- `normalizer.json` 记录实际拟合行数、每字段有效值数、中位数、IQR、`epsilon`、裁剪界、协议词表与保留索引。

### 资源、可恢复性与可观测性

- 固定 256 桶、单批 65,536 行、单序列 128 流、最多 64 个同时打开的桶文件、最多 5,000,000 个序列候选。
- 桶载荷逐字节计入 60 GiB 上限；进入外排前再以“桶总字节 + 两倍最大桶字节”做保守临时空间门禁。
- 精确分位数最多保存 `76 × 1,048,576` 个 `f64`，原始数值状态约 608 MiB；配置峰值内存估算为 1.5 GiB。
- 启动日志打印全部状态上界、内存和 I/O 估算、临时上限及磁盘低水位；长阶段打印开始、处理量、吞吐、累计时间和剩余时间状态，不输出 IP、标签、载荷或凭据。
- 每个 Parquet/JSON 文件使用既有 `PartialOutput` 的 `.partial` 提交；完整输出先写 `output_root.partial`，全部收据完成后才原子重命名为正式输出根。

## 高风险路径自检

| 路径 | 自检结论 |
| --- | --- |
| 77 字段顺序 | 配置必须逐项等于编译期冻结数组；Parquet 按名投影；缓存固定长度 77 |
| 标签泄漏 | 目标前缀无标签输出；验证/目标开发候选不含标签；标签不在共同缓存模式中 |
| 最终区隔离 | 最终切点判断发生在 IP、标签和特征逐行取值前；收据固定空最终制品列表和 `final_accessed=false` |
| 2-IP 确定性 | 规范 IP 字节排序、规范元组编码、SHA-256；稳定键包含时间与源行号 |
| 序列边界 | 分角色分桶，按 pair 切块，128 上限、非重叠、尾块保留；三次桶遍历使用同一序列标识算法 |
| 源训练池 | 两标签池独立预算与独立成员哈希；只选择完整序列 |
| 64 层抽样 | 活动秒秩决定层号，层内稳定哈希；不按目标标签补样 |
| 归一化绑定 | 选择先冻结，归一化只观察入选源训练序列；实际观察行数必须等于选择收据 |
| 有界内存 | 批、活动秒、候选、打开文件、序列和精确分位数容量均有硬上限，超限失败 |
| 临时空间 | 桶写入硬上限加外排最大桶保守预留门禁；不自动扩大 |
| 原子发布 | 文件级 `.partial` 加输出根级暂存重命名；既有正式根存在时拒绝覆盖 |
| 可追溯性 | 输入、制品、选择集合和角色稳定顺序均有 SHA-256；行数和隔离原因进入收据 |

## 已知风险

1. 真实数据尚未经过该入口。LSPR23 全量 CSV 词法边界、LSPR24 实际 Arrow 类型、角色实际行数、字段缺失分布和首批制品能否被后续统一加载器消费仍为“实验待证”。
2. 生产机必须提供兼容的系统 `unzip` 和 `df -Pk`。入口会对进程退出码和输出解析失败提供上下文并停止，不会回退到全量解压。
3. `max_selection_candidates=5,000,000`、60 GiB 临时上限和 1.5 GiB 峰值内存是启动前估算。真实数据超过上限时会 fail-closed；应依据首批日志调整配置并重新物化，不能静默突破门禁。
4. 完整序列不可拆，因此各角色实际缓存行数可能略低于上限；源训练两个池的实际行数也可能因尾序列长度不等而略有差异。训练器必须按收据中的两个序列池等量取批，不能把“行数完全相等”误作合同。
5. 源验证抽样后恶意流少于 200 条时，冻结合同允许在任何 LSPR24 评价前按预注册规则扩大到完整源验证区。本入口保留全量源验证主产品与标签侧车，但没有自动读取标签扩大快速缓存；首批门禁若触发该条件，应在统一加载器侧按冻结规则生成新的有哈希收据，不能按目标标签补样。
