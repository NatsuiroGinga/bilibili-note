# LSPR24 与 LSPR25 单数据集选型审查

- **证据截止日期**：2026-08-05
- **决策目标**：在 LSPR24 与 LSPR25 中选择一个数据集，作为“基于 RWKV-7 的恶意流量检测”论文第三、四章的唯一主数据集
- **第三章候选**：方案 A“受序动态记忆＋正常状态生成”；方案 B“状态条件字段交互＋单路 RWKV-7”
- **第四章责任**：复用第三章冻结状态，研究外生流量轨迹上的早期告警／风险约束最优停止
- **证据规则**：数据事实只接受官方 Zenodo、DataCite、正式论文、官方仓库和实际取得的可核验全文；未取得全文的论文数字不进入裁决
- **执行边界**：本轮未下载大型数据、未运行模型、未申请或提交外部访问请求

## 一、唯一裁决

### 1.1 当前唯一首选：LSPR24

**选择 LSPR24，裁决为“数据接入可执行、训练仍须通过 G0”。**

原因不是 LSPR24 更新或更容易，而是它是两者中唯一已经同时满足以下最低可执行条件的数据集：

1. 官方核心流表与辅助文件公开下载，固定 DOI、逐文件字节数和 MD5 可核验；
2. 数据文件许可由 DataCite 明确登记为 `CC0-1.0`；
3. 官方 CyCon 2025 论文全文已取得并逐页核验；
4. Parquet 页脚已经只读核验为 20,227,356 行、21 个行组、101 列，包含流开始与流结束时间；
5. 公开制品包含攻击叙事、Suricata 事件和主机日志，至少为独立事件恢复提供了可审计材料；
6. 核心流表只有 2,775,972,952 字节，适合本机 Rust 流式物化；完成窗口缓存后，2M～10M 参数数值 RWKV-7 的首轮比较可由单张 RTX 5090 顺序执行。

LSPR24 不是无条件放行。其标签代表**红队基础设施或跳板活动关联**，不是逐载荷确认的攻击效果，也不是攻击家族标签。主任务应冻结为：

> **基于已完成网络流因果序列的红队关联恶意活动检测与早期告警。**

第四章主要延迟应从“同一事件中第一条已标恶意流完成”计时。只有攻击叙事、流表和主机侧证能唯一恢复真实动作起点时，才允许增加“红队动作开始至告警”的次级结果。

### 1.2 LSPR25 当前裁决：资料候选，实验 NO-GO

LSPR25 不能作为当前唯一主数据，原因是**文件受限访问构成直接 NO-GO**：

- [官方 Zenodo 记录](https://zenodo.org/records/17093949)公开元数据，但文件状态为 `Restricted`；未登录访问只显示总数据量约 3.8 GB，不显示文件名、精确字节数或校验值。
- 当前无法核验精确行数、模式、时间字段、流完成时间、缺口、标签组合、事件数、攻击叙事或独立事件起点。
- [DataCite DOI 元数据](https://api.datacite.org/dois/10.5281/zenodo.17093949)确认许可为 `CC BY 4.0`，但许可不等于实际下载授权。
- 配套论文真实存在，DOI 为 [10.2139/ssrn.6597680](https://doi.org/10.2139/ssrn.6597680)，但本轮只核验到 SSRN 预印本记录；没有核验到《Computer Networks》的正式卷期、页码或 Elsevier DOI。
- SSRN 声称有 49 页全文，但直接 PDF 与浏览器入口分别受到 403／安全验证阻断。本轮没有实际读到全文，因此摘要中的模型分数、差值、相关系数和配置数量全部禁止参与裁决。

因此，LSPR25 的阻塞不是算力问题，而是**数据真实性细节、可复现性和全文证据尚不可审计**。

### 1.3 条件升级与失败后退路

LSPR25 只有在以下条件全部满足后，才允许重新与 LSPR24 比较，并可能因更低正类占比和更大的流量规模升级为唯一主数据：

1. 获得 Zenodo 文件访问权，并记录所有文件名、精确字节数、校验值和固定版本；
2. 核验精确行数、字段模式、流开始／结束时间和可用时刻；
3. 能在去除 IP、主机名、端口、网段、角色和红队身份字段后形成非退化主特征；
4. 能恢复至少 30 个开发验证正事件，每个主要事件至少形成 8 个有效决策步；
5. 全局时间前向拆分后，训练、校准、验证和封存区均有可用正负轨迹，且会话、主机、事件和重叠窗口无交叉；
6. 取得配套论文全文，逐页核验预处理、正类比例、序列构造、拆分和基线结果。

如果 LSPR24 的 G0 事件恢复、去身份非退化或时间前向覆盖失败，**不得自动改用尚未获批的 LSPR25**。单数据集合同的后退顺序是：

1. 先完成 LSPR25 访问申请；获批且通过上述门禁时，改用 LSPR25；
2. LSPR25 未获批或门禁失败时，判定“Locked Shields 单数据集双章合同”不可行；
3. 若仍坚持一个数据集，改用事件起点明确的 ROSPaCe，并把论文对象收窄为 ROS2／信息物理系统入侵检测；
4. 不用“LSPR24 做第三章、LSPR25 做第四章”规避唯一数据集要求。

## 四、字段、标签、时间与事件合同

### 4.1 LSPR24 已核验事实

Parquet 页脚和既有只读模式审计确认 101 列，至少包括：

- 因果时间：`mTimestampStart`、`mTimestampLast`；
- 流统计：双向包／字节、持续时间、包长、到达间隔、活动／空闲、批量、子流、初始窗口和 TCP 标志；
- 协议状态：协议、三四层协议、连接状态、服务；
- 分组字段：流标识、源／目的 IP 和端口；
- 既有检测器字段：Suricata 签名、类别、严重性和异常事件；
- 身份／标签字段：内外部、网段、EXPO 端点、`Label_src`、`Label_dst`、`Label`。

完整流统计只能在 `mTimestampLast` 之后使用。按开始时间把尚未结束流的最终包数、字节数、持续时间或到达间隔送入模型，属于未来信息泄漏。

页脚时间统计给出最早开始 2024-03-01 17:53:24 UTC、最晚结束 2024-03-07 15:40:16 UTC，墙钟跨度约 142 小时，明显长于 31.6 小时有效活动。这说明必须先识别大缺口，再按有效活动时间拆分，不能按墙钟范围等比切分。

### 4.2 LSPR25 目前只能确认的事实

官方元数据只确认：

- 80 余个 CICFlowMeter 派生特征；
- 二元良性／恶意标签；
- 标签由官方角色元数据和红队基础设施标识派生；
- 目标包括跨年度、现实时间分布漂移评价。

目前**不能确认**：精确列名、是否有流完成时间、时间精度、缺口、流更新语义、事件标识、攻击叙事、主机日志、正事件数或正常连续段。论文题名和摘要证明作者研究了序列构造，但不能替代实际数据模式审计。

### 4.3 标签泄漏风险

两个数据集都存在同源泄漏风险：标签由红队基础设施、角色或跳板关系派生，而 IP、主机名、网段、端口、端点身份或其编码可能直接重建标签。

所有模型和基线必须统一禁止：

- IP、主机名、网段、角色、EXPO 标识及其哈希／编码；
- 源／目的端口、流标识、文件名和绝对日历时间；
- `Label`、源宿标签和标签派生计数；
- Suricata 签名、类别、严重性和异常事件；
- 攻击叙事、步骤名、阶段和目标。

这些身份字段可在数据层构造端点、端点对、会话或事件簇，但不得进入可训练表示。即使只用于分组，也必须增加“整主机／整主机对留出”和分组置换对照，排除模型记住组身份或固定业务角色。

### 4.4 独立攻击事件、起点与流完成时间

| 能力 | LSPR24 | LSPR25 |
| --- | --- | --- |
| 流完成时间 | `mTimestampLast` 已确认 | 未确认 |
| 可恢复流级正段 | 可按同一统计单位连续正窗口构造，待全量 G0 | 未确认 |
| 攻击叙事 | 有 `attack_narratives.json` | 官方文件清单不可见，不能声称存在 |
| 真实攻击动作起点 | 不能默认恢复；`Steps_submitted_time` 不是动作开始 | 未确认 |
| 上位同步事件簇 | 可由时间、目标网段和端点唯一映射后构造 | 未确认 |
| 第四章至少 8 步 | 待 G0 统计 | 当前无法审计 |

LSPR24 的早期检测起点必须优先使用第一条已标恶意流的**完成时刻**。该定义较真实攻击动作起点晚，但因果、可复现，并且不会把流结束后才知道的统计提前使用。

## 五、序列构造与基线难度

### 5.1 序列构造不能留到看结果后选择

LSPR24 当前允许预注册三种统计单位：受保护端点、无序端点对、稳定双向会话。主单位只能依据训练区的连续长度、每步密度、缺口、重复率和 1／4／16／32 步覆盖率冻结，不能按哪个单位使 RWKV-7 增益最大来选择。

LSPR25 配套预印本明确把序列构造作为主要研究因素，摘要列举时间顺序、五元组、IP／IP 对、主机名／主机名对和会话等策略。这个结论足以支持“序列构造必须预注册并纳入公平基线”，但未取得全文前不得引用其具体模型分数或优胜幅度。

### 5.2 基线难度裁决

- LSPR24 公开全文没有提供可直接复用的、去身份、时间前向、同历史预算的 HGB／XGBoost／GRU／Transformer／RWKV 基线。其实际难度仍需本项目 G0 后建立。
- LSPR25 的官方 2.2% 正类描述说明类别更不平衡，但类别不平衡不等于时序机制更难，也不能证明 RWKV-7 有提升空间。
- SSRN 摘要声称 LSPR25 更难、LSPR23／24 接近上限，但由于全文未取得，不能把该定性判断升级为本项目选型事实，更不能引用摘要数字。

正式基线必须共享相同分区、截止时刻、序列单位、历史长度、合法字段、调参次数和种子。至少包括：

- 当前窗口与同历史预算的 HGB／XGBoost；
- GRU、TCN、因果 Transformer、TimesNet、Mamba；
- 官方状态核的普通 RWKV-7；
- 方案 A／B 的共同正常生成对照；
- 固定前缀、单阈值、连续 K 步阈值和无课程约束停止。

## 六、对第三章两套候选的适配

### 6.1 方案 A：受序动态记忆＋正常状态生成

| 条件 | LSPR24 | LSPR25 |
| --- | --- | --- |
| 丰富的下一窗生成目标 | **强**：流、包、字节、持续时间、到达间隔、活动／空闲、协议、连接状态 | **潜在强**：80 余字段，但精确模式不可见 |
| 连续正常历史 | 待 G0；31.6 小时活动与大缺口并存 | 官方 2.2% 正类暗示负类多，但正常连续性未知 |
| 快慢记忆价值 | 可用 1／4／16／32 步、跨缺口重置检验 | 可能可用，但时间字段与跨度未核验 |
| 正常生成污染 | 红队关联标签并非逐流攻击效果，需 1%／5%／10% 污染敏感性 | 同样存在角色标签语义风险，且无法抽样核验 |
| 当前可执行性 | **条件 GO** | **NO-GO** |

方案 A 在 LSPR24 上的优势是生成目标、完成时间和开放数据已经闭合；主要风险是有效活动只有 31.6 小时，未必足以证明“长时”慢状态。必须让 32 步历史、时间块置换和周期清空状态决定是否保留“长时”主张。

### 6.2 方案 B：状态条件字段交互＋单路 RWKV-7

| 条件 | LSPR24 | LSPR25 |
| --- | --- | --- |
| 字段组丰富度 | **强**：101 列可按规模、方向、传输、协议、质量分组 | **潜在强**：80 余 CICFlowMeter 字段 |
| 字段缺失语义 | 待全量审计 | 未知 |
| 状态条件字段交互 | 可用合法数值组，身份／IDS 字段必须排除 | 可能更有价值，但精确字段不可见 |
| 身份捷径风险 | **高** | **高**，标签明确来自角色与红队基础设施 |
| 当前可执行性 | **条件 GO** | **NO-GO** |

如果 LSPR25 后续获批，其更大的流量规模和更低正类比例更适合检验方案 B 是否能在低先验下提取字段组合证据；但这只是待验证假设。当前不能据此选择一个无法下载、无法核验模式的数据集。

### 6.3 A/B 之间的数据集倾向

- **LSPR24 对方案 A 更稳妥**：生成目标、流完成时间和辅助事件材料已知。
- **LSPR25 对方案 B 可能更有挑战性**：字段多、正类低、配套论文专门研究序列分组；但受限访问使该优势目前不可执行。
- 唯一数据集选型不应替代 A/B 模型选型。LSPR24 通过 G0 后，仍应以共享 `C0/A01/B01`、参数匹配和种子 42 的预注册淘汰门决定第三章胜者。

## 七、对第四章早期检测／最优停止的适配

### 7.1 LSPR24

LSPR24 可以建立外生轨迹上的监督最优停止：动作只决定继续观察或告警，不改变网络流量。冻结状态可包括 RWKV-7 状态、监督概率、生成惊讶度，以及方案 A 的快慢分歧或方案 B 的字段交互不确定性。

启动前必须满足：

1. 开发验证区至少 30 个独立正事件；
2. 每个主事件至少 8 个有效决策步；
3. 正常连续块足以估计每小时误报；
4. 事件起点、静默合并阈值和风险预算在看模型结果前冻结；
5. 攻击叙事唯一映射率、歧义率和无匹配率明确；
6. 失败时退回漂移感知课程与时序校准，不把静态阈值包装成强化学习。

### 7.2 LSPR25

当前无法确认流完成时间、攻击叙事、独立事件或 8 步前缀，因此第四章是直接 NO-GO。仅凭“30M 流”和“2.2% 正类”不能推导独立攻击事件数，多个主机或流行也不能当作独立攻击复现。

## 八、本机 Rust 物化与单张 RTX 5090 成本

| 成本项 | LSPR24 | LSPR25 |
| --- | --- | --- |
| 原始核心输入 | 2.776 GB Parquet，20,227,356 行 | 总量约 3.8 GB、超过 30M 流；格式与精确字节未知 |
| 本机 CPU/Rust | 两遍流式扫描：先时间与分区，再开发区字段／标签／事件；按独立段并行、段内稳定排序 | 行数至少约为 LSPR24 的 1.48 倍，预期扫描与排序成本更高；未获文件前不能实测 |
| GPU 数据形态 | 只加载冻结窗口缓存，不把原始流表放入显存 | 同理，但类别不平衡可能需要更多训练窗口或事件采样 |
| 模型档位 | 2M～10M 参数首轮；32 步主序列；种子顺序运行 | 理论上同档可在 5090 执行，当前因数据访问而非显存阻塞 |
| 主要风险 | 全局排序、缺口切分、事件映射、正常生成污染 | 访问审批、未知模式、未知事件、未知精确规模，其次才是吞吐 |

LSPR24 的单卡结论只能写“资源上可行”，不能提前承诺总训练小时数。正式三种子前必须用固定窗口数完成端到端计时、峰值显存、吞吐和缓存体量收据。

- SSRN 摘要中的任何模型分数、差值、相关系数或配置数量已经全文核验；

- LSPR24 的 `Label` 是攻击家族、攻击成功或逐载荷恶意真值；

- 流行数、主机数或同步端点数等于独立攻击事件数；
- 单张 RTX 5090 已被实测能在某个固定小时数内完成三种子矩阵；

## 十三、研究空白与最佳下一方向

当前 Locked Shields 文献仍缺少四类直接证据：

1. 去除主机／红队身份捷径后的时间前向序列基线；
2. 把流完成时间、缺口和独立攻击事件同时纳入的因果序列合同；
3. 正常状态条件生成是否改善监督检测，而不仅是下一窗拟合；
4. 在事件级误报预算下，RWKV-7 状态能否减少观察步数和检测延迟。

最值得推进的研究方向是：**先在开放的 LSPR24 上冻结泄漏清洁、流完成因果、事件分组和序列构造，再比较普通 RWKV-7、方案 A 和方案 B；只有第三章状态确有增量且事件门禁通过，才启动第四章风险约束停止。**

LSPR25 的最佳用途不是当前替换 LSPR24，而是访问获批后的条件升级候选。若其 G0 通过，可用同一合同重新裁决；在此之前，不让“年份更新”和未全文核验的摘要分数推翻一个已经可下载、可校验、可物化的数据集。
