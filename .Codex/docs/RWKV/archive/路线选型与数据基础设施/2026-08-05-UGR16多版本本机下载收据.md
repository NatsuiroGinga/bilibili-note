## 5. 验收结果与封存边界

1. 24 个本机文件的实际大小逐一等于固定提交 API 中的官方大小；总大小也完全相等。
2. 官方 API 把这些路径登记为大文件 Git Blob，最小文件仍为 `861,370 B`；本机大小全部与之相等，因此它们不是约 100 至 150 字节的 Git LFS 指针文件。
3. 仅训练区 `Xtrain/Ytrain` 被 CSV 结构检查读取。所有训练文件均可流式读取，行数和字段数稳定；除 v2noIRC 外，去掉表头和 `Row` 索引列后的维度与官方 README 相容。
4. 所有 `Xtest/Ytest` 只进行了文件大小和 SHA-256 字节完整性计算，未交给 CSV 解析器，未读取标签、样本值或实际行列。表中的测试维度只转录官方 README，版本选择阶段继续封存。
5. v2 与 v2noIRC 的四对 SHA-256 全部相同。实际 v2noIRC Xtrain 表头为 134 个特征，而不是 README 声称的 132 个；这是官方仓库内部矛盾，不得通过本地删列或改名掩盖。
6. v1、v2、v2noIRC 的 Xtest/Ytest 分别逐字节相同；v3、v4、v3v4 的 Ytrain/Ytest 分别逐字节相同。这些重复关系来自固定提交原件，不代表版本特征相同。

## 6. 后续使用门禁

- 版本选择只允许读取每版训练区，并先按连续时间块从训练区冻结 `train/calibration/dev-validation`；不得按分钟行随机拆分。
- 官方 `Xtest/Ytest` 在版本、字段、归一化、阈值、检查点和成功轨全部冻结前保持封存。
- v2noIRC 暂不作为独立版本参与排名，除非上游作者或新固定提交澄清 132 维文件缺失问题。
- 本收据只完成下载、来源、版本、大小、哈希和最小结构验收；未处理数据、未运行模型、未修改两份恢复文档。
