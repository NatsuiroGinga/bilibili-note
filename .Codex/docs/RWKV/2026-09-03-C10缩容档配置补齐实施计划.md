## 关键事实：C10 与 C00 的训练图完全相同

C11 配置中 `entity_aggregation.numeric_provenance.scope` 原文：
「仅两处实体分数聚合挂载点（**BER 排序损失内的 `S_e`**、**评价期实体得分**）」。

C10 是 `z2=0`，**没有 BER 排序损失**，故 ETA 只作用于评价期。
**推论：C10-half 的训练与 C00-half 逐位等价，只有最终评价聚合口径不同。**

这带来两个后果：

1. **速度按 C00 估**：`3.403` 步/秒、单轮约 `5.6` 分钟、20 轮约 `1.9` 小时
   （不是 C01 的 `14.7` 分钟/轮）。
2. **免费的正确性检查**（任务 4）：两个运行的模型权重应当逐位相同。
   若不同，说明 ETA 意外进入了训练图，**四格设计的前提就是错的**，必须停下报告。

**不能复用 C00 检查点省这 1.9 小时**：宿主无纯评价入口（仅
`--validate-config` / `--calibrate-runtime` / `--run` / `--resume`），
且 `--resume` 限定 `resume_scope: same_run_same_profile_only`（`:3032`），
C10 是不同 `run_id` 与不同科学身份，不合法。

- [ ] **步骤 1：以 C00 为底，取 C11 的 ETA 块**

用 Python 读两份配置并合成，**不要手写整份 JSON**（83 个字段手抄必错）：

```python
import json, pathlib
d = pathlib.Path("configs")
c00 = json.loads((d / "ch3-ft-c00-halfwidth-screening-v1.json").read_text(encoding="utf-8"))
c11 = json.loads((d / "ch3-ft-c11-halfwidth-screening-v1.json").read_text(encoding="utf-8"))

c10 = json.loads(json.dumps(c00))                      # 深拷贝，避免共享引用
c10["mechanism"] = {"entity_aggregation": json.loads(json.dumps(c11["mechanism"]["entity_aggregation"]))}
c10["identity"]["run_id"] = "ch3-ft-c10-halfwidth-screening-v1"
c10["identity"]["candidate_key"] = "entity-tail-aggregation-c10-dual-selection"
c10["identity"]["science_contract_version"] = c11["identity"]["science_contract_version"]
c10["evaluation"]["entity_aggregation"] = "entity_tail_mean_over_validation_flows"
c10["data"]["reuse_input_transform_from"] = "ch3-ft-c00-halfwidth-screening-v1"
c10["tracking"]["group"] = "ch3-ft-c10-halfwidth-screening-v1"
c10["paths"]["output_root"] = c00["paths"]["output_root"].replace("c00", "c10")

(d / "ch3-ft-c10-halfwidth-screening-v1.json").write_text(
    json.dumps(c10, ensure_ascii=False, indent=2) + "\n", encoding="utf-8")
```

**注意 `paths.output_root` 的替换**：若 C00 的该值不含字面 `c00`，
`replace` 会静默无效并让两个运行写进同一目录。**先打印确认再写**。

- [ ] **步骤 2：核对三处关键字段**

### Task 4：C10 跑完后做等价性检查（**本计划的关键验证**）

**Files**

- [ ] **步骤 1：比对两个运行的模型权重**

因 ETA 在 `z2=0` 时只挂评价期、不进训练图，两者训练应逐位等价：

```python
import torch
a = torch.load("runs/diagnostics/ch3-ft-c00-halfwidth-screening-v1/checkpoints/inflight.pt",
               map_location="cpu", weights_only=False)
b = torch.load("runs/diagnostics/ch3-ft-c10-halfwidth-screening-v1/checkpoints/inflight.pt",
               map_location="cpu", weights_only=False)
sa, sb = a["model_state_dict"], b["model_state_dict"]
assert sa.keys() == sb.keys(), "参数名集合不同"
diff = [k for k in sa if not torch.equal(sa[k], sb[k])]
print("权重不同的张量数:", len(diff), diff[:5])
print("训练损失序列相同:", [e["mean_training_loss"] for e in a["history"]] == [e["mean_training_loss"] for e in b["history"]])
```

预期：`权重不同的张量数: 0`，训练损失序列相同为 `True`。

- [ ] **步骤 2：若不为 0，停下报告**

**这不是可以忽略的数值噪声。** 权重不同意味着 ETA 进入了训练图，
而四格设计假定它在 `z2=0` 时不进——**该前提被证伪，四格的解释就要重写**。
把两个运行的 `history` 与配置 diff 一并写进 `.Codex/docs/`，交用户裁决，不要自行修补。
