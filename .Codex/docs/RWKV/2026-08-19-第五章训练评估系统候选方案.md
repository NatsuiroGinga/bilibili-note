## 一、候选题目与一句话故事

### 1.1 推荐题目

**面向跨年度网络攻击状态检测的训练与评估系统设计与实现**

备选题目为：

1. **网络攻击状态检测训练与评估系统的设计与实现**。
2. **支持多骨干机制路由的网络攻击状态检测训练与评估系统设计与实现**。

推荐首选题目。它同时说明任务对象、跨年度评价场景和系统章性质，不把尚未实现的具体技术栈或第四章候选写入题名。

### 1.2 一句话故事

第三章回答跨流历史表示与实体级决策能否提高跨年度网络攻击状态检测能力，第四章研究长实体证据保持与目标年度预算标定，第五章把已冻结机制、候选接口、统一数据合同和评价协议组织成一个可配置、可追溯、可复核的训练与评估系统。

### 1.3 本章完成的任务

本章不继续扩展研究机制，而是回答四个工程问题：

1. 同一份 LSPR 数据合同如何服务多种骨干和不同机制组合。
2. 系统如何根据模型能力启用、禁用或拒绝不兼容机制。
3. 训练、推理、评价、资源和标签访问过程如何留下可复核收据。
4. 系统封装后是否保持参考入口的检测结果，并把额外时间和资源开销控制在预注册范围内。

## 二、为什么第五章不再提出新算法

### 2.1 朱焱雷论文的直接证据

朱焱雷第五章题为“加密流量分析集成平台与评估系统的设计与实现”，印刷 p.73 至 p.87。其 5.1 明确说明系统用于验证第三章 DS-RGO 与第四章 DF-ACR 的工程有效性，见印刷 p.73；5.6 明确把本章定位为把两章算法转化为系统功能，见印刷 p.87。摘要将贡献分成两个算法和一个原型系统，见印刷 p.I；第六章再次按 DS-RGO、DF-ACR、ETADS 系统三项总结成果，见印刷 p.89。

朱焱雷第五章共有 10 幅图、5 张表、0 个编号公式，没有新增算法框、定理或引理。该事实表明其第五章承担的是集成、部署与验证责任，而不是第三个算法创新责任。

### 2.2 本课题的裁决

本课题第五章同样不提出第三个创新算法，理由如下：

1. 第三章 CPA-ELP 已承担表示层与决策层机制贡献，第四章 DTEP-PBC 候选承担长实体和预算标定问题。第五章再造算法会产生新的问题定义、共同预算基线、独立消融、联合消融和正式实验负担。
2. 系统需要证明的是统一接口、路由正确性、结果一致性和运行可追溯性。骨干感知路由、任务状态机、资源准入和结果看板属于系统设计，不应包装成算法原创。
3. 第四章当前仍是实验待证。第五章应先为候选保留受控接口，而不是通过系统叙事提前把候选升级为有效算法。
4. 三章递进关系已经完整：第三章解决检测表示与聚合，第四章处理第三章暴露的长实体与预算问题，第五章完成可运行和可核验的工程承载。

### 2.3 允许写入的系统亮点

以下内容可以作为系统设计亮点，但不得称为新算法：

- 基于能力清单的多骨干机制路由。
- 标签访问顺序和选择封印的系统级强制检查。
- 数据、模型、配置、指标和运行状态的一致性收据。
- 失败任务隔离、新身份重跑和不可覆盖运行目录。
- 参考命令入口与系统入口的检测结果一致性核验。

## 四、四层系统架构

### 4.1 第一层：数据与制品层

该层只提供统一数据和长期制品，不包含模型专用的一次性数据副本。

核心对象包括：

- LSPR23 官方源年度数据与 LSPR24 官方目标年度数据。
- 数据模式版本、输入哈希、字段清单、实体主键、标签连接和成员计数。
- 第三章冻结模型、第四章候选模型接口及其清单。
- 配置、模型权重、日志、状态、哈希、运行清单和聚合指标。

禁止在该层长期保存预处理矩阵、标签数组、折成员表、逐样本概率、逐样本预测和新的拆分缓存。

### 4.2 第二层：检测计算层

该层执行统一加载、特征选择、模型前向、训练和评价计算，包含：

- 统一数据加载器和字段组选择器。
- 实体因果历史构造与标签隔离检查。
- 多层感知机、沿流序列因果卷积、全注意力、门控循环、XGBoost 等模型适配器。
- CPA-ELP 表示层和决策层机制。
- DTEP 和 PBC 的禁用态接口，以及未来满足晋级条件后的实现挂载点。
- 逐流指标、实体指标、误报预算指标、分桶指标和效率指标计算器。

模型适配器只能从统一清单选择字段、历史关系和训练目标，不得各自重新扫描、解释或物化原始数据。

### 4.3 第三层：任务编排与审计层

该层负责把用户请求变成可追溯的运行，不参与修改研究结论。

主要职责为：

- 参数模式校验和非法字段拒绝。
- 模型注册、能力发现和机制路由。
- CPU、内存、GPU 和磁盘资源准入。
- 任务排队、状态转换、取消、失败和新身份重跑。
- 标签访问时序、选择封印和目标年度读取审计。
- 运行目录、配置、模型、日志、聚合指标和哈希的关联。
- 参考命令入口与系统入口的一致性比较。

### 4.4 第四层：交互展示层

该层提供最小可用的配置和结果查看能力，不承担重新计算或手工修改指标。

最小页面包括：

1. 实验配置与路由说明页。
2. 任务状态与资源轨迹页。
3. 跨年度检测结果与预算曲线页。
4. 制品、哈希和审计收据页。

界面必须显示机制的证据状态。DTEP、PBC 和联合候选在未通过实验门禁时显示“实验待证、不可执行”，而不是提供可启用开关。

## 五、端到端数据流

系统数据流冻结为以下顺序：

1. 用户选择数据合同版本、模型、机制组合、训练或评价模式和运行身份。
2. 编排层解析模型能力清单，拒绝不兼容组合并生成路由决定收据。
3. 数据层核对来源、清单、哈希、模式版本、字段数、实体键和标签连接。
4. 字段门确认 83 个合法入模字段，确认原始 IP 只作实体分组键，确认 18 个禁止字段零入模。
5. 资源门核对 CPU、cgroup 内存、GPU 和磁盘，失败时任务直接进入失败状态且不启动训练。
6. 计算层从统一加载器取得源年度训练输入和冻结历史表示。
7. 训练模块按路由运行骨干和允许的机制，实时输出聚合训练状态，不持久化逐样本预测。
8. 训练完成后原子保存模型、配置、环境和运行收据，再进入评价阶段。
9. 评价模块按冻结协议读取 LSPR24；任何选择、阈值或尺度变更均不得消费目标标签。
10. 如未来启用 PBC，必须先原子落盘选择封印，随后评价进程才可读取目标标签。
11. 指标模块计算逐流 AP、实体 AP、DR@1%/2%/4%FPR、预算曲线、五个实体长度桶和资源指标。
12. 展示层只读取聚合指标和审计收据，生成页面和导出表，不允许手工改写数值。

## 六、第三章与第四章的接入和路由规则

### 6.1 模型能力清单

每个注册模型必须声明以下能力，不允许根据模型名称硬编码猜测：

| 能力键 | 含义 |
| --- | --- |
| `supports_causal_prefix` | 能否消费实体内因果前缀表示 |
| `supports_entity_pooling` | 能否输出供实体级幂平均池化使用的逐流分数 |
| `supports_fixed_dyadic` | 能否消费固定二进近期证据特征 |
| `supports_pilot_calibration` | 能否提供 PBC 所需的可比概率和源混淆收据 |
| `supports_training` | 是否支持系统内训练，而非只加载冻结权重评价 |
| `supports_gpu` | 是否需要或允许 GPU 资源 |
| `evidence_status` | 已冻结、诊断用、实验待证或禁止执行 |

### 6.2 CPA-ELP 接入

CPA-ELP 是第三章已冻结的方法，由表示层因果前缀跨流聚合和决策层实体级可学幂平均池化组成。系统接入遵守以下规则：

1. CPA 与 ELP 必须分别可禁用，以支持 C00、C01、C10、C11 四格复核。
2. 主实验基座沿用先注册的多层感知机，不根据 LSPR24 结果选冠军。
3. 系统可注册第三章已报告的四种等参数神经骨干，并允许按用途选择，但不得把骨干本身写成贡献。
4. XGBoost 的 CPA-ELP 接入使用已冻结的字段和聚合合同，不与约 90 千参数神经骨干混为同一模型。
5. 系统评价必须显示逐流 AP、实体 AP 和 DR@4%FPR，不得只展示对本方法有利的实体 AP。
6. 第三章主 C11 全精度锚点 `e_lp=0.518350415398`、`fap=0.291842625120`、`dr_main=0.703457446809` 只用于系统一致性验收，不作为新系统实验结果。

### 6.3 DTEP 接口

DTEP 当前为设计可行、实验待证。系统只预留以下接口：

- 固定尺度族和尺度模式版本。
- 原始 83 维当前流表示、长历史表示和固定二进近期表示的输入位置。
- 模型能力键 `supports_fixed_dyadic`。
- 源年度方向门、目标年度一次评价和分桶聚合结果的收据字段。

在 DTEP Q0 未通过源年度三折方向门、目标评价和效率门之前：

- 系统不得执行 DTEP。
- 界面不得提供可用开关。
- 文档不得写“已接入”“已改善长实体”或“已提高检测性能”。
- 不得因为系统需要而修改尺度表、融合权重或评价子集。

### 6.4 PBC 接口

PBC 当前为设计可行、实验待证。系统只预留以下接口：

- 目标先导比例、实体 FPR 预算和源冻结阈值字段。
- 源混淆收据、无标签告警比例和 BBSE 准入结果。
- 精确回退原因和源阈值回退路径。
- 选择封印、标签首次读取时刻和评价结果收据。

在 PBC Q0 未通过预注册门槛之前，系统不得执行 PBC。未来若通过，仍必须强制“先封印、后读标签”，后段不得重新取分位数、做 top-k 或用后段全体分数选阈值。

### 6.5 联合路由

DTEP-PBC 联合入口只有在以下条件全部成立后才可从“实验待证、不可执行”变为可执行：

1. DTEP 独立门禁形成有效证据。
2. PBC 独立门禁形成有效证据。
3. 联合消融在共同预算、同骨干和同一评价协议下完成。
4. 长实体、总体指标、预算指标、告警时延和效率边界均有聚合制品。
5. 路线恢复卡正式裁决其可进入第四章。

任何一项不成立时，系统必须拒绝联合路由，不得用接口存在代替实验支持。

## 七、核心模块及最小接口

### 7.1 统一数据合同模块

输入：数据合同版本、来源清单和使用阶段。

输出：

- 模式版本和数据来源标识。
- 输入文件哈希及行数。
- 83 个合法字段清单。
- 18 个禁止字段清单和零入模断言。
- 实体主键、时间顺序和标签连接规则。
- LSPR23 与 LSPR24 成员数和实体数收据。

失败条件包括字段缺失、禁止字段入模、实体键不稳定、时间顺序破坏、标签提前连接或清单哈希不一致。

### 7.2 任务状态模块

建议使用以下不可逆主状态：

`CREATED → VALIDATING → QUEUED → RUNNING → EVALUATING → COMPLETED`

任一非终态可以进入 `FAILED` 或 `CANCELLED`。规则如下：

- `COMPLETED` 必须同时具备退出码 0、完整聚合指标和收据完整性通过。
- 失败任务的运行目录不得覆盖；重跑必须使用新身份并指向父任务。
- `RUNNING` 不能由页面按钮直接改成 `COMPLETED`，只能由后端收据驱动。
- 候选机制被路由拒绝时停在 `VALIDATING` 并进入 `FAILED`，不生成伪运行目录。

### 7.3 模型注册与路由模块

模型注册记录至少包含：

- 展示名称和稳定内部键。
- 模型类别、参数量和权重清单。
- 输入字段组、历史表示和聚合算子。
- 能力键及证据状态。
- 训练入口、评价入口和参考运行锚点。
- 已知适用边界和禁止组合。

路由输出必须包含“实际启用的机制、被禁用的机制、禁用原因、配置哈希和注册表版本”，不得静默降级。

### 7.4 训练与推理模块

训练模块只接收通过数据门、路由门和资源门的任务。推理模块必须加载冻结权重和清单，禁止根据目标年度结果修改模型、阈值或特征。两者共用统一加载器和模型适配器，不建立系统专用数据副本。

### 7.5 指标模块

核心指标固定为：

- 主指标：实体 AP。
- 补充检测指标：逐流 AP。
- 工作点指标：DR@1%FPR、DR@2%FPR、DR@4%FPR。
- 曲线：实体级告警预算曲线。
- 困难分面：实体流数桶 `1-2`、`3-10`、`11-100`、`101-1000`、`1001+`。
- 效率指标：训练壁钟时间、评价壁钟时间、吞吐量、CPU 峰值内存、GPU 峰值显存和制品体积。

指标模块必须同时输出分母、有效样本数、实体数、正实体数、阈值来源和标签读取阶段，不接受只有百分比的结果。

### 7.6 审计模块

每个完成任务至少保存：

- 运行身份、父任务和状态时间线。

## 十、三类验收实验与预注册通过条件

以下阈值是候选方案的预注册建议，不是已经达到的结果。实施前由主代理和用户冻结；实施后不得根据结果放宽。

### 10.1 功能与路由验收

#### 测试范围

至少覆盖：

1. 合法 83 字段合同通过。
2. 任一禁止字段入模时拒绝任务。
3. 原始 IP 只作实体分组键，不进入模型张量。
4. CPA、ELP 四格组合均按请求路由。
5. 不兼容模型与机制组合被明确拒绝。
6. DTEP、PBC 和联合候选保持不可执行状态。
7. 任务从创建到完成或失败的状态转换正确。
8. 资源门失败时不启动训练。
9. 失败重跑使用新身份且不覆盖父目录。
10. 完成任务生成规定的配置、模型、日志、状态、哈希和聚合指标。
11. 页面显示的路由、指标和制品与后端收据一致。
12. 不生成逐样本预测、标签数组或新拆分缓存。

#### 通过条件

- 全部预注册功能用例通过，允许失败用例数量为 0。
- 所有非法输入均在训练启动前被拒绝，静默忽略和静默降级次数为 0。
- 所有 `COMPLETED` 任务均满足退出码 0、指标齐全和审计收据齐全。
- 所有候选禁用态测试均确认 DTEP、PBC 和联合入口没有执行模型或读取目标标签。

### 10.2 性能与资源开销验收

#### 比较合同

系统入口与参考命令入口必须在同一服务器、同一空闲资源状态、同一数据成员、同一模型权重、同一批量、同一精度和同一评价配置下比较。先完成一次不计时预热，再各运行 3 次，以中位数报告；顺序交替，避免只让一方总在热缓存下运行。

#### 指标

- 训练任务提交至计算启动的编排延迟。
- 参考训练片段与系统训练片段的壁钟时间。
- 冻结权重评价吞吐量和总壁钟时间。
- 主机峰值 RSS 和 GPU 峰值显存。
- 长时间任务的退出码、死锁、内存溢出和状态滞留。

#### 通过条件

- 冻结权重评价吞吐量不低于参考命令入口中位数的 95%。
- 同一训练片段的计算阶段壁钟时间不超过参考命令入口中位数的 105%。
- 系统封装引入的 GPU 峰值显存增量不超过参考入口峰值的 5%。
- 系统封装引入的主机峰值 RSS 增量不超过参考入口峰值的 10%。
- 代表性训练任务和全量冻结权重评价均以退出码 0 结束，不出现死锁、任务状态滞留或未记录的内存溢出。

若硬件波动使相对阈值无法稳定复现，应在看结果前通过独立空载测量重新冻结重复次数和容差，不得在看到候选系统结果后修改阈值。

### 10.3 检测结果一致性与审计验收

#### 第三章冻结结果复核

使用第三章冻结 C11 权重、同一 LSPR24 成员和同一指标实现，分别通过参考命令入口与系统入口评价。通过条件为：

- 评价流数、实体数、正实体数和五个桶成员数逐项完全一致。
- 逐流 AP、实体 AP 和 DR@4%FPR 的绝对差均不超过 `1e-10`。
- 系统入口对全精度锚点 `0.291842625120 / 0.518350415398 / 0.703457446809` 的绝对差均不超过 `1e-10`。
- 预算曲线各冻结工作点的分母、阈值方向和检出数完全一致。
- 运行结束后不存在逐样本预测、目标标签副本或拆分缓存制品。

如果第三章权重清单独立复核发现锚点变化，应先修正第三章权威制品，再重新冻结本测试；不得由系统测试自行选择更有利锚点。

#### 第四章候选审计

在 DTEP、PBC 仍为实验待证时，通过条件只包括：

- 三个候选入口均被拒绝执行。
- 界面和导出报告均显示“实验待证、不可执行”。
- 没有读取 LSPR24 标签、没有生成候选效果指标、没有把接口存在写成已支持。

若第四章以后正式晋级，必须另行冻结其参考制品、同骨干基线、独立消融、联合消融和一致性锚点，再新增验收用例；不得用本方案预留接口直接推断通过。

## 十三、第三、四、五章的整体关系

### 13.1 第三章到第四章

第三章 CPA-ELP 用因果前缀跨流聚合和实体级可学幂平均池化建立跨年度网络攻击状态检测方法。冻结分桶诊断显示该组合在短中实体有利，但在 `101-1000` 和 `1001+` 长实体桶上显著有害。第四章据此研究双时域证据保持和先导段预算标定，而不是重新选择第三章冠军骨干。

### 13.2 第四章到第五章

第四章只有在 DTEP、PBC 独立门禁和联合消融形成有效证据后，才产生可执行的统一候选。第五章当前先冻结数据、能力、路由、封印和审计接口，使第四章无论被支持、缩小或否决，都能以真实状态进入系统：

- 支持时，按正式恢复卡裁决开放对应路由。
- 部分支持时，只开放得到证据的部件。
- 否决时，保留拒绝原因和历史接口记录，不伪造功能。

### 13.3 第五章的闭合责任

第五章不再证明新机制优于基线，而是证明：

1. 第三章冻结方法能够通过统一系统入口复现参考结果。
2. 第四章候选状态能够被路由和界面如实约束。
3. 多骨干、数据、任务、指标和制品之间不存在静默错配。
4. 系统封装没有超过预注册的性能和资源开销。
5. 所有结论均能回到配置、模型、日志、哈希和聚合指标。

由此形成“方法机制、困难场景改造、统一训练评估载体”的三章递进，而不是三个互不关联的算法。
