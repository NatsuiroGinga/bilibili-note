实现 N-08 独立入口，在不运行已撤销三折代码的前提下，按原 MLP 协议 A 完成：

1. LSPR23 C00 下 R0 线性输入、R1 字段感知输入、R2 同参普通投影的单次固定训练/验证比较；

## 六、输入适配器与参数量

输入适配阶段固定隐藏宽度 `C=112`、头大小 `16`、LoRA 维 `8`。共同 RWKV、融合、输出与 `p_log` 参数为 `82,322`。

### 6.1 R0：线性输入效率锚

```text
Linear(83,112,bias=True)
```

- 适配器参数 `83×112+112=9,408`。
- 总参数 `91,730`，与既有协议 A RWKV-7 锚逐位一致。

### 6.2 R1：字段感知输入

每个字段标量先经共享 `Linear(1,15)`，再加独立字段嵌入和所属语义组嵌入；每组对字段 token 取均值，12 个组向量拼成 180 维，经 `Linear(180,112)`、`LayerNorm(112)` 和共享输出尺度合成为**一个**逐流表示。

参数量：

```text
共享标量投影       1×15+15       =    30
字段身份嵌入       83×15         = 1,245
语义组嵌入         12×15         =   180
组表示合成         180×112+112   =20,272
LayerNorm          112+112       =   224
输出尺度           1             =     1
合计                              21,952
```

维度 15 由精确同参方程机械解出，不是标签调参：`1441q+337=21,952` 的唯一正整数解为 `q=15`。

### 6.3 R2：不分字段语义的同参普通投影

```text
Linear(83,112,bias=True) -> ReLU -> Linear(112,112,bias=False)
```

- 参数 `9,408+12,544=21,952`，与 R1 精确相同。
- 总参数 R1/R2 均为 `104,274`。

R1 相对 R2 的差异只允许来自字段身份、语义组和组内汇聚，不得增加字段注意力、预训练或额外损失。

### 6.5 输入适配不是容量上限

- R0 的 `91,730` 参数只作效率与旧实现回归锚。
- R1/R2 的 `104,274` 参数只用于输入语义消融，二者精确同参不代表 RWKV-7 能力上限。
- 输入适配器冻结后必须执行第七节容量筛选；禁止直接把约 90K/104K 四格结果写成 RWKV 模型族裁决。

### 6.6 初始化可比性

- 每个候选与每格开始前重置 Python、NumPy、PyTorch CPU/CUDA 到种子 42。
- 模型构造先初始化共同 RWKV、融合和输出模块，再初始化输入适配器，使三候选共同参数初值相同。
- RWKV-7 参数初始化逐字复用固定官方提交；R1 字段/组嵌入 `Normal(0,0.02)`，其余适配层使用 PyTorch 固定种子默认初始化，输出尺度初始为 1。

## 七、RWKV-7 容量候选、时间混合与优化器合同

### 7.1 容量候选来源

容量阶段固定胜出适配器类型，不再比较输入。三档按顺序：

| 容量 | 层数/宽度 | 头/LoRA | 来源与角色 |
|---|---|---|---|
| K0 | 1 个时间混合块，`C=112` | `16/8` | 既有 91,730 参数效率与回归锚；不代表上限 |
| K1 | 3 个时间混合块，`C=576` | `64/32` | 层数来自 RWKV-TS 论文的 3 层配置；576 是不超过 5,355,649 参数 GRU 资源邻域的最大 64 倍数机械解 |
| K2 | 3 个时间混合块，`C=768` | `64/32` | 直接取 RWKV-TS 论文的 3 层、隐藏 768 配置；参数量低于已发表 10,729,345 参数 Transformer 资源锚 |

K1/K2 使用 PreLN 残差时间混合块；第 2、3 层实现官方 value residual。为保持本任务边界，不增加 ChannelMix/FFN、词嵌入或语言模型头。该结构是“RWKV-7 时间混合的表格时序任务适配”，不是完整语言模型复现。

三层容量共同部分参数公式为：

```text
P_common(C,r)=14C²+22Cr+49C+2
P_R0_adapter(C)=84C
P_R1_adapter(C)=1456+183C
P_R2_adapter(C)=C²+84C
```

机械参数表：

| 容量 | 胜出 R0 时 | 胜出 R1 时 | 胜出 R2 时 |
|---|---:|---:|---:|
| K0 | 91,730 | 104,274 | 104,274 |
| K1 | 5,126,978 | 5,185,458 | 5,458,754 |
| K2 | 8,900,354 | 8,977,842 | 9,490,178 |

K1 的 R2 组合略高于 GRU 参数数只作透明披露；5.355M/10.729M 是资源参照而非硬等参数门。

### 7.2 容量筛选顺序

1. 输入适配阶段胜出 C00 即为 K0 C00，可直接进入容量候选表。
2. 顺序训练 K1 C00；完成第一轮后，以真实训练、验证、逐轮权重写盘成本重算剩余总 GPU 时间。
3. K1 完整有效后，只有 4.5 GPU 小时累计门仍允许时才启动 K2 C00。
4. 容量只按固定验证逐流 AP 选择；全精度相等时取参数较少者，再按 K0/K1/K2 顺序。
5. 只有容量与输入适配组合共同封印后，才运行四格。

若资源门阻止 K1 或 K2，必须写 `capacity_upper_bound_not_verified_due_to_resource_cap=true`。这不是 RWKV-7 科学失败，也不得把 K0 当作已验证模型族上限。

### 7.3 时间混合

- K0 为单层 `layer_id=0`，无 value residual 分支；K1/K2 为三层，后两层按官方公式启用 value residual。
- K1/K2 每层使用 `x = x + TimeMix(LayerNorm(x))`，初始状态不跨序列。
- `rwkv7_op` 的矩阵状态、`r/w/k/v/a/b` 全部强制 FP32。
- 递归状态只保留当前批次，形状 `[B,H,N,N]`，不跨实体、序列或批次复用。
- 补零位置输入、隐藏和输出严格归零；有效位置 `t` 只依赖 `<=t`。
- 不把纯 PyTorch `for t in range(T)` 路径宣传为官方加速实现。

### 7.4 参数组

基础学习率 `0.002`、AdamW、梯度裁剪 `1.0`：

1. `time_mix.w0`：学习率 `0.004`、权重衰减 0。
2. 名称含 `.weight` 且压缩后维数至少 2 的大矩阵：学习率 `0.002`、权重衰减 `0.01`。
3. 其余参数，包括 `x_*`、LoRA、`a0/k_k/k_a/r_k`、归一化、偏置、字段身份和 `p_log`：学习率 `0.002`、权重衰减 0。

运行收据保存每组参数名、数量、学习率和衰减，组间交集必须为空且并集覆盖全部可训练参数。

## 八、训练顺序与输入、容量、四格选择封印

### 8.1 输入适配器 C00

按 `R0 -> R1 -> R2` 顺序，每个只训练一次 C00：20 轮、每轮 1000 步、批量 64、辅助损失权重 1.0，不早停。

- 每轮在固定 LSPR23 验证集计算逐流 AP。
- 每候选选择 AP 全精度最大轮，完全相等取最早轮。
- 唯一输入适配器先比选中验证逐流 AP；全精度相等时选总参数更少者；仍相等按 R0、R1、R2 顺序。
- 实体 AP、最大池化、六档检测率和资源只作诊断，不参与输入选择。

选择写入 `input-adapter-selection-frozen.json` 后不得修改字段组、参数、学习率、轮次或选择规则。

### 8.2 容量 C00

- 冻结胜出输入后，K0 复用该适配器选中 C00；K1/K2 按第 7.2 节顺序单次训练。
- 每档 20 轮、每轮 1000 步，只按固定验证逐流 AP 的最早最大轮选择。
- 容量封印写入 `capacity-selection-frozen.json`，包含未启动容量的资源原因。

### 8.3 C00 复用与四格

- 胜出容量与适配器的 C00 结构、机制位、源码、配置和检查点身份完全兼容时，四格 C00 直接复用其选中轮权重与选择收据，不重训。
- C01、C10、C11 使用同一胜出适配器，各自从种子 42 初始化并训练 20 轮。
- 每格按验证逐流 AP 的最早最大轮封印。
- 四格全部写入 `selection_frozen.json` 后，目标数组才允许首次加载。

### 8.4 LSPR24 描述性评价

- 每格只评价一次；恢复时只可复用身份与哈希完全匹配的完成收据。
- LSPR24 不得回改输入适配器、模型、轮次、`p`、CPA、ELP、阈值或资源门。
- 目标指标只作直接可比描述，`independent_test=false`、`target_previously_accessed=true`。

## 九、CPA、ELP 与梯度可达

- CPA：对 RWKV 输出的逐流隐藏表示按掩码做因果前缀均值；关闭时使用同形零张量。
- 融合：`cat[current,context] -> Linear(224,112) -> ReLU -> Dropout(0.1)`。
- ELP：单一共享 `p_log`；关闭时实体最大池化，打开时可学幂平均。
- 最终实体损失必须对输入适配器、RWKV-7 的分裂无关核心参数、融合头和 `p_log` 产生有限梯度。

每个训练单元首步保存梯度收据：参数总数、获得梯度数、有限数、非零数和各参数组范数。C11 必须额外断言实体损失到 RWKV `receptance/key/value/output/w0/a0` 的梯度有限非零。

## 十、时间与空间优化

### 10.1 CPU 内存映射与流式上卡

- 六源数组和目标数组均用 `np.load(..., mmap_mode="r")`。
- `I/M` 先在 CPU 选择当前序列批，只把 `[B,T,83]`、标签和掩码搬入 GPU。
- 禁止把 `X23/X24/I23/I24` 全量转为 GPU 张量。
- 验证与目标评价按序列批流式推理；逐流分数只在 CPU 内存中暂存，聚合后立即释放，不落盘。

### 10.2 向量化

- R1 字段编码、12 组汇聚、CPA、ELP 和实体聚合使用张量/NumPy 向量化。
- RWKV 状态递归保留沿 T 的 128 步循环；禁止对字段或样本逐项 Python 循环。
- 完整预算曲线使用一次稳定排序与累计计数，复杂度不高于 `O(n log n)`。

### 10.3 精度

正式首跑全模型 FP32。只有后续独立证据证明输入/输出投影混合精度与 FP32 数值一致时才可另立版本；本运行不得静默启用 autocast。RWKV 递归状态始终 FP32。

完成单元保留最后 inflight 并标记 `completed=true`，不得像旧工具一样删除；它是关机恢复证据。

### 11.3 恢复

- 唯一运行身份 `ch3-rwkv7-field-aware-protocol-a-2x2-seed42-v1`。
- 同一身份显式 `--resume`；配置、代码、数据、字段组、参数组和检查点哈希任一不符即拒绝。
- 已完成适配器、格和目标评价按收据幂等跳过。
- 累计 GPU 时间跨恢复单调增加，不因重启重置 4.5 小时门。

## 十二、资源门与停止

- 唯一会话：`ch3-rwkv7-field-aware-protocol-a-s42-v1`。
- 启动前空闲显存至少 20 GiB；主存、磁盘按启动器实测并记录。
- 默认串行 `actual_parallelism=1`，保证效率测量无并发污染。
- R0 完成第一轮后首次校准；首个放大容量 K1 完成第一轮后，必须再次以真实训练、验证、保存 20 份权重的墙钟与峰值重算剩余总成本。
- 累计预计或实测超过 4.5 GPU 小时、显存不安全、非有限损失/梯度或训练不稳定时，在原子检查点后停止；不得减轮、减步、减序列、改宽度或绕门继续。

停止分为运行无效、工程否决和科学结果，不能把依赖/资源失败写成 RWKV-7 无效。
