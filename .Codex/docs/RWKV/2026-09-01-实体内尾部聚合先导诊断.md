## 二、已实测的事实

### 2.1 向量化聚合与逐实体朴素实现一致（合成输入，构造真值）

命令：`/opt/miniconda3/envs/rwkv/bin/python <会话临时目录>/check_grouping.py`
（300 实体、20,000 条流的随机输入，与 `EntityGrouping` 对拍逐实体 `sort`+`topk` 均值）

| α | `k = max(1,⌈α·m⌉)` 一致 | 最大绝对差 | 逐位一致 |
| --- | --- | --- | --- |
| k≡1（max 基线） | 是 | `0` | **是** |
| 0.05 | 是 | `0.000e+00` | 是 |
| 0.1 | 是 | `2.220e-16` | 否 |
| 0.33 | 是 | `5.551e-16` | 否 |
| 0.5 | 是 | `4.441e-16` | 否 |
| 1.0 | 是 | `5.551e-16` | 否 |

`α > 0` 各档的差异全部是求和次序造成的浮点末位差（≤ `5.6e-16`）。
**关键性质：`k ≡ 1` 时逐位一致**——因为该档只取元素再除以 `1.0`，没有加法误差。
口径自检正建立在这条性质上：`k≡1` 的 top-k 均值必须与 `np.maximum.at` 的 max 聚合
逐位相同，否则实现有误。同一断言已写进工具，不通过即以 `EXIT_RUNTIME` 停止。

实体集合、实体顺序与实体标签（`np.maximum.reduceat` 对
`np.maximum.at`）三项也逐位一致。

### 2.5 本机执行为什么被放弃

首轮本机 MPS 运行（`mps-fp32-v1`、未编译）已通过身份门并加载权重，进入前向后
13 分 17 秒仍未走完 18 个验证批（第一个心跳阈值 = 2,244 条序列）。同期 `iostat`
显示磁盘持续 `~500 MB/s`、`~14.5k tps`，进程 CPU 仅 `7–15%`，`vm_stat` 显示可用页
约 `472 MB`——瓶颈是 5.4 GB `X23.npy` 内存映射随机读在内存受限机器上的抖动，
叠加 MPS fp32 前向。按该速率外推，单趟完整验证约 2 小时，两趟（交叉核验 + 重聚合扫描）
约 4 小时，且期间用户工作机不可用。主进程据此中止本机执行。

该外推是**按已观测吞吐的推算，不是实测总耗时**；服务器 CUDA 上同一扫描的既有实测是
`24.78 秒`（见 2.3），所以服务器是正确的执行位置。

## 四、判读约定（不变，先登记再看数）

- 该运行是单检查点、单种子、`screening_only` 级诊断。**任何结果都不构成机制有效性证据**，
  不得进入论文正式结果、表格或帕累托比较。
- **max 基线必须与 `0.7887951742121221` 逐位一致。** 对不上即口径错误或数值路径漂移，
  停下来报告，不得调参凑数。工具已把该比较写进 `calibration_self_check`，
  同时保留三条独立比较：本探针 `k≡1` 对 `np.maximum.at`（同进程，必须逐位一致）、
  本探针对未修改的 `validation_metrics`（同设备同权重，必须逐位一致）、
  以及对 CUDA 记录读数 `0.7887951742121221`（跨运行）。
  前两条不成立即实现有误；只有第三条不成立且前两条成立，才属于数值路径差异而非口径错误。
- 全网格都不高于基线同样如实报告。**负结果是有效结果**，不换检查点、不换指标去找正信号。
- 分层结果必须点明：若改善只出现在 `m ≥ 100` 层，那正是恶意实体所在的层，
  可能只是把同一批样本重新加权，不能据此声称机制有效。

## 五、遗留风险

- **跨版本反序列化**：冻结的 `sealed-input-transform.pkl` 由 scikit-learn `1.7.2` 保存，
  本机 miniconda `rwkv` 环境是 `1.9.0`，读取时 `QuantileTransformer` 触发
  `InconsistentVersionWarning`。服务器环境版本未核验（SSH 被拒）。
  该警告在服务器上若同样出现，须与 `0.7887951742121221` 的逐位比较结果一并判读——
  变换漂移会同时改变逐流分数与实体 AP。
- **并发条件**：服务器上同时有 `ch3-ft-c01-reservoir-xi-screening-v1` 在跑。
  探针已按 `--concurrent-with` 把 `resource_contention=true` 与并发对象写进收据，
  耗时与显存只能作并发条件实测，不得当作独占效率。
- **两趟前向**：默认开启对 `validation_metrics` 的交叉核验，代价是多一趟完整前向
  （CUDA 上约 25 秒，可接受）。确需省时可加 `--no-cross-check`，
  但那样就失去「我复制的扫描循环等于原函数」的实测证据，只剩文本层面的对照。
