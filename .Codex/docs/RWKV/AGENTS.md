## Rust 数据处理规则

- RWKV 路线的正式数据物化、全量 CSV 解析、时间排序、连续段切分、滑窗索引、样本清单生成和 Parquet 写出，若预计 Python 单进程成为明显瓶颈，优先评估 Rust 实现。
- 并行只允许发生在相互独立的版本、文件和连续时间段之间。同一连续时间段内的时间排序、攻击事件合并、历史窗口和状态顺序必须保持确定性语义，不得为提高吞吐打乱行序。
- 并行结果必须按冻结稳定键重新排序，并输出输入哈希、模式、行数、样本标识清单、分割收据和语义哈希；不得只用 Parquet 容器字节是否一致判断数据一致性。
- 探索性小样本、一次性表头审计或已有 Python 实现能够在可接受时间内完成时，不为形式强制改写 Rust。是否采用 Rust 由数据规模、预估耗时、复用价值和确定性风险共同决定。
- Rust 只改变实现与吞吐，不得改变字段、标签、时间拆分、样本比例、困难版本、统计簇或最终测试隔离合同。Rust 与 Python 参考实现并存时，先用小型冻结样本核对模式、行数、稳定顺序和语义哈希，再执行全量物化。
- Rust 代码必须遵循项目已安装的 `rust-skills` 规范，并通过编译与最小语义一致性检查；不得让格式化、全仓静态检查或无关复审阻塞已经满足运行门禁的实验。
