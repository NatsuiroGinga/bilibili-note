# RWKV 路线规则

<!-- 规则加载哨兵：NOTE_CODEX_DOCS_RWKV_20260805 -->

本文件适用于显式绑定或默认进入 `RESEARCH_ROUTE=RWKV` 的任务，只规定 RWKV 路线恢复与写回增量。当前候选、数据比例、服务器、运行状态和效果数字不复制进本文件。

## 唯一恢复链

1. 读取本文件与 `RWKV路线总控.md`。
2. 第三章任务只追加 `RWKV第三章恢复卡.md`；第四章任务只追加 `RWKV第四章恢复卡.md`；跨章任务才读取两张卡。
3. 只有追溯第三章候选存废时追加 `2026-08-08-第三章候选方案登记册.md`；只有事实冲突、制品追溯或用户明确要求时，经 `RWKV历史交接入口.md` 选择历史材料。
4. `RWKV当前恢复卡.md` 只作旧链接兼容页，不是默认入口。总控链接的设计、数据合同和报告按当前门禁读取，不无条件展开。

- 默认不读取 PINN/R2 的 `output/` 恢复文档。跨路线比较或用户明确返回历史路线时，先声明边界再按根规则切换，禁止混写。
- 恢复后先查询现有代理、原始日志、运行状态和制品，确认没有同一运行后再继续；聊天摘要和旧设计不得覆盖总控、章节卡或新制品。
- 当前数据集、切分、字段、标签权限、候选、基线、数值门槛和下一实验，以总控、对应章节卡及其链接的冻结合同为唯一事实源；本文件不冻结这些易变事实。

## 路线裁决与写回

- 候选只能用绑定数据、配置、共同预算基线、日志、指标和制品支持或证伪。全文文献证明机制来源与可试性，不替代本课题实验；筛选运行、代理实验和历史结果不得进入论文正式结果。
- RWKV 公共合同和跨章裁决写入 `RWKV路线总控.md`；第三章或第四章的方法裁决、确定结果、路径、状态和下一门禁写入对应章节恢复卡；长日志与过程细节留在专属计划或报告，由恢复卡链接。
- 不把 RWKV 过程状态写入 PINN/R2 的 `output/` 总控。只有用户正式决定替换论文主线时，才按专门迁移计划更新跨路线文档。
- 本论文不以公开代码、公开模型、公开数据或公开仓库为前置门禁；本地或私有备份仍须完整保存代码、配置、日志、哈希、模型与数据谱系，并遵守许可证。

## RWKV 训练后端当前裁决

- 用户于 2026-08-22 明确停用纯 PyTorch RWKV 训练路径。除非用户以后主动、明确点名恢复，任何代理不得规划、同步、启动、恢复或把纯 PyTorch RWKV 当默认回退、速度基线和正式候选；既有权重、断点、日志与失败结果只作历史证据保留。
- 当前 RWKV 主路径是独立 CUDA 融合版。它以新的数值与训练身份从头训练，不冒充纯 PyTorch 的透明等价后端，不复用纯后端模型权重或优化器；其有效性仍须由同一冻结数据、协议、指标和真实实验裁决。
- CUDA 入口不可用、编译失败或结果不合格时，记录精确工程或科学失败并停止该候选，不得自动恢复纯 PyTorch 路线。只有用户新的显式裁决才能解除本节边界。

## RWKV 数据实现增量

- 正式全量解析、时间排序、连续段切分、滑窗索引和 Parquet 写出预计由 Python 成为明显瓶颈时，优先评估 Rust；探索性表头审计或 Python 可在可接受时间完成时不为形式改写。
- 并行只发生在独立文件、版本或连续时间段之间。同一时间段内保持排序、事件合并、历史窗口和状态顺序确定；汇总后按冻结稳定键重排，并输出输入哈希、模式、行数、样本清单、切分收据和语义哈希。
- Rust 只改变实现与吞吐，不得改变字段、标签、切分、样本比例、统计簇或最终测试隔离。与 Python 参考实现并存时，先用有解析预期的冻结样本核对模式、行数、顺序和语义哈希，再全量物化。
- Rust 代码读取 `rust-skills` 并通过编译与最小语义一致性检查；格式化和无关全仓检查不得阻塞已满足门禁的真实实验。

- 直接相关的官方源码固定提交、许可证和哈希并保留本机备份；网络或许可证阻塞时记录精确原因。事故案例和历史细节只留在专属报告，不常驻加载。
