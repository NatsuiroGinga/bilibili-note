## RWKV 当前门禁

- 最终论文只能使用一个数据集。依据 2026-08-08 本地数据适配审计，候选筛选阶段使用 LSPR24；第三、四章不得为提高结果追加第二数据集。UGR'16 只保留为历史筛选证据。
- 候选筛选阶段一次性物化覆盖前 80% 开发区的合法宽表、标签旁车和历史索引；按活动时间顺序使用全局 `60%/20%/20%` 的训练、验证、最终测试切分，前 60% 训练、随后 20% 验证、最后 20% 最终测试。所有基线与候选只通过 Parquet 列裁剪、历史长度和训练目标清单取用所需信息，禁止为每个候选重复扫描或物化原始数据。
- 不机械套用随机 `8:1:1`，也不保留五段式软件发布门禁。LSPR24 仅约 31.6 小时，最后 10% 只有约 3.2 小时，窗口行数不能替代独立攻击事件数；训练区已有数百万窗口，保留 20% 验证和 20% 最终测试更利于时间前向评价。快速筛选只要求真实模式、时间因果、身份禁入、标签旁车、固定拆分和最终 20% 不可见。
- 宽表真实物化完成后立即运行共同强基线和种子 42 快速消融；没有有效信号时先调整或淘汰候选，不继续扩建正式数据治理链。
- **快速实验执行纪律**：冻结可观测量、最小对照和失败门后立即运行真实数据；编译、配置、格式、清单、报告、文献补漏与非阻断复审不得串行挡在实验前。仅当数据泄漏、标签或指标错误、因果时序错误、预算不公平、不可运行或资源安全失败时暂停；修复一次只改一个已证实变量，并用新运行身份重跑。
- 快速实验启动后不做高频人工轮询，不边跑边扩写文档。默认只在运行结束或明确异常时读取一次状态、日志和结果；过程进度只有用户明确要求时才查询。失败运行原样保留，禁止为省时覆盖或把工程失败写成科学否决。
- 论文外部主比较表只能纳入已有论文公开基线方案，并在本课题同一冻结 LSPR 数据成员、切分、字段预算、标签权限、训练预算和评价指标下重新运行；字段或预处理无法等同时必须标为论文约束独立复现并单列差异，不得直接混排。内部参数匹配公平基线不得冒充公开基线、进入外部横向胜负表或用于声称胜过文献方法；不同数据或协议下的论文原始数字只作背景参照。当前 Q0、有界缓存、种子 42、少轮共同预算或并发运行产生的内部公平基线与 C12 结果仅用于候选筛选、快速消融、故障诊断和正式实验设计，禁止进入论文正式结果表、摘要、结论或效果主张；文献桥接 Q0 同样仅属复现可行性筛选，正式横向表仍须按正式协议重跑。候选冻结后，内部消融须在正式冻结数据、预注册训练预算、种子 42/43/44、配对统计或置信区间和隔离效率测量下重新运行，才可进入论文消融章节。
- **快速消融与正式物化分阶段**：候选种子 42 快速筛选默认直接流式读取官方原始 CSV/Parquet，或只生成冻结预算内、可由全部快速变体共享的有界缓存；不得为了快速筛选提前生成全量宽表、全量侧车或论文正式数据产品。只要字段、样本身份、时间切分、标签权限、归一化和序列顺序一致，直接读取与缓存物化必须具有相同实验语义。只有候选出现独立正增益并决定进入多种子正式实验，或多个正式消费者确实需要复用时，才生成大而全的正式数据产品。

- 新增数据源必须先补齐官方版本、发布页、许可证与下载页凭据，再执行序列可行性审计。
- 强化学习仅用于继续观察、告警或拒识构成的序列停止决策；攻击事件和决策步门禁失败时禁止启用。
- 任何先导实验产物仅可写入 `/Users/bilibili/personal/note/.Codex/docs/` 对应先导目录或 `runs`，不得作为论文结论。

- **文献驱动候选的联网查重门禁**：当任务要求“综合文献”“`research-ideation`”或明确要求联网检索时，即使本地已经有多篇全文，也不得自行判断材料足够而跳过近期联网查重。章级候选冻结前必须检索近年原论文、官方源码或作者页面，核验是否存在同构机制、相同任务和已报告结果；未完成只能标为草案。网络或来源不可用时记录精确阻塞和已尝试入口，不得把“未检索到”写成“不存在”。

## Rust 数据处理规则

- RWKV 路线的正式数据物化、全量 CSV 解析、时间排序、连续段切分、滑窗索引、样本清单生成和 Parquet 写出，若预计 Python 单进程成为明显瓶颈，优先评估 Rust 实现。
- 并行只允许发生在相互独立的版本、文件和连续时间段之间。同一连续时间段内的时间排序、攻击事件合并、历史窗口和状态顺序必须保持确定性语义，不得为提高吞吐打乱行序。
- 并行结果必须按冻结稳定键重新排序，并输出输入哈希、模式、行数、样本标识清单、分割收据和语义哈希；不得只用 Parquet 容器字节是否一致判断数据一致性。
- 探索性小样本、一次性表头审计或已有 Python 实现能够在可接受时间内完成时，不为形式强制改写 Rust。是否采用 Rust 由数据规模、预估耗时、复用价值和确定性风险共同决定。
- Rust 只改变实现与吞吐，不得改变字段、标签、时间拆分、样本比例、困难版本、统计簇或最终测试隔离合同。Rust 与 Python 参考实现并存时，先用小型冻结样本核对模式、行数、稳定顺序和语义哈希，再执行全量物化。
- Rust 代码必须遵循项目已安装的 `rust-skills` 规范，并通过编译与最小语义一致性检查；不得让格式化、全仓静态检查或无关复审阻塞已经满足运行门禁的实验。

## 官方源码发现与工程接入（强制）

- 工程勘察在本地未找到源码快照、可导入包或固定提交时，**不得据此写成“没有源码”“源码不可定位”或“只能自行实现”**。必须先交叉读取路线既有全文笔记、官方源码笔记、依赖预取清单和实现报告，再联网核验论文指向的官方 GitHub、作者组织或项目页。
- 源码状态必须分开记录为：`官方仓库已核验`、`固定提交已确定`、`本机快照已归档`、`正式环境可导入`、`真实前向/反向已运行`。后一个状态不能由前一个状态推断；汇报时必须说明具体缺在哪一层。
- 文献代理已经核验的官方仓库、提交和许可证必须写入后续工程任务简报，工程代理不得只做局部文件搜索而忽略已有外部证据。反过来，文献发现官方源码也不等于工程可用，仍需固定提交、许可证、哈希、依赖和运行收据。
- 官方源码与当前基线或候选直接相关时，确认有用后应按实验工程制品规范下载固定快照、记录远程地址、提交、许可证和 SHA-256，并保留本机备份；网络或许可证阻塞时记录精确原因。不得等到模型实现阶段才重新发现同一仓库。
- 2026-08-11 已发生一次反例：跨年度基线勘察只搜索本地工作区，没有先查询论文作者页和 GitHub，也没有复用文献任务已经核验的源码证据，因而遗漏 `fla-org/flash-linear-attention` 的 DeltaNet 官方实现与 `NVlabs/GatedDeltaNet` 官方仓库，并把“本机尚无快照”错误表述为“源码不可定位”。后续同类勘察必须执行上述交叉检查，并使用“官方仓库已核验，但本机快照/导入尚未完成”的精确措辞。
