# LSPR24 有界筛选加载器修复计划

## 问题

真实统一基线 v2 在样本上限生效前读取全部宽表和历史关系，并把全部历史样本构造成 Python/Pandas 对象。进程常驻内存约 56 GiB，A44 的 SSH 30 秒探针超时，尚未进入模型拟合。

## 根因

`Lspr24ScreenDataset.load` 的执行顺序是“全量读入 → 全量连接 → 全量 Python 循环构造 → 最后稳定采样”。`sample_limit` 只限制返回结果，不限制读取、连接和中间状态，因此空间复杂度仍随完整开发区增长。

## 修复边界

- 只修改 `src/flow_probe/lspr24_screen_dataset.py`，必要时增加一个项目内只读缓存辅助模块。
- 先从最小主键列确定指定切分的稳定目标样本，再以 PyArrow 批扫描筛选 `H=1/4` 的关系和相关窗口字段。
- 中间状态上界由 `sample_limit × (H+1) × 字段数` 决定，不得随 794 万完整窗口增长。
- 输出的样本标识、标签、字段顺序、历史顺序和数值必须与原合同一致。
- 只允许 `train/validation`，拒绝最终测试；绝对路径与工程根约束保持不变。
- 将冻结数组写入运行专属 `.npy` 与清单，供 HGB/XGBoost 和四个神经进程复用，避免重复扫描 Parquet。

## 真实验收

1. Python 编译通过。
2. 在真实 LSPR24 清单上生成 `H=4` 的 10 万训练、2 万验证共享缓存。
3. 记录峰值内存、样本数、类别数、字段数和缓存哈希；目标峰值内存低于 12 GiB。
4. 缓存成功后直接启动 HGB/XGBoost 与四个 RWKV 变体，不运行人工测试、格式化或独立复审。
