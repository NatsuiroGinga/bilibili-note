# FT 候选本机 MPS 与服务器 CUDA 单代码统一运行合同

日期：2026-08-28。状态：**设计冻结，代码待主进程实现，实验待证**。

## 一、目的与适用范围

本合同规定 FT 候选只维护一份 Python 工具、一份模型实现和一套科学接口。本机 Apple Silicon 使用 MPS FP32 做真实数据筛选，服务器使用 CUDA BF16 做正式运行。两条路径不得复制模型代码，不得各自修补算子，不得共享训练权重。

本合同只冻结运行接口，不批准任何候选机制，不改变 83 字段、切分、标签、指标、最终测试隔离或研究问题。候选机制仍须分别通过数据集－模型适配表、朱论文对位表和真实实验门。

证据笔记见[跨设备运行证据](notes.md)，上位精度要求见[神经训练按需合同](../../agents-split/llm-probe-neural-training-contract.md)。

## 二、核心裁决

| 对象 | 本机筛选 | 服务器正式运行 |
| --- | --- | --- |
| 工具源码 | 同一 Python 文件与同一 `code_sha256` | 同左 |
| 精度 profile | `mps-fp32-v1` | `cuda-bf16-amp-fp32-sensitive-v1` |
| 运行级别 | `screening_only=true` | `formal_run=true` |
| 参数与优化器状态 | FP32 | FP32 |
| 自动混合精度 | 关闭 | BF16，启用 |
| 梯度缩放器 | 无 | 无 |
| 有效批语义 | 与正式合同相同 | 冻结正式合同 |
| 微批量与累积 | 由本机真实资源收据冻结 | 由服务器真实资源收据冻结 |
| 训练预算 | 筛选预算，源年，结果只决定是否增加计算 | 正式预算，所有格共同预算 |
| 权重用途 | 只在同一 MPS 筛选身份内恢复 | 新身份从头训练 |
| 科学结论 | 禁止 | 满足正式证据门后才允许 |

**禁止跨 profile 续训。** CUDA 正式运行不得加载 MPS 模型、优化器、选中轮次、调度器、梯度缩放器或随机状态。它必须用相同种子规则重新初始化模型与优化器，以新的 `run_id` 从第一个优化步开始。

## 三、跨设备必须相同的科学合同

下列对象须进入 `science_identity_sha256`，本机与服务器逐项相等：

- Python 工具内容哈希、模型类与前向图哈希。
- 83 字段顺序、字段角色、输入变换算法、训练区拟合规则与变换状态模式。
- 数据模式版本、源数据内容或语义哈希、实体与时间顺序、切分成员哈希。
- 候选机制开关、公式、Token 布局、参数量闭式与实际参数量。
- 随机种子、采样算法、样本池、每个有效批的样本选择顺序规则。
- 优化器类型、学习率、权重衰减、参数分组、损失、辅助损失权重和梯度路径。
- 有效批对象单位、有效批量、归一化单位、尾批策略和每个有效批一次优化器更新的语义。
- 训练、验证、实体聚合、选轮、打平、阈值与全部评价指标实现。
- 检查点字段集合、字段含义、原子写边界和恢复规则。
- 目标年只在全部源年选择封印后读取的隔离门。

路径、文件修改时间、设备名称和平台构建标识不进入科学同一性判断，但必须进入运行收据。

## 四、只允许变化的运行字段

完整配置须同时生成科学投影与运行投影。除下表字段外，本机与服务器配置出现任何差异都应停止。

| 配置字段 | 允许差异 | 约束 |
| --- | --- | --- |
| `run_id` | 是 | 两个环境必须不同且语义化命名 |
| `runtime.device_type` | 是 | 只能是 `mps` 或 `cuda`，必须与 profile 一致 |
| `precision_profile_id` | 是 | 本机与服务器分别固定为第二节的 profile |
| `run_tier` | 是 | 本机 `screening_only`，服务器 `formal` |
| `training.micro_batch_sequences` | 是 | 必须是有效批量的机械因子 |
| `training.gradient_accumulation_steps` | 是 | 与微批量乘积必须等于冻结有效批量 |
| `budget.epochs` | 是 | 本机值须由实测预算收据冻结；正式值由正式实验计划冻结 |
| `budget.steps_per_epoch` | 是 | 不得依据目标年或筛选结果事后修改 |
| `resource.sample_interval_seconds` | 是 | 只影响资源采样密度，不影响训练 |
| `resource.memory_provider` | 是 | 由设备 profile 派生，不允许人工任选 |
| `resource.pin_memory` | 派生差异 | MPS 固定为假；CUDA 只有真实收据证明有效时可为真 |
| `resource.non_blocking_transfer` | 派生差异 | 只有 CUDA 且页锁定内存为真时才允许为真 |
| `paths.output_root` | 是 | 末级目录必须等于 `run_id` |
| `tracking.group` | 是 | 必须等于 `run_id`；本机可离线，正式按授权平台运行 |

`training.effective_batch_size` 不属于允许差异。当前 FT 正式合同为 `64` 个序列；本机必须通过微批量与累积步数保持同一有效批。如果 MPS 连微批 `1` 都无法完成 `64` 序列的等效有效批，候选记为本机资源不合格，不得静默缩小有效批。

当前正式预算为 `20` 轮、每轮 `1000` 个优化步，来源为[现有 FT 配置](../../../../thesis/experiments/llm_probe/configs/ch3-ft-transformer-field-token-protocol-a-seed42-v1.json)。新候选若正式计划改变预算，须先建立独立数值依据并对全部比较格共同改变；不得从本机效果反推正式预算。

## 五、配置字段合同

统一工具至少消费以下配置段：

| 配置段 | 必填字段 |
| --- | --- |
| `identity` | `run_id`、`run_tier`、`candidate_key`、`science_contract_version` |
| `runtime` | `device_type`、`precision_profile_id`、`allow_device_fallback=false`、`allow_cpu_op_fallback=false` |
| `data` | `cache_root`、`manifest_path`、`schema_version`、`source_semantic_sha256`、`split_sha256`、`field_order_sha256` |
| `model` | 架构、Token 布局、机制开关、参数量期望值 |
| `optimizer` | 类型、学习率、权重衰减、参数分组规则 |
| `training` | 种子、有效批量、微批量、累积步数、归一化单位、损失、选轮规则 |
| `budget` | 轮数、每轮优化步数、验证频率、预算依据收据 |
| `resource` | 采样周期、主存与加速器内存提供者、页锁定、异步传输、并发披露 |
| `checkpoint` | 模式版本、在途路径、选中路径、恢复允许范围、原子写规则 |
| `evaluation` | 指标清单、实体聚合、阈值规则、目标年隔离状态 |
| `tracking` | 模式、工作区、项目、分组、标签 |

本机配置在预算实测前必须标为 `budget_state="unmeasured"`，只能执行资源探测入口，不能启动筛选训练。实测收据冻结微批量、累积步数、轮数和步数后，配置改为 `budget_state="frozen"` 并记录收据哈希；只有冻结状态可以创建筛选运行身份。

服务器配置固定 `run_tier="formal"`、`screening_only=false`、`precision_profile_id="cuda-bf16-amp-fp32-sensitive-v1"`。`formal` 只表示运行使用正式合同，不自动表示结果已经可以写入论文；`formal_paper_evidence` 仍由多种子、结果分析和章节门禁裁决。

## 六、设备解析与精度

统一工具必须从配置显式读取设备，不得使用“CUDA 可用就选 CUDA，否则选 MPS/CPU”的自动回退。

设备解析行为固定如下：

| 设备 | 准入条件 | 失败行为 |
| --- | --- | --- |
| MPS | 配置为 `mps`、profile 为 `mps-fp32-v1`、目标 PyTorch 声明 MPS 后端可用 | 停止并保留环境收据，不回退 CPU |
| CUDA | 配置为 `cuda`、profile 为 `cuda-bf16-amp-fp32-sensitive-v1`、CUDA 可用且支持 BF16 | 停止并保留环境收据，不自动改 FP16 或 FP32 |

自动混合精度统一调用[共享精度运行时](../../../../thesis/experiments/llm_probe/tools/neural_precision_runtime.py)的 `autocast_context`：MPS FP32 得空上下文；CUDA 得 BF16 上下文。参数、优化器状态以及登记的敏感计算均保持 FP32。两个 profile 都不得创建梯度缩放器。

模型、损失和指标代码不得出现 `if device.type == ...` 的科学分支。设备条件只允许存在于设备解析、同步、资源统计、主机传输和随机状态适配器。

## 七、同步、计时与资源统计

统一运行时须提供以下行为接口，具体 PyTorch 签名在代码落笔前按目标版本官方文档核验：

| 接口 | 行为 |
| --- | --- |
| `synchronize_device(device)` | 在计时起点、计时终点、资源采样和原子检查点前等待该设备已提交工作完成 |
| `reset_peak_memory(device)` | CUDA 使用原生峰值重置；MPS 清零本进程采样峰值计数器 |
| `sample_memory(device)` | 返回统一字段并附设备原生字段、可用性和采样来源 |
| `capture_accelerator_rng_state(device)` | 保存当前加速器随机状态或明确的不可用收据 |
| `restore_accelerator_rng_state(device,state)` | 只允许同 profile、同设备族恢复 |

资源收据统一字段至少包括：

- `device_type`、`precision_profile_id`、设备名称、PyTorch 版本和平台构建标识。
- `process_rss_bytes`、`process_peak_rss_bytes`、主机可用内存和磁盘可用量。
- `accelerator_memory_current_bytes`、`accelerator_memory_reserved_or_driver_bytes`、`accelerator_memory_peak_sampled_bytes`。
- `measurement_available`、`measurement_source`、`sample_interval_seconds`、样本数。
- 有效批、微批、累积步数、处理有效流、耗时和吞吐。

CUDA 继续保留 `allocated/reserved/max_allocated/max_reserved` 与外部进程显存。MPS 没有等价原生字段时不得伪造为零；应写 `null`、`measurement_available=false` 和原因，同时以真实进程峰值、系统内存压力和设备可用内存接口完成资源门。

所有吞吐和耗时必须在同步边界内测量。未同步的异步提交时间只能记为提交延迟，不能作为效率结果。

## 八、主机传输与内存映射

`X23.npy` 和 `X24.npy` 必须使用 `np.load(..., mmap_mode="r", allow_pickle=False)` 打开。禁止以下行为：

- 对整张 `X23` 或 `X24` 调用 `np.asarray`、`copy`、`astype` 或一次性构造 Torch 张量。
- 把全量 83 字段矩阵常驻 MPS 统一内存或 CUDA 显存。
- 为本机筛选另存一份模型专用全量特征复制。

允许的热路径是：按 `I/M` 选取当前微批流索引，从只读内存映射取对应行，在主机侧应用同一冻结输入变换，形成当前微批的连续数组，再传入设备。分位数拟合允许逐列有界缓冲，但不能复制全表。

页锁定内存规则固定如下：

- MPS：`pin_memory=false`、`non_blocking_transfer=false`。
- CUDA：只有主机到设备传输路径真实使用页锁定缓冲且首步收据证明无回归时，才允许 `pin_memory=true` 和 `non_blocking_transfer=true`。
- 当前工具没有 `DataLoader`；不得为了形式新增 `DataLoader`。若继续直接按微批索引，页锁定策略在批缓冲适配器内实现。
- 页锁定和异步传输只属于资源策略，不得改变批成员、顺序、类型或数值。

## 九、MPS 不支持算子的处理

本机筛选禁止通过环境变量或隐式后端把 MPS 不支持算子静默回退到 CPU。出现不支持算子时：

1. 记录算子、输入形状、类型、设备、PyTorch 版本和完整错误。
2. 将本机筛选状态写为 `MPS_OPERATOR_UNSUPPORTED`，保留运行目录。
3. 若存在数学等价且两端均支持的实现，只能修改共享代码路径，代码哈希变化后重新执行 MPS 与 CUDA 的全部入口检查。
4. 不允许只在 MPS 分支替换模型、损失、归约、指标或机制公式。
5. 无共同实现时停止本机筛选；不得用 CPU 筛选结果冒充 MPS，也不得因此修改正式 CUDA 模型。

指标允许在 CPU 上计算，但必须是统一显式路径：两个设备都把已完成推理的 FP32 分数传回 CPU，调用同一指标函数。该路径不属于算子回退。

## 十、随机性合同

每次新运行统一设置 Python、NumPy、Torch CPU 和当前加速器随机状态。种子和采样算法进入科学身份，不允许因设备改变种子。

检查点中的 `rng_state` 使用同一字段模式：

| 字段 | 含义 |
| --- | --- |
| `python_random` | Python 随机状态 |
| `numpy_random` | NumPy 随机状态 |
| `torch_cpu` | Torch CPU 随机状态 |
| `accelerator_type` | `mps` 或 `cuda` |
| `accelerator_state` | 当前加速器状态；能力不可用时为 `null` 并带原因 |
| `sampler_state` | 训练采样器或 `torch.Generator` 状态 |

同一运行恢复时必须逐项恢复。MPS 状态接口无法按目标版本核验时，该运行不得宣称可精确断点续训；只能从最近完整、可验证的运行阶段重新开始。CUDA 正式运行绝不恢复 MPS 随机状态。

## 十一、统一检查点模式与加载

MPS 和 CUDA 使用同一个检查点模式版本与字段集合。建议新模式标识为 `ch3-ft-candidate-unified-checkpoint-v1`，至少保存：

- `schema_version`、`science_identity`、`runtime_identity`、`run_id`、`run_tier`。
- `device_type`、`precision_profile_id`、完整 profile 对象。
- `model_state_dict`、`optimizer_state_dict`、`scaler_state_dict`。
- 当前轮次、优化器步、历史、双选轮状态和输入变换状态哈希。
- 有效批、微批、累积步数、归一化单位、完整优化器步边界。
- 第十节的统一随机状态。
- `resume_scope` 与 `formal_resume_eligible`。

检查点只在完整 `optimizer.step()` 后原子写。加载一律先使用 `map_location="cpu"`，核验模式、哈希、profile 和恢复范围，再把模型及优化器状态移到目标设备。禁止直接把检查点反序列化到 MPS 或 CUDA 后再核身份。

恢复规则：

| 来源 | 目标 | 允许 |
| --- | --- | --- |
| MPS 筛选 | 同一 MPS 筛选身份 | 身份、profile、批量与预算一致时允许 |
| CUDA 正式 | 同一 CUDA 正式身份 | 身份、profile、批量与预算一致时允许 |
| MPS 筛选 | CUDA 正式 | **禁止** |
| CUDA 正式 | MPS 筛选 | 禁止用于训练；只读结构诊断须另建身份 |

MPS 检查点固定写 `formal_resume_eligible=false`。CUDA 启动器发现任何初始化或恢复路径指向 MPS 运行根时必须停止。

## 十三、当前 FT 最小重构接口

主进程只需重构设备与数据运行层，不应改写模型主体：

| 最小接口 | 输入与输出 | 取代的硬编码 |

| `resolve_runtime(config, torch)` | 返回设备、profile、运行级别与能力收据 | `_resolve_device` 与固定 `PRECISION_PROFILE_ID` |
| `validate_science_config(config)` | 返回科学投影与哈希 | 当前整份配置逐字固定校验 |
| `validate_runtime_config(config, runtime)` | 核验白名单差异和资源策略 | CUDA 专属资源合同 |
| `device_autocast(runtime)` | 返回共享精度上下文 | CUDA BF16 专属断言 |

## 十四、验收命令合同

候选实施计划须绑定三个环境变量：`TOOL` 为唯一 Python 工具，`MPS_CONFIG` 为本机配置，`CUDA_CONFIG` 为服务器正式配置。不得把两个配置绑定到不同工具。

本机静态与配置验收：

```bash
source tools/env/activate.sh
uv run --no-sync python "$TOOL" --config "$MPS_CONFIG" --validate-config
uv run --no-sync python "$TOOL" --config "$CUDA_CONFIG" --validate-config
```

本机真实资源探测与筛选：

```bash
uv run --no-sync python "$TOOL" --config "$MPS_CONFIG" --stage probe-runtime
uv run --no-sync python "$TOOL" --config "$MPS_CONFIG" --stage train --resume
```

服务器正式运行由主进程按服务器身份与同步合同执行：

```bash
uv run --no-sync python "$TOOL" --config "$CUDA_CONFIG" --stage train --resume
uv run --no-sync python "$TOOL" --config "$CUDA_CONFIG" --stage evaluate --resume
```

`--validate-config` 必须在无目标设备时完成纯配置校验；`probe-runtime` 才检查真实设备并使用冻结开发区真实数据完成至少一个完整优化步。不得创建人工夹具、单元测试、集成测试或独立合成冒烟实验。

机械验收必须同时证明：

- 两个配置的 `science_identity_sha256` 相等，`runtime_identity_sha256` 不等。
- `code_sha256` 与工具路径相同。
- 数据语义、切分、字段、模型、机制、损失、指标和检查点模式哈希相同。
- 两个 profile 的参数与优化器状态均为 FP32；MPS 无自动混合精度，CUDA 为 BF16 自动混合精度。
- 微批量乘累积步数等于同一有效批量。
- `X23/X24` 是只读内存映射，运行收据没有全表复制。
- MPS 检查点写有 `formal_resume_eligible=false`，CUDA 正式入口机械拒绝其路径。
- 首个完整优化步之后损失、梯度、参数和优化器状态均有限。
- 计时和资源值来自同步边界。
- 正式评价前目标年读取计数为零且全部源年选择已封印。

## 十五、正式 CUDA 重跑条件

满足以下条件后才允许从 MPS 筛选进入 CUDA 正式运行：

1. MPS 真实数据入口完成，代码、前向、反向、完整优化步、检查点写回和恢复均可运行。
2. MPS 资源收据确认主存、统一内存、磁盘和运行时间在本机安全范围内。
3. 候选预注册的源年筛选门已满足；门槛来自候选计划，不由本合同新增，也不得读取 LSPR24 后补写。
4. 两端 `science_identity_sha256` 相同，差异清单只含第四节白名单字段。
5. 服务器身份、依赖、数据、磁盘和 CUDA BF16 能力由主进程重新只读核验。
6. CUDA 正式 `run_id` 从未使用，输出根不存在其他身份的部分制品。
7. 正式入口不提供 MPS 检查点、模型初始化或优化器恢复参数，从随机初始化开始。

以下情形禁止启动正式运行：MPS 使用了 CPU 算子回退；科学配置有非白名单差异；数据语义哈希不同；本机筛选读取过 LSPR24；MPS 权重被配置为初始化；候选只因异精度点估计更高而晋级；正式资源门不能保持冻结模型、有效批和预算。

## 十六、结果解释边界

- MPS 与 CUDA 数值不要求逐位相等，也不以损失或指标接近作为科学身份门。
- MPS 正向结果只能标为“筛选信号”，MPS 负向结果可按预注册筛选门停止追加计算，但不能写成正式模型否决。
- CUDA 正式结果必须独立报告，不能把 MPS 与 CUDA 的指标混合平均、配对或当作多种子。
- 资源指标按设备分别报告，不能用 MPS 统一内存与 CUDA 显存做直接效率支配。
- 本合同只证明运行接口可统一；机制是否有效仍由真实数据、共同预算基线、消融和统计实验裁决。
