# FT 候选本机 MPS 与服务器 CUDA 单代码合同任务计划

## 目标

冻结一份可由同一 Python 工具在本机 MPS 与服务器 CUDA 直接执行的统一运行合同，使本机筛选只承担工程资格与方向筛查，服务器正式运行始终以独立身份从头训练。

- 本任务独占本目录下的 `task_plan.md`、`notes.md` 与 `统一运行合同.md`。
- 不修改生产代码、配置、恢复卡、研究问题卡、论文正文或服务器制品。

## 核心问题

1. 哪些科学对象必须跨 MPS 与 CUDA 保持逐字或哈希一致？
2. 哪些运行字段允许按设备和资源实测变化？
3. 如何处理自动混合精度、同步、内存统计、页锁定内存、随机状态和断点迁移？
4. 如何确保 MPS 筛选权重不能成为 CUDA 正式训练的初始化或续训来源？
5. 当前 FT 工具中哪些 CUDA 写死点必须收敛为最小设备运行时接口？

## 已作决定

- 本机运行固定为 `mps-fp32-v1` 与 `screening_only=true`，不得产生正式科学结论。
- 服务器正式运行固定为 `cuda-bf16-amp-fp32-sensitive-v1` 与 `formal=true`。
- 模型、数据、机制、损失、指标、选择规则和检查点模式跨环境一致；只允许运行配置中显式白名单字段变化。
- CUDA 正式运行使用新 `run_id`、新随机初始化和新优化器状态从头训练，禁止加载 MPS 筛选权重续训。
- 本机预算不预填魔法数字；先由真实数据首个完整优化步和设备资源收据冻结。
