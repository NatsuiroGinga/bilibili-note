## 1. 修订动因

v4 合同的两处条文与 `lspr24_v2.parquet` 的真实模式冲突，按原文实现会让全部 2000 万行流在解析阶段进入隔离，或让时间语义没有唯一冻结实现。本次修订只闭合这两处冲突，方向已由正式入口修复报告的阻断项裁决。

### 3.2 §2.2 可用时刻：增补 `utc_ns` 冻结实现

修订前：`start_ns` / `last_ns` 公式块之后直接进入 `必须满足 start_ns <= last_ns`，`utc_ns` 没有唯一冻结定义。

修订后在公式块与该约束之间新增一段：

> `utc_ns` 的唯一冻结实现为 `utc_ns(x) = x × 1000`；`mTimestampStart/mTimestampLast` 的源单位为 UTC 微秒整数（已由 2026-08-06 页脚与数值范围审计确证）。乘法必须使用受检查算术，溢出即隔离。

这是纯增补，未删除或改写原有任何时间条文。

### 3.3 §3.1 分组解析器：`External_*` 类型与映射

| | 条文 |
| --- | --- |
| 修订前 | `External_*` 必须是 Parquet 布尔类型；空值、非布尔类型或同一端点在相同冻结输入中出现自相矛盾的内外部语义时，相关流全部进入 `resolver_quarantine`。 |
| 修订后 | `External_*` 源类型必须为 Parquet string；唯一冻结映射为 `"0"`→内部（被防御侧）、`"1"`→外部。空值、其他取值、非法 UTF-8 或同一端点在相同冻结输入中内外部自相矛盾时，相关流全部进入 `resolver_quarantine`。 |

隔离语义方向不变：不满足冻结映射的流仍然整流进入 `resolver_quarantine`，只是把判定依据从「布尔类型」换成「string 且取值属于冻结二元映射」。
