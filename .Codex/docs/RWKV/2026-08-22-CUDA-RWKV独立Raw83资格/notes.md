## 三、共享 Raw83 提交 `eeb0f4a`

### 3.1 已冻结事实

- LSPR23 原始压缩包为源年唯一拟合与选择来源；LSPR24 在完整源年资格封印前模式、特征和标签均不可打开。
- 83 字段必须按字段名投影，字段顺序固定；原始 IP 只构造无向实体侧车，`mTimestampStart` 只控制排序和序列身份，不入模。
- LSPR23 固定 `16,353,511` 条流、`271,815` 个长度 128 序列、`150,680` 个实体、`208,598` 个训练序列、`22,444` 个验证序列。
- `I[s,p]` 是原始流行号，`M[s,p]` 是有效位；训练有效流只能由 `I23[train_rows][M23]` 去重得到。
- 标签只在运行内按 `raw_row_index` 阶段化连接，不持久化逐样本标签或预测。
- 可解析有限数值默认保留，包括有限负值；端口、协议和三个二元粗拓扑字段另做结构强校验。

### 3.2 两个共享输入视图

- A：训练有效流均值填补、总体方差口径标准化、裁剪到 `[-10,10]`。
- B：索引 `3..78` 的 76 列使用官方固定参数的分位数正态变换；端口、协议和二元粗拓扑七列逐位复制 A。
- A/B 均为模型无关的 LSPR23 共享 `float32` 视图；视图身份只由年度、Raw83 内容、切分和变换状态哈希决定。
- 任何模型都不得在共享视图外重新用验证流拟合均值、方差、分位数、词表或类别权重。

### 3.3 当前实施状态

- 共享方案状态为 `DESIGN=READY`。
- 生产实现提交 `c581a12` 已完成静态验收，状态为 `IMPLEMENTATION=READY_FOR_REAL_DATA_GATE`。
- 该提交没有访问服务器、真实 ZIP、`I/M/E/T` 或 LSPR24，真实物化仍为 `EXPERIMENT=NOT_RUN`。
- 因此 2026-08-22 当前不存在可供 CUDA-RWKV 合法训练的已封印源年 Raw83 产品。

## 四、既有选择失效的根因

- 既有 `X23` 先对完整 LSPR23 全年度求均值与标准差，验证成员参与了拟合。
- 既有输入适配和容量选择建立在该矩阵上，违反“所有拟合只使用训练有效流”的固定开发划分。
- 提交 `f207f6e` 的配置继续把旧缓存列为输入，并要求读取旧结构封印收据；其选择资格不能迁移到共享 Raw83。
- 提交 `f207f6e` 的训练入口导入并动态改写另一训练入口，不满足“独立模型、训练、评价代码”的依赖闭包。
- 提交 `f207f6e` 的启动器还绑定旧训练文件、旧运行收据和旧输入数组，不能作为新的活动入口。
- 可保留的只有官方固定 CUDA 源码、许可证事实、统一精度模块、统一跟踪模块和共有研究合同；失效选择及其运行身份只作历史证据。

## 五、官方 CUDA 源码与后端

- 官方仓库：`BlinkDL/RWKV-LM`。
- 固定提交：`952102498e9ed367ea0a59ee64106916d474d30f`。
- 许可证：`Apache-2.0`。
- 官方源码：`rwkv7_clampw.cpp`、`rwkv7_clampw.cu`。
- 官方 CUDA 核前向接收 `r,w,k,v,a,b` 六个张量，输出逐位置状态混合结果；反向返回六个梯度。
- 输入、输出和六个梯度使用 BF16；递归状态、分块状态和核内累加使用 FP32。
- 现有供应商清单固定官方源码 SHA-256，派生 C++ 只修改注册命名空间并声明变化。
- 当前后端把目标环境冻结为 `torch==2.13.0+cu130`、CUDA `13.0`、计算能力 `12.0`、`sm_120`，并要求 `nvcc`、`ninja` 与 C++ 编译器。
- 新实现须重新建立中性命名的供应商目录与后端文件，逐字复制官方原件并保留许可证；不得导入现有训练入口或把任何历史训练文件列入身份哈希。

## 六、RWKV 数据适配证据

- 每个时间步是一条 83 维流记录，字段维不是时间维。
- 序列按无向实体和开始时刻排序，长度 128，连续非重叠；当前资格检验的是块内有序状态。
- 实体流数中位数为 2，头部实体高度重尾；状态机制是否有用必须由真实消融判断，不能由模型名称推断。
- 当前方案冻结块间状态重置，禁止跨块、跨实体、跨切分携带状态。跨块连续状态属于另一独立机制任务，不在本资格中混入。
- 12 语义组 R1 与同参普通投影 R2 只比较输入语义归纳偏置，不代表模型族容量上限。
- LSPR24 已被历史访问，只能作源年封印后的直接可比描述性评价。

## 七、朱焱雷论文对位证据

- 第三章为 ET-BERT 和 BUPT-CNN 分设模型适配小节，输入分别是长度 512 的离散 Token 序列与 `28×28` 灰度矩阵。
- 同一双模块框架按骨干改变挂载点与合法约束：嵌入层扰动与像素层扰动分别实现。
- 第三章按单模块、另一单模块、组合和完整系统组织消融，验证互补机制，不评选骨干冠军。
- 论文的任务是加密流量对抗鲁棒训练；其攻击、输入模态、扰动约束、训练配方、准确率指标与数值增益均不能迁移到 LSPR 网络攻击状态检测。
- 可迁移的只有组织原则：先说明研究问题，再给模型专属输入和挂载点，再用完整消融与资源证据裁决。

## 八、统一精度与跟踪证据

- 精度配置固定 `cuda-bf16-amp-fp32-sensitive-v1`：参数和优化器状态 FP32，BF16 自动混合精度，不使用 `GradScaler`。
- `neural_precision_runtime.py` 已提供精度合同、FP32 敏感岛、有效批累积、随机状态、检查点运行状态和资源收据接口。
- `tracking.py` 已提供目的地和有效标签门、原子标签收据与统一初始化入口；SwanLab 固定版本为 `0.9.0`。
- 提交 `89ddecf` 证明资源收据的后置增量必须按明确允许键集合比较，不可把“恰好七个键”写成脆弱门。
- 提交 `d6313ca` 冻结最多两次在线初始化：只有首次零步 `401` 可由启动器在全新 Python 进程重试一次；未知在途状态禁止再次初始化；已有成功收据只做本地封口。
- 提交 `70a8a2b` 证明成功收据必须哈希尝试目录中已经存在的标签收据，不能提前读取尚未复制的顶层文件。

### 8.1 PyTorch 技能与仓库合同差异

- 采纳 `pytorch-patterns` 的随机种子、显式形状、`model.train()/eval()`、验证无梯度、`zero_grad(set_to_none=True)`、完整训练状态断点和显存观测原则。
- 技能的 CPU/GPU 自动设备选择不适用于本候选；CUDA-RWKV 必须在冻结 CUDA 身份上运行，CUDA 不可用即停止。
- 技能的混合精度示例使用 `GradScaler`，与仓库 BF16 合同冲突；本方案按近层规则禁止缩放器。
- 技能的 `drop_last=True` 示例与“不补、不丢尾批”冲突；本方案按实际有效流数归一化尾批。
- 技能建议的 `torch.compile` 不进入首版，因为它会增加未登记可执行身份；后续若使用必须另立版本和哈希。
