# CUDA RWKV 独立正式资格实验实施计划

> **执行方式：**主代理已将本任务分派给独立实现代理 `rwkv_k0_fused_training_impl_sol_high`（`gpt-5.6-sol`，`effort=high`）。按 `writing-plans`、`daily-coding` 与 `pytorch-patterns` 执行；仓库规则禁止人工测试夹具、服务器访问、训练和自动格式化器，本任务只做生产入口与静态验证。

## 目标

新增一个与纯 PyTorch BF16 路径完全隔离的 K0 CUDA 融合数值变体正式资格入口。该入口只消费旧 Protocol A 已封印的 `R2/K0` 结构与同一训练合同，从种子 `42` 全新初始化并训练 `C00/C01/C10/C11`，不加载纯 PyTorch 模型、优化器、轮次或断点。

## 已知证据与裁决

- 官方 RWKV-7 训练使用 CUDA 融合 WKV 算子、BF16 输入输出以及核内 FP32 状态，因此 CUDA WKV 可作为正式主候选路径。
- 固定官方源码为 `BlinkDL/RWKV-LM@952102498e9ed367ea0a59ee64106916d474d30f`，许可证为 `Apache-2.0`。
- 本项目采用 `HEAD_SIZE=16`、`C=112`、`L=128`、R2 输入适配、单层 TimeMix，且没有完整官方 ChannelMix；它是任务化派生，不是未经修改的官方完整 RWKV。
- 既有 K0 资格基准的合成与 LSPR23 首批数值门通过，整轮速度比为 `8.668993`；但整轮验证 AP 绝对差为 `0.004199787`、reserved 显存比为 `1.099476`，未通过“透明替换”门。
- 用户已明确授权采用 CUDA 版 RWKV。该授权只允许另立独立数值变体，不把透明替换门改写为通过，也不构成效果支持。

## 实施步骤

### 任务 1：独立后端入口与身份

- [ ] 基于纯 PyTorch BF16 入口复用数据、训练、评价、恢复和聚合逻辑，只在新模块中接入 `rwkv7_k0_fused_backend`。
- [ ] 固定 `R2/K0`，拒绝 K1/K2、非 CUDA、非 BF16、后端源码或清单哈希不符。
- [ ] 将官方提交、许可证、派生源码哈希、融合后端哈希、基准身份及透明替换失败事实写入运行、检查点、聚合与 manifest 身份。

### 任务 2：独立训练与恢复边界

- [ ] 四格均从同一种子全新初始化，不读取纯 PyTorch模型、优化器、检查点或运行根。
- [ ] 保持 BF16 输入输出梯度、核内 FP32 状态和其他敏感 FP32 岛，不创建 `GradScaler`。
- [ ] 每 20 个完整优化步原子保存，并在恢复时机械校验 CUDA 数值变体身份与全部摘要。

### 任务 3：完整指标与目标隔离

- [ ] 训练 `C00/C01/C10/C11`，源年四格选择封印后才加载 LSPR24。
- [ ] 产出源年与目标年逐流 AP、实体 AP、最大池化实体 AP、六档实际 DR、完整告警预算曲线和 `exposure_index` 首次告警聚合。
- [ ] 产出首次完整步、总运行、恢复次数、峰值显存、主存、磁盘与后端构建身份收据。

### 任务 4：启动器与静态验收

- [ ] 新启动器使用独立 run_id、显示名、锁、screen、输出根、SwanLab 分组与扩展构建根。
- [ ] 运行 `py_compile`、模块导入、`--help`、JSON/解析配置、`bash -n`、参数量、后端身份、无 `GradScaler`、目标隔离和 `git diff --check`。
- [ ] 不运行 `black`、人工测试、训练、CUDA 编译或服务器命令。
