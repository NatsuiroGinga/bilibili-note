## 结论

已完成首个 `resmlp2` 六训练单元资格门的本地实现。实现只新增独立工具、单候选冻结配置和独立启动器，不包含 `resmlp4`、`resmlp6` 或 `tabm4` 配置与启动逻辑。当前状态为**实现完成、效果实验待证**；未访问服务器，未读取任何目标年数组，未启动真实实验。

本轮阻断修复代理映射为 `ch3_resmlp_xgb_evidence_fix_sol_high → gpt-5.6-sol → effort=high`。修复关闭两项 P0：历史 XGBoost 启动器摘要被误当成五数组摘要，以及逐流/序列正类权重读取全体 `y23` 导致的折间标签泄漏。

## 参数量核验

冻结公式为：

```text
P(B,d) = (2 + 2B)d^2 + (86 + 4B)d + 2
P(1,139) = 89,796
```

代码同时用逐模块展开公式计算参数量，并在正式 `build_model` 后再次对 `model.parameters()` 求和。C00 与 C11 只改变是否启用 CPA/ELP 计算，不改变参数外壳，因此两格均必须为 `89,796`。相对现有多层感知机 `90,242` 少 `446` 个参数，差异为约 `-0.494%`，位于预注册 `±1%` 内。

### P0 修订的静态合同

- 原始 XGBoost 启动器已只读核验：其 `input-sha256.txt` 写入命令仅包含父工具、父配置和父启动器，不含 `X23/y23/I23/M23/E23`。新工具已删除五数组解析和等值比较，仅校验这三个历史条目；当前五数组仍必须逐文件匹配多层感知机 E1 的 `input-identity.json`。
- `train_unit` 不再对全体 `y23` 求正例率，也不再从全部序列构造序列标签。新增 `training_label_balance` 按 `train_rows` 分块读取有效位置，记录训练序列数、训练有效流数、正负计数、逐流正类权重和序列正类权重，并写入单元身份、检查点、收据、状态与聚合结果。
- 聚合结果明示使用留出折逐流 AP 选择 epoch，故只承担源年快速资格筛选，不宣称是无选择偏差的独立折外泛化估计。

## 第三方接口核验

本实现只复用仓库中已经存在并经过真实运行的 PyTorch 同构接口：`nn.Linear`、`nn.LayerNorm`、`nn.ModuleList`、`nn.Dropout`、`torch.cumsum`、`torch.logsumexp`、`AdamW` 和梯度裁剪；没有引入签名不确定的新第三方接口，因此未触发 Context7 查询。

隔离工作树自带虚拟环境缺少 `numpy`；主项目现有本地虚拟环境可完成配置入口导入，但不含 `torch`。因此本机没有实例化真实 PyTorch 模型。正式运行时 `build_model` 会对实际模块参数重新求和，不等于 `89,796` 时在读取训练数据后的模型构建阶段立即停止；聚合制品会记录服务器实际 `torch.__version__`。计划目标环境为 PyTorch 2.8 系列，服务器实际版本仍须在后续授权运行前核验。

## 风险与后续门禁

1. 历史 XGBoost 没有持久化五数组逐文件哈希，因此不能证明其输入与本次五数组密码学同一。源年快速筛选只依赖冻结父工具/配置/启动器摘要、选择与有效配置收据、精确折统计、恢复证明、模型哈希和树数；本次五数组另与多层感知机 E1 输入身份逐文件匹配。该证据局限不机械阻断快速资格，但禁止升级为历史 XGBoost 五数组密码学同一主张。
2. 留出折逐流 AP 参与 epoch 选择，pooled OOF 带选择偏差，只能用于单种子源年筛选；正式替换结论仍须来自冻结候选在新的独立漂移域的一次性评价。
3. 本机缺少 PyTorch，未完成真实张量前向与参数实例化核验。服务器授权后必须先执行正式入口内的依赖、配置和 `build_model` 参数量门，不得建立独立冒烟运行身份。
4. 未产生 LSPR23 指标。残差深度信号、相对 XGBoost 的差距和源年资格均为实验待证；不得据本实现报告启动 `resmlp4` 或写入论文效果结论。
