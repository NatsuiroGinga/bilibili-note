## 1. 两项改动的实现方式与依据

### 1.1 V1：排除 MOC 导航页

**实现位置**：`scripts/literature_search/documents.py:load_notes`（第 154–186 行）。

```python
if is_navigation_page(path):
    # 排除 MOC 导航页，见 NAVIGATION_PAGE_FILENAME 处的实测依据。
    continue
```

`is_navigation_page(path: Path) -> bool` 用 `path.name == "INDEX.md"` 判定，判定发生在
`for path in sorted(repo_root.glob(pattern))` 循环内、读取文件内容之前——不读取被排除文件的
字节，也不产生对应的 `NoteDocument`。判定用 `Path.name`（真实文件名），不是从相对路径字符串
裁剪或建字典键，因此不受知识图谱代理报告的“裸文件名做字典键会静默覆盖”陷阱影响
（该陷阱只发生在按文件名去重合并时；此处是逐文件布尔跳过，天然不会合并同名文件）。

**依据**：`.Codex/docs/RWKV/2026-08-28-文献检索精度评测与改进方案.md` 第 4.1 节实测——
15 个 `INDEX.md` 占语料 2.9%，却占据 40% 查询第 1 名命中、17.6% 的 Top-5 位次，超额表征
约 14 倍。依据已写入 `documents.py` 模块顶部常量 `NAVIGATION_PAGE_FILENAME` 旁的中文注释，
可一眼看到排除规则与理由。

**与前序测量脚本的对应关系**：`.Codex/docs/RWKV/litsearch_precision/build_variants.py:
is_navigation_page` 用的是同一判据（`relative_path.rsplit("/", 1)[-1] == "INDEX.md"`），
生产实现语义等价（`Path.name` 与相对路径取最后一段结果相同），只是换成更直接的 API。

### 1.2 V2：索引 frontmatter 的 tags 与 key_finding

**实现位置**：同文件，新增三个函数：

- `parse_metadata_fields(text) -> Dict[str, object]`（第 66–103 行）：独立于既有
  `parse_frontmatter`，支持单行标量、缩进列表（`tags:` 换行后 `  - x`）与内联数组
  （`[a, b, c]`）三种 YAML 写法，返回值可以是 `list`。
- `render_metadata_section(fields) -> str`（第 106–122 行）：把 `METADATA_FIELDS =
  ("tags", "key_finding", "venue", "authors", "year", "aliases")` 六个字段渲染成
  `"## 条目元数据\n\n字段：值\n...\n\n"` 格式的正文小节。
- `load_notes` 内新增两行：

```python
metadata_section = render_metadata_section(parse_metadata_fields(text))
body = (metadata_section + body.strip()).strip()
```

**契约保持不变**：既有 `parse_frontmatter(text) -> Tuple[Dict[str, str], str]` **未做任何修改**，
其简单标量字典契约（`title`、`source_pdf`、`doi` 等调用方依赖 `fields.get(key, "").strip()`
这类字符串操作）继续成立。`parse_metadata_fields` 是完全独立的新函数，只服务于“元数据小节”
这一新用途，两者各自对同一段 frontmatter 文本重新执行一次正则匹配（525 篇笔记量级下开销
可忽略，构建全程仍 <1 秒，见第 3 节）。

元数据小节以 `## ` 二级标题拼接在正文最前面，因此天然成为 `chunk_note` 里
`_section_units` 识别出的第一个小节，走既有分块通路参与词法与（未来的）向量检索，
不需要修改 `chunk_note`、`storage.py`、`lexical.py` 或 `ranking.py` 任何一行。

**依据**：报告第 4.2 节实测——`parse_frontmatter` 原实现把整段 frontmatter
（含 `tags`、`key_finding`）连同其后的 `text[match.end():]` 一起剥离丢弃；`tags` 覆盖率
100.0%、`key_finding` 覆盖率 96.6%，全库对这两个字段字面量的检索命中数原为 0。

**附带效果**：`venue`、`authors`、`year`、`aliases` 一并可检索（这些字段过去同样被
`parse_frontmatter` 剥离丢弃，只是覆盖率远低于 `tags`/`key_finding`，报告未单独测量其增量）。

## 5. 协调者补充事实的处理：V4（排除重定向页）实测被否决

协调者传达知识图谱代理的发现：`wiki/papers/` 除 15 篇导航页外，还有 28 篇“重定向页”
（frontmatter `status: 重定向` 或 `tags` 含 `类型/跳转页`），并建议在 V3 复现成功后
额外试一个 V4（排除重定向页），只在四项指标不劣于 V3 时才采纳。

V3 复现成功后按建议做了实测，脚本 `.Codex/docs/RWKV/litsearch_precision/
build_v4_variant.py`（不改生产代码，复用已落地的生产 `load_notes` 输出后再过滤，写到
独立索引 `.cache/literature-search/index_V4.sqlite3`，评测后已删除该临时索引文件）：

```
V4: 笔记=482（排除重定向页 28 篇） 分块=7138 耗时=0.971s
```

```

----------------------------------------------------
lexical        0.9149      0.9272   1.0000    0.9450
```

| 指标 | V3（生产默认） | V4（+排除重定向页） | 结论 |
| --- | ---: | ---: | --- |
| Recall@5 | 0.9332 | 0.9149 | **变差** |
| Recall@10 | 0.9556 | 0.9272 | **变差** |

| nDCG@10 | 0.9657 | 0.9450 | **变差** |

**否决，未采纳，未改动生产代码。** 根因在于评测集自身的判定规则第 2 条：
“同一篇论文在仓库中的所有笔记都计为相关，包含重定向页与占位页”——重定向页在
`evaluation_queries_real.json` 里是**合法的相关文档**（例如 K04「NetMamba」查询的 3 篇
相关路径之一 `wiki/papers/rwkv/2024-Wang-NetMamba-网络流量分类.md` 正是知识图谱报告点名
的那篇跳转页）。这与导航页的情况结构性不同：导航页在判定规则里**从不计为相关**（第 3 条），
排除它们只移除错误命中；重定向页**会被计为相关**，排除它们直接减少可命中的目标数，
因此结构上必然拉低召回类指标。V4 的负结果因此完全符合预期，不是实现缺陷。

已按硬约束要求如实记录，未因该负结果重跑或调参掩盖。
