# RWKV 恢复协议分流设计

## 目标

让显式绑定 `RWKV` 的会话在上下文压缩或重启后只恢复 RWKV 路线，不再默认加载 PINN/R2 的两份 `output/` 总控；同时保持原 PINN/R2 会话的恢复行为不变。

## 设计

1. 项目根 `AGENTS.md` 先判断研究路线，再选择恢复文档。
2. 显式绑定 RWKV 的会话读取 `.Codex/docs/RWKV/AGENTS.md` 与 `.Codex/docs/RWKV/RWKV路线总控.md`。
3. 未显式绑定其他路线的会话继续读取 `output/开题改进交接文档.md` 与 `output/第一创新点实验总控.md`。
4. RWKV 总控只保存当前裁决、实际进度、活动任务、阻塞和唯一下一顺序；详细设计与报告只通过链接按需读取。
5. 跨路线比较、决定替换论文主线或返回 PINN/R2 时，才按任务范围读取和更新 `output/` 文档。

## 安全边界

- 不创建全仓共享的“当前活动路线”开关，避免一个会话改变其他并行会话的恢复路线。
- 使用字面哨兵 `RESEARCH_ROUTE=RWKV`，要求上下文摘要保留该标识。
- 路线不明确时停止实验分派并向用户确认，不能同时加载两套恢复文档后自行推断。
- 本次只修改 Markdown 规则和恢复文档，不修改实验代码、数据、服务器状态或论文主线裁决。

## 验收

- 根规则能够明确区分 RWKV 与 PINN/R2 两条恢复路径。
- RWKV 局部规则不再把两份 `output/` 文档列为默认先读项。
- RWKV 总控包含路线哨兵、当前事实、下一门禁和按需证据链接。
- 三份规则不存在相互矛盾或循环读取。
