# RWKV-7 首轮资源门根因与修订笔记

## 真实运行证据

- 设备：B76，RTX 5090。
- 旧运行身份：`ch3-rwkv7-field-aware-protocol-a-2x2-seed42-v1`。
- 停止位置：`adapter-R0-K0-C00` 完成第 `1/20` 轮、`1000` 步后。
- 全局日志时间：第 `250/500/750/1000` 步分别为 `45.8/81.2/116.6/152.1` 秒。
- 资源门投影：当前单元加后续五个等价单元累计 `4.844 GPU 小时`，超过冻结 `4.5 GPU 小时`。
- 运行状态：计算入口为 `failed/exit=1/stage=runtime`；目标年数组读取计数为 `0`；GPU 已空闲。
- 恢复制品：存在 `inflight/adapter-R0-K0-C00.pt` 和梯度收据。
- 启动器状态：`screen` 已退出，但启动器状态仍陈旧为 `running`。

以上均来自本任务提供的真实收据摘要；本任务不访问服务器复核。

## 代码证据

- `train_candidate` 在每轮完成后用 `elapsed × 20 / epoch` 估计当前完整单元，再乘当前单元与剩余等价单元数量。
- 首个 R0/K0/C00 的 `reserve_equivalent_runs=5`，因此首轮投影六个单元，没有把已完成首轮重复算成额外单元。
- 当前每 `20` 步写一次 `inflight`。每次保存均包含模型 CPU 克隆、优化器、最佳状态、历史、随机状态和生成器状态。
- 每轮结束另存完整轮权重并覆盖完整轮 `inflight`，因此降低轮内保存频率不影响轮级制品。
- 启动器 `worker` 在 `run_logged` 返回非零后直接 `return`，只有成功路径写 `finished`，所以启动器状态会停留在 `running`。该问题与预算根因独立，本轮先记录，不与性能变量同时修改。

## 定量判断

- 资源缺口：`(4.844 - 4.5) / 4.5 = 7.64%`。
- 第 `250` 步后的三个 250 步区间均约 `35.4` 秒，说明运行稳定推进，没有卡死证据。
- 首轮约 `2.4` 分钟的已完成计算不足以支持开发跨代码身份迁移；新身份从头重算更简单且可审计。

## 裁决

- **不是投影公式错误**：公式表达的六单元执行图正确。
- **没有实现效率结论**：纯 PyTorch 递归本身较慢，但本轮不引入 CUDA 内核、混合精度或编译，因为这些会改变数值路径或引入新接口风险。
- **撤销人为工程预算**：`4.5 GPU 小时`不是科学门，用户已明确取消所有运行时长与 GPU 小时上限；不设置替代上限。
- **不附带提速修改**：在途检查点频率、训练数值路径和评价路径保持不变。
- **旧在途状态不复用**：代码身份和配置身份改变，新身份重算首轮。
