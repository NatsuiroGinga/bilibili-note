# FT C01/C10 提前目标年描述评价证据笔记

## 任务边界

- 输入：已完成的 FT C01、C10 LSPR23 源运行及各自 `selected-by-entity` 检查点。
- 输出：独立目标年描述评价运行目录及同口径基线比较。
- 本地阶段：只做实现与静态入口验收，不访问服务器、不读取 LSPR24、不运行评价。

## 已确认事实

- 目标六个文件在实施前均无工作树改动，不需要创建额外 Git 快照。
- 工作树存在大量其他代理或用户改动，本任务不修改、不暂存、不提交这些文件。
- 根规则要求手工文件修改仅使用 `apply_patch`；Python 不运行 `black`，实验代码不新增人工测试夹具。
- 现有 FT 目标年评价器已经提供同源数组核验、封印变换、模型回载、CEM 目标实体链扫描、最大实体聚合、资源统计和完整预算曲线；新入口只增加两格单角色编排。
- C01 与 C10 源运行均为 `finished`、`exit_code=0`、`target_reads=0`，实体规则都选第 17 轮；C01 源实体 AP 为 `0.9537273846736761`，C10 为 `0.8150313407035376`。
- 两格配置都声明启用 `torch_compile`，但恢复卡记录实际历史路径为 C01 编译、C10 即时执行；配置开关不能替代实际调用路径收据，故本次目标年结果不得升级为正式同路径比较。
- 当前指标总表程序为 `tools/ch3_build_metrics_table.py`，来源登记册为 `configs/ch3-metrics-table-sources-v1.json`。程序会把 LSPR23 选择、LSPR23 性能、LSPR24 描述评价和资源分表，且实体 AP 与最大实体 AP 分列。
- XGBoost＋CPA-ELP 的主实体 AP 来自 C11 的前缀算术均值，最大实体 AP 由登记册明确锚定 C10 最大池化格；两者不得混成同一指标。
- 全容量 MLP O11 同一制品同时给出主实体 AP 与最大实体 AP，可分别同列比较。

## 待核接口

- 正式运行后核验程序生成表中同池可比较行是否全部齐备；缺行只报告证据缺口，不反推胜负。
