## 根因与修复

两个工具原先都在 `finish()` 返回后才写本地成功收据，且清单缺失时会重新进入发布路径。因此，云端完成后、本地收据或清单写入前中断会产生重复运行风险；首次零步 `401` 也没有新进程的一次上限恢复合同。

本轮统一实现：

1. 每个工具最多存在 `attempt-1` 与 `attempt-2` 两个在线初始化尝试。
2. 只有首次零步 `init 401` 返回专用退出码 `91`；非 `401` 和第二次失败均停止。
3. 启动器收到 `91` 后重新运行 `swanlab ping` 与 `swanlab verify`，再用新的 `uv run --no-sync python` 进程执行第二次尝试。
4. `init` 返回后立即原子写 `inflight-receipt.json`，登记云端运行 ID、尝试编号、阶段和生产身份。
5. `finish()` 返回后立即写 `success-receipt.json`。没有成功收据的在途状态视为云端终态未知，禁止再次初始化。
6. 成功收据存在而 `manifest.json` 缺失时，只重建顶层标签收据、SwanLab 收据、状态和清单。
7. 最终清单逐文件登记尝试收据、标签收据、健康门日志和 SHA-256，并独立登记生产身份摘要。
