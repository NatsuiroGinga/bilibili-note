# N-15/N-16 SwanLab 单运行恢复修复证据笔记

## 已确认事实

- 中央标签和目的地门的稳定提交为 `89ddecf`。
- SwanLab 锁定版本为 `0.9.0`。
- 故障手册规定：同一 Python 进程不得连续创建多个正式在线运行；零步初始化 `401` 只允许在保留失败证据后，以全新进程重试一次。
- N-15 当前生产提交为 `a3cf1c5`，报告订正为 `56a1295`。
- N-16 当前生产提交为 `5476798`。

## 新发现

- 两个工具都在云端发布完成后才继续写本地收据、状态和清单，存在云端已完成但本地未封口的中断窗口。
- 两个启动器均未实现与 GRANDE 发布修复相同的一次新进程 `401` 重试合同。
- 该问题只影响跟踪生命周期和恢复证据，不否定已经修复的共同整数 FP 预算、首次告警共同轴、父输入哈希或零训练边界。

## 单一修复假设

把 SwanLab 发布视为独立的两次上限状态机，并把“云端尝试状态”和“本地科学制品封口状态”分开记录，可以在不改变任何科学数值的前提下消除重复运行和无限重试。

## 根因证据与可证伪判据

- N-15 的 `publish_tracking()` 与 N-16 的 `publish_tracking()` 都在 `finish()` 返回后才写顶层 `swanlab-receipt.json`，存在云端已完成而本地无成功收据的窗口。
- 两个入口在 `manifest.json` 缺失时都会再次进入发布路径；现有启动器没有按首次零步 `401` 区分专用退出码，也没有第二次健康门和新进程边界。
- 若状态机实现正确，则代码路径必须满足：非 `401` 永不返回 `91`；`attempt-2` 无首次合法失败收据时拒绝；任一在途未知状态拒绝；合法成功收据存在时不调用中央初始化接口。
- 本任务按仓库禁令不创建或运行人工测试，以上判据通过静态入口、配置门、Shell 语法和差异检查验收，真实在线行为留给主进程后续服务器运行验证。
