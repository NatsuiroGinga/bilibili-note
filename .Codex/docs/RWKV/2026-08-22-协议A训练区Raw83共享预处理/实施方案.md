# 协议 A 训练区 Raw83 共享预处理实施方案

- **状态**：`DESIGN=READY`、`IMPLEMENTATION=NOT_STARTED`、`EXPERIMENT=NOT_RUN`
- **适用范围**：第三章 Protocol A 的表格 ResNet、FT-Transformer 与后续神经骨干
- **不适用范围**：改变 83 字段预算、重定义实体、重切 Protocol A、恢复三折、用 LSPR24 选输入

## 一、结论

推荐建立一个模型无关的 Raw83 数据产品，并把“拟合状态”和“训练视图”分开：

1. LSPR23 ZIP 与 LSPR24 Parquet 分阶段按**字段名**流式投影；Raw83 规范值、无向 IP 实体、`mTimestampStart` 和 Protocol A 序列索引有独立制品与哈希。源侧全部封印前不得打开 LSPR24 的模式、特征或标签。
2. 旧 `X23.npy/X24.npy` 只作历史语义核对，**禁止作为新变换的拟合源**。旧 `I/M/E/T` 的成员与切分身份可在完整哈希核验后复用。
3. 候选 A 在 LSPR23 训练有效流上做均值填补、`StandardScaler` 与 `[-10,10]` 裁剪；候选 B 对 76 个连续/计数字段采用官方 `e3ed46c` 的分位数参数，七特殊字段复制候选 A 的对应列。
4. LSPR23 为候选 A、B 各物化一份**共享** `float32` 视图；输入、配方、容量、检查点、机制和评价代码全部完成源侧资格封印后，LSPR24 只物化胜出臂。模型不得再各自复制全年度矩阵。
5. 标签不持久化。训练器或评价器按阶段从原始数据流式加载 `y` 到运行内存，以 `raw_row_index` 连接；只保存标签内容 SHA 和聚合计数。

该方案比“Raw83 加训练时全在线变换”多占约 `16.37 GiB` 的共享臂级视图，但避免每个 epoch 对数亿流出现重复分位数插值。它也比“每模型两年度两臂各存一份”严格有界：视图由变换状态决定，不由模型决定。

1. 旧 `select_signal` 对完整 LSPR23 求均值/标准差，随后标准化 LSPR23 与 LSPR24 并落盘；这不是 Protocol A 训练区状态。

### 3.2 字段、切分与因果

| 项 | 冻结合同 |

### 3.3 缺失、非法值与标签

原始解析先在 `float64/int64` 中做检查，再把合法模型值规范为小端 `float32`。以下原因分开计数，但在 Raw83 值槽统一编码为规范静默 `NaN`：

- CSV 空字符串或 Parquet `NULL`；
- 解析失败；
- `NaN`、正无穷、负无穷；
- 端口非整数或越出 `[0,65535]`；
- 二元字段不属于 `{0,1}`；
- 协议/计数/标志/时长/IAT/速率等已冻结为非负的字段出现负值；负一类哨兵同样记为非法后转缺失。

每列必须记录原始总数、各原因数、合法有限数、最小值、最大值、均值所需和/补偿项、是否常量。任一字段在训练有效流中合法数为零即失败；是否删除字段不能由 LSPR24 触发，本方案固定 83 字段，因此全缺列不能静默删除。

标签只取字段名 `Label`，规范为 `{0,1}`。标签读取器输出运行内 `int8` 数组或流式批，不落盘。训练逐流正类权重和序列正类权重只从训练有效流/训练序列计算并保存聚合分子、分母和哈希；禁止 `labels.mean()` 覆盖全年度或验证区。

| 消费者 | 输入 | 输出 | 状态 | 梯度 |
| --- | --- | --- | --- | --- |

| FT-Transformer | Raw83 特殊列＋A/B 数值列、`M` | 逐字段 Token 与对数几率 | 训练区词表/越界桶，引用 Raw83 与 split 哈希 | 梯度只到 Token 与主干参数 |

### 5.1 Raw83 模式

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `raw_row_index` | 隐式 `uint64` | 等于矩阵行号；不另存一列 |
| `x_raw83` | `float32[83]` | 小端、C 连续、按 Dijk 固定顺序；缺失为规范 NaN |
| `flow_entity_id` | `uint32` | 同年度内稳定实体编号，不入模 |
| `entity_digest` | `bytes[32]`，每实体一条 | 规范无向 IP 对摘要；受控侧车 |
| `mTimestampStart` | `int64` | 原始值；只作排序、映射和审计 |

标签接口不属于磁盘模式。运行时 `LabelResolver` 必须核对源文件 SHA、行数、按字段名投影的标签内容 SHA 和请求的年度/阶段，再提供按 `raw_row_index` 的只读连接。

### 5.2 序列和切分兼容

新产品不重新发明序列。实现先按 SHA 读取旧 `I/M/E/T`，再逐项验证：

1. `I`、`M` 同形，`M` 仅含 0/1；所有有效 `I` 均在流行范围内。
2. 每个有效 `raw_row_index` 恰好出现一次；若旧制品存在重复或遗漏，停止并单独裁决，不能在共享层悄悄修补。
3. 同一序列的全部有效流属于同一 `flow_entity_id`，时间非降；填充只在尾部。
4. `E23/T23` 与原序列首流的实体/时间一致。
5. 重新计算固定 `train_rows/validation_rows` 后，完整数组和成员哈希与冻结值一致。

通过后可逐字节复制或硬链接到共享数据根；跨文件系统时复制后重算文件 SHA。任何重新生成但只“统计相同”的 `I/M/E/T` 都不能自动替代旧身份。

## 六、生产阶段

### 6.1 阶段 P0：源年模式预检

- 只核对 LSPR23 源文件字节数与 SHA，从 ZIP 内唯一 CSV 读取表头。
- 要求 83 字段、`Label`、`SrcIP`、`DstIP`、`mTimestampStart` 全部存在且名称唯一。
- 按名投影器不得持有任何 LSPR24 路径或打开句柄；两年度最后九列顺序差异只作为已核历史事实登记，目标侧相同门在阶段 P6 独立执行。

### 6.2 阶段 P1：Raw83 与侧车

只处理 LSPR23，按源行顺序流式处理，不按实体、标签或时间重排。每批：

1. 以字段名投影 83 字段、两个 IP、开始时间和标签；标签只计算内容 SHA 和聚合计数，不写逐样本文件。
2. 在 `float64/int64` 做缺失与非法分类，更新聚合统计，再规范为 `float32` Raw83。
3. 计算无向 IP 对摘要和 `flow_entity_id`；原始 IP 不写入模型数据根。
4. 写入预分配 `.partial` 映射文件；批完成后同步并写独立原子收据。
5. 断点恢复时，LSPR23 ZIP 必须从头重放解压流，但已完成批只重算哈希并跳过写入，直到抵达首个未完成行。

### 6.3 阶段 P2：Protocol A 绑定

- 导入并哈希核验 `I/M/E/T`。
- 生成 `train_rows`、`validation_rows` 和训练有效流位图。
- 只保存切分/位图，不保存标签。
- 输出 `sequence_split_state_hash`，覆盖源 `I/M/E/T` 内容 SHA、算法、种子、比例、实体成员哈希、行数组和有效流位图哈希。

### 6.4 阶段 P3：候选 A 状态

只遍历训练有效流。对每列先计算合法值均值；缺失填为该均值后，再按 `StandardScaler` 的总体方差口径拟合：

```text
filled(x_j) = x_j                         若合法
              mean_j                      若缺失或非法
z_j = (filled(x_j) - mean_j) / scale_j
a_j = clip(z_j, -10, 10)
```

常量列按 `StandardScaler` 语义取 `scale_j=1`。实现优先用目标版本 `StandardScaler.partial_fit` 的分块等价路径；状态保存 `mean_`、`var_`、`scale_`、训练有效流数、各列填补数、scikit-learn 版本和状态数组 SHA。

`[-10,10]` 是本课题既有 Protocol A 的任务化数值稳定设置，无 Gorishniy 论文精确依据；它只在 LSPR23 输入臂选择中裁决，不能写成官方配方。

### 6.5 阶段 P4：候选 B 的官方参数任务适配分位数状态

对索引 `3..78` 的 76 列执行：

```text
n_quantiles = max(min(n_train // 30, 1000), 10)
output_distribution = "normal"
subsample = 1_000_000_000
random_state = 42
noise_scale_j = 1e-3 / max(std_j, 1e-3)
```

缺失先用训练区均值填补；`std_j` 是填补后训练矩阵的 `np.std(..., ddof=0)`。随后复制训练矩阵，加入一次 `np.random.default_rng(42).standard_normal((n_train,76))` 的行主序噪声，再拟合 `QuantileTransformer`。

为保持官方随机流而不占约 `9.26 GiB` 主存，默认把一次性 `float64` 噪声输出写入 C 连续磁盘映射临时文件；这仍须在目标 NumPy 版本核验 `out` 参数和逐位一致性。之后生成至多约 `4.63 GiB` 的 76 列 `float32` 噪声训练映射，每次只把一列载入 `QuantileTransformer.fit`，得到共同 `references_` 与每列地标。因为 `n_train < 1e9`，不发生随机子采样。

状态保存：训练均值/标准差/噪声尺度、`quantiles_`、`references_`、官方提交、NumPy/scikit-learn 版本、单次行主序随机流说明、临时文件内容 SHA 和训练有效流哈希。

**偏离规则**：现有 FT/N14 的 `seed+dijk_feature_index` 逐字段随机流不是官方行为。若未来为节省磁盘采用它，必须使用新臂键 `quantile-per-field-seed-deviation`、独立状态哈希和源年选择；不得覆盖本候选 B，也不得自动回退。

七特殊字段不参与分位数噪声与地标拟合，候选 B 输出直接复制候选 A 的对应列。端口保持数值，不独热、不建词表、不分桶。**官方源码对传入的全部数值列统一规范化，并未规定本课题的七字段旁路；“76 列官方参数＋七列 A 透传”是有源年选择门的任务适配，不得写成官方原配方。**

### 6.6 阶段 P5：共享视图与源封印

- 全量 LSPR23 分别生成 A、B 两个 `float32[16,353,511,83]` 只读视图。
- 每批变换后必须全有限、字段顺序不变、行数不变；批内容 SHA 汇聚成全视图内容 SHA。
- 表格 ResNet 的 C00 输入选择只消费这两个视图，按冻结 LSPR23 验证逐流 AP 封印唯一输入臂。
- `source-input-arm.json` 必须含两个状态哈希、两个视图哈希、选择检查点/指标/并列规则和 `target_feature_rows_read=0`、`target_label_rows_read=0`。它只封印输入臂，**不能单独解锁目标年**。
- 模型配方、容量、源选择检查点、机制版本和评价代码也完成源侧封印后，由实验入口签发 `source-qualification-seal.json`。该封印引用输入臂封印哈希，并继续断言目标特征/标签读取均为零。

### 6.7 阶段 P6：封印后的目标年产品

只有 `source-qualification-seal.json` 存在、内容哈希有效且覆盖输入、配方、容量、检查点、机制和评价代码时，才可首次打开 LSPR24：

1. 读取 Parquet 模式，按字段名核对 83 字段、`Label`、两个 IP 与 `mTimestampStart`；同时验证最后九列物理顺序与 LSPR23 不同，列号绑定实现必须失败。
2. 按行组生成 LSPR24 Raw83、实体和开始时间侧车；标签只在描述性评价进程的运行内解析，不落盘。
3. 只用源年冻结状态生成胜出臂目标视图；不得拟合、更新均值/标准差/地标/词表，也不得生成落败臂视图。
4. 断点恢复按 Parquet 行组继续，任何源资格封印哈希变化均拒绝拼接。

## 七、容量、内存与磁盘上界

### 7.1 主数据体积

| 制品 | 公式 | 上界 |
| --- | --- | ---: |
| LSPR23 单个 `float32` 83 列视图 | `16,353,511×83×4` | `5.06 GiB` |
| LSPR24 单个 `float32` 83 列视图 | `20,227,356×83×4` | `6.26 GiB` |
| 两年度 Raw83 | 上述两项之和 | `11.31 GiB` |
| 两个源候选视图 | `2×5.06` | `10.11 GiB` |
| 一个目标胜出视图 | `1×6.26` | `6.26 GiB` |
| 推荐方案特征总载荷 | Raw83＋源 A/B＋目标胜出 | `27.68 GiB` |

数值不含 NPY 头、序列和侧车。无向实体用每流 `uint32` 加每实体 32 字节摘要，开始时间用每流 `int64`；两年度合计低于 `0.5 GiB`。`I/M/E/T` 按旧 dtype 逐字复用，另按实际文件字节计入门禁。

### 7.2 分位数临时空间

以全部 LSPR23 流都属于训练有效流作保守上界：

- 官方行主序 `float64` 噪声：`16,353,511×76×8 ≈ 9.26 GiB`；
- 噪声后的 `float32` 训练矩阵：`16,353,511×76×4 ≈ 4.63 GiB`；
- 单字段排序/百分位临时：每字段原值约 `62.4 MiB`，实现须按目标库实测乘数计入，不并行 76 列。

启动空间门不使用固定猜测值：

```text
required_free = 尚未存在的最终制品字节
              + 尚未完成的最大临时阶段字节
              + 最大单个原子发布文件字节
              + 仓库统一磁盘低水位 10 GiB
```

不满足即停止，不自动删旧制品或降低科学合同。

### 7.3 主存上界

Raw83 解析批的显式工作集按下式登记：

```text
peak_batch_bytes <= B × 83 × (8 解析 + 4 规范值 + 8 噪声/统计 + 4 输出 + 1 掩码)
```

`B` 不写死为科研常量；根据 cgroup 可用内存和上式反解，并限制在源 RecordBatch/行组边界。分位数每次只处理一列，不同时排序多列。所有跨批集合必须是固定 83 列统计、实体字典或磁盘溢写；实体字典超过预估时切换外排，不允许随流数无界驻留 Python 对象。

## 八、原子断点与恢复

每阶段有独立状态机：`pending -> running -> sealed`，失败保持 `failed` 和原退出码。

1. 写大文件前预分配 `.partial.<run-id>`，已完成批由独立收据记录 `[start_row,end_row)`、输入位置、输出内容 SHA 和累计统计 SHA。
2. 批收据先写临时 JSON，再原子替换；状态文件不能先于数据同步。
3. 恢复时重新核验源文件、代码、字段、split 和已完成批的内容 SHA。任一不符拒绝拼接。
4. CSV ZIP 不能随机跳转，恢复从头重放并验证已完成区；Parquet 按行组直接恢复。
5. 分位数状态只有噪声、地标和自检全部完成后才封印。临时噪声属于可再生中间物，只有在状态、视图和清单哈希全部通过后才按精确清单清理；失败时保留用于诊断。
6. 视图封印后设只读。消费者没有写权限，模型运行不能改变共享状态。

## 九、消费者接口

建议生产模块公开以下稳定接口，具体类名可在实施计划中微调，但语义不得改变：

```python
open_protocol_a_dataset(manifest_path, year, purpose, arm=None, source_qualification_seal=None)
dataset.gather_sequences(sequence_rows, columns="all83")
dataset.gather_raw_fields(raw_row_indices, field_names)
dataset.iter_feature_batches()
dataset.open_label_resolver(stage_token)
dataset.receipt()
```

### 9.1 能力分离

- `purpose="fit"`：只允许 LSPR23 训练有效流和 Raw83；没有标签、验证或目标接口。
- `purpose="train"`：只允许 `train_rows`、封印源视图和 LSPR23 训练标签连接。
- `purpose="validate"`：只允许 `validation_rows`、同一源视图和验证标签；只读。
- `purpose="target-evaluate"`：要求完整源资格封印哈希；可读取胜出目标视图、目标实体和运行内目标标签；无拟合接口。

每次 `gather_sequences` 返回 `features`、`valid_mask`、`raw_row_indices`。标签另由阶段化解析器返回，避免特征加载器无意暴露标签。FT-Transformer 请求原始特殊字段时必须显式列名，加载器不提供任意元数据投影。

### 9.2 兼容策略

- 模式版本固定 `ch3-protocol-a-raw83-shared-v1`。主版本不匹配立即失败，不做列位置回退。
- 消费者登记 `field_list_sha256`、`raw_content_sha256`、`sequence_split_state_hash`、`transform_state_hash` 与接受的 dtype/shape。
- 旧工具迁移后禁止直接 `np.load(X23.npy/X24.npy)`；旧数组只可通过明确的历史核验入口读取。
- 同一状态哈希的视图可以跨模型共享；不同状态即使展示名相同也不能拼接。
- 新字段、不同合法性规则、不同随机流或不同裁剪口径必须升状态/模式版本，不能覆盖 v1。

## 十、哈希与清单

每个最终制品同时记录：

1. **来源 SHA**：ZIP/Parquet 文件 SHA、内部 CSV 名和 Parquet 行组清单。
2. **模式 SHA**：83 字段名、索引、规范 dtype、合法性规则、缺失规则和物理单位的规范 JSON SHA。
3. **内容 SHA**：不含容器头的规范小端 C 行主序值字节 SHA；另记录物理文件 SHA。
4. **切分 SHA**：`I/M/E/T`、`train_rows`、`validation_rows`、训练有效流位图及算法台账的组合 SHA。
5. **状态 SHA**：候选配置、训练区身份、状态数组 SHA、库版本、代码 SHA、官方提交和随机流说明的规范 SHA。
6. **视图 SHA**：Raw83 内容 SHA＋状态 SHA＋年度＋每批内容 SHA 的组合 SHA。

状态哈希禁止包含绝对路径、mtime 或进程号；这些只进资源收据。清单发布后重算链接目标、文件大小和 SHA，拒绝缺文件、额外标签文件、符号链接越界或路径逃逸。

## 十一、科研数值依据台账

| 数值 | 用途 | 依据与边界 |
| --- | --- | --- |
| `83` | 字段数 | Dijk 2026 附录 A；本项目统一合法信息预算 |
| `76+7` | 候选 B 字段分组 | 由 83 字段扣除两个端口、两个协议和三个二元粗拓扑字段得到；七字段旁路无官方直接依据，是 LSPR23 输入选择中的任务适配 |

## 十二、最小真实数据验证与失败门

本方案不创建人工训练夹具，不用子集判断性能。实现后的第一条真实验证链为：

1. **源模式门**：只读取实际 LSPR23 ZIP 表头，核对字段名与源 SHA；进程中没有 LSPR24 路径或句柄。
2. **源 Raw83 门**：完成 LSPR23 特征流式物化；每批及全量行数、内容 SHA、缺失/非法计数互相覆盖。
3. **序列绑定门**：旧 `I/M/E/T` 文件 SHA、原始行映射、实体一致、时间顺序、填充尾置、全覆盖且无重复全部通过。
4. **切分门**：实体/训练/验证数量为 `150680/208598/22444`，训练验证实体和序列行交集均为零；训练有效流位图哈希稳定。
5. **候选 A 门**：状态只读训练有效流；全视图有限；用实际批直接调用冻结 `StandardScaler` 路径复算，逐位或按库保证的精确口径一致。
6. **候选 B 门**：官方单次行主序噪声磁盘映射与内存路径逐位相同；76 列地标、references、实际批 transform 与目标版本 `QuantileTransformer` 一致；七特殊列与 A 视图逐位相同。
7. **源消费者门**：表格 ResNet 与 FT-Transformer 各读取一个实际 Protocol A 批，核对形状、行号、掩码、字段角色和状态哈希；不训练、不创建 SwanLab 身份。
8. **年度隔离门**：没有有效 `source-qualification-seal.json` 时，任何 LSPR24 模式、特征、视图、实体或标签请求必须失败。
9. **目标产品门**：封印后才读取实际 Parquet 模式并生成 LSPR24 Raw83；只应用胜出臂，目标状态更新数为零，标签仍不落盘。
10. **禁止制品门**：最终文件清单出现逐样本标签或预测即失败。

以下任一情况使数据产品无效并停止受影响实验：字段按位置错绑、源 SHA 不符、行数变化、Raw83 与 `I` 映射不一致、训练/验证实体重叠、验证或目标流进入状态拟合、状态/内容哈希不一致、候选 B 随机流未声明、完整源资格封印前打开任何 LSPR24 内容、目标落败臂被物化、标签/预测落盘、恢复拼接不同身份。

编译、入口或单批读取通过只能证明实现可运行；Raw83 全量门和状态门通过仍不证明候选 A/B 或任何骨干有效。模型效果必须由后续 LSPR23 真实资格实验裁决。
