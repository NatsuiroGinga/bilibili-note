- **审计日期**：2026-08-05
- **审计对象**：UGR'16 特征仓库固定提交 `760863d31413739a129b3be2d1d52cde217962e8`
- **本机原始根**：`thesis/experiments/llm_probe/data/raw/ugr16-feature-v3/`

- **适用路线**：[RWKV 恶意流量替代路线研究合同](2026-08-05-RWKV恶意流量替代路线研究合同.md)
- **总体裁决**：**当前监督式基线合同为 `NO-GO`；背景密度建模与长序列物化准备为 `GO`**

## 1. 直接结论

六个版本的训练文件均完整、可解析，时间键、特征维度、长历史窗口和版本同源关系已经闭合；官方 `Xtest/Ytest` 仍保持只做大小与 SHA-256 封存、未解析内容。

当前不能启动原合同中的监督二分类、多分类、攻击事件早停或基线困难版本选择。决定性原因是：六版 `Ytrain` 中除 `blacklist` 外，其余七个攻击计数字段全部为零；`blacklist` 又在 v1、v2、v2noIRC 的全部训练分钟和 v3 系的 96.04% 训练分钟非零。将八列任一非零定义为攻击会得到 96% 至 100% 的阳性率，目标不再表示“是否出现已标注攻击事件”。

训练区可以合法承担正常／背景密度建模、下一分钟生成预测和工程吞吐验证，但它本身不能评价攻击检测性能。若要继续比较方案 A、方案 B 与公平基线，必须先修改数据合同：在读取官方测试内容之前预注册一个不看标签的连续时间盲拆分，把一部分官方测试时间块转为开发攻击区，剩余时间块永久冻结为最终测试；或者更换具有独立开发攻击标签的数据集。

## 2. 审计边界与方法

### 2.1 明确读取的文件

只读取下列六对训练文件：

- `UGR16v1.Xtrain.csv` 与 `UGR16v1.Ytrain.csv`
- `UGR16v2.Xtrain.csv` 与 `UGR16v2.Ytrain.csv`
- `UGR16v2noIRC.Xtrain.csv` 与 `UGR16v2noIRC.Ytrain.csv`
- `UGR16v3.Xtrain.csv` 与 `UGR16v3.Ytrain.csv`
- `UGR16v4.Xtrain.csv` 与 `UGR16v4.Ytrain.csv`
- `UGR16v3v4.Xtrain.csv` 与 `UGR16v3v4.Ytrain.csv`

所有官方 `Xtest/Ytest` 均未交给 CSV 解析器，未读取表头、行列、时间、标签或样本值。其文件大小和 SHA-256 只沿用下载收据的字节级完整性结论。

### 2.2 统计定义

- 时间键：X/Y 的首列 `Row`，格式为 `YYYYMMDDHHMM`。
- 朴素二元标签：仅用于发现标签问题，定义为八个标签计数中任一大于零。
- 连续段：相邻 `Row` 恰好相差 1 分钟；任何更大间隔均重新编号。
- 长度为 (L) 的“历史到下一分钟”样本数：

\[
N_L=\sum_{s\in\mathcal{S}}\max(0, |s|-L),
\]

其中 \(\mathcal{S}\) 是全部连续段。窗口不得跨越缺失分钟。
- 事件间隔候选：若两个阳性分钟之间最多允许 (G\in\{0,5,30,60\}) 个阴性分钟，则时间差不超过 (G+1) 分钟时并入同一事件。
- 近标签字段：检查非恒定特征与朴素二元标签、八类计数总和的同刻皮尔逊相关系数，并检查逐行完全相等关系。相关性只能发现风险，不能证明因果泄漏。

## 4. 标签字段与攻击事件门禁

### 4.1 字段命名

- v1、v2、v2noIRC：`labeldos`、`labelscan11`、`labelscan44`、`labelnerisbotnet`、`labelblacklist`、`labelanomalyidpscan`、`labelanomalysshscan`、`labelanomalyspam`。
- v3、v4、v3v4：`dos`、`scan11`、`scan44`、`botnet`、`blacklist`、`udpscan`、`sshscan`、`spam`。

两个命名体系列序一致，v3 系只是把 `nerisbotnet`、`anomalyidpscan`、`anomalysshscan`、`anomalyspam` 简化为 `botnet`、`udpscan`、`sshscan`、`spam`。

### 4.2 全量训练标签分布

| 版本组 | `blacklist` 非零分钟 | 比例 | 其余七类非零分钟 | 朴素二元阴性分钟 |
| --- | ---: | ---: | ---: | ---: |
| v1 | 134,262 / 134,262 | 100.00% | 0 | 0 |
| v2、v2noIRC | 98,262 / 98,262 | 100.00% | 0 | 0 |
| v3、v4、v3v4 | 69,770 / 72,644 | 96.04% | 0 | 2,874 |

训练区不存在 DOS、扫描、僵尸网络、UDP 扫描、SSH 扫描或垃圾邮件阳性分钟。八类计数同时非零的分钟数为 0，最大同时非零类别数为 1；这不是“攻击类别天然互斥”的证据，而只是训练区除 `blacklist` 外没有攻击阳性的结果。官方测试仍封存，因此测试区是否多标签共现尚未审计。

`blacklist` 是黑名单命中流量的计数标签，不等价于一个稀疏、边界明确的独立攻击事件。v1/v2 中它贯穿全部连续段；v3 系即使采用 0、5、30、60 分钟事件间隔，得到的也只是黑名单活动段，不能冒充 DOS、扫描或僵尸网络事件。因此：

- 当前训练区独立确认攻击事件数为 0。
- 第四章“每个主要类别至少 8 个决策步”的事件门禁失败。
- 当前不能冻结二元、多分类或多标签监督目标。
- 不能用训练区 AUPRC 选择“基线最困难版本”。

## 5. 长历史序列预算

以下是严格不跨时间缺口的“历史到下一分钟”样本数：

| 版本 | 历史 16 | 历史 64 | 历史 256 |
| --- | ---: | ---: | ---: |
| v1 | 134,214 | 134,070 | 133,494 |
| v2、v2noIRC | 98,214 | 98,070 | 97,494 |
| v3、v4、v3v4 | 64,979 | 58,330 | 43,620 |

结论是：**长序列数量不是阻塞项**。即使 v3 系存在大量缺口，三档历史仍有足够样本用于背景预测和架构吞吐先导。真正阻塞项是缺少标签可见的开发攻击事件，而不是序列不足。

## 6. 缺失、常量与近标签字段

### 6.1 数据质量

- 六版训练特征缺失单元格数均为 0。
- 非有限值单元格数均为 0。
- 负数特征单元格数均为 0。
- v1、v2、v2noIRC 没有常量列。
- v3 常量零列为：`sportdaytime`、`sportftpdata`、`tcpflagsACK`、`tcpflagsPSH`、`tcpflagsRST`、`tcpflagsSYN`、`tcpflagsFIN`。
- v4 常量零列为：`tcpflagsACK`、`tcpflagsPSH`、`tcpflagsRST`、`tcpflagsSYN`、`tcpflagsFIN`。
- v3v4 有 12 个常量零列，即上述 v3 七列与 v4 五列的后缀版本。

所有常量列必须在开发训练区冻结后删除，删除清单进入特征模式哈希。不能根据测试区是否常量再次改列。

### 6.2 泄漏检查

- `Row` 是时间排序键，禁止进入模型数值特征；允许由开发训练时间构造周期性时间特征，但必须做去时间特征消融。
- X 表头不含八个标签字段。
- 没有非恒定特征与朴素二元标签、八类计数总和或任一非恒定单类计数逐行完全相等。
- v1 的最大同刻总计数相关系数绝对值约 0.519；v2 约 0.170；v3/v4/v3v4 约 0.199。v3 系与朴素二元标签的最大绝对相关系数约 0.511。没有字段达到预警阈值 0.95。

这些结果只排除显式逐行复制和极强线性同刻捷径，不能证明不存在端口、协议或时段捷径。后续仍需设置“无当前分钟、只用历史”“去端口组”“去周期时间特征”三类诊断对照。

## 7. 版本同源关系

| 关系 | 核验结论 | 对实验的影响 |
| --- | --- | --- |
| v1 与 v2 | v2 的 98,262 行 X/Y 是 v1 的逐行精确前缀；v1 另多 36,000 分钟 | 不能把二者当成独立数据集；原生时段比较会混入时间跨度差异 |

| v3v4 与 v3/v4 | v3v4 的前 134 维逐行等于 v3，后 134 维逐行等于 v4 | v3v4 是确定性拼接，不是独立采集 |

可物化：`v1`、`v2`、`v3`、`v4`、`v3v4`。

- v3/v4/v3v4 共享时间和标签，最适合做字段表示与计算成本比较。

### 9.2 监督攻击检测与早期决策

当前可物化集合为空。必须先获得标签可见且与最终测试隔离的开发攻击时间块。任何直接使用 `blacklist>0` 的二元化都需要改变研究问题，不能作为原合同的默认修复。

## 10. Rust 物化建议

本任务不修改生产代码。若数据合同修订获批，建议使用 Rust 实现确定性物化器。

### 10.1 输入模式

每条观测至少包含：

- `version`：固定枚举 `v1/v2/v3/v4/v3v4`。
- `timestamp_minute`：由 `Row` 严格解析的分钟时间。
- `features`：去除 `Row` 与冻结常量列后的非负计数向量，使用有界整数解析并在写出前转换为训练所需浮点类型。
- `attack_counts`：八个原始计数只作标签元数据，不在合同修订前派生 `binary_label`。
- `segment_id`：遇到非 1 分钟间隔立即递增。
- `source_sha256`、`schema_hash`：绑定固定原件和字段顺序。

### 10.2 输出模式

- `observations.parquet`：按 `version_rank, timestamp_minute` 稳定排序的分钟观测。
- `segments.parquet`：每个连续段的起止时间、行数、缺口来源和可用历史长度。
- `sequence_manifest.parquet`：`sample_id`、版本、段、历史起止、目标时间、历史长度和划分角色；不复制大张量。
- `dataset_manifest.json`：源文件哈希、模式哈希、行数、常量列、时间边界、拆分合同和语义哈希。

### 10.3 并行与确定性

- 允许按版本、文件和独立连续段并行。
- 段内解析、事件状态和窗口生成保持严格时间顺序。
- 合并时使用固定版本次序和稳定键排序，不依赖线程完成顺序或哈希映射遍历顺序。
- 语义复验比较模式、行数、有序样本清单和规范化字段值哈希，不机械要求两份 Parquet 容器字节完全相同。
- 探索性物化运行一次；最终冻结或标签语义变化时才做第二次独立语义复验。

预计生产实现、最小测试和收据生成需要 4 至 8 小时；约 300 MB 训练 CSV 的单次物化预计为数分钟级，但必须以本机实测为准。Rust 可以减少解析时间和运行期类型错误，不能修复标签协议缺陷。

当前下一步不是启动 GPU 或模型训练，而是修订数据合同。先用下列只读命令定位必须修改的条款：


修订合同必须在解析任何官方测试内容之前完成，并至少冻结：

1. 训练区只承担背景密度建模还是允许 `blacklist` 单独形成辅助任务。
2. 官方测试按不看标签的连续时间块盲拆成开发攻击区和最终测试区，或改用另一份带开发攻击标签的数据。
3. 困难版本选择改由哪个标签可见开发区计算，不能继续引用当前不可计算的训练区 AUPRC。

5. 先分时间块再构窗、跨缺口重置状态和最终测试永久不可见。

在上述五项完成、通过独立审查并生成新收据前，不存在诚实且可复现的“极限效果实验”启动命令。
