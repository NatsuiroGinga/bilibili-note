## 二、原文事实

### 2.1 骨干处理逐章不同

| 章 | 骨干 | 原文依据 |
| --- | --- | --- |
| 第三章 | ET-BERT 与 BUPT-CNN 两个，并列报告 | 2132 行，表 3-5 与表 3-6 分列 |
| 第四章 | 收窄到 ET-BERT 一个 | 3567 行起「骨干网络选型策略」 |
| 第五章 | 系统同时预置两个，附自动路由 | 4585 行起「模型感知与防呆路由」 |

### 2.2 第三章的两骨干就是跨基座验证

2132 行称选取两种在架构机理与参数规模上截然不同的模型作骨干，目的是验证防御框架的**通用性与有效性**。
1312 行再次以「验证算法通用性」表述同一安排。
3567 行是决定性交叉引用：第四章回头指认第三章为「验证防御通用性时同时选取 CNN 和 ET-BERT」。

**结论：朱做了跨基座验证，只是称之为通用性验证。** 此前认为「朱没有跨架构比较先例」的判断不成立，已更正。

### 2.3 两个骨干各自绑定一个待压测的机制

选型不是「随便挑两个不同的」，而是逐个说明它压测哪一项：

| 骨干 | 原文给的特性 | 原文给的目的 |
| --- | --- | --- |
| ET-BERT | 12 层 Transformer，1.1 亿参数，损失曲面高度非凸，直接对抗训练极易发散 | 重点验证课程学习机制在解决非凸优化收敛难题上的有效性 |
| BUPT-CNN | LeNet-5 改进，结构简单推理快，常用边缘侧部署 | 验证 Stackelberg 博弈策略不依赖特定大模型架构，适用于不同计算量级 |

**两个骨干分别是「最难收敛的」与「最轻量的」，各考一个机制。** 全程未评优劣，未挑赢家。

### 2.4 第四章收窄的依据不是性能排名

3567 行起明确给出两条依据：

1. **计算瓶颈的紧迫性**：BUPT-CNN 轻量、训练开销可控；ET-BERT 自注意力的二次复杂度叠加对抗训练的 K 倍反向传播，训练成本指数级增长，解决大模型效率瓶颈工程价值更高。
2. **技术适配性**：第四章 DF-ACR 的对抗扰动缓存针对变长序列设计了掩码对齐机制，契合 Transformer 处理填充位的方式，能在 ET-BERT 上发挥最大加速效能。

**即「哪个骨干最能暴露本章要解决的问题」加「本章机制在技术上适配哪个」，与第三章谁分高无关。**

### 2.5 第五章系统不是只上最好的模型

4585 行起：系统在骨干选项中预置两种异构架构；选计算密集的 ET-BERT 时加速内核开关保持激活，
切换到参数量极小的卷积模型时**自动锁定并禁用该加速选项**，以防止无效算力分配与资源浪费。

只有 5.5.2 性能测试为控制变量而「固定骨干网络为 ET-BERT」（4696 行）。

**支持多模型并知道何时关闭哪项加速，本身被写成系统章的工程亮点。**

### 2.6 参数量在朱论文中是一等公民

多处报告参数量与资源开销：938 行比较卷积与 Transformer 的参数量与推理速度并指向边缘部署；
3570、4696 行重复 ET-BERT 约 1.1 亿参数；表 4-7 报资源开销与轻量化收益；
图 4-5 报显存峰值；4.6.3 节专门分析资源消耗与显存优化。

**在其价值体系中，小模型打平或打赢大模型是加分项。**

### 2.7 全文零命中的两类内容

已记入[实验台账](2026-08-17-第三章实验台账.md)，此处只作索引：随机种子与全部统计术语
（置信区间、标准差、误差棒、显著性、方差分析、p 值、多次实验、重复实验、平均值）**全文零命中**；
小数只用于超参数。第三章正文已据此清除相关表述。

### 2.8 逐骨干实现细节自成小节：同一机制、不同挂载点与约束集

朱第三章 3.4 节下设两个逐骨干小节，正文位置在抽取文本第 1795 行与 1848 行。

| | 3.4.2 针对 ET-BERT | 3.4.3 针对 BUPT-CNN |
| --- | --- | --- |
| 为何需要单独一节 | 输入是离散 Token 索引序列，无法直接梯度反传 | 输入是二维灰度矩阵 |
| 机制挂载点 | **嵌入层**：`E_adv = E + δ`，δ 与综合嵌入同维 | **像素级**：`x_adv = Clip[0,1](x + δ)` |
| 约束集 | Frobenius 范数 `‖δ‖_F ≤ ε(t)` | L∞ 范数 `‖δ‖_∞ ≤ ε(t)` **加盒约束**，保证对抗样本可还原为合法二进制流 |
| 自带公式 | (3.16) 至 (3.18) | (3.19) 至 (3.21) |

**机制本身一字未改，改的是挂载点与约束集，各配自己的编号公式。** 另有一条模态适配原则：数据预处理按序列模态与视觉模态分别设计（序列截断填充至 `L=512`，视觉重塑为 `28×28` 灰度矩阵），同样只动接口不动机制。

**注意其约束的来源**：朱的两处约束都是**模态强制**的——离散 Token 不可导，像素必须落在 `[0,1]` 才能还原成真实数据包。这类约束不需要额外辩护，写出来即成立。

## 三、对本论文的直接启发与决定

### 3.1 第三章：五骨干按「压测什么」组织，不按架构族罗列

原先把五个骨干说成「五个架构族」是扫描式的。照 2.3 的做法改为设计式，每个骨干绑定一个待检验问题：

| 骨干 | 相对本方法两机制的位置 | 它在考什么 |
| --- | --- | --- |
| 多层感知机 | 完全没有时序结构 | 因果前缀聚合能否补上骨干缺失的上下文 |
| 一维卷积 | 局部感受野 | 上下文范围有限时机制还有多少空间 |
| 门控循环单元、RWKV-7 时间混合 | 骨干自带递归状态 | 骨干已在建模序列时，跨流聚合是否冗余 |
| 全注意力 Transformer | 全局注意力，可见全部位置 | 骨干已能看到所有流时，机制是否还有增量 |

**问题因此从「哪个骨干最好」变为「机制在骨干能力谱系上什么位置仍然成立」。** 后者可写进论文，前者不可。

### 3.2 第三章主表基座维持多层感知机，五骨干全部报告

依据是先注册，不是最优。**不评冠军**，与 2.3 一致。
若某骨干的组合格结果高于多层感知机，如实写出，主实验仍沿用先注册基座。

### 3.3 第四章可以收窄到单骨干，但依据照 2.4 写

**此前「用目标年结果选骨干等于测试集选优」的反对，只适用于第三章的基线对比，不延伸到第四章。**
理由：第四章的论断是「第四章机制相对第三章基线的增量」，属同骨干内的差值；
换骨干改变绝对水平，不改变该差值，故不污染第四章自身贡献。

第四章主题是困难样本、长尾与未知攻击的课程优化训练，因此选型依据应为：

1. **哪个骨干最能暴露长尾问题**。已有实测参照：多层感知机上组合格相对无机制格的实体平均精确率分桶增量为
   `+0.123948 / +0.239138 / +0.137851 / -0.322915 / -0.302212`（桶为 1-2、3-10、11-100、101-1000、1001+），
   短中实体有益、长实体显著有害。五骨干结果出来后比较该分桶模式在哪个骨干上最尖锐。
2. **第四章机制在技术上适配哪个骨干**。待第四章方案冻结后才能判定。

**依据写这两条，不写「它在第三章分最高」**，即使两者恰好指向同一个骨干。

### 3.4 第五章系统支持多骨干加路由，不是只上最好的

照 2.5，系统章应支持骨干切换，并在切换时按模型特性启用或禁用相应的加速与优化选项。
**这个路由逻辑本身是系统章的可写内容**，比只集成单一最优模型的信息量更大。
性能测试可固定单一骨干作控制变量，但那是测试设计，不是产品决策。

### 3.5 参数量进主表，并作为正面论断

照 2.6，主对比表加参数量列。本方法 90,242 参数与已发表基线的差距（全注意力 Transformer 为 10,729,345，
即 119 倍）应作为正面论断而非需要辩解的事项，与所参照论文的价值取向一致。

### 3.6 第三章 3.4 增设逐骨干实现细节小节，照 2.8 的体例

**两个机制里只有一个需要逐骨干处理：**

| 机制 | 需否逐骨干小节 | 原因 |
| --- | --- | --- |
| 实体级可学幂平均池化 | **不需要** | 作用在输出分数上，与骨干无关。任何骨干产出的逐流分数都可直接输入 |
| 因果前缀跨流聚合 | **需要** | 作用在表示层，挂载点随骨干而变：感知机挂隐藏层，卷积挂池化后特征，注意力骨干挂哪一层待定 |

**这一分工本身就是可写内容**：一个机制天然普适、一个需要适配，正好对应本章「表示层与决策层职责划分」的论证结构（3.2.3 节）。

每个逐骨干小节写三项：挂载点、约束及其来源、参数量核算，各配编号公式。朱第三章有 33 个编号公式，本章现有 32 个，该节正好补齐工作量。

**一处必须诚实区分的差别**：朱的逐骨干约束是模态强制的，本章卷积骨干的融合约束是**参数预算选择导致的**，理由更弱，因此必须写明是何种预算约束下的选择，不得含糊成「模态所需」。

### 3.7 一处方法论更正：该固定的是总参数量，不是骨干参数量（2026-08-18 用户指出）

**主代理此前把「等参数骨干」作为卷积 2×2 的约束，这条约束是从跨基座实验照搬的，属于误用。**

跨基座实验比较的是**不同骨干**，固定骨干规模才能隔离骨干效应，等参数骨干是对的。
卷积 2×2 比较的是**同一预算的两种花法**，该固定的是**总量**。

误用的后果：因果前缀聚合的 `cat` 融合会使首个全连接输入宽度翻倍，在卷积骨干上增加 86,528 个参数；为维持骨干参数不变，实现被迫改为绑定权重形式 `h + c`，即完整融合在 `W1 = W2` 时的特例，**表达能力严格更弱**。独立审查据此判为 invalidating：一旦无增益，结论在「机制对卷积骨干无效」与「融合被约束后失效」之间不可区分。

**改按固定总量后该问题消失。** 实测核算（可复现）：

| 配置 | 参数量 | 相对 90,242 |
| --- | ---: | ---: |
| 基线卷积 `c1=26 c2=52 fc=104`，无 cat | 90,949 | +0.78% |
| 同配置改真 `cat` | 177,477 | +96.7% |
| **缩小至 `c1=19 c2=37 fc=74` + 真 `cat`** | **89,987** | **−0.28%** |

即无机制格沿用基线卷积原配置（回归比对门禁完整保留），加机制格改用缩小骨干加完整融合，两者总预算相同。**问题因此从「骨干固定时加机制有没有用」变为「给定同一参数预算，全部投入更宽的卷积，还是投入更窄的卷积加两个机制」**——后者才是部署时真正要回答的问题，且机制实现逐字忠实。

**该设计引入一个新的替代解释，必须设对照**：加机制格的首个全连接输入宽度翻倍，增益可能来自更宽的全连接而非跨流上下文。对照做法是同样缩小的骨干、同样翻倍的宽度，但输入 `cat[h, h]` 而非 `cat[h, c]`——参数量与宽度完全相同，那一半不携带任何跨流信息。

**一处代价**：无机制格与加机制格使用不同骨干规模，2×2 的交互项跨两个规模不好解释。交互项论断本就建立在感知机骨干上，核心表每行只需无机制与加机制两个数，卷积行不算交互项不影响该论断。

### 3.8 关于 BERT 式骨干：本课题数据条件不支持

朱的 ET-BERT 输入是**载荷字节的十六进制 Token 序列**（3.4.2 节：`w=[w1,…,wL]`，`wi` 为词表索引，`L=512`）。

本课题数据是**流级统计特征**，83 个字段全为端口、协议、计数、时序与粗粒度拓扑指示；**LSPR 不提供载荷字节**，且路线总控第 1 节明写不宣称逐包或逐连接检测，字段预算亦不含载荷类字段。**没有载荷就无法 Token 化，ET-BERT 那套无从谈起。**

可做的是「注意力编码器」而非「ET-BERT」，且有两处必须说明的差别：其一，跨年度检测要求因果掩码，不能用双向注意力，否则造成时序泄漏；其二，不存在在流级特征上预训练好的权重，无法复现「大规模预训练模型」这一角色。**该限制应在正文写明，不回避。**
