# LSPR24 Rust G0-A 任务 1 实施报告

- **日期**：2026-08-06
- **路线**：`RESEARCH_ROUTE=RWKV`
- **任务范围**：独立 Rust 包骨架与 Parquet 时间列流式扫描
- **数据边界**：只使用人工构造 Parquet 夹具；未读取 LSPR24 标签、攻击叙事、最终测试内容或全量数据

## 1. 实施结果

已建立 `tools/lspr24_g0/` 独立 Rust 2024 包，并实现以下最小能力：

- 按字段名验证并仅投影 `mTimestampStart`、`mTimestampLast`。
- 两列必须唯一存在、声明为可空且类型为 `Int64`，否则在扫描前失败。
- 按 Parquet 原始行组和批次顺序流式产出记录，不收集全表。
- 在任何后续过滤、隔离或去重之前分配零基全局 `source_row_index`。
- 空值保持为 `None`，不跳行、不改变行号。
- 扫描结束时核对实际行数与 Parquet 元数据行数，计数与转换使用显式溢出检查。

## 2. 测试驱动证据

### 红灯

执行命令：

```bash
cargo test --manifest-path tools/lspr24_g0/Cargo.toml --locked --test parquet_time_scan
```

结果：退出码 `101`。编译器报告 `E0432`，明确指出测试要求的 `ScanConfig`、`TimeRowReader`、`TimeRow`、`ScanError` 和模式错误接口尚未实现。失败原因是目标功能缺失，不是锁文件、依赖或夹具错误。

### 绿灯

实现最小生产代码后执行同一命令：

```bash
cargo test --manifest-path tools/lspr24_g0/Cargo.toml --locked --test parquet_time_scan
```

结果：退出码 `0`，`3 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out`。

通过项：

- 人工夹具包含额外非时间列、乱序字段、空值和 3 个行组；批大小 `1`、`3`、`65_536` 得到完全相同的时间值、顺序和全局行号。
- 缺少 `mTimestampLast` 时在扫描前返回结构化模式错误。
- `mTimestampStart` 为 `Int32` 时在扫描前返回结构化类型错误。
