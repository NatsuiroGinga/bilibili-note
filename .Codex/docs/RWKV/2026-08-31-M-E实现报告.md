## 三、实现代理对计划的修正（均已核验并采纳）

1. **`piecewise_linear_encode` 的截断结构**。计划的嵌套 `where` 在 `T = 1` 时会让末箱被错误上截。
   改为按 `index > 0` 下截、`index < T-1` 上截。`T ≥ 2` 与计划逐位等价，构造真值最大绝对差 `0.0`。
2. **`fit_quantile_bin_edges` 的 float32 安全性**（有复现）。计划在 float64 上核验严格递增后才转
   float32，转换后仍可能塌缩。复现：`np.full((256,1), 1e5, dtype=np.float32)` 下计划版最小箱宽为
   `0.0`、编码出 `nan`。修法是先转 float32 再去重核验。真实 `X23` 上两版最小箱宽同为
   `8.568167686462402e-07`，差异仅末位 1 ULP，即该修正不改变本数据集的分箱语义。
3. **参数量闭式增加 `gate_mode` 关键字**。计划对三种门模式统一断言 `own == 124673`，
   而 E1／E2 的实际专属参数是 `124417`，**该断言在消融臂上必然失败**。计划已同步修正。
4. **`RandomState` 取代 `default_rng`**（中断前未提交，本次核验后提交）。箱边界拟合的抽样改用
   legacy `RandomState`：NEP 19 冻结了它的流，而 `Generator` 的分布方法允许跨 numpy 版本改变取值序列。
   箱边界是随运行冻结的制品，本机（numpy `2.4.6`）与服务器必须抽到同一批行。与 `base.source_split`
   用同一种生成器。同时把取数日志改为限频心跳并补预计剩余时间。

计划中被点名检查但**证实不成立**的一项：`torch.cat` 会物化新张量，`expand` 产生的 stride-0 视图
不会传播到输出，故类别补零用 `expand` 无隐患。`register_buffer("bin_edges", ...)` 也不会被优化器
误当参数——buffer 不进 `named_parameters()`，实测排除 `base.` 前缀后专属参数恰为 `124673`。

## 四、一个被实测否定的上报缺陷

实现代理上报「分位数分箱在真实数据上大面积退化为等距，`70/81` 列命中补齐分支」并请求裁决。
**该问题基于错误口径，已被实测否定**：统计取自 `X23` **原始列**，而骨干喂进分词器的是变换后的张量。
`_fit_quantile_column` 在拟合 `QuantileTransformer(output_distribution="normal")` **前先叠加
`noise_std = 1e-3 / max(列标准差, 1e-3)` 的高斯噪声打散重复值**。按同一口径复测：

| 口径 | `9` 个分位数互异的字段 | 需要退化处理 |
| --- | ---: | ---: |
| `X23` 原始列 | `11 / 81` | `70 / 81` |
| 变换后 | `81 / 81` | `0 / 81` |

退化分支在真实训练区不会触发，等距化与 `39%` 死箱都不会发生。`T = 8` 由此获得可行性支持
（可行不等于最优，敏感性仍待源年实验）。详见形式化第八节。

## 五、遗留风险

- `_gather_transformed_numeric` 对训练区全量取数会产生排序副本，`bin_fit_sample_cap` 用于限制规模。
  该上限的实际取值与内存占用**未在服务器实测**，首次正式运行需观察峰值。
- 箱边界是随运行冻结的制品。本机与服务器的 numpy 版本不同（`2.4.6` 对服务器待核），
  修正 4 已把抽样改为 `RandomState` 以保证同批行，但**跨版本一致性未实测**，首次正式运行须比对
  `bin_edges_sha256`。
- 本报告的全部验证在 CPU 与本机 MPS 环境完成。**服务器 CUDA 路径未验证**，尤其是
  BF16 自动混合精度下 `einsum` 与门的数值行为。
