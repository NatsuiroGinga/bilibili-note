只读核验全容量 MLP 统一 BF16 单种子资格实验，产出可追溯的严格分析与研究裁决，不修改生产代码、运行制品、冻结门槛或 LSPR24 数据。

- 禁止：修改生产代码、运行制品、冻结配置与门槛；访问服务器；使用 LSPR24 调参；运行 `black`；提交本目录外文件。

## 关键问题

1. 运行是否满足状态、清单、哈希、选择隔离与最终测试隔离合同？
2. 六个分支的逐流 AP、实体 AP、最大 AP、六档 DR、完整曲线面积和首次告警暴露分布分别如何？
3. 名义预算与实际可达 FPR 是否一致，尤其 O11 在真实 `FPR <= 0.04` 下的最优可达 DR 与并列概率悬崖是什么？
4. 全容量 MLP 相对同池传统模型、已发表神经基线及 MLP 历史基线是支配、被支配还是非支配？
5. B00/B10/O01/O11 与 N01/N11 支持哪些机制消融和交互结论？

## 裁决原则

- 不使用加权总分，以全精度标量、共同可达完整曲线、首次告警轴分别判定支配关系。
- 源年只支撑资格选择；LSPR24 只作冻结后的描述性迁移证据，不是独立测试。
- 单种子结果不升级为稳定结论。
- 资源数据受 GRANDE 并发争用影响，只记录运行事实，不作公平效率结论。

## 错误记录

- 本机 `results-analysis` 技能引用的 `analysis-plan.md`、`evidence-standards.md`、`claim-candidate-guidance.md`、`dominance-analysis.md` 不存在；改读技能现有的统计、分析深度与常见陷阱参考，不以缺失引用替代仓库合同。
- 首次运行本地混合检索时，`uv` 默认缓存目录因沙箱权限失败；后续把 `UV_CACHE_DIR` 与 `PYTHONPYCACHEPREFIX` 指向 `/tmp` 重试。
- 向量索引增量构建因离线环境无法访问模型仓库失败；按仓库规则改用 `build --lexical-only`。词法构建成功后又因其他代理并发修改文档立即变陈旧，因此不使用检索结果作结论，直接读取精确合同与原始制品。
- 首次 NPZ 重算漏加源年键前缀 `source__`，触发 `KeyError`；读取实际键表后修正，不产生文件写入。
- 首次清单哈希循环使用 zsh 特殊变量 `path`，临时覆盖命令搜索路径并产生无效“mismatch”输出；更名为 `file_path` 后从零重算，最终为 7 个本地成员全匹配、0 个不匹配。
- 一次 `jq` 查询把含点号的键写成属性语法，另一次 shell 引号提前结束；均未写文件，改用方括号键访问后通过。
- 用户级通用规范要求 JSON 运行 `prettier`，但仓库 `P0-NO-PRETTIER` 钩子阻止执行；按更近的仓库门禁不绕过，改用 `jq empty`、结构化断言和差异检查。
- 首轮最终验收的报告令牌断言预期“103 个成员未回收”，实际报告为同义的“103 个未回收”；证据值无误，修正验收令牌后从头复验。
