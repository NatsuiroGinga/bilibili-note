# RWKV-7 字段感知输入与协议 A 四格实施报告

## 一、结论

N-08 独立生产入口已实现，当前状态为**设计可执行、实验待证**。本轮没有访问服务器、没有加载 LSPR23/LSPR24 缓存、没有运行训练或人工冒烟，因此没有性能结论，也不得据此宣称 RWKV-7 有效或无效。

实现严格采用 LSPR23 固定实体不相交训练/验证的单次协议 A，不包含三折、OOF 或嵌套选择。约 90K/104K 模型只承担输入消融与效率锚角色；输入适配器冻结后另行执行 K0/K1/K2 容量筛选，只有资源合格且源年验证逐流 AP 胜出的容量与输入组合进入四格。

## 三、模型与输入实现

### 3.1 固定源码身份

- 官方仓库：`BlinkDL/RWKV-LM`。
- 固定提交：`952102498e9ed367ea0a59ee64106916d474d30f`。
- 许可证：Apache-2.0。
- 参考实现：RWKV-7 纯 PyTorch 递归、官方参数初始化、value residual 与优化器分组语义。
- 运行路径不使用官方 CUDA 内核，不能把其效率写成官方 RWKV-7 效率。

### 3.2 逐流表示

模型输入始终为 `values=[B,T,83]` 与 `valid=[B,T]`。每个时间步是一条流，RWKV 状态只沿 `T` 递归；代码没有载荷 token、字节词表、图像重塑或字段 token 时间化。

R0/R1/R2 如下：

| 键 | 机制 | K0 适配器参数 | K0 总参数 |
|---|---|---:|---:|
| R0 | `Linear(83,112)` | 9,408 | 91,730 |
| R1 | 共享标量编码、字段嵌入、12 语义组嵌入与组内均值后合成 | 21,952 | 104,274 |
| R2 | 不含字段语义的两层普通投影 | 21,952 | 104,274 |

R1/R2 精确同参。配置保存 Dijk 83 字段原顺序、12 组无重无漏索引和规范摘要 `e622f059d2295c8740daeb7d29fe92761c68c17a78b3d57ad65821d9137f105d`；运行时逐项核验。

共同 RWKV、融合层、输出层和 `p_log` 在输入适配器之前构造。每个候选重置 Python、NumPy、PyTorch CPU/CUDA 随机状态到种子 42，使同容量候选的共同模块初值一致。

### 3.3 容量筛选

| 键 | 结构 | R0 参数 | R1 参数 | R2 参数 | 角色 |
|---|---|---:|---:|---:|---|
| K0 | 单时间混合块，`C=112,H=16,r=8` | 91,730 | 104,274 | 104,274 | 效率与旧实现回归锚，不是容量上限 |
| K1 | 三层 PreLN 残差与 value residual，`C=576,H=64,r=32` | 5,126,978 | 5,185,458 | 5,458,754 | RWKV-TS 三层结构与 5,355,649 参数 GRU 资源邻域 |
| K2 | 三层 PreLN 残差与 value residual，`C=768,H=64,r=32` | 8,900,354 | 8,977,842 | 9,490,178 | RWKV-TS 三层 768 维来源，低于 10,729,345 参数 Transformer 资源锚 |

配置核验会实际实例化九个“容量×适配器”组合，机械比较参数实数与冻结台账。容量按 K0、K1、K2 顺序，只用 LSPR23 C00 验证逐流 AP 选择；相等时依次取较少参数和冻结顺序。

资源门会把当前单元及同容量剩余协议格作为等价单元一并投影。某放大容量被资源门阻止时记录 `capacity_upper_bound_not_verified_due_to_resource_cap=true`，不会生成“RWKV-7 失败”结论。

## 四、RWKV-7 与机制接口

### 4.1 时间混合

- K0 保留既有单层 `layer_id=0` 初始化，用于回归锚。
- K1/K2 使用三层官方比例初始化，第 2、3 层实现 value residual。
- 每层矩阵状态为 `[B,H,N,N]`，`r/w/k/v/a/b` 和递归状态强制 FP32。
- 多层容量使用 `x + TimeMix(LayerNorm(x))`，不增加 ChannelMix/FFN。
- 补零位置在输入、层间和输出处重新乘掩码，状态不跨序列或批次。

### 4.2 官方优化器分组

运行时保存全部参数名和组统计，并断言无重无漏：

1. 每层 `w0` 使用 `0.004` 学习率、零权重衰减。
2. 名称含 `.weight` 且压缩后至少二维的矩阵使用 `0.002` 学习率和 `0.01` 权重衰减。
3. 其余参数使用 `0.002` 学习率、零权重衰减。

### 4.3 CPA、ELP 与梯度门

- CPA 对 RWKV 逐流隐藏表示做因果前缀均值；关闭时使用同形零上下文。
- ELP 使用单一共享 `p_log`；关闭时实体层使用最大池化。
- 每个训练单元保存第一步梯度诊断。官方零初始化可能使上游梯度在第一步为零，因此实现继续检查到第 3 步，但不放宽有限性与非零要求。
- C11 额外只对 ELP 实体辅助损失反向，要求输入适配器、分类头、`p_log` 以及 RWKV 的 `receptance/key/value/output/w0/a0` 全部出现有限非零梯度；该诊断后清梯度，再执行正式总损失反向，不改变训练更新。

## 五、协议 A 与隔离

执行顺序固定为：

1. 只加载 LSPR23，生成同一固定实体不相交训练/验证成员。
2. 顺序训练 R0/R1/R2 的 K0 C00，仅按验证逐流 AP 封印输入适配器。
3. 胜出输入的 K0 C00 直接复用；顺序训练资源允许的 K1/K2 C00，仅按验证逐流 AP 封印容量。
4. 胜出输入与容量的 C00 直接引用其选中轮权重；再训练 C01/C10/C11。
5. 写入 `selection_frozen.json` 后，才首次清点并加载 LSPR24。
6. LSPR24 每格执行一次描述性评价；恢复只复用身份与哈希完全匹配的完成收据。

输入、容量和每格均跑满 20 轮，每轮 1000 步，不早停；选中验证逐流 AP 最大的最早轮。目标指标不进入选择、调参或资源裁决。

## 六、时间、空间与恢复

### 6.1 空间

- LSPR23 和 LSPR24 数值数组使用只读内存映射。
- `s24/d24` 只在目标封印后作为 CPU 只读字符串数组加载。
- CPU 按序列索引取当前批，再只搬运 `[B,T,83]`、标签和掩码到 GPU。
- 不把 16.35M/20.23M 全量特征矩阵搬入 GPU。
- 目标实体映射先按序列首个有效流向量化生成，再按块回填逐流实体编码；不构造 20M 个 Python 字符串键。
- 逐流和实体分数只在 CPU 内存暂存，不落盘；完整告警预算曲线落盘。

### 6.2 恢复

- 每 20 个优化步原子覆盖最新完整 inflight，满足长任务恢复间隔。
- inflight 保存模型、优化器、调度器占位、轮/步、当前轮损失、最佳状态、Python/NumPy/PyTorch CPU/CUDA 随机状态、采样生成器、累计耗时和资源峰值。
- 每轮另存纯模型权重 `epoch-01.pt` 至 `epoch-20.pt`，不覆盖、不删除。
- 完成单元保留 `completed=true` 的最后 inflight；选中检查点直接引用最佳轮文件与 SHA-256，不复制权重。
- 运行身份、配置、代码、源数据、任务、适配器、容量、格或权重摘要任一不符时拒绝恢复。

## 七、指标与制品

每个源年候选在选中轮补算并保存：逐流 AP/AUC、实体 AP、最大池化实体 AP、六档 DR@FPR、完整可达告警预算曲线、参数、墙钟、有效流吞吐、CUDA 分配/保留峰值、RSS、梯度收据、逐轮权重数量与字节数。

LSPR24 每格保存同一组性能指标与完整预算曲线；聚合结果另外报告 CPA、ELP、组合效应和二阶交互。逐样本分数不持久化、不上传 SwanLab。

- 启动前空闲显存至少 20 GiB、控制组可用主存至少 40 GiB、磁盘可用至少 25 GiB且使用率低于 80%。
- 串行运行，`actual_parallelism=1`。
- R0 第一轮和首个放大容量 K1 第一轮后按真实训练、验证与写盘墙钟重新投影。
- Python 内部累计门和启动器 `timeout` 硬门均为 4.5 GPU 小时。
- 若资源门阻止放大容量，结论只能是“本预算未验证模型族容量上限”。

## 十、阻塞与未证事项

1. 没有服务器运行制品，所有性能、显存、吞吐、4.5 小时内可完成性与科学资格均为实验待证。
2. 纯 PyTorch 128 步递归可能使 K1/K2 在资源门前停止；这种停止只否决本预算内的执行资格，不否决 RWKV-7 模型族。
3. LSPR24 已被历史工作访问，因此 `target_previously_accessed=true`、`independent_test=false`；目标结果只能作描述性直接比较。
4. 结果写入论文或路线总控前仍须运行 `results-analysis`，不能以本实施报告代替真实数据分析。
