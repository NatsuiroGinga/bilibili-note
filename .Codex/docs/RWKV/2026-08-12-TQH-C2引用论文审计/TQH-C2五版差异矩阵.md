# TQH-C2 五版差异矩阵

- **代理名**：`/root/tqhc2_citation_literature_sol_max`
- **模型**：`gpt-5.6-sol`
- **推理强度**：`max`
- **核验日期**：2026-08-12
- **对象**：Zenodo 概念 DOI `10.5281/zenodo.21330094` 下全部 5 个已公开版本

## 1. 裁决摘要

1. 五个版本的题名与作者完全一致；题名不能用于判版。规范题名为 `TQH-C2: An Encrypted Command-and-Control Traffic Dataset Across Protocols and Encryption Layers`，作者为 Deokjo Jeon 与 DongGue Park。
2. v1.0.0 到 v1.0.2 共用旧 B 捕获；其 C2 流因断裂的杀伤链而单向。v1.1.0 重采 12 个 B 单元，将 B 改为 324/324 条双向 C2 流。v1.2.0 在 v1.1.0 的 A/B/C 上新增 D，A/B/C 包与 v1.1.0 字节相同。
3. v1.0.0 与 v1.0.1 的逐流标签、PCAP、特征和脚本不变；v1.0.1 只修正 21 个单元的计数文件。如果论文只使用逐流数据而未保留计数文件或下载日期，v1.0.0 与 v1.0.1 可能无法从实验制品反推区分。
4. v1.0.2 清除陈旧容器流，将总流数从 333,961 降为 193,084，并将 `unknown` 从 29,482 降为 0；此处的 `unknown` 是传输/基础设施噪声，不是未知攻击。
5. v1.2.0 实际为 4 个测试床、48 个捕获单元，而 README 的部分概览仍写 3 个测试床、36 个单元。数量与模式必须以实际包内制品为准。
6. v1.0.1、v1.0.2、v1.1.0 和 v1.2.0 README 的引用块均沿用 v1.0.0 DOI `10.5281/zenodo.21330095`；部分还沿用 v1.0.0 版本文本。因此“被引 DOI”和“实际使用版本”必须分列，引用 `21330095` 不能自动归为 v1.0.0。

## 5. 模式、模态与可观测单位

### 5.1 实际 Parquet 模式

v1.1.0 A/B/C 和 v1.2.0 A/B/C/D 的测试床聚合 Parquet 都是相同 27 列：

`ts, uid, orig_h, resp_h, duration, orig_bytes, resp_bytes, orig_pkts, resp_pkts, orig_p, resp_p, proto, conn_state, history, orig_ip_bytes, resp_ip_bytes, missed_bytes, ja4, ja4s, ja4h, profile, encryption_profile, interval_s, jitter_pct, capture_id, label_raw, y`

| 成员 | 聚合 Parquet 行数 | 列数 |
| --- | ---: | ---: |
| A | 96,149 | 27 |
| B | 21,796 | 27 |
| C | 23,292 | 27 |
| D | 11,528 | 27 |

其中 27 列包括直接目标 `y` 和标签副本 `label_raw`；“26 列”只能表示排除 `y` 后的存储列，不是可安全用于模型的特征数。

### 5.2 原始逐流 JSONL

- A/C 样本实际为 40 个键，除连接、标签与组信息外，含 TLS/HTTP 可选字段。
- B/D 样本实际为 31 个键，没有 HTTP 方法、主机、URI、状态码、用户代理和体长等 9 个字段。
- 公共可观测字段包含 `ts`、每条 Zeek 连接的 `uid`、端点/端口、协议、持续时间、字节、包数、连接状态/历史、标签、`capture_id`、成员/框架/加密配置、间隔和抖动。
- manifest 包含 `start_utc`、`end_utc`、框架、传输配置、间隔/抖动、捕获拓扑、校验结果和计划目标。

### 5.3 包内模态不对称

- A/B/C 标签包含 36 份 `labeled.jsonl`、36 份 manifest、36 份校正计数、36 份 gate 和按成员出现的 Zeek 日志，共 343 个中央目录成员。
- D 标签包只含 12 份 `labeled.jsonl` 与 12 份 manifest，没有 `conn.log`、计数文件或 gate。D 的原始 PCAP 可用于重放 Zeek，但这是新的重物化过程，不能假定既有小包已包含日志。
- 数据包明确不包含杀伤链驱动日志和采集工具内部日志。

### 5.4 现有身份和时序边界

- 样本原子是 Zeek 连接流，`uid` 不是跨连接的应用会话标识。
- 没有持久的跨捕获主机身份字段；manifest 拓扑和 IP 只能作为组织/审计侧信息，IP 又是已知标签捷径，不得默认输入检测器。
- 没有逐流攻击阶段、任务事件、杀伤链步骤或线索图标签。`malicious_recon` 只是粗粒度流标签，且只在 C 出现。
- 48 个单元完整覆盖 `4 成员 × 4 间隔 × 3 抖动`，但每个组合只有一次捕获。安全的默认划分原子是完整 `capture_id`，不是逐流随机分割。

## 7. 对任务设计的硬边界

- 封闭集 C2/非 C2 分类可直接构造，但地址、端口、采集身份、连接状态等是已知捷径；主证据应使用完整捕获留出和跨成员评估。
- 可以构造“留一框架/成员为未见域”的开放集代理，但不能称为数据集原生未知攻击；`unknown` 为 0 且其语义原本是噪声。
- 版本变化主要是计数修正、污染清理、B 重采和 D 新增；它们可用于软件/数据版本偏移审计，但不是自然时间概念漂移的无混杂证据。
- PCAP 支持重建报文或流前缀，但现有逐流标签是完整连接级，且缺少攻击任务开始时间；“流前缀早识别”可弱构造，“杀伤链早期预警”不能直接构造。
- 没有阶段事件、稳定跨捕获主机身份或因果链标签；不得把 `capture_id`、IP 或 `malicious_recon` 臆造成完整攻击链识别/溯源目标。
- 数据为受控实验室合成流量，不含人类主体私密数据。可直接审计制品中的地址、SNI/HTTP 元数据与发布最小化，但不能用其支持对现实用户的成员推断或个人隐私结论。

## 8. 证据来源与局限

- 官方版本链、题名、作者、DOI、发布日期、文件清单和记录总字节：Zenodo 五版记录元数据。
- 版本变化、旧 B 故障、过滤前后计数与引用块：各版官方 README。
- v1.2.0 标签、包结构、27 列模式与成员行数：本地 `raw/datasets/TQH-C2-v1.2.0/` 官方小包逐行/中央目录实测，并与既有 E0 数据审计交叉核对。
- 本制品没有为了填表而下载五版全部大型 PCAP；早期版的逐流数量依据官方 changelog，v1.1.0/v1.2.0 小包数量由本地制品实测。
- README 与制品冲突时，文件完整性、模式和训练样本量以已校验制品为准；历史变更意图以当版 README changelog 为准并显式披露冲突。
