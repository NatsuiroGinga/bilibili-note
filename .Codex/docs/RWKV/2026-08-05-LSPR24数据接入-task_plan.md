# LSPR24 数据接入任务计划

## 目标

基于官方论文与 Zenodo 记录，确定 LSPR24 是否能以不泄漏最终测试的方式支持 RWKV 方案 A/B 的连续序列实验，并形成最小、可恢复、可复核的本机下载闭环。

## 阶段

- [x] 阶段 1：恢复总控文档与 RWKV 局部规则。
- [x] 阶段 2：读取 RWKV 研究合同、单数据集报告和方案 A/B 第三章文档。
- [x] 阶段 3：核验官方论文与 Zenodo 文件清单、大小、校验值、许可和字段语义。
- [x] 阶段 4：定义开发可见区、封存区、统计单位和最小下载集合。
- [x] 阶段 5：按磁盘与文件规模启动可恢复下载，并完成核心流表与攻击叙事的官方大小、MD5 和本地 SHA-256 验收。
- [x] 阶段 6：完成数据接入报告与最小验证。

## 关键问题

1. 哪些官方文件足以完成字段、标签、时间连续性和序列门禁审计？
2. 如何在下载前冻结开发区与最终封存区，避免读取最终测试标签？
3. LSPR24 的统计单位能否支持方案 A/B 的有序窗口和攻击事件级评价？
4. 数据许可、校验值和攻击叙事映射能否满足论文复现要求？

## 决策

- 不读取拟作为最终测试的标签内容；先用官方元数据冻结文件级或时间级封存边界。
- 优先本机可恢复下载；只有文件清单和磁盘预算明确后才启动。
- 不修改模型代码，不运行模型训练。
- 以全局 `mTimestampLast` 的时间秩冻结最后 20% 为最终封存区；切点只由时间列决定，不读取 `Label`、叙事或日志内容。
- 首轮只下载 `lspr24_v2.parquet`；攻击叙事可随后原样下载但按时间过滤前不得解析，`eve.log` 与 5GB 主机日志不阻塞流量基线。

## 错误记录

- 本机 `screen` 后台会话启动后立即成为 `Dead`，且未生成下载日志或退出码；未把该失败计作数据下载失败，已使用同一 `.aria2` 控制文件恢复到统一执行会话继续断点续传。
- 官方源在下载约 81% 时出现一次连接超时；下载器沿用同一控制文件续传，最终大小与官方 MD5 一致，未遗留 `.aria2` 临时文件。
