## 1. 设计

同 83 字段、同数据（LSPR23 `16,353,511` → LSPR24 `20,227,356` 零样本）、同 `4000` 优化步、同 seed 42，
**只逐级加入一个因子**：

| 档 | 内容 | 隔离什么 |
| --- | --- | --- |
| A | 逐流 MLP（3 层 hidden 192） | 基准 |
| B | A + 2-IP 无向对序列 + **因果前缀均值上下文** | 序列表示的效应 |
| C | B 的上下文换成 **RWKV-7 式状态递归** | RWKV 机制的独立增益 |

B 档上下文实现（无注意力、无循环、无门控）：

```python
cum = torch.cumsum(h, dim=1)
cnt = torch.cumsum(m, dim=1).clamp(min=1.0).unsqueeze(-1)
ctx = cum / cnt                      # 因果前缀均值
out = self.o(self.g(torch.cat([h, ctx], dim=-1)))
```

C 档状态递归（RWKV-7 核心：衰减 + delta 移除键 + 外积写入 + 查询读出，多头 `heads=4`）：

```python
S = S * w_t                                          # diag(w) 衰减
S = S - einsum(S, (a_t ⊙ k̂_t) ⊗ k̂_t)                 # delta 移除键
S = S + v_t ⊗ k̂_t                                    # 写入
ctx_t = einsum(S, q_t)                               # 读出
```

序列构造照 Dijk §4.1.5：`χ(a,b)=sortlex{srcIP,dstIP}`，按时间排序，非重叠切 `L=128`。
训练序列 `271,815`，评价序列 `200,825`，评价覆盖 `1.0000`。

## 4. 必须更正的既有表述

主进程在 2026-08-13 凌晨曾多次表述「逐流 ≥ 序列，序列表示在该迁移上是劣势」，
依据是 Dijk 表 5 的 GRU `0.1758` < XGB `0.2416` 与候选 B 的 `0.0192`。

**该表述被本消融证伪，作废。** 正确表述：

> **最简因果前缀聚合大幅有效（`+81.0%`）；而完整序列模型（GRU、Transformer）
> 与 RWKV 状态递归在同任务上反而更差。问题不是"要不要序列"，是"序列上该用多复杂的聚合"。**

同时更正另一处：此前引用「候选 B 最佳 `0.0192`」时未说明该值属于**对照组** `B-DISCRETE-RWKV`（离散步长 RWKV）；
候选 B 的**创新机制** `B-ROLE-SEPARATED` 实为 `0.0101230212`，**比自身对照组低 47.3%**。
