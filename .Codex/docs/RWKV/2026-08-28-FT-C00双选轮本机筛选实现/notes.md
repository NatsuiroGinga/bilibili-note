# FT C00 双选轮本机筛选证据笔记

## 已核环境

- 本机为 Apple M1、16 GB 统一内存。
- LSPR23 本地缓存约 5.5 GB，六个源年数组齐全。
- `/opt/miniconda3/envs/rwkv`：PyTorch `2.12.0`，MPS 可用。
- 已只向该环境补装 `scikit-learn 1.9.0` 及其必要运行依赖；项目 `pyproject.toml`、`uv.lock` 与 `.venv` 未修改。
- 现有精度合同已定义 `mps-fp32-v1` 与 `cuda-bf16-amp-fp32-sensitive-v1`。

## 已核 FT 事实

- 实际输入为 78 个分位数数值字段、3 个二值直通字段、2 个协议词表字段，加 `[CLS]` 共 84 Token。
- 裸 FT 参数量为 924,283；历史四格 C00 仍携带旧机制脚手架，总参数量 998,204，因此新 C00 必须直接使用裸 `build_model`。
- 当前训练每轮只计算验证逐流 AP，仅保存最终逐流 AP 最优检查点；在途检查点逐轮覆盖并在完成后删除。
- 双选轮最小改造无需保存全部 20 轮，只需同一验证前向同时计算两项指标，并维护两份最优 CPU 状态。
- 当前 FT 工具硬编码 CUDA 设备和 CUDA 显存统计，新工具必须按精度 profile 解析设备并条件化资源收据。
- 本机字段基数扫描已完成 `7/7`，收据位于 `runs/diagnostics/ch3-lspr23-field-cardinality-receipt-v1/field-cardinality-receipt.json`；训练区唯一值计数为 SrcPort `61057`、DstPort `6041`、Protocol `7`、L3/L4 Protocol `5`，三个二值字段均为 `2`。

## 待核

- `FieldTokenTransform` 在 16 GB 内存下拟合时的真实峰值。
- MPS 单步训练和完整源验证吞吐。
- MPS 对当前 ReGLU、注意力 FP32 岛、无裁剪梯度范数接口的支持。
- 基于实测吞吐推导的本机筛选轮数与步数。

## MPS 实测预算

- 微批 `1×64`：完整优化步 `15.0129` 秒；验证批 1 的完整验证 `1344.5834` 秒。
- 微批 `4×16`：完整优化步 `14.3856` 秒；验证批 8 的完整验证 `1900.0964` 秒，反而更慢。
- 本机筛选冻结微批 `4×16`、验证批 1、`2` 轮×每轮 `60` 步；预计约 `74.8` 分钟。该预算只作源年筛选，正式 CUDA 仍为 `20×1000`。
