# FT C00 双选轮单代码实现计划

> **执行要求**：主进程负责实现与真实运行；所有步骤使用同一工作树。禁止修改旧 FT 正式入口。

**目标**：新增一个可在 MPS/FP32 和 CUDA/BF16 上直接运行的裸 FT C00 工具，并从同一训练轨迹保存逐流 AP 与实体 AP 两个最优检查点。

**架构**：新工具导入既有 `ch3_ft_transformer_field_token_protocol_a`，复用字段变换、`ProtocolASourceView`、裸 `build_model`、优化器和精度运行时。设备、训练预算、制品身份由两份配置提供；算法和指标代码只有一份。

**技术栈**：Python、PyTorch、MPS/CUDA、NumPy 内存映射、scikit-learn、既有神经精度合同。

## 全局约束

- 源年数组只以 `mmap_mode="r"` 打开，不把完整 `X23` 复制到 MPS/CUDA。
- 输入变换只在协议 A 训练区拟合，验证区只应用。
- 模型为裸 FT，不调用 `build_cell_model`。
- 逐流 AP 与实体 AP 必须来自同一轮同一次验证前向。
- 选轮均为严格大于更新，平局保留最早轮。
- MPS 与 CUDA 检查点使用同一模式，但不同运行身份和精度身份，禁止跨精度续训。
- 本机仅 `screening_only`，不得读取 LSPR24 或上传正式 SwanLab 结论。

## 任务 1：统一配置和入口

**文件**：新建两份配置、新工具与两个启动器。

1. 配置冻结父 FT 配置路径/哈希、数据清单、裸模型身份、设备 profile、运行角色和输出根。
2. 工具提供 `--validate-config`、`--calibrate-runtime`、`--run`、`--resume`。
3. 本机和服务器启动器只选择配置，不复制 Python 逻辑。
4. 配置门拒绝目标数组、旧机制开关、跨精度恢复和不同运行根覆盖。

## 任务 2：流式数据与裸 FT

1. 用内存映射加载 `X23/y23/I23/M23/E23/T23`。
2. 逐字复用协议 A 实体不相交训练/验证划分和输入变换拟合。
3. 复用 `ProtocolASourceView` 按微批提取特征。
4. 直接调用 `build_model` 构造 924,283 参数裸 FT，断言无旧融合层和 `p_log`。
5. 按 profile 解析 MPS 或 CUDA；`pin_memory`、同步和显存统计只在对应设备启用。

## 任务 3：双指标验证与双检查点

1. 验证前向同时保存流索引、标签和概率，仅驻内存。
2. 逐流 AP 直接由全部验证流计算。
3. 使用 `I23/M23/E23` 构造逐流实体映射，对验证流概率作实体最大池化并计算实体 AP。
4. 每轮历史记录 `validation_flow_ap`、`validation_entity_ap`、训练损失、梯度范数和资源。
5. 分别维护 `best_by_flow`、`best_by_entity`，训练结束原子保存两份检查点和选择收据。

## 任务 4：真实运行校准与预算冻结

1. `--calibrate-runtime` 在真实 LSPR23 训练区执行一个完整优化步和一次完整源验证，不创建正式模型结论。
2. 输出训练步吞吐、验证吞吐、峰值主存/设备内存和预计完整预算时间。
3. 本机筛选预算根据校准收据和用户允许的墙钟窗口写入新配置修订；不得在代码内写死。
4. 配置修订后执行完整本机 C00 筛选，保存两份选择检查点。

## 验证

- 不运行 `black`、人工单元测试或合成性能测试。
- 执行 Python 语法、模块导入、`--help`、两份 `--validate-config` 和两个 `bash -n`。
- 随后直接运行真实 LSPR23 `--calibrate-runtime`。
- 校准通过后再运行本机筛选；服务器正式配置只做静态入口检查，待服务器可用时执行。
