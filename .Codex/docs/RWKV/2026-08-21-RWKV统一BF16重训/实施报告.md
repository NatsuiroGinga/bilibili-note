# RWKV 固定结构统一 BF16 重训实施报告

## 结论

独立 BF16 重训入口已达到本地静态 **READY**。它只消费旧 FP32 Protocol A 已封印的 `R2 + 最终胜出 K`，随后在新运行中从头训练 C00/C01/C10/C11；不会重跑 R0/R1/R2 或 K0/K1/K2 搜索，也不会复用旧模型、优化器、选中轮次、目标结果、输出根或 SwanLab 身份。

旧 FP32 工具、配置和启动器没有修改，因此正在继续的 K2 容量选择及其原生检查点恢复不受本任务代码摘要影响。本轮没有访问服务器、没有解析真实容量收据、没有启动训练或评价。

## 架构选择边界

模板配置固定旧 FP32 容量收据路径，但把 `selected_capacity` 和收据 SHA-256 留空。独立启动器在实际启动前只读检查：

1. `capacity_selection_frozen.json` 已存在。
2. 模式为 `ch3-rwkv7-capacity-selection-v1`。
3. `selected_adapter` 恰为 R2。
4. `selected_capacity` 是 K0、K1、K2 之一。
5. `target_arrays_loaded` 为 0。
6. 模板没有预填容量或摘要。

通过后，启动器把最终 K 与收据 SHA-256 原子写入独立 launcher 目录的解析配置。Python 入口再次核对文件摘要、R2、最终 K 和目标零读取字段。任一条件不满足都在创建正式训练前退出。因此 K2 尚未完成时，模板可以同步，但不能误启动或自行拍定 K。

结果与源年封印均写入 `precision_changed_after_architecture_selection=true` 和 `bf16_architecture_search_repeated=false`。旧 FP32 搜索仅是架构选择来源，不是 BF16 下 R2 或某容量优越性的因果证据。

## 精度实现

统一配置固定为 `cuda-bf16-amp-fp32-sensitive-v1`：

- 模型参数和 AdamW 状态保持 FP32，初始化、恢复和每个优化步后机械检查。
- R2 两层输入投影、receptance/key/value/output、门控低秩矩阵和融合/输出线性层在 BF16 autocast 下执行。
- w 构造、双指数衰减、RWKV 递归 state、状态矩阵更新、LayerNorm、GroupNorm、向量归一化、CPA 前缀归约、LP 对数池化、sigmoid 概率、BCE、损失归约和指标处于关闭 autocast 的 FP32 区。
- BF16 profile 的 `create_grad_scaler` 必须返回 `None`；配置、训练入口和恢复检查点三处拒绝非空缩放器。
- 旧 `forward` 的“输入必须 FP32”硬拒绝没有扩散到新入口。新模型检查 profile 身份与输入类别，数据缓存仍按 FP32 搬运，由 autocast 决定安全算子的计算类型；递归状态不会随输入降精度。

Context7 没有 PyTorch 2.13 固定文档页。本轮核验 `/pytorch/pytorch` 当前官方源与 `/websites/pytorch_2_12` 固定页，采用统一接口 `torch.amp.autocast(device_type, dtype=..., enabled=...)`。目标环境版本依据既有收据为 `2.13.0+cu130`，真实兼容性仍须服务器第一完整优化步证明。

## 等效微批与双归一

科学有效批保持 64 个序列。资源实现固定为微批 8、累积 8，不改变每轮 1000 个优化步或 20 轮预算。

原目标函数包含两个不可混合的分母：

- 流 BCE 按当前 64 序列中的真实有效流数归一。
- ELP 辅助 BCE 按当前 64 序列的冻结正类权重和归一。

入口在抽样完整有效批后先从 CPU 只读缓存计算两个全步分母，再逐微批反向 `flow_loss_sum / total_valid_flows` 与 `weighted_sequence_loss_sum / total_sequence_weight`。正式更新只有一次清梯度、一次裁剪和一次 `optimizer.step()`。C11 的实体梯度可达性门仍是更新前独立诊断反向，诊断梯度在正式损失前清除，不进入参数更新。

共享运行时用于 profile 验证、autocast、FP32 岛、微批因子门、模型/优化器 FP32 门、检查点运行时状态和资源收据。检查点分别记录 `normalization_unit=flow` 与 ELP 格的 `normalization_unit=sequence`，没有把两种损失伪装成一个归一化单位。

## 检查点与恢复

每 20 个完整优化步原子覆盖 inflight，每轮另存一个完整检查点。两者都包含：

- 模型、优化器、无调度器占位与 `scaler=None`。
- 当前轮/步、全局 optimizer step、历史、最佳 AP、最早最佳轮、最佳状态和梯度门。
- Python、NumPy、PyTorch CPU/CUDA 与采样生成器随机状态。
- profile 全定义、有效批、微批、累积、流/序列归一化单位和完整优化步边界。
- 已处理有效流、内部 CUDA allocated/reserved 峰值和主存峰值。

恢复时重新验证配置、代码、源数据、旧架构收据、统一精度合同摘要和任务身份，并拒绝缩放器、半步检查点或非 FP32 参数/优化器状态。四格均从相同种子独立初始化，每格在 BF16 下按 LSPR23 验证逐流 AP 选择最早最佳轮。

## 目标隔离与资源

只有四格源年选择全部写入 `selection_frozen.json` 后，代码才清点和加载 LSPR24。每格目标评价仍是一调用或同身份完整收据复用；目标指标不进入架构、轮次、微批或资源选择。

启动器没有 `timeout`、`maximum_gpu_hours` 或其他墙钟硬门。每格第一完整优化步各写一份共享格式资源收据，包含内部 allocated/reserved 峰值、外部 `nvidia-smi` 采样、有效单位、耗时和吞吐。模板中的微批 8 是 K2 最坏结构上界下的工程预注册值，正式首步仍可能因真实展开与驱动行为失败；失败应保留收据并调整资源实现，不得改变有效批、模型、序列或训练步数。

## 科学状态与正文边界

当前只能标为“工程静态 READY，实验待证”。BF16 的数值稳定性、显存、吞吐、轮次选择、四格效果及目标结果均无真实制品支持。

- 若正文只报告最终固定 RWKV 对基线，可在本运行经过真实实验、结果分析和正文证据门后使用。
- 若正文要主张 R2 优于 R0/R1，或胜出 K 优于其他 K，并展示对应消融，必须另立同一 BF16 profile 的全族正式重跑。
