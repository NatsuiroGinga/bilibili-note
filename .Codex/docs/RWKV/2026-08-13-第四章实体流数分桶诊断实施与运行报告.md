## 1. 结论

已实现第三章四格 `C00/C01/C10/C11` 的冻结协议重跑、20 个末五检查点的
`safetensors` 归档，以及第四章实体流数五档诊断。代码只读取冻结缓存规定的十个字段，
重新扫描原始 LSPR23 ZIP 只用于计算 83 字段均值、标准差与固定行一致性核验，不读取或
引用作废的 `runs/diagnostics/ch4-drift/`。

真实运行已完成，四格对冻结结果逐项均为零差（逐流 AP、实体 AP、`DR@4%FPR`），并已产生
20 个 `safetensors` 检查点。全程 `seen_all=true`，未保存逐样本分数；运行状态为
`screening_only=true`、`formal_paper_evidence=false`、`independent_test=false`，因此只构成
诊断筛选证据，不能写成独立测试、统计显著结果、全局普适提升或 SOTA。

实体分桶表明组合格 `C11` 相对基线 `C00` 只在短中实体有利：`1-2`、`3-10`、`11-100` 档
实体 AP 增量依次为 `+0.123948`、`+0.239138`、`+0.137851`；在长实体 `101-1000`、`1001+` 档
则分别为 `-0.322915`、`-0.302212`。结论是现有机制对短中实体有益、对长实体显著有害，
不得概括为全局提升。下一 AP 候选为「实体均匀训练测度×直接实体 AP 目标」：设计可行、
实验待证，且与第四章 BBSE 决策层问题分开处理。

2026-08-13 限定复核发现初版生成的 `model_package/inference.py` 在归一化前没有执行训练
合同中的“非有限值置零”。这会使推理输入中的 NaN/Inf 传播到模型，但不影响正在进行的
归一化重算、训练或指标。根因已在生成源修复，并新增无需重训的模型包安全刷新参数。

## 3. 实现合同

### 3.1 数据与归一化

- 缓存根固定为 `runs/diagnostics/dijk-repro/cache`，只读取
  `X23,y23,X24,y24,I23,M23,I24,M24,s24,d24`；任一缺失即失败，不补写缓存。
- 原始 LSPR23 ZIP 固定为 `data/raw/lspr23-v1/ls23pr_flows.zip`。
- 83 字段按 LSPR24 Parquet schema 的顺序排除第三章冻结 18 列生成，并断言字段数为 83。
- 原始列先转为 `float32`，非有限值置零，再按第三章实现计算均值与标准差；标准差小于
  `1e-8` 时置 1，变换后裁剪到 `[-10,10]`。
- 固定核验行是 `0,1,2,127,128,1024,100000,1000000,16000000`，与缓存 `X23.npy`
  的最大绝对差容差冻结为 `1e-5`。该门禁在训练前执行，失败时不得继续。

### 3.2 四格训练与归档

- 四格顺序、模型容量、随机种子、损失与辅助损失、AdamW 参数分组、梯度裁剪、批次抽样和
  评价批次均按 `ch3_full.py` 实现。
- 冻结值为 `seed=42`、`HID=192`、`L=128`、`BS=64`、`lr=2e-3`、
  `weight_decay=0.01`、`grad_clip=1.0`、`20000` 步。
- 每格保存步 `16000/17000/18000/19000/20000`，共 20 个
  `model_package/checkpoints/<cell>/step-<step>.safetensors`；真实运行强制
  `safetensors==0.8.0`，不保存 pickle、`.pt` 或 `.pth`。
- 全局四格逐流 AP、实体 AP 与 `DR@4%FPR` 对冻结 JSON 的绝对差容差为 `0.001`。
  任一格失败时状态失败、清空分桶研究输出，并禁止研究裁决。
- 模型包包含 `config.json`、`features.json`、`normalization.json`、`metrics.json`、
  `manifest.json`、中文 `README.md`、`inference.py` 和 20 个检查点。清单记录除自身外
  每个文件的相对路径、字节数与 SHA-256。
- 模型卡明确 LSPR23 训练、LSPR24 已反复用于探索性评价、不是独立测试、只供研究且不得
  直接用于生产告警。包内不保存数据、缓存、原始 IP 值、标签、实体标识或逐样本预测。
- 推理源码现在与训练数据合同一致：输入转 `float32` 后先将 NaN/Inf 置零，再使用模型包
  均值和标准差变换并裁剪到 `[-10,10]`。

### 3.3 实体分桶

- 实体键固定为无向 `2-IP`，实体标签为实体内流标签最大值，并强制 `seen.all()`。
- 五档固定为 `1-2`、`3-10`、`11-100`、`101-1000`、`1001+`。
- `C00/C10` 使用最大值实体聚合；`C11` 使用其末五检查点学到的平均 `p` 做 Lp 聚合；
  `C01` 只做全局复现和模型归档。
- 每档报告实体数、正实体数、基率、实体 AP、`AP/基率`、档内 `DR@4%FPR`，并报告
  `C10-C00`、`C11-C00`、`C11-C10` 的三个指标差。正实体少于 20 时标记
  `underpowered=true`。

### 3.4 启动与可恢复性

- 输出根固定为 `runs/diagnostics/ch4-entity-length-bucket-diagnostic-seed42-v1/`。
- 启动器使用项目 `uv run --no-sync`，同时检查同名持久会话、同名 Python 进程和 `flock`
  文件锁。已存在但未合法完成的输出根保留并阻断，不覆盖失败证据。
- 允许无关 GPU 进程，但在启动前记录 GPU 型号、总显存、空闲显存与利用率；空闲显存低于
  16 GiB 时拒绝启动。
- 启动前调用 `bash tools/memory_admission_gate.sh 32 <运行标识>`，按 cgroup 上限执行
  内存准入。命令与 `tee` 退出码分别保存并原样传播。
- 输出白名单为配置副本、聚合 JSON、模型包、状态、日志、资源与哈希收据；不持久化逐流分数。

### 3.5 不重训模型包刷新

`--refresh-model-package-inference` 不进入 `execute()`，不会导入训练期 `torch`、扫描原始数据、
读取缓存、修改检查点或重新评价。刷新前机械验证：

1. 启动器 `status.json` 与生产入口 `run-status.json` 均为 `finished/complete/exit_code=0`。
2. `aggregate-results.json` 为 `passed`，`research_decision_emitted=true`、`seen_all=true`，且记录
   20 个检查点、未持久化逐流分数。
3. `model_package/metrics.json` 与聚合结果完全一致。
4. `normalization.json` 的 schema、`float32`、非有限值置零合同、83 个有限均值与正标准差通过。
5. 四格 `16000/17000/18000/19000/20000` 共 20 个非空 `safetensors` 文件恰好存在。
6. 旧模型包 manifest 的文件集合、字节数和 SHA-256 全部通过。

门禁通过后仅原子重写 `model_package/inference.py`，再重建 `model_package/manifest.json` 与
`output-hashes.json`。刷新前后再次核对聚合结果、`metrics.json`、`normalization.json` 和全部
检查点 SHA-256 不变；任一状态不完整或受保护文件变化即失败。正式启动器文件及其默认训练行为
未修改。

- **保护边界**：不修改训练、损失、优化器、快照、评价、指标、检查点或启动器正式行为。
- **恢复方式**：既有运行成功后执行模型包刷新参数，不重训。
- **验证**：限定的 Python 语法编译、配置解析与模块导入、CLI `--help`、Shell `bash -n` 和
