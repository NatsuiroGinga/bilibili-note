# GeNIS 与 HIKARI 数据论文研读计划

## 目标

核验指定 PDF 是否为 GeNIS 原始论文，并完整研读指定 HIKARI-2021 分类论文；分别形成包含字段、标签、数据划分、局限性及第三章实验映射的可追溯中文论文笔记。

## 阶段

- [x] 阶段一：恢复课题边界并读取 PDF 转换规范
- [x] 阶段二：核验 PDF 元数据、页数和既有笔记模板
- [x] 阶段三：提取 GeNIS 全文并逐页复核关键表格、图和实验事实
- [x] 阶段四：提取 HIKARI 全文并逐页复核关键表格、图和实验事实
- [x] 阶段五：创建或更新两篇结构化论文笔记及最相关索引
- [x] 阶段六：执行 Markdown 格式化、YAML 与链接检查

## 关键问题

1. 指定 PDF 是否为 GeNIS 数据集的原始论文？
2. GeNIS 流程数据包含哪些完整字段、单位和标签？
3. 数据如何采集、组织和划分，存在哪些泄漏风险？
4. 当前 8 字段接口丢失了哪些可用于历史辨识和物理状态估计的信息？
5. HIKARI、GeNIS 与 ns-3 的公共观测交集是什么？

## 决策

- 原文事实必须附 PDF 页码或表图编号；推断单列说明。
- PDF 自动提取只作阅读辅助，关键事实必须回到原 PDF 复核。
- 不修改两份总控文档和实验代码。

## 错误记录

- `mineru-open-api flash-extract` 在受限网络环境中无法解析 `mineru.net`；改为申请联网执行，若仍不可用则回退本地 `pdftotext` 与逐页渲染核验。
- MinerU 联网提交返回会话号但未在指定路径生成文件；先核验命令行为，必要时按既定回退方案使用本地文本提取并逐页检查原 PDF。
- 本地 GeNIS PDF 元数据声明 14 页，但页面树仅能读取印刷页 1、8 至 14，印刷页 2 至 7 对应空或损坏页面；缺失部分包含数据说明核心内容，必须从 DOI 对应的一手来源补齐后再写结论。
- 首次请求 NCBI 开放获取接口时 URL 中的问号被 `zsh` 当作通配符；改为给 URL 加引号后重试，不涉及数据或代码修改。
- HIKARI-2021 原始数据论文的 MDPI `/pdf` 端点返回 HTTP 403；改用 MDPI 官方 XML 全文中的章节、表 2、表 3 和图 2 核验，不使用第三方镜像。
- 首次用绝对路径删除并重建证据笔记时 `apply_patch` 拒绝删除；改为仓库相对路径执行同一非破坏性重写。
