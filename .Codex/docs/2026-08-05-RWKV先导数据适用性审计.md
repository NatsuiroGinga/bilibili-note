# RWKV 先导数据适用性审计

日期：2026-08-05

## 裁决

**DATA_NO_GO。** 现有合法冻结开发数据不能构造长度 `4`、`16` 或 `32` 的同一父会话因果序列。因此不得开始 GRU、轻量 Transformer、普通 RWKV、HGB 或漂移校准的任何训练与实现。

## 审计范围

- 仅审计现有 `llm_probe` 制品，未修改 R2 源码、配置、数据或运行目录。
- 目标是判断现有 GeNIS 与 TQH-C2 是否支持“面向长时加密流的 RWKV 状态检测与漂移校准”的开发阶段，而非产生模型结果。
- 最终测试清单未被用于统计、训练、归一化或模型选择。TQH-C2 的样本内容与测试样本共存于单一 `samples.parquet`，这本身不满足严格物理隔离要求；本次统计只按训练和验证 `sample_id` 清单筛选。后续若重新启动本主题，必须先物理拆分开发制品并限制读取权限。

## GeNIS 证据

- 来源制品：`runs/data-audit/r2-genis-global-assignment-v0/run_manifest.json`。
- 原始文件被记录为 Zenodo `14919237` 的 `1-packets.zip` 与 `2-flows.zip`，其中 `2-flows.zip` SHA-256 为 `72033b5e3df6e45cda9a339985194d8232c437c243a5037a62ebeff457489b30`。
- 现有全局分配审计的 `semantic_decision` 为 `NO-GO`，原因包括候选身份缺失和持续时间区间不匹配；不能绕过该结论重建序列。
- 已有层次样本清单包含 `train`、`validation` 和 `test` 集，不能作为“最终测试完全不可见”的 RWKV 开发输入。
- 本地审计制品未提供本轮可复核的官方许可证文本或已核验的官方发布页记录。因此 GeNIS 仅登记为候选来源，不进入本轮实验输入。

## TQH-C2 证据

- 来源制品：`runs/data-frozen/dataset-candidate-tqhc2-abc-v0/protocol/`。
- 冻结协议为 `data-protocol-v1.0-rc1`，范围为 A/B/C 三个 profile 的固定 36 单元分配；`input-contract.json` 记录三个已批准输入和其摘要。
- `field-roles.yaml` 固定 37 个数值模型字段，`parent_session_id`、`window_start_ns`、`window_ordinal`、`profile`、`interval_s` 与 `jitter_pct` 可用于审计，但不允许按标签或模型结果重新拼样本。
- `fixed-assignment.json` 显示 `tqhc2_cell_indomain` 的开发训练 28 单元、开发验证 4 单元，测试 4 单元；测试未进入计算。
- 协议状态仍为 `provisional` / `review_pending`，且本地 `source-artifacts.jsonl` 只记录派生输入和摘要，未提供本轮可核验的官方许可证或发布者证据。它不能升级为论文正式证据。

## 开发序列统计

统计对象：`tqhc2_cell_indomain-train.jsonl` 与 `tqhc2_cell_indomain-validation.jsonl` 中的 `sample_id`，映射至 `samples.parquet` 后按 `(split, parent_session_id)` 分组。

| 项目 | 训练 | 验证 |
| --- | ---: | ---: |
| 冻结清单样本数 | 27,235 | 4,000 |
| 成功映射样本数 | 27,235 | 4,000 |
| 独立父会话数 | 27,235 | 4,000 |
| 长度至少 4 的会话数 | 0 | 0 |
| 长度至少 16 的会话数 | 0 | 0 |
| 长度至少 32 的会话数 | 0 | 0 |

附加检查：训练与验证的 `sample_id` 交集为 0，父会话交集为 0，组内标签冲突为 0，时间与窗口序号非单调组数均为 0。结论不是顺序污染，而是每个允许父会话只有一个可用窗口，无法形成长时状态序列。

## 可复现命令

以下命令均在本机 CPU 上只读执行：

```bash
uv run python -c '<读取冻结 train/validation 清单，按 parent_session_id 统计长度 4/16/32>'
```

结果摘要：训练和验证的三个长度档均为 0。

## 解除条件

只有同时满足下列条件，才可重新评估本主题：

1. 提供官方发布者、版本、许可证和摘要可核验的来源记录。
2. 物理隔离最终测试，并提供只含开发训练、校准和开发验证的制品。
3. 在同一合法采集组或会话内提供至少两个长度档的有序窗口，且每个主要类别有足够独立组。
4. 冻结组划分、时间顺序、数值字段和归一化范围后，再实施模型。
